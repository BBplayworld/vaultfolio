# S-4.25 암호화폐 매수/매도 거래내역

> 상태: 완료 | 브랜치: `issue-4.21` (기존 작업 브랜치 유지) | 작성 2026-08-04 (구현 후 역작성)

## 1. 왜

`crypto[]`는 `quantity`·`averagePrice`(잔고 스냅샷)만 있고 거래 이력이 없다 — 코인은 "잔고를 통째로 덮어쓰기"만 가능하고 매수/매도 이력·평단 자동 재계산이 없다. 반면 주식은 `transactions[]`(체결 기록 + 가중평균), 현금은 `cashTransactions[]`(입출금), 대출은 `loanTransactions[]`(상환/추가대출)까지 이미 갖춰 코인만 뒤처져 있었다.

그 여파가 자산성적표 "순자산 왜"에도 드러났다: `buy:crypto`/`sell:crypto` 원인 라벨은 있었지만 실제 거래 기록이 아니라 `averagePrice×quantity`의 스냅샷 간 원가 델타 **추정치**였다(`asset-report.ts` 옛 `dCostCrypto` 처리). 또한 "자산업데이트" 플로팅 버튼 플로우에 현금·대출은 기록 액션이 있는데 코인만 빠져 있어 진입로 자체가 없었다.

## 2. 무엇 (범위)

- 포함:
  - 코인 자산에 **매수/매도 거래내역**(주식 `transactions`/`trade-utils.ts` 가중평균 계산 재사용, 잔액 선형 가감이 아니라 수량×평단).
  - 반영(reflected) ON 시 `crypto[].quantity`/`averagePrice` 자동 재계산, OFF는 로그만(과거 소급 기록).
  - "자산업데이트" 플로팅 버튼 플로우에 현금·대출과 동일한 위치·패턴으로 코인 기록 액션 추가.
  - 코인 상세 탭 카드에 기록/내역 진입 버튼 추가(병합 카드는 분할 보유 시 비활성화, 거래소별 하위 카드에서 개별 기록).
  - 자산성적표 "순자산 왜"의 `buy:crypto`/`sell:crypto`를 실제 거래 기록 기반으로 정확화(정밀·예측 분기 모두).
  - 공유 토큰·JSON 내보내기에 코인 거래내역 포함.
  - `trade-utils.ts`의 가중평균 재계산 함수 5개·`validateReflection`을 구조적 타입(`TxLike`/`PositionLike`)으로 일반화해 주식 코드를 복제하지 않고 재사용.
- **제외**:
  - 거래내역 전용 스크린샷 일괄 등록(주식 `TradeScreenshotImport`급 기능) — cash-tx/loan-tx도 없는 기능이라 관행 일관성 위해 제외. 기존 `crypto-screenshot-import.tsx`(잔고 스냅샷 갱신)는 그대로 유지.
  - 코인의 `currency`/환율 개념 — 스키마상 항상 KRW 취급 유지, 해외 거래소 통화 환산은 범위 밖.
  - `Crypto` 자산 스키마 자체 필드 변경(코인 종류·거래소 목록 확장 등) — 거래내역 관련 필드(`positionSource`/`positionEffectiveDate`)만 추가.
  - 성적표 습관(habit) 축 신호 반영(S-4.22가 현금에 한 것과 대칭되는 코인판) — 이번 범위 밖.

## 3. 수용 기준

- [x] AC1. 코인 카드에서 "매수/매도 기록" → 입력 폼(코인 선택·매수/매도 토글·수량·체결단가·날짜·메모·반영 ON/OFF, 반영 후 예상 포지션 인라인 미리보기)과 "매수/매도 내역" → 로그 뷰(기간·유형 필터, 총매수·총매도 통계).
- [x] AC2. WHEN 반영(reflected) ON 매수를 기록하면, 시스템은 `computeNewPosition`(가중평균)으로 해당 `crypto.quantity`/`averagePrice`를 갱신하고 로그+포지션을 **단일 저장**한다. 매도는 수량 차감·평단 유지.
- [x] AC3. WHEN 반영 ON 매도 수량이 보유 수량을 초과하면, 시스템은 기록을 **차단**(restrict)한다(`validateReflection` 일반화 재사용, 주식 oversell 대칭).
- [x] AC4. WHEN 반영 ON 거래를 삭제하면, 시스템은 `rollbackTransaction`(거래로그 전체 재적용 방식, 가중평균이라 단순 산술 역가감 불가)으로 포지션을 되돌리고 로그+포지션을 단일 저장한다. 미반영 거래 삭제는 포지션 불변.
- [x] AC5. WHEN 거래 날짜가 오늘 기준 3년(`TRANSACTION_RETENTION_YEARS`) 밖이면, 시스템은 저장 시 해당 로그를 정리(prune)한다.
- [x] AC6. "자산업데이트" 플로팅 버튼에서 코인 선택 시, 현금 "입출금 기록"·대출 "상환/대출 기록"과 동일 위치에 "매수/매도 기록" 액션이 노출된다.
- [x] AC7. 원인분해 기간 내 **반영된** 코인 매수/매도 순액(`reflectedCryptoFlow`)이 `buy:crypto`/`sell:crypto`로 정확히 표시되고, 거래내역으로 설명 안 되는 나머지(직접 수정·스크린샷 잔고 갱신)만 같은 방향으로 합산된다. 예측 분기(`estimatePeriodInflows`)는 반영 거래를 가진 코인을 매수일 기반 추정에서 제외해 이중계산을 막는다(`tradedCryptoIds`, 주식 `tradedStockIds` 대칭). **표시 금액 합계 = deltaNet 불변**.
- [x] AC8. WHEN 공유 URL을 생성·복원하면, 시스템은 코인 거래내역을 손실 없이 왕복하고 부모 코인(`crIdx`)에 재연결한다. 구버전 공유 토큰(코인 거래 미포함)도 정상 파싱한다(R3).
- [x] AC9. 구버전 백업 JSON(코인 거래 필드 없음)이 `applyImportedPayload`를 통과한다(신규 필드는 optional/default).
