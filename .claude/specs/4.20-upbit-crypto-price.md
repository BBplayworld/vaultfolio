# S-4.20 업비트 코인 시세 자동 갱신

> 상태: 완료 | 브랜치: `issue-4.20-upbit-crypto-price` | 작성 2026-07-20

## 1. 왜

암호화폐만 **현재가가 100% 수동 입력**이다. 주식은 `syncTodayStockPrices`가 접속 시 자동 갱신하는데 코인은 대응물이 없어(`asset-data-context.tsx`에 crypto 시세 갱신 코드 0건), 사용자가 직접 고치지 않으면 평가액·순자산·성적표가 낡은 값으로 계산된다.

## 2. 무엇 (범위)

- **포함**: 업비트 Quotation API로 코인 현재가 1시간 단위 자동 갱신, 주식과 동일한 서버·클라이언트 2단 캐싱, 마켓 코드 단위 공통 캐시, rate limit 방어(백그라운드 갱신·분산 락·stale 폴백)
- **제외**
  - 전일 대비 등락 표시 (`prev_closing_price`·`signed_change_rate`는 응답에 있지만 이번엔 안 씀)
  - 업비트 외 거래소 API 연동 (모든 보유분을 업비트 KRW 시세로 갱신)
  - BTC/USDT 마켓 (KRW 마켓만)
  - 코인 분류(L1/DeFi 등) X-Ray, 코인 거래내역, 과거 기준가(profit) 조회
  - 서킷 브레이커 — 업비트는 토큰 발급이 없어 실패 지점이 단순. 과한 구조를 먼저 넣지 않는다

## 3. 수용 기준

- [ ] AC1. WHEN 코인 보유 항목의 `baseDate`가 현재 슬롯과 다를 때, 접속 시 현재가가 업비트 시세로 갱신된다
- [ ] AC2. WHEN 같은 슬롯 내 재접속일 때, 외부 호출 없이 캐시를 사용한다
- [ ] AC3. WHEN 여러 사용자가 같은 코인을 보유할 때, 마켓 단위 서버 캐시를 공유해 외부 호출이 슬롯당 1회로 수렴한다
- [ ] AC4. WHEN 업비트에 없는 심볼일 때, 해당 항목의 수동 입력값을 유지하고 요청 전체를 실패시키지 않는다
- [ ] AC5. WHEN 같은 코인을 여러 거래소에 보유할 때, 조회는 심볼 단위로 1회만 수행한다
- [ ] AC6. 데이터 삭제·불러오기로 취소된 동기화의 응답은 상태에 반영되지 않는다
- [ ] AC7. WHEN 슬롯 캐시가 없고 stale 값이 있을 때, stale을 즉시 반환하고 갱신은 백그라운드로 처리한다
- [ ] AC8. WHEN 동시 요청이 여러 건일 때, 외부 호출은 락으로 직렬화되고 호출 간 최소 500ms 간격을 지킨다
- [ ] AC9. WHEN 업비트가 429·418을 반환할 때, 재시도를 멈추고 stale 값을 유지한다

## 4. 데이터 계약

| 항목 | 확인 |
| --- | --- |
| `assetDataSchema` 변경 | **있음** — `cryptoSchema.baseDate?: string` 추가. **optional 필수** |
| 구버전 백업 JSON 복구 | optional이므로 `applyImportedPayload`의 parse 통과 ✅ |
| 신규 `STORAGE_KEYS` | **없음** (자산 데이터 내부에 저장) |
| 공유 토큰 직렬화 | **미포함** — `packV7` crypto 섹션은 8필드 고정 배열이라 추가 시 구버전 파싱이 깨짐(R3). 주식도 `baseDate`를 공유 토큰에 넣지 않는 선례를 따름 |
| cloud-sync 비교 대상 | **제외 필요** — `getComparablePayloadString`에서 crypto의 `baseDate`·`currentPrice` 제외. 미제외 시 접속마다 자동 push 핑퐁(R14) |
| 마이그레이션 | 불필요 (optional 필드) |
| 통화·환율 | `computeNetAsset`의 crypto는 환율 미적용(KRW 전제). 업비트 KRW 시세를 그대로 넣으므로 **계산식 변경 없음** |
| 비활성 종목 | 무관 (주식 전용 개념). 업비트 미상장 코인은 수동값 유지로 대응 |
