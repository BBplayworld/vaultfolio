# S-4.30 자산 최신화 — FAB 통합 카드 화면

> 상태: 구현중 | 브랜치: `issue-4.30-asset-refresh-fab` | 작성 2026-08-14

## 1. 왜

secretasset의 핵심 가치는 순자산 "기록"이 아니라 "해석"(원인분해·5축 성적표·X-Ray)이며, 이 해석 품질은 데이터 신선도에 전적으로 의존한다. 그런데:

- 온보딩 마법사(S-4.29)는 자산 0건인 최초 사용자에게만 노출되고, 이후 재진입 경로가 없다. 자산을 이미 등록한 사용자가 여러 카테고리를 한 번에 갱신할 방법이 없어 개별 항목을 하나씩 손으로 고쳐야 한다.
- FAB "자산 업데이트"에서 stock/cash/loan의 보유현황 스크린샷 등록은 append-only다. crypto만 유일하게 기존 보유와 중복 감지 후 merge/reset을 지원한다. 즉 재등록을 시도하면 stock/cash/loan은 중복 등록이 발생한다.
- "보유현황 갱신"과 "거래 기록"이 FAB의 `select-type→select-action→select-method` 2탭 흐름에 묻혀 있고, 마지막 갱신 시점을 알 방법이 없어 사용자가 최신화를 놓치기 쉽다.

## 2. 무엇 (범위)

- 포함:
  - FAB `floating-add-button.tsx`의 `select-type`+`select-action` 2단계를 **허브(보유현황/거래 2개 타일) → 카테고리 컴팩트 리스트** 2단계로 재구성(별도 "보유현황" 리스트, 별도 "거래" 리스트, `navigateTab` 있으면 행에 수정 아이콘). 행 클릭 시 기존과 동일하게 즉시 단건 처리. (2026-08-20 수정: 체크박스 다건 순차 처리는 요구사항 재검토로 제거 — 항상 단건 처리)
  - stock/cash/loan의 보유현황 스크린샷 등록을 crypto와 동일한 병합형(merge/reset)으로 전환. 공용 훅으로 추출.
  - 암호화폐 거래(매수/매도) 스크린샷 인식 신규 추가(`crypto-tx-input.tsx`에 스크린샷 옵션, API `assetType="crypto-trade"`).
  - 다건 시퀀스 완료 후 원인분해(attribution) 요약 화면(기존 `asset-report.ts`/`dashboard.tsx` 로직 재사용).
  - 홈 화면 인앱 넛지(30일 기준, 카테고리별 최종 갱신일 추적) — 백업 넛지와 동시 노출 금지.
- **제외** (이번에 하지 않는 것):
  - 현금·대출의 거래(입출금/상환) 스크린샷 인식 — 매수/매도 개념이 아니므로 기존 수동 입력 폼 유지.
  - 더보기(tool-menu.tsx) 메뉴에 신규 진입점 추가 — 진입점은 기존 FAB "자산 업데이트" 하나로 유지.
  - 온보딩 마법사(`onboarding-wizard-flow.tsx`) 자체의 변경 — 자산 0건 최초 사용자 전용으로 그대로 둔다. 단, 카테고리 스크린샷 스텝의 저수준 동작(다이얼로그 open/close·onSaved·skip)만 신규 공용 훅으로 뽑아 온보딩과 FAB 양쪽이 공유한다.
  - Web Push 등 서버 인프라 기반 알림 — 인앱 넛지만 사용(S-4.26~4.28이 "Push 인프라 부재"로 롤백된 전례 반복 금지).
  - `assetDataSchema`(stock/cash/loan)에 계좌 고유 식별자 필드 추가 — 마이그레이션 회피, 근사 매칭으로 대체.
  - Push 알림 관련 어떠한 코드도 추가하지 않는다.
