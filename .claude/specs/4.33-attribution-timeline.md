# S-4.33 자산 변화 원인분해 — 항목별 날짜·기록 타임라인

> 상태: 완료 | 브랜치: `issue-4.29` | 작성 2026-10-24

## 1. 왜
홈 헤더 "전일 대비 / 지난 접속(M/D) 이후" 펼침과 성과 "순자산 변화"는 원인을 key별 합계로만 보여준다. 오랜만에 접속했거나 현금 출금 → 주식 매수를 연달아 입력하면 "현금 출금 −671만 / 주식 매수 +439만 / 신규 현금 +233만"처럼 언제 무엇이 일어났는지 알 수 없어 흐름이 이상하게 느껴진다. 홈에는 비교 구간 자체도 표시되지 않는다.

## 2. 무엇 (범위)
- 포함:
  - 원인 항목 중 **기록 기반 항목**(현금 입금·출금, 주식·코인 매수·매도, 대출 상환·추가 대출)에 근거 기록 날짜를 표시(단일 `10/21` 또는 범위 `10/20~10/23`)
  - 원인 목록 정렬: 구간 항목(시세·환율) → 날짜 있는 항목(최초일 오름차순) → 날짜 없는 나머지(기존 `CAUSE_ORDER`)
  - **기록 내역** 펼침: 비교 구간 안의 반영된 입출금·매매·대출 기록을 건별로 시간순 나열(날짜·구분·계좌/종목명·금액)
  - 비교 구간 표기(`10/20 → 10/24`) — 홈 펼침에 신규, 성과는 기존 표기 유지
  - 홈 헤더 펼침과 성과 순자산 변화 두 화면 동일 적용(공용 컴포넌트)
- **제외**:
  - 원인분해 금액 계산·합계(= `deltaNet`) 로직 변경 — 표시용 파생 정보만 추가
  - 시세·환율·"신규 현금/현금 정리"(기록 없는 잔액 변동)·예적금·스냅샷 차이 기반 부채에 대한 날짜 추정 — 근거 기록이 없어 날짜 미표시
  - 미반영(`reflected: false`) 기록 — 순자산을 움직이지 않았으므로 타임라인에서도 제외
  - 성과 화면의 자산군 그룹 구조 변경 — 그룹은 유지하고 그룹 **내부** 정렬만 날짜 규칙 적용
  - 스크린샷 모드(인증카드 등)에서의 기록 내역 노출
  - `Cash` 스키마에 생성일 필드 추가(신규 현금 날짜 표시용) — 스키마 변경 범위라 이번에 하지 않음

## 3. 수용 기준
- [ ] AC1. WHEN 비교 구간 안에 반영된 현금·주식·코인·대출 기록이 있으면, 시스템은 해당 원인 항목(`income`·`buy/sell:stock`·`buy/sell:crypto`·`debt`) 옆에 기록 날짜를 표시한다(기록 1건 또는 같은 날짜면 단일 날짜, 여러 날짜면 `최초~최신` 범위).
- [ ] AC2. WHEN 원인 항목에 근거 기록이 없으면(시세·환율·신규 현금 등), 시스템은 날짜를 표시하지 않는다.
- [ ] AC3. 원인 목록은 시세·환율 → 날짜 있는 항목(최초일 오름차순) → 날짜 없는 나머지 순으로 정렬된다. 성과 화면은 그룹 순서를 유지하고 그룹 내부에만 같은 규칙을 적용한다.
- [ ] AC4. 기록 내역은 기본 접힘이며, 구간 내 반영 기록이 1건 이상일 때만 "기록 내역 N건" 토글이 나타난다. 펼치면 날짜 오름차순(같은 날은 입력 순)으로 날짜·구분·계좌/종목/대출명·금액을 보여준다.
- [ ] AC5. 기록 포함 경계는 원인분해와 같다 — 주식·코인 매매는 `(시작일, 종료일]`, 현금·대출은 `[시작일, 종료일]`. WHEN 시작점이 월별 스냅샷이면, 시스템은 표시용 "YYYY-MM"이 아닌 실제 기준일로 경계를 판정한다.
- [ ] AC6. 기록 금액은 원인분해와 같은 KRW 환산 규칙(체결 환율 우선, 없으면 현재 환율)을 쓰며, 같은 원인의 기록 금액 합은 해당 원인의 기록 기반 금액(`reflectedCashInflow`·`reflectedTradeFlow`·`reflectedCryptoFlow`)과 일치한다.
- [ ] AC7. 홈 펼침 목록 위에 비교 구간(`M/D → M/D`)을 표시한다.
- [ ] AC8. 원인분해 합계(`deltaNet`)·항목 금액·기존 라벨/문장은 변경되지 않는다(기존 테스트 통과).
