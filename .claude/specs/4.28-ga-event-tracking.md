# S-4.28 GA4 사용자 행동 추적 (gtag 상세 이벤트)

> 상태: 구현중 | 브랜치: `4.28` | 작성 2026-10-18
> (번호 주의: 과거 롤백된 "목표 설정"도 S-4.28을 썼으나 명세 파일 없이 철회됨 — 본 명세와 무관, changelog로 구분)

## 1. 왜

지금 GA는 `gtag('config')`의 자동 page_view 하나뿐이다(`src/app/layout.tsx`). 그래서 다음 문제가 있다.

- **화면 전환을 측정할 수 없다.** 앱은 해시 라우팅 SPA(`#detail/stocks`·`#activity/profit`)라 GA가 화면 이동을 잡지 못하고, 어떤 화면이 쓰이는지 알 수 없다.
- **핵심 퍼널을 볼 수 없다.** 웰컴 → 첫 자산 저장 → 재방문 퍼널, 스크린샷 인식 성공률, 공유·동기화·백업 사용률이 전혀 측정되지 않는다. 서버도 사용자 행동을 볼 수 없다(localStorage 앱).
- **해시가 GA로 나갈 위험이 있다.** 초기 page_view의 `page_location`에 URL 해시(`#share=…_<localKey>`, `#sync=<assetId>`)와 `?url=` 쿼리가 실려 전송될 수 있다. 해시 제거는 비동기로 그보다 늦게 일어난다.

목표는 사용자가 **GA4 기본 보고서·탐색 분석에서 별도 가공 없이 바로** 행동을 분석할 수 있게 하는 것이다.

## 2. 무엇 (범위)

- 포함:
  - **GA ID 단일 출처화**: `APP_CONFIG.gaId`. 하드코딩 4곳(layout 3곳, settings-page 1곳)을 이것으로 치환한다.
  - **공용 래퍼 `src/lib/analytics/ga.ts`**:
    - `track`: 이벤트·파라미터 사전을 TS 타입 union으로 고정하고, 런타임 sanitizer를 둔다.
    - `trackScreen`, `setUserProps`.
    - gtag가 없거나 옵트아웃이거나 예외가 나면 no-op이다.
  - **전역 타입** `window.gtag`·`dataLayer`.
  - **초기 page_view 유출 차단**: `send_page_view:false`로 두고, `page_location`을 origin+pathname으로 덮어쓴다. 화면 전환은 수동 page_view로 보낸다(`page_path=/v/<viewKey>`, 한국어 `page_title`).
  - **디버그 플래그** `?ga-debug=1`/`0`: 기존 `?ga-optout` 패턴과 동일하게 localStorage에 저장하고, 켜져 있으면 `debug_mode:true`로 보낸다.
  - **§3 이벤트 사전 약 20종**과 사용자 속성 5종의 발생 지점 계측.
  - **첫 자산 저장 1회 판정용 신규 저장 키.**
  - **GA4 관리자 설정 가이드**(§3-C): 사용자가 GA 콘솔에서 할 작업.
- **제외** (이번에 하지 않는 것):
  - 금액·수량·종목명·티커·닉네임·assetId·공유키·URL 해시·토스트·에러 원문 전송. 버킷·enum·bool만 보낸다.
  - 자산 성적표 등급·점수 전송(개인 재무 상태 추정 가능).
  - 동기화 로직·순서·반환값 변경. 결과 확정 뒤 `track()` 한 줄만 추가한다. 자동 폴링(`runPush`/`runPull` 60초·focus·online)에는 걸지 않는다.
  - 스크린샷 파싱 6개 컴포넌트의 fetch 리팩터링. 결과 분기에 1줄 계측만 넣는다.
  - GTM 컨테이너, 서버사이드 Measurement Protocol, 동의 배너(CMP), 처리방침 문서 작성.
  - 기존 `ga-optout`과 `gaEnabled`(production 한정) 정책 변경. 그대로 유지한다.
  - GA 관리자 콘솔 설정 자체. 사용자 작업으로 가이드만 제공한다.

## 3. 수용 기준

### A. 전송 안전성
- [ ] AC1. WHEN `window.gtag`가 없다(로컬·preview·`ga-disable` 옵트아웃), 시스템은 `track`/`trackScreen`/`setUserProps` 호출을 예외 없이 무시한다.
- [ ] AC2. WHEN 파라미터 값이 사전에 정의되지 않은 문자열·객체·배열·NaN/Infinity다, 시스템은 그 키를 제거하고 나머지만 전송한다. 이로써 금액·이름·ID가 실려 나갈 수 없다.
- [ ] AC3. WHEN 앱이 `#share=…`, `#sync=…`, `?url=…`가 포함된 URL로 진입한다, 시스템은 어떤 GA 요청의 `page_location`·`page_path`에도 해시·쿼리를 넣지 않는다. 초기 config는 `send_page_view:false`이고, `page_location`은 origin+pathname이다.
- [ ] AC4. `track` 내부 예외는 호출부로 전파되지 않는다. 계측 실패가 저장·동기화·화면 흐름을 바꾸지 않는다.
- [ ] AC5. GA ID 문자열은 `APP_CONFIG.gaId` 한 곳에만 존재한다(grep `G-PZXY31JVEW` 결과 1곳).

### B. 이벤트 사전 (GA4 친화 명명 + 공용 파라미터)
공용 파라미터 이름은 모든 이벤트에서 동일하다: `asset_type` · `method` · `result` · `source` · `category` · `step` · `nav_source` · `content_type`.

| 이벤트 | GA 분석 용도 | 발생 지점(코드 사실) | 파라미터 값(enum) |
| --- | --- | --- | --- |
| `page_view` | 화면별 사용량·경로 | `navigation-context.tsx` `navigate()`·`onPop`·초기 마운트 | `page_path=/v/<viewToKey>`, `page_title`(한국어), `nav_source`=tap/back/swipe/initial |
| `welcome_view` | 활성화 퍼널 1단계 | `page.tsx` 웰컴 분기 마운트 | `source`=web/pwa/inapp |
| `onboarding_action` | 웰컴 CTA 선택 비교 | `welcome-guide.tsx` CTA 5곳 | `method`=wizard/manual/import/sync_connect/skip_install |
| `tutorial_begin` / `tutorial_complete` (GA 권장명) | 튜토리얼 완료율 | `tutorial-store.ts` 첫 `completeStep` / 전체 완료 전이 | — |
| `tutorial_step` | 스텝별 이탈 | `completeStep` | `step`=1~5 |
| `wizard_step` | 마법사 단계별 이탈 | `onboarding-wizard-flow.tsx` 시작·카테고리 저장/건너뛰기·완료·종료 | `step`=start/stock/crypto/cash/loan/complete/exit, `result`=done/skipped |
| `first_asset_saved` (핵심) | 활성화 전환 | 아래 AC8 | `asset_type`, `method` |
| `asset_add_start` | 입력 시도→완료 전환율 | FAB `handleMethodSelect`·`handleHoldingsClick` | `asset_type`, `method`=manual/screenshot |
| `asset_save` | 자산 등록·수정 | 5종 input add/update 분기, 스크린샷 등록 성공 4곳 | `asset_type`, `method`, `result`=create/update |
| `asset_delete` | 삭제 | context `delete*` 5곳 | `asset_type` |
| `screenshot_parse` | AI 인식 성공률·한도 | 6개 import 결과 분기(성공은 `use-gemini-usage` `increment`) | `asset_type`, `result`=success/fail/empty/limit |
| `transaction_save` / `transaction_delete` | 거래 기록 사용 | trade/crypto/cash/loan-tx 입력·스크린샷 일괄·각 tx-view 삭제 | `asset_type`, `method`, `result`=reflected/unreflected/blocked/rollback |
| `share` (GA 권장명) | 공유카드·링크 바이럴 | `share-menu.tsx` 저장·공유·복사, `tool-menu.tsx` 링크 생성 | `method`=save/share/copy/link, `content_type`=카드 variant/link |
| `share_restore` | 링크 수신 전환 | `processShareToken`·`handlePin*` 결과 | `result`=success/invalid/pin_mismatch/cancel/ignored |
| `sync_action` (관측만) | 동기화 채택·오류율 | `enableSync`·`connect` 결과 후, `pushNow`/`pullNow`(수동만), 충돌 | `method`=enable/connect/push/pull, `result`=success/conflict/error |
| `data_action` | 백업 습관 | `exportAssetData`, `use-asset-import`, settings 전체 삭제·캐시 초기화 | `method`=export/import/clear_all/clear_cache, `result`, `source` |
| `app_lock` | 보안 기능 사용 | settings 잠금 설정·해제, `pwa-lock-screen` 해제 | `method`=enable/disable/unlock, `result` |
| `pwa_install` | 설치 전환 | `use-pwa-install`, `in-app-browser-gate` | `method`=prompt_view/accepted/dismissed/installed/inapp_move, `source` |
| `feature_use` | 부가 기능 사용 비교 | X-Ray 분류 요청, 세금 시뮬레이터 조정, 홈 팁, 공지, 의견 보내기, 테마 | `category`=xray/tax_sim/home_tip/notice/feedback/theme, `method`, `result` |

- [ ] AC6. 위 이벤트명·파라미터 키·값 외의 조합은 타입 오류로 컴파일되지 않는다.
- [ ] AC7. WHEN 화면이 바뀐다(`navigate`·뒤로가기·초기 진입), 시스템은 `page_view` 1회를 `page_path=/v/<viewToKey>`로 보낸다. 같은 화면 재렌더에는 보내지 않는다.
- [ ] AC8. WHEN 저장 전 자산 0건 → 저장 후 1건 이상이고, 그 저장이 사용자 직접 입력(수동·스크린샷)에 의한 것이다, 시스템은 `first_asset_saved`를 **기기당 1회만** 보낸다. 공유 복원·백업 가져오기·동기화 pull에 의한 0→N 전이는 제외한다.
- [ ] AC9. 동기화 관련 이벤트는 수동 동작(`enableSync`·`connect`·`pushNow`·`pullNow`)과 충돌에서만 발생하고, 60초 폴링·focus·online 자동 동기화에서는 발생하지 않는다.
- [ ] AC10. `setUserProps`는 앱 시작 시와 자산 수·동기화 상태가 바뀔 때 갱신된다. `app_mode`=pwa/web/inapp, `asset_count_bucket`=0/1/2-5/6+, `sync_enabled`=y/n, `onboarding_state`=new/wizard_done/skipped, `theme`=light/dark.
- [ ] AC11. WHEN URL에 `?ga-debug=1`이 있다, 시스템은 플래그를 저장하고 이후 모든 이벤트에 `debug_mode:true`를 붙인다. `?ga-debug=0`이면 해제한다.

### C. GA4 관리자 설정 가이드 (사용자 작업 — 구현 완료 보고에 포함)
1. 데이터 스트림 → 향상된 측정에서 "브라우저 기록 이벤트 기반 페이지 변경"을 **끈다**. 해시 전송과 page_view 중복을 막기 위해서다.
2. 맞춤 정의 → 측정기준 등록:
   - 이벤트 범위: `asset_type`, `method`, `result`, `source`, `category`, `step`, `nav_source`, `content_type`
   - 사용자 범위: `app_mode`, `asset_count_bucket`, `sync_enabled`, `onboarding_state`, `theme`
3. 핵심 이벤트로 지정: `first_asset_saved`, `tutorial_complete`, `share`. 필요하면 `sync_action`과 `data_action`도 지정한다(탐색에서 `method` 필터).
4. 탐색 분석 템플릿:
   - **활성화 퍼널**: `welcome_view` → `onboarding_action` → `wizard_step(step=start)` → `first_asset_saved` → (7일 내) `page_view`
   - **스크린샷 퍼널**: `asset_add_start(method=screenshot)` → `screenshot_parse(result=success)` → `asset_save(method=screenshot)`. `asset_type`으로 분류한다.
   - **경로 탐색**: 시작점 `page_view(page_path=/v/home)`
   - **세그먼트 비교**: `app_mode`·`asset_count_bucket`별 `feature_use`·`share`·`sync_action`
5. 데이터 보관 기간을 14개월로 설정한다.
6. 검증: `?ga-debug=1`로 접속해 DebugView에서 이벤트·파라미터를 확인한다. 이때 `page_location`에 `#`·`?`가 없어야 한다.

## 5. 영향 표면
- 화면:
  - 이벤트 계측 지점만 추가하고 UI는 변경하지 않는다.
  - 대상: 웰컴, 마법사, 튜토리얼, FAB, 자산 입력 5종, 스크린샷 import 6종, 거래 입력·뷰, 공유카드·공유 링크, 설정, 잠금화면, PWA 설치·인앱 게이트, X-Ray, 세금 시뮬레이터, 홈 팁, 의견 보내기.
- 컨텍스트·유틸:
  - 신규 `src/lib/analytics/ga.ts`, `src/types/gtag.d.ts`.
  - 변경: `config/app.ts`(`gaId`), `layout.tsx`(config·디버그), `navigation-context.tsx`(page_view), `asset-data-context.tsx`(first_asset_saved·delete·share_restore 계측), `tutorial-store.ts`, `local-storage.ts`(`gaFlags`), `asset-storage.ts`(keepKeys).
- API·캐시 키: 없음. GA 직접 전송이고 서버 경유가 없다.
- **건드리지 않는 것**:
  - 동기화 로직(`cloud-sync/*` 처리 흐름. `track` 1줄 추가만 허용).
  - `/api/*`.
  - 자산 저장 경로의 동작.
  - `ga-optout`과 `gaEnabled` 정책.
  - 기존 화면 UI.
