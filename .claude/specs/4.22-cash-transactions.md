# S-4.22 현금성 자산 입출금 거래내역

> 상태: 완료 | 브랜치: `issue-4.19` (기존 작업 브랜치 유지) | 작성 2026-07-25

## 1. 왜
현금 자산은 단일 `balance` 잔액만 있어 "언제 얼마가 들어오고 나갔는지" 이력이 없다. 그래서 매월 월급·목돈 같은 **외부 유입(소득·저축)** 을 자산 성과·습관 분석에 쓸 수 없다. 홈 원인분해는 현금 증감을 "저축·신규 매수"로 뭉뚱그리고, 성적표 습관 축은 저축 행위를 시세 상승과 구분하지 못한다.

## 2. 무엇 (범위)
- 포함:
  - 현금 자산에 **입금/출금 거래내역**(주식 `transactions` 패턴 답습, 잔액 선형 가감). 입금에 **정기/비정기** 구분.
  - 반영(reflected) ON 시 `cash[].balance` 자동 가감, OFF는 로그만(과거 소급 기록).
  - 홈·성적표 **원인분해에 `income`(소득·저축 유입) cause 분리** 노출.
  - 성적표 **습관(habit) 축에 저축 규칙성 신호 + 현금 입출금 딥링크**.
  - 공유 토큰·JSON 내보내기에 현금 거래내역 포함.
- **제외**:
  - 소득원 세분(근로/이체/이자 등) — 자산 관점 유의미 축은 "정기성"뿐이라 하지 않음.
  - 내부 계좌 간 이체의 복식부기(현금↔현금 이동 상쇄) — 단일 계좌 입출금만.
  - 예산·지출 카테고리(식비 등) 가계부 기능.
  - 주식처럼 스크린샷 일괄 가져오기(`addTransactionsBatch` 대응) — 이번 제외.
  - 예적금 만기·금리(별도 S-4.19-deposit-maturity 소관).

## 3. 수용 기준
- [ ] AC1. 현금 카드에서 "입출금 내역" 진입 → 입금/출금 기록 폼(금액·날짜·메모, 입금 시 정기/비정기 토글, 반영 ON/OFF)과 로그 뷰(기간·유형 필터, 총입금·총출금·순유입 통계).
- [ ] AC2. WHEN 반영(reflected) ON 입금을 기록하면, 시스템은 해당 `cash.balance`를 `+amount` 하고 로그+잔액을 **단일 저장**한다. 출금이면 `−amount`.
- [ ] AC3. WHEN 반영 ON 출금액이 현재 잔액을 초과하면, 시스템은 기록을 **차단**(restrict)한다(주식 oversell 대칭).
- [ ] AC4. WHEN 반영 ON 거래를 삭제하면, 시스템은 `cash.balance`를 역가감하고 로그+잔액을 단일 저장한다. 미반영 거래 삭제는 잔액 불변.
- [ ] AC5. WHEN 거래 날짜가 오늘 기준 3년(`TRANSACTION_RETENTION_YEARS`) 밖이면, 시스템은 저장 시 해당 로그를 정리(prune)한다.
- [ ] AC6. 원인분해 기간 내 **반영된** 현금 거래 순액(Σ입금−Σ출금, KRW 환산)이 `income` cause로 분리 표시되고, 나머지 `saving`은 투자자산 신규 매수분만 남는다. **표시 금액 합계 = deltaNet 불변**(price는 잔차 유지).
- [ ] AC7. WHEN 현금 입금이 최근 N개월(기본 6) 중 M개월에 관측되면, 시스템은 습관 축 '꾸준함' 점수에 저축 규칙성을 반영한다(가중치 0.1·재정규화·티어 로직 불변). 현금 거래가 없으면 기존 순자산-상승-개월 방식으로 폴백.
- [ ] AC8. 습관 축 카드는 현금 거래가 있을 때 현금 입출금 뷰로 딥링크된다.
- [ ] AC9. WHEN 공유 URL을 생성·복원하면, 시스템은 현금 거래내역을 손실 없이 왕복하고 부모 현금(`cashIdx`)에 재연결한다. 구버전 공유 토큰(현금 거래 미포함)도 정상 파싱한다(R3).
- [ ] AC10. 구버전 백업 JSON(현금 거래 필드 없음)이 `applyImportedPayload`를 통과한다(신규 필드는 optional/default).

## 4. 데이터 계약

| 항목 | 확인 |
| --- | --- |
| `assetDataSchema` 변경 | `cashTransactions: z.array(cashTransactionSchema).default([])` 추가(최상위, 주식 `transactions`와 동형). `cashSchema` 자체는 불변. 신규 필드 default라 optional 요건 충족 |
| 구버전 백업 JSON 복구 | `applyImportedPayload` parse 통과 — `cashTransactions` 부재 시 `.default([])`로 복구, 필수 필드 미추가 |
| 신규 `STORAGE_KEYS` | 없음 — `STORAGE_KEYS.assetData` 단일 저장 경로 재사용 |
| 공유 토큰 직렬화 | 변경 — packV7 꼬리에 현금 거래 섹션 추가(`cashIdx` 참조), unpackV7 복원. 구 `packV7~v72Z` 파싱 유지(꼬리 추가라 기존 섹션 오프셋 불변, R3) |
| cloud-sync 비교 대상 | `getComparablePayloadString` **포함**(사용자 편집분이라 push 유발이 정상, 파생·타임스탬프 아님 → R14 핑퐁 없음) |
| 마이그레이션 | 불필요 — 신규 빈 배열 default, loose 스키마가 부재 허용 |
| 통화·환율 | 현금 거래는 `cash.currency` 따름. 원인분해 income 집계 시 KRW 환산(USD·JPY→`/100` 분기, 기존 `mul` 재사용) |
| 비활성 종목 | 무관 — 현금 자산 전용 |

## 5. 영향 표면
- 화면: 현금 상세 탭(`cash-tab` 진입 버튼) · 신규 현금 입출금 뷰(`cash-transactions` 탭) · 신규 입력 폼 · 홈 헤더 원인 문구 · 지난 접속 브리핑 · 성적표(원인분해·습관 축).
- 컨텍스트·유틸: `asset-data-context`(CRUD 단일저장 3곳) · 신규 `lib/cash-tx-utils.ts` · 신규 `stores/cash-tx-view-store.ts` · `lib/report/asset-report.ts`(income cause) · `lib/report/asset-grade.ts`(습관 신호).
- API·캐시 키: 없음(외부 API 무관).
- **건드리지 않는 것**: `cashSchema`(잔액 진실원본 유지) · `getAssetSummary`/`computeNetAsset`/스냅샷 계산 · 주식 `transactions`·`trade-utils`(참조만) · 예적금 만기(S-4.19).
