# S-4.21 부동산 실거래가 연동

> 상태: 승인 | 브랜치: `issue-4.21-realestate-price` | 작성 2026-07-21

## 1. 왜

부동산은 앱에서 유일하게 시세(`currentValue`)가 100% 수동 입력인 자산군이다(자동 갱신 로직·안내 전무). 주식(KIS)·코인(업비트)과 달리 외부 시세가 없어 부동산 평가·수익률이 사용자 기억에 의존하고, 오래 방치되면 순자산 전체가 부정확해진다.

## 2. 무엇 (범위)

- 포함:
  - 국토교통부 실거래가 공개 API로 **최근 실거래 유사치**를 조회해 `marketEstimate`(추정 시세)로 **병기**(사용자 `currentValue`는 유지).
  - 사용자는 **주소 + 동·호수**만 입력 → 주소해석(법정동코드·단지명)·평형해석(전용면적) 자동. 평형 자동해석 실패 시 실거래 면적 목록에서 **수동 선택** 폴백.
  - 종류: 아파트·오피스텔·빌라(연립다세대)·단독/다가구·상가·사무실. `type` enum에 `officetel`·`villa` 가법 추가.
  - **접속 시 자동 조회 + 내부 캐싱**(주식 현재가 오케스트레이션과 동일 계층). 서버 `cache-storage` 시군구·월 단위 캐시.
- **제외** (이번에 하지 않는 것):
  - **토지**(land) 실거래 매칭.
  - `marketEstimate` 등 신규 필드의 **공유 토큰 전파**(pack/unpack 포맷 확장 안 함 — 구 파싱 유지, 수신자는 재조회/재입력).
  - `currentValue` 자동 덮어쓰기(사용자가 "반영" 버튼으로만).
  - 지도·주소 자동완성 등 고급 UI, 실거래가의 시계열 차트.

## 3. 수용 기준

- [ ] AC1. WHEN 사용자가 부동산 종류·주소·동·호수를 입력하고 "검색"하면, 시스템은 주소를 법정동코드(LAWD_CD 5자리)·법정동·단지명으로 해석하고, 종류별 MOLIT 데이터셋에서 최근 실거래를 매칭해 `marketEstimate`·`marketEstimateDate`를 세팅한다.
- [ ] AC2. WHEN 평형(전용면적) 자동해석이 실패하면, 시스템은 해당 단지 실거래의 전용면적 목록을 Select로 제시해 사용자가 수동 선택하게 한다.
- [ ] AC3. 추정 시세는 `currentValue`와 **병기**하며, `currentValue`는 사용자가 "반영" 버튼을 누를 때만 갱신된다.
- [ ] AC4. WHEN 앱 접속 시 `regionCode`·종류·전용면적이 갖춰진 부동산이 있으면, 시스템은 (캐시 우선) 실거래를 재조회해 `marketEstimate`를 갱신한다. 매칭 정보가 없는 항목은 자동조회를 스킵하고 안내 CTA만 노출한다.
- [ ] AC5. WHEN 서비스키 미설정·외부 API 실패면, 시스템은 등록·사용을 막지 않고 안내(토스트/배너)만 하며 마지막 캐시값을 유지한다.
- [ ] AC6. 비단지형(단독·상가·사무실)은 법정동+면적 근사임을 UI에 명시한다.
- [ ] AC7. 실거래가는 시군구+월 배치라 "최근 실거래 건(기준일)"로 표기하며 "실시간"으로 오인시키지 않는다.
- [x] AC8. 시스템은 데이터셋별로 다른 면적·이름 필드를 각각 파싱한다(apt/offi/rh=`excluUseAr`, sh=`totalFloorAr`, nrg=`buildingAr`, 폴백 `plottageAr`). 서로 다른 면적 종류(`areaKind`)는 절대 섞어 비교하지 않는다.
- [x] AC9. WHEN 단지명으로 좁힐 수 없는 종류(`matchBy: "area"` = 단독·상가·사무실)에서 면적을 모르면, 시스템은 추정치를 계산하지 않고 면적 입력을 요구한다. (시군구 전체 최근 거래 1건이 추정치가 되는 오매칭 차단)
- [x] AC10. 유사 거래가 없으면 같은 법정동·같은 면적 종류·면적 ±30% 표본의 ㎡당 단가 중앙값 × 사용자 면적으로 추정하되, **표본 3건 미만이면 추정치를 내보내지 않는다.** 추정 결과는 등급(`exact`/`similar`/`approx`/`estimated`)·표본 수와 함께 표기한다.

## 4. 데이터 계약

| 항목 | 확인 |

| 구버전 백업 JSON 복구 | 통과 — 신규 필드 optional, enum은 값 추가라 기존 데이터에 없음. `applyImportedPayload` 무영향 |
| 신규 `STORAGE_KEYS` | 없음 — 추정치는 `assetData`의 realEstate 항목에 저장, 실거래 목록 캐시는 서버 `cache-storage`가 담당 |

| cloud-sync 비교 대상 | `getComparablePayloadString`에서 파생값 `marketEstimate*` 전 필드(추정가·일자·근거·면적·등급·표본수) **제외**(R14 핑퐁, 주식 currentPrice와 동일 이유). `regionCode`·`complexName`·`exclusiveArea`·`addressDetail`·`dongName`·`hoName`은 실사용자 입력이라 비교 포함 |
| 주소 해석 경로 | **다음(카카오) 우편번호 서비스 우선** — 검색 결과의 `sigunguCode`(=LAWD_CD)·`bname`·`buildingName`으로 폼을 채우므로 카카오 로컬 `op=resolve` 호출이 불필요하다. `regionCode`가 없는 레거시 수기 주소에만 `resolve`를 **폴백**으로 호출(`use-daum-postcode.ts`, 스크립트는 검색 버튼 클릭 시 1회 동적 로드·실패 시 수동 입력으로 degrade) |
| 마이그레이션 | 불필요 — optional 필드·enum 가법 |
| 통화·환율 | 무관 — 부동산은 KRW |
| 비활성 종목 | 무관 |
