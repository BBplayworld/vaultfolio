# S-4.18 자산 성적표 (Asset Report Card)

> 상태: 완료 | 브랜치: `issue-4.18-award` | 작성 2026-07-21

## 1. 왜

사용자는 자기 자산의 숫자(순자산·수익)는 보지만 **"내 자산 관리가 통념 기준으로 잘 되고 있는가"**를 판단할 기준이 없다. 성장·수익의 질·레버리지·분산·습관을 한눈에 채점해주는 참고 지표가 없어, 무엇을 개선해야 하는지 스스로 알기 어렵다. (투자 조언이 아니라 사용자 자신의 자산 구조·습관에 대한 사실 기반 채점.)

## 2. 무엇 (범위)

- 포함:
  - 5축 별점(0~5, 0.5 단위) + 트로피 티어(bronze/silver/gold/platinum): 장기 성장·수익의 질·레버리지 건전성·분산·투자 습관.
  - 측정 불가 축은 `null`(회색), 종합은 **측정 가능한 축만 가중 재정규화**(신규 사용자도 등급 산출).
  - 축별 이유(reason)·개선 행동(action), 일부 축은 관련 화면으로 딥링크.
  - 레버리지 수지(이자 vs 투자 수익), 순자산 변화 원인분해, AI 평가 프롬프트.
  - 등급 이력화: 전 축 확정(non-pending) 시 오늘/이번 달 스냅샷에 `grade` 기록 → 전일·전월 대비 변화 표기.
  - **이번 이터레이션 변경**: (a) 채점 임계값을 `GRADE_THRESHOLDS`로 상수화(로직 불변), (b) 무부채 레버리지 축 4.0→**5.0(건전성 만점)** 재설계, (c) 신용대출로 산 코인·부동산 수익 제외에 대한 안내 문구 강화.
- **제외** (이번에 하지 않는 것):
  - 암호화폐·부동산 **레버리지 수익의 분모 보정**(정밀 수익 귀속). 데이터 한계(코인 1년 전 가격·부동산 시세 자동갱신 부재)로 측정 불가 → 문구 안내로만 처리.
  - 임계값의 사용자 설정 UI(상수화까지만, 노출/편집 없음).
  - 성적표 값의 공유 토큰/외부 공유 노출 확장.

## 3. 수용 기준

- [x] AC1. 자산이 하나도 없으면 "자산을 등록하면 성적표가 계산됩니다" 안내만 표시한다.
- [x] AC2. 측정 가능한 축이 1개 이상이면 종합 별점·티어를 산출한다(측정 가능한 축만 가중 재정규화). 측정 불가 축은 회색 별 + "측정불가"로 표기한다.
- [x] AC3. WHEN 부채가 없으면(loanBalance ≤ 0), 시스템은 레버리지 건전성 축을 **5.0(건전성 만점)**으로 산출하고 "부채가 없어 이자 부담 리스크가 0 — 건전성 만점" 취지로 표기한다.
- [x] AC4. WHEN 자기자본이 0 이하이고 부채가 있으면, 시스템은 레버리지 축을 0.5(자본잠식)로 산출한다.
- [x] AC5. 채점 컷(CAGR 15/10/5%, 부채비율 40/60%, 평균금리 6%, 배당수익률 1.5%, 집중도 0.6/0.35, 외화비중 50/70%, 티어 4.5/3.5/2.5)은 `GRADE_THRESHOLDS` 단일 소스에서 온다. 상수화 전후 동일 입력의 산출 등급은 **무부채 축을 제외하고 불변**이어야 한다.
- [x] AC6. WHEN 전 축이 non-pending 확정되면, 시스템은 오늘자 daily·이번 달 monthly 스냅샷의 `grade`에 결과를 기록한다(동일 값 재기록은 스킵). 과거 스냅샷 `grade`는 소급 변경하지 않는다.
- [x] AC7. 이전 스냅샷 `grade`가 있으면 종합·축별 변화(▲▼)와 티어 승·강등을 표기한다.
- [x] AC8. WHEN 투자 레버리지(부동산 담보 제외 대출)가 있고 코인 또는 부동산을 보유하면, 시스템은 "암호화폐·부동산 수익은 측정 불가로 비교 제외" 캡션과, 신용대출로 산 코인·부동산 수익이 낮게 보일 수 있다는 InfoHint 안내를 노출한다.

## 4. 데이터 계약

| 항목 | 확인 |
| --- | --- |
| `assetDataSchema` 변경 | 없음 — `grade`는 `assetData`가 아니라 **스냅샷 타입**의 optional 필드(`SnapshotGrade`, 이미 v3로 존재). 이번 이터레이션은 채점 로직만 변경, 스키마 무변경 |
| 구버전 백업 JSON 복구 | 영향 없음 — `grade`는 optional. 없는 스냅샷도 `applyImportedPayload` 통과, 성적표는 재계산됨 |
| 신규 `STORAGE_KEYS` | 없음 — `grade`는 기존 `dailySnapshots`·`monthlySnapshots` 키에 저장 |
| 공유 토큰 직렬화 | 영향 없음 — `grade`는 optional이라 구 `packV7` 파싱과 호환(미포함/포함 무관). 이번 변경은 직렬화 포맷 무변경 |
| cloud-sync 비교 대상 | 영향 없음 — `getComparablePayloadString`이 **오늘자 daily·이번 달 monthly를 이미 제외**하고, `grade`는 그 두 곳에만 기록되므로 등급 확정이 push를 유발하지 않음(R14 핑퐁 없음). 과거 스냅샷 grade는 불변 |
| 마이그레이션 | 불필요 — optional 필드, 기존 데이터 그대로 유효 |
| 통화·환율 | 관련 — 분산 축 외화비중·환노출은 `computeFxExposure`(USD·JPY 100엔 기준 `/100`) 재사용 |
| 비활성 종목 | 관련 — `delisted`는 외화노출·평가에서 제외(computeFxExposure/computeNetAsset 기존 정책 준수) |
