## 절대 규칙

**대조와 보고만 한다. 미충족을 발견해도 코드를 고치지 않는다.** 수정은 사용자 승인 후 별도로.
판정 근거는 반드시 `파일:라인`으로 댄다 — 추측으로 충족 판정하지 않는다.

## 2. 데이터 계약 대조 (P0 게이트)

§4에 "변경 있음"으로 적힌 모든 행을 코드로 확인한다.

- **스키마 신규 필드가 `.optional()`인가** — 필수면 즉시 **P0** 보고(구버전 백업 JSON이 `applyImportedPayload` parse에서 throw → 복구 불능)
- 공유 토큰에 필드를 추가했다면 구버전 unpack 경로가 보존됐는가 (R3)
- 신규 저장 키가 `STORAGE_KEYS` 상수를 경유하는가(문자열 하드코딩 금지), `clearAssetData` keepKeys 판단이 주석으로 남았는가
- 마이그레이션 id가 명세와 동일한가 (변경 시 전 사용자 재실행)
- 신규·변경 캐시 키의 tickerList에 `.sort()`가 있는가 (R1)
