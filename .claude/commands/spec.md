## 절대 규칙

**이 커맨드 실행 중 Edit/Write 대상은 `.claude/specs/*.md` 뿐이다. 소스 코드는 읽기만 한다.**
모르는 항목을 추측으로 채우지 않는다 — 사용자에게 묻는다.

## 1단계 — 명세가 필요한지 판정

[.claude/specs/README.md](../specs/README.md)의 판정 체크리스트를 **코드 탐색으로 검증**한다(추측 금지).

- 스키마 영향은 `src/types/asset.ts`, 저장 키는 `src/lib/local-storage.ts`를 실제로 읽고 판단
- 예상 수정 파일 수는 Grep으로 호출처를 세어 산정

**해당 항목이 0개면 명세를 만들지 않는다.** "명세 불필요 — 이유: ○○. 바로 진행할까요?"만 출력하고 종료한다. 작은 변경에 명세를 강요하면 체계 자체가 버려진다.

## 2단계 — ID·브랜치 결정

`git branch`와 `git log --oneline -20`으로 최신 이터레이션 번호를 확인하고 다음 번호를 **제안한 뒤 확인받는다**.

- 파일: `.claude/specs/{번호}-{slug}.md` · 명세 ID: `S-{번호}`
- 브랜치: `issue-{번호}-{slug}` (기존 관행 유지)

## 3단계 — KB 선행 읽기

작업 유형에 맞는 KB만 읽는다([CLAUDE.md](../../CLAUDE.md) 참조 테이블).
스키마 영향이 있으면 `types-and-schemas.md` + `dev-rules.md`, 동기화·공유면 `api-reference.md`, 화면 추가면 `design-system.md` + `components.md`는 필수.
