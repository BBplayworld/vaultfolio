## 3. 서버 전송
- 요청: `GET /api/finance/price-history?ticker=<T>&range=1y|5y`. 새로 나가는 값은 `range` 하나. `ticker`는 이미 profit·market-index 라우트로 나가는 값이다.
- 수량·평단·매수일·거래일·계좌·평가금액은 보내지 않는다. 응답은 공개 시세뿐이고 사용자 보유 정보와 무관하며, 같은 URL이면 모두 같은 응답이라 서버가 보유 여부를 알 수 없다(보유 종목 목록은 이미 profit 요청에 포함돼 정보 증가 0).
- 클라이언트 가드(서버 요청 0 조건): 티커 없음·`category==="unlisted"`·`inactiveStatus==="delisted"`면 훅 `enabled:false`. 5년은 탭 시에만 `enabled`.

## 4. 판정 ① 가격 이력 라우트
- **새 라우트로 한다.** profit은 `{ticker → ref/prev 한 점}` 계약·`period` 5종·ref 캐시 키 구조에 묶여 있어 시계열을 얹으면 응답 형태가 갈리고 1년 TTL 쓰레기 키 위험(11-09 학습)이 늘어난다. market-index 라우트가 이미 "시계열 + `cdnCacheHeaders`" 선례다.
- 입력 검증: `guardRequest(req,{route:"price-history", l1PerMinute:60})` → `isOneOf(range,["1y","5y"])` 아니면 `badRequest()` → `ticker = searchParams.get("ticker")?.toUpperCase()`를 `parseTickerList(raw,1)[0]`로 검증(없으면 400). 그 밖의 쿼리 키는 읽지 않는다. 시장 판별은 `classifyTickers([t])`(`kr` / `us` / 둘 다 아님 → 빈 `points`, KIS 호출 0).
- KIS 호출
  - 국내 `FHKST03010100` `inquire-daily-itemchartprice`: `FID_COND_MRKT_DIV_CODE=J`, `FID_INPUT_DATE_1`(시작)·`FID_INPUT_DATE_2`(종료), `FID_PERIOD_DIV_CODE=D`(1년) / `W`(5년), `FID_ORG_ADJ_PRC=0`. 샘플 docstring 확인: "0=수정주가, 1=원주가", **한 번에 최대 100건**, `output2` 내림차순. 현행 `fetchDomesticHistoricalPrice`(741행)와 같은 URL·헤더.
  - 해외 `HHDFS76240000` `dailyprice`: `GUBN=0`(일)/`1`(주), `MODP=1`(수정), `BYMD`=종료일, 회당 100행(내림차순). 샘플 저장소에 해외 예제가 없어 문서 확인은 못 했다. 기존 코드(796행)는 `NCNT=5`를 넣고 "최대 5개 row"로 쓰는데 공식 파라미터가 아닐 수 있다. **시계열 호출은 `NCNT`를 빼고, preview에서 첫 응답이 100행인지 확인**한다(5행이면 페이징 계산이 틀어지므로 development 첫 확인 항목).
- 페이징(순차, 병렬 금지): 종료일 = 오늘(KST 기준 영업일 보정 없이 오늘). 시작일 = 오늘−365일(1년) / −5년(5년). 회차마다 종료일 = 직전 회차 가장 오래된 날짜 − 1일, 시작일보다 오래되면 중단, 응답이 100행 미만이면 중단(상장 이후 끝). **최대 회차 상한 4**(1년 일봉 약 3회, 5년 주봉 약 3회, 여유 1). 상한은 무한 루프 방지용이다. 해외 EXCD는 `marketToExcd`(profit 라우트 33행, 비공개 함수 → `finance-service.ts`로 export 이동 또는 소규모 복제. 이동 쪽이 중복 없음)로 `US_TICKERS` 마스터에서 얻고, 없으면 첫 회차만 NAS→NYS→AMS 시도해 성공한 EXCD로 이후 회차 고정(3배 호출 방지).
- 호출량: 종목당 1년 최대 3~4회, 5년 3~4회. `withinUpstreamBudget("kis", 4)`(전역 분당 900) — 거부 시 외부 호출 0, 기존 '일시 오류' 응답(503) → 화면 오류 줄. `getKisAccessToken`·`recordKisSuccess/Failure` 기존 패턴 사용. `maxDuration=20`, 회차당 `fetchWithTimeout` 기존.
- 캐시: **CDN 캐시만** — 시계열은 하루 한 점만 바뀌므로 `cdnCacheHeaders(6*3600, 3600)` 권장(profit의 정시 슬롯 `secondsUntilNextHour`는 쓰지 않음)(키=URL=ticker+range, 사용자 무관). 실패·빈 응답은 `no-store`. **줄이기 제안**: `ICacheStorage`에 시계열 get/set을 추가하지 않는다(인터페이스+메모리+Redis 구현 3곳 수정). 활성 6명 규모에서 CDN으로 충분하고, 이후 필요해지면 추가한다. spec의 "서버 공유 캐시"는 "CDN 공유"로 충족된다고 본다 — 이견이면 `getDividend/setDividend`류 메서드 1쌍 추가(+약 40줄)로 확장 가능.
- 응답 정규화: `{ ticker, range, currency:"KRW"|"USD", interval:"D"|"W", points:[{d:"YYYY-MM-DD", c:number}] , listedFrom?:string }`. 오름차순, 날짜 중복 제거, `c>0`만, 시작일 이전 제외. 점이 시작일보다 늦게 시작(회차 중단이 100행 미만)이면 `listedFrom=첫 점 날짜`(화면 "상장 이후 기간만 있어요" 판정). 국내 `stck_bsop_date`/`stck_clpr`, 해외 `xymd`/`clos`.
- 진행 중 봉: 5년 주봉의 마지막 봉은 이번 주 현재가일 수 있다 → 그대로 둔다(종가=현재가). 등락률은 `points[0].c` 대비 `points.at(-1).c`로 라우트가 아니라 화면(순수 함수)에서 계산.

## 5. 판정 ② 매수 점 위치
- **차트(수정주가) 위 위치, y는 그날(그 주) 종가.** 거래 단가는 y로 쓰지 않고 탭 시 표시만 한다. 날짜→봉 매핑은 "매수일 이상인 첫 봉"(`placeBuyDots(points, buys)`): 일봉은 주말·휴일 매수가 다음 영업일 봉, 주봉은 봉 날짜가 그 주 마지막 영업일이므로 그 주 봉에 정확히 들어간다. 첫 봉보다 앞이면 창 밖(건수), 마지막 봉보다 뒤면 마지막 봉에 붙인다. 같은 봉에 여러 건이면 점 1개 + 건수/목록(탭 시 모두).
- 점 대상: 그룹 `stocks[].transactions` 중 `type==="buy"`(`Stock.transactions`, `trade-utils.ts` 11행 타입). `purchaseDate`는 쓰지 않는다(테스트로 고정).
- 평단선은 `mergeStockGroup(items).averagePrice`(종목 통화). **수정주가 차트와 평단 불일치**: 분할 종목은 평단(원단가 기준)이 수정 차트 범위 밖일 수 있다. 범위 판정은 `avgLineStatus(avg, min, max)` → `in | above | below`(ui.md의 `평단 ↑/↓`). 이는 spec이 정한 동작이고, 거래 단가를 수정 환산하지 않는다(분할 비율을 모르므로 시도하지 않는다).

## 8. C76 수용 6구간 테스트 계획 (vitest)
순수 함수·라우트 중심, 렌더 테스트는 최소.
1. 거래 0·분할 0: `placeBuyDots(points, [])` = 점 0, 화면 렌더 `stock-page-no-trades` 존재, `purchaseDate`만 있는 Stock에서 점 0(완료기준 6).
2. 증권사 2곳: 2개 Stock 합산 → 평단선 = `mergeStockGroup().averagePrice`(펼침 평단과 같은 값 단언), 점은 두 계좌 buy 모두.
3. 1년 밖 매수: 매수일이 창 시작 이전 → `outsideCount` N, 5년 points에서는 점으로 배치. `1y→5y` 전환 시 요청이 `range=5y`로 1회 추가(훅 테스트).
4. 분할 전 매수: 수정 차트(점 가격 수정) + 거래 단가 원값(예: 단가 1,000,000 vs 차트 100,000) → 점 y = 해당 봉 종가, 상세 문구에 원단가. y 계산에 `tx.price`가 쓰이지 않음을 입력 변화(단가만 바꿈 → y 불변)로 단언.
5. 상장 1년 미만: 라우트 `buildPricePoints`가 100행 미만 1회로 중단 → `listedFrom` 설정, 화면 정의 줄에 `상장 이후 기간만 있어요`.
6. 비상장·상장폐지·티커 없음: 훅 `enabled=false` → fetch mock 호출 0, `stock-page-no-price`.
