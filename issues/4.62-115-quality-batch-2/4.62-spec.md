## 4. 사용자 흐름 (수정 후)
1. **A 홈 팁 유지**: 홈 마운트 동안 한 번 보여 준 backup·refresh 팁은 effect가 다시 돌아도 그 종류의 '오늘 노출' 판정만 건너뛴다. 나머지 조건(백업 필요 / 보유 자산군 중 오래된 것 존재)이 참이면 같은 팁을 유지한다. 권고 구현은 `pickHomeTip`에 `keepShown?: "backup" | "refresh"` 입력을 추가하는 것이다. 순수 함수라 테스트할 수 있다. 우선순위 순서는 그대로라 더 높은 순위(새 공지)가 새로 생기면 그쪽이 이긴다.
   - **C5 구현 제약**: `keepShown`은 해당 종류의 `nudgeShownOn === today` 검사만 건너뛰는 **선택 인자**다. 기본값(미지정)은 현행과 출력이 같다. `shouldShowBackupNudge`·`shouldShowRefreshNudge`에 옵션 1개 추가만 허용한다. `pickHomeTip`의 결산·세금·공지 분기와 결산 창 정의는 **diff 0**이다.
   - 유지 대상은 이번 마운트에서 실제로 승자였던 종류 1개뿐이다(ref로 기억). 승자가 아니었던 종류에는 적용하지 않는다.
   - 사용자가 팁을 누르거나(activate) 닫으면 유지 표시를 해제한다. 그래야 맞추기 저장 뒤 같은 팁이 되살아나지 않는다.
   - 결산 창 안 백업 팁 대상 기기: 지금은 백업 팁이 약 1초 뒤 결산 팁으로 바뀌었다. 수정 뒤에는 그 마운트 동안 백업 팁이 유지되고 결산 팁은 다음 홈 진입(재마운트)부터 보인다. 원래 우선순위(백업 > 결산) 회복이며, 결산 창·세션 닫기 정책은 그대로다.
   - 조건이 거짓이 되면(그 자산군을 맞춤, 백업함) 현행대로 다음 판정을 따른다.
   - 다른 화면에 갔다가 홈으로 돌아오면(재마운트) 현행 '하루 1회' 그대로 다시 뜨지 않는다.
   - GA view는 같은 팁이면 1회(`homeTipViewKey` 그대로)다.
2. **B 손익 0**: `ProfitMetric`의 판정(`Math.round(profit) === 0` → 부호 없음, `text-muted-foreground`, 금액 `0`, 수익률 부호 없음)을 헬퍼(예: `profitTone(profit)` → `{ isZero, sign, colorClass }`)로 꺼낸다. 2절 B의 9곳 + 부동산 '실투자금 수익률'(C6, 수익률만 0 판정)과 ProfitMetric 자신이 이 헬퍼를 쓴다. **헬퍼는 상세 화면 전용**이다(`ProfitMetric`과 같은 파일 또는 detail 유틸). 공용 `theme.ts`(`getProfitLossColor`)·결산·Hero·성적표는 diff 0. 환차손익(:141·:665)·등락 칩(:274)은 다른 지표라 범위 밖이다. 0이 아니면 현행과 같다. 공유 캡처(`screenshotMode`) 주식 카드도 같은 규칙을 따른다. `hideAmounts`일 때 금액 부호를 숨기는 규칙은 유지한다.
3. **C 되돌리기**: 저장 경로 변경이 아니다(cto 판정). `secretasset_asset_refresh`는 기기 로컬 UI 메타이고 동기화·내보내기 대상이 아니며, 적용 때 이미 같은 키·형식으로 쓰고 있다. assetData 저장(`saveData`)·새 키는 건드리지 않는다.
   - **C1** 원복 값은 `undoRef` 사본 `{entries, done, prevRefreshedAt, appliedAt}`에 담는다. 적용 직전 `lastRefreshedAt(kind)` → `prevRefreshedAt`, `markCategoryRefreshed`가 쓴 값 → `appliedAt`. 결과 화면 버튼과 닫은 뒤 토스트가 **같은 사본**을 쓴다.
   - **C2** compare-and-restore: 되돌리기에 성공했고 현재 `categories[kind] === appliedAt`일 때만 원복한다. 그 사이(토스트 8초) 다른 경로로 다시 맞췄다면 그 기록을 지우지 않는다. 쓰기는 `writeMeta` 병합을 재사용해 `nudgeShownOn`을 보존한다. `prevRefreshedAt`이 null이면 그 자산군 키만 지운다. `asset-refresh-status.ts`에 원복 함수 1개를 추가하고 신호는 보내지 않는다.
   - **C3** `handleClose`의 복귀 신호 조건을 `step==="result" && u && !u.done`으로 바꾼다(현행 `applied = step==="result"`, :209-211). 결과 화면에서 되돌린 뒤 [닫기]·Esc로 닫으면 `notifyCategoryRefreshed`를 보내지 않는다(복귀 목록 없음). 되돌리기가 실패하면(`u.done=false` 복구) 원복도 신호 생략도 하지 않는다(데이터는 적용 상태 그대로, 복귀 목록 현행대로).
   - vitest 4경로: ① 결과 화면 되돌리기 → 닫기(원복·신호 없음) ② 닫은 뒤 토스트 되돌리기(원복) ③ 되돌리기 실패(원복 없음·신호 있음) ④ 이전 값 null(그 자산군 키만 삭제, `nudgeShownOn`·다른 자산군 보존). 추가로 appliedAt 불일치(그 사이 재맞춤) 시 원복하지 않음.
4. **D 시트 포커스**: FAB 시트 `SheetContent`에 `onCloseAutoFocus`를 단다. 순서는 이렇다. ⓪ **C7 1순위**: 시트에서 방법을 선택하면 명시 플래그(잔액 맞추기 `goAddRef`와 같은 방식, ref)를 세우고, 닫힘 시 플래그가 있으면 해제만 하고 아무것도 하지 않는다(다음 창이 포커스를 가짐, 타이밍 의존 없음). ① 보조: 시트 외 열린 `[role=dialog]`가 있으면 아무것도 하지 않는다. ② 보이는 '자산 업데이트' FAB(`[data-tutorial="tutorial-fab"]`, opacity-0 제외). ③ 시트를 열기 직전 포커스 요소(DOM에 남아 있을 때). ④ `main`(tabindex -1). 잔액 맞추기 창과 같은 함수를 공용으로 꺼내 쓴다. 꺼낼 때 4.60 잔액 맞추기 동작(`goAddRef`로 '새로 추가' 시 생략 · FAB → opener → main)은 바뀌지 않아야 한다. 공용 함수는 `state-and-utils.md`에 등록한다(KB 배치 시점). ## 5. 엣지 케이스
- 빈 데이터: 자산 0이면 팁·카드가 없다(현행). 허브 해당 자산군이 0건이면 손익 줄이 없다(현행).
- 일부 갱신: C에서 직접 고친 항목이 있어 일부만 되돌려진 경우(`skipped>0`)에도 원복한다. 되돌리기 의도를 따른다. 오늘 맞추기 전에 이미 다른 경로로 맞췄다면 이전 값이 오늘이라 ✓가 유지된다(사실).
- 오래된 데이터: A는 30일 경과 자산군이 여러 개면 첫 항목만 바뀔 수 있다(문구 재계산). 팁 종류는 유지된다.
- 첫 사용자: 백업 7일 유예, refresh 이력 없음 유예 규칙 그대로다. 첫 진입에 백업·최신화 팁이 없으면 A는 영향이 없다.
- 동기화 pull로 assetData가 바뀌어도 A는 같은 규칙을 따른다. 다른 기기에서 그 자산군을 맞췄다면 메타는 기기 로컬이라 팁이 유지된다(현행과 같은 기기 단위).
- 토스트 되돌리기는 이미 복귀 목록이 열려 있는 상태에서 일어날 수 있다. 이때 열린 목록의 상태 줄·✓는 닫기 전까지 남고, 다시 열면 사라진다. **알려진 한계(C47 기록 대상)**다.
- D: 상세 하위 탭(FAB 숨김)에서 PWA 하단 네비로 연 시트는 하단 네비 버튼으로 복귀한다. 홈 팁으로 연 시트는 팁이 사라졌으므로 `main`으로 복귀한다. 터치로 닫으면 포커스 링이 보이지 않아야 한다(focus-visible).
