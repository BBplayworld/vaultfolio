## 2. 쟁점 판정
**(1) C = 저장 경로 변경인가 → 아니다. 컷 불필요.**
- `secretasset_asset_refresh`는 기기 로컬 UI 메타다. 확인 결과 동기화·내보내기 대상이 아니다(`asset-storage.ts:501` 보존 키, 데모 주입만 직접 씀). 사용자 자산 데이터(assetData)도 아니다. 이미 적용 시점에 `markCategoryRefreshed`가 같은 키·같은 형식으로 쓰고 있다. 원복은 그 쓰기를 취소할 뿐이고 키·형식·마이그레이션 변화는 0이다. 위임 ④에 해당하지 않는다.
- **C1** 원복할 이전 값은 `undoRef` 사본(`{entries, done, prevRefreshedAt, appliedAt}`)에 담는다. 그래야 결과 화면 버튼과 닫은 뒤 토스트 두 경로가 같은 값을 쓴다.
- **C2** compare-and-restore: 현재 `categories[kind]`가 이번 적용 때 쓴 값(appliedAt)과 같을 때만 원복한다. 그 사이(토스트 8초) 다른 경로로 다시 맞췄다면 그 기록을 지우지 않는다. 쓰기는 `writeMeta` 병합을 재사용해 `nudgeShownOn`을 보존하고, 이전 값이 null이면 그 자산군 키만 지운다.
- **C3** `handleClose`의 복귀 신호 조건을 `step==="result" && u && !u.done`으로 바꾼다. 되돌리기에 실패하면(u.done=false 복구) 원복도 신호 생략도 하지 않는다. vitest는 4경로: 결과 화면 되돌리기→닫기, 토스트 되돌리기, 되돌리기 실패, 이전 값 null.

**(2) A 위험 → 수용. 결산 판정 diff 0 조건 아래 low.**
- 결산 팁 노출 변화: 결산 창 중에 백업 팁 대상(동기화 꺼짐·백업 30일+)인 사용자는 지금까지 백업 팁이 약 1초 뒤 결산 팁으로 바뀌었다. 수정 뒤에는 그 마운트 동안 백업 팁이 유지된다. 다른 화면에 갔다가 돌아오면 재마운트되어 결산 팁이 뜨므로 같은 날 도달은 가능하다. 이것은 원래 우선순위(백업 > 결산)를 회복하는 것이다. 결산 창·세션 닫기 정책은 그대로이므로, 대표가 패스한 '결산 팁 노출 기간·열람 후 숨김'(LEARNINGS 11-06)의 재도입이 아니다.
- **C4 #51 판독 영향**: 지금은 한 방문에서 view가 두 번(백업 + 결산) 찍혀 `home_tip` view가 부풀어 있다. 수정 뒤 view는 줄고 클릭률은 오른다. business-pm은 #51·#110 판독 메모에 "머지 시각 = home_tip view 분모 변경 경계, 전후 비교는 click·사용자 수 기준"을 적는다. direction의 지표(click 중 refresh 비중)는 click 기준이라 유효하다.
- **C5** `pickHomeTip` 결산·세금·공지 분기 diff 0. `keepShown`은 해당 종류의 `nudgeShownOn===today` 검사만 건너뛰는 선택 인자로 구현하고, 기본값은 현행과 같아야 한다(`shouldShowBackupNudge`·`shouldShowRefreshNudge`에 옵션 1개 추가 허용). vitest: keepShown 유무 × 결산 창 안/밖에서 결산 판정 출력이 같아야 한다. 유지 표시는 이번 마운트에서 실제로 승자였던 종류만 대상으로 하고, activate·close 때 해제한다.

**(3) B 범위 → 9곳 수용 + 1곳 추가(C6). 결산·Hero diff 0.**
- 대조 결과 9곳 모두 `getProfitLossColor(profit)` + `profit >= 0 ? "+"` 구조다. 실물(:26)만 `profit === 0`(반올림 전) 판정이라 헬퍼로 통일하는 것이 맞다.
- **C6 추가**: `real-estate-tab.tsx:180-181` '실투자금 수익률'. 담보대출이 있는 부동산을 매입가 = 평가액으로 등록하면(흔한 경우) 펼침 카드에서 평가손익은 회색 `0원`인데 바로 옆 수익률은 빨간 `+0.0%`가 된다. 같은 카드 안 같은 사실이 어긋나므로 같은 헬퍼로 묶는다(수익률만 0 판정). 환차손익(:141·:665)·등락 칩(:274)은 다른 지표라 범위 밖으로 둔다(spec 동의).
- 헬퍼는 상세 화면 전용으로 둔다(`ProfitMetric`과 같은 파일 또는 detail 유틸). 공용 `theme.ts`·결산·Hero·성적표 diff 0을 qa가 grep으로 확인한다. 공유 캡처 주식 카드의 0 회색은 정정으로 수용한다(공유 이미지 문구·레이아웃 변화 0).

**(4) D·E 범위 → 수용, D는 조건부.**
- **C7 D의 주 위험은 포커스 탈취다.** 시트에서 방법을 골라 다음 창이 열릴 때 우리 핸들러가 FAB에 포커스를 주면 모달 밖으로 포커스가 빠진다(접근성 회귀). DOM의 `[role=dialog]` 검사만으로는 타이밍에 기대게 된다. 잔액 맞추기의 `goAddRef`처럼 **방법 선택 시 명시 플래그**로 건너뛰는 것을 1순위로, dialog 검사는 보조로 둔다. 공용 함수로 꺼낼 때 4.60 잔액 맞추기 동작(goAdd 생략·FAB→opener→main)이 바뀌지 않아야 하며, qa는 F-* 회귀로 확인한다. 공용 함수는 state-and-utils.md에 등록한다.
- E는 클래스 2곳이라 이견 없다. C25에 따라 같은 창의 다른 도움말 `<p>`도 320에서 전수 확인한다.
