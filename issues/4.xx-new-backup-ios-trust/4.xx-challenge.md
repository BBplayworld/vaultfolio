## 반대 검토 (WORKFLOW 2장 ②)
1. 꼭 해야 하는가 — 예. 로컬 저장이 핵심 강점 2인데, 백업이 실패한 사용자에게 "백업함"이 남으면 기기 초기화 때 복구 불가 데이터 손실이 난다. 이탈 중 가장 회복 불가능한 형태
2. 더 작게 — 사용자 데이터를 서버로 보내는 우회(같은 출처 URL 다운로드)는 **금지**(PRINCIPLES 2장). 해법은 기기 안에서만: Web Share(files) 우선 → 미지원 시 기존 blob, revoke 지연, "백업함" 기록은 공유 완료·다운로드 시작이 확인될 때만. 새 화면·새 저장 키 없음
3. 빼거나 합치기 — P3 통합은 이번에 빼고, 동일 원인인 PNG만 합친다
4. LEARNINGS·DECISIONS — .ics 사례(형식 검증만으로 통과, 전달 방식 미검증)와 같은 실수를 예방하는 방향. 반려 방향과 충돌 없음
5. 목표 기여 확인 — GA `data_action{method:export}`·`share{method:save}`의 iOS 비사파리 비중 대비 성공 처리 수, 백업 안내 재노출 후 재시도율(익명 기기 기준)
