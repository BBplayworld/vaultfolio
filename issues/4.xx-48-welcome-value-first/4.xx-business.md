# 4.xx 사업 계획 — 첫 화면 "가치 먼저" 재배열 + 링크 미리보기 (#48)

## 1. 지표와 판정 규칙 (기존 GA 이벤트만, 새 계측 없음, 익명 기기 기준)
- 주 지표: 28일 창 `first_asset_saved` 기기 수 ÷ `welcome_view` 기기 수. 목표 = 기준선 대비 상대 +30% 이상.
- 가드레일: `pwa_install`(method=installed) ÷ `welcome_view`가 기준선 대비 30% 이상 하락하면 실패 신호(설치 주 버튼 유지의 근거).
- 보조(참고): `onboarding_action`(wizard·manual·skip_install) ÷ `welcome_view`. source=web·pwa와 inapp은 분리해서 본다.
- 구간: 기준선 = 머지일 직전 28일, 비교 = 머지일 +1일부터 28일.
- 보류: 어느 창이든 `welcome_view` 30기기 미만이면 판정하지 않고 창을 연장한다. 표본이 작아 오차가 크다는 전제로 읽는다.
- 주의: `first_asset_saved`는 기기당 1회다. 창 안에서 처음 저장한 기기만 센다.

## 2. GA4 탐색 보고서 레시피 (대표가 직접 보고 싶을 때만, 판독 요청 아님)
1. GA4 왼쪽 메뉴 탐색 > 새로 만들기 > 유입경로 탐색 분석.
2. 설정: 측정 기준 = 기기 기준이므로 "활성 사용자" 지표, 단계(스텝)를 순서대로 추가: ① 이벤트 `welcome_view` ② 이벤트 `onboarding_action` ③ 이벤트 `first_asset_saved`. "간접 추적"은 끄지 않고 기본값 사용.
3. 기간: 기준선 = 머지일 전날부터 28일 전까지, 비교 = 머지일 +1일부터 28일. 같은 보고서를 두 번 만들거나 날짜 범위 비교를 켠다.
4. 세그먼트: 이벤트 매개변수 `source`(=web, pwa)로 필터, inapp은 별도 보고서. 전환율은 ③ 단계 사용자 ÷ ① 단계 사용자.
5. 가드레일: 같은 방식으로 단계 ①`welcome_view` → ②`pwa_install`에 `method`=installed 조건.
6. GA에는 한글 라벨로 기록된다(`ga.ts` PARAM_LABELS): source = 웹 / PWA 앱 / 인앱 브라우저, method = 설치 완료(installed) / 설치 없이 시작(skip_install) / 마법사. 위 필터의 web·pwa·installed는 이 라벨로 읽는다.
7. 매개변수 `source`·`method`가 목록에 없으면 관리 > 맞춤 정의에서 이벤트 범위 측정기준으로 등록해야 보인다(등록 이후 데이터부터 반영되므로 머지 전에 확인).

## 3. 데이터 보존 기간과 판독 마감
- 확인 방법: GA4 관리 > 데이터 수집 및 수정 > 데이터 보관 > "이벤트 데이터 보관"이 2개월인지 14개월인지 확인. 탐색 보고서(위 레시피)는 이 기간 밖 데이터를 못 본다.
- 2개월이면 기준선(머지 직전 28일)이 머지 후 약 8주 안에 사라진다. 이 경우 14개월로 바꾸는 것이 권고(대표만 설정 가능, 비용 없음). 14개월이면 이 제약은 없다.
- 판독 마감: 머지 후 8주 이내. 에이전트는 GA를 직접 조회할 수 없다(STATE 한계). 조회 수단이 생기기 전에는 "지표 미확인"으로 두고, 8주 경과 시 cto가 preview 첫 화면 실측(qa)으로 정성 판정한다. 대표에게 판독을 요청하지 않는다.

## 4. 머지 일시 기록
- 대표 머지 후 첫 정기 실행이 PR 머지 시각(KST, 시·분)을 DECISIONS에 한 줄로 남긴다: `| 날짜 | #48 | 머지 일시 YYYY-MM-DD HH:MM KST, 기준선 구간 = 직전 28일, 비교 구간 = +1일~28일, 판독 마감 = +8주 | business-pm | 지표 구간 경계 |`
- 같은 날 STATE "지표" 절에 판독 마감일을 적는다.

## 5. 판정 후 다음 행동
- 성공(+30% 이상, 가드레일 통과, 30기기 이상): 체험 모드(데모 주입 재사용)와 #33 투자 유형 온보딩 재개를 팀 판정으로 검토. 히어로 주 버튼 자리를 #33이 대체한다.
- 실패(상승 미달·가드레일 위반): 원인 가설을 순서대로 확인: ① 신뢰 한 줄이 약해 이탈(설치율 하락과 동반) ② 미리보기 노출이 첫 화면에서 충분하지 않음(qa 375 실측) ③ 유입 구성 변화(inapp 비중, 블로그 글 주제). 가설별로 한 가지만 고쳐 다음 28일 창에서 재측정.
- 보류(30기기 미만): 창을 28일씩 연장, 8주 한계 도달 시 정성 판정.

## 6. 링크 미리보기(OG)와 채널 연결
- 쓰임: 블로그 주 1회 글(검색형)과 Threads 매일 글, 카페 결산 글 끝에 서비스 링크가 걸리면 각 플랫폼이 OG 이미지·제목·설명을 링크 카드로 보여 준다. 클릭 전 마지막 첫인상이다. 이미지는 브랜드 문구만, 금액 없음, 워터마크 확장 없음.
- 출시 후 점검(게시 전 사람이 1회): 링크 카드가 의도한 이미지·문구로 뜨는지 각 플랫폼 미리보기에서 확인. 플랫폼 캐시가 남아 있으면 갱신까지 시간이 걸릴 수 있다.
- 블로그 마케팅 초안: 출시 주차 `marketing/<YYYY-WW>/blog.md`에 검색형 주제 1건(엑셀·노션 자산 정리의 불편함 → 로그인 없이 내 기기에만 저장하는 방식)을 쓰고 말미에 서비스 링크를 건다. 기능 설명은 실제 동작 범위만(예: 예시 화면을 먼저 보고 시작할 수 있다. 체험 모드·유형 테스트는 아직 없으므로 언급 금지).
- Threads 초안: 기능 1건당 2~4문장, 친구에게 말하듯 반말 축약형, 금액·과장·감성 금지, 마무리 "안전한 자산 관리, 시크릿에셋".
- 규칙 재확인: 외부 게시는 사람이 한다(초안까지). GeekNews는 이 건으로 쓰지 않는다.
