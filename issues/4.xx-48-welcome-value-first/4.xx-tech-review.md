## 4. GA 불변 조건 검증(vitest)과 예상 테스트
- 현 환경은 `environment: "node"`, jsdom 미설치(`@testing-library/react`는 있으나 미사용). 클릭·effect 실행 테스트를 위해 jsdom 추가는 새 의존성이라 피한다.
- 방식: (a) `renderToStaticMarkup`(기존 inline-selector 테스트와 같은 방식)로 초기 마크업 검사 — 접힘 기본 시 "PBKDF2·Ed25519·blob" 미포함, "설치 없이 웹에서 바로 시작" 링크 없음, 블록 DOM 순서, 히어로 중복 문구 1회. (b) GA 매핑은 순수 함수로 소량 분리(`welcomeSource()` 판정, 버튼별 `method` 상수)해 `ga.test.ts`의 window/gtag 스텁 방식으로 라벨("PWA 앱"·"인앱 브라우저"·"웹", "설치 없이 시작"·"마법사"·"직접 입력") 검증. (c) 정적 grep 테스트: `welcome-guide.tsx`에 `localStorage`·`STORAGE_KEYS`·`saveAssetData`·`setAssetData`·`notifyAssetUserEdit` 문자열 0, `track("welcome_view"` 1곳·`useEffect(..., [])` 안. `PARAM_VALUES` 스냅샷 고정.
- 예상: 신규 1파일 8~10건 + 기존 30파일 411건 유지. 렌더 시 provider 의존(`useCloudSync`·스토어)은 `vi.mock`으로 대체.

## 5. 수정 요청
- **수정 요청: 11~14(vitest 렌더·클릭 카운트)** — node 환경에선 effect·클릭이 실행되지 않는다. "마운트 1회·토글 후 추가 없음·탭 1회당 1회"의 런타임 카운트는 qa Playwright로 이관(preview는 GA 스크립트가 없으므로 `addInitScript`로 `window.gtag` 스텁을 심어 호출 배열을 센다). vitest는 4절 (a)(b)(c) 정적·순수 검증으로 한정. 기준 문구를 "vitest: 정적 마크업·매핑·grep / Playwright: 런타임 호출 횟수"로 나눠 달라.
- **수정 요청: 15** — `og:image`는 `APP_CONFIG.siteUrl`(운영 도메인) 절대 URL이라 preview 단계에선 운영에 파일이 없어 200이 안 난다(머지 전). 또 secretasset.xyz는 클라우드 환경에서 403(STATE 막힌 것). 기준을 "meta content = `${siteUrl}/og-image.png` 일치 + **preview 호스트의 `/og-image.png`** 200·png·1200x630·1MB 이하"로 바꾸고, 운영 URL 응답은 머지 후 운영 별칭 스모크로 돌린다.
- **수정 요청: 8 (PWA standalone)** — Playwright에 display-mode 에뮬레이션 옵션이 없다. "`addInitScript`로 `matchMedia('(display-mode: standalone)')`를 true로 모킹" 방식을 기준에 명시.
- 참고(수정 아님): 1번 "순자산 숫자 bottom ≤ 812"는 상단 앱 바 높이 포함이라 ui.md 수치가 이를 만족해야 한다. 10번 320 폭은 CTA 두 버튼 세로 쌓임 전제.
