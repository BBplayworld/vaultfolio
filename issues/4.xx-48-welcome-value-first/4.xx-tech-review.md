## 4. GA 불변 조건 검증(vitest)과 예상 테스트
- 현 환경은 `environment: "node"`, jsdom 미설치(`@testing-library/react`는 있으나 미사용). 클릭·effect 실행 테스트를 위해 jsdom 추가는 새 의존성이라 피한다.
- 방식: (a) `renderToStaticMarkup`(기존 inline-selector 테스트와 같은 방식)로 초기 마크업 검사 — 접힘 기본 시 "PBKDF2·Ed25519·blob" 미포함, "설치 없이 웹에서 바로 시작" 링크 없음, 블록 DOM 순서, 히어로 중복 문구 1회. (b) GA 매핑은 순수 함수로 소량 분리(`welcomeSource()` 판정, 버튼별 `method` 상수)해 `ga.test.ts`의 window/gtag 스텁 방식으로 라벨("PWA 앱"·"인앱 브라우저"·"웹", "설치 없이 시작"·"마법사"·"직접 입력") 검증. (c) 정적 grep 테스트: `welcome-guide.tsx`에 `localStorage`·`STORAGE_KEYS`·`saveAssetData`·`setAssetData`·`notifyAssetUserEdit` 문자열 0, `track("welcome_view"` 1곳·`useEffect(..., [])` 안. `PARAM_VALUES` 스냅샷 고정.
- 예상: 신규 1파일 8~10건 + 기존 30파일 411건 유지. 렌더 시 provider 의존(`useCloudSync`·스토어)은 `vi.mock`으로 대체.

## 5. 수정 요청
- **수정 요청: 11~14(vitest 렌더·클릭 카운트)** — node 환경에선 effect·클릭이 실행되지 않는다. "마운트 1회·토글 후 추가 없음·탭 1회당 1회"의 런타임 카운트는 qa Playwright로 이관(preview는 GA 스크립트가 없으므로 `addInitScript`로 `window.gtag` 스텁을 심어 호출 배열을 센다). vitest는 4절 (a)(b)(c) 정적·순수 검증으로 한정. 기준 문구를 "vitest: 정적 마크업·매핑·grep / Playwright: 런타임 호출 횟수"로 나눠 달라.
- **수정 요청: 15** — `og:image`는 `APP_CONFIG.siteUrl`(운영 도메인) 절대 URL이라 preview 단계에선 운영에 파일이 없어 200이 안 난다(머지 전). 또 secretasset.xyz는 클라우드 환경에서 403(STATE 막힌 것). 기준을 "meta content = `${siteUrl}/og-image.png` 일치 + **preview 호스트의 `/og-image.png`** 200·png·1200x630·1MB 이하"로 바꾸고, 운영 URL 응답은 머지 후 운영 별칭 스모크로 돌린다.
- **수정 요청: 8 (PWA standalone)** — Playwright에 display-mode 에뮬레이션 옵션이 없다. "`addInitScript`로 `matchMedia('(display-mode: standalone)')`를 true로 모킹" 방식을 기준에 명시.
- 참고(수정 아님): 1번 "순자산 숫자 bottom ≤ 812"는 상단 앱 바 높이 포함이라 ui.md 수치가 이를 만족해야 한다. 10번 320 폭은 CTA 두 버튼 세로 쌓임 전제.

## ui.md 교차 검토 (developer)

**수정 요청** (1건만, 나머지 구현 가능 확인)

- **수정 요청: 보안 상세의 루트 `space-y-5` 간격** — 상세를 루트 직계 자식으로 두면 접힘(높이 0) 상태에서도 `space-y-5`의 `margin-top: 20px`가 붙어 신뢰 줄과 순자산 라벨 사이가 40px이 된다. 그러면 4장 표(196→216)와 11장 3번(간격 20±2)이 깨진다. 상세를 `welcome-trust` 블록 안(토글 다음)으로 넣고, 그 블록을 `items-center`에서 `w-full`로 감싸 상세 그리드 폭을 확보한다. 열림 여백은 기존 안쪽 `pt-2`로 충분하다. DOM 순서(hero < trust < security-detail < preview-net)는 그대로라 qa 기준은 바뀌지 않는다.
- 펼침(3장): 구현할 수 있다. React 19.2라 `inert`를 boolean prop으로 쓸 수 있고, Tailwind 4.1에서 `grid-rows-[0fr]/[1fr]`·`transition-[grid-template-rows,opacity,visibility]`·`invisible`이 임의값으로 바로 된다. `grid-template-rows` 보간은 Chrome 107+·Safari 16+·Firefox 66+에서 지원하고, 미지원 브라우저는 즉시 전환으로 대체되며 기능 손실은 없다. visibility 이산 전환(닫힐 때 끝에서 숨김, 열 때 즉시 표시)과 재탭 시 현재 값에서 역전되는 동작은 CSS 기본 동작이라 따로 코드를 쓸 필요가 없다. 높이 0 판정은 바깥 grid 기준이다(안쪽 `pt-2`는 overflow-hidden으로 가려진다).
- CTA 셸(5장): 구현할 수 있다. 셸 `div`에는 key를 주지 않고 `data-state`와 안쪽 콘텐츠만 분기하므로 같은 노드가 유지된다. `pending` 상태는 `mounted=false`일 때 서버와 클라이언트가 같게 렌더하므로 hydration 불일치가 없다. 다만 `PwaInstallFlow`가 자체 `mounted` 전에는 `null`을 돌려주므로(`pwa-install-flow.tsx:76`) 설치 버튼이 1프레임 늦게 뜬다. `min-h-[152px]`로 자리를 잡아 두었으니 이동량(12번, 8px 이하)에는 영향이 없다. 바로 시작 후 포커스 이동은 `ref` + `showAssetCta` effect로 처리한다. `Button size="lg"`는 `h-10`(40px)이고 `variant="secondary"`도 이미 있다.
- 375×812 수치(4장): 들어간다. 현재 실측(배지 26+12, h1 63)으로 역산하면 콘텐츠는 16이 아니라 약 25에서 시작한다. 그래도 +9px이라 슬롯 bottom이 약 779로 812 안에 들어오고, 여유는 33px이다. qa 측정은 `ENTER`의 slide-in(12px, 500ms+stagger 180ms)이 끝난 뒤, 즉 약 800ms 대기 후에 해야 bottom 오차가 없다(11장 1·2·12번에 대기 조건 추가 권장, 수정 요청은 아님).
- OG(9장): sharp 1회 생성은 가능하지만, sharp(librsvg)의 SVG `<text>`는 시스템 fontconfig 폰트로 그려진다. 이 환경에 깔린 한글 글꼴은 WenQuanYi Zen Hei뿐이고 Pretendard·Noto Sans KR은 없다. 그래서 OFL 폰트 파일(Noto Sans KR 500·700)을 스크래치 폴더에 받아 사용자 fontconfig 경로로 지정한 뒤 생성한다. 폰트는 저장소에 커밋하지 않고 앱에도 추가하지 않는다. 대안은 Playwright Chromium으로 `@font-face` HTML을 1200×630으로 캡처한 뒤 sharp로 압축하는 방식이다. 글로우(radialGradient)·로고 합성(`composite`)·1px 링은 sharp에서 된다. 그림자는 SVG `feGaussianBlur`로 근사한다. 생성 스크립트는 커밋하지 않고, 텍스트 목록과 폰트명은 dev-notes에 남긴다.
- testid 12개(10장): 모두 실제 요소에 붙일 수 있다. `welcome-install-btn`은 데스크톱에서는 설치 박스, 모바일에서는 슬롯에 붙는데, 같은 화면에는 하나만 렌더되므로 중복이 없다(9번과 일치). `Button`은 `data-*`를 그대로 전달한다. 순자산 금액 선택자(`/^[0-9,]+원$/`)는 `NetAssetSummaryBox` 출력 형식에 달려 있으므로, 구현할 때 실제 텍스트로 확인해 dev-notes에 확정 선택자를 적는다.
- 그 밖에 배지 삭제, `outline`→`secondary`, 설치 박스의 모바일 미렌더, 상세 위치 이동은 기술적으로 막히는 점이 없다. 새 패턴(grid-rows 펼침)은 KB 배치 때 design-system §6에 등록한다.
