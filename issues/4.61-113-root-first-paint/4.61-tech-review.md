## 2. SSR 가능 여부·렌더 순서 (확인함)
- `page.tsx`는 `"use client"`지만 Next가 SSR한다. `(main)/layout.tsx`는 `cookies()`를 쓰는 동적 서버 컴포넌트. 서버·클라이언트 첫 렌더 모두 `isDataLoaded=false`(`useState(false)`, `initAndSync`에서만 true) → **조각을 `!isDataLoaded` 분기에 두면 서버/클라이언트 첫 렌더 마크업이 동일**(hydration 안전). `useAssetData`·`useAssetNavigation`·`useIsMobile` 등 훅은 이미 SSR 통과 중(현재 null 반환만 하므로 SSR 자체는 이미 돌고 있음).
- 렌더 순서(바깥 → 안): `ReactQueryProvider` → `TrialGate`(`?trial=1` 없으면 children 그대로, 있으면 SSR에도 로딩 덮개만 렌더, children 미렌더) → (preview 환경만) `PreviewGate`(클라이언트에서만 children 렌더 → preview SSR HTML엔 조각 없음) → 프로바이더들 → `{children}`(= page) + 형제로 `PwaLockScreen`(`mounted && locked` 아니면 null, 143행)·`InAppBrowserGate`(`mounted` 전 none)·`BottomNav`·`TopBar`.
- 결과: 운영 SSR에서 조각은 `data-content-area` 안에 들어가고, 덮개류는 모두 mount 후에만 뜨므로 조각을 가리지 않는다. 잠금(PWA)·인앱 덮개는 effect 이후 → 현행 순서 그대로.

## 3. K1·K2 head 스크립트 / CSP
- 기존 `data-device` 스크립트 try 블록 안에 한 줄: 키 3개 중 하나라도 `localStorage.getItem(k)!==null`이면 `document.documentElement.setAttribute('data-has-assets','')`. 값 변수 보관·parse·길이 확인 없음. `<script>` 수 불변.
- `<html>`에 이미 `suppressHydrationWarning`이 있고 `data-device`와 같은 방식이라 속성 추가에 따른 hydration 경고 없음. 단 React가 html 속성을 재조정하지 않으므로 클라이언트가 이 속성을 지우지 않는다(속성은 새로고침마다 재계산).
- CSP는 Report-Only + `script-src 'unsafe-inline'`(next.config.mjs 41행) → 기존 인라인 블록 확장은 영향 0. nonce 전환 대상 개수도 불변.
- 숨김은 body 파싱 전에 속성이 정해지고, CSS는 렌더 차단이라 보유자 첫 페인트 전 숨김이 성립. 단 CSS가 `<link>` 외부 파일이므로 첫 페인트는 CSS 도착 후 → 조각이 CSS 없이 노출되는 프레임은 없음(Next는 스타일시트를 head에서 blocking). 실측으로 확인할 것(§8).
- 키 이름 3개는 `src/lib/local-storage.ts`(`assetData`·`physicalAssets`, `LEGACY_KEYS.assetData`)와 중복 하드코딩이 불가피(인라인이라 import 불가). **키 변경 시 깨지는 위험** → 단위 테스트로 head 문자열에 세 키가 포함됨을 단언하는 가드 1개 권장(`local-storage.ts` 값과 비교).

## 4. 0건 첫 방문에서 본 키가 써지는가 (planner 질문)
- `getAssetData()`(asset-storage.ts:120~): 키 없으면 EMPTY로 읽기만 함. **쓰기는 레거시 nickname 마이그레이션·구버전 거래소 정규화 때만**(0건 첫 방문엔 해당 없음).
- `initAndSync`(asset-data-context.tsx ~843): `if (!hasAssets) return` 이전에 `initAssetData`·`setIsDataLoaded`만 수행 → 환율·시세·`saveSnapshots`(yearlyNetAssets 저장, 사용자가 말한 연도별 순자산 경로)는 **자산이 있을 때만** 실행. `saveSnapshots` 쓰기는 `lastVisitDate`·스냅샷 키이며 본 키 3개가 아님. 0→양수 전환(892행) 때도 자산이 이미 생긴 뒤.
- `migrateStorageKeys()`는 레거시 키가 있을 때만 새 키로 복사.
- 결론: **0건 방문만으로는 3개 키가 생기지 않는다** → 재방문 0건 기기도 조각 노출(spec 엣지 일치). 잔여 불확실: 닉네임·마법사 등 설정 저장이 0건에서 본 키에 쓰는 경로는 전수 확인 못 함 → 쓰면 그 기기는 "숨김→웰컴"(현행과 동일, 퇴행 아님). qa가 "웰컴에서 CTA 진입 전 본 키 존재 여부"를 1회 확인.

## 5. K3 hydration
- 조각은 `isMobile`·`mounted`·`window`·`isTrialMode()` 미사용 정적 마크업이어야 한다. `WelcomeGuide` 자체를 SSR하면 `useIsMobile`(undefined→값)·`mounted` 분기 때문에 불일치가 나므로 **WelcomeGuide를 SSR하지 않는다**(spec 일치). 서버 첫 렌더 = 클라이언트 첫 렌더 = 조각 → 불일치 구조적 0.
- 숨김은 CSS만(`display:none`) — React 분기 아님. 아이콘은 lucide(SVG, SSR 안전).

## 6. K4 구현 선택지 (선택은 ui-designer)
- A. **공용 컴포넌트 추출**(히어로+신뢰 줄, `animate` prop 또는 클래스 인자): 조각은 애니메이션 없이, WelcomeGuide는 같은 컴포넌트를 쓰되 **조각과 같은 DOM 위치·같은 키로** 이어 붙이면 React가 노드를 재사용하지 못함(분기가 달라 언마운트→마운트) → 재마운트 시 ENTER 재생 위험. 이를 막으려면 WelcomeGuide 쪽 히어로·신뢰 줄 ENTER를 제거하고(첫 화면에선 조각이 이미 보임), 미리보기 이하만 ENTER 유지. 변경량 최소. h1은 분기 전환 순간 교체라 동시 2개 없음.
- B. 조각을 page 바깥(layout)에 고정 렌더 후 WelcomeGuide가 히어로를 안 그림 → h1 이동·구조 변경이 커서 비권장.
- C. WelcomeGuide에 `prePaint` 플래그로 ENTER만 생략: 0건 방문자 전원이 조각을 이미 봤으므로 사실상 A와 동일, 분기가 늘어 비권장.
- 권고: **A(WelcomeGuide 히어로·신뢰 줄 ENTER 제거 + 공용 추출)**. 단 위치 이동 0을 위해 WelcomeGuide 루트 간격(`space-y`)과 조각 컨테이너 클래스를 동일하게 맞춰야 함.

## 7. K5 `resolveInAppGate` 1줄
- `if (!env.isDataLoaded) return "cover"` 앞/뒤에 인자 `hasAssetsAttr:boolean`(= `document.documentElement.hasAttribute('data-has-assets')`)을 추가: `if (!env.isDataLoaded) return env.hasAssetsAttr || env.isSharePending || env.syncAssetId || env.restoreHash ? "cover" : "welcome"`. 속성은 순수 함수 바깥(`InAppBrowserGate`)에서 mounted 이후 읽는다(SSR 안전).
- 주의: `isSharePending`은 로드 전엔 아직 false일 수 있어 `#share` 진입은 `restoreHash`(첫 렌더 캡처)가 담당 → 기존 `restoreHash` 캡처로 충분. `syncAssetId`는 mounted 후 계산. 동기화 기기는 키가 있어 속성도 true일 가능성이 높음(이중 방어).
- 테스트 추가: 로드 전 + 속성 없음 + 해시/sync 없음 → welcome / 속성 있음 → cover / 로드 전 + restoreHash → cover / 로드 전 + syncAssetId → cover / isTrial·standalone·non-inapp → none 유지. 기존 "데이터 로드 전 → cover" 두 케이스(53~54행)는 새 인자 필요하므로 갱신(테스트 삭제·우회 아님, 사양 변경 반영).

## 8. SW 오프라인·검증 방법
- `public/sw.js`: HTML은 `no-store` 네트워크 우선, 성공 응답만 오프라인 폴백 캐시(`CACHE_NAME v4`). 조각이 포함된 `/`가 캐시돼도 보유자는 속성으로 숨김 → 영향 0. 캐시 버전 올릴 필요 없음.
- 원본 HTML 검증: preview는 PreviewGate(클라이언트 전용) 때문에 불가. `NEXT_PUBLIC_VERCEL_ENV` 미설정으로 `npm run build && npx next start -p 3100` → `curl -s localhost:3100/ | grep -c "나만의 비밀 자산 금고"` 및 부제·세 신뢰 문구, `<h1` 개수 1 확인. `curl -s localhost:3100/?trial=1`은 조각 부재 확인. 머지 후 운영 curl 동일.
- 깜빡임 실측: 로컬 운영 빌드 + Playwright `addInitScript`로 키 선주입 → 느린 4G 스로틀 필름스트립/`page.screenshot` 연속 캡처에서 조각 0프레임(320·375·PC), 실물만(`secretasset.physical_assets`만) 포함.

## 9. 테스트 계획
1. `resolveInAppGate` 케이스(§7). 2. 조각 ↔ WelcomeGuide 공용 문구 동일(공용 상수/컴포넌트 `renderToStaticMarkup` textContent 비교, node 환경 가능). 3. head 스크립트 키 3개 = `STORAGE_KEYS.assetData`·`physicalAssets`·`LEGACY_KEYS.assetData` 가드. 4. `data-has-assets` 속성 판정 로직은 인라인이라 단위 불가 → Playwright 실측으로 대체. 스키마 변경 0이므로 마이그레이션 테스트 해당 없음.
