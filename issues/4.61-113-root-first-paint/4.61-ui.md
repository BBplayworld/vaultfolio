## 2. 컴포넌트 트리 (위→아래)
신규 파일 `src/app/(main)/_components/layout/onboarding/welcome-intro.tsx` (**`"use client"` 없음**, 훅·window·isMobile 0, 서버/클라 양쪽에서 같은 출력 — K3).
- `WelcomeHero({ enter })` : 기존 ① `section[data-testid=welcome-hero]` 마크업 그대로(`text-center space-y-2`, h1 `text-3xl md:text-4xl font-bold tracking-tight text-balance`, 부제 `text-base md:text-lg text-muted-foreground max-w-xl mx-auto leading-relaxed text-pretty break-keep`). `enter`가 true일 때만 클래스에 `ENTER` 추가.
- `WelcomeTrustLine({ enter })` : 기존 ② 안의 신뢰 `<p>`(ShieldCheck + 3항목 + nowrap 구분자)만. 바깥 `div[data-testid=welcome-trust]` 래퍼는 WelcomeGuide·사전 조각이 각자 같은 클래스(`w-full flex flex-col items-center`)로 둔다.
- 문구는 이 파일의 기존 문자열을 **이동**만 한다(새 리터럴 0). `ENTER` 상수는 welcome-guide에서 export해 재사용(중복 정의 금지).

사전 조각 `RootFirstPaint` (page.tsx의 `!isDataLoaded` 분기, 별도 컴포넌트 가능):
```
<div data-first-paint data-testid="first-paint-shell" className="flex flex-col gap-4 md:gap-6">   ← page 웰컴 분기 래퍼와 동일
  <div className="w-full py-2 space-y-5">                                                           ← WelcomeGuide 루트와 동일
    <WelcomeHero enter={false} />
    <div data-testid="welcome-trust" className="w-full flex flex-col items-center">
      <WelcomeTrustLine enter={false} />
    </div>
  </div>
</div>
```
- 바깥 두 래퍼 클래스를 WelcomeGuide·page와 **같은 값으로 맞추는 것이 위치 일치의 핵심**. 래퍼 클래스가 갈라지지 않도록 상수(`WELCOME_PAGE_WRAP`, `WELCOME_ROOT`)로 빼 두 곳이 import하는 것을 권장.
- 사전 조각에는 `자세히 보기` 버튼·보안 상세·미리보기·CTA·설치 박스·푸터 없음(spec 범위). `aria-hidden`·`hidden`·`sr-only` 금지(수집기와 사람이 같은 텍스트를 같은 모습으로 — 클로킹 방지).
- 조각 안 testid: 공용 조각이 `welcome-hero`·`welcome-trust`를 그대로 가지므로, **사전 조각 여부는 래퍼 `first-paint-shell`로만 판별**한다(웰컴 완성 여부는 `welcome-cta-slot` 존재).

## 3. 전환 규칙 (K4)
1. 첫 렌더(서버·클라 모두 `isDataLoaded=false`) = `RootFirstPaint`. 데이터가 읽히면 같은 return 위치에서 웰컴/마법사/홈으로 바뀐다.
2. 웰컴이면 `<WelcomeGuide skipHeroEnter />`: 히어로·신뢰 줄은 `enter={false}`(애니메이션 클래스 없음) → 새 노드가 만들어져도 조각과 **같은 위치·같은 글자·불투명 1.0**으로 같은 커밋에서 교체되어 시각 변화 0.
3. ③(예시 미리보기)·④(CTA 슬롯)·⑤ 이하는 기존 ENTER + `animationDelay`(120/180ms) 그대로 **아래쪽에만** 등장(motion-safe, reduced-motion이면 즉시). 위 두 블록 아래로 새로 붙는 것이므로 위 콘텐츠를 밀지 않는다(위쪽 정렬 레이아웃, 수직 가운데 정렬 없음).
4. `자세히 보기` 버튼(`min-h-10 mt-1`)은 신뢰 줄 **아래**에 처음 생기는 요소다. 조각 상태에서 그 자리는 비어 있고 그 아래에 다른 요소가 없으므로 이동 유발 요소 0. 버튼은 애니메이션 없이 나타난다(기존 ENTER는 래퍼 `div`에 걸려 있었으므로 `skipHeroEnter`일 때 래퍼 ENTER만 생략, 버튼은 신규 모션 없이 즉시).
5. `skipHeroEnter`는 **첫 사전 조각 직후 첫 웰컴 mount에만** true. 이후 마법사→웰컴 복귀·체험 종료 후 재mount는 기존처럼 ENTER 유지(조각이 없었으므로). 구현은 page의 ref(첫 웰컴 렌더 후 false)로 한다. 모션 효과는 재mount와 무관하게 "조각을 거쳤는가"로만 갈리므로 연타·중간 방향 전환 영향 없음(상태 비의존 CSS 애니메이션, 기존 ENTER 동일).
6. 조각이 보이는 동안 `welcome_view` 전송 0, hydration 불일치 요소 0(마운트 전 조각은 정적).

## 4. 보유자 숨김 규칙
- head 기존 `data-device` try 블록에 키 3개 존재 판정 → `document.documentElement.setAttribute('data-has-assets','')` (spec 3장, K1·K2). 값 미읽기.
- CSS (globals.css, 일반 레이어, specificity 0,2,1 이상):
  `html[data-has-assets] [data-first-paint] { display: none; }`
  - 속성 없음(0건·수집기·localStorage 예외) → 조각 보임. 속성 있음 → 숨김 상태로 첫 페인트(현행 빈 화면과 동일).
  - `visibility`/`opacity`가 아닌 `display:none`(레이아웃 점유 0, 접근성 트리 제외).
  - 숨김은 `[data-first-paint]` 한 곳에만 건다. 웰컴/홈 DOM은 영향 0.

## 5. 레이아웃 수치 (조각과 웰컴 완성 화면이 동일해야 하는 값)
- 컨테이너(변경 없음): `[data-content-area] px-3 pt-2 md:px-12 md:pt-2`, 모바일 `mt-2 sm:mt-0`, 최대폭 1400 centered. 콘텐츠 시작 y는 TopBar 아래 고정(조각·웰컴 동일, TopBar는 이미 SSR).
- 래퍼: `gap-4 md:gap-6`(page) > `py-2 space-y-5`(WelcomeGuide 루트) → 히어로 ↔ 신뢰 줄 간격 20px(`space-y-5`, 섹션 gap-5 규약).
- 320: 콘텐츠 폭 296px. h1 30px/36px 한 줄~두 줄(text-balance), 부제 16px `break-keep`, 신뢰 줄은 nowrap 덩어리 단위로 줄바꿈(구분자 뒤에서만). 가로 스크롤 0.
- 375: 콘텐츠 폭 351px. 신뢰 줄 보통 2줄.
- 1280: `md:px-12` → 콘텐츠 폭 1184px, h1 `md:text-4xl`(36px), 부제 `md:text-lg`, 신뢰 줄·부제 `max-w-xl`(576px) 가운데. 히어로·신뢰는 가운데 정렬 유지.
- 타이포·색: 기존 토큰 그대로(`text-muted-foreground`, 아이콘 `text-primary`). 구분자 `text-muted-foreground/50`. 새 색 0.
- 하단: 조각 아래 빈 영역은 그대로 배경(푸터·내비는 레이아웃 소관, 변경 없음).

## 7. 접근성
- 조각에 role·aria 추가 없음. h1 1개, 문서 순서 = TopBar 뒤 콘텐츠.
- 조각 → 웰컴 교체 시 포커스 이동 없음(조각에 포커스 대상 0). 키보드 탭 순서는 웰컴 완성 후 기존과 같음.
- 히어로·신뢰 줄 대비는 기존 토큰이라 다크/라이트 AA 동일(신규 확인 불필요, qa는 스크린샷 육안만).
- reduced-motion: 조각·히어로·신뢰 줄은 원래 무모션. ③ 이하는 기존 `motion-safe:`로 즉시 표시.

## 8. 문구·스크린샷
- 새 문구 0. 사용 문자열은 전부 welcome-guide.tsx에서 이동(h1, 부제, 로그인 없음, 자산은 내 기기에 저장, 원하면 암호화 동기화).
- `data-screenshot-hide`: 해당 없음(조각은 웰컴 전, 캡처 대상 아님).

## 9. testid

- 기존 유지: `welcome-hero`, `welcome-trust`, `welcome-security-toggle`, `welcome-cta-slot`, `inapp-gate-cover`.

## 10. qa 측정 방법
1. **사전 조각 상태 고정**: Playwright `page.route`로 `/_next/static/**/*.js` 요청을 보류(`route.fulfill` 지연)해 하이드레이션 전 상태를 만든다. 그 상태에서 `h1`·`[data-testid=welcome-trust] p`의 `getBoundingClientRect()`(x,y,w,h)를 기록(A). 보류를 풀어 `welcome-cta-slot`이 나타난 뒤 같은 요소를 다시 측정(B). **A와 B의 4값 차이 0**(소수점 포함 0.5px 이내를 허용하되 1px 이상이면 FAIL). 320·375·1280 × 라이트·다크.
2. **재애니메이션 0**: 전환 직후 `hero.getAnimations().length === 0`, `trust` 래퍼도 0(③·④만 > 0 허용), `getComputedStyle(h1).opacity === '1'`를 `requestAnimationFrame` 0·1·3프레임 + 100·300ms에 확인. 필름스트립(스크린샷 연속)에서 히어로가 사라졌다 나타나는 프레임 0.
3. **h1 개수**: 전환 전 과정에 MutationObserver를 달아 매 변이마다 `document.querySelectorAll('h1').length ≤ 1`(동시 2개 0). 기준선을 origin/main에서 먼저 측정해 다른 h1이 없음을 확인.
4. **CLS**: `PerformanceObserver({type:'layout-shift', buffered:true})`로 누적. 히어로·신뢰 줄이 `sources`에 포함된 layout-shift 항목 0건, 전체 CLS ≤ 0.01(origin/main 대비 악화 없음). 느린 4G + CPU 4x 스로틀 조건 포함.
5. **보유자 노출 0프레임**: 키 심은 컨텍스트(`addInitScript`로 `secretasset_asset_data`/`secretasset.physical_assets`)에서 느린 4G로 필름스트립(또는 tracing screenshots) → 모든 프레임에서 `[data-first-paint]`의 `getComputedStyle.display==='none'`, `first-paint-shell` 가시 0. 첫 페인트 이전 확인용으로 `html[data-has-assets]` 존재도 `document-start`에서 단언.
6. **원본 HTML**: JS 비활성(`javaScriptEnabled:false`) 스크린샷이 히어로+신뢰 줄을 보이는지(로컬 운영 빌드), curl 문자열 5종(spec 9장).
7. 첫 프레임 배경: JS 보류 상태 스크린샷 4장(375/1280 × 라이트/다크)의 배경색 = 최종 화면 배경(픽셀 샘플 동일).

## 11. 품질 체크리스트 (qa 판정용)
1. 사전 조각의 h1·신뢰 줄 위치(x,y,w,h)가 웰컴 완성 후와 320·375·1280에서 일치(차이 <1px).
2. 조각→웰컴 전환 시 히어로·신뢰 줄에 fade/slide 없음(`getAnimations()` 0, opacity 1).
3. ③ 예시 미리보기·CTA 슬롯만 기존 ENTER stagger로 조각 아래에 등장하고, 조각 요소를 밀어내지 않는다(CLS source 0).
4. `h1`이 어느 시점에도 2개 이상 아니다.
5. 조각과 WelcomeGuide가 `WelcomeHero`·`WelcomeTrustLine`을 공용 사용(복제 마크업 0), 문자열 리터럴 신규 0.
6. `html[data-has-assets]`이면 `[data-first-paint]`가 `display:none`, 보유자 필름스트립에 조각 프레임 0.
7. 0건 기기·JS 비활성에서 조각이 보이고, 죽은 버튼/링크가 없다.
8. 다크/라이트 첫 프레임 배경이 최종 배경과 같다(흰/검 번쩍임 0).
9. 320에서 가로 스크롤 0, 신뢰 줄이 구분자 뒤에서만 줄바꿈, h1 잘림 0. 1280에서 가운데 정렬·`max-w-xl` 유지.
10. 조각에 `aria-hidden`·`hidden`·`sr-only` 없음(수집기/사람 동일 텍스트).
11. reduced-motion(`emulateMedia reducedMotion`)에서 ③ 이하도 즉시 표시, 전환 중 위치 변화 0.
12. `?trial=1`·`#share`·`#sync`·인앱 UA 진입이 spec 5장 표대로 동작, 인앱 0건에서 `inapp-gate-cover` 0.
13. 웰컴 재진입(마법사 닫기 후 복귀)에서는 히어로·신뢰 줄 ENTER가 기존처럼 재생된다(회귀 아님 확인).
14. CHECKLIST.md UI 항목(동심 radius·tabular-nums·히트영역 40px 등)은 이번 변경에 신규 요소가 없어 `자세히 보기` 버튼(min-h-10) 유지 확인만.

## 12. design-system 반영
신규 토큰·패턴 없음. 단 "정적 사전 페인트 조각은 서버/클라 공용 조각을 재사용하고 ENTER는 생략한다" 규약 1줄을 KB 일괄 갱신 때 design-system §6(모션)에 흡수 권고. `WelcomeHero`·`WelcomeTrustLine`은 components.md 등록 대상.
