# 5.163 웰컴 첫 문장 + 상세·암호화폐 거래소별 합계 — spec (#325, risk:low)

근거: tech-review(같은 폴더), CEO 2차 판정 `_discovery/2026-11-26-core-value-2/ceo.md` ②·④, 1차 핵심 가치 문장, DECISIONS 11-26(#325 읽기 전용·GA 1개), PRINCIPLES 2·3·6장. 코드 기준 main `9c13292`.
선행 조건: 5.160 운영 스모크 PASS(11/26 20:38 KST) 충족 → 거래소별 블록 포함.

## 1. 문제
- 웰컴 부제 `흩어진 자산을 한 화면에서 정리해 보세요.`는 다른 자산 앱과 무엇이 다른지 말하지 않는다.
- 거래소를 2곳 이상 쓰는 사용자는 상세·암호화폐에서 전체 합계와 코인별 금액만 본다. 거래소별 금액은 코인 카드를 하나씩 펼쳐 더해야 한다.

## 2. 목표 행동
- 웰컴에 도착한 사람이 첫 문장에서 '계좌를 연결하지 않는 앱'임을 읽고 기존 첫 버튼(등록)을 누른다. 측정: 기존 `welcome_view`·`onboarding_action` 그대로(이벤트·title 변경 0).
- 상세·암호화폐에서 '거래소별'을 열어 거래소마다 평가금·손익·코인 수·비중을 확인한다. 측정: GA `crypto_exchange_open` 1개.

## 3. (a) 웰컴 부제
- **확정**: `계좌 연동 없이, 여러 증권사 주식을 한 화면에 모아 보세요.`
- 대안(확정안이 320에서 3줄이 되면 교체): `계좌 연동 없이, 흩어진 주식과 자산을 한 화면에서 정리해 보세요.`
- 바꾸는 곳은 `welcome-intro.tsx` `WelcomeHero`의 부제 `<p>` 글자뿐이다. h1 `나만의 비밀 자산 금고`, 신뢰 한 줄, 첫 버튼, 배치, 클래스는 그대로 둔다(CEO ④).
- 사실성(코드 확인)
  - 연동 없음: `src/app/api/`는 시세·스크린샷 분석·동기화·공유·푸시·실거래가·검색뿐이고, `src` 전체에 마이데이터·오픈뱅킹·계좌 조회 코드가 0이다.
  - 앱 안에서 '연동'은 기기 동기화에도 쓰인다. 그래서 `연동 없이` 단독이 아니라 `계좌 연동 없이`로 쓴다.
  - 여러 증권사: `Stock.broker`와 5.160 증권사별 블록이 있다.
- 금지: '서버로 안 보내요'·'아무것도 안 나가요' 류, 금액, 수익·투자 표현, '정확하게' 같은 단정. 보안 문구는 추가하지 않는다(위임 조건 ⑤).
- 줄 수: 320 폭(본문 296px, `text-base`)에서 2줄 이내. 글자 폭 계산으로는 두 문장 모두 2줄이다. 실측은 qa가 한다.
- 문구 고정 테스트 3곳 갱신: `welcome-guide.test.tsx:119`, `welcome-intro.test.tsx:35`, `welcome-non-trial-snapshot.test.tsx.snap`(tech-review에 빠진 1곳).
- 판독: 운영 반영 시각에 #292 판독을 '그때까지 n일 관측·판정 보류'로 끊고, 같은 지표로 새 4주 판독을 시작한다. 경계 시각을 DECISIONS에 적는다.

## 4. (b) 거래소별 블록(읽기 전용)
- 위치: 상세·암호화폐의 selector(`전체`) 바로 아래, 비중바 위. 요약 헤더·비중바·코인 목록은 바꾸지 않는다.
- 렌더 조건: 수량>0 코인의 묶음(미지정 포함)이 **2개 이상**이고 총 평가금>0일 때만. 그 밖에는 DOM 0. 섹션에 `data-screenshot-hide`를 둔다.
- 접힘: 기본 접힘. 접힌 줄은 `거래소별 · N곳`과 펼침 아이콘. 열림 상태는 `useState`만 쓴다(저장 키 0). 다시 들어오면 접힘.
- 행(5.160 `BrokerRow` 모양 재사용)
  - 왼쪽: 거래소명, `코인 N개`(같은 거래소의 같은 심볼은 1개로 센다)
  - 오른쪽: 평가금, 손익(부호·빨강/파랑)과 수익률(원가 0이면 `—`), 비중 %
  - **`맞추기` 버튼 없음**(DOM 0. 숨김 처리가 아니라 그리지 않는다)
- 정렬: 평가금 내림차순. `거래소 미지정`은 항상 맨 아래.
- 묶음 규칙
  - `assetData.crypto` 행 단위로 묶는다. 수량>0 전체가 대상이다(목록의 `value>0` 필터를 쓰지 않는다. 헤더와 같은 모집단).
  - 공백·대소문자를 뺀 값이 `cryptoExchanges`의 라벨이나 value와 **완전히 같으면** 목록 라벨로 표시한다. 그 밖의 글자는 사용자가 쓴 그대로 한 묶음이다.
  - `matchExchangeHint`의 부분 일치(`includes`)는 쓰지 않는다. `코인`이 `코인원`으로 합쳐지는 식의 오분류가 생긴다.
  - `기타`는 지정된 묶음이다. 빈 값·`항목 N`만 `거래소 미지정`이고, 펼친 블록 끝에 `거래소를 적지 않은 코인이에요.` 1줄을 둔다.
- 합계 일치(C150): 정본은 요약 헤더 `총 암호화폐 평가금액`·`평가손익`. 블록에 합계 줄은 없다. 묶음 값을 원 단위로 반올림하고 `apportionUnits`로 헤더 표시값에 맞춘다. 비중은 `largestRemainderTenths`, 합 100.0%.
- GA: `feature_use` category `crypto_exchange_open`, title `상세·암호화폐·거래소별 열기`. 첫 펼침에 페이지 수명당 1회, preview 미전송, 거래소명·금액 미전송.
- 하지 않을 것: 맞추기 진입, 거래소 필터·탭, 거래소 이름 편집, 열림 상태 저장, 인증카드 포함, 주식 블록 제네릭화, 코인 이관.

## 5. 사용자 흐름
1. 처음 방문 → 웰컴 h1 아래 새 부제를 읽는다 → 기존 첫 버튼으로 등록을 시작한다.
2. 상세 › 암호화폐 진입. 묶음이 2개 이상이면 selector 아래에 `거래소별 · N곳`이 접힌 채 보인다.
3. 탭하면 펼쳐진다(첫 펼침에 GA 1회). 다시 탭하면 접힌다.
4. 코인을 추가·삭제·맞추면 블록이 새 값으로 다시 계산된다. 묶음이 1개가 되면 사라진다.

## 6. 엣지 케이스
- 빈 데이터·첫 사용자: 코인 0건이면 블록 DOM 0.
- 거래소가 전부 비었거나 전부 한 곳: 묶음 1개라 블록 없음.
- 현재가 0인 코인(시세 미수신): 묶음에 넣는다(평가금 0, 손익은 원가만큼 음수). 헤더 손익과 맞추기 위해서다. 이런 코인만 가진 묶음도 행을 그린다.
- 일부 갱신·오래된 시세: 헤더와 같은 `currentPrice`를 쓰므로 불일치 0. 블록은 시각을 표시하지 않는다.
- 긴 자유 텍스트 거래소명: 320에서 2줄까지 줄바꿈, 금액은 줄바꿈 없음. 둘째 줄 `코인 N개 · 비중`은 nowrap(C152).

## 8. 완료 기준(qa)
1. 웰컴과 루트 사전 조각의 부제가 확정 문구와 글자 단위로 같다. h1·신뢰 줄·버튼 순서와 글자는 main과 같다.
2. 320·360·390 폭에서 부제가 2줄 이내이고, 첫 버튼 위치가 main보다 1줄 넘게 밀리지 않는다.
3. 부제에 금지 표현(3장)이 0이다. GA 이벤트·title·파라미터 변경은 `crypto_exchange_open` 추가 1건뿐이다.
4. 거래소 3곳·미지정·`기타`·같은 코인 2개 거래소·현재가 0 코인 픽스처에서, 화면에 표시된 행 평가금 문자열의 합과 손익 문자열의 합이 헤더 문자열과 같다. 비중 합은 100.0%다.
5. 묶음 1개, 코인 0건, 총 평가금 0에서 블록 DOM이 0이다. 인증카드(저장 PNG 포함)에 블록이 없다.
6. 처음과 재진입 때 접혀 있다. localStorage 키 증가 0.
7. `거래소 미지정`은 맨 아래 1묶음이다. `업비트`·` 업비트 `·`upbit`는 한 묶음이고, `코인`은 `코인원`과 다른 묶음이다.
8. 블록 안에 버튼은 접기 토글 1개뿐이다(`맞추기` 0). 주식 증권사별 블록의 동작·테스트는 그대로 통과한다.
9. GA는 펼침당 페이지 수명 1회, preview 미전송, 파라미터에 거래소명·금액 없음.
10. 저장 스키마·키·동기화·서버 전송 변경 0. 320에서 이름·금액 겹침 0, 토글 히트영역 40px 이상.

## 9. (d) 새 소식
- 웰컴 문구: 넣지 않는다. 기존 사용자는 웰컴을 보지 않는다.
- 거래소별 블록: 1건 넣는다. `featureId: "crypto"`.
  - title `암호화폐를 거래소별로 모아 볼 수 있어요`
  - body `거래소마다 평가금과 손익, 비중을 한눈에 보여 줘요`
  - 금액·권유 표현 0, C25 결합자 적용(`볼 수`).
- id는 **머지일 KST**다. 11/27 머지면 `20261127-01`(그날 먼저 머지된 항목이 있으면 다음 순번), 11/26 자정 전 머지면 `20261126-06`.
