# 5.158 spec — 기록 입력 정확도 (#311)

근거: roadmap/ceo.md ④(축소 범위)·planner.md P6·P7·P8·P10·P11·P12, core-value/ceo.md ②(5.158 순서·risk:medium·tech-review P8만), 5.149 spec('기록만' 용어). 코드 main 986057b(v5.155).
risk:medium · CEO 승인 · ui.md 필요 · tech-review P8만 1쪽.

## 1. 문제
- 과거 날짜 입출금·거래도 기본값이 '즉시 반영'이다. 이미 잔액(수량)에 든 돈을 적으면 두 번 더해진다(#293 유형). 경고는 맞추기 뒤 날짜일 때만 뜬다(`balance-edits.ts:115-119`).
- 해외 체결 환율 칸, 미리보기, 저장값이 서로 다르다(3장 재현).
- 보유 종목 체결 단가를 매번 0부터 입력해야 한다.
- 긴 메모가 날짜 뒤에 붙고, 한글은 글자 단위로 끊긴다. 띄어쓰기 없는 긴 문자열은 칸을 넘친다.
- 기록 폼 토스트 말투가 섞여 있고('기록되었습니다'와 '저장하지 못했어요'), 결산 오류는 사용자에게 할 일이 아닌 행동을 권한다.

## 2. 목표 행동
- 과거 날짜를 고른 사용자가 저장 전에 질문 한 줄에 답한다. 이미 든 돈이면 `기록만`으로 남긴다.
- 해외 거래를 저장하면 칸에 보이던 환율이 그대로 저장되고, 미리보기에도 같은 환율이 쓰인다.
- 보유 종목을 사고팔 때 1탭으로 현재가를 넣은 뒤 고친다.

## 3. 범위와 규칙
### ① P6 과거 날짜 '이미 들어 있나요?' (현금 입출금·주식 거래)
- 조건: `date < todayKst()`이고 날짜 칸이 비어 있지 않다. 주식은 `isNewSelected`(신규 자산, 항상 반영)이면 묻지 않는다.
- 위치: 반영 체크박스 상자 바로 위에 질문 1줄과 답 2개를 둔다. 문구 초안(ui.md가 확정):
  - 현금: `이 돈이 지금 잔액에 이미 들어 있나요?` → `이미 들어 있어요`(체크 해제 = 기록만) / `아니요, 더해 주세요`(체크 유지)
  - 주식: `이 거래가 지금 보유 수량에 이미 들어 있나요?` → `이미 들어 있어요` / `아니요, 더해 주세요`
- 답하기 전 기본값은 현행(`reflected: true`, cash-tx-input.tsx:58, trade-input.tsx:147)이다. 답하지 않아도 저장할 수 있고, 결과는 v5.155와 같다(저장 차단 0).
- 상태는 기존 `reflected` 하나만 쓴다. 화면에만 `answered`(메모리) 값을 두고, 답 버튼 또는 체크박스를 직접 누르면 true가 된다. 선택 표시는 `answered && !reflected` → 앞 버튼, `answered && reflected` → 뒤 버튼이다. 날짜를 오늘로 바꾸면 질문을 숨기고 체크 값은 그대로 둔다. 폼 reset 때 `answered=false`.
- 용어는 #295와 맞춘다. 답 뒤 결과는 기존 도움말 문장(`기록만 남고 잔액은 그대로예요` / `기록만 남아요`)이 설명하므로 새 설명 문장을 더하지 않는다. 저장 뒤 목록 배지는 기존 `기록만`이다.
- `ResyncTxWarning`(현금)·연결 계좌 경고(주식)는 현행 조건 그대로 둔다. 답하기 전에는 질문과 겹치므로 경고를 숨기고, 답한 뒤에 현행 조건으로 보인다(ui.md가 겹침 화면을 확인).
- 줄일 것: 대출 상환·코인 거래 폼은 이번에 넣지 않는다. 같은 조각을 2차에 1줄로 붙일 수 있다(대출은 맞춘 날 경고가 이미 있고, 코인은 #295 P4에서 재현 테스트만 했다).

### ② P8 해외 체결 환율 — 칸 = 미리보기 = 저장값
**코드 재현 경로(연결 계좌 '연결 안 함', USD 종목)**
1. 칸: `value={field.value ?? 0}`(trade-input.tsx:865, allowDecimals)라서 `0`으로 보인다. 폼 값은 undefined다.
2. 미리보기·연결 금액·원화 입력 환산: `watchedExRate || exchangeRates.USD`(:208·:221), `linkRate`(:229), 도움말 `÷ exchangeRates.USD`(:844)는 현재 환율을 쓴다. 그런데 `PositionChangePreview`에는 `exchangeRate: watchedExRate`(undefined)가 넘어가서 `computeNewPosition`이 기존 평균 환율을 쓴다(trade-utils.ts:75).
3. 저장: `exchangeRate = data.exchangeRate`(:407)이고 연결 계좌가 있을 때만 `conv.rate`로 채운다. 그래서 undefined가 저장된다.
4. 저장 뒤: 원인·결산의 `tradeKrwRate`(asset-report.ts:986-990)와 세금(tax-utils.ts:127)은 **볼 때의 현재 환율**로 대체한다. 그래서 과거 거래 환산액이 환율이 움직일 때마다 바뀐다(qa 결함 확정 대상).
5. 변형(0 저장): 칸을 눌러 지우면 NumberInput이 `0`을 보낸다(number-input.tsx:63). 이 경우 `0`이 저장된다. 세금은 `tx.exchangeRate ?? …`라서 0을 그대로 써서 매도 대금이 0원이 된다(tax-utils.ts:127). 포지션은 `?? current.avgExchangeRate`라서 평균 환율을 0 쪽으로 끌어내린다(trade-utils.ts:75). `tradeKrwRate`는 `> 0` 검사가 있어 안전하다.
**규칙**
- 해외 종목이 정해지고 칸이 비어 있으면(undefined 또는 0) 현재 환율(`currentRate`, :228)로 **칸을 채워 보여 준다**. 기존 `handleLinkChange`(:318-327) 채움을 종목 선택 시점으로 넓힌다. 사용자가 고친 값은 덮지 않는다. 자동으로 채운 값을 사용자가 고치기 전에 통화가 바뀌면(USD↔JPY) 새 통화의 환율로 바꾼다.
- 칸 아래에 1줄을 둔다. 문구 초안: `지금 환율이에요. 체결 때 환율로 고칠 수 있어요`. 자동으로 채운 값일 때만 보인다.
- 미리보기(`reflectionPreview`·`PositionChangePreview`), 연결 금액, 원화 입력 도움말 `÷ N`, 저장값이 모두 같은 값 하나(`linkRate`)를 쓴다.
- 저장: `exchangeRate > 0`이면 그 값을 저장한다. 아니면 `currentRate > 0`일 때 currentRate를 저장하고, 그것도 없으면(환율 미수신) undefined를 저장한다. **0은 저장하지 않는다.** 국내 종목이면 항상 undefined를 저장한다(앞서 고른 해외 종목의 칸 값이 남지 않게).
- 환율을 받지 못했을 때(`currentRate = 0`)는 칸을 비워 두고 placeholder를 표시한다. 저장 결과는 현행과 같다(undefined).
- 근거 선례: 스크린샷 가져오기는 이미 '오늘자 환율'을 저장한다(trade-screenshot-import.tsx:155·334·439). 직접 입력도 같은 규칙으로 맞춘다.
- 기존 레코드는 다시 쓰지 않는다. 이미 저장된 `0`을 읽을 때 없는 값으로 볼지(tax-utils `??`→`> 0`, trade-utils:75·139)는 **tech-review가 정한다**(기존 계산값이 바뀌므로 영향 범위·판독 경계를 함께 적는다). 기본 권고는 읽기 보정 포함이다. 0은 쓰기 버그의 결과일 뿐 사용자 의도가 아니기 때문이다.

### ③ P7 `현재가 넣기` (보유 종목 매수·매도)
- 출처: 선택한 보유 항목의 `stock.currentPrice`. 홈·상세와 같은 값이고 새 요청은 0건이다.
- 위치: 체결 단가 칸 바로 아래 줄. 매도 수량의 `보유: N주 [전량]` 패턴(trade-input.tsx:794-805)을 재사용한다. 줄에는 버튼 `현재가 넣기` 하나만 두고 금액은 적지 않는다(현재가 정본은 상세, 4장).
- 누르면 `price = currentPrice`(통화별 소수 자릿수 USD 3·JPY 4·KRW 0으로 반올림)로 바뀐다. 자동으로 채우지 않는다.
- 숨기는 경우: 보유 항목이 정해지지 않음(`selectedStock` 없음·`NEW_STOCK_ID`·검색 신규 종목), `currentPrice ≤ 0`, USD `원화로 입력` 켜짐(줄일 것: 원화 환산 넣기는 하지 않음).
- 시세 시각은 표시하지 않는다(5.153: '언제 시세'는 홈·주식 2곳만).

## 5. 사용자 흐름
1. 상세›현금›입출금 기록 → 날짜를 11/20으로 바꾼다 → 체크 상자 위에 질문이 뜬다 → `이미 들어 있어요` → 체크가 꺼지고 예상 잔액 줄이 사라진다 → 저장 → 토스트 `입금을 기록했어요` → 목록에 `기록만`이 붙고 잔액은 그대로다.
2. 같은 흐름에서 답하지 않고 저장하면 현행처럼 잔액에 더해진다.
3. 거래 입력›직접 입력 → 보유 해외 종목·매수 → 환율 칸에 현재 환율이 들어 있고 아래에 안내 1줄이 보인다 → `현재가 넣기` → 단가가 들어간다 → 저장 → 저장된 거래의 `exchangeRate`가 칸 값과 같다.
4. 상세›현금 목록에서 긴 메모가 날짜 아래 2줄로 보이고 끝이 말줄임이다 → 누르면 전체가 보인다.

## 6. 엣지 케이스
- 빈 데이터: 보유 종목 0개 → 넣기 버튼 없음(검색 신규 흐름은 현행). 현금 계좌 0개 → 폼 현행.
- 일부 갱신: 시세 실패로 `currentPrice`가 이전 값이면 그 값을 넣는다(사용자가 고칠 수 있음). 환율 미수신이면 칸 비움·undefined 저장(현행).
- 오래된 데이터: 구버전 기록(`exchangeRate` 없음·0)은 쓰기 0. 읽기 보정은 tech-review 결정에 따른다. 구버전 기기는 새 기록의 `exchangeRate` 숫자를 기존 필드로 그대로 읽는다(스키마 동일).
- 첫 사용자: 처음 사는 종목은 신규 자산이라 질문·넣기 버튼이 모두 없다. 환율 칸 채움은 적용된다.
- KST 00~09시: 오늘 판정은 `todayKst()`를 쓴다(UTC 아님).
- 중복 확인 창·출금 하한 가드: 답에 따라 바뀐 `reflected`로 현행 분기를 탄다.

## 7. 저장 변경 0 확인
- 저장 키·zod 스키마·마이그레이션·동기화 형식·서버 전송·공유 토큰 변경 0. `exchangeRate`는 기존 optional 필드이고 **새 기록에서만** 값을 채운다. `answered`는 메모리 값이다. GA 이벤트 추가 0. 새 소식 읽음 키는 기존 그대로다.
- 보안·데이터 문구 변경 0.

## 9. 완료 기준(qa)
1. 현금·주식 폼에서 날짜가 오늘이면 질문이 0개, 어제면 1개 보인다. 신규 자산 칸을 고르면 날짜와 관계없이 0개다.
2. 질문에 답하지 않고 과거 날짜로 저장한 결과(잔액·수량·`reflected`)가 v5.155와 같다.
