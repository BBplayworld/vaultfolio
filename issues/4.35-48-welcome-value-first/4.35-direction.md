# 4.xx 첫 화면 "가치 먼저" 재배열 + 링크 미리보기 정비 — 방향 (#48)

## 사업

**1. 왜 지금**
- 기여: 첫 발견(유입 전환). 리텐션이 아니라 "들어온 사람이 첫 자산 등록까지 가는가"의 문제다.
- 블로그 주 1회 검색형 글(채널 DECISIONS 2026-10-27)이 유입 경로다. 글을 읽고 들어온 사람이 처음 보는 화면이 보안 전문용어 카드 3장이고, 모바일 웹은 시작 버튼이 맨 아래 보조 링크뿐이다. 유입을 늘려도 이 화면에서 새면 월 활성으로 남지 않는다.
- 링크 미리보기(OG)는 블로그·Threads·카페에 링크가 걸릴 때마다 첫인상이 된다. 지금 정비하지 않으면 글을 올릴수록 같은 약한 첫인상이 반복된다.

**2. 누구를 위해**
- 엑셀·노션으로 자산을 정리하던 3040 주식 투자자 중, 블로그·링크로 처음 들어와 `welcome_view`까지 온 신규 방문자.
- 퍼널 단계: 링크 클릭(미리보기) → `welcome_view` → `onboarding_action`(wizard·manual·skip_install) → `first_asset_saved`. 이번 과제는 앞 3단계의 이탈을 줄인다.

**3. 성공 지표·측정 (기존 GA 이벤트만, 새 계측 없음, 기기 단위 익명)**
- 주 지표: 28일 창 `first_asset_saved` 기기 수 ÷ `welcome_view` 기기 수. 목표는 기준선 대비 상대 +30% 이상.
- 가드레일: `pwa_install`(installed) ÷ `welcome_view`가 기준선 대비 30% 이상 하락하지 않을 것(설치 주 버튼 유지의 근거 확인).
- 기준선 = 머지일 직전 28일, 비교 = 머지일 +1일부터 28일(날짜 구간 비교). source=web·pwa와 inapp은 분리.
- 판정 보류: 창당 `welcome_view` 30기기 미만이면 판정하지 않고 창을 연장한다. 표본이 작아 오차가 크다는 점을 전제로 읽는다.
- 한계: 에이전트는 GA를 직접 조회할 수 없다. 판독 수단이 생기기 전까지 "지표 미확인"으로 두고, 8주 경과 시 cto가 preview 첫 화면 실측으로 정성 판정한다. 대표에게 판독을 요청하지 않는다.

**4. 월 활성 100명 기여 경로 (추정, 실측 아님)**
- 월 활성 약 50명을 100명으로 올리려면 신규 유입이 "열어 보고 한 번 쓴 사람"으로 남아야 한다. 신규 방문 중 첫 자산 등록 비율이 상대 +30% 오르면, 같은 유입에서 남는 신규 사용자가 그만큼 늘어난다. 이번 과제 하나로 +50명을 채운다는 주장은 아니며, 블로그 유입 증가와 곱해지는 전환 개선분으로 본다.
- 실제 효과 크기는 기준선 전환율을 GA에서 아직 확인하지 못해 모른다. 위 +30%는 목표치이지 예측치가 아니다.

**5. 하지 않으면 무엇을 잃나**
- 블로그·링크 유입이 늘어도 신규 방문자 100%가 거치는 유일한 화면에서 이탈이 계속되어, 채널 운영 노력이 월 활성으로 환산되지 않는다.
- 근거 강도: 화면 구조(전문용어 3장, 모바일 CTA 숨김)는 코드로 확인된 사실이라 강함. 이탈 규모는 GA 기준선 미확인이라 약함.
- 범위가 작다(순서 변경·압축·OG 정적 이미지 1장, 데이터·저장 경로 무변경)는 점에서 비용 대비 손실 방지 효과가 합리적이다.

**원칙 준수**: 자산 데이터 서버 전송 없음, 투자 조언 없음, OG 이미지·문구에 금액 없음("안전한 자산 관리, 시크릿에셋"만), 새 진입점·워터마크 확장 없음.

## 경험

**1. 사용자 행동 (관찰 가능)**
- 블로그·Threads 링크 미리보기(OG 이미지+문구)를 보고 클릭 → 첫 화면 첫 스크롤에서 예시 순자산을 보고 → 시작 버튼을 누른다(`onboarding_action` wizard/manual, 모바일 웹은 설치 또는 "바로 시작").
- 기기별: 모바일 웹은 설치(주)와 "웹에서 바로 시작"(보조)이 나란히 보임. PWA 설치 상태는 설치 박스 없이 CTA만. 데스크톱 1280도 같은 순서(설치 박스는 기존 조건 그대로).

**2. 375x812 첫 화면 순서** (운영 실측: 현재는 제목 아래 보안 카드 3장이 812px 전부를 채우고, 미리보기는 스크롤 2~3번 뒤)
제목+쉬운 말 한 줄 -> 신뢰 한 줄(+"자세히") -> 예시 순자산 미리보기(일부 노출) -> 주 CTA(모바일 웹: 설치+바로 시작) -> 이하 미리보기 나머지 -> 설치 안내 -> 보안 상세(펼침).
- 한 화면에 미리보기가 다 안 들어가면 순자산 숫자까지만 보이게 하고 CTA를 그 아래 고정 순서로 둔다. CTA 자리는 한 곳(#33이 대체 가능).

**3. 범위**
- 줄이는 것: 보안 카드 3장 -> 신뢰 한 줄 + "자세히" 펼침(내용 보존, 기본 접힘). 모바일 맨 아래 "설치 없이 시작" 링크 제거. 설치 박스의 3단계 설명은 CTA 아래로(줄일 수 있으면 1줄 요약).
- 하지 않을 것: challenge.md "하지 않을 것" 전체(체험 모드, 새 진입점, #33, 마법사·저장·이벤트 변경, 미리보기 데이터 변경).
- 바뀌는 화면: `welcome-guide.tsx`(순서·펼침·CTA 위치), `layout.tsx` metadata(OG). 그대로: 마법사, 입력 폼, 홈, 앱가이드(보안 3카드 원문은 앱가이드에도 있어 정본 유지).

**4. 신뢰가 유지되는 근거**
- 3장을 삭제하지 않고 한 줄로 요약해 첫 화면에 남기고 상세는 한 번 탭으로 열린다. 핵심 약속("로그인 없음, 서버 저장 없음")은 오히려 첫 화면 위쪽으로 올라 눈에 먼저 띈다. 전문용어(PBKDF2·Ed25519)는 첫 방문자의 신뢰를 높이기보다 읽히지 않는 벽이었다. 단 신뢰 한 줄 문구는 담백하게, 과장 금지.
- 위험: 한 줄이 약하면 신뢰 하락. 가드레일은 `pwa_install` 비율과 qa 첫 화면 실측.

**5. 사업 절 의견**
- 1 왜 지금: 동의. 2 누구를 위해: 동의. 3 지표·측정: 동의(단 `skip_install`은 버튼 위치 변경 후에도 같은 조건 1회 발생 필요). 4 기여 경로: 동의(추정임을 명시한 점 좋음). 5 하지 않으면: 동의. 원칙 준수: 동의.
- 참고: OG는 링크 미리보기 첫인상에 해당하므로 문구는 이미지 안 텍스트 최소화(담백한 브랜드 문구만).

## 합의

**최종 방향**
- 범위: 첫 화면 순서를 히어로 → 신뢰 한 줄 → 예시 미리보기 → 주 CTA(설치 유지, 모바일 웹은 "바로 시작" 보조 버튼을 옆/아래로 올림) → 설치 안내로 바꾼다. 보안 카드 3장은 기본 접힘 "자세히"로 압축(내용 보존)하고, OG 이미지 1장 + twitter 카드는 `layout.tsx` metadata만 건드린다. 이미지 안에는 브랜드 문구만 짧게 넣고 금액은 없다.
- 지표: 28일 `first_asset_saved`÷`welcome_view` 상대 +30%, 가드레일은 `pwa_install` 비율 30% 이상 하락 금지, 30기기 미만이면 보류. 기준선은 머지일 전후 28일 구간 비교이고 새 계측은 없다.
- 조건 수용: 버튼 위치가 바뀐 뒤에도 `skip_install`·`welcome_view`·`onboarding_action`이 같은 조건에서 1회씩 발생하는지 vitest/qa로 확인한다(시계열 연속성). OG 텍스트 최소화도 수용한다.
