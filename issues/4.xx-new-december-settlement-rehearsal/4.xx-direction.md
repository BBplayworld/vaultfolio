# 4.xx 12월 결산 창 리허설 — 11월 새 기록 경로가 11월 결산에 맞게 보이는지 점검·수정 — direction

## 사업 (business-pm 초안, 2026-11-09)

### 1. 왜 지금 — 리텐션(보통), 첫 발견 없음
- 11월 한 달 동안 결산 값을 바꾸는 기록 경로가 7개 새로 생겼다. 현금·대출 잔액 맞추기(v4.54), 스크린샷 맞추기(v4.50), 실물 자산(v4.56), 홈 내부 이동 상쇄(v4.56), 거래 연결 계좌(v4.58), 이어서 맞추기(v4.59), 삭제 시 거래 동반 삭제(v4.60)다.
- **12월 결산 창(11/27~12/10)이 이 경로들이 실제 사용자 결산에 처음 나오는 시점이다.** 11월 결산은 "10월 말 → 11월 말" 구간이라, 11월에 새 경로로 남긴 기록이 원인·구성·다음 달 준비·AI 질문에 모두 들어간다.
- 각 기능은 자기 픽스처로 qa를 통과했다. 하지만 **여러 경로가 한 달에 섞인 실제 사용 형태**(예: 실물 등록 + 연결 계좌 매수 + 월말 잔액 맞추기)로 11월 결산 화면 전체를 본 적은 없다. LEARNINGS 2026-10(데모 데이터로만 검증해 실사용 형태에서 비는 문제)과 11-09 대표 지적(C42, 다른 자산의 사건과 함께 쓰는 조합을 전수 매핑)이 같은 종류의 누락이다.
- 결산은 PRINCIPLES 우선순위 1(한 달에 한 번 돌아오는 의식)이다. 의식의 첫 화면에서 숫자가 어긋나면 "앱 숫자를 못 믿겠다"로 이탈한다. 창이 열리기 전에 찾아야 고칠 시간이 있다.

### 2. 누구를 위해
- 엑셀·노션에 월말마다 자산군별 합계를 적어 온 3040 주식 투자자 중, **11월에 새 기능으로 기록을 바꾼 사람**: 증권 앱 캡처로 보유 현황을 맞춘 사람, 매수할 때 현금 계좌를 연결한 사람, 금·은을 실물로 등록한 사람, 월말에 현금·대출 잔액을 한 번에 맞춘 사람.
- 이들은 엑셀에서 "지난달 대비 얼마, 왜"를 직접 맞춰 봤던 사람이라 원인 줄 하나가 틀려도 바로 알아챈다.

### 3. 성공의 모습 (익명 기기, 기존 GA page_title로만)
- **주 완료 기준(GA 아님)**: 리허설 픽스처 전 조합에서 11월 결산의 Hero 증감 = 원인 합, 같은 금액이 두 번 잡히지 않음(내부 이동 상쇄), 구성 블록·다음 달 준비·AI 질문 문구가 화면 값과 같음. 결함 0건 또는 발견 결함 수정 머지가 **11/26 이전**에 끝남.
- **방향 지표(CSV '페이지 및 화면')**: 12월 창(11/27~12/10) `월 결산` 활성 사용자가 10월 창(10/28~11/10)보다 줄지 않는다. 대표 기기(`?ga-optout=1`) 제외. 표본이 작아 % 판정은 하지 않는다.
- **가드레일**: 12월 창 동안 결산 관련 `의견 보내기` 0건, 운영 결함으로 인한 C 빠른 경로 0건.
- 측정 한계: 결산을 연 사람이 숫자를 믿었는지는 GA로 볼 수 없다. 주 판정은 qa 완료 기준이다. 새 이벤트·맞춤 정의는 만들지 않는다.

### 4. 하지 않으면 무엇을 잃나 — 보통
- 11월 새 기능을 쓴 소수(동기화 외부 기기 약 2대 규모, 주 사용자 수십 명)가 12월 결산에서 틀린 원인을 처음 본다. 숫자 정확성은 이 앱의 정체성("내 자산을 내가 정확히 아는 상태")이라, 대상이 적어도 이탈 비용이 크다.
- 반대로 결함이 없으면 비용은 qa 반나절에 그친다. 리허설 자체는 코드 변경이 0이다.

### 범위 제안 (경험 절에서 확정)
- **포함**: 11월 결산(월 탭) 화면 전체와 12월 창 홈 결산 팁 → 결산 진입. C42 흐름 표의 7개 경로 × 대표 조합 픽스처(실제 사용자 기록 형태: 전년 월 스냅샷 없음, 연도별 순자산 수동값, 10월 말 스냅샷 1개). 발견 결함 수정은 같은 이슈에서 처리.
- **제외**: 첫 결산 공백 UX(E3 v2, 12/11 판독 후), 결산 홈 팁 노출 기간·숨김(11-06 반려), 결산 AI v2, 새 화면·새 문구. 고아 거래 일괄 정리(1월, high).
- **관찰만**: 실물·부동산은 직접 입력 평가액이라 '다음 달 준비'에 나오지 않는다. 경과일만으로 갱신을 요구하지 않는다는 교훈(LEARNINGS 2026-08)에 따라 이번에 넣지 않고, 리허설에서 "결산이 0 변화로 보이는 것이 사실과 맞는지"만 확인한다.
- 위험: 리허설만이면 코드 0. 결함 수정이 결산 계산에 닿으면 risk:medium(COO 자체 승인 범위), 저장·스키마에 닿으면 high로 올려 대표 승인.

### 알릴 방법 (출시 후)
- 별도 공지 없음(사용자가 바뀐 점을 느끼지 못해야 정상). 12월 창 Threads 1건은 기존 채널 패키지에서 "이번 달부터 실물·연결 계좌도 결산 원인에 같이 나와"처럼 사실만 쓴다. 금액은 쓰지 않는다. 리허설에서 사실로 확인된 표시만 문구에 쓴다.
