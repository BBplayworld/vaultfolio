# [4.39] 주식 스크린샷 등록: 국내·해외 혼합 인식 시 공통 모드가 전 종목을 한 카테고리로 바꿔 저장

라벨: `type:bug` · `risk:medium` · `status:development`(4.39 동승, #63과 같은 브랜치·PR) · 발견: #63 design-review(cto·developer 코드 확인, 2026-11-01)

## 현상 (코드상 확정, 재현은 qa vitest로 확정)
- `src/app/(main)/_components/forms/asset-update/screenshot/stock-screenshot-import.tsx` 176-199
- 파싱 직후 기본 "공통 적용" 모드가 **모든 종목**에 같은 `defaultCategory`를 `convertStockCategory`로 적용한다.
  - `defaultCategory`: 해외가 과반이면 `foreign`, 아니면 `domestic`(또는 국내계열 activeTab)
- 국내·해외가 한 화면에 섞인 캡처(예: 증권앱 "전체" 보유 탭)에서 생기는 일
  - 소수 쪽 종목의 카테고리가 다수 쪽으로 바뀐다
  - 해외→국내로 바뀌면 USD 가격이 ×환율(원화)로, 국내→해외로 바뀌면 원화 가격이 ÷환율(달러)로 변환된다
  - 사용자가 미리보기에서 개별로 고치지 않고 "등록"을 누르면 잘못된 카테고리·통화·가격으로 저장된다
- 영향: 상세·주식 국내/해외 구분, 홈 구성 바, 해외 평가 환산(이중 환산 가능), 배당·X-Ray 조회 티커 분류

## 기대 동작
- 인식 결과에 section "해외"와 "국내"/"기타"가 함께 있으면 **개별 선택 모드로 시작**한다
  - 종목별 `section` 기반 카테고리를 유지하고, 공통 일괄 변환을 하지 않는다
- 사용자가 "공통 적용"을 누르면 오늘처럼 전 종목에 일괄 적용한다(명시적 선택)
- 단일 section 결과(국내만·해외만)는 현재 동작과 같다

## 수정 범위 (최소)
- 매핑 순수 함수 `src/lib/asset/screenshot-stock-map.ts`의 `isMixed` 판정 1개 + 시작 모드 분기 1개. #63 인계 경로(`initialParsed`)와 같은 분기다
- `handleRegister`·저장 경로·`reset()`은 무변경
- 이미 잘못 저장된 기존 기록은 자동 보정하지 않는다. 보정은 스키마 마이그레이션에 해당하므로 범위 밖이다. 사용자는 상세에서 수정한다
