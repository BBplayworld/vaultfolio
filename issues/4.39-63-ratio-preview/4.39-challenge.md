## 판정: `축소` — 위험 등급 `medium` 확정
방향(설치·금고 없이 캡처 1장 → 비중 확인 → 선택 저장)은 유지한다. 근거는 다음과 같다.
- 첫 발견 병목: first_visit 월 약 17, first_asset_saved 0/17이다.
- 대표 승인: 2026-11-01, 새 공개 라우트 허용.
- 기존 서버 경로(`parse-screenshot`)를 재사용한다.

위험 등급을 medium으로 두는 이유는 서버 한도 로직 변경, 공개 라우트 추가, 기존 주식 등록 컴포넌트 변경이다. 스키마·저장 키는 바뀌지 않는다.

## 1. 줄일 것 (v1 제외)

## 2. 확인 결과와 필수 보완 (spec·tech-review 반영)
**입구 전용 한도(60/일·IP 5/일)**
- 수치에는 동의한다. 기대 사용량(월 약 5회) 대비 여유가 크고, 앱 사용자 몫은 최악에도 240회가 남는다. IP 5는 CGNAT와 재시도 2~3회를 감안한 값이다.
- **Referer 보강을 채택한다.** 입구 풀은 `entry === "ratio"` **또는** Referer의 경로가 `/ratio`인 요청이다.
  - 근거: `next.config.mjs:61`의 `Referrer-Policy: strict-origin-when-cross-origin` 정책상 같은 출처 fetch는 전체 경로를 보낸다. `guardRequest`가 cross-site 요청을 이미 403으로 막으므로 정상 브라우저 요청은 Referer로 분류된다.
  - 스크립트로 두 표시를 다 빼는 우회는 막을 수 없다. 이 경우는 기존 IP 30·전역 300·L1 20/분이 막고, 새로 노출되는 면은 없다. 한계로 명시한다.
- 예약 순서: IP 일반 → 입구 IP → 입구 전역 → 전역. 어느 단계에서 실패해도 그 앞에서 증가시킨 카운터를 전부 되돌린다. vitest 대상은 다음 3가지다.
  - 입구 61번째 요청 429
  - 같은 IP 6번째 요청 429
  - 그 상태에서 일반 요청 통과

**canonical·OG·sitemap·robots**
- 루트 `layout.tsx:41`이 canonical을 siteUrl로 박아 두었으므로 `/ratio`는 반드시 덮어써야 한다.
- **Next metadata의 `openGraph`·`twitter`는 자식이 정의하면 부모 값을 통째로 대체한다.** `/ratio`에서 제목·url만 넣으면 og:image가 빠져 채널 링크 미리보기가 비게 된다. `images`까지 다시 선언한다.
- 완료 기준 2에 `og:url=/ratio`·`og:image`·`twitter:card`가 SSR HTML에 있어야 한다는 조건을 추가한다.
- robots(`/` allow, index true 상속)는 그대로 둔다. sitemap 추가는 v1에서 제외한다(direction과 같음, G2 때 정리).

**모듈 메모리 인계**
- 안전하다고 판정한다. 저장 키가 없고 1회 소비, 10분 만료다. `/ratio`와 `(main)`은 같은 루트 레이아웃이라 `router.push`가 클라이언트 이동이고, 모듈 상태가 유지된다.
- 하드 이동(배포 스큐·새로고침·새 탭)에서는 인계가 사라진다. 이는 재업로드 안내로 끝나는 fail-safe다.
- 보완 3가지:
  - (a) 만료 시 참조를 실제로 지운다. 소비 시점에만 검사하지 않는다.
  - (b) 인계 호스트는 다음 조건을 모두 확인한 뒤에만 연다. `isDataLoaded`, `!isPwaLocked()`(`asset-data-context`의 공유 토큰 잠금 가드와 같은 함수), `!isSharePending`, 온보딩 마법사 닫힘, 튜토리얼 오버레이 비활성.
  - (c) 0건 기기에서 웰컴·튜토리얼과 확인 창이 겹치지 않는 것을 375 스크린샷으로 확인한다.

**결함 의심: `stock-screenshot-import.tsx` 공통 모드(`applyMode="common"`)**
- 이 모드가 혼합 인식 결과 전체를 `defaultCategory` 하나로 `convertStockCategory`하는지 qa 확인을 요청한다.
- 그렇다면 미리보기의 국내/해외 비율과 저장 결과가 달라진다. 인계 경로에서는 `section` 기반 카테고리가 유지되어야 한다(개별 모드로 시작하거나 같은 효과).
- 완료 기준 6에 "미리보기 국내/해외 종목 수 = 저장 후 국내/해외 종목 수"를 추가한다.

**인앱 저장**
- spec 7절에 동의한다. 판정은 `IN_APP_BROWSER_RE`를 재사용한다(barcelona 포함, #60).
- 인앱에서 브라우저로 넘어가면 재업로드가 필요하고 기기 한도도 따로 계산된다. 사업 절의 전환 목표에 반영한다.

**개인정보**
- 이미지는 이미 기존 경로로 서버를 거쳐 AI 인식에 쓰인다(대표 2026-10-31 보안 메시지 기준: 서버 역할 나열·단정 금지). 공개 페이지라고 해서 새로 전송되는 값은 없다.
- GA 이벤트에 종목명·티커·금액·비중을 싣지 않는다(파라미터는 category·method·result만). 이 조건을 완료 기준 9에 추가한다.

**UTM**
- 허용 목록 방식에는 동의한다. 다만 적용 위치는 첫 `trackScreen`이 아니라 **루트 인라인 gaConfig**이고, `pathname === "/ratio"`일 때만 적용한다. 세션 첫 이벤트·자동 이벤트도 같은 `page_location`을 갖게 하기 위해서다.
- 허용 범위: `utm_source|utm_medium|utm_campaign`만 받고, 값은 `[A-Za-z0-9._-]{1,50}`이다. 그 밖의 쿼리는 버린다.
- 검증: 순수 함수로 분리해 vitest로 확인한다. preview에서는 GA가 꺼져 있으므로 GA4의 캠페인 인식은 "알려진 한계"로 둔다(C9).
