## 2. 저장소·데이터 영향
- 로컬 스키마·저장 키 **변경 없음**, 마이그레이션 없음, 이전 버전 복원 테스트 해당 없음. 건드리는 것: 저장(`StockScreenshotImport`의 기존 `handleRegister` 경로만, 변경 없음)·스냅샷·동기화·거래·공유·백업·성적표 모두 무접촉. `/ratio`는 `geminiUsage`와 GA 플래그 외 localStorage를 읽지 않는다.
- 구버전 혼재: 인계는 모듈 메모리라 구버전 기기와 무관. 롤백(머지 revert) 시 `/ratio`가 404가 될 뿐 사용자 기록 손실 없음. 배포 스큐로 하드 이동되면 인계가 사라지는 fail-safe.
- 단, 저장 시 기존 `handleRegister`가 자산을 쓰므로 **인계 경로의 카테고리 매핑 오류가 곧 잘못 저장된 자산**(6절 결함)이다. 이 점만 데이터 위험.

## 3. 서버로 나가는 값
- 새 값 없음. 업로드 본문은 기존 `image`·`assetType`에 `entry=ratio`(고정 리터럴) 하나 추가. 환율은 공개 시세 GET(사용자 값 미전송). GA 파라미터는 category·method·result뿐, 종목명·티커·금액·비중 미포함 → 사용자 보유 정보 역산 불가. 서버 카운터는 IP·날짜 키의 횟수뿐.

## 4. 위험 등급 초안
**medium**(cto 확정과 일치): 서버 한도 로직(공용 `reserveGeminiCalls`), 새 공개 라우트, 공용 `StockScreenshotImport` 변경. high 승격 조건 없음(스키마 무변경). 단 `layout.tsx` 인라인 스크립트와 `StockScreenshotImport` 변경은 전 사용자 영향이라 회귀 테스트를 강하게 둔다.

## 5. 줄이는 제안
1. 인계 호스트를 `(main)/page.tsx`가 아니라 **`(main)/layout.tsx` 한 줄**(PwaLockScreen 옆)에 둔다(6절 근거). page.tsx·웰컴 diff 0.
2. UTM은 순수 함수를 `.toString()` 주입하지 말고 **인라인에 정규식 한 줄 복제** + 같은 정규식 상수를 테스트가 문자열로 대조(함수 파일과 인라인이 어긋나면 실패). 구현 최소화.
3. 결과 목록의 "그 외 N종목" 합산·tabular 표시 외 시각 요소는 ui-designer 사양 그대로, 추가 금지.

## 6. 위험·미확정 (코드 확인 결과)
- **공통 모드 결함: 확인됨(코드상 확정, 재현은 qa)**. `stock-screenshot-import.tsx:176-199`는 해외 종목이 과반이면 `foreign`, 아니면 domestic으로 **전 종목을 한 카테고리로 `convertStockCategory`**한다. 혼합 결과의 소수 쪽이 통째로 바뀌고 가격도 환율로 나눠지거나 곱해진다(USD 1380 폴백 가정). 기존 앱 내 업로드에도 동일하므로 별도 `type:bug` 분리 대상. 인계 경로 해결: `initialParsed` 시 `applyMode="individual"`로 시작하고 공통 일괄 변환을 건너뛴다(`section` 기반 `resolvedCategory`만 유지). 이때 `commonCategory`·`commonBroker` 초기화 영향과 미리보기 UI의 개별 모드 표시를 qa가 확인. 기존 앱 내 업로드 동작은 4.39에서 **고치지 않는다**(범위 밖, 회귀 위험).
- **page.tsx 접촉 범위**: `(main)/page.tsx`는 `isWizardOpen`·`isWelcomeGuide`·`isMobile===undefined` 3개 조기 return이 있어 "인계 호스트 1줄"을 마지막 return에만 넣으면 0건 방문자(웰컴 분기)에서 호스트가 렌더되지 않는다. 분기마다 넣으면 diff 3곳. 호스트가 자체 게이팅(`isDataLoaded`·`!isPwaLocked()`·`!isSharePending`·`!wizard.isOpen`·`activeStep===null`)하므로 `(main)/layout.tsx`에 두면 1줄이다. 단 tutorial store·AssetDataProvider 아래여야 하고 layout의 TutorialStoreProvider 안쪽 배치 필요. **#48 웰컴 충돌**: 0건 방문자에서 웰컴이 먼저 렌더되고 그 위에 확인 창이 뜨며 `welcome_view` 1회 발생(spec 7절 기록대로). 튜토리얼은 웰컴 분기에서 `TutorialOverlay`가 `activeStep`을 켤 수 있어 "activeStep===null까지 대기"가 웰컴 사용자에게는 영원히 열리지 않을 수 있음 → **10분 만료로 조용히 사라짐**. 실제로 0건 방문자 전환이 핵심 경로이므로 구현 시 웰컴 분기에서 `activeStep`이 언제 non-null인지(TutorialOverlay `isWelcomeGuide` 처리) 먼저 확인 후 조건 확정. 미확정.
- **인앱 UA 저장 버튼**: 판정은 클라이언트 `navigator.userAgent`라 SSR 불가. 최초 렌더는 일반 버튼, 마운트 후 인앱이면 교체(깜빡임 최소화는 결과 화면이 업로드 후에만 나오므로 영향 없음). 외부 열기 안내는 #60 컴포넌트(`in-app-browser-gate.tsx`)가 `(main)` 의존이면 문구만 재사용 — 구현 시 확인.
- **canonical/OG**: `/ratio` metadata에서 `openGraph`·`twitter` 전체와 `images` 재선언 필수(challenge). OG_IMAGE 상수가 `layout.tsx` 내부 const라 공용 위치로 이동 또는 복제 필요(최소: 같은 파일 URL 상수 export).
- **UTM 인라인 복제**와 GA4 캠페인 인식은 preview에서 검증 불가(C9). 로컬 `isLocal`/optout 가드는 그대로.
- 입구 풀도 일반 IP 카운터(30)를 먼저 소모하므로 입구 5회가 IP 일반 30에 포함된다(의도와 일치, 문서화).
- Referer는 같은 출처 fetch에서 쿼리 포함 전체 URL이 올 수 있어 `pathname` 파싱으로 판정(`/ratio?utm=…`·`/ratio/` 모두 처리, `/ratio-x`는 불일치).

## 10. 질문 (cto/planner 결정 요청)
1. 인계 호스트 위치: `(main)/layout.tsx` 1줄로 변경해도 되는가(spec 12절은 page.tsx 1줄)? 기본 제안은 layout.
2. 0건 방문자에서 튜토리얼 `activeStep`이 웰컴에서도 켜지면 호스트가 10분간 대기 후 소멸한다. 이 경우 "웰컴 중에도 확인 창 우선"으로 조건을 완화할지(웰컴·튜토리얼 코드는 무수정 유지) 결정 필요. 구현 시 먼저 사실 확인 후 보고.
3. 공통 모드 혼합 결함을 type:bug로 분리하고 4.39에서는 인계 경로만 우회(앱 내 업로드 미수정)로 확정해도 되는가.
4. 인앱에서 외부 열기 안내를 `in-app-browser-gate` 문구 재사용(import)으로 할지, `/ratio` 전용 짧은 문구 상수로 할지(ui-designer 사양에 의존).
5. `OG_IMAGE`를 `src/config`로 이동(layout.tsx 1줄 수정)해도 되는가, 아니면 `/ratio`에 URL 복제 상수로 둘지.
