# #63 스크린샷 비중 미리보기 — spec

상태: planning ② 초안(planner-designer, 2026-11-01) — direction 합의 전 선작성, 사업 절 합의 후 확정 / 근거 코드: main 5eebe74
위험 등급 제안: **medium** (스키마·저장 키 무변경, 서버 한도 로직 변경, 새 공개 라우트)

## 1. 문제
엑셀·노션으로 종목 비중을 직접 계산하던 사람이 "한번 해보기"를 할 수 없다. 결과를 보려면 앱 진입 → 웰컴 → 금고 생성·등록을 거쳐야 하고, 채널 글에 걸 수 있는 "캡처 1장으로 바로 보기" 링크가 없다. 기준선: first_visit 월 약 17, first_asset_saved 0/17, screenshot_parse 0(STATE 28일).

## 2. 목표 행동
링크 도착 → 캡처 1장 업로드 → 비중 확인 → (선택) 저장 버튼으로 앱에 등록. 판독은 머지 후 8주: `ratio_preview` 업로드 시도 기기 수, 결과 확인 기기 수, 저장 연결 → `first_asset_saved` 기기 수.

## 3. 범위
direction 2절과 같다. 요약: 주식 캡처 1장 · 결과 1화면 · 금액 기본 가림 · 저장은 사용자 탭 시에만 기존 경로 · 입구 전용 AI 상한.

## 4. 사용자 흐름
1. `/ratio` 도착(SSR 본문: 제목·한 줄 설명·고지·업로드 버튼이 서버 렌더되어 링크 미리보기·크롤러에도 보인다). 마운트 시 `trackScreen("ratio")`.
2. 업로드 박스 아래 고지 1줄(아래 6절) → 사진 선택(JPG·PNG·WEBP·HEIC, 10MB 이하, 1장). 선택 즉시 업로드, 진행 표시(기존 `Loader2` 패턴).
3. 클라이언트 사전 검사: `useGeminiUsage().canUse()`(기기 15회/일). 초과면 기존과 같은 한도 안내, 업로드 안 함.
4. `POST /api/parse-screenshot` (`image`, `assetType=stock`, `entry=ratio`). 성공 시 `geminiUsage.increment("stock")`.
5. 결과 화면(같은 페이지, 상태 전환만):
   - 종목 비중 목록: 평가액(수량×현재가×환율) 내림차순, 상위 7개 + "그 외 N종목" 합산. 각 행 = 종목명·비중 %(소수 1자리, tabular-nums). 비중 링/막대 시각은 ui-designer.
   - 국내/해외 비율(파싱 응답 `section` 기준, "기타"는 국내 쪽 합산 대신 별도 표기).
   - 종목 수, 상위 3종목 합계 비중(사실 표시, 평가 문구 없음).
   - "금액 보기" 토글(기본 꺼짐). 켜면 행마다 평가액·합계 표시. 상태는 메모리만.
   - 안내 1줄: "이 결과는 저장되지 않아요. 페이지를 닫으면 사라져요."
   - 버튼: [내 기기에 저장하고 계속 관리](brand) / [다른 사진으로 다시 보기](보조).
6. 해외 종목 환산: `GET /api/finance?type=exchange`의 USD·JPY(공개 시세, 사용자 값 미전송). 실패 시 `StockScreenshotImport`와 같은 폴백(USD 1380)을 쓰고 "환율은 추정값이에요" 1줄 표시.
7. 저장 버튼:
   - 인앱 브라우저(`detectBrowserEnv`/`IN_APP_BROWSER_RE`, Threads=`barcelona` 포함)면 버튼을 "브라우저에서 열어 저장하기"로 바꾸고 #60과 같은 외부 열기 안내(현재 주소 복사·스킴)를 쓴다. 인계 데이터는 넘어가지 않으므로 "브라우저에서 사진을 한 번 더 올려 주세요" 명시.
   - 일반 브라우저면 파싱 원본 배열(`data.stocks`)을 **모듈 메모리 인계 저장소**(신규 `src/lib/ratio-preview/handoff.ts`, 저장 키 없음, 1회 소비, 10분 만료)에 넣고 `router.push("/")`(클라이언트 이동 — 같은 루트 레이아웃이라 모듈 상태 유지).
8. `(main)/page.tsx`의 인계 호스트: `isDataLoaded` 이후(앱 잠금이면 해제 후) 인계 데이터를 1회 소비해 `StockScreenshotImport`를 `initialParsed`로 연다 → 기존 매핑(`activeTab` 없음 → 공통 모드·defaultCategory 규칙 그대로)·`countConflicts`로 충돌 단계 또는 미리보기 단계 → 사용자가 "등록" 탭 시 기존 `handleRegister` 저장. 이 경로는 `increment`·`trackParse`를 다시 부르지 않는다.
9. 저장 성공 → 기존 토스트·`trackAssetSave`(자산 0건이었으면 `first_asset_saved` 자동) + `feature_use{category: ratio_preview, method: submit, result: create}` 1회. 취소하면 인계는 이미 소비되어 사라진다.

구현 메모: `stock-screenshot-import.tsx:132-209`의 응답 → `ImportStock[]` 매핑을 함수로 분리해 업로드 경로와 인계 경로가 같이 쓴다(중복 코드 금지).

## 5. 엣지 케이스
| 상황 | 동작 |
|---|---|
| 인식 0종목(`stocks` 빈 배열) | "인식된 종목이 없어요. 보유 종목 목록 화면을 캡처해 주세요." + 다시 올리기. `result: empty` |
| 평가액 0 종목(현재가 역산 실패) | 비중 계산에서 제외하고 "가격을 읽지 못한 종목 N개" 1줄 |
| 티커 없는 종목 | 미리보기는 이름으로 표시. 저장 단계는 기존 티커 입력 요구 그대로 |
| 입구 상한·IP 상한·전역 상한 초과(429) | "오늘 미리보기 이용이 많아 마감됐어요. 내일 다시 시도해 주세요." `result: limit` |
| 기기 15회 초과 | 기존 문구 재사용, 업로드 안 함 |
| 네트워크·5xx | 서버 메시지 표시, `result: fail` |
| 기존 금고가 있는 방문자 | 저장 시 기존 충돌 단계(교체/전체 대체)가 그대로 뜬다 — 미리보기 페이지는 금고를 읽지 않는다 |
| 앱 잠금(PIN) 사용자 | 인계 호스트는 잠금 해제·데이터 로드 뒤 연다. 10분 지나면 인계 만료 → 아무것도 열지 않음 |
| 새로고침·새 탭으로 `/` 열기 | 인계 없음(메모리) → 일반 화면. 재업로드 필요(의도) |
| 자산 0건 방문자 | `/`에서 웰컴 위에 확인 창이 뜬다. 웰컴 코드는 무수정(아래 #48 기록) |
| 체험 모드 | `/ratio`는 `TrialGate` 밖이라 영향 없음. `/?trial=1`과 인계는 동시에 생기지 않는다(앱 안 링크 없음) |
| preview 환경 | GA 꺼짐(기존). 파싱은 preview 키로 동작, 인계 저장은 PreviewGate 규칙 따름 |

## 6. 고지 문구 (#61 기준 그대로)
- 업로드 박스: `SCREENSHOT_UPLOAD_NOTICE` 상수 재사용 — "스크린샷은 AI 인식을 위해 전송돼요. 인식된 자산 값은 이 기기에 저장돼요."
- 결과 안내(이 페이지 전용 1줄): "이 결과는 저장되지 않아요. 페이지를 닫으면 사라져요." — 저장 전에는 "기기에 저장"이 사실이 아니므로 위 고지와 함께 둔다. 새 문구도 `security-copy.ts`에 둔다.
- 금지: "서버에 저장하지 않아요"·"이미지는 즉시 삭제돼요" 등 서버·외부 처리 단정, "안전하게 분석" 같은 보증, 투자 조언.

## 7. GA
- 가상 화면: `SCREEN_TITLES.ratio = "비중 미리보기"` → `/v/ratio`.
- `PARAM_VALUES.category`에 `ratio_preview` 추가(맞춤 정의는 이미 등록, 값만 추가).
- 이벤트: `feature_use{category: ratio_preview, method: submit, result: success|fail|empty|limit}`(업로드 결과), `feature_use{…, method: toggle}`(금액 보기), `feature_use{…, method: click}`(저장 버튼), 저장 완료는 4절 9. 기존 `screenshot_parse`는 보내지 않는다(앱 안 등록 지표와 분리).
- UTM: 현재 `page_location`이 쿼리를 버린다. 제안: `/ratio` 첫 `trackScreen`에서만 `utm_source|utm_medium|utm_campaign` 허용 목록을 `page_location`에 붙인다(그 외 쿼리 금지). tech-review가 GA4 캠페인 인식 여부를 확인.
- #48 오염 기록: 저장 연결로 `/`에 온 0건 기기는 `welcome_view`를 1회 보낸다. 12/25 #48 판독 때 `ratio_preview click` 기기를 제외 필터로 쓴다.

## 8. 서버 AI 입구 전용 한도 (현재 코드 확인값)
- 현재: 전역 `GEMINI_SERVER_DAILY_LIMIT = 300`(`cache-storage.ts:131`), IP당 `GEMINI_PER_IP_DAILY_LIMIT = 30`(`api-guard.ts`), 하루 5회 넘게 쓴 IP는 전역의 70%(210)까지만, 기기 `CLIENT_DAILY_LIMIT = 15`(`use-gemini-usage.ts:4`), L1 분당 20(`parse-screenshot/route.ts:648`).
- 제안: `entry=ratio` 요청에 한해 추가 카운터 2개를 먼저 예약하고, 기존 IP 30·전역 300도 그대로 함께 차감한다.
  - 입구 전용 전역 **60회/일**(전역의 20%) → 최악에도 앱 사용자 몫 240회 보장. 기대 사용량은 월 약 5회라 여유가 크다.
  - 입구 전용 IP당 **5회/일** — 통신사 공용 IP(CGNAT)로 여러 명이 같은 IP를 쓸 수 있어 3회보다 넉넉히, 실패 재시도 2~3회 허용.
  - 예약 실패 시 차감 되돌림은 기존 `reserveGeminiCalls` 방식과 같다.
- 한계(명시): `entry` 값은 클라이언트가 보내므로 빼고 보내면 일반 풀을 쓴다. 이 상한의 목적은 공개 입구의 정상 유입 급증이 앱 사용자 몫을 다 쓰지 않게 하는 것이고, 악의 호출은 기존 IP 30·전역 300·L1이 막는다(신규 노출 없음). 보강안: `Referer` 경로가 `/ratio`이면 `entry` 없이도 입구 풀로 분류(tech-review 판단).

## 10. 완료 기준 (qa 검사 문장)
1. `/ratio`가 `(main)` 밖 라우트이고, 페이지 렌더 중 `secretasset` 자산·스냅샷 저장 키에 대한 `getItem`/`setItem` 호출이 0건이다(저장 버튼 이후 `/` 경로 제외). 허용: `geminiUsage`·GA 플래그 키.
2. JS 끈 상태(SSR HTML)에 제목·설명·고지 문구가 있고 `<link rel="canonical">`이 `/ratio`를 가리킨다(루트 canonical 상속 금지).
3. 주식 캡처 1장 업로드 시 요청 본문에 `image`·`assetType=stock`·`entry=ratio`만 있다.
4. 결과 화면에 금액이 기본으로 보이지 않고, 토글 후에만 보인다. 비중 합계가 100%(반올림 오차 ±0.1)다.
5. 업로드 박스 고지가 `SCREENSHOT_UPLOAD_NOTICE`와 글자 단위로 같고, 페이지 전체에 "서버" 단정 문장·투자 조언 문구가 없다.
6. 일반 브라우저에서 저장 버튼 → `/` 이동 후 사진 재선택 없이 기존 확인 창(충돌 또는 미리보기 단계)이 열리고, 등록 탭 시 기존과 같은 저장 결과·토스트가 난다. 취소·새로고침 후에는 다시 열리지 않는다.
7. 인앱 UA(카카오톡·Threads `barcelona`)에서는 저장 버튼 대신 외부 열기 안내가 보인다.
8. 서버: 입구 전용 61번째(전역)·같은 IP 6번째 요청이 429와 6절 마감 문구를 반환하고, 그때도 `entry` 없는 일반 요청은 통과한다(단위 테스트). 기존 한도 테스트(`api-guard.test.ts`) 전부 통과.
9. GA: `/v/ratio` page_view 1회, `feature_use` category `ratio_preview` 값이 `PARAM_VALUES`·라벨에 등록(컴파일 통과), `screenshot_parse`는 이 페이지에서 전송되지 않는다.
10. 기존 4종 스크린샷 등록·마법사 회귀(F-* 관련 항목) PASS, 웰컴·결산·홈 팁 파일 diff 0.
11. 320·375px에서 결과 화면 문구 끊김 없음(C25), 히트영역 40px.

## 11. 제외 범위
배당 분포, ETF 구분, 결과 이미지 저장·공유, 여러 장·다른 자산군, 앱 안 진입 링크, sitemap·SEO 확장(G2), 결과 영구 저장, 체험 모드 컴포넌트 재사용(v1은 자체 경량 컴포넌트).

## 12. 결산 창 무접촉
결산(`settlement*`)·홈 팁(`home-tip*`)·웰컴(`welcome-guide.tsx`) 파일은 수정하지 않는다. `(main)/page.tsx`는 인계 호스트 1줄 추가만, 인계가 없을 때 렌더 결과 동일. 11/27~12/10에 머지하더라도 #51·#54 지표 경로와 겹치지 않는다(대표 일정: 11/26 이전 반영 목표).

## 13. 재사용 확인 결과 (코드)
- `parse-screenshot`: 이미지 1장·`assetType` 필드 구조 그대로 사용 가능. 추가는 `entry` 필드 읽기와 `reserveGeminiCalls` 옵션 전달뿐(`route.ts:681-702`).
- `api-guard`: `reserveGeminiCalls(request, n, message)`에 선택 인자 `{ pool, poolDailyLimit, poolPerIpDailyLimit }` 추가로 수용. 카운터는 기존 `incrementCounter`·`reserveGeminiDaily` 재사용.
- `StockScreenshotImport`: `useAssetData()`에 의존(`:84`)해 `(main)` 밖에서 쓸 수 없다 → 미리보기 페이지는 결과 화면만 자체 구성하고, 저장은 `/`에서 이 컴포넌트를 연다(4절 7~8).
- 배당 API: 티커만 받는 공개 API라 원칙상 사용 가능하나 v1 제외(direction 2절).
- 인앱 판정: `src/lib/pwa/detect-browser.ts` 재사용.
