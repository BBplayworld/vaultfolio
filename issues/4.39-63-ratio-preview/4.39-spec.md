# #63 스크린샷 비중 미리보기 — spec

상태: design-review 확정 (cto 교차 검토 2026-11-01, **4.39-design-final.md 우선**) — cto 반대 검토(4.39-challenge.md, 축소) 반영 / 근거 코드: main 5eebe74
위험 등급: **medium 확정**(cto) — 스키마·저장 키 무변경, 서버 한도 로직 변경, 새 공개 라우트, 공용 주식 등록 컴포넌트 변경

## 1. 문제
엑셀·노션으로 종목 비중을 직접 계산하던 사람이 "한번 해보기"를 할 수 없다. 결과를 보려면 앱 진입 → 웰컴 → 금고 생성·등록을 거쳐야 하고, 채널 글에 걸 수 있는 "캡처 1장으로 바로 보기" 링크가 없다. 기준선: first_visit 월 약 17, first_asset_saved 0/17, screenshot_parse 0(STATE 28일).

## 2. 목표 행동
링크 도착 → 캡처 1장 업로드 → 비중 확인 → (선택) 저장 버튼으로 앱에 등록. 판독은 머지 후 8주 퍼널: `/v/ratio` 기기 → `feature_use{ratio_preview, submit, success}` 기기 → `click` 기기 → `first_asset_saved` 기기.

## 3. 범위
direction 2절과 같다. 요약: 주식 캡처 1장 · 결과 1화면(비중·%만, **금액 표시 없음**) · 저장은 사용자 탭 시에만 기존 경로 · 입구 전용 AI 상한.

## 4. 사용자 흐름
1. `/ratio` 도착. SSR 본문(제목·한 줄 설명·고지·업로드 버튼)이 서버 렌더되어 링크 미리보기·크롤러에도 보인다. 마운트 시 `trackScreen("ratio")`.
2. 업로드 박스 아래 이 페이지 전용 고지 1문장(6절) → 사진 선택(JPG·PNG·WEBP·HEIC, 10MB 이하, 1장). 선택 즉시 업로드, 진행 표시(기존 `Loader2` 패턴).
3. 클라이언트 사전 검사: `useGeminiUsage().canUse()`(기기 15회/일). 초과면 기존 한도 안내, 업로드 안 함.
4. `POST /api/parse-screenshot` (`image`, `assetType=stock`, `entry=ratio`). 성공 시 `geminiUsage.increment("stock")`.
5. 결과 화면(같은 페이지, 상태 전환만):
   - 종목 비중 목록: 평가액(수량×현재가×환율) 내림차순, 상위 7개 + "그 외 N종목" 합산. 각 행 = 종목명·비중 %(소수 1자리, tabular-nums). 금액은 표시하지 않는다. 시각은 ui-designer.
   - 국내/해외 비율과 국내·해외 종목 수(파싱 응답 `section` 기준, "기타"는 별도 표기).
   - 전체 종목 수.
   - 버튼: [내 기기에 저장하고 계속 관리](brand) / [다른 사진으로 다시 보기](보조). 금액 확인은 저장 후 기존 확인 창 미리보기에서 한다.
6. 해외 종목 환산: `GET /api/finance?type=exchange`의 USD·JPY(공개 시세, 사용자 값 미전송). 실패하면 `StockScreenshotImport`와 같은 폴백(USD 1380)을 쓰고 "환율은 추정값이에요" 1줄을 표시한다.
7. 저장 버튼:
   - 인앱 브라우저(`IN_APP_BROWSER_RE` 재사용, Threads=`barcelona` 포함, #60): 버튼을 "브라우저에서 열어 저장하기"로 바꾸고 #60과 같은 외부 열기 안내를 쓴다. 인계는 넘어가지 않으므로 "브라우저에서 사진을 한 번 더 올려 주세요"를 명시한다(기기 한도도 따로 계산됨). `InAppExternalGuide`의 `lastStep`은 "이동한 브라우저에서 주소로 접속한 뒤 사진을 한 번 더 올려 주세요."(기본 "그대로 이어집니다"는 사실이 아니라 금지). GA는 `useExternalMove`의 `onTrack` 선택 인자로 `feature_use{ratio_preview, open}`만 보낸다(`pwa_install` 미전송, design-final U6).
   - 일반 브라우저: 파싱 원본 배열(`data.stocks`)을 **모듈 메모리 인계 저장소**(신규 `src/lib/ratio-preview/handoff.ts`)에 넣고 `router.push("/")`로 이동한다. 저장 키는 없다. 같은 루트 레이아웃이라 클라이언트 이동이 되고 모듈 상태가 유지된다.
   - 인계 규칙: 1회 소비. 10분 만료 시 **타이머로 참조를 실제로 지운다**(소비 시점 검사만으로 끝내지 않음).
8. `(main)/layout.tsx`의 인계 호스트(1줄, page.tsx diff 0)는 다음을 **모두** 만족할 때만 `StockScreenshotImport`를 `initialParsed`로 연다(재평가: 값 변화 + `PWA_UNLOCKED_EVENT`).
   - `isDataLoaded`
   - `!isPwaLocked()`(asset-data-context 공유 토큰 잠금 가드와 같은 함수)
   - `!isSharePending`
   - 온보딩 마법사 닫힘
   - `!isTrialMode()`(방어)
   - 튜토리얼 `activeStep`은 조건이 아니다: 새 기기·튜토리얼 미완료 기기는 늘 non-null이라 인계가 막힌다. `TutorialOverlay`는 웰컴에서 미렌더, 일반 화면에서는 다이얼로그가 열리면 스스로 숨는다(design-final Q2)

   조건을 기다리는 사이 만료되면 아무것도 열지 않는다. 확인 창에서는 기존 매핑과 `countConflicts`로 충돌 단계 또는 미리보기 단계로 가고, 사용자가 "등록"을 누르면 기존 `handleRegister`로 저장한다. 인계 경로는 `section` 기반 카테고리(국내/해외)를 유지해야 한다. 공통 모드 결함 의심은 13절에 적었다. 이 경로에서는 `increment`·`trackParse`를 다시 부르지 않는다.
9. 저장 성공 → 기존 토스트·`trackAssetSave`(자산 0건이었으면 `first_asset_saved` 자동) + `feature_use{category: ratio_preview, method: submit, result: create}` 1회. 취소하면 인계는 이미 소비되어 사라진다.

구현 메모: `stock-screenshot-import.tsx:132-209`의 응답 → `ImportStock[]` 매핑을 함수로 분리해 업로드 경로와 인계 경로가 같이 쓴다(중복 코드 금지).

## 6. 고지 문구 (#61 기준)
- 이 페이지 전용 1문장, `security-copy.ts`에 새 상수로 둔다(예: `RATIO_PREVIEW_UPLOAD_NOTICE`): "스크린샷은 AI 인식을 위해 전송돼요. 결과는 이 화면에만 보이고, 저장을 누를 때만 이 기기에 저장돼요."
- 기존 `SCREENSHOT_UPLOAD_NOTICE`는 이 페이지에 함께 두지 않는다. 저장 전에는 "기기에 저장"이 사실이 아니어서 나란히 두면 모순으로 읽힌다(C26).
- 금지: "서버에 저장하지 않아요"·"이미지는 즉시 삭제돼요" 같은 서버·외부 처리 단정, "안전하게 분석" 같은 보증, 투자 조언.

## 7. GA
- 가상 화면: `SCREEN_TITLES.ratio = "비중 미리보기"` → `/v/ratio`.
- `PARAM_VALUES.category`에 `ratio_preview`를 추가한다(맞춤 정의는 이미 등록되어 값만 추가).
- 이벤트(파라미터는 category·method·result만):
  - `feature_use{ratio_preview, submit, success|fail|empty|limit}`: 업로드 결과
  - `feature_use{…, click}`: 저장 버튼
  - 저장 완료는 4절 9
- 기존 `screenshot_parse`는 보내지 않는다(앱 안 등록 지표와 분리). 종목명·티커·금액·비중은 어떤 이벤트에도 싣지 않는다.
- UTM(design-final 6절로 정정): `ga.ts`가 모든 이벤트의 `page_location`을 이벤트 단위로 덮어쓰므로, **`ga.ts` `pageLocation()`에서** `location.pathname`이 `/ratio`일 때만 `utm_source|utm_medium|utm_campaign`을 붙인다. 값은 `[A-Za-z0-9._-]{1,50}`이고 그 밖의 쿼리는 버린다. 루트 인라인 gaConfig는 수정하지 않는다. 판정은 순수 함수로 분리해 vitest로 검증한다. GA4가 실제로 캠페인을 인식하는지는 preview에서 GA가 꺼져 있어 확인할 수 없다(알려진 한계 C9).
- #48 오염 기록: 저장 연결로 `/`에 온 0건 기기는 `welcome_view`를 1회 보낸다. 12/25 #48 판독 때 `ratio_preview click` 기기를 제외 필터로 쓴다.

## 8. 서버 AI 입구 전용 한도 (cto 확정)
- 현재 한도(코드 확인값):
  - 전역 `GEMINI_SERVER_DAILY_LIMIT = 300`(`cache-storage.ts:131`)
  - IP당 `GEMINI_PER_IP_DAILY_LIMIT = 30`(`api-guard.ts`), 하루 5회 넘게 쓴 IP는 전역의 70%까지만
  - 기기 `CLIENT_DAILY_LIMIT = 15`(`use-gemini-usage.ts:4`)
  - L1 분당 20(`parse-screenshot/route.ts:648`)
- **입구 풀 판정**: `entry === "ratio"` **또는** Referer 경로가 `/ratio`인 요청. 같은 출처 fetch는 `Referrer-Policy: strict-origin-when-cross-origin`(`next.config.mjs:61`)이라 전체 경로를 보낸다.
- 입구 풀에 추가되는 한도:
  - 입구 전역 **60회/일**: 최악에도 앱 사용자 몫 240회가 남는다
  - 입구 IP당 **5회/일**: CGNAT와 재시도 2~3회를 감안
- 예약 순서: IP 일반 → 입구 IP → 입구 전역 → 전역. 어느 단계에서 실패해도 그 앞에서 증가시킨 카운터를 **전부 되돌린다**. 카운터는 기존 `incrementCounter`·`reserveGeminiDaily`를 재사용한다.
- 한계(명시): 스크립트로 `entry`와 Referer를 모두 빼면 일반 풀을 쓴다. 이 경우는 기존 IP 30·전역 300·L1이 막으므로 새로 노출되는 면은 없다.

## 10. 완료 기준 (qa 검사 문장)
1. `/ratio`는 `(main)` 밖 라우트이고, 페이지 렌더 중 자산·스냅샷 저장 키에 대한 `getItem`/`setItem` 호출이 0건이다(저장 버튼 이후 `/` 경로 제외). 허용되는 키는 `geminiUsage`·GA 플래그뿐이다.
2. SSR HTML(JS 끔)에 다음이 있다. robots는 상속, sitemap에는 `/ratio`가 없다.
   - 제목·설명·고지 문구
   - `<link rel="canonical">` = `/ratio`
   - `og:url` = `/ratio`
   - `og:image`(기존 OG 이미지)
   - `twitter:card` = `summary_large_image`
3. 업로드 요청 본문에는 `image`·`assetType=stock`·`entry=ratio`만 있다.
4. 결과 화면 어디에도 금액(원·달러 값)이 없고, 비중 합계가 100%(반올림 오차 ±0.1)다. 구현은 largest remainder로 표시 합 100.0(목록·국내/해외 막대 모두).
5. 업로드 고지는 `security-copy.ts`의 이 페이지 전용 상수와 같고, `SCREENSHOT_UPLOAD_NOTICE`는 이 페이지에 렌더되지 않는다. 페이지 전체에 "서버" 단정 문장·투자 조언 문구가 없다.
6. 일반 브라우저에서 저장 버튼 → `/` 이동 후 사진을 다시 고르지 않아도 기존 확인 창(충돌 또는 미리보기 단계)이 열린다. 등록을 누르면 기존과 같은 저장 결과·토스트가 난다. **미리보기의 국내/해외 종목 수와 저장 후 국내/해외 종목 수가 같다.** 취소·새로고침 뒤나 10분이 지난 뒤에는 다시 열리지 않는다. 앱 잠금·공유 대기·마법사 중에는 열리지 않고 해제 후 열린다. 튜토리얼 미완료 기기·0건 기기에서도 열리며, 열린 동안 튜토리얼 스포트라이트·웰컴과 겹쳐 보이지 않는다(375 스크린샷). 국내·해외 혼합 인식은 앱 내 업로드에서도 개별 선택 모드로 시작해 저장 후 국내/해외 수가 유지된다(bug 이슈, design-final Q3).
7. 인앱 UA(카카오톡·Threads `barcelona`)에서는 저장 버튼 대신 외부 열기 안내가 보인다.
8. 서버 vitest 3건: 입구 61번째 요청은 429와 5절 마감 문구를 반환한다 / 같은 IP의 6번째 입구 요청은 429다 / 그 상태에서 `entry`·Referer가 없는 일반 요청은 통과한다. 예약 실패 시 앞 단계 카운터가 되돌려진다. 기존 `api-guard.test.ts`는 전부 통과한다.
9. GA:
   - `/v/ratio` page_view가 1회 전송된다
   - category `ratio_preview`가 `PARAM_VALUES`·라벨에 등록되어 컴파일이 통과한다

## 13. 재사용 확인 결과와 결함 의심
- `parse-screenshot`: 이미지 1장·`assetType` 구조를 그대로 쓴다. 추가는 `entry`·Referer 판정과 `reserveGeminiCalls` 옵션 전달뿐이다(`route.ts:681-702`).
- `api-guard`: `reserveGeminiCalls(request, n, limitMessage, pool?: { name: "ratio"; dailyLimit; perIpDailyLimit })`(design-final 4절). 입구 요청의 모든 429 문구는 route가 `limitMessage`로 넘긴다.
- `StockScreenshotImport`: `useAssetData()`에 의존해 `(main)` 밖에서 쓸 수 없다. 그래서 결과 화면은 자체 구성하고, 저장은 `/`에서 이 컴포넌트를 연다.
- 배당 API: 티커만 받는 공개 API라 원칙상 쓸 수 있지만 v1에서는 뺀다.
- 인앱 판정: `src/lib/pwa/detect-browser.ts`를 재사용한다.
- **결함 의심(qa 확인 요청)**: 공통 모드(`applyMode="common"`, 기본값)가 파싱 직후 모든 종목을 `defaultCategory` 하나로 `convertStockCategory`한다(`stock-screenshot-import.tsx:184-199`). 그러면 국내·해외 혼합 인식 결과가 한 카테고리로 바뀌어 미리보기 비율과 저장 결과가 달라진다. 인계 경로는 개별 모드로 시작하거나 같은 효과를 내야 한다(완료 기준 6). **확정(cto 2026-11-01)**: 코드상 확인되어 type:bug 별도 이슈(초안 `4.39-bug-draft-common-mode.md`)로 분리하고 4.39에 동승한다. 혼합 section이면 개별 모드로 시작(인계 경로와 같은 분기), 단일 section은 현행과 동일.
