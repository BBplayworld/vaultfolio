## 1. 문제 / 2. 목표 행동
- 문제: 주식 숫자가 어느 날 기준인지 증권사별로 보이지 않는다. 다 맞는 걸 확인한 날은 어디에도 남지 않는다(`changes === 0`이면 `맞추기` 꺼짐, `holdings-resync-dialog.tsx:651`).
- 목표 행동: 상세·주식 `증권사별`을 열고, 날짜가 오래됐거나 없는 행의 `맞추기`를 눌러 다시 맞춘다. 다음에 열면 그 행 날짜가 오늘이다.

## 3. 범위
- 포함: ① 주식 `BrokerRow` 메타 줄 `N종목 · M/D 맞춤` ② 변경 0 확인 경로 ③ 되돌리기 시 날짜 원복 ④ 주식 블록 비중 조각 제거(별도 커밋) ⑤ GA `resync_confirm_same` ⑥ 데모 메타 날짜 예시.
- 범위 밖: 코인 거래소별 행(코인 DOM·비중 유지, 코인 맞추기는 날짜 쓰기 0), 홈·FAB·종목 펼침의 날짜 반복, 경과일(`N일 전`)·독촉·색 경고, 동기화·백업 포함, 접힌 헤더 날짜(후속 후보), 새 저장 키·숨김 키.

## 4. 사용자 흐름
**쓰기 가능 범위(정의, 두 경로 공통)** — `handleApply` 클릭 순간 `getAssetData()`로 다시 계산한 `computeDiff` 결과 `d` 기준(memo 값 금지).
1. `d.incomplete === true`이면 범위 0(실패·잘림·한도·실패 장 제거·증권사 미확정 장 중 하나라도 있으면 아무 날짜도 쓰지 않음. diff.ts 정의 그대로).
2. 후보 = `d.scopes`(확정 장의 증권사 × `Stock.category`, unlisted 없음).
3. 제외: 그 범위에 `resolveRow` 결과가 skip인 `needs` 행이 있음(행의 범위 = `item.broker` × `item.category`, ambiguous면 후보들의 category도 포함) / 그 범위 `removes` 중 적용 후에도 남는 항목이 있음(삭제 해제·기본 해제 포함, 이관된 항목은 제외).
4. 남은 범위마다 `{ broker: scope.broker, category, date: todayKst(), count }`를 쓴다. `count` = 저장 직후 stocks에서 `category` 같고 `sameBroker`이며 `inactiveStatus !== "delisted" && quantity > 0`인 **항목 수**.

**경로 A — 변경 있음(`changes > 0`, 현행 + 날짜)**
1. 맞추기 → `saveData(next)` 성공 → `markCategoryRefreshed("stock")`(현행) → 쓰기 가능 범위에 날짜 기록(`next.stocks`로 count) → 결과 화면.
2. `saveData` 실패면 날짜 쓰기 0(현행 `맞추기에 실패했어요`). 날짜 쓰기 실패는 무시(자산 저장이 정본).
3. 코인(`kind === "crypto"`)은 날짜 쓰기 0.

**경로 B — 변경 0 확인(주식만)**
1. 미리보기에서 `changes === 0 && kind === "stock" && 쓰기 가능 범위 ≥ 1`이면 `맞추기` 켜짐. 범위 0이면 현행대로 꺼짐.
2. 누르면 `applyResync`·`saveData`·`pruneStockTargets`·결과 대조(reconcile·GA 구간) 모두 호출 0. 날짜 기록(count는 `getAssetData().stocks`) + `markCategoryRefreshed("stock", { notify: false })`만.
3. 다시 읽어 기록이 없으면 토스트 오류, 미리보기 유지, GA 0. 있으면 결과 화면.
4. 되돌리기(결과 버튼·닫은 뒤 토스트)는 `brokers.stock`·`categories.stock`만 비교 후 원복. `planUndo`·`saveData`·`resync_undo` 0.
5. 닫으면 현행 `shouldNotifyResyncClose`로 복귀 신호(되돌렸으면 0).

## 5. 데이터 계약 (`secretasset_asset_refresh`)
- 모양: `brokers?: { stock?: Array<{ broker: string; category: "domestic"|"foreign"|"irp"|"isa"|"pension"; date: "YYYY-MM-DD"; count: number }> }`. 증권사 이름을 객체 키로 쓰지 않는다(배열) → `__proto__`·`constructor` 무관. `brokers` 아래 키는 `stock` 고정. 금액·수량·종목명 0.
- 쓰기(upsert): 기존 항목 중 `sameBroker && category 같음`을 지우고 추가. 최대 60항목(초과 시 오래된 날짜부터 버림). `brokers`가 plain object면 다른 키 보존, 아니면 `{ stock }`으로 교체. `categories`·`nudgeShownOn`은 `writeMeta` 병합으로 보존.
- 파서(관대, **throw 0**, 전체 try/catch): meta·`brokers`가 객체 아님 / `stock`이 배열 아님 → `[]`. 항목별로 버림: 객체 아님, `broker`가 문자열 아님·미지정(`isUnassignedBroker`)·40자 초과, category가 5종 밖(unlisted 포함), date가 형식·달력 불일치 또는 KST 오늘보다 미래, count가 0 이상 정수 아님. 같은 범위 중복은 늦은 날짜 1개. 읽기는 `hasOwn`만.
- 손상 시: 표시 조각 0, `categories`·홈 넛지·FAB는 그대로 동작. 다음 쓰기에서 유효 항목만 남겨 덮는다.
- 쓰는 곳은 맞추기 대화상자 1곳(`handleApply` 두 경로 + 되돌리기). 스크린샷 가져오기·수동 입력·거래 입력·데모 외 경로 0. **assetData 쓰기 0**(경로 B), 배당·결산은 `brokers` 읽기 0.
- 되돌리기 원복: 적용 직전 `stock` 배열(없음 포함)과 적용 직후 값을 사본에 둔다. 현재 값이 적용 직후 값과 같을 때만 이전 값으로(없었으면 `stock` 키 삭제). `restoreCategoryRefreshed`와 같은 방식.
- 동기화·백업 제외: `buildExportPayload`·sync payload에 이 키를 넣지 않는다(현행 그대로). `clearAssetData` keepKeys에 있어 pull·복원 후 보존, `전체 삭제`는 `clearAssetRefreshStatus`로 제거.
- 구버전·롤백: 21bd696 `writeMeta`는 `{...readMeta(), ...patch}`라 `brokers` 보존. 롤백 중 맞추면 날짜가 갱신되지 않아 이른 날로 보임 → 그대로 표시(그날 맞춘 사실, 한계로 기록).
- 화면 갱신: 기록·원복 직후 로컬 window 이벤트 1개(예 `asset-broker-synced`, 저장 0)를 보내고 블록이 다시 읽는다. `asset-category-refreshed`는 재사용 금지(FAB 복귀 신호와 섞임).
- 데모: `buildDemoRefreshMeta`에 `brokers.stock` 추가 — 데모증권 domestic·foreign(count 2·2, 2일 전), 연금저축 pension(count 1, 작년 12/3), ISA 없음. 세 표기를 preview에서 확인.
