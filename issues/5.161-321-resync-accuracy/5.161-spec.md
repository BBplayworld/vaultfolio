## 1. 문제
- (a) 코인 맞추기에서 체크로 지운 코인의 거래가 남는다. `holdings-resync-dialog.tsx:377`이 코인이면 `planResyncSave`를 건너뛰고 `crypto`만 바꾼다. 남은 거래는 결산·홈 원인에 계속 더해진다. 주식은 5.156에서 고쳤다. 미리보기 고지도 `kind === "stock"`일 때만 정리 문구를 띄운다(`:874`).
- (b) 맞춘 뒤 숫자가 증권사 화면과 맞는지 확인할 방법이 없다. 프롬프트가 총평가금액을 `무시`하라고 지시한다(`route.ts:51`).
- (c) 마무리: 종목 한 장의 `거래내역 N건`(`stock-page-view.tsx:449`)은 3년 보존분만 세는데 그런 표기가 없다. 토스트 '되돌리기' 가림은 tech-review ④에서 **현재 코드로는 가려지지 않음**으로 확인했다(sonner z 999999999 > 시트 z-[10001~2], 맞추기 대화상자가 닫힌 뒤 열린 모달 0). 그래서 구조를 바꾸지 않고 확인 테스트만 둔다.

## 2. 목표 행동
- 코인 보유자가 맞추기로 코인을 지우면 그 코인의 거래도 직접 삭제와 같은 규칙으로 정리된다. 되돌리기를 누르면 거래까지 돌아온다.
- 주식 보유자가 증권사 화면 1장으로 맞춘 직후 결과 화면에서 "증권사 화면 합계와 맞는지"를 읽는다. 다르면 어느 종목이 다른지 보고 그 행을 고친다.

## 4. 사용자 흐름
**(a) 코인 맞추기 삭제**
1. 거래소 화면을 올리고 미리보기에서 `업비트 화면에 없는 코인` 묶음의 코인을 체크한다(상태 라벨 `삭제`).
2. 체크한 코인 중 평가액이 남아 거래가 정리되는 코인이 있으면, 고지가 주식과 같은 문구로 바뀐다: `지우는 코인은 거래 기록도 함께 정리돼요`. 없으면 현행 문구 `거래 기록은 그대로 남아요…`를 유지한다. 주식 문구의 '종목'만 COPY 규칙으로 '코인'으로 바꾼다.
3. `맞추기` → 코인·코인 거래를 저장 1회로 함께 쓴다. 정리 규칙은 `planDeleteCryptos`를 그대로 쓴다(평가액 0 이하 코인은 거래 유지, 지난달 연결 짝 거래 유지, 연결 현금·대출 기록과 잔액 불변). 새 규칙은 만들지 않는다.
4. 결과 화면 `되돌리기`(닫은 뒤 토스트도 같은 사본) → 코인과 정리된 거래가 함께 돌아온다. **필수 조건**: 되돌리기 목록에 `crypto`와 `cryptoTransactions` 두 컬렉션을 담는다(주식 `buildResyncUndoEntries`와 같은 방식). 지금 코인 되돌리기는 `crypto`만 담는다(`:389`). 거래 정리만 넣고 이것을 빠뜨리면 되돌린 뒤 거래가 사라진다. 이 경우 데이터 손실이므로 high로 다시 판정한다.
5. 삭제 id는 'diff에서 체크한 행'이 아니라 **'맞추기 직전 `fresh.crypto`에 있고 결과에 없는 id'**로 계산한다. 이름이 바뀌어 매칭된 코인이 잘못 지워지는 일을 막기 위해서다. 구현은 `transfer.ts`에 `planCryptoResyncSave`를 둔다(tech-review ①).

**(b) 대조 1줄(주식만)**
1. 증권사 화면 1장을 인식한다. 서버는 같은 이미지에서 행과 **별도 필드**로 화면 총액을 읽는다.
2. 미리보기 → `맞추기`.
3. 결과 화면 요약 줄(`resync-result` 첫 줄) 바로 아래에 대조 1줄을 둔다(새 카드 0, 같은 상자 안 `text-sm`, 숫자 tabular-nums).
4. 차이가 있으면 둘째 줄에 다른 종목 이름을 보여 준다. 사용자는 `닫기` 뒤 그 종목을 고치거나 `되돌리기`를 누른다. 되돌리면 대조 줄을 숨긴다(이미 맞춘 상태가 아니므로).

**(c) 마무리**
1. 되돌리기 구조는 그대로 둔다. 결과 화면 `되돌리기` 버튼이 정본이고, 닫은 직후 토스트 `되돌리기`는 같은 사본을 쓴다. 두 진입은 같은 화면에 동시에 보이지 않는다(C124 위반 아님). 확인 테스트만 더한다. 대화상자 닫힘 애니메이션(약 200ms) 동안 토스트를 누를 수 없는 문제는 실사용 영향이 작아 이번 범위에 넣지 않는다.
2. 종목 한 장: `거래내역 N건` → `최근 3년 거래 N건`. 세는 방식은 그대로다(보존 3년, `TRANSACTION_RETENTION_YEARS` 상수 참조). 0건 표기도 같은 꼴(`최근 3년 거래 0건`).
3. 환율 기준일 표기는 **제외**한다(tech-review ⑤: 날짜를 새로 저장하면 high). 메모(후속 판정용 사실): context에 `exchangeRateDate`가 이미 있다(`asset-data-context.tsx:478`, 기존 키 `exchangeSyncDate`에서 읽음, `:1285`). 다만 이 값은 '동기화한 날'이지 '환율 기준일'이 아니고, 조회 실패 때는 기본값 1380이 들어간다. 그래서 그대로 쓰면 문구가 사실과 어긋날 수 있다. 다시 할 때는 tech-review 1쪽으로 판정한다.

## 5. 대조 1줄 사양
**계산(기기 안, 메모리만)**
- 화면 총액 `screenTotal`: 서버 응답 `{ stocks, screenTotal?: { value, label, currency } }`. 행 배열과 섞지 않는다.
- 앱 합계: **화면 행에 대응하는 앱 종목**의 맞춘 뒤 `수량 × 앱 현재가`(원화 환산, 화면 표시와 같은 환율). 화면에 없는 종목(삭제 후보 유지분)은 넣지 않는다.
- 비교 기준은 **'맞춘 뒤 앱 값' 대 화면 총액**이다(tech-review ③ 권장 채택). 사용자가 궁금한 것은 '내 앱이 증권사와 같은가'이기 때문이다. 대상은 이번 장이 덮은 증권사·계좌 유형(덮어쓴 값 포함)의 종목뿐이다.
- 차이율 = |앱 합계 − 화면 총액| / 화면 총액. 표시는 소수 1자리(`2.4%`).
- **허용 오차 = max(화면 총액 × 0.5%, 1,000원). 이내면 일치.** 시세 시각·환율 차이를 흡수하는 값이다. 경계값(오차와 정확히 같음)은 일치로 본다.
- 다른 행: 행별 화면 `currentValue`와 앱 값의 차이가 같은 식(max(행 값 × 0.5%, 1,000원))을 넘는 행. 차이가 큰 순서로 최대 2개 이름 + `외 N개`. 화면 `currentValue`가 0인 행은 비교하지 않는다.
- 계산은 순수 함수(`reconcileTotal`, tech-review ③)에 두고 결과를 `match | diff | hidden` 3값으로 돌려준다.

**문장(C138, 3가지 값 대입)**
| 상태 | 화면 문장 | GA category(title) |
|---|---|---|
| 일치(차이 0.4%, 오차 안) | `증권사 화면 합계와 맞아요` | `resync_check_match`(보유 현황 맞추기 대조·일치) |
| 차이(2.4%, 다른 행 있음) | 1줄 `증권사 화면 합계와 2.4% 달라요. 시세 시각이 달라 조금 다를 수 있어요` / 2줄 `차이가 큰 종목: 삼성전자, TIGER 미국S&P500 외 1개` | `resync_check_diff`(…·차이) |
| 차이(2.4%, 다른 행 없음) | 1줄 같음 / 2줄 `화면에 안 담긴 종목이 있을 수 있어요` | `resync_check_diff` |
| 총액 없음·숨김 조건 | 줄 없음(DOM 0) | `resync_check_none`(…·총액 없음). 숨김 사유 구분 없이 1개 |
- 금지 어휘: 투자 조언, `정확해요`·`보장`, `서버로 안 보내요`·`아무것도 안 나가요`(스크린샷은 서버에서 분석한다), 금액 숫자.
- GA는 적용 1회당 위 3개 중 1개만 보낸다. 금액·%·증권사명·종목명은 보내지 않는다. 체험 중에는 `ga.ts:401`에서 막힌다(현행). 코인 맞추기에서는 보내지 않는다.

**숨김 조건(하나라도 해당하면 줄 없음)**
1. `screenTotal` 없음 또는 0 이하·숫자 아님, 또는 통화가 KRW가 아님.
2. 예수금 포함이 모호함: 라벨에 `평가`가 없거나 `자산`·`예수금`·`예탁`·`추정`·`순` 중 하나라도 있으면 숨긴다(예: `총자산`·`추정자산`). 그래서 서버는 총액과 함께 화면 라벨 글자(`label`)를 돌려준다. 이 값은 같은 이미지에서 읽은 글자이며 요청은 늘지 않는다. [TR] 라벨 목록은 픽스처 화면에서 확정한다. 라벨을 얻지 못하면 줄을 숨긴다. CEO ③-6에 따라 '숨김'이 기본이고, 차이 문구로 대신하지 않는다.
3. 인식 성공 장이 2장 이상이거나, 실패·잘림(`truncated`)·한도 장이 1장이라도 있거나, 실패 장을 지운 상태(`failedRemoved`).
3-1. 해외 종목이 섞였는데 환율이 추정값이다(tech-review ③-④).
4. 미리보기에서 `확인 필요` 행이 있거나, 화면 행 중 적용하지 않은 행(추가 체크 해제 등)이 있음. 이 행들은 앱 합계에 없어 차이가 거짓으로 생긴다.
5. 대응 앱 종목 중 현재가 0 또는 시세 조회 실패 상태인 종목이 있음. [TR] 5.153 시세 신선도 신호 재사용.
6. 되돌리기를 누른 뒤.

**서버 조건(CEO ③, qa 데이터 안전 점검표)**
1. 요청 본문은 그대로다(이미지·assetType). 앱 합계·보유 목록은 보내지 않는다.
2. 서버는 `screenTotal`을 저장·캐시·로그하지 않는다. `:833` 오류 로그는 `e.message`만 남긴다. qa가 grep으로 확인한다.
3. 응답에서 행과 분리된 필드로 둔다. Gemini 스키마는 `{ rows, screenTotal }`로 감싸고, 파서는 배열과 `{rows}`를 둘 다 받는다(tech-review ②). 프롬프트에는 '합계 줄은 행으로 만들지 말 것'을 남긴다. 지금은 `무시: 총평가금액`이 이 역할을 한다. 클라이언트 응답 `{ stocks, screenTotal? }`는 필드만 더하는 변경이라 종목 등록·온보딩·/ratio는 영향이 없다. `maxOutputTokens` 2048 잘림 여유는 픽스처로 잰다. **기존 인식 픽스처 행 회귀 0이 머지 조건이다.** 하나라도 어긋나면 대조 1줄을 5.162로 분리한다.
4. 기기에서는 결과 화면 상태로만 쓴다. AssetData·localStorage에 쓰지 않는다(저장하면 스키마 변경이라 high로 재판정).

## 7. 엣지 케이스
- 빈 데이터: 주식 0건이면 맞추기 대화상자가 열리지 않는다(기존 `StockScreenshotImport`). 대조 줄도 없다. 코인 거래가 0건이면 고지는 현행 문구를 쓴다.
- 일부 갱신: 일부 행만 적용하면 숨김 조건 4에 걸린다. 코인 일부만 체크 삭제하면 체크한 코인의 거래만 정리된다.
- 오래된 데이터: 시세 실패·현재가 0이면 숨긴다(5). 상장폐지·평가액 0 코인은 거래를 남긴다(`planDeleteCryptos` 현행).
- 첫 사용자: 맞추기 1회차도 같은 규칙. 체험(`?trial=1`)에서는 스크린샷 인식 가능 여부에 따라 대조 줄이 보이지 않을 수 있다. 새 소식 노출과 함께 상태표에 적는다(C126). [TR]
- 맞춘 뒤 닫고 다시 열면 대조 줄은 없다(메모리만).
