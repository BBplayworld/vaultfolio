## 1. 문제
- (a) 코인 맞추기에서 체크로 지운 코인의 거래가 남는다. `holdings-resync-dialog.tsx:377`이 코인이면 `planResyncSave`를 건너뛰고 `crypto`만 바꾼다. 남은 거래는 결산·홈 원인에 계속 더해진다. 주식은 5.156에서 고쳤다. 미리보기 고지도 `kind === "stock"`일 때만 정리 문구를 띄운다(`:874`).
- (b) 맞춘 뒤 숫자가 증권사 화면과 맞는지 확인할 방법이 없다. 프롬프트가 총평가금액을 `무시`하라고 지시한다(`route.ts:51`).
- (c) 마무리 3곳: 시트 위에서 닫으면 토스트 '되돌리기'가 시트에 가려 눌리지 않는다. 종목 한 장의 `거래내역 N건`(`stock-page-view.tsx:449`)은 3년 보존분만 센다. 해외 거래의 `지금 환율이에요`(`trade-input.tsx:914`)는 환율 조회에 실패해도 그대로 나온다(`exchangeRateDate`가 이미 있음).

## 2. 목표 행동
- 코인 보유자가 맞추기로 코인을 지우면 그 코인의 거래도 직접 삭제와 같은 규칙으로 정리된다. 되돌리기를 누르면 거래까지 돌아온다.
- 주식 보유자가 증권사 화면 1장으로 맞춘 직후 결과 화면에서 "증권사 화면 합계와 맞는지"를 읽는다. 다르면 어느 종목이 다른지 보고 그 행을 고친다.

## 4. 사용자 흐름
**(a) 코인 맞추기 삭제**
1. 거래소 화면을 올리고 미리보기에서 `업비트 화면에 없는 코인` 묶음의 코인을 체크한다(상태 라벨 `삭제`).
2. 체크한 코인 중 평가액이 남아 거래가 정리되는 코인이 있으면, 고지가 주식과 같은 문구로 바뀐다: `지우는 코인은 거래 기록도 함께 정리돼요`. 없으면 현행 문구 `거래 기록은 그대로 남아요…`를 유지한다. 주식 문구의 '종목'만 COPY 규칙으로 '코인'으로 바꾼다.
3. `맞추기` → 코인·코인 거래를 저장 1회로 함께 쓴다. 정리 규칙은 `planDeleteCryptos`를 그대로 쓴다(평가액 0 이하 코인은 거래 유지, 지난달 연결 짝 거래 유지, 연결 현금·대출 기록과 잔액 불변). 새 규칙은 만들지 않는다.
4. 결과 화면 `되돌리기` → 코인과 정리된 거래가 함께 돌아온다(`buildUndoEntries(..., "cryptoTransactions")`. 코인 경로에도 이미 있는 컬렉션 키를 쓴다). [TR] `planResyncSave`를 일반화할지 코인 경로에서 `planDeleteCryptos`를 직접 부를지.

**(b) 대조 1줄(주식만)**
1. 증권사 화면 1장을 인식한다. 서버는 같은 이미지에서 행과 **별도 필드**로 화면 총액을 읽는다.
2. 미리보기 → `맞추기`.
3. 결과 화면 요약 줄(`resync-result` 첫 줄) 바로 아래에 대조 1줄을 둔다(새 카드 0, 같은 상자 안 `text-sm`, 숫자 tabular-nums).
4. 차이가 있으면 둘째 줄에 다른 종목 이름을 보여 준다. 사용자는 `닫기` 뒤 그 종목을 고치거나 `되돌리기`를 누른다. 되돌리면 대조 줄을 숨긴다(이미 맞춘 상태가 아니므로).

**(c) 마무리**
1. 되돌리기 정본은 결과 화면 `되돌리기` 버튼이다. 닫은 뒤 토스트 action은 **닫은 뒤 화면에 열린 시트·모달이 없을 때만** 둔다. 시트 위라면 action 없이 `보유 현황을 맞췄어요`만 띄운다. 토스트 action 라벨은 결과 화면 버튼과 같은 `되돌리기`로 한다. 한 화면에 보이는 진입은 1개다(C124). [TR] 시트 열림 판정 방법(`sheet.tsx` z-[10001~2]).
2. 종목 한 장: `거래내역 N건` → `최근 3년 거래 N건`. 세는 방식은 그대로다(보존 3년, `TRANSACTION_RETENTION_YEARS` 상수 참조). 0건 표기도 같은 꼴(`최근 3년 거래 0건`).
3. 해외 거래 입력 환율 안내: 환율 기준일(`exchangeRateDate`)이 오늘(KST)이면 현행 `지금 환율이에요. 체결 때 환율로 고칠 수 있어요`를 유지한다. 오늘이 아니면 `11/25 환율이에요. 체결 때 환율로 고칠 수 있어요`(M/D, 앞자리 0 없음)로 바꾼다. 기준일이 비어 있으면 `저장된 환율이에요. 체결 때 환율로 고칠 수 있어요`로 쓴다. `비워 두면 지금 환율로 저장해요`도 같은 조건으로 `지금`을 바꾼다.

## 5. 대조 1줄 사양
**계산(기기 안, 메모리만)**
- 화면 총액 `screenTotal`: 서버 응답 `{ stocks, screenTotal?: { value, label, currency } }`. 행 배열과 섞지 않는다.
- 앱 합계: **화면 행에 대응하는 앱 종목**의 맞춘 뒤 `수량 × 앱 현재가`(원화 환산, 화면 표시와 같은 환율). 화면에 없는 종목(삭제 후보 유지분)은 넣지 않는다.
- 차이율 = |앱 합계 − 화면 총액| / 화면 총액. 표시는 소수 1자리(`2.4%`).
- **허용 오차 1.0% 이하 = 일치.** 시세 시각·환율 차이를 흡수하는 값이다. [TR] 운영 픽스처로 1.0% 적정성 확인(바꾸면 이 줄만 고친다).
- 다른 행: 행별 화면 `currentValue`와 앱 값의 차이가 1.0%를 넘는 행. 최대 2개 이름 + `외 N개`. 화면 `currentValue`가 0인 행은 비교하지 않는다.

**문장(C138, 3가지 값 대입)**
| 상태 | 화면 문장 | GA category(title) |
|---|---|---|
| 일치(차이 0.4%) | `증권사 화면 합계와 맞아요` | `resync_check_match`(보유 현황 맞추기 대조·일치) |
| 차이(2.4%, 다른 행 있음) | 1줄 `증권사 화면 합계와 2.4% 달라요. 시세 시각이 달라 조금 다를 수 있어요` / 2줄 `차이가 큰 종목: 삼성전자, TIGER 미국S&P500 외 1개` | `resync_check_diff`(…·차이) |
| 차이(2.4%, 다른 행 없음) | 1줄 같음 / 2줄 `화면에 안 담긴 종목이 있을 수 있어요` | `resync_check_diff` |
| 총액 없음·숨김 조건 | 줄 없음(DOM 0) | `resync_check_none`(…·총액 없음). 숨김 사유 구분 없이 1개 |
- 금지 어휘: 투자 조언, `정확해요`·`보장`, `서버로 안 보내요`·`아무것도 안 나가요`(스크린샷은 서버에서 분석한다), 금액 숫자.
- GA는 적용 1회당 위 3개 중 1개만 보낸다. 금액·%·증권사명·종목명은 보내지 않는다. 체험 중에는 `ga.ts:401`에서 막힌다(현행). 코인 맞추기에서는 보내지 않는다.

**숨김 조건(하나라도 해당하면 줄 없음)**
1. `screenTotal` 없음 또는 0 이하, 또는 통화가 KRW가 아님.
2. 예수금 포함이 모호함: 라벨에 `평가` 가 없거나 `자산`·`예수금`·`예탁`·`추정`·`순` 중 하나라도 있으면 숨긴다(예: `총자산`·`추정자산`). [TR] 라벨 목록은 픽스처 화면에서 확정한다.
3. 인식 성공 장이 2장 이상이거나, 실패·잘림(`truncated`)·한도 장이 1장이라도 있음.
4. 미리보기에서 `확인 필요` 행이 있거나, 화면 행 중 적용하지 않은 행(추가 체크 해제 등)이 있음. 이 행들은 앱 합계에 없어 차이가 거짓으로 생긴다.
5. 대응 앱 종목 중 현재가 0 또는 시세 조회 실패 상태인 종목이 있음. [TR] 5.153 시세 신선도 신호 재사용.
6. 되돌리기를 누른 뒤.

**서버 조건(CEO ③, qa 데이터 안전 점검표)**
1. 요청 본문은 그대로다(이미지·assetType). 앱 합계·보유 목록은 보내지 않는다.
2. 서버는 `screenTotal`을 저장·캐시·로그하지 않는다. `:833` 오류 로그는 `e.message`만 남긴다. qa가 grep으로 확인한다.
3. 응답에서 행과 분리된 필드로 둔다. Gemini 스키마를 객체로 바꾸면 `:820`의 배열 전제와 다른 호출처(종목 등록·온보딩·/ratio)를 하위 호환해야 한다. [TR] 기존 인식 픽스처 회귀 0이 머지 조건이다.
4. 기기에서는 결과 화면 상태로만 쓴다. AssetData·localStorage에 쓰지 않는다(저장하면 스키마 변경이라 high로 재판정).

## 7. 엣지 케이스
- 빈 데이터: 주식 0건이면 맞추기 대화상자가 열리지 않는다(기존 `StockScreenshotImport`). 대조 줄도 없다. 코인 거래가 0건이면 고지는 현행 문구를 쓴다.
- 일부 갱신: 일부 행만 적용하면 숨김 조건 4에 걸린다. 코인 일부만 체크 삭제하면 체크한 코인의 거래만 정리된다.
- 오래된 데이터: 시세 실패·현재가 0이면 숨긴다(5). 상장폐지·평가액 0 코인은 거래를 남긴다(`planDeleteCryptos` 현행).
- 첫 사용자: 맞추기 1회차도 같은 규칙. 체험(`?trial=1`)에서는 스크린샷 인식 가능 여부에 따라 대조 줄이 보이지 않을 수 있다. 새 소식 노출과 함께 상태표에 적는다(C126). [TR]
- 맞춘 뒤 닫고 다시 열면 대조 줄은 없다(메모리만).

## 8. 완료 기준(qa)
1. vitest: 코인 맞추기 체크 삭제 결과의 `cryptoTransactions`가 같은 입력의 `planDeleteCryptos` 결과와 같다. 고아 코인 거래 0. 평가액 0 코인과 지난달 연결 짝 거래는 남는다.
2. vitest: 코인 맞추기 → 되돌리기 후 `crypto`·`cryptoTransactions`가 맞추기 직전과 같다.
3. 코인 미리보기에서 평가액이 남은 코인을 체크하면 `지우는 코인은 거래 기록도 함께 정리돼요`가 보이고, 체크를 풀면 현행 문구로 돌아간다.
4. 주식 1장·총액 라벨 `총 평가금액`·차이 0.4% 픽스처 → `증권사 화면 합계와 맞아요`. 2.4%·다른 행 2개 → 두 줄 문장이 §5 표와 글자 단위로 같다. 총액 없음 → `resync-result` 안에 대조 줄 DOM 0.
5. 숨김 조건 1~6 각각을 픽스처로 넣으면 대조 줄 DOM 0, GA `resync_check_none` 1회.

7. 서버: 응답 `screenTotal`이 `stocks` 배열 안에 없다. 기존 주식 인식 픽스처 행 결과 diff 0. 종목 등록·온보딩·/ratio 호출 응답 처리가 그대로 동작한다. `route.ts`에서 `screenTotal`을 쓰는 로그·저장 경로 0(grep).
8. 시트 위에서 결과 화면을 닫으면 토스트에 action이 없다. 시트가 없으면 `되돌리기` action이 있고 누르면 되돌아간다. 390·320 둘 다 확인한다.
9. 종목 한 장 링크 문구 `최근 3년 거래 N건`, N = 거래내역 화면 행 수.
10. 환율 기준일 ≠ 오늘 → `M/D 환율이에요…`, 오늘 → 현행 문구, 비어 있음 → `저장된 환율이에요…`.

## 9. 새 소식 판단
- 대조 1줄을 포함해 반영하면 1줄을 등록한다: 제목 `주식을 맞추면 증권사 화면 합계와 맞는지 알려 줘요`. 주식 한정을 제목에 밝힌다(C91). 도착할 화면 1곳이 없으므로 `바로 가기`(featureId)는 두지 않는다(C87). id는 **머지일 기준** `YYYYMMDD-NN`이다. 같은 날 다른 릴리스와 겹치면 나중에 머지하는 쪽이 번호를 올리고 테스트 기대값을 고친다(DECISIONS 11-26 선례). 진입점 개수 = 시트 `새` 개수 대조(C84·C127).
- (a)·(c)는 수정·정돈이라 별도 항목을 만들지 않는다(C86). 대조 줄이 5.162로 빠지면 `새 소식: 해당 없음(정확성 수정·문구 정돈)`.
- 체험·preview 데모 행(C126): 데모에 주식 맞추기 인식 결과가 없으면 기능이 조작 없이 보이지 않는다. 이 경우 체험 새 소식 목록에서 이 항목을 숨긴다. [TR] 체험 인식 차단 여부.
