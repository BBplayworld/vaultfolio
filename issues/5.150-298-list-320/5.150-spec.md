근거: CEO 판정 `issues/_discovery/2026-11-26-next/ceo.md`(A·B 채택, C 축소, D 보류, E·F 기각), planner.md §2. 코드 기준은 `/home/user/vf-5149`(main과 같음)이며, 읽기만 했다. risk:low이고 CEO 승인 대상이다. SHOT 토큰이나 인증카드 이미지에 diff가 생기면 medium으로 다시 판정한다.

## 1. 문제
- 320 폭 상세·주식 행에서 이름 칸이 66px까지 줄어 `SK하이닉스`가 `SK하이닉`/`스`로 끊긴다. 나머지 탭의 행 이름은 줄바꿈 규칙이 탭마다 다르다. 현금·대출·코인·부동산은 규칙 없이 음절 단위로 끊기고, 실물은 `truncate` 1줄이다.
- 320 주식 거래 행에서는 '기록만' 배지가 줄을 바꿔 그 행만 22px 높아진다(104 vs 82px). 거래 4종은 음수 부호(주식만 ASCII `-`)와 삭제 버튼의 접근 이름(주식만 `aria-label`)이 서로 다르다.
- 자주 쓰는 화면에서 320 폭의 숫자 잘림·어절 끊김·겹침을 팀이 전수 점검한 적이 없다(LEARNINGS 11-22, C145).

## 2. 목표 행동
사용자가 320~430 휴대폰에서 상세 목록과 거래내역을 훑을 때, 이름을 끝까지 읽기 위해 행을 열거나 화면을 가로로 돌리지 않고 한 번에 종목을 알아본다.

## 3. 범위
- 포함: A 행 이름 줄바꿈 통일, B 거래 4종 행 정돈, C 5곳 320 감사 후 미달분 수정(상한 있음).
- 하지 않을 것: D(스크린샷 실패 GA 분리, CEO 보류), 홈 Hero·7일·원인 열기, 카테고리 줄 2px, 연 결산 `꺼낸 돈 −N`, 새 입구·지표·문구·배치 방향 변경, 화면 title 변경, 컴포넌트 구조 변경.
- **데이터 변경은 0이다.** 저장 키·스키마·마이그레이션·동기화·서버 전송·공유 토큰을 바꾸지 않는다. 바뀌는 것은 표시 클래스, 부호 글자, 접근 이름뿐이다.

### C. 320 감사 → 미달분만 수정 (상한 고정)
- **대상 5곳 (고정, 추가 금지)**: ① 상세 허브 ② 상세·주식(목록·종목 페이지) ③ 성과·자산 변화(주·월·연, 원인 행) ④ 월 결산 ⑤ 상세·대출(목록·거래내역)
- **판정 5가지만**: 가로 넘침, 숫자 잘림, 말줄임이 아닌 잘림, 어절 중간 끊김(C25·C114), 요소 겹침. 정보 구조·문구·배치 방향은 판정하지 않는다.
- **방법**: A·B를 구현한 뒤 로컬 프로덕션 빌드에서 320·라이트로 1회 감사한다(C146). 감사표는 5곳 × 5판정이다.
- **수정 한도**: 클래스 수준(폭·줄바꿈·줄 배치)만 허용한다. **미달 수정은 최대 4곳.** 4곳을 넘거나 컴포넌트 구조를 바꿔야 하는 항목은 5.150에서 빼고 다음 후보로 넘긴다(감사표에 '이월'로 적는다).
- 고친 화면만 C104 4폭(360·390·430·1280)으로 확인하고, preview는 화면마다 1장만 본다. 미달이 0이면 감사표만 남기고 코드는 바꾸지 않는다.

## 5. 사용자 흐름
1. 상세 → 탭(주식·현금·코인·대출·부동산·실물)을 고르면 행 이름이 어절 단위로 최대 2줄까지 보인다.
2. 주식 탭에서 종목 행 → 종목 페이지 → 거래내역으로 가면, 기록만 행과 반영 행이 같은 높이로 줄지어 보인다.
3. 현금·코인·대출 거래내역에서는 음수 부호와 삭제 버튼 읽기가 4종 모두 같다.

## 6. 엣지 케이스
- 공백 없는 긴 이름(ETF·영문 코인명): 칸 경계에서 글자 단위로 줄을 바꾸고 2줄에서 말줄임한다. 가로 넘침은 0이다.
- 거래정지·상장폐지 배지가 붙은 주식: 기존 모바일 `line-clamp-1`을 유지한다.
- 증권사 미지정(`미지정`) 또는 증권사 1개(증권사 줄 숨김): B 규칙의 '증권사 줄 없음' 경우를 따른다.
- 빈 목록·첫 사용자: 빈 상태는 바뀌지 않는다. 행이 없으면 A·B 변경이 드러나지 않는다.
- 인증카드(screenshotMode): SHOT 토큰을 쓰고 기존 분기(`screenshotMode ? "" : ...`)도 그대로이므로 이미지가 바뀌지 않는다.
- 오래된 데이터·일부 갱신: 표시 클래스만 바뀌고 데이터 경로는 그대로라 영향이 없다.
