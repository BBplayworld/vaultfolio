## qa D1 수정 (평가금액 오독 방어)
- 원인: C 분기가 swap 후 수익률 허용폭 검사(`swapped<=3%p`) 없이 평가금액÷수량 0.2% 일치만으로 swap. 평가금액 칸에 매입금액이 들어오면 바른 읽기를 뒤집음(130/100/+30, 80/100/-20).
- 수정: C 분기에 `swapped<=TOLERANCE_PP` 추가. C·B의 E1 swap 모두 `swapMatchesProfitAmount`(평가손익이 있으면 swap 후 기대 손익=평가금액-현재가×수량과 부호·3% 일치)를 추가로 통과해야 swap. 평가손익 없으면 검증 불가라 통과.
- 테스트: qa 반례 2건, 평가금액=매입금액 오독 퍼징 2000회(평가손익 포함, swap 0건), 부호 누락+오독 평가금액 keep.
- 추가 수정: 소수익률(C) 분기는 평가손익이 있고 `swapMatchesProfitAmount` 통과 시에만 swap, 평가손익이 없으면 keep(4.99 동작). 차이는 최대 약 1.5%라 새 오류를 만들지 않는 쪽을 택함. 퍼징 '평가손익 없음+오독 평가금액 → swap 0건' 고정.
- 한계: 평가손익이 없으면 소수익률 뒤바뀜(C)은 교정하지 않음(4.99와 동일).
