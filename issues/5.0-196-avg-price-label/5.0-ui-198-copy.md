# 5.0 #198 ③ '맞추기에 포함' 문구 (ui-designer)

문제: '포함'이 무엇에 포함인지 불명. 확인 필요 항목은 기본 해제라 "왜 꺼져 있나"가 안 읽힘.

## 대안
- A. 라벨 "이번 맞추기에 포함" 단독: 짧지만 '포함'이 그대로라 의미 개선 약함. 하단 문구와 어휘 불일치.
- B. 라벨 "이 항목도 맞추기" + muted 캡션 "체크하지 않으면 그대로 둬요": 동작(체크=맞춤, 미체크=그대로)을 동사로 직결, 하단 "그대로 둬요"와 같은 어휘.

## 확정: B
- 라벨: `이 항목도 맞추기` (기존 text-sm, 체크박스 우측)
- 보조 1줄: `체크하지 않으면 그대로 둬요` (기존 `text-sm text-muted-foreground text-pretty break-keep`, 라벨 아래 block, 체크박스 아래 정렬 gap-2 들여쓰기 없이 라벨 열에 맞춤)
- 하단 문구는 유지: `확인 필요 N개는 맞추지 않고 그대로 둬요` (어휘 "맞추기/그대로 둬요" 일치)
- 구조: label 안에 span 2단(라벨+캡션), `items-start`, 체크박스 `mt-0.5`.
- 320px(C25): 라벨 9자, 캡션 14자 → 한 줄 또는 break-keep 2줄, 잘림 없음.
- 히트: label `min-h-10` + 체크박스 `after:-inset-3` 유지 (40px 이상).
- 투자 조언 아님, 존댓말 '~요' 체로 앱 톤 일치.
- qa: 확인 필요 항목에서 라벨·캡션 노출, 티커/수량 입력 시 자동 체크되어도 라벨 동일, 320 줄바꿈·히트 40px.

## 확인 필요 사유 문구
원칙: 사유 = "무슨 일이 있었나"(보조 muted 1줄) + 입력칸 = "무엇을 하면 되나". 앱 표현 '읽지 못했어요'는 인식 실패 맥락이 명확해 유지하되 '왜 필요한지/어디에 쓰는지'를 덧붙인다. 모든 사유·캡션은 기존 `text-sm text-muted-foreground text-pretty break-keep`, 투자 조언 아님, 존댓말 '~요'. 320px(C25)는 한 줄 17자 내외 + break-keep 2줄 허용, 잘림 없음.

| 사유 코드 | 현행 | 확정 문구 | 보조 캡션 |
|---|---|---|---|
| qtyDecrease | 수량이 줄었어요 | 기존보다 수량이 줄었어요 (표에 "(기존 N)" 이미 병기) | 없음 |
| quantityMissing | 수량을 읽지 못했어요 | 화면에서 수량이 안 보였어요 | 입력칸 위 라벨 "수량을 직접 알려 주세요" |
| quantityMissing 입력 placeholder | 수량 입력 | 수량 | - |
| 두 장 수량 불일치(cand) | 두 장에서 A·B주로 읽혔어요 | 두 장에서 수량이 달라요: A·B주 (기존 어조 유지, 값만 뒤로) | 입력 placeholder는 현행(item.quantity) 유지, 라벨 "맞는 수량을 입력해 주세요" |
| tickerMissing | 티커를 읽지 못했어요 | 종목 코드(티커)가 안 보였어요 | 입력칸 위 라벨 "티커를 직접 알려 주세요" |
| tickerMissing placeholder | 티커 입력 | 예: AAPL (티커) | - |
| ambiguous 제목 | 어느 줄인가요 | 같은 종목이 여러 곳에 있어요. 어느 항목을 맞출까요? | 캡션 "계좌가 달라 하나로 정할 수 없었어요" |
| ambiguous placeholder | 줄 선택 | 항목 선택 | - |
| brokerUnconfirmed(상단 안내) | 증권사를 못 정한 장이 있어서 삭제는 모두 꺼 뒀어요 | 현행 유지(이미 평이) | - |
| 체크 라벨(확정) | 이 항목도 맞추기 | 유지 | 체크하지 않으면 그대로 둬요 |

- '줄'은 모든 곳에서 '항목'으로 통일(사용자는 '줄'을 모름). 증권사 용어는 T.broker 그대로.
- 라벨 길이: 가장 긴 'ambiguous 제목' 29자 → 320px에서 break-keep 2줄(수용), 보조 캡션 17자 1~2줄.
- 사유 3개 이상 겹쳐도 사유 줄 → 캡션 → 입력 순서 고정.

### 줄 선택 드롭다운 항목 표시
같은 종목·같은 증권사의 DC·IRP·연금저축 구분이 목적이므로 이름 반복을 빼고 구분 정보를 앞에 둔다. 2줄 구성(SelectItem 안 flex-col):
- 1줄(text-sm): `{증권사} · {계좌명/메모}` (계좌명·메모가 없으면 증권사만, 증권사 미지정이면 `{T.broker} 미지정`)
- 2줄(text-sm muted, tabular-nums): `수량 {N}주 · 평가 {금액}`은 금액 노출이 불필요하면 `수량 {N}주`만. 같은 값이면 `매수일 {날짜}`를 추가해 구분.
- 종목명은 위 행 제목에 이미 있으므로 제외. 동일 표시가 2개 이상이면 `(1)`·`(2)` 접미 금지, 대신 메모/계좌 유형(DC·IRP·연금저축)이 없으면 수량·매수일로 차별.
- 선택 후 트리거에는 1줄 요약만 표시(`키움 · IRP`), 항목 높이 min-h-10(40px) 이상.
- 계좌 유형 필드가 데이터에 있는지는 developer 확인 필요(없으면 메모, 그래도 없으면 수량·매수일).

### qa(C25·체크리스트)
- 각 사유 화면에서 문구가 위 표와 일치, '줄' 단어 0건, 320px 잘림·가로 스크롤 없음
- ambiguous 후보 3건(같은 증권사)에서 항목이 서로 구분되어 보임
- 선택 시 자동 체크(onInclude) 동작 유지, 입력칸 라벨-입력 연결(aria-label 동일 문구)
