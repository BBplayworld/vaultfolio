# #222 spec — 종가 기준 설정 쉬운 말로·한 모양으로 (XS)

근거: `5.xxx-direction.md`(경험 절), `5.xxx-challenge.md`(통과, 조건 A·B·C 반영). 기준 코드 origin/main bee7856.

## 1. 문제
국내·해외 종가를 맞추는 설정 하나가 두 곳(더보기 `표시`의 2칸 선택, 성과 `기준 종가 비교` 안의 Switch)에 서로 다른 모양으로 있다. 이름 `동일 영업일 / KST 접속일`은 읽어도 뜻을 알기 어렵다. 성과에서 바꾸면 다른 화면 값도 바뀌는데 그 사실이 보이지 않는다.

## 2. 목표 행동
사용자는 두 곳에서 같은 이름의 2칸 선택을 보고 한 칸을 누른다. 설명(i)을 열면 이 값이 어디에 함께 적용되는지 읽을 수 있다.

## 3. 확정 문구 (공용 상수 1개, 두 곳 동일)
| 키 | 문구 |
|---|---|
| 이름·aria-label | `국내·해외 날짜 맞춤` |
| sameBusinessDay | `같은 거래일` |
| kstAccessDay | `시장별 최신` |
| 설명 요약 | 국내·해외 종가를 어느 날짜로 묶어 더할지 정해요. |
| 설명 1 | **같은 거래일** — 국내·해외 모두 같은 날짜의 종가로 더해요. 해외 종가는 다음 날 새벽에 정해져요. |
| 설명 2 | **시장별 최신** — 지금(한국 시간) 기준으로 각 시장의 마지막 종가를 더해요. 두 시장 날짜가 다를 수 있어요. |
| 설명 3 (조건 A) | 기간 수익·성적표·시장 비교(홈·상세 포함)에 함께 적용돼요. |

- 설명 3은 direction 표의 문장을 대체한다. 이 문장이 다루는 범위는 profit-chart, asset-report-view, use-market-compare, `useMarketEntryValue`를 거치는 화면(홈 시장 줄 `dashboard.tsx`·자산 변화 타일·성과 허브 행 `hub-change-rows.tsx`·상세 주식 시장 타일 `stock-tools.tsx`), 공유 링크다.
- 성과 쪽 일별 환율 문장(`period === "daily"`)은 성과에서만 기존처럼 덧붙인다.
- ui가 폭 때문에 선택지를 줄일 때는 의미를 유지해야 하고(예: `같은 날`/`각자 최신`) planner의 재확인을 받는다.
- **공용 상수 위치 후보**: 1순위는 `src/lib/finance/profit-utils.ts`다. `ProfitBasis`·`DEFAULT_PROFIT_BASIS`가 있는 곳이라 `PROFIT_BASIS_COPY`(name·summary·options·notes)를 이 옆에 둔다. 2순위는 `src/config/`의 새 파일이다(`security-copy.ts`처럼 문구 전용). 고를 때는 dev-rules 재사용 지도를 먼저 검색한다. 설명 본문(JSX)은 상수 배열을 map으로 그린다. 공용 컴포넌트를 새로 만들지는 않는다.

## 4. 두 화면 컨트롤 형태
- 더보기(`settings-page.tsx` 230-252): 구조는 그대로 두고 상수 문구만 바꾼다. InlineSelector `size="sm"`과 hydrate 가드는 유지한다.
- 성과(`profit-chart.tsx` 593-606): `글자 / Switch / 글자`를 InlineSelector 2칸 1개로 바꾼다. 옵션 배열은 더보기와 같은 상수를 쓴다. (i)는 선택기 왼쪽에 두고 `w-fit ml-auto` 배치를 유지한다. 렌더 조건은 `profitBasisHydrated`다. Switch import가 더 쓰이지 않으면 제거한다.

## 5. 사용자 흐름
1. 더보기 → 표시 → `국내·해외 날짜 맞춤` (i) → 한 칸 선택 → 저장값이 바뀐다.
2. 성과 → 기간 수익 → `기준 종가 비교` 펼침(기본 접힘) → 한 칸 선택 → 아래 국내·해외 날짜 행과 합계가 갱신된다.
3. 어느 쪽에서 바꿔도 다른 쪽 선택기와 성적표·시장 비교·홈·상세 시장 줄이 같은 기준으로 보인다.

## 6. GA (조건 B)
- `featureTitleOf`는 `params.source`를 title에 싣지 않는다(ga.ts 246~). 그래서 category 2개를 허용 목록에 추가해 출처를 title로 나눈다. 새 이벤트명은 0이다.
  - `profit_basis_settings` → `종가 기준·변경·설정`
  - `profit_basis_chart` → `종가 기준·변경·성과`
- 값이 실제로 바뀐 경우에만 `track("feature_use", …)`를 부른다(같은 칸 재선택은 0건). 값은 전송하지 않는다. 체험 모드는 기존 가드대로 no-op이다.
- ga.test에 title 2건 케이스를 추가한다. 최종 형태는 tech-review가 확정한다.

## 7. 엣지
- 국내만·해외만 보유: 컨트롤은 그대로 보인다. 국내만 보유해도 `같은 거래일`은 해외 영업일로 날짜를 맞추기 때문이다. 날짜 행은 기존처럼 보유한 시장만 나온다.
- 주식 0개: 성과 표는 기존 조건대로 나오지 않는다. 더보기에서는 보이고 바꿀 수 있다.
- hydrate 전: 두 곳 모두 선택기를 그리지 않는다(기본값이 깜빡이지 않게).
- 구버전 기기·공유 링크 값: 저장값이 같으므로 새 이름으로 그대로 보인다.
- 320 폭: 성과 펼침 안의 (i)와 2칸이 한 줄에 들어가야 한다. 안 들어가면 선택지 글자를 줄인다.

## 8. 완료 기준 (AC)
- AC-1 더보기 표시 섹션의 이름이 `국내·해외 날짜 맞춤`이고 선택지가 `같은 거래일`/`시장별 최신`이다.
- AC-2 성과 `기준 종가 비교`를 펼치면 Switch가 없고 AC-1과 같은 글자의 2칸 선택이 있다.
- AC-3 두 곳의 (i)를 열면 요약·설명 1~3이 글자 하나까지 같다(성과 일별 환율 문장만 예외).
- AC-4 성과에서 `시장별 최신`을 누르면 더보기 선택기도 `시장별 최신`이 선택돼 있다. 성적표·시장 비교·홈 시장 줄·상세 시장 타일도 같은 기준으로 날짜·값이 다시 계산된다.
- AC-5 새로고침 뒤에도 선택이 유지된다. 저장 키 `secretasset_profit_basis`의 값은 `sameBusinessDay|kstAccessDay` 그대로다.
- AC-6 화면 문자열에 `동일 영업일`·`KST 접속일`·`종가 기준 옵션`이 0건이다(주석 제외 grep).
- AC-7 360·390·430·1280·320 폭에서 두 곳 선택지가 줄바꿈·말줄임 없이 한 줄이고, 설명에 어절 중간 줄바꿈이 없다. 칸 히트영역은 40px 이상이다.
- AC-8 값을 바꾼 경우에만 GA title `종가 기준·변경·설정` 또는 `·성과`가 1건 나간다. 같은 칸을 다시 누르면 0건이다.

## 9. 하지 않는 것
성과 컨트롤 삭제·이동, `기준 종가 비교` 제목·날짜 표·`(KST)` 머리·마감 기준 줄 변경, 보유 구성에 따른 숨김, 토스트·확인창, 저장 키·값·기본값·계산·공유 토큰 변경, 홈·결산·첫 화면 코드 변경, 신규 컴포넌트.
