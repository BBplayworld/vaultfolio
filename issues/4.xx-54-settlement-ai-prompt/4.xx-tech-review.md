## 2. 데이터 영향 범위: 없음
- 읽기만 한다: 화면이 이미 계산한 `computed.value`. 저장·동기화·스냅샷·거래·공유·백업·성적표 계산은 건드리지 않는다. 스키마·키가 바뀌지 않아 마이그레이션이 필요 없고, 구버전 기기와 섞이거나 롤백해도 손실이 없다.
- **서버 전송 0**: 프롬프트는 `navigator.clipboard.writeText`로만 나간다(fetch 없음). GA에는 enum 4개만 추가되고 금액·달·원인은 보내지 않는다(`sanitizeParams`가 허용값 외 값을 버린다). 외부 AI에 붙여넣는 것은 사용자의 직접 행동이고, 다이얼로그 고지로 알린다.
- 성적표 source `report` 추가의 영향: 지금까지 성적표 복사 이벤트가 0건이었으므로 끊기는 시계열이 없다. 허브 카드 `card`("결산 카드")와 섞이지 않는다. `report`는 settlement_view 등 다른 이벤트에서 쓰이지 않으니 판독 혼동도 없다.

## 3. 위험 등급 초안: **low**
UI 버튼 1개·순수 함수 1개·선택 prop 1개·GA enum 4개다. 저장소·API·동기화·새 이벤트명이 없다. 위험은 프롬프트 문구(투자 조언 금지)이고 단위 테스트로 막는다.

## 5. spec 수정 요청
- **수정 요청: 완료 기준 12(공유 캡처 숨김)** — origin/main에는 `[data-screenshot-hide]`를 읽는 캡처 코드가 없다. 공유 PNG(`share-menu.tsx` `toPng`)는 화면 밖 전용 카드만 찍고, 결산 화면을 캡처하는 기능은 없다(`stock-insight-strip.tsx:22` 주석 "현 구현에선 무영향"). 그래서 "공유 이미지에 버튼 미포함"은 검증할 대상이 없다. 기준을 "버튼 래퍼에 `data-screenshot-hide` 속성이 있다(기존 결산 화면 관례와 일치)"는 DOM 검사로 바꿔 달라. 3장 범위의 "공유 캡처 숨김"도 "관례 마커 부착"으로 표현을 고쳐야 한다.
- **수정 요청: 5장 ③ 표기 함수** — 화면 Hero·CauseBlock은 `formatShortCurrency`가 아니라 `formatPriceByMode`를 쓴다(현재 모드에서는 결과가 같지만, 모드 상수가 바뀌면 9번 "Hero와 같다"가 깨진다). 프롬프트도 `formatPriceByMode`로 맞춘다. 증감률은 화면과 같은 `toFixed(1)` + 부호.
- **수정 요청: 완료 기준 5(onCopy)** — node 환경이라 다이얼로그 클릭 테스트를 할 수 없다. 기준을 "`copyPrompt` 헬퍼 단위 테스트(성공 1회/실패 0회/미지정 무해) + Playwright 10번(실제 클릭 시 이벤트 1건, 실패 시 0건)"으로 나눠 달라.
- 참고(수정 아님): 원인 키에는 `loan`("대출")도 있다(`splitLoanCause`). 3번 테스트 입력에 대출 항목 1건을 포함한다.
