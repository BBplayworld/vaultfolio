# 4.xx 결산 AI 질문 프롬프트 — spec (#54)

기준: 4.xx-direction.md(합의 완료), 4.xx-challenge.md. 시각 수치는 ui.md 몫. 개발은 v4.36(#51) 머지 후 4.37.

## 1. 문제
결산 화면은 숫자와 원인을 보여주고 끝난다. "그래서 이번 달 왜 이랬나"를 풀어 줄 다음 행동이 없다. AI 프롬프트(강점 3)는 성적표 맨 아래뿐이고 복사 계측이 0이다(`ga.ts` category 허용값에 ai 없음, `PromptPreviewDialog`·성적표·X-Ray 호출부 `track(` 0건).

## 2. 목표 행동
결산 값이 있는 월 결산에서 "AI에게 이번 달 물어보기" → 미리보기 → 복사 → 외부 AI에 붙여넣기. 주 지표: 결산 창 `feature_use` ai_prompt source=settlement 기기 ÷ `settlement_view` 기기 ≥ 15%(가설, 기준선 확보가 첫 소득). 창당 30기기 미만이면 판정 보류.

## 3. 범위
- 포함: 결산 화면 버튼 1, 프롬프트 템플릿 1종(`lib/ai-prompts.ts`에 함수 추가), `PromptPreviewDialog` 재사용(탭 1개), 복사 계측, 공유 캡처 숨김.
- 제외: 연 탭 프롬프트, 성적표 프롬프트 수정·이동, 금액 가리기 옵션, 홈 팁·공지·새 진입점·푸시, 서버 AI 호출·외부 전송, 새 저장 키·스키마, 새 GA 이벤트명.

## 4. 버튼 위치·노출 (`settlement-view.tsx`)
- `CauseBlock` 바로 아래, `PrepBlock` 위. 담백한 보조 버튼 "AI에게 이번 달 물어보기"(최종 시각·문구는 ui.md). 기존 `!firstMonth && <CauseBlock>`와 같은 렌더 분기 안.
- 노출 조건 = `computed.ok` && `!firstMonth`(비교 가능한 결산 값이 있을 때). 월 기록 0건·자산 0건(`settlement-empty`)·계산 오류(`settlement-error`)·첫 달(`settlement-first-month`)에는 버튼 없음. 진행 중(`in_progress`)·긴 간격(`longGap`)에서는 노출하되 프롬프트에 "진행 중 구간"·"N일 구간"이 그대로 담긴다.
- 월 화살표로 달을 바꾸면 프롬프트는 그 달 값으로 다시 생성된다(`getPrompt`는 다이얼로그가 열려 있을 때만 호출).
- `data-screenshot-hide` 래퍼로 감싸 공유 캡처에서 숨긴다. testid `settlement-ai-button`.

## 5. 프롬프트 구성 (화면 값만)
- 입력은 `computed.value`(window·prevValue·currValue·delta·pct·mapped·estimatedLabel)와 `settlementName`·`settlementRangeLabel` — 새 계산·화면에 없는 숫자 금지.
- 본문 순서: ① 가드레일(기존 `GUARDRAIL` 재사용: 종목 추천·목표가·타이밍·단정 예측 금지) ② 달 이름과 기간 라벨 ③ 시작·끝 순자산, 증감, 증감률(화면과 같은 표기 `formatShortCurrency`) ④ 원인 항목: `SETTLEMENT_CAUSE_LABEL` 라벨 그대로 + 금액 + 예측 항목은 "예측"(`estimatedLabel`) 표시 ⑤ 설명 한 줄: "'기록 안 된 변화'는 새로 등록한 자산·직접 고친 잔액처럼 시세·환율·입출금·대출로 설명되지 않는 금액이며, 실제 원인을 알 수 없으니 단정하지 마세요" ⑥ 요청: "무엇이 이번 달 순자산을 바꿨는지 쉬운 말로 해석해 주세요", "다음 달 기록을 더 정확하게 하려면 무엇을 확인하면 좋은지 질문 3개 이내로 알려주세요".
- 금지 문구(프롬프트 본문·요청에 포함 금지, 단위 테스트로 검사): "매수", "매도"(가드레일의 부정 지시문에만 허용), "추천해", "사야", "팔아야", "목표가", "수익률 예측", "리밸런싱", "비중을 늘", "비중을 줄". 화면 값 외 숫자를 새로 생성하는 문장 없음. 원인 라벨에 "부채 상환"·"매수"를 만들지 않는다(LEARNINGS 2026-10: 앱 내 이동은 순자산을 바꾸지 않음; 라벨은 기존 상수 그대로).
- 자산 개별 종목명·수량·평단 같은 상세는 넣지 않는다(결산 화면에 없는 값).

## 6. 다이얼로그
- `PromptPreviewDialog` 재사용, tabs 1개(탭 영역 자동 숨김). 제목 "이번 달 결산 AI 질문", 설명에 "프롬프트에 내 금액이 포함돼요. 붙여넣기 전에 확인하세요." 고지 포함(문구 최종은 ui.md). `copySuccessMessage="결산 프롬프트가 복사되었습니다."`.
- 앱이 서버로 보내는 데이터 없음(클립보드 복사만).

## 7. 계측 (`ga.ts`)
- `PARAM_VALUES.category`에 `"ai_prompt"`, `source`에 `"settlement"` 추가, `PARAM_LABELS`에 라벨 추가(`ai_prompt: "AI 프롬프트"`, `settlement: "결산 화면"`; 라벨 누락은 컴파일 오류). method는 기존 `copy`(라벨 "이미지 복사"로 매핑되어 의미 불일치 → 새 method 값 `prompt_copy`(라벨 "프롬프트 복사") 추가).
- 전송: `track("feature_use", { category: "ai_prompt", method: "prompt_copy", source: "settlement" })`. 새 이벤트명 0.
- `PromptPreviewDialog`에 선택 prop `onCopy?: () => void` 추가, `handleCopy`에서 클립보드 쓰기 성공 후에만 호출. 미지정 호출부(X-Ray 등)는 동작 불변.
- 성적표 기준선 포함: `asset-report-view.tsx` 호출부에 `onCopy`로 같은 이벤트 source=`card`. 허브 카드 source `card`("결산 카드")와 라벨 충돌하므로 성적표용은 새 source 값 `report`(라벨 "자산 성적표")로 한다. X-Ray 호출부는 범위 밖.
- 복사 실패(토스트 오류) 시 이벤트 없음. 한 다이얼로그 세션 내 복사 버튼 연타는 클릭마다 전송(기기 수 지표라 무해).

## 8. 정보 구조 — 지표 단위 전수 대조표
| 지표/항목 | 정본 위치 | 이 기능 처리 |
|---|---|---|
| 시작·끝 순자산, 증감·% | 결산 Hero | 프롬프트에 화면과 같은 값 복사만(새 계산 없음) |
| 원인 항목·금액·예측 표시 | `CauseBlock` | 라벨·금액 그대로 프롬프트에 포함 |
| 기록 안 된 변화 설명 | `CAUSE_HINT.unrecorded` | 같은 뜻으로 프롬프트 설명 1줄 |
| 성적표 AI 프롬프트 | 성적표 맨 아래 | 그대로(계측 훅만 추가) |
| 연 탭 원인 | 기간별 변화 연 탭 | 프롬프트 없음 |

## 9. 엣지 케이스
- 클립보드 권한 거부: 기존 "복사에 실패했습니다." 토스트, 이벤트 없음.
- 일부 이전 값("일부 이전 값" 배지)·예측 항목: 프롬프트에 "예측" 표시를 그대로 둔다.
- 원인 항목 0건("뚜렷한 변화 원인이 없어요"): 버튼은 노출, 프롬프트 원인 절에 "뚜렷한 원인 항목이 없음" 한 줄.
- 오래된 데이터(`longGap`): "N일 구간" 문구 포함.
- 첫 사용자·첫 달: 버튼 없음.

## 10. 데이터 영향 없음 근거
읽기만: `computed.value`는 기존 로컬 계산 결과. 저장 키·스키마·동기화·서버 전송 변경 없음. GA 파라미터는 enum 값만 추가(금액·자산 데이터 미전송). 마이그레이션 불필요, 위험 low.

## 교차 검토 (business-pm)

**승인**
- 계측 값 변경(method `prompt_copy`, source `settlement`·`report`)에 동의한다. 기존 `copy`("이미지 복사")·`card`("결산 카드") 라벨 혼동을 피해 GA4 판독이 명확해진다. direction 합의의 "성적표 source=card"는 이 spec의 `report`로 대체되며, business.md의 지표 정의·GA 레시피를 같은 값으로 고쳤다.
- 지표 측정: 주 지표(ai_prompt/prompt_copy/settlement 기기 ÷ `settlement_view` 기기)가 완료 기준 10으로 검증된다. 복사 성공 시에만 전송이라 분자가 과대계상되지 않는다.
- 문구·원칙: 가드레일 재사용, 추천 문구 금지 테스트(기준 2), 금액 고지 1줄(기준 8), 서버 미전송 확인(기준 14) 모두 원칙에 부합한다.
- 참고(수정 요청 아님): 새 파라미터 값은 GA4 맞춤 측정기준 등록 여부에 따라 보고서에 보일 수 있어, 출시 직후 등록 확인을 판독 전 체크로 둔다(business.md 2장 3항).
