## 2. 홈 헤더 결함 상세 (S1·S4·S5)
- **Δ가 0이면 결함이 안 보인다**: preview에서 S1·S4·S5 순수 이동만 있으면 헤더는 "전일 대비 변동 없음"(`negligible`, 만원 미만)이고 원인 목록은 숨김(스크린샷 `cross-452-header-S1-m/d.png`, S4, S5).
- **다른 변동이 함께 있으면(주식 시세 +5% 가정) 두 다리가 그대로 노출**(실제 DOM 텍스트, `...-S1b/S4b/S5b-m/d.png`):
  - S1b: `주식 시세 상승 +105만원 / 주식 매수 11/9 +100만원 / 현금 정리 −100만원`
  - S4b: `주식 시세 상승 +85만원 / 주식 매도 11/9 −300만원 / 신규 현금 +300만원`
  - S5b: `주식 시세 상승 +75만원 / 주식 매도 11/9 −500만원 / 대출 상환 +500만원` (LEARNINGS "원인에 상환 금지" 형태)
- 합은 Δ와 일치(항등식 유지) → **숫자 오류 아님, 서술 오류**. 사용자 영향: 시세가 오른 날 매수·매도·상환을 하면 큰 ± 쌍이 보여 "무엇이 원인인지" 혼란. 기존 사용자 영향 있음(4.52 무관, 이전 버전부터). 데이터 손실 0, 수정 필요 시 홈 헤더 한정(`getAttributionItems` 표시 단계에서 내부 이동 쌍 상쇄).
- 맞는 점: 헤더 원인 문장 `새로 추가한 현금으로 +300만`(S4)은 `formatAttributionSentence`(공유 이미지·스크린샷 경로) 쪽 라벨이며 화면에는 `신규 현금`으로 표기됨.

## 3. S3 재현 (4.52 preview 757c9b0, demo, 375px)
1. `trigger-resync-balance`(cash) 열기 → 머리말 "바뀐 잔액만 입력하세요. 입출금 기록은 생기지 않아요."(스크린샷 `cross-452-s3-1-resync.png`) → 생활비 통장 3,000,000 → 2,000,000 저장.
2. 입출금 기록(생활비 통장, 출금 1,000,000, 기본 '현재 잔액에 즉시 반영' ✓): 폼에 경고 없이 **"반영 후 예상 잔액 2,000,000원 → 1,000,000원"**(`cross-452-s3-5-cashtx-withdraw.png`) → 저장 후 localStorage `생활비 통장 balance = 1,000,000`(은행 실제 200만).
3. **확정**: 같은 100만이 두 번 빠짐. 현금·대출 기록 입력에 `validateReflection`류 가드 없음. 반복 재현 2회 중 1회는 타이밍으로 출금 반영이 저장 전에 읽혀 미반영처럼 보였으나(3초 대기 후 재현), 최종 상태는 1,000,000.
- 사용자 영향: 맞추기를 쓴 사용자가 이어서 입출금을 따로 기록하면(머리말이 '기록 안 생김'만 안내해 오해 가능) 잔액·순자산 −100만 과소, 결산 순유입 −100만. 값 오류 = **데이터 신뢰 결함**. 4.52 신규 경로가 주 유발(4.50 주식은 manual_override 확인으로 차단됨).
