# D5 선정 + 반대 검토 (cto, 2026-11-16)

기준: origin/main 67d311f(v5.120). 대표 지시 "다음 과제로 넘어가자"(11/16)에 따라 D4('11/18 GA 후 재선정')를 앞당긴다. 대표 방침(11-09)에 따라 판독은 '창 피하기'가 아니라 **머지 시각 경계 기록**으로 관리한다. 그래서 D4가 후보를 막은 이유 중 '4.90 홈 판독 창'은 더 이상 막는 이유가 아니다.

## 2. 반대 검토 — 판정: **축소 후 통과**
- **꼭 해야 하나**: 해야 한다. 홈에서 `금융자산`을 고르면 같은 금액이 ①도넛 가운데 ②범례 ③`금융자산 총액` 박스(`dashboard.tsx` 838~846)에 세 번 나온다. 또 `주식 N개 · 암호화폐 M개 · 현금성 K개 보유 중 >` 줄을 누르면 항상 주식 탭으로 간다(851행). 임차보증금만 있는 사용자가 부채 줄을 눌러도 대출 탭으로 간다(898행). 사용자가 누른 것과 도착하는 화면이 다르다.
- **더 작게(v1에서 뺀 것)**:
  - 도넛 위 필터 줄(`InlineSelector`, 475행) 삭제는 **뺀다.** 도넛·범례 누르기는 잘 발견되지 않아 필터에 들어가는 길이 사라질 위험이 있다. 이 컴포넌트는 `NetAssetSummaryBox` 안에 있고, 웰컴(`welcome-guide.tsx`)도 같은 컴포넌트를 쓴다. 손대면 #48·4.86 웰컴 판독까지 건드리게 된다.
  - 모바일에서 필터를 고르면 `최근 7일` 카드가 사라지는 현행 동작은 바꾸지 않는다(C119 표에는 이유를 적는다).
  - GA 신규 이벤트, 문구 추가, 수익 숫자, 도넛 최소 비중(#148)은 다루지 않는다.
- **v1 범위(Dashboard의 TabsContent만)**:
  - 금융·부동산·부채 탭의 `○○ 총액` 박스 3개를 지운다.
  - 이동 줄을 고친다. 금융 줄은 누른 종류의 탭으로 가게 하고, 방식은 ui가 고른다(종류별 줄 또는 구성 막대 조각). 이때 줄 수 순증 ≤ 0이어야 한다. 부채 줄은 임차보증금만 있으면 부동산 탭으로 보낸다.
  - 저장·계산·서버 변경은 0이다. `NetAssetSummaryBox`·`AssetDonutChart` diff도 0이다.
- **중복·충돌**: 4.46(#82)은 도넛 시각만 정리했고 박스·이동은 범위 밖이었다. 반려 방향과 겹치지 않는다. 대표 결정 #148(최소 비중)과 #207(전일대비 영역)은 건드리지 않는다.
- **위험·머지**: **risk:low, 위임 머지(COO 자체 승인).** 첫 화면이지만 다음 이유로 '큰 UI 방향 변경'이 아니다.
  - 중복 박스를 지우고 이동 대상을 바로잡을 뿐이다. 필터·도넛·첫 진입 모습은 그대로다.
  - 대표 반려 영역의 재시도도 아니다(LEARNINGS 11-12).
  - 단 qa에서 다음 중 하나라도 생기면 COO가 '대표 확인 필요'로 다시 판정한다: 필터 줄이나 웰컴 diff 발생, 모바일 첫 화면 높이 변화가 8px를 넘음.
- **익명 기기 기준 확인**: 신규 GA는 넣지 않는다. 성공 판정은 ① preview 상태 표 전 행 캡처 ② 머지 후 2주 동안 대표 지적·피드백 0 ③ 기존 `page_view` 상세 주식·코인·현금 탭 비율의 방향만 참고한다(인과 주장 없음).

## 4. 필수 조건(C119·C120·C103·C116)
1. ui.md에 **상태별 배치 표**를 넣는다. 행은 다음과 같다.
   - 탭: 전체 / 금융(주식만·코인만·현금만·혼합) / 부동산(1종·다종) / 부채(대출만·임차보증금만·둘 다)
   - 탭이 1개뿐이라 필터가 없는 경우, 자산 0, 첫 저장 당일, 주말(일요일), 원인 없는 날, 웰컴 screenshotMode
   - 폭: 모바일 / 1024 이상 2열

   각 칸에는 요소(가운데 금액·범례·구성 막대·이동 줄·7일 카드)의 위치와 '도착 탭'을 적는다. '현행 유지' 칸에는 이유 열을 반드시 둔다.
2. 표의 각 행을 preview 캡처로 최소 1회 확인한다. 데모에 없는 상태는 시드를 주입해 만든다(C120).
3. 360·375·768·1024·1280에서 홈 첫 화면 높이를 main과 표로 대조한다. 9자리 금액도 넣는다(C103·C116).
4. 웰컴·`NetAssetSummaryBox`·`AssetDonutChart`의 diff가 0인지 qa가 확인한다.
