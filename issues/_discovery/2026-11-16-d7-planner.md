# D7 근거 — 기획·경험 관점 (planner-designer, 2026-11-16)

기준: origin/main 5d2e301(v5.123). 읽기만 했다. 출발점은 대표 질문 "도대체 내 돈이 왜 안 불어날까"다.
지금 앱은 이 질문의 재료를 이미 계산한다. 다만 답이 4화면에 흩어져 있고, 답의 절반은 '기록 안 된 변화'로 뭉개진다. 아래 A·B는 한 쌍이고, C는 A의 후속이다.

## 지금 흐름의 공백 (코드 확인)
- 원인 분해는 6행 평면 목록이다: 시세 변동·평가 갱신·환율 효과·순유입·대출·기록 안 된 변화(`src/lib/report/settlement.ts` 249·333행). 사용자가 '내가 넣어서 는 돈'과 '돈이 스스로 불어난 돈'을 직접 더해 봐야 한다.
- 같은 질문의 답이 4곳에 있다: 자산 변화 연 탭 원인(`views/activity/net-asset-chart.tsx` 413행, `change-hero.tsx` computeChainCauses), 월 탭 결산(`settlement-view.tsx`), 성적표 '투입 대비 성과'(`asset-report-view.tsx` 433행~, 매입 후 누적 기준), 시장과 비교(`market-compare-view.tsx`, 주식만). 기간·기준이 서로 달라 한 문장으로 이어지지 않는다.
- 현금·대출 '잔액 맞추기'는 잔액만 바꾸고 입출금 기록을 만들지 않는다(`forms/asset-update/balance-resync-dialog.tsx` 96~114행, saveData 1회). 그래서 월급·저축·지출이 전부 '기록 안 된 변화'로 간다. 화면은 "입출금을 기록하면 더 정확해져요"(`change-hero.tsx` 486행)라고만 하고, 기록하는 길은 상세 › 현금 › 입출금까지 따로 찾아가야 한다.

## 후보 A (1순위): 연 탭을 "넣은 돈 / 불어난 돈 / 빠져나간 돈" 3묶음 답으로
- **누구·문제**: 6개월 이상 기록한 장기 사용자. 순자산은 늘었는데 '내가 모아서 는 건지, 굴려서 는 건지' 모른다.
- **새 흐름**: 성과 › 자산 변화 › 전체 › 연 → Hero 아래 첫 블록이 결론 한 줄("올해 늘어난 금액 중 넣은 돈 N%, 불어난 돈 M%" — 사실 서술만, 평가어 0) → 3묶음 행: 넣은 돈(순유입) / 불어난 돈(시세+평가 갱신+환율) / 빠져나간 돈(대출) + 기록 안 된 변화는 따로 한 줄 → 묶음을 누르면 기존 6행이 펼쳐진다 → '불어난 돈' 아래에 자산 종류별 몫(주식·코인·부동산, 엔진 키 `price:stock`·`price:crypto`가 이미 있음) → 시장과 비교는 기존 진입 줄 재사용.
- **줄이는 것**: 연 탭 6행 평면 목록은 펼침 안으로. 성적표 '투입 대비 성과' 결론 상자와 지표 전수 대조 후 정본 1곳만 남김(spec 필수). 새 메뉴·새 화면 0, 계산 엔진 변경 0(묶음은 표시 매핑).
- **정해야 할 것**: 기록 1년 미만 사용자는 '기록 시작 이후'로 보여줄지(LEARNINGS 11-11: 연 단위 축을 팀이 임의로 빼지 않는다 → 방향 알림에 명시). 배당은 현재 원인 키에 없어 '불어난 돈'에 넣을지 별도 판정. 투자 조언 경계: 비율·금액 사실만, "더 넣으세요"류 문구 금지.
- **규모**: M(화면 1곳 재구성, 매핑 함수 + 테스트). 저장·서버 전송 변경 0. risk:medium(대표가 본 성과 화면의 구성 변경).

## 후보 B (A와 한 쌍): 잔액 맞추기 때 차이를 한 번만 묻기
- **누구·문제**: 현금을 등록한 사용자 전원. 매달 잔액을 맞출 때마다 차액이 '기록 안 된 변화'가 되어, A의 답이 "대부분 알 수 없음"으로 나온다.
- **새 흐름**: 잔액 맞추기에서 현금 잔액을 바꿔 저장 → 차액이 있는 행에 "늘어난 N원은?" 선택 1회: 넣은 돈(월급·저축) / 쓴 돈 / 다른 자산에서 옮김 / 건너뛰기 → 고르면 기존 입출금 기록(`cashTransactionSchema` deposit·withdrawal, `src/types/transaction.ts` 30행) 1건이 반영 완료 상태로 생김 → 결산·연 탭 '기록 안 된 변화'가 '순유입'으로 옮겨감.
- **줄이는 것**: 상세 › 현금 › 입출금을 따로 찾아가 손으로 적는 단계. "입출금을 기록하면 더 정확해져요" 안내는 맞추기 창 바로 가기로 바꿔 막다른 문구를 없앰.
- **정해야 할 것**: 기록 날짜는 저장 시각(시스템 값)으로 고정(LEARNINGS 11-11: 판별에 사용자 수정 필드 금지). '옮김'은 순자산 원인이 아니므로 기록을 만들지 않는다(LEARNINGS 2026-10). 기존 이중 차감 경고(`balance-edits.ts` shouldWarnTxAfterResync)와 충돌 여부는 developer 확인 필요 — 확인 전 가정.
- **규모**: M. 스키마 변경 0이지만 사용자 기록을 새로 쓰므로 qa 데이터 안전 점검 대상, risk:medium~high(cto 판정).

## 후보 C (A 후속): 월별 기록을 "달마다 넣은 돈·불어난 돈" 막대로
- **누구·문제**: 결산을 3개월 이상 쌓은 사용자. 월별 기록 블록(`monthly-log-block.tsx`)은 달마다 순자산 숫자만 나열해 '어느 달에 왜 늘었나'가 안 보인다.
- **새 흐름**: 월 탭 하단 월별 기록 → 달마다 2색 막대(넣은 돈 / 불어난 돈) + 순자산 → 막대를 누르면 그 달 결산으로 이동(기존 월 화살표와 같은 도착지).
- **줄이는 것**: 월별 기록의 자산 종류별 숫자 열(구성 변화 블록과 중복)을 펼침으로.
- **규모**: M. A의 묶음 매핑을 재사용하므로 A 이후에만 의미가 있다.

## 권고·왜 지금
- **A+B를 한 릴리스로** 권고한다. A만 하면 현금 기록이 없는 다수 사용자에게 '기록 안 된 변화'가 가장 큰 줄로 나와 체감이 약하다. B만 하면 기록한 보람을 보여줄 화면이 없다.
- 12월 결산 창(11/27~)과 연말 직전이라 '올해 내 돈' 질문이 가장 자연스러운 시기다. 대표의 최근 방향(핵심 정보만 #209, 인지성 #215·#224)과 같은 결이고, 화면 수는 늘지 않는다.
- 근거의 한계: 실사용자 중 현금 입출금 기록 비율, 연 탭 방문 수는 이번에 확인하지 않았다(GA '성과·자산 변화' title 수치로 business-pm 확인 필요). 화면 동작은 코드 읽기 기준이며 preview로 재현하지 않았다.
