# 동기화 push conflict 시 로컬 편집 교체 — 재현 결과 (2026-11-06, qa)

## 판정: 확정 결함 (재현됨, 코드 무수정)
방법: 서버 API 모의(fetch 목킹, route.ts의 compareAndSet 409 의미 재현) + 기기 2개(localStorage 분리)로 실제 `pushAsset`/`pullAsset`/`applyImportedPayload`를 실행(vitest 임시 테스트, 재현 후 삭제). provider의 conflict 경로(`runPush` → `autoPull({force:true})` → `runPull` → `pullAsset`)와 동일 호출 순서.

## 재현 시나리오와 결과
공통: A·B 동기화 완료(v1). 현금 c1=1000, c2=500, 주식 S1 수량 10.
1. B가 c1을 2000으로 수정 후 push(v2).
2. A(아직 v1)가 c1=3000, **S1 수량 99(B가 안 건드림)**, c2 삭제, c3 신규 추가 후 push → **409**.
3. force pull 후 A 상태: c1=2000, c2=500(되살아남), S1=10, c3=777(보존).
4. A 재push 후 B pull: 동일(c1=2000, c2 존재, S1=10, c3 존재). 즉 **원격 값이 확정되고 A의 편집은 서버·B 어디에도 남지 않음**.

| A의 로컬 변경 | 결과 |
|---|---|
| 같은 항목 수정(c1) | 덮임 (원격 우선, 코드 주석상 의도된 범위 밖) |
| 다른 항목 수정(S1, B는 무관) | **덮임** — 항목 단위 병합이 아니라 페이로드 통째 교체 |
| 항목 삭제(c2) | **취소됨(부활)** — 기준점 3-way는 "원격에서 삭제"만 존중, "로컬 삭제 vs 원격 존치"는 원격 우선 |
| 신규 추가(c3) | 보존 (reconcileAdditiveMerge, mergedAdditions) |

## 코드 근거
- `cloud-sync-provider.tsx` runPush: conflict → `autoPullRef.current({force:true})`(편집 보류 가드 우회), 실패 시 3초 후 재시도. 로컬 변경분 보관·알림 없음. silent push면 토스트도 없음.
- `sync-client.ts` pullAsset → `applyImportedPayload(payload,{syncedIds})`: `reconcileAdditiveMerge`는 mergeById로 **id 기준 "로컬에만 있고 기준점 밖" 항목만** 복원. 기존 id의 필드 수정·삭제는 병합하지 않음. 이후 `userEditRef=false`로 편집 신호도 소거.
- 마운트(216~224행)와 online 이벤트의 `force:true` pull도 같은 경로: 오프라인 중 편집이 원격이 앞서 있으면 동일하게 교체.

## 영향 범위·빈도
- 덮이는 데이터: 이미 동기화된 항목의 수정(보유수량·단가·잔액·메모 등 모든 필드), 이미 동기화된 항목의 삭제, 같은 push 안의 무관 항목 수정 전부(범위가 충돌 항목이 아니라 **A의 미push 변경 전체**). 닉네임·profitBasis 등 payload 단위 필드도 원격 우선. 스냅샷은 keepLocalSnapshots로 보호.
- 조건: 서로 다른 기기가 같은 금고에서 A가 최신 pull 전(폴링 60초·포커스 미경과) 편집+디바운스 push, 그 사이 B가 push. 또는 오프라인 편집 후 복귀. 편집 직후 10초 pull 보류, 마운트/온라인 pull-first가 일부 창을 줄이나 60초 폴링 간 창은 남음.
- 단일 기기 사용자: 영향 없음. 다기기·가족 공유(#57)에서 빈도 상승.
- 기존 사용자 영향: 있음(동기화 사용 다기기 사용자). 사용자에게 사라짐 사실이 안 알려짐(자동 push는 silent, 토스트는 "다른 기기의 변경을 반영했습니다" 한 줄 또는 없음). 원칙상 "사용자 기록 손실 가능성 = FAIL" 해당.
- 서버로 가는 값 변화 없음(원칙 위반 아님).

## #57 보류 spec 재사용 가능 여부 (.memory/issues/4.38-57-family-vault/4.38-spec.md)
- 문제 정의(1절 "충돌 시 원격 교체, 빈틈")는 본 재현과 일치 → **재사용 가능**. 단 r2는 "덮인 항목 알림·목록만, 다시 적용 없음, 같은 항목 동시 수정은 원격 우선"까지라 **무관 항목 수정 소실·삭제 부활**을 다루지 않음. 재개 시 보강 필요:
  1. 덮임 감지 범위를 "충돌 항목"이 아니라 pull 직전 로컬 vs 원격 diff 전체(수정·삭제 포함)로.
  2. 알림만으로 부족 → 최소 안: pull 전 로컬 사전 상태를 메모리에 보관해 "내 값으로 다시 적용"(r2에서 삭제된 기능) 복원 검토, 또는 항목 단위 3-way(기준점 값 해시 저장 시 sync-state 스키마 변경 → risk:high, 마이그레이션 테스트 필수).
  3. 삭제 부활 케이스 알림 문구 추가.
- 가족 공유 기능과 분리해 "동기화 소실 방지/알림" 단독 버그 수정으로 먼저 착수 가능(가족 UI 불필요).
