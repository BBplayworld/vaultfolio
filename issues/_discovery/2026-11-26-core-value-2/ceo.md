## ③ 맞추기 결과 대조 — 서버 프롬프트 변경 판정: **절대 규칙 위배 아님(조건부)**
- 스크린샷 분석은 이미 승인된 서버 경유 기능이다(2026-08 승인, 10-31 대표 보안 기준). 이 변경은 **서버로 가는 입력을 늘리지 않는다**. 같은 이미지에서 숫자 1개를 더 읽어 같은 응답으로 돌려줄 뿐이다. 앱 합계와 차이 계산은 기기에서만 한다.
- 조건(qa 데이터 안전 점검표에 넣는다)
  1. 요청 본문은 그대로다. 앱 합계·보유 목록은 서버로 보내지 않는다(11-12 '보유 사실'도 보내지 않는다).
  2. 서버는 응답 값을 저장·캐시·로그하지 않는다. `:833`은 `e.message`만 남기고, 새 필드는 로그 경로에 없다. qa가 grep으로 확인한다.
  3. 응답은 `{ rows, screenTotal? }` 꼴로 행과 **분리된 필드**로 받는다. 총액이 행으로 섞이는 회귀를 막기 위해서다. `:820`의 배열 전제와 /ratio 경로(같은 route)가 하위 호환되는지 tech-review에서 확인한다. 기존 인식 픽스처 회귀 0이 머지 조건이다.
  4. 기기에서는 메모리에서만 쓰고 AssetData에 저장하지 않는다. 저장하면 스키마 변경이라 high로 다시 판정한다.
  5. GA는 `일치/차이/총액 없음` 구간 title 1개만 보낸다. 금액·%·증권사명은 보내지 않는다(C122: 전송 코드 줄 인용).
  6. 총액에 예수금이 포함됐는지 라벨로 확신할 수 없는 화면, 여러 장이 섞여 범위가 다른 경우, 잘린 화면에서는 줄을 숨긴다. 허용 오차 안이면 '일치'로 보이고, 차이가 나면 `시세 시각이 달라 조금 다를 수 있어요`와 다른 행을 함께 표시한다. C138에 따라 일치·차이·총액 없음 3가지 값을 넣어 본 문장을 spec에 적는다.

## ④ 웰컴 문장 — #292 4주 판독과 충돌하는가: **규칙상 충돌 없음, 판독은 끊긴다**
- 판독 화면 동결은 대표 지시(11/26)로 풀렸다. 경계 기록 의무만 남는다. 웰컴 도착이 주 6대 수준이라 4주 판독이 결론을 낼 힘이 약하다.
- 처리: 5.163 운영 반영 시각에 #292 판독을 끊는다('그때까지 n일 관측·판정 보류'). 문장 교체는 새 판독(같은 지표, 4주)으로 이어 간다. 이렇게 하려면 첫 버튼·배치는 바꾸지 않아야 한다. #292의 효과와 섞이면 둘 다 판정할 수 없다.
- 문장에 '서버로 안 보내요'·'아무것도 안 나가요'를 넣지 않는다. 스크린샷이 서버에서 분석되므로 사실이 아니다(10-31 단정 금지). '연동 없이'는 사실이다(마이데이터 0). 보안 문구를 넣으면 위임 조건 ⑤에 해당하니, 넣지 않는 것이 기본이다.

## ⑤ high 트랙 선행 필요성·착수 시점
- **받은 배당 기록(D)**: 선행 passthrough가 **필수**다. 거래 스키마가 `z.object`(strict)라 구버전 기기가 동기화 때 `kind`를 지운다. 그러면 새 기록이 조용히 사라진다. 이것은 데이터 손실이다.
  - 시점: 5.164(passthrough)의 spec·tech-review는 5.161 개발과 병행한다. 머지는 5.163 다음에 한다.
  - **5.165 본편은 5.164 운영 반영 + 7일 뒤**에 머지한다. 구버전 PWA가 갱신될 시간을 두기 위해서다. 그 사이 개발·qa는 해도 된다.
  - 복원 테스트 필수: 이전 버전 → 새 버전, 새 → 구 → 새 왕복에서 kind가 유지되는지 확인한다.
  - 11-10 반려 대조: 새 메뉴 0, 입금 폼의 칩 1개이므로 반려 형태가 아니다. 예상과 받은 기록은 라벨로 나눈다(C133).
- **예·적금(E)**: passthrough가 현금 스키마도 덮도록 5.164 범위에 넣는다. 그러면 나중에 재개할 때 선행 비용이 0이다. 본편은 보류한다(⑥).
- **옛 0 환율(G)**: 기존 레코드를 고쳐 쓰는 일이고, 영향 기기 수를 잴 방법이 없다(기록 사실을 GA로 보내는 것은 11-12 위반). 지금은 착수하지 않는다.
