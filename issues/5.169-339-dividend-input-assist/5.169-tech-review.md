## 4. 지급일 정합
- 국내 `payoutDate` = KIS `divi_pay_dt`(실지급일), 해외 = `acpl_bass_dt`(현지 기준일, `finance-service.ts:681`) → spec대로 국내형만. 추정 행은 서버가 만든 `YYYY-MM-15`·`isEstimated:true` → `isDividendPaid`가 제외.
- **spec 정정 1**: 응답은 **올해 조회분 + 추정만**(route.ts 7단계, 작년분은 빈도 추정용으로만 쓰고 내려오지 않음). 1월~첫 지급 전엔 버튼 없음(상태 표와 일치). 또 국내 조회 기간이 기준일 기준이면 작년 12월 기준·올해 4월 지급분이 빠질 수 있다 — 틀린 날짜가 아니라 버튼 없음/더 이른 날짜로만 나타나며 배당 화면과 같은 한계(알려진 한계로 dev-notes 기록). `minDate` 조건은 사실상 항상 참이지만 유지.
- 키 정합: 폼 종목 칸은 `groupStocksByTicker`(`t:ticker`), 배당 화면은 `groupStocksByTickerCategory`. 묶음 안에서 `ticker && category≠unlisted && inactiveStatus≠delisted && currency≠JPY && 국내형` 행이 있고 **비국내형 행이 섞이지 않을 때만** 조회, ticker는 `normalizeTicker(그 행)` → domestic·ISA가 섞여도 type은 같아 키 1개. 오늘은 `todayKst()`(배당 화면 `kstTodayString`과 같은 값). 글자 `M/D`는 문자열 분해(Date 객체 금지, 시간대 밀림 방지).

## 5. 계좌 — '사용자가 고른 계좌 불변'
- 진입 경로 4개: ① FAB `입출금 기록`(`dispatchAddCashTx()`, 자유) ② 현금 탭 계좌 칩(`cash-tab.tsx:97`, cashId → `lockedCash`) ③ 계좌 입출금 화면(`cash-tx-view.tsx:144`, 고정) ④ 배당 받은 기록 칩(`dividend-chart.tsx:146`, 현금 1개면 고정·2개 이상 자유). 규칙은 `lockedCash=false`일 때만.
- 구현: 판정은 effect가 아니라 **종목 Select `onValueChange` 안에서 1회**(경합 없음). `cur = getValues("cashId")`가 `""` 또는 `autoCashRef.current`일 때만 → 매칭 있으면 setValue+ref 기록, 없고 cur가 자동값이면 `""`로 되돌림. 계좌 Select `onValueChange`에서 ref=null(그 뒤 영구 불변). `선택 안 함`·배당 끔은 계좌를 건드리지 않음.
- `brokerCashDefault`: 행 `broker`에서 `isUnassignedBroker` 제외 → `matchBrokerHint(raw)??raw` → `noSpace` → `FIRM_NAMES`(기타 제외)에 있는 값만, 서로 다른 값 정확히 1개 → `noSpace(cash.institution)===그 값`인 계좌(잔액 0 포함). 2개 이상이면 `items[0].currency`와 같은 통화만 남겨 1개일 때. 자유 텍스트 `키움`은 `matchBrokerHint`로 `키움증권`이 되지만 현금 쪽은 정확 일치만(5.167과 같은 비대칭, 의도).
- **판정 요청(위험 1)**: 금액 칸이 종목 칸보다 위라 금액을 먼저 적은 뒤 종목을 고르면 계좌가 USD로 자동 전환돼 `1,000,000(원)`이 `$1,000,000`이 될 수 있다. 제안: **금액 > 0이고 후보 계좌 통화 ≠ 현재 표시 통화(빈칸이면 KRW)면 자동 채움 안 함**. 수용 기준 4에 케이스 추가 필요.
- 한계: Radix는 같은 값 재선택 시 `onValueChange`가 안 불려, 자동값을 사용자가 "그대로 다시 고른" 경우는 자동값으로 남는다(실제 피해 낮음, dev-notes 기록).
