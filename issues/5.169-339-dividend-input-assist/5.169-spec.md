# 5.169 배당 입금 입력 줄이기 — spec (planner-designer, 2026-11-27)

> 근거: `_discovery/2026-11-27-core-value-3/` planner.md C·ceo.md ②③, 받은 배당 기록 `5.165-spec.md`(정본)·`5.165-ui.md`, 증권사 현금 `5.167-spec.md` §4(정확 일치), C162·C163. 코드 기준 origin/main `cb4e5e3`(v5.166).
> **게이트**: 개발 G1 통과 뒤(11-27 10:15 통과), **머지는 G2 통과 뒤(~12/4 09:20 KST, 7일 사고 0 + qa 재스모크 1회)**. 5.167은 이미 머지됨(v5.165). 5.164(받은 배당 기록)가 revert되면 이 과제는 동결한다.

## 1. 문제
배당 입금 1건을 적으려면 계좌·금액·날짜·종목을 매번 직접 고른다. 날짜 기본값은 오늘(`cash-tx-input.tsx:77`)이라 지난 지급분을 적으면 달력을 직접 넘겨야 한다. 계좌도 종목의 증권사와 무관하게 빈칸에서 시작한다.

## 2. 목표 행동
- 배당 체크 → 종목 선택 → `M/D 지급일로` 1탭 → 금액만 입력하고 저장한다.
- 지표: GA 1개 `feature_use` category `cash_dividend_date`(버튼 누름, 금액·종목·날짜 미전송). 판독은 `cash_dividend_date` / `cash_dividend`(저장) 비율. 철수선: 머지 4주 뒤 누른 기기 0이면 버튼 제거 후보.

## 3. 범위
- 포함: (a) 날짜 칸 옆 `M/D 지급일로` 버튼 (b) 증권사 현금 계좌 기본값. 폼 1개(`cash-tx-input.tsx`)만 바뀐다.
- 하지 않을 것: **금액 자동 채움(0 포함, 세후 계산 보류)**, 종목 선택 시 날짜 자동 변경, 지급일 목록·달력 표시, 보유 여부로 버튼 거르기, 새 메뉴·화면·저장 키, 서버·API 변경, 배당 화면·거래내역 변경.
- **줄인 것(CEO 3차 표와 다름, 판정 요청)**: `세전 추정 N원` 참고 글자는 v1에서 뺀다. 세전 값이 금액 칸 바로 옆에 있으면 그 값을 그대로 적는 오입력(실제 입금은 세후)을 부르고, 11-18 '사실 조각' 피로와 같은 성질이다. 재개 조건: 버튼 판독 뒤 사용자 신호.

## 4. (a) `M/D 지급일로` 버튼
- **지급일 출처**: 고른 종목의 배당 조회 결과(`DividendPayoutResult[]`, 배당 화면과 같은 `dividendQueryOptions(ticker, type)` 쿼리 키·같은 요청 형식). 종목 1개만 조회하며 캐시가 있으면 요청 0, 없으면 같은 형식 1회(새 서버 요청 형식 0 — tech-review 확인).
- **후보** = `isDividendPaid(p, 오늘 KST)`가 참인 지급(추정 `isEstimated:true` 제외 — 추정일은 서버가 만든 15일이라 실제 날짜가 아님) 중 `payoutDate`가 폼 `min`(3년 보관) 이상인 가장 늦은 1건. 같은 티커 묶음(`groupStocksByTicker`)의 조회 결과를 쓴다.
- **노출 조건(모두)**: 입금 + 배당 체크 켬 + 종목 선택 + 국내형 조회(`domestic·irp·isa·pension`) + 후보 있음 + 조회 완료. 미래 날짜는 후보가 아니므로 노출되지 않는다.
- **해외(USD)는 노출하지 않는다**: 해외 조회 날짜는 `acpl_bass_dt`(현지 기준일, `finance-service.ts:681`)라 국내 계좌 입금일과 다르다. 기준일을 '지급일'로 채우면 틀린 날짜를 1탭으로 넣게 된다. (배당 화면이 이 날짜를 지급으로 부르는 건 기존 현상 — 후속 후보 p3.)
- **누르면 날짜만 바꾼다**: `form.setValue("date", payoutDate)`. 금액·계좌·메모·`잔액에 반영`은 건드리지 않는다. 종목을 바꿔도 날짜는 그대로이고 버튼 글자만 새 종목 기준으로 바뀐다.
- **덮어쓰기**: 버튼은 사용자가 누를 때만 동작하므로 날짜 칸에 무엇이 있든(오늘 기본값·직접 고른 날) 누르면 지급일로 바꾼다. 날짜가 이미 그 지급일과 같으면 버튼은 자리를 유지한 채 비활성(높이 불변, 표현은 ui.md).
- 지급일이 과거이므로 기존 과거 날짜 질문(`PastDateQuestion`, `shouldAskPastDate`)·맞춘 뒤 경고(`ResyncTxWarning`)가 직접 입력할 때와 똑같이 뜬다(새 분기 0).
- 글자 `M/D 지급일로`(예 `4/18 지급일로`), 연도는 붙이지 않는다(올해·작년 조회만 오고 후보는 오늘 이전).

## 5. (b) 증권사 현금 계좌 기본값
- **조건**: 계좌 칸(`cashId`)이 비어 있거나 직전에 이 규칙이 채운 값일 때만. 사용자가 Select로 직접 고른 계좌, `lockedCash` 진입(현금 탭·계좌 1개 칩)은 바꾸지 않는다.
- **증권사 결정**: 고른 티커 묶음의 행들 `broker`를 `matchBrokerHint(raw) ?? raw`(증권사별 행 이름과 같은 규칙)로 맞춘 뒤, 미지정·`기타`를 빼고 **서로 다른 증권사가 정확히 1곳**일 때만 진행. 2곳 이상이면 기본값 없음.
- **계좌 매칭(5.167 §4 규칙)**: 증권사 이름이 목록 값(`기타` 제외)이고, 공백을 지운 `cash.institution`이 그 이름과 **정확히 같은** 현금 계좌만(`sameBroker` 부분 일치 금지, 은행·부분 글자 불일치). 잔액 0 계좌도 대상.
  - 1개 → 그 계좌. 2개 이상 → 종목 통화와 같은 통화 계좌만 남겨 1개면 그 계좌, 아니면 기본값 없음. 0개 → 기본값 없음.
- 규칙이 채운 값은 종목을 바꾸면 다시 판정한다(새 매칭 있으면 교체, 없으면 빈칸으로 되돌림). 사용자가 계좌를 한 번이라도 고르면 그 뒤로는 손대지 않는다. 새 문구 0(선택된 계좌는 기존 계좌 요약 상자에 보임).
- 해외·엔화 종목도 이 규칙은 적용한다(배당 조회와 무관).

## 8. 수용 기준(qa가 그대로 검사)
1. 국내 배당 종목(확정 지급 2건 이상, 추정 1건 포함 픽스처)을 고르면 `M/D 지급일로`가 가장 늦은 확정·오늘 이전 지급일로 보이고, 추정·미래 날짜는 쓰이지 않는다.
2. 버튼을 누르면 날짜만 그 날로 바뀌고 금액은 0 그대로, 계좌·메모·반영 체크 불변. 종목 선택만으로는 날짜가 바뀌지 않는다. 직접 고른 날짜도 버튼을 누르면 바뀐다. 같은 날짜면 비활성.
3. 6장 표의 '버튼 없음' 상태 각각에서 버튼 DOM 0, 폼 높이는 main과 같다. 해외 USD 종목에서 버튼 0.
4. 계좌 기본값: 픽스처(키움증권 주식 · `키움증권` KRW·USD 현금 · `키움` 부분 일치 현금 · `하나은행`/`하나증권` · 2개 증권사에 나뉜 티커 · 미지정)에서 5장 규칙대로만 채워진다. 직접 고른 계좌·`lockedCash`는 종목을 바꿔도 불변. 규칙이 채운 계좌는 매칭 없는 종목으로 바꾸면 빈칸.
5. 버튼 누름 → 과거 날짜 질문이 직접 입력 때와 같게 뜨고, 저장 레코드·`cashTxTags` 형식은 main과 같다(저장·동기화·서버 diff 0, 네트워크는 기존 `/api/finance/dividend?ticker&type&excd` 형식만).
6. GA: 버튼 누름 1회당 `feature_use{category:"cash_dividend_date"}` 1건, 금액·종목·날짜 파라미터 0. 기존 `cash_dividend`는 저장 때만 그대로.
7. C162: 버튼 판정 테스트 픽스처의 `isEstimated`는 없음·false·true 세 값, 지급일은 과거·오늘·미래, 카테고리는 국내·ISA·해외·엔화를 모두 포함한다. 계좌 기본값 테스트의 `broker`는 실제 쓰기 경로 값(목록 값·자유 텍스트·미지정)으로 만든다.
8. 320·375 × 라이트·다크에서 날짜 칸과 버튼이 겹치지 않고 버튼 히트영역 40px 이상, 추가분 색은 brand 아님(보조 버튼, ui.md), 투자 조언·금액 문구 0.
