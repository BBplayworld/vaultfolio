## 2. (a) `M/D 지급일로` 버튼 — 날짜 라벨 줄 오른쪽
**위치 판정: 날짜 칸 옆·아래가 아니라 `날짜` 라벨 줄 오른쪽 끝.**
- 옆(같은 줄)은 320에서 날짜 칸이 240−8−125 = 107px로 줄어 `2026. 11. 27.`+달력 아이콘(약 140px)이 잘리고, 버튼이 조회 완료 뒤 나타날 때 날짜 칸 폭이 튄다. 아래(새 줄)는 나타날 때 폼이 +48px 밀린다(spec 8-3 '높이 main과 같음' 위반 소지).
- 라벨 줄 오른쪽은 실측 날짜 FormItem 높이 58px(1280 60px) = 버튼 없을 때와 같고, 날짜 칸 폭 불변, 버튼 폭이 종목마다 달라도 오른쪽 정렬이라 다른 요소가 움직이지 않는다. 라벨 줄 오른쪽 보조 액션은 §5 '목록 정렬 트리거'와 같은 자리 규약.

**모양**
- `<Button type="button" variant="secondary">` + className `relative -my-[5px] h-6 gap-1 rounded-full px-2.5 text-sm font-medium tabular-nums after:absolute after:inset-x-0 after:-top-[13px] after:-bottom-[3px] after:content-['']`.
  - 보이는 크기 h-6(24) 칩(§3.2 칩=full). 음수 마진으로 라벨 줄 레이아웃 높이 14px 유지.
  - 히트 40px = 24 + 위 13 + 아래 3. 아래 끝 = 날짜 칸 윗변(실측 겹침 0~−1px), 위는 배당 상자 아래 패딩으로 1~2px 들어감(그 자리에 누를 요소 없음, 허용).
- 색: secondary 면 + 기본 글자. **brand·주황·빨강/파랑 금지**(확인 버튼이 아니고 의미값도 아님). 라이트에서 날짜 칸과 면 톤이 비슷하지만 칸은 테두리·사각, 버튼은 알약이라 구분된다(시안 320 라이트).
- 글자: `{M}/{D} 지급일로`(앞자리 0 없음, 연도 없음). 실측 폭 103(`4/8`)~121px(`12/28`), 320에서도 라벨 `날짜`와 한 줄.
- 아이콘 없음(준비 상태). 글자가 동작을 그대로 말한다.

**누른 뒤(같은 날짜 = 적용됨)** — 날짜 칸은 강조하지 않는다(값이 바뀌는 것 자체가 피드백).
- 버튼은 그 자리 유지, 표현만 바뀜: 면 없음(`bg-transparent hover:bg-transparent`), `text-muted-foreground`, 왼쪽에 `Check size-3.5`(aria-hidden), 좌우 패딩 `px-1.5`. 글자 동일. 실측 폭 129px(320 한 줄 유지).
- **`disabled` 대신 `aria-disabled="true"`** — 키보드로 누른 직후 포커스가 사라지지 않게. 클릭 처리는 이때 아무것도 하지 않는다(setValue·GA 0). `static` prop으로 누름 축소도 끈다.
- `opacity-50`(비활성 표준)을 쓰지 않는 이유: '못 누름'이 아니라 '이미 맞춤'으로 읽혀야 한다.
- 날짜를 직접 다른 날로 바꾸거나 다른 종목을 고르면 준비 상태로 돌아온다.
- 스크린리더: 항상 마운트된 `role=status` sr-only에 누른 순간 `날짜를 {M}월 {D}일로 바꿨어요`. 종목·날짜가 바뀌면 비운다.

**모션**
- 나타날 때 `motion-safe:animate-in fade-in-0 duration-150`(높이 영향 없음). 사라질 때 즉시(§6 퇴장 절제).
- 종목을 바꿔 글자만 바뀔 땐 재마운트 금지(`key`에 티커·날짜 넣지 않기) — 같은 요소에서 글자만 교체, 페이드 재생 0. 새 종목이 조회 중이면 spec대로 숨겼다가 완료 시 다시 페이드.
- 준비↔적용 전환은 Button 기존 `transition-[color,…]`로 글자색만 보간, 면은 즉시. `transition: all` 금지.
- 연타: 첫 탭만 동작(이후 aria-disabled no-op), GA 1건.

**과거 날짜 질문**: 누르면 `PastDateQuestion`이 메모 아래에 기존과 똑같이 나타난다(높이 증가는 기존 직접 입력과 동일한 의도된 증가). 동기화 경고도 같다.

## 3. (b) 증권사 현금 계좌 기본값 — 알림 방식
- **새 글자 0(보조 캡션도 두지 않음).** 근거: spec 5장 '새 문구 0', LEARNINGS 11-18 사실 조각 피로. 채워진 사실은 ① 계좌 칸 값 ② 그 아래 기존 요약 상자(계좌명·잔액) ③ 금액 라벨 통화로 보인다. 375×667(다이얼로그 최대 600px)에서도 스크롤 0 상태면 계좌 칸·요약 상자·지급일 버튼이 한 화면에 들어온다(시안 375 다크, 버튼 위끝 다이얼로그 기준 약 558px).
- **요약 상자 펼침(필수)**: 종목을 고르는 순간 위쪽에 요약 상자(36px + 간격 16 = +52px)가 갑자기 생기면 방금 누른 종목 칸이 손가락 아래에서 튄다. 요약 상자를 §6 높이 펼침으로 바꾼다 — 계좌 칸과 같은 블록 안에 항상 마운트, `grid ease-out motion-safe:transition-[grid-template-rows] motion-safe:duration-200`, 계좌 있음 `grid-rows-[1fr]` / 없음 `grid-rows-[0fr]` + `inert`, 간격 16px는 펼침 안쪽 `pt-4`(lockedCash면 `pt-0`)로 둬 빈 상태 높이 = main. 닫힘은 내용이 즉시 빠지는 것 허용. 직접 계좌를 고를 때도 같은 펼침(같은 요소, 동작 차이 0).
- 계좌 SelectTrigger `data-autofill="broker"`(규칙이 채움) / `"none"`(빈칸·직접 고름·고정). 화면 표시 아님, qa 판정용.
- 금액·날짜·메모·반영 체크는 규칙이 건드리지 않는다.
