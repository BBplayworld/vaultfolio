## ① 원/달러 일별 종가 소스
- **앱 현재 경로**: `fetchExchangeRateFromKis`(`src/lib/finance/finance-service.ts` 497~560) = 해외 시세 price-detail의 `t_rate`(현재값 1건). 일봉이 아니고, 날짜 붙은 이력은 클라이언트 `readExchangeHistory()`(로컬, 기기마다 다름)뿐이라 서버 Cron에서 못 쓴다. 4.91 초기에도 이 이력으로 전일값을 만들다 f0e232a에서 '원/달러 제외'했다.
- **후보 A(권장 검증 대상): KIS 해외지수 일봉과 같은 TR**. `fetchOverseasIndexDailySeries`는 `inquire-daily-chartprice`(FHKST03030100)를 `FID_COND_MRKT_DIV_CODE=N`으로 부른다. KIS 문서상 같은 API가 시장구분 `X`(환율) + 코드 `FX@KRW`를 받는 것으로 알고 있다(미검증, 실호출 1회 필요). 맞으면 키·약관·호출 방식이 기존 KIS와 같고, 구현은 시장구분·코드 인자 추가와 `changeFromSeries` 재사용으로 끝난다(+30줄 안팎). 추가 비용 0, 키 추가 없음.
- **후보 B: 한국은행 ECOS** `731Y001`(원/달러 매매기준율) 일별. 무료·**인증키 필요**(무료 발급), Vercel 환경변수 추가 필요. 한국은행 공개 통계는 출처 표시 조건의 이용이 일반적이나 약관 문구는 미확인. 기준 시각이 서울 15:30 환율이라 국내 마감 알림과는 맞고, **미국 종가 시각과는 정의가 다르다**(카탈로그 제외 사유와 동일). 후보 A 실패 시 대안.
- **판정**: A 실호출이 되면 진행. 안 되면 환율 제외(질문 2의 '제외 후 진행') 권고. 어느 쪽이든 "미국 마감 알림의 환율"은 정의가 서울 15:30 기준이라는 한계가 남으니 문구를 `원/달러`가 아닌 `원/달러(서울 마감)`처럼 날짜 검증 `changeFromSeries`(마지막 행 날짜 = 기대 거래일)로 보호하고, 미국 회차에서는 전일 서울 마감 기준임을 둘째 줄이 아닌 라벨로 구분하는 것을 제안한다.

## ② Cron 구성 (Hobby: 최대 2개, 각각 하루 1회, 시각은 지정 시간대 내 임의 분)
- 현재 `vercel.json`: `/api/push/cron` 0 0 * * * 1개. 2개까지 가능하므로 아래 2개로 충분하다.
  1. `0 0 * * *`(09:00 KST) → 미국 마감(화~토) + 주간(월) + 결산 열림 + 세금. 요일 판정은 코드(KST 요일), Cron은 매일 호출. 09시 회차 합치기는 한 핸들러에서 우선순위(결산>세금>주간>미국)로 1건 구성하므로 구조상 자연스럽다.
  2. `0 7 * * *`(16:00 KST) → 국내 마감(월~금, 휴장 제외). 이전 `cron/kr/route.ts` 복원(Hobby는 시각 ±59분이므로 15:30 마감 후 16~17시 범위 안).
- 휴장 상수는 `src/lib/finance/kr-holidays.ts`·`us-holidays.ts`(2026~2030 이미 존재) 재사용. 새 Cron 불필요, 한도 여유 0개(추가 확장 불가).
- 주의: 서버 시각 지연으로 날짜가 넘어가는 회차는 `markPushSent(topic,date)` 중복 방지가 이미 보호.

## ③ A 교체 이전 코드 복원 규모와 risk
- 복원 대상(5f2d8aa 기준): `push/quotes.ts` 130줄 중 지수 경로만(kr-index·us-index·`changeFromSeries`) ~60줄, `cron/kr/route.ts`+`cron-run.ts` 지수 회차(원본 131줄 중 시세 조회·cond 판정) ~100줄, catalog 대상 6개+cond, `message.ts` 종가 문구. A 교체 커밋은 push 영역에서 -2198/+284(테스트 포함)이므로 순복원은 대략 **+500~600줄(테스트 절반)**.
- 신규: 주간 요약(지난주 마지막 거래일 대비, ~80), 일정 상수(~40), 09시 합치기(~60), prefs v2→v3 + 복원 테스트(~120), 기본 묶음 버튼·GA(~80), 설정 UI 대상·조건(~150). **합계 약 900~1,100줄(테스트 포함)**.
- 줄이는 방법(권고): ⓐ 첫 릴리스는 지수 4개+환율을 빼고 **S&P 500·나스닥 종합·코스피·코스닥만**(실호출 검증 끝난 코드), SOX·나스닥100은 실호출 후 추가. ⓑ '큰 움직임 있는 날만'(cond)은 이전 코드가 있어 복원 쉬움 — 유지. ⓒ 주간·일정 줄은 2차로 분리 가능.
- **risk: high 유지**. 사유: 구독 레코드(서버 저장 값) 확장 + 로컬 저장 키 prefs v3 변경 → 마이그레이션 필수. 서버로 나가는 값은 종류 ID·대상 ID·cond뿐이고 보유 자산 역산 불가(공통 시세, 구독자 보유 미사용). 구버전 기기 혼재: v2 prefs는 종류 보존(변환 시 손실 없음), 롤백 시 v3 키를 못 읽어 알림 설정만 기본값 → 자산 기록 영향 0.
- KIS 호출: 이전 4.91 구조상 항목당 1호출·350ms 간격이라 지수 6+환율 1은 약 3초, 예산 문제 없음(단 Cron 실행 시간 제한 Hobby 60초 이내).

## ④ 일정 상수 출처·갱신
- **휴장**: 위 `kr-holidays.ts`·`us-holidays.ts` 재사용(연 1회 수동 갱신, 이미 운영 중). 부활절 기준 Good Friday·임시공휴일은 연초 검수.

## 결론
환율은 KIS `X`/`FX@KRW` 실호출 1회로 가부 판정, 불가 시 제외하고 진행. Cron 2개로 구성 가능. 규모 900~1,100줄, risk high. 먼저 지수 4개(검증 완료)로 시작하는 축소안 권고.
