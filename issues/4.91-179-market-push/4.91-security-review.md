결론: **코드 차단 결함 0건 / 머지 전 운영 설정 조건 1건(PUSH_STORE_KEY를 Preview와 Production에 서로 다른 값으로 등록) / 권고 6건.** 사용자 자산 데이터는 서버로 가지 않고, 서버에 평문 endpoint·keys·IP·UA·금고 ID는 남지 않는다. (cto 보안 검토, PR #180 head 585b11b, 2026-11-12)

**대표용: 서버에 남는 것 3줄**
1. 기기 주소(endpoint)와 암호화 키(p256dh·auth)는 서버 비밀키로 AES-256-GCM 암호화한 덩어리로만 남고, 조회 키도 주소 원문이 아닌 HMAC 값이다.
2. 평문으로 남는 것은 고른 알림 대상 ID(고정 15개 중), 조건(매일/±2%), 날짜(일 단위)뿐이며 90일 미사용 시 자동 삭제된다. 끄기·모든 데이터 삭제·기기 해지(410)에도 삭제된다.
3. 보유 종목·금액·금고 ID·IP는 구독 기록에 없다. 예외로 기존 모든 API에 공통인 요청 횟수 제한 카운터(`rl:push-subscribe:<IP>`)가 1시간 동안만 남으며, 구독 기록과 연결되지 않는다.

## 머지 전 조건 (운영 설정, 코드 변경 아님)
- **C1** `PUSH_STORE_KEY`를 Vercel Preview와 Production에 **서로 다른 32바이트 무작위 값**으로 등록한다(`openssl rand -base64 32`). VAPID 키쌍과 CRON_SECRET도 Production 전용(또는 분리)으로 둔다. 비밀값은 문서·이슈·로그에 쓰지 않는다. 확인할 것: Production 값이 Preview 범위에 체크되어 있지 않은지.

## 권고 (차단 아님, 같은 브랜치 후속 또는 다음 릴리스)
- **R1 키 교체·유출 대응 절차**: 유출이 의심되면 ① Production PUSH_STORE_KEY를 새 값으로 바꾸고 재배포 ② Redis에서 `push:prod:sub:*`·`push:prod:topic:*`를 삭제한다(옛 키로 암호화된 블롭 제거) ③ 사용자는 앱을 다시 열 때 `reconcilePush`가 새 키로 자동 재등록한다(prefs.on과 권한 granted가 조건). 유출 범위는 endpoint·keys뿐이며, 이것으로 그 기기에 알림을 보낼 수 있지만 자산 정보는 없다. VAPID 개인키까지 유출됐으면 키쌍을 교체한다(기존 구독은 무효가 되고 재구독이 필요하다). dev-notes에 이 절차를 남긴다.
- **R2 GCM 강화**: `createDecipheriv(..., { authTagLength: 16 })`를 쓰고 `buf.length < 29`면 null로 처리한다. 짧은 태그 수용을 막는 조치다(현재는 Redis 쓰기 권한이 있어야만 악용 가능해서 실위험이 낮다). HMAC 키와 암호화 키를 HKDF로 분리하는 것도 선택 사항이다.
- **R3 DELETE 키 미설정 시 500**: subscribe DELETE에 `if (!isPushConfigured()) return 503`을 추가한다.
- **R4 삭제 판정 기준**: `handleClear`와 `reconcilePush`가 `prefs.on`만 보고 판단한다. 로컬 키 저장이 실패했거나 지워진 상태에서 기기 구독이 살아 있으면 서버 기록과 발송이 최대 90일 남는다. 수정 방법: 체험 모드가 아니면 prefs와 관계없이 `unsubscribePush(false)`를 호출한다(내부에서 구독이 있는지 확인함).
- **R5 고아 정리·발송 상한**: TTL 만료나 키 교체로 `getPushSub`가 null을 반환한 id가 topic 집합에 계속 남는다(HMAC뿐이라 노출은 없고 용량만 늘어난다) → cron에서 null id를 `srem`·`del`한다. 분산 IP로 허용 호스트의 가짜 구독을 대량 등록하면 cron 60초를 넘겨 그날 발송이 일부 빠질 수 있다(회차 플래그를 먼저 잡기 때문) → 전체 구독 수 상한(예: SCARD 합계 5천 초과 시 신규 거부)을 둔다. 목표 규모(100명)에서는 현실 위험이 낮다.
- **R6 문서 정합**: dev-notes 서버 저장 표에 `testlock` 키와 `rl:push-subscribe:<IP>`(기존 공통 가드, 1시간)를 추가한다. 대표 지시의 'IP 금지'는 구독 기록 기준으로 지켜지고 있다는 점을 명시한다.
