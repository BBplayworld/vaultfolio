## 1. 현재 KIS 환율 사용처 (origin/main 전수)
**서버(KIS 호출은 2곳뿐)**
- `src/lib/finance/finance-service.ts` `fetchExchangeRateFromKis`(L532): 해외 현재가 TR `HHDFS76200200` 에 NAS/AAPL, TSE/7203(도요타)을 불러 응답 `t_rate`를 환율로 추출(USD, JPY는 ×100 = 100엔 기준). 즉 **실시간 적용환율**.

**클라이언트(출처 무관, `exchangeRates`/`exchangeHistory` 소비만)** — `asset-data-context.tsx` L455(`/api/finance?type=exchange` 수신·`mergeExchangeHistory`), `profit-utils.ts`(L222~279 `ExchangeHistory`, localStorage `STORAGE_KEYS.exchangeHistory`, 날짜별 USD·JPY 저장, 로컬 우선 병합), 홈 `dashboard.tsx`, `asset-report.ts`(귀인 분해: 시세 vs 환율), `change-hero`·`use-day/week-hero`·`net-asset-chart`·`settlement-view`, 매수/거래 입력(`stock-input`·`trade-input` 매입환율 기본값), 스크린샷 가져오기, 배당·세금·X-Ray 환산 등 약 45개 파일. 이 소비처는 **수정 불필요**(출처만 바뀜).

## 2. ECOS 대체 가능성
- **인증키 필요(확정).** ECOS Open API는 `https://ecos.bok.or.kr/api/StatisticSearch/{인증키}/json/kr/1/N/{통계표}/D/{시작}/{끝}/{항목}` 형식이며 키 무료 발급(ecos.bok.or.kr 회원가입 → 인증키 신청). 샘플키(`sample`)는 건수 제한이라 운영 불가. **현재 저장소·환경에 ECOS 키 흔적 없음**(코드·.env.example·셸 환경 확인). → 대표가 키를 발급해 Vercel 환경 변수(제안명 `ECOS_API_KEY`, Production·Preview)에 등록해야 한다. 값은 파일에 쓰지 않는다.
- 통계표: 주요국 통화의 대원화 환율 일별 계열(731Y001 계열 — 원/미국달러 `0000001`, 원/일본엔(100엔) `0000002`; 요청서에 언급된 731Y006은 15:30 종가 계열 후보). **키 없이 통계표 코드·항목코드·단위를 실호출 검증하지 못했다** → 키 수령 후 `StatisticTableList`/`StatisticItemList`로 먼저 확정(구현 첫 단계).
- 갱신 시각: ECOS는 **영업일 일별 고시 종가**(원/달러 15:30 시장평균 계열은 당일 저녁~익영업일 아침 반영, 주말·휴일 행 없음). KIS는 장중 실시간 적용값이라 **의미가 바뀐다**: 평일 오전·장중에는 '전 영업일 종가'가 현재 환율로 표시됨.
- 과거 일별: ECOS 일별 범위 장기(수년) 조회 가능 → 서버 `EXCHANGE_HISTORY` 빈 날짜 백필에도 이점(현재 KIS는 호출한 날만 기록).
- 장애 시: 기존 캐시 fallback·서킷 로직 유지, KIS 예산·토큰 의존 제거(환율은 KIS 토큰 없이 동작 → KIS 점검 영향 분리). 키 없음/한도 초과/빈 행이면 캐시 → 없으면 503(기존과 동일 계약). ECOS 일 호출 한도 충분(10만 건 규모, 캐시 1일 1회 수준).

## 3. 화면·운영 영향
- 원화 환산값 변화 크기: 실시간(예: 장중 1,385) vs 전 영업일 종가(1,380) 차이는 통상 0.1~0.5%, 급변일 1%+. 순자산 해외 비중이 X%면 순자산 변화 ≈ 0.003×X%(예: 해외 50% → 최대 0.2~0.3%). 전환일에 일회성 계단 가능.
- **'기준' 표기**: 홈·상세에 '환율 기준' 시각 문구는 현재 없음(환율 관련 카드 문구는 '시세·환율' 귀인 라벨 정도). 푸시 알림 '환율 N원(±x%)': 아침은 오늘 행(개장 전 stale/flat → 현행도 생략 가능), 16시 국내 회차는 15:30 종가가 반영돼야 하므로 **ECOS 반영 지연 시 stale 판정 → 환율 항목 생략** 가능. 푸시 날짜 검증 로직(`quotes.ts`) 재사용하되 일별 종가 계열이라 오히려 자연스러움. 정확한 반영 시각은 키로 실측 필요.
- 캐시 경계: `getEffectiveDateStr("exchange")` 09:00 컷오프 → 고시 반영 시각 이후로 조정 검토(하루 1회로 단순화 가능).

## 4. 사용자 데이터·스키마 영향
- 저장 스키마·저장 키·마이그레이션·동기화·공유 토큰 변경 **없음**. 환율은 환산 시점 값만 쓰고 이력(`exchangeHistory`, localStorage·서버)은 `{USD,JPY}` 형태 유지. 매입환율(`purchaseExchangeRate`) 등 사용자 입력 저장값은 불변. 과거 이력은 KIS 값이 남고 이후부터 ECOS(종가) 값 → 혼재하나 구조 호환(귀인 분해에서 전환일 경계 1건 미세 변동 가능).
- 서버로 나가는 값 증가 없음(공개 환율 조회만, 사용자 정보 무관). 구버전 혼재·롤백 시 기록 손실 없음(서버 응답 형태 `ExchangeRates {USD,JPY,updated_at}`+`history` 유지).

## 5. 위험 등급 초안
**risk:medium** (순자산·해외 환산 전반에 걸친 값 의미 변화 + 푸시 문구 영향, 스키마 변경 0). 머지 위임 조건 ④ 충족이나 환율 의미(실시간→종가) 변화는 COO 확인 권장.

## 6. 구현 계획(키 수령 후, 작게)
1. `fetchExchangeRateFromBok(key, todayStr)` 신설(최근 영업일 행 USD·JPY, 빈 행이면 직전 행) — 응답 형태 `ExchangeRates` 동일. 2. route `type=exchange`에서 KIS 토큰·예산 분기 제거, 실패 시 기존 캐시 fallback 유지. 3. 서버 이력 빈 날짜 백필(선택·보류). 4. `fetchFxKrwDailySeries`를 ECOS 일별 계열로 교체(`quotes.ts` 인터페이스 유지). 5. 단위 테스트(파서·빈 행·키 없음·장애 fallback·푸시 stale). 6. 출처 표기 문구 '한국은행' 필요 여부는 ui·COO 판단(대표 결정 #263: 출처 표기). 코드 규모 파일 4~5개.

## 7. 대표 요청
ECOS 인증키 발급(ecos.bok.or.kr → 인증키 신청, 무료) 후 Vercel 환경 변수 `ECOS_API_KEY`(Production·Preview) 등록. 등록되면 이 문서 6절대로 구현.
