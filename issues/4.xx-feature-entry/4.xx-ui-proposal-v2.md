# 4.xx 신기능 진입 — UI 제안 v2 (ui-designer)

작성 2026-11-11 · v1(`4.xx-ui-proposal.md`) 대체 부분만 적는다. v1 ②(`새` chip 규칙)·④(하지 않을 것)는 유지.
입력: 대표 피드백 ① "버튼만 덩그러니 따로 있는 느낌. 상세-주식 '내 종목과 비교'·'종목 보기'가 위치·모양 모두 눈에 안 들어온다" ② "X-Ray와 양도소득 안내까지 묶어서 기능화하는 건 어때?"
근거: 운영 `?trial=1` 실측(쿠키 `theme_mode` 강제·캡처마다 `html.dark` 대조 C81, 불일치 0), 코드 origin/main 95abcdb. 목업은 실제 화면 DOM 주입(`mock2-inject.mjs`·`mock2-tools-inject.mjs`), 이미지 `screenshots/mock2-*`(320·375·1280 × 라이트·다크).

## 0. v1이 실패한 이유 (설계 원칙 교정)
v1은 기존 구조를 그대로 두고 **입구를 하나 더 얹었다**(펼침 안 틴트 버튼·카드 밑 칩). 대표가 본 것은 '버튼 개수'가 아니라 **입구가 화면의 정보 단위와 따로 논다**는 점이다.
v2 원칙: **이미 있는 정보 단위(요약 아래 도구 묶음·종목 이름 띠·허브 카드)를 그대로 입구로 만든다.** 입구마다 그 기능의 **숫자 1개를 미리 보여 주고, 행·타일 전체가 탭 영역**이다(토스·애플 증권의 '숫자 있는 행'). 추가하는 요소보다 없애는 요소가 많아야 한다.

## 5. 4.81·기존 결정과의 관계, GA·기존 경로 영향
- **X-Ray 분류**
  - 4.81 spec은 '분류의 정본 = X-Ray'로 정해 종목 한 장에 분류 줄을 두지 않았다. 타일은 하이라이트 1개만 미리 보이고 분류 목록을 옮기지 않으므로 정본은 X-Ray 그대로다
  - 메모리에서 별도의 'X-Ray 분류 전환' 결정 기록은 찾지 못했다. 다른 결정을 뜻했다면 근거 위치를 알려 주시면 대조하겠다
- **세금(4.45 #79)**: 노출 조건·이동이 그대로라 판독 비교 축(시즌 노출)은 유지된다. 문장형 안내는 타일 2줄째 짧은 사실 문구로 줄인다(같은 사실, 보장·조언 어휘 없음)
- **시장과 나란히(4.72·4.73)**: 상세·주식 진입이 글줄 → 타일로 바뀐다. 이동·뒤로 라벨(`marketCompareEnteredInApp`)은 같다. 머지 시각을 4.72·4.73 판독 경계로 기록
- **GA**
  - page_view 이름(`상세·주식 X-Ray`·`세금 관리`·`시장과 비교`·`상세·주식·종목`)은 바뀌지 않는다
  - 진입원 구분이 필요하면 `feature_use {category, source:"stock_tools"|"hub_row"|"stock_row"}`를 추가한다(예약 이벤트명 금지 C67) → planner 결정
- **저장**: 새 저장 키 0. 스파크라인은 react-query 메모리(종목 한 장과 같은 키 `["price-history", ticker, "1y"]` → 행을 본 뒤 페이지를 열면 즉시 표시)
