# 5.156 ui — 증권사 이관 질문 카드 (#310) · ui-designer · 2026-11-26
근거: `5.156-spec.md`(감지·경로·저장·되돌리기는 정본 그대로), ceo.md 7장③(카드로 체크한 쌍은 순위가 아니라 A로 고정 — 화면 영향 0), design-system §2·§3·§7, 코드 main 5bd5c1e `holdings-resync-dialog.tsx`. 로컬 실측 미실시, 줄 수는 추정(qa·ui-review가 320·390 실측).

## 1. 컴포넌트·재사용
- 카드 = 기존 묶음 섹션 문법 그대로: `<section className="space-y-1 rounded-xl bg-muted/40 p-4" data-screenshot-hide>`(증권사별 묶음·삭제 후보와 동일, 신규 토큰 0).
- 행 = **기존 `CheckRow` 재사용**(체크박스 `Checkbox` 자동 brand, `label` 전체 클릭, `min-h-10`, 체크 `after:-inset-3` = 히트 40px). 새 행 컴포넌트 금지.
- 제목 줄은 `GroupHead`를 쓰지 않는다(오른쪽 `N건`이 좁은 폭에서 제목을 더 좁힘). `<h3 className="text-sm font-bold text-pretty break-keep">`만.
- 변경: `CheckRow`에 쓰는 `sub`·`note` 슬롯만 사용, 시그니처 변경 0.

## 2. 위치·간격
`resync-summary` 줄 바로 아래, `brokerUnconfirmed` 안내·증권사별 묶음·`확인 필요`·삭제 후보보다 위. 상위 `space-y-4` 그대로(16px). 후보 A는 접힌 '다른 증권사 종목' 목록에서 뺀다(같은 `resync-chk-{id}` id 중복 금지 — 접근성 `label for` 충돌). 후보 0이면 DOM 0(현행과 diff 0), 코인 맞추기·스크린샷 모드 0.

## 3. 카드 내용(최종 문구)
- 제목: `같은 종목이 다른 증권사에도 남아 있어요`(320에서 2줄 허용, `text-pretty break-keep`).
- 설명(`text-sm text-muted-foreground leading-relaxed text-pretty break-keep`): `증권사를 옮겼다면 체크해 주세요. 체크한 종목과 거래 기록을 새 증권사 종목으로 옮겨요.`
  - spec 문구에서 두 가지를 바꿨다. ① `{B}` 자리표시자 제거: 후보가 여러 개면 B가 행마다 달라 한 문장에 못 넣는다(행 보조 줄이 B를 보여 줌). ② `지우고`를 `옮겨요`로: 경로 ①(B가 새로 추가되는 행)은 사용자 눈에 A가 지워지는 게 아니라 이어받는 것이라 `지우고`가 사실이 아니다. 사용자는 두 경로를 구분하지 않아도 되고 구분하게 만들지 않는다.
- 행(`CheckRow`): 이름 `{종목명}`(truncate), 오른쪽 상태 `옮김`(체크, `text-foreground`)·`유지`(해제, `text-muted-foreground`). 삭제 빨강 `text-destructive` 쓰지 않음(데이터가 사라지는 게 아니라 이동).
  - `sub`: `{A증권사} · 수량 {n} → {B증권사}`(수량 표기는 이 다이얼로그의 기존 `수량 N`에 맞춤, spec의 `N주` 대신). 숫자 `tabular-nums`, 화살표 앞뒤 조각은 `whitespace-nowrap`이 아니라 어절 단위 줄바꿈(`break-keep`)로 2줄까지.
  - `note`(체크 여부와 무관, 항상 보임): `거래 기록 {M}건을 함께 옮겨요`, M=0이면 `옮길 거래 기록은 없어요`. 사용자가 실제로 걱정하는 것(내 거래 기록은 어디로?)에 답하고, 경로가 달라도 같은 문장이다.

## 4. 두 경로에서 사용자가 보는 차이(= 거의 없음, 의도)
| | 이어받기(B가 추가 행) | 합치기(B가 변경·그대로 행) |
|---|---|---|
| 카드 | 동일 | 동일 |
| 체크 시 미리보기 | B 행이 `추가`에서 `변경`으로 바뀌고 요약의 추가 −1·변경 +1(기존 #144 동작) | B 행은 그대로, 요약 변경 +1(체크 1건=변경 1) |
| 결과 화면 | 동일 문구 | 동일 문구 |
- 두 경로 이름·'합친다/이어받는다' 설명을 화면에 올리지 않는다. 차이가 사용자 행동·결과에 영향을 주지 않기 때문(수량·평단은 화면 값, 거래는 따라옴).
- 요약 줄 `resync-summary`는 `aria-live`로 체크 직후 건수 변화를 읽는다(현행). 삭제 건수로 세지 않음.

## 5. 적용 결과·되돌리기
- 결과 박스(`resync-result`, 현행 `space-y-2 rounded-xl bg-muted/40 p-4`) 첫 줄 요약은 현행, **그 아래 새 줄**(이관이 1건 이상일 때만): `증권사를 옮긴 종목 {N}개 · 이은 거래 {M}건` — `text-sm text-foreground tabular-nums`, 숫자 `font-semibold`(요약 줄과 같은 규칙). `{B}로` 형태는 쓰지 않는다(증권사명 끝 받침이 `증권`=ㄴ, `은행`=ㅇ 등으로 갈려 `로/으로`가 틀릴 수 있음).
- 셋째 줄 `이 창을 닫기 전에는 되돌릴 수 있어요` 현행, 되돌린 뒤 `되돌렸어요`/`직접 고친 항목 N건은 그대로 뒀어요` 현행. 이관 포함 되돌리기가 거래·대출까지 되돌리는 것은 문구에 쓰지 않는다(결과 박스가 길어지고 사용자는 기록이 돌아오면 충분).
- 버튼 `되돌리기`(secondary)·`닫기`(brand) 현행. 닫은 직후 토스트 현행.

## 6. 상태
| 상태 | 처리 |
|---|---|
| 후보 0 | 카드 DOM 0 |
| 기본 | 모든 행 해제(`유지`) |
| 후보 여러 개 | 행마다 독립 체크, 순서는 미리보기 행 순서 |
| 적용 중(`applying`) | 체크박스는 현행 규칙 따라 입력 잠금 없음(버튼 `맞추는 중` 비활성이 중복 적용 방지) |
| 뒤로 갔다 다시 미리보기 | 체크 상태 유지(기존 `removeOv` 상태와 같은 방식) |
| 긴 종목명·긴 증권사명 | 이름 truncate, `sub`는 줄바꿈 |
| 오류(저장 실패) | 현행 토스트, 카드 변화 없음 |
- 모션 없음: 카드는 미리보기 진입과 같이 나타나며 체크 시 레이아웃 이동 0(`옮김/유지` 글자 교체만). 새로 만드는 transition 0이라 인터럽트 문제 없음, `motion-safe` 필요 없음.

## 7. 레이아웃 수치·줄 수(추정)
- 320: 다이얼로그 내부 글자 폭 ≈ 190px(패딩 20 + 카드 16 + 체크 16 + 간격 12). 제목 2줄, 설명 4줄 내외, 행 `sub` 2줄, `note` 1줄 → 행 높이 ≈ 90px. 390: 제목 1~2줄, 설명 3줄, `sub` 1~2줄. 1280: 다이얼로그 `max-w` 현행, 모두 1줄 위주.
- 카드 총 높이는 후보 1개일 때 320에서 약 260px로 첫 화면의 상당 부분을 쓴다. 첫 화면에서 증권사별 묶음이 완전히 밀려나지 않도록 설명은 위 한 문장으로 고정하고 안내 문단을 더하지 않는다(미리보기 첫 화면 ≥ 한 묶음 일부가 보임, 체크리스트 11).
- 다크: `bg-muted/40` 위 muted 0.74 대비 4.5:1 이상. `유지` muted·`옮김` foreground 대비 차등이 상태 전달의 유일한 색이 아니라 **글자(옮김/유지) 자체**가 의미를 가진다.

## 8. 접근성·testId
- 체크박스 `Checkbox` 기본(brand), 라벨 클릭 영역 전체 행 `min-h-10`, 체크 히트 40×40. 키보드 Tab·Space 현행. 카드는 `<section aria-labelledby="resync-transfer-title">`(제목 `h3 id`).
- testId: `resync-transfer-card`, `resync-transfer-check-{A.id}`(CheckRow `testId`), `resync-transfer-note-{A.id}`(note), `resync-result-transfer`(결과 새 줄).
- 문구 존댓말(해요체), 투자 조언 0.

## 9. 품질 체크리스트(qa·ui-review 판정용)
1. 후보 있음 390 다크: 카드가 요약 줄 바로 아래·증권사별 묶음 위, 접힌 '다른 증권사' 목록에 같은 종목 체크 칸 없음.
2. 후보 0: 카드 DOM 0, 화면이 v5.152와 같음(스크린샷 diff 0).
3. 기본 상태 모든 행 `유지`·체크 해제, 체크 시 `옮김`으로 바뀌고 요약 변경 +1·삭제 0.
4. 320 다크: 제목·설명·`sub`에서 어절 중간 끊김 0(`증권`/`사` 같은 분리 없음, C25), 이름과 `옮김/유지` 겹침 0, 카드 가로 스크롤 0.
5. 체크박스 DOM이 shadcn `Checkbox`(`data-slot="checkbox"`), 체크 시 brand 색, 히트 40×40(`elementFromPoint`로 체크 주변 ±12px 안 눌림 확인).
6. 라이트 390: `bg-muted/40` 위 설명·`sub` 대비 4.5:1 이상.
7. 두 경로(B 추가 / B 변경) 모두 카드·결과 문구가 같고, 이어받기 쪽만 B 행이 `추가`→`변경`으로 바뀜.
8. 결과 화면: 이관 있을 때만 `증권사를 옮긴 종목 N개 · 이은 거래 M건` 줄이 보이고 N·M이 실제와 일치, 조각 `N개`·`M건`이 줄 끝에서 쪼개지지 않음. 이관 0이면 줄 DOM 0.
9. 되돌리기: 결과·토스트 두 경로 모두 문구 현행, 되돌린 뒤 카드 상태와 무관하게 결과 박스가 깨지지 않음.
10. 코인 맞추기·스크린샷 모드에서 카드 0, 인증카드 캡처 영향 0.
11. 320에서 카드 1개 + 증권사별 묶음 1개가 있는 미리보기에서 스크롤 없이 `맞추기` 버튼(푸터 고정)이 가려지지 않고 첫 화면에 두 번째 섹션 일부가 보임.
12. 결과 N·M 문구에 `{B}로`·조사 의존 표현 0, `삭제 빨강` 사용 0, 모든 숫자 `tabular-nums`(C139 전수).
13. CHECKLIST C25·C139·C145(390·320 전체 길이)·C104(핵심 폭) 전수.
