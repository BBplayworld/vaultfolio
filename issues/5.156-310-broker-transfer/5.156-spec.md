# 5.156 spec — 증권사 이관 정리 (#310) · planner-designer · 2026-11-26
근거: CEO 판정 `_discovery/2026-11-26-roadmap/ceo.md` ②(정본, 조건 1~5·qa 4항목)·planner.md P4·P5, `5.156-tech-review.md`. 코드 기준 main 5bd5c1e. **risk:high, 대표 승인**(기존 거래 `stockId`·대출 `linkedStockId` 재작성, 4.77 #147 선례). 저장 키·zod 스키마·마이그레이션·sync payload 형식 변경 0. 주식만(코인 거래소 이관은 2차).

## 1. 문제
- A증권사의 종목 X를 B로 옮긴 뒤 B 화면으로 맞추면, A의 X는 접힌 '스크린샷에 없는 다른 증권사 종목 N개'(기본 유지)에 남아 **순자산에 두 번 잡힌다**(diff.ts:170-176). 빈 A 계좌는 찍을 화면도 없다. 대표 실사례.
- 사용자가 접힌 목록에서 A의 X를 직접 체크해도, B가 이미 있는 종목(변경·그대로 행)은 이어받기가 없어 A가 지워지고 **A의 거래가 고아**가 된다.
- **결함(포함 확정, tech-review §8)**: `applyResync`는 stocks만 거른다(apply.ts:236-241). 맞추기에서 체크해 지운 모든 종목의 거래가 고아로 남고, `reflectedTradeFlow`·`tradedStockIds`가 종목 존재를 보지 않고 합산해 결산·홈 원인에 잔차를 만든다. 직접 삭제(`planDeleteStocks`)와 규칙이 다르다. 현금 유입(`reflectedCashInflow`)은 영향 없음.

## 2. 목표 행동
B 화면으로 맞추는 사용자가 확인 화면 맨 위 질문에 체크 한 번으로 A의 남은 종목을 정리한다. 적용 뒤 순자산에 X가 한 번만 잡히고, A 시절 거래가 B의 X 아래 그대로 보인다. 체크하지 않으면 v5.152와 결과가 같다.

## 3. 범위
포함
1. 이관 후보 감지(순수) + 확인 화면 질문 카드(기본 미체크).
2. 적용: 경로 ①·② (아래 5장), 거래 `stockId`·`Loan.linkedStockId` 재지정, 매수일 최소값.
3. stocks·transactions·loans를 **한 번의 `saveData`**로 저장, 되돌리기가 세 컬렉션을 함께 되돌림.
4. 결함 수정: 맞추기 체크 삭제 종목의 거래를 `planDeleteStocks` 규칙으로 같은 저장에서 정리.

줄이는 것 — v1 범위 검토 결과
- tech-review §9 안('옛 종목 1개 + 추가 행'만, 재작성 0)은 **채택하지 않는다.** 대표 사례는 이미 두 번 잡혀 있다는 상태라, A와 B가 둘 다 저장돼 있다. 다음 B 맞추기에서 B의 X는 '그대로/변경' 행이 되므로 경로 ①만으로는 대표 데이터를 고치지 못한다. 줄이면 대표 사례가 빠진다.
- 대신 **A가 1개일 때만** 지원한다. 같은 종목·같은 계좌 유형의 남은 옛 종목이 2개 이상이거나, B 화면에 같은 종목 행이 2개 이상이면 그 종목은 카드에 올리지 않고 현행(접힌 목록)으로 둔다. 어느 쪽을 옮겼는지 묻는 화면이 늘지 않고, 생존 id 고르기 규칙이 필요 없다.
- 빈 A 계좌 정리 화면 0(카드가 겸함). 결과 화면은 relink의 '이은 거래 N건' 문구·스타일만 재사용.

하지 않을 것
- 날짜·이름·메모로 판별(LEARNINGS 11-11), 자동 적용·기본 체크.
- 코인, 비상장, 이관 후 거래로 수량·평단 재계산(화면 값이 권위, `positionSource=manual` 현행).
- 고아 거래를 날짜·티커로 다시 잇는 자동 복구(relink #147 조건과 다름).

## 4. 감지 규칙(순수 함수, `computeDiff` 결과만 사용)
후보 = 아래를 모두 만족하는 (A, 행) 쌍
1. 행: 주식 맞추기, 상태 `add`·`change`·`same`(needs 제외), 증권사 B 확정.
2. A: `diff.kept`에 있음(이번 장 범위 밖 = A 증권사 화면을 안 올림), `tickerKey` 같음, **category 같음**(국내 일반·ISA·IRP·연금·해외 각각 — ISA·연금 세제 계좌를 일반으로 합치지 않게, CEO '시장'의 좁은 해석), 증권사 지정됨이고 `sameBroker(A, B) = false`, unlisted 아님.
3. 같은 tickerKey·category로 위 A가 정확히 1개, B 화면 행이 정확히 1개.
- 쓰는 필드: id·tickerKey·category·broker. 증권사는 사용자 수정 필드지만 결과는 질문뿐이고 기본 미체크라 허용(CEO 조건 1·C36).
- A 증권사 화면도 같이 올려 A의 X가 '○○ 화면에 없는 종목'(삭제 후보)에 있으면 카드 대상이 아니다. 그 체크 삭제는 결함 수정 규칙(7장)을 따른다.

## 5. 적용 경로
| | 경로 ① 이어받기 | 경로 ② 합치기 |
|---|---|---|
| 조건 | B 행 = 추가 | B 행 = 변경·그대로(B 종목 저장돼 있음) |
| 남는 id | A.id(카드로 체크한 쌍은 순위로 고르지 않고 **A로 고정**) | B.id |
| 증권사·계좌 | broker=B, category=화면 | B 그대로 |
| 수량·평단 | 화면 값(현행 evaluateLink) | 화면 값(현행) |
| 매수일 | A 그대로 | min(A, B) |
| 거래 stockId | 재작성 0 | A.id → B.id |
| Loan.linkedStockId | 0 | A.id → B.id |
| 매입 환율·메모·비활성 | A 승계(현행) | B 그대로 |
- 경로 ① 정정: `pickPredecessor`(apply.ts:132-141)는 지금도 증권사가 달라도 이어받는다(순위만 낮음). 따라서 '증권사 다름 허용 확장'은 새 허용이 아니다. 바뀌는 것은 체크한 쌍을 순위 대신 A로 고정하는 것뿐이다(다른 장에서 같은 티커를 함께 지울 때 엉뚱한 종목을 이어받지 않게). developer는 이 내용을 tech 메모로 dev-notes에 남긴다(CEO 7절 ③).
- 순자산 변화: ① 화면 수량 차이분만(대개 0). ② −(A 평가액)(이미 두 번 잡혀 있던 몫을 걷어냄).
- '자산 사이에 옮긴 돈' 상쇄: **대상 아님**(돈이 오가지 않았다). ①은 원인 변화 0, ②는 현재 맞추기 삭제와 같은 경로(직접 수정분 → 주식 매도·시세)로 잡히며 '기록 안 된 변화'로 잡히면 FAIL.

## 6. 질문 카드
- 위치: 미리보기 화면 요약 줄 바로 아래, 증권사별 묶음보다 위. 접힌 목록 밖. 후보 A는 접힌 '다른 증권사 종목' 목록에서 **뺀다**(같은 항목에 체크 칸 2개 금지).
- 제목 `같은 종목이 다른 증권사에도 남아 있어요`
- 설명 `증권사를 옮겼다면 체크해 주세요. 체크한 종목은 지우고, 그 거래 기록은 {B} 종목으로 옮겨요.`(다음 행동 명시)
- 행(체크박스, 기본 해제): `{종목명}` / 보조 `{A} {수량}주 → {B}`. 체크 시 라벨 `옮김`, 해제 시 `유지`.
- 요약 줄 건수: 체크 1건 = 변경 1(삭제로 세지 않음). 결과 화면: `{B}로 옮긴 종목 N개 · 이은 거래 M건`(M=재작성 거래 수, ①은 A의 거래 수를 그대로 셈).
- 후보 0이면 카드 DOM 0(현행 화면과 diff 0). 코인 맞추기에서는 그리지 않는다.

## 7. 저장·되돌리기·결함 수정
- handleApply: 저장 직전 `getAssetData()` 최신본으로 다시 계산 → `{ ...fresh, stocks, transactions, loans }`를 `saveData` 1회. 실패 시 전부 미저장(토스트 현행).
- 거래 정리(결함): 체크로 실제 지워지는 종목(이어받기·이관 생존 id 제외)에 `planDeleteStocks`와 같은 규칙 적용 — 평가액 0 이하 보존(C24), 닫힌 달 연결 짝 보존(`keepClosedMonthLinked`). 함수를 재사용하고 새로 쓰지 않는다. 대출 `linkedStockId`는 직접 삭제와 같게 둔다(현행 직접 삭제도 건드리지 않음).
- 되돌리기: `buildUndoEntries`를 stocks·transactions·loans 세 번 합쳐 `undoRef`에 넣고 기존 `planUndo`로 처리(tech-review §4안 채택 — relink undo pack과 같은 방식, 구조 신규 0). `buildUndoEntries`의 `coll` 타입에 `"loans"`만 더한다(overwrite-guard `OverwriteColl`은 이미 loans 포함). `planUndo` 주석 '거래 배열은 그대로'는 갱신. 결과 화면 버튼·닫은 직후 토스트 두 곳(현행). 맞춘 뒤 직접 고친 항목은 건너뜀(R1, 현행).
- 화면 상태: 적용·되돌리기 성공 시 `trade-view-store`·`stock-page-store`의 `groupStockIds`·`initialStockId`에서 없는 id를 걸러내고, 비면 `clear()`.

## 10. 엣지 케이스
- 빈 데이터·첫 사용자: 기존 종목 0 → kept 0 → 카드 0.
- 일부 갱신(장 실패·증권사 미확정): 확정된 행만 후보. 실패 장이 있어도 카드는 체크해야만 동작.
- 오래된 데이터: A가 오래전 매수일·거래 다수여도 규칙 같음. 거래정지·상장폐지 A도 후보(체크하면 정리).
- A 수량 0·평가액 0: 후보. ②에서 거래는 옮겨지므로 C24 보존과 충돌 없음.
- 분할 보유(진짜로 두 곳에 나눠 가짐): 체크 안 하면 현행.

## 11. 완료 기준(qa)

3. 다른 기기에서 A를 동시에 고친 뒤 '덮인 변경 되돌리기': 고아 0, A 부활 시 거래는 B를 가리켜도 앱 오류 0(상태 기록).

## 12. 대표에게 보여줄 결정 요약
증권사를 옮긴 뒤 새 증권사 화면으로 맞추면 옛 증권사 종목이 남아 순자산에 두 번 잡히던 문제를 고칩니다. 맞추기 확인 화면 맨 위에 '같은 종목이 다른 증권사에도 남아 있어요' 질문이 뜨고, 기본은 체크 해제라 체크한 종목만 정리됩니다. 정리할 때 옛 종목의 거래 기록을 새 증권사 종목으로 옮기므로 기존 기록의 연결 값을 다시 씁니다. 그래서 risk:high로 대표 승인을 받습니다. 저장 형식과 동기화 형식은 바뀌지 않고, 결과 화면에서 바로 되돌릴 수 있습니다(거래 포함). 같은 릴리스에서 맞추기로 지운 종목의 거래가 남아 결산 원인에 더해지던 결함도 직접 삭제와 같은 규칙으로 고칩니다. 옛 종목이 2개 이상인 경우와 코인은 다음으로 미룹니다. 이미 남아 있는 예전 고아 거래는 이번에 자동 정리하지 않습니다. 알려진 한계: 이관을 아직 동기화하지 못한 다른 기기(옛 버전·새 버전 모두)에서 옛 종목으로 기록한 거래, 또는 그런 기기가 이관을 덮은 뒤 '덮인 변경 되돌리기'를 하면, 그 거래는 연결이 끊긴 채 남을 수 있습니다(거래 1건당 1건, 기록은 삭제되지 않고 데이터·백업에 남음 — qa 5.156-qa-report 7·8절 실측). 그런 기기가 이관 전 모양을 먼저 올리면 원격 우선으로 이관이 취소될 수 있고, 다시 맞추면 됩니다.
