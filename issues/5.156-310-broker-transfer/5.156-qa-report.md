## 7. 구버전(main 빌드) 기기 혼재 동기화 — 고아 건수
병합 함수(`reconcileAdditiveMerge`·`collectAssetIds`)는 diff 밖이라 main 빌드 기기와 같다. 이 함수들로 시나리오 재현(독립 vitest).
| 시나리오 | 결과 |
|---|---|
| 구 기기(동기화 상태)가 이관 후 데이터를 pull | A 사라짐·거래 B, 고아 **0** |
| 구 기기에 A.id로 쓴 **미동기 새 거래 2건**이 있고 pull | 되살아나 고아 **2건**(1건 = 고아 1) — spec 알려진 한계 재현. 정상 거래는 데이터에 남고 연결할 종목이 없음 |
| 신 기기(이관 완료)가 구 기기 push(이관 전 모양, B에 새 거래 포함)를 pull | 원격 우선으로 **A·거래 A 연결이 복귀**(이관이 사실상 취소됨), 고아 0, B 새 거래 보존. 신 기기의 덮인 변경은 8절 되돌리기로 복구 가능 |
| 신 기기 로컬에 미동기 새 거래(b)가 있고 같은 구 push를 pull | 새 거래 보존, 고아 0 |
- 같은 한계는 **구버전만이 아니다**: 이관을 아직 pull하지 않은 모든 기기(신버전 포함)에서 A로 쓴 미동기 거래는 같은 방식으로 고아가 된다. 결정 요약 문장은 "이관 전 버전의 다른 기기"로 한정돼 있다(R1).

## 9. 권고·관찰 (FAIL 아님)
- **R1(권고, 대표 결정 요약 보완)**: 12장 마지막 문장을 "이관을 아직 동기화하지 못한 다른 기기(옛 버전 포함)에서 A로 기록한 거래, 또는 그런 기기가 덮은 뒤 '덮인 변경 되돌리기'를 하면 그 거래가 연결 끊긴 채 남을 수 있습니다"로 넓힌다. 측정: 미동기 새 거래 n건 = 고아 n건.
- **O1(경미)**: 카드 보조 줄 `거래 기록 N건`은 화면 메모리(assetData)의 보존 기간(3년, `pruneTransactions`) 안 거래만 센다. 3년보다 오래된 거래가 A에 있으면 카드는 1건, 결과 줄은 2건(실측 재현: 2023-02-03 거래 포함 시 카드 1건·결과 2건). 보존 기간 밖 거래는 앱 어디서도 보이지 않으므로 사용자 영향 미미, 수정 불필요.
- **O2(이번 diff 밖, main 실측은 안 함)**: 맞추기를 `자산 업데이트` 시트에서 시작해 닫으면 시트가 다시 열리고, 그 위의 토스트 `되돌리기` 버튼 좌표에서 `elementFromPoint`가 시트 행 버튼을 반환(실제 마우스 클릭이 토스트에 닿지 않음). `handleClose`·토스트 코드는 이번 diff에서 변경 0이라 기존 동작으로 판단한다. 결과 화면 `되돌리기` 버튼은 정상. 토스트 핸들러 자체(DOM click)는 세 컬렉션을 원복함을 확인.
- O3: 코인 맞추기 체크 삭제 거래는 여전히 정리되지 않음(spec 범위 밖, dev-notes에 명시).
