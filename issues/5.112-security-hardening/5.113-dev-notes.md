# 5.113 dev-notes (developer, 2026-11-14)

브랜치 `issue-5.113`(origin/main 4194474 기준, PR 미생성). 5.112(PR #216)와 cache-storage.ts가 겹치면 먼저 머지된 쪽을 origin/main merge로 해결한다.

## 변경 요약
1. **IP 미저장**: `rl:*:ip`·`rl:legacy`·Gemini ip/pool-ip Redis 키 0. IP는 L1 메모리 버킷 키로만(`rl-mem:`, 창 ≤1분, 최대 5000개, 로그·Redis 0). `guardRateLimit`은 메모리 판정으로 전환(창>1분 라우트 feedback·push는 분당 환산 최소 3회 — 인스턴스별 한도라 이전보다 느슨, 한계 참고). `checkRateLimit` 삭제.
2. **대체 한도**: sync PUT = 인증 전 L1 60/분 → 서명 통과 후 금고 id별 20/분(`rl:sync-put:{id}:{분}`) → 신규 금고 일 전역 1000(`rl:sync-new:global:{날짜}`). share POST 일 전역 5000. Gemini = L1 분당 5 + 시간당 전역 150(`rl:gemini:global:{KST시}`) + 일 1500 유지 + 기기 30(기존 `use-gemini-usage`, 변경 없음). /ratio 풀 일 60 유지(IP별 5 제거), HEAVY 70% 차등 제거.
3. **푸시**: TTL 30일, HKDF 키 분리(`2:` 접두 + 파생 AES 키, 신 subId), 구 형식 이중 읽기, subscribe 시 신 id 저장 + 구 id 삭제, DELETE는 신·구 모두 삭제, push/test는 구 id 폴백, cron은 읽은 구독마다 `capLegacyPushTtl`(구 형식이면 TTL을 min(남은, 30일)로 1회). rewrap 생략.
4. **C26**(별도 커밋): pwa-install-flow '안전하게 전송' → '열기 위한', cloud-sync-menu-entry '안전하게 전달' → '암호화해 옮기고'.

## reconcilePush 확인 결과
`push-host.tsx:34`가 앱 로드마다 `reconcilePush()` 호출 → 로컬 on이면 구독 유무와 무관하게 `/api/push/subscribe` POST(재등록). 앱을 여는 활성 사용자는 자동으로 신 id·`2:`·30일로 이행되고 구 레코드는 삭제된다. 열지 않는 사용자는 cron의 EXPIRE 축소(30일)로 자연 소멸. 구 경로(`pushSubIdLegacy`·구 블롭 읽기)는 이행 30일 경과 후 다음 릴리스에서 제거.

## 스키마·데이터 영향
localStorage·STORAGE_KEYS 변경 0, 서버로 나가는 값 증가 0(금고 id는 기존 가명 id). 서버 저장 형식: 푸시 sub id·blob 형식 변경(이중 읽기로 하위호환). 롤백 시 구 코드는 신 레코드를 못 읽어 알림 구독 일시 중단(재구독 필요, 자산 데이터 무영향).
