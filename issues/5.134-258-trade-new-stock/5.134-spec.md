# 4.xx #258 처음 사는 종목도 거래로 기록 — spec

작성: planner-designer · 2026-11-20(challenge C1~C9·business 보완 반영, design-review: ui.md 충돌 2건·#259(C5) 반영) · 기준 `origin/main` 1aaeb62, 릴리스 `origin/issue-5.134` 1707b6b · 방향 `4.xx-direction.md` · 판정 `4.xx-challenge.md`

## 1. 문제
`거래 입력 › 직접 입력`의 종목 목록은 보유 종목뿐이다(`trade-input.tsx:191·466`). 처음 사는 종목을 기록하는 경로는 `주식 추가`와 `스크린샷 거래 가져오기`(미보유 매수를 새 종목으로 만듦, `trade-screenshot-import.tsx:211·267~308`) 두 가지인데, **둘 다 연결 계좌를 고를 수 있는 경로가 없다.** 그래서 산 돈이 현금·대출에 반영되지 않아 순자산이 부풀고 결산에 `기록 안 된 변화`로 잡힌다. 보유 0개면 거래 입력이 막다른 길이다.

## 2. 목표 행동
처음 사는 종목을 거래 입력 한 창에서 검색 → 매수 기록하고, 고른 통장·대출에 같은 저장으로 반영한다.

## 3. 범위
- 주식 수동 거래 입력(FAB 진입, `lockedStock=false`)의 매수. 국내·IRP·ISA·연금(KRW, 검색 시장 `kr`), 해외(USD, `us`). 제외는 direction 1절 그대로.
- **코인 제외 근거(C1)**: 28일 GA(`_discovery/2026-11-19-ga28-analysis.md` 2절, #250 direction·proxy-review-business 같은 판독) 화면 기기 수 `상세·주식` **10** vs `상세·코인` **0**(표에 행 없음). 코인 쪽이 가장 흔한 사용 형태가 아니다. 거래 입력 title 기기 수(`거래 입력·주식` vs `거래 입력·암호화폐`) 28일 값은 **숫자 없음**(memory에 판독 기록 없음). → **C1: 화면 기준 충족, 거래 입력 기준 미충족.** 11/25 title CSV에서 두 값을 적고, `거래 입력·암호화폐` ≥ `거래 입력·주식`이면 CEO가 코인 제외를 다시 판정한다(development 진행은 막지 않음, 결과는 이 절에 추가).
- 코인 거래 폼은 안내 1줄만(AC-13).
- **#259 동승(qa 운영 결함 확정 C5, `4.xx-qa-c5-check.md`)**: `신규 자산 등록`에서 보유와 같은 증권사·종류를 고르면 중복 stock이 생기는 main 결함을 **거래 입력 직접 입력·스크린샷 거래 가져오기 두 호출부 모두** 같은 릴리스에서 고친다(AC-17). direction 3절 '스크린샷 거래 가져오기 그대로'의 예외는 이 결함 수정 1건뿐(방향 변경 아님). `주식 추가` 경로는 범위 밖(10절).

## 4. 사용자 흐름
1. FAB › 거래 › 주식 › `직접 입력`.
2. 보유 1개 이상: `종목` 칸 아래 `다른 종목 찾기` 버튼. 보유 0개: `종목` 칸 자리에 검색이 바로 열림.
3. 검색 위 `국내`·`해외` 2칸(기본: 카테고리 필터가 해외면 해외, 그 밖은 국내) → 이름·코드 입력 → 결과(이름·코드·시장).
4. 결과를 고름 → 정규화 티커가 보유와 같으면 기존 `종목` 선택으로 전환하고 안내 1줄(AC-4). 아니면 고른 종목 요약(이름·코드) + `StockTargetPicker`가 `신규 자산 등록` 선택 상태로 열림 → 증권사·종류(시장별 허용 목록, AC-5a).
5. 수량·체결 단가·(해외) 체결 환율·체결일 → 즉시 반영은 켜진 채 잠김(기존 신규 동작).
6. `연결 계좌`(체결일이 이번 달일 때, 기존 규칙)에서 통장·대출 선택 → 미리보기.
7. `매수 기록` → 저장 1회 → 토스트(기존 `linkSavedToast` 또는 `매수 거래가 기록되었습니다.`) → 창 닫힘 → 상세·주식에 새 행.

## 5. 수용 기준 (qa가 그대로 검사)
- AC-1 보유 1개 이상, 매수 상태에서 `종목` 칸 아래 `다른 종목 찾기`가 보이고, 누르면 검색 입력이 열린다. 매도 상태에서는 버튼이 없다.
- AC-2 보유 0개(delisted만 있는 경우 포함)면 `종목` 선택 칸 대신 검색이 처음부터 열려 있고, 빈 Select는 보이지 않는다.
- AC-3 검색 결과를 고르면 `신규 자산 등록`이 선택된 채 증권사 Select가 보이고, 증권사를 고르기 전 `매수 기록`을 누르면 기존 문구 `신규 자산의 증권사를 선택하세요.`로 막힌다.
- AC-4 (C4) 고른 결과와 보유 종목(delisted 제외, **카테고리 필터와 무관하게 전체 보유**)을 **양쪽 모두 `normalizeTicker`(카테고리 반영, `finance-service.ts:147`)를 거친 값으로** 비교해 같으면 새 항목을 만들지 않고 기존 종목 선택과 같은 상태(보유 항목 카드 + `신규 자산 등록`)가 된다. qa 픽스처에 보유 `005930.KS`(국내)·소문자 미국 티커(`aapl`, 해외)를 넣고 검색 `005930`·`AAPL`이 보유 쪽으로 전환되는지 본다. 전환 시 그 종목이 카테고리 필터에 가려지면 필터를 `전체`로 되돌려 `종목` Select에 이름이 보인다(빈 Select 0). 자산 항목 기본 선택은 기존 규칙(후보 1개면 자동, 2개 이상이면 미선택). 전환 직후 `trade-switched-existing-note`(`data-reason="ticker"`)에 **AC-17과 다른** 1줄 `이미 가진 종목이라 보유 종목에서 골랐어요`가 보인다(ui.md 확정 문구 우선, 뜻은 '이미 가진 종목으로 바꿨다').
- AC-5 해외 검색으로 고르면 통화 USD, 체결 단가 `(USD)`·`원화로 입력`·`체결 환율` 칸이 기존 해외 종목과 같게 보인다.
- AC-5a (C6) 검색 경로의 종류 Select는 국내 검색이면 국내·IRP·ISA·연금 4개, 해외 검색이면 해외 1개만 보인다. 비상장은 없다. `StockTargetPicker`에 허용 종류 목록 prop을 추가해 넘기고, prop이 없으면 지금처럼 전체(상세 진입·스크린샷·기존 같은 종목 경로 화면 diff 0).
- AC-6 연결 계좌를 고르고 저장하면 `assetData` 한 번의 저장으로 ① 새 stock(수량=입력 수량, 평단=체결 단가, purchaseDate=체결일, positionSource=computed) ② 거래 1건(reflected=true) ③ 짝 기록 1건 ④ 계좌 잔액(현금 −금액 / 대출 +금액)이 모두 들어간다. 해외+원화 계좌는 체결 환율 환산 금액(#119와 같음).
- AC-7 `연결 안 함`으로 저장하면 ①②만 들어가고 현금·대출은 그대로다.
- AC-8 연결 계좌 오류(잔액 부족·1원 하한·환율 없음)면 저장되지 않고 새 stock도 생기지 않는다(기존 오류 문구·위치 그대로).
- AC-9 (C7) 현재가 조회 실패 시에도 저장된다. 새 stock의 currentPrice = 유효 체결 단가(USD 환산 후)이고 **`baseDate`는 비운다**(오늘 날짜를 넣지 않음). 요약 아래 `현재가를 못 가져와서 체결 단가로 먼저 표시해요` 1줄. 다음 시세 갱신에서 현재가로 바뀐다. 체결일이 지난달 이전이어도 안내 줄이 보이는지 확인.
- AC-10 (C8) 결산 단언(C42·C143): 픽스처 ⓐ 처음 사는 국내 종목 + 원화 통장 연결 ⓑ 처음 사는 해외 종목 + 원화 통장 환산 ⓒ + 대출 연결 ⓓ 연결 안 함. ⓐ~ⓒ는 월 결산·홈 원인에 `주식 매수`·`신규 현금`·`기록 안 된 변화` 줄 없음(Σ원인=Δ순자산, 같은 달 시세 변동만), ⓓ는 기존 `주식 추가`와 같은 원인 분류. 원인 엔진(effects) diff 0이므로 **#258 첫 커밋 직전 `issue-5.134` head**(developer가 dev-notes에 SHA 기록, 11/20 기준 1707b6b) 대비 주·월·연 causes 동일 단언. main과 비교하지 않는다(#251이 원인 분류를 옮김). 결산 단언 테스트는 #251과 별도 파일·describe로 둔다.
- AC-11 거래 삭제(상세·주식 거래내역): 기존 신규 자산 경로와 같은 되돌림(짝 기록 삭제·잔액 역가감). 되돌림 로직 diff 0.
- AC-12 `주식 추가` 화면의 검색은 공용 컴포넌트 교체 뒤에도 동작·문구·키보드(↑↓·Enter·Esc)가 같다(화면 diff 0, 기존 F-STOCK 회귀).
- AC-13 (C2) 코인 거래 폼 코인 칸 아래 안내 1줄(상세 진입 locked일 때는 없음). 보유 0개면 빈 Select 대신 이 줄만. 문구 기본안 `처음 사는 코인은 '암호화폐 추가'로 등록해요. 산 돈은 현금에서 따로 빼 주세요`(현금 결과 포함). **320폭 2줄 이하**가 목표이고, 넘치면 짧은 안 `새 코인은 '암호화폐 추가'로 등록해요. 현금은 따로 빼 주세요`. 확정은 ui-designer(ui.md). 금액 예시·`자동` 금지. **design-review 추가**: 문구는 실제로 누르는 진입 이름(FAB `보유 현황 업데이트` › `암호화폐`)과 '산 만큼 현금을 줄인다'는 뜻을 담아야 한다(다이얼로그 제목 `암호화폐 추가`만으로는 찾아갈 수 없음). 둘을 지키느라 320에서 2줄을 넘으면 3줄까지 허용(뜻 우선).
- AC-14 상세 진입(종목 고정)·스크린샷 거래 가져오기 화면 diff 0. 예외 2건만 허용: ① AC-17(#259) 안내 줄과 실효 대상 판정 ② `StockTargetPicker` 신규 자산 등록의 증권사·종류 2칸이 **359px 이하에서만 1열**(`max-[359px]:grid-cols-1`, 360px 이상은 지금 그대로 2열). ②는 두 호출부에 함께 나타나며 320에서 `증권사 선택`이 잘리지 않는다.
- AC-15 (C3) 새 화면·새 소식·안내 문자열에 `연동`·`자동`·`동기화`·`추천`·`인기`·금액 예시 0, **이미 등록한 종목을 다시 적으라고 권하는 문장 0**. 보이는 표기 전수표(C139) 첨부.
- AC-16 320·360·390 폭에서 검색 결과 행·요약 줄·코인 안내 줄·AC-4/AC-17 안내 줄이 넘치거나 겹치지 않는다. 히트영역 40px 이상. 359px 이하 picker 신규 2칸은 1열, 360·390은 2열.
- AC-17 (C5·#259) `신규 자산 등록`에서 고른 증권사·종류가 **같은 종목 보유 항목**(거래 입력: 같은 정규화 티커 그룹 `groupCandidates` / 스크린샷: 해당 행의 비유사(fuzzy 아님) 후보)의 broker·category와 같으면 그 행의 **실효 대상은 그 기존 항목**이다. 증권사 빈 값은 비교하지 않는다.
  - 화면: 신규 칸(증권사·종류 Select)은 **접지 않고 열린 채** 두고(종류를 바꿔 다른 조합을 바로 고를 수 있게 — 종류 기본값이 보유와 같아 증권사만 고르면 바로 일치하는 함정 방지), 그 아래 안내 1줄 `trade-switched-existing-note`(`data-reason="account"`) `같은 증권사·종류의 항목이 있어서 그 항목에 이어서 기록해요`. 증권사나 종류를 바꿔 일치가 풀리면 안내도 사라지고 다시 신규다. 스크린샷은 행마다 같은 문구(그 화면의 기존 안내 줄 크기).
  - 동작: 미리보기(반영 후 예상 포지션)·같은 거래 중복 검사·저장은 그 기존 항목을 고른 것과 같다(`addTransactionsBatch`에 newStocks 0건, 거래의 stockId=기존 항목). 거래 입력의 즉시 반영은 신규 칸이 선택된 동안 지금처럼 켜짐 잠금. GA `trade_new_stock*` 미전송.
  - 판정은 두 호출부가 공유하는 순수 함수 1개(`src/lib/trade/`)로 하고, 저장 함수·picker의 기존 props 의미는 바꾸지 않는다(picker 변경은 `allowedCategories?`·359px 1열뿐).
  - 검사: 거래 입력·스크린샷 각각 같은 조합 저장 뒤 같은 ticker·broker·category stock 수 1개, 거래는 기존 항목에 붙고 수량 합산. 스크린샷 한 배치 안 같은 조합 신규 2건은 지금처럼 1개로 묶인다(회귀). 유사 후보(fuzzy)만 있는 행은 판정하지 않는다(다른 종목일 수 있음).
