## 4. ui.md 수정 요청
1. **AC-17 상태 D: 신규 칸을 접지 말 것.** 현재 D는 일치하면 보유 카드를 선택하고 신규 2칸을 접는다(목업 `f`). 종류 기본값이 보유 종목의 종류(`groupRep.category`, 스크린샷은 인식 기본값)라 **증권사만 고르는 순간 바로 일치해 칸이 사라진다.** 같은 증권사 ISA처럼 다른 종류로 새로 만들려는 사람은 다시 `신규 자산 등록`을 눌러 종류부터 골라야 하는 함정이다. → 신규 칸은 열린 채, 아래 안내 1줄(문구 유지 `같은 증권사·종류의 항목이 있어서 그 항목에 이어서 기록해요`), 종류·증권사를 바꿔 일치가 풀리면 안내도 사라짐. 미리보기는 그 기존 항목 기준(spec AC-17). 스크린샷 화면 행 안내(기존 `text-2xs` 안내 줄 크기)도 상태표에 추가. 목업 `f0→f` 교체.
2. **상태 D1(AC-4) 안내 문구를 D와 분리.** 검색에서 이미 가진 종목을 고른 경우는 증권사·종류를 아직 고르지 않았으므로 `같은 증권사·종류의 항목이 있어서…`는 뜻이 틀리다(C139). → 별도 1줄, 기본안 `이미 가진 종목이라 보유 종목에서 골랐어요`(`data-reason="ticker"`). 또 D1의 "보유 카드 선택"은 기존 규칙(후보 1개만 자동, 2개 이상은 미선택)으로 고치고, 그 종목이 카테고리 필터에 가려지면 필터를 `전체`로 되돌리는 상태를 추가(spec AC-4).
3. **코인 안내 문구가 실제 진입 이름을 가리키게.** `암호화폐 추가`는 다이얼로그 제목일 뿐, 사용자가 누르는 경로는 FAB `보유 현황 업데이트` › `암호화폐`(`floating-add-button.tsx:363·36`)다. 거래 창에서는 `암호화폐 추가`라는 버튼을 찾을 수 없다. 또 `현금은 직접 줄여 주세요`는 무엇을 얼마나 줄이는지가 빠져 있다(C139). → 뜻 기준안 `새 코인은 보유 현황 업데이트 › 암호화폐에서 등록해요. 산 만큼 현금을 직접 줄여 주세요`. 320 2줄을 넘으면 ui-designer가 줄이되 **진입 이름과 '산 만큼'은 유지**, 넘치면 3줄 허용(AC-13 목표보다 뜻 우선). 인용부호 없이 어절 측정(C114).
4. **시장 표기 통일.** 결과 행은 API 원문(`KOSPI`·`NASDAQ` 등), 요약 카드 목업은 `005930 · 국내`로 서로 다르다. → 요약도 결과 행과 같은 API 값(없으면 `국내`/`해외`)으로 통일하고 전수표 1행 갱신. 같은 종목이 고르기 전후로 다른 시장 이름이 되면 안 된다.
