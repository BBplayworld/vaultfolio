## 1. 경험 (planner-designer)

### 누구의 어떤 문제
상세·주식에서 거래를 기록하는 고정 사용자. `거래 입력 › 직접 입력`의 종목 목록은 **보유 종목뿐**이다(`trade-input.tsx:191` `tickerReps = stockGroups`, `:466` SelectItem). 처음 사는 종목은 고를 수 없어서 `주식 추가`로 먼저 등록해야 하고, 그 경로에는 연결 계좌가 없다. 결과: 산 돈이 현금·대출에서 빠지지 않아 순자산이 산 금액만큼 부풀고, 결산에 `기록 안 된 변화`로 잡힌다. 4.63에서 "국내·해외 공통 입력 경로 결손"으로 남긴 한계이고(4.63-spec 83행), 대표 지적(4.52) "매수도 현금이나 대출로 산다"의 마지막 빈칸이다.
- 보유 종목이 0개인 사용자는 FAB `거래 › 주식`에서 빈 목록만 보고 막힌다(카테고리 칸도 숨음, `:437`). 막다른 길.

### 흐름 전 → 후 (창 3번 → 1번)
- 전: FAB › 거래 › 주식 › 직접 입력 → 종목 목록에 없음 → 창 닫기 → ② FAB › 주식 추가(매수일 기본 1/1, 연결 계좌 없음) → ③ 현금 화면에서 잔액 직접 맞춤.
- 후: FAB › 거래 › 주식 › 직접 입력 → 종목 아래 `다른 종목 찾기` → 이름·코드 검색 → 고르면 대상이 새 항목(증권사·종류 선택)으로 정해짐 → 수량·단가·체결일 → `연결 계좌`에서 통장·대출 선택 → `매수 기록` 1번.

### 이 기능 후 관찰 가능한 행동
1. 처음 사는 종목을 거래 입력 한 창에서 저장하고, 같은 저장으로 고른 통장 잔액이 줄거나 대출이 늘어난다.
2. 새 종목 매수가 결산·홈 원인에 `기록 안 된 변화`가 아니라 앱 안 이동(상쇄)으로 처리된다.
3. 새 종목의 매수일이 1/1 기본값이 아니라 실제 체결일로 남는다.

### 범위
- 포함: 주식(국내·해외 USD·IRP·ISA·연금) × FAB 진입. 이미 있는 저장 경로 재사용 — 신규 종목 + 거래 + 연결 계좌를 `addTransactionsBatch([tx], [], [newStock], link)` saveData 1회(C37, context:1627, 4.56부터 존재). 검색은 `주식 추가`의 종목 검색(`stock-input.tsx:212~262`, `/api/ticker-search`)을 공용 컴포넌트로 빼서 두 곳이 같이 쓴다(중복 코드 0).
- 보유 0개: 종목 칸 대신 검색이 바로 열린다(막다른 길 제거).
- 코인 거래 폼: **이번 범위에서 제외, 화면에 이유 1줄**(아래).
- 줄일 수 있는 것(합친 것): 새 화면·새 진입점 0. `신규 자산 등록` 카드(같은 종목 다른 증권사)와 증권사·종류 선택 UI를 그대로 쓴다. 현재가를 못 가져오면 별도 차단 없이 체결 단가로 임시 채움(코인 스크린샷 선례, qa-full-test-plan 144행).
- 하지 않을 것: `주식 추가`(보유 옮겨 적기)에 연결 계좌 붙이기(이중 차감, 4.63 challenge). 매도 신규(현행 금지 유지). 비상장 검색(검색·시세 불가, 기존 `주식 추가`로). 상세 진입(종목 고정) 변경. 종목 추천·인기 목록·최근 검색 저장. 스키마·저장 키·동기화·서버 전송 변경. JPY 신규 종목(직접 추가도 해외=USD뿐).

### 코인 대조 결과 (범위 판정)
`crypto-tx-input.tsx`도 같은 한계(`:268~276`, `:271` 목록 = 보유 코인뿐)지만 **사정이 더 크다**: 거래 폼에 신규 대상 경로 자체가 없고(`addCryptoTransactionWithPosition`은 기존 코인 패치만, context:1791), 코인 검색 API도 없다. 넣으려면 새 원자 저장 함수(코인 생성+거래+짝 기록)와 거래소 선택·검색을 새로 만들어야 해 규모가 2배, 저장 로직 변경으로 위험도도 오른다. 주식은 저장 로직 변경 0으로 끝난다. → v1 제외. C49에 따라 코인 거래 폼 종목 칸 아래에 `처음 사는 코인은 '암호화폐 추가'로 먼저 등록해 주세요` 1줄을 둔다(보유 0개 막다른 길도 같이 해소). 코인 신규 거래는 후속 후보로 STATE에 올린다.

### 바뀌는 곳 / 그대로인 곳
- 바뀜: 거래 입력 직접 입력의 종목 칸 아래(검색 진입·검색·고른 종목 요약), 보유 0개일 때 종목 칸, 코인 거래 폼 안내 1줄, `주식 추가` 검색부(공용 컴포넌트로 교체, 화면 diff 0).
- 그대로: 스크린샷 거래 가져오기, 상세 진입(locked), 연결 계좌 행·미리보기·오류(4.56·4.63), 즉시 반영 강제(신규), 중복 검사 생략(신규), 결산·홈·성과 화면.

### 정보 구조 — 지표 대조
새 지표·블록 0. 새로 보이는 값은 검색 결과(이름·코드·시장)와 고른 종목 요약(이름·코드·현재가)뿐이고, 정본은 상세·주식 행이다. 저장 뒤에는 기존 상세·주식 행 1곳에만 나타난다(중복 블록 없음).

## 2. 사업 (business-pm 후보 문서 요약)
- 기여: 신규 유입이 아니라 **핵심 사용자(상세·주식, 28일 10기기·앱 안 시간 51%)의 정확성·유지**. 정직한 크기는 '중간 이하'(10월 거래 저장 3명).
- 왜 지금: 12월 월 결산·올해 결산(#237, 12/27~1/10) 전에 새 매수가 순자산을 부풀리지 않게. 홈·웰컴·체험 판독 창과 겹치지 않아 ≤12/5 머지 가능.
- 성공 지표(머지 후 4주, 익명 기기 절대 수): ① `거래 입력·주식·새 종목` 2기기 이상 ② 그중 `거래 저장·계좌 함께 반영` 1기기 이상. 가드레일: `거래 입력·주식`·`상세·주식` 기기 수 불감소.
- 철거 조건: 4주 0기기 → 8주 재판독, 그때도 0이면 `다른 종목 찾기` 진입 철거(검색 공용화는 유지).
- 동승 p2(별도 spec 절 없음, 후보 문서 B·C): `/asset` 서버 리다이렉트, 상세·주식 행 겹침 정돈.
- 하지 않으면 잃는 것: 연말 새 매수가 결산 '순유입·기록 안 된 변화'를 틀어 결산 신뢰가 깨진다.
