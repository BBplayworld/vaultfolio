# 4.xx #258 결함 확인 C5 — 신규 자산 등록 중복 stock (qa, 2026-11-20)

판정: **결함 확정 (main 운영 실측 재현)** · 심각도 중(P2) · 데이터 손실 없음, 표시·집계 왜곡·정리 부담

## 1. 코드 근거 (origin/main)
- `forms/trade/stock-target-picker.tsx` 신규 자산 등록: 증권사 Select는 `securitiesFirms`, 종류 Select는 `stockCategories` 전체를 그대로 보여 준다. 선택값이 `candidates`(보유)와 같은지 비교하는 코드가 없다(onChange가 `{kind:"new",broker,category}`를 그대로 올림).
- 호출부 2곳 모두 같은 picker를 쓰고 `allowNew`는 매수일 때 true:
  - `trade-input.tsx:480` 직접 입력(`:324~334` 주석 "중복 검사 대상 없음"): `stock_${Date.now()}`로 새 Stock을 만들어 `addTransactionsBatch([finalTx],[],[newStock],link)` 저장. 같은 ticker·broker·category 보유 여부 검사 없음. (`:370` 중복 검사는 같은 거래 중복만 보며 신규 경로는 `:326`에서 먼저 return)
  - `trade-screenshot-import.tsx:481` 스크린샷 가져오기: 후보 0개일 때만 자동 new(`:217`)이지만, 후보가 있어도 사용자가 picker에서 신규 자산 등록을 고를 수 있다. 저장은 `newlyCreated`→`newStocks`→`addTransactionsBatch(txs,patches,newStocks)`(`:332~348`), 검사 없음. 같은 배치에서 신규 2건이 같은 조합이면 `newlyCreated` 키 구성에 따라 동일 영향(미실측).
- 저장 함수는 신규 Stock을 그대로 append한다.

- 절차: 상세 > 주식 > 거래 입력(`trigger-add-trade`) > 직접 입력 > 종목 삼성전자 > 거래 유형 매수 > 자산 항목 `신규 자산 등록` > 증권사 토스증권·종류 국내주식 > 수량 3·단가 70,000 > 매수 기록. 이 절차를 2회 반복(데모 보유 증권사 `데모증권`은 목록 밖이라 1회차로 실제 증권사 항목을 먼저 만든 뒤 같은 조합을 한 번 더 선택).

## 3. 영향
- 재현 진입: 거래 입력 직접 입력, 스크린샷 가져오기 두 곳(둘 다 매수에서 신규 자산 등록 선택 시). 주식 추가(`주식 추가`) 경로는 본 점검 범위 밖.
- 데이터: 같은 ticker·broker·category의 stock 2개. 거래·수량은 보존되고 소실 없음. 하나로 합치는 기능이 없어 사용자가 수동 정리해야 함.
- 화면: 종목 묶음(그룹)에 같은 증권사 행이 2개 표시, 평단·수량은 항목별로 따로 계산되어 합산 평단이 실제와 다름. 합계(홈·주식 합계)는 총량은 맞고 이중 계상은 없음(수량 합산이므로). 결산·성과는 항목별 합산이라 총액 영향 없음, 단 종목 단위 집계·점검 차례·보유 현황 맞추기(resync)가 같은 broker 2개를 만나 오분류할 수 있음(미실측).
- 기존 사용자 영향: 있음(main 운영 상태, 사용자 실수로 발생). 신규 기능 아님.

## 4. 결론
- challenge C5 근거 확정. #258 spec에 AC-4 충족 조건(보유와 같은 증권사·종류 선택 시 기존 항목 선택으로 전환 또는 차단) 필요하며, picker 수정은 두 호출부에 함께 적용되고 저장 함수 변경 0으로 가능. 테스트는 picker 단위 + 두 호출부에서 같은 조합 선택 시 `newStocks` 0건 단언 권장.
