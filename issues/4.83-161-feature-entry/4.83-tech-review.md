## 5. 질문별 판정
**① 미니 차트 비용 — 가능, 아래 조건**
- 요청 경로: 서버는 CDN 히트면 `guardRateLimit`(10회/60초)을 지나지 않는다(route.ts는 CDN 미스 때만 도달). L1 60/분은 그대로. 병목은 **콜드 미스**: 한 번에 최대 `MAX_PAGES=4`회 KIS 호출 + `withinUpstreamBudget("kis", 4)`. 1분에 10종목 초과 펼침이면 429 → 폴백.
- 조건: (a) **펼칠 때만** `usePriceHistory(ticker,"1y", open && hasPriceFlow)` (`StockCard`의 `open` 상태 사용, 접힌 행 요청 0). 5y는 요청하지 않는다. (b) 같은 키라 종목 한 장·다른 행(같은 티커 다른 카테고리)과 dedup, `staleTime` 30분 + CDN 6시간 공유. (c) 응답 1y 일봉 ≈250점(약 8KB)은 **그리기 직전** 약 40점으로 다운샘플(마지막 점 포함). 서버 응답은 바꾸지 않는다(CDN 키·종목 한 장 공용 보존). (d) `retry:false` 유지, 429/503/빈 응답은 R-C 문구 `1년·5년 가격 흐름과 내 평단`으로 대체하고 탭은 그대로 종목 한 장 진입. (e) 첫 방문 자동 펼침(`defaultOpen = isFirst && !hasInteracted`)은 이미 있다 → 첫 종목 1건 요청은 신규 최초 방문에서만. v1 A+(별도 자동 펼침) **추가하지 않는다**(요청 증가·범위 밖, C3는 미유지 권고).
- **같은 함수(C65)**: 1년 % = `computePriceChange(points)`에 **원본 points**를 넣는다(다운샘플 후 값 아님). 평단 = `buildStockGroupHead(effectiveGroupItems, rates, displayCurrency).averagePrice`(종목 한 장과 동일). 부호·포맷은 `signedRate`·`getProfitLossColor` 재사용. 평단이 y 범위 밖이면 점선 생략(`stock-page.ts`의 domain/clamped 규칙 재사용).
- 서킷: 실패 503이 마스터 티커면 `recordKisFailure` 누적 → 행 펼침이 서킷 실패 분모를 늘린다. 종목 한 장과 같은 경로라 새 위험 종류는 아니지만 **연속 펼침 시 전 사용자 시세 서킷 영향 가능성**은 있어 qa가 운영 이상 시 `X-KIS-Unavailable` 헤더 폴백 확인(C79). 완화 필요 시 펼침 후 300ms 지연(디바운스)으로 빠른 연속 펼침 요청 억제 — 우선 미도입, 지표로 판단.

**② X-Ray 훅 이전**: `useXrayClassifications(stocks)`를 `StockToolTiles`가 호출(현재 `StockInsightStrip` 27행 위치). 토스트 `주식 X-Ray 분류가 완료되었습니다`는 훅 내부 `fetchAndStoreClassifications`(fetch-classifications.ts:156)에서 나가므로 훅만 유지되면 유지. **타일은 하이라이트 0개여도 항상 렌더**(훅이 언마운트되면 수집·토스트 정지). 주식 0건이면 타일 숨김 + 훅 호출은 `[]` 전달로 no-op. `StockXrayView`·`ShareMenu`는 자체 호출이라 영향 없음. 훅 deps가 `stocks` 참조라 타일이 상세·주식을 벗어나면 중단되는 점은 현행과 동일.

**③ 숫자 출처**
- 시장: `MarketEntryLine`의 계산(`classifyHoldings`·`useMarketIndexRefs`·`computeIndexSpan("weekly")`·`formatCompareRate`)을 훅으로 분리해 **그대로 재사용**(4.73과 동일 함수, 새 계산 0). 기존 `MarketEntryLine` 테스트의 문자열 규칙(`최근 1주 …` / 폭 <360에서 `최근` 숨김) 유지 → 타일에는 `1주 코스피 −7.8%`(접두 `최근` 제외). 값 로딩 중 타일은 숨김 아닌 고정 높이 스켈레톤.
- X-Ray: `pickHighlights(mergedStocks, exchangeRates)[0]?.label`. 분류 전이면 `분야·국가 비중`.
- 세금: `isForeignTaxSeason()` + `stocks.some(isTaxSimCandidate)` 조건 그대로. D-day = 올해 12/31까지 **KST 일수**(`todayKst()` 기반, 12/31 당일 `D-0`). 신규 유틸 `daysToYearEnd(today)`을 `tax-utils.ts`에 추가하고 단위 테스트(11/1=D-60, 12/31=D-0, 윤년 무관). 이동은 `setInitialTab("simulator")` + `navigate({type:"tax"})` 그대로.

**④ KpiCard `rows` 슬롯**: 현재 `Card` 전체가 `onClick`(중첩 버튼 불가)·`active:scale-[0.98]`. `rows`가 있으면 헤더 영역(아이콘~secondary)을 button 영역으로 분리하고 `rows`는 형제로 둔다(카드 본체 `onClick`은 헤더로 이동). `rows` 없는 기존 호출(배당·성적표·상세 허브)은 동작 무변경. 행 전체 press scale 금지(ui 5.1) → hover/active 배경. `lg:row-span-2`는 `grid-cols-2`에서 자산 변화 래퍼(`hub-card-change`)에 적용. `data-tutorial` 속성 보존 확인 필요(온보딩 튜토리얼 앵커). 허브 값: 최근 7일 = 기존 `computeAttributionView`·`weekSinceDate`(홈 Hero와 동일, `asset-change-view` 사용 방식 그대로), 월별 기록 = `readMonthlySnapshots()` 달 수, 시장 = ③의 훅. 허브 행 이동은 `init:{scope:"all",period:"week"|"month"}`, 시장 행은 `change-market`.

**⑤ `총 N주` 제거 적합 — 맞음.** `StockCard`가 받는 `stock`은 `mergeStockGroup`(222~244행) 합산본이고 접힌 행 `StockRowHeader`(323행)가 같은 `stock.quantity`를 `N주`로 표시한다. 분할 종목의 증권사별 수량은 `subItems` 타일(`detail-subitems`)에 남는다. 종목 한 장 머리의 `총 N주`(`stock-page-quantity`)는 범위 밖이라 유지. 주의: 헤더 맨 앞 줄 폭이 `총 N주` 영역만큼 늘어나므로 이름 줄 `min-w-0` 유지 확인.

**⑥ 주 탭 `recordVisit('change-week')` 누락 — 실제 버그.** `change-week` 키는 코드 어디서도 기록되지 않고(테스트가 visitKey만 확인) `navigate`는 `activity:change`만 올린다. 그래서 홈 팁 `week-causes`는 방문해도 0회로 남아 계속 추천된다. 수정 2곳만: ⓐ `asset-change-view.tsx` `changePeriod`의 `v==="week" && scope==="all"` 분기에 `recordVisit("change-week")`(GA 분기와 같은 조건), ⓑ `navigate`에서 `v.type==="activity" && v.tab==="change" && v.init?.period==="week" && (v.init.scope ?? "all")==="all"`이면 추가 기록(whats-new·팁·허브 행 `최근 7일`이 init로 진입하는 경로). 해시 새로고침 복원은 기록 안 함(현행 GA 정책과 동일). feature-usage 테스트에 두 경로 케이스 추가.

**⑦ 바로 가기 정정 방식**
- 05(`stocks`): 목록에 보일 대상이 없어 **`featureId` 제거**(시트 `바로 가기` 비노출). 항목 자체는 유지.
- 07(`share-card`): `APP_FEATURES`에 `share-card-stock`(action: `dispatchOpenShareCard("stock")`, `visitKey:"share-card"` — top-bar 리스너가 `share-card`만 기록하므로 기존 `share-card-portfolio/-type`의 visitKey 불일치와 달리 정확히 집계). `whats-new` 07의 `featureId`를 이 id로. 단 **홈 팁 후보가 1개 늘어** 추천 순환이 바뀐다 → `pickRecommendedFeature`가 방문 0회 우선이라 `share-card`를 쓰면 동시에 꺼지도록 visitKey 공유가 중요. 대안(후보 증가 회피): `whats-new` 엔트리에 선택 필드 `action` 지정 — 스키마(config) 변경이라 비권고.
- 04(`change`→월별 기록 스크롤)는 요청 범위 밖이므로 이번에 하지 않는다(기본 기간이 이미 `month`).
- 탭 지정은 신규 `ChangeInit` 필드 없이 기존 `init.period`로 충분.

**⑧ 테스트 영향**
- 유지: `market-entry-line.test.tsx`(컴포넌트는 hero용으로 남음, 훅 분리 후 동일 출력), `stock-page-view.test.tsx`(종목 한 장 불변), `week-causes.test.tsx`(visitKey 검증 유지).
- testid: `stock-market-entry`는 타일이 이어받음(`stock-market-entry-wrap` 래퍼는 타일 묶음 `stock-tools`로 대체). `stock-page-entry`는 펼침 머리 버튼에 유지(1개). `hub-card-change`·`hub-card-report` 래퍼 유지. 기존 `__tests__`에 `stock-insight-strip`·`tax-season-strip`·stock-tab testid 직접 참조 없음(grep 확인) → 삭제해도 깨지는 테스트 0, 단 qa-full-test-plan `F-*`의 해당 설명(상단 스트립·`종목 보기`·`총 N주`)은 KB 갱신 때 정정.

## 6. 규모와 줄이는 방법
- 예상: 신규 ~250줄(타일 100·행 차트 90·훅 분리 30·유틸 30), 삭제 ~150줄(스트립 2개·footer·머리 링크), 수정 ~120줄, 테스트 ~200줄. spec(v2)보다 큰 부분 없음.

## 7. 위험·주의 요약
1. 외부 시세 요청: 펼침 시 +1(CDN 히트 다수). 콜드 미스 시 KIS 최대 4콜, 한도 10/60초→429 폴백. 서킷은 5-① 모니터링.

3. `KpiCard` 헤더/행 분리 시 허브 전체 카드 탭 영역 회귀 → 기존 허브 테스트·`data-tutorial` 확인.
4. 4.72·4.73 판독 경계(진입점 변경)와 `change-week` 집계 시작점은 머지일로 기록.
