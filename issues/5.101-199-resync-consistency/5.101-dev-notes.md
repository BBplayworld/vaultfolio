## 원인 진단
1. 브로드컴 뒤바뀜: 키움 화면은 평가금액 열이 없고 평가손익·수익률만 있다. 수익률 +0.86%는 읽은 그대로·바꾼 것 모두 3%p 허용폭 안(둘 다 가능)이라 C 분기(소수익률)로 가는데, C는 평가금액÷수량 엄격 일치(E1)가 있어야 swap하므로 평가금액이 없으면 4.99식 keep. 같은 이미지의 다른 행(수익률 큼)은 정상이라 이미지 안 방향이 섞였다.
2. 이름: 미래에셋 2줄 행에서 이름이 `10(`로 잘리고 아래 줄 수량이 붙어 `10(104`(닫는 괄호 없음). 기존 정규화는 `(N)` 닫힌 꼴만 처리. 키움은 이름에 `현금 | 티커` 2행이 섞임, `…`·`(…`가 겹쳐 남음, 줄바꿈 자리 공백(`미국 빅테크`).
3. IRP 미노출(진단만, 구현 없음): `match.ts matchExisting`은 ① 티커·category·증권사 일치가 있으면 그것만 후보로 쓰고, 일치가 없을 때만 ①'(같은 증권사 다른 유형)으로 넓힌다. 장 유형(account)은 `inferScreenAccount`가 같은 티커의 기존 항목 과반 category로 추정(과반 없으면 domestic)하고 사용자가 장 드롭다운으로 바꾼다. 그래서 (a) 장 유형이 연금저축으로 잡히면 같은 티커 IRP 보유분은 ① 후보에서 빠지고(삭제 범위도 증권사×유형 단위라 IRP는 유지 묶음), (b) DC·IRP가 둘 다 category `irp`이면 같은 유형 안 다수라 `multiAccount`로 묻는다. 저장 항목에 계좌명 필드가 없어 화면 글자로는 구분 불가.
4. 사진별 선택 신뢰(설계안, 구현 보류): ①이 이미 사용자 선택 유형을 우선하고 1개면 자동 확정한다. 남은 갭은 ① 없음 → ①' 폴백에서 다른 유형 항목을 조용히 연결·후보화하는 점과 유형 미선택 시 추정 오류. 안: 사용자가 사진별 유형을 직접 고른 경우(accountOverrides 존재)에는 ①'를 쓰지 않고 '없음(추가)'로 두며, 다른 유형 같은 티커가 있으면 기존 문구 패턴으로 안내. UI 문구 확정(ui-designer) 필요라 이번 릴리스 제외.

## 변경
- `price-consistency.ts`: `reconcileImagePrices` 추가. 행별 `reconcilePrices` 결과로 표(asIs/swap)를 모아 swap 표 2 이상·반대 표의 3배 이상일 때만, 소수익률로 방향이 애매했던 행에 swap 적용. 평가손익이 있고 부호가 swap 결과와 모순이면 그 행은 유지(C102). 동률·근거 부족·asIs 다수면 행별 결과 그대로. `route.ts processStockResults`가 호출.
- `name-normalize.ts`: 닫는 괄호 없는 `(숫자`(수량 같거나 마스터 매칭 필요 시), `구분 | 티커` 꼬리, 겹친 말줄임 반복 제거, 마스터와 공백·괄호 무시로 같으면 마스터 표기 사용.
