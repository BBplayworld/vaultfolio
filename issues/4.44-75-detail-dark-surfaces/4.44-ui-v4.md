# 4.44 ui-v4 — 상세 > 주식 행 "오늘 등락" 칩 위치 검토 (UI 디자이너)

기준: e3ed78c, stock-tab.tsx `StockRowHeader`·`TodayChangeChip`, theme.ts `ASSET_THEME.todayBox`.
한계: 이 환경에 Playwright/브라우저가 없어 375/360/320 스크린샷 재현은 불가. 코드 구조와 폭 계산으로 판정했고, 실측 스크린샷은 developer preview에서 qa가 확인한다(아래 체크리스트).

## 1. 현재 구조와 4줄이 되는 조건
- 행 = 아이콘(size-6) | 좌측 `cardInfoLeft`(flex-1, min-w-0) | 우측 `cardInfoRight`(flex-shrink-0, 금액 + 손익 한 줄 nowrap) | 쉐브론.
- 좌측: 제목 줄(이름 `line-clamp-2` + 거래정지/상장폐지 배지, `flex-wrap`) + 메타 줄(`{수량}주` + 모바일에서 비중은 숨김 + 오늘 등락 칩, `flex-wrap`).
- 우측은 shrink 불가라 폭을 먼저 가져간다. 금액 + `+₩1,234,567 (+12.3%)` 손익 줄이 320px에서 약 140~160px라서 좌측은 약 80~100px만 남는다.
- 4줄 조건 = 이름 2줄 + 메타 줄에서 `1,234주`(약 45px)와 칩 `오늘 ▼65.3%`(약 80px)가 한 줄에 못 들어가 칩이 아래로 줄바꿈. 배지가 붙으면 제목 줄도 배지 때문에 줄바꿈해 같은 결과(최악: 이름 2 + 배지 줄 + 수량 + 칩 = 5줄까지 가능).
- 외화 종목은 보조줄이 없다. 표시 화폐는 `fmt`로 한 줄에 처리되므로 줄 수에 영향이 없다.
- 인증카드(screenshotMode)는 칩을 렌더하지 않고(`!screenshotMode`), 온보딩 `StockRowItem`도 `dailyRate`를 넘기지 않아 칩이 없다. 영향 범위는 상세 리스트 `StockCard`(L816) 한 곳뿐이다.

## 2. 후보 비교
| 안 | 최악 줄 수(320) | 판단 |
|---|---|---|
| (a) 우측 3번째 줄(금액·손익·오늘) | 좌측 3줄(이름2+수량) / 우측 3줄 → **3줄** | 좌우 모두 3줄 이하. 우측은 이미 `text-right`라 칩이 오른쪽 끝에 정렬된다. 배지가 붙는 최악 케이스는 좌측 4줄이 되므로 아래 보정(§3-3)이 필요하다. |
| (b) 손익 줄에 합치기 | 우측 폭 +80px → 320에서 좌측이 사라짐 | 불가. 또 손익%와 오늘%가 한 줄에 나란히 놓여 혼동된다. |
| (c) 좌측 인라인 유지 + 모바일만 우측 이동 | (a)와 같음, PC는 현 상태 유지 | **권고**. PC는 폭이 넉넉해 현행이 가장 낫고(비중도 같은 줄에 있음) 모바일만 문제다. |
| (d) 모바일 숨김 | 3줄 | 비권고. 대표 의도(종목별 오늘 등락 노출)와 어긋난다. |
| (e) 칩을 수량 줄 대신 이름 줄 끝 | 이름이 더 좁아져 이름 3줄 위험 | 비채택. |

색 혼동: 칩은 muted 배경 + 회색 "오늘" 라벨 + 방향 기호(▲/▼)를 쓰고, 손익은 라벨 없이 원/% 숫자만 쓴다. 칩을 손익 줄 아래 별도 줄에 두면 둘이 한 줄에서 겹치지 않고, 칩 배경과 라벨로 구분된다. 한국 관습(빨강=상승/파랑=하락)은 `getProfitLossColor`를 그대로 써서 유지된다.

## 3. 권고: (c) 모바일만 우측 3번째 줄로 이동 (신규 토큰 없음)
`stock-tab.tsx` 변경 3곳(`StockRowHeader`).
1. 좌측 메타 줄의 칩에 `max-sm:hidden` 추가.
   `<TodayChangeChip rate={dailyRate} className="text-[11px] max-sm:hidden" />`
2. 우측 `cardInfoRight` 안, 손익 줄 아래에 모바일 전용 칩 추가. 조건은 기존과 같다(`!screenshotMode && dailyRate != null`).
   `<TodayChangeChip rate={dailyRate} className="text-[11px] sm:hidden mt-1 ml-auto" />`
   - `ml-auto`는 칩이 inline-flex이고 부모가 `text-right`라 정렬은 이미 오른쪽이지만, 줄 높이 안정을 위해 부모를 flex-col로 바꾸지 않고 `block w-fit ml-auto`로 쓰는 편이 안전하다. 구현은 `inline-flex` 대신 `flex w-fit ml-auto`로 override한다.
   - 칩 높이는 약 `text-[11px]` leading + py-0.5 ≈ 20px. 3줄 총 높이는 금액(≈18) + 손익(≈22) + 칩(≈24) ≈ 64px로, 좌측 3줄(≈62px)과 비슷하다.
3. 배지 보정: 모바일에서 배지가 이름과 같은 줄에 못 들어가 줄바꿈하는 최악 케이스는 배지를 `max-sm:order-first` 같은 순서 변경이 아니라 이름 `line-clamp-2` 유지 + 배지는 `shrink-0`으로 두고, 모바일 이름 폭이 좁으면 이름 `line-clamp-1`로 낮춘다(`line-clamp-2` → `max-sm:[&:has(+*)]:line-clamp-1`은 과해서 비채택). 현실적인 규칙: 배지(상장폐지·거래정지) 종목은 `nameCls`에 `max-sm:line-clamp-1`을 추가한다. 이때 최악은 이름1 + 배지 + 수량 ≤ 3줄이다. 배지는 상장폐지·거래정지 종목에서만 뜨고 그런 종목은 대개 오늘 등락 칩이 없다(기준가 없음).
- 접근성/히트영역: 행 전체가 `button`(cardTriggerButton)이라 히트영역 변화 없음. 칩은 장식이므로 aria 추가 불필요(텍스트 "오늘 ▼65.3%"가 그대로 읽힘). 중복 렌더(좌/우)는 `hidden`이라 접근성 트리에서 제외되어 이중 낭독이 없다.
- 영향 범위: PC(sm 이상)는 변화 없음. 다크·라이트는 같은 토큰이라 대비 변화 없음(muted/60 칩 배경은 다크 card 면에서 이미 승인됨). 인증카드·온보딩은 칩 미렌더라 영향 없음. 모션 변화 없음.
- 같은 패턴: 가상자산 탭 등은 `dailyRate`/칩을 쓰지 않으므로 이번 범위에 적용하지 않는다(코드상 `TodayChangeChip` 사용처는 주식 요약 헤더·주식 행뿐. 요약 헤더 칩은 `flex-wrap` 인라인이라 별도 이슈 없음). 향후 같은 칩이 다른 탭에 생기면 동일 규칙을 적용한다.

## 4. 품질 체크리스트 (qa용)
1. 320/360/375 라이트·다크에서 긴 종목명(2줄 이상) + 오늘 칩 종목의 행이 3줄을 넘지 않는다.
2. 모바일에서 좌측 메타 줄에는 수량만 있고 칩은 우측 손익 줄 아래에 오른쪽 정렬로 있다.
3. 1280에서 칩은 기존처럼 수량·비중 옆(좌측)에 있고 우측에는 칩이 없다.
4. 칩 문구 `오늘 ▲/▼N.N%`, 수치는 tabular-nums, 상승=빨강, 하락=파랑.
5. 손익 줄과 칩이 같은 줄에 놓이지 않는다(겹침 없음).
6. 상장폐지·거래정지 배지 종목이 모바일에서 3줄 이하다.
7. `dailyRate`가 null이면 좌·우 어디에도 칩이 없다.
8. 행 클릭 시 펼침 동작 유지, 쉐브론 정렬 유지.
9. 인증카드 PNG와 온보딩 StockRowItem 화면은 변화가 없다.
10. 칩이 DOM에 좌·우 두 번 있어도 화면에는 한 번만 보인다.

UI 판정: 위 권고(c) 적용 요청. 수정 후 developer가 preview에 올리면 375/360/320 × 라이트·다크 스크린샷으로 재검수한다.
