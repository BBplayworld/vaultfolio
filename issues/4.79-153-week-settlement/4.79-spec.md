## 1. 문제
- 자산 변화 › 전체 › **주** 탭(`asset-change-view.tsx` `WeekList`)은 '7일 전 대비' 숫자 하나와 날짜별 마감 목록만 보인다. 원인 분해가 없다.
- 그래서 월 결산 사이 3~4주 동안 "최근 일주일 왜 변했나"를 물을 곳이 없다. 홈 Hero는 '지난 접속 이후'만 보이고, 그 구간은 접속 간격에 따라 하루~몇 주로 바뀐다.
- 주 탭 증감은 마감 기록끼리의 차, 홈 Hero는 실시간 끝점이라 같은 날 두 숫자가 다를 수 있다.

## 2. 목표 행동 (관찰 가능)
1. 전체 범위에서 `주`를 누르고, Hero 아래 원인 줄로 최근 7일 증감을 나눠 본다.
2. 원인 블록 푸터의 `종목 등락 보기`를 눌러 시장과 비교(1주)로 넘어간다.
3. `기록 내역 N건`을 펼쳐 이 기간 입출금·매매·대출 기록을 본다.

## 4. 사용자 흐름
1. 성과 › 자산 변화 → 범위 `전체 자산` → 기간 `주`. 팁으로 들어오면 같은 상태로 열린다.
2. Hero: 제목 `최근 7일`(또는 `M/D 이후`) + 구간 `M/D → 오늘`(7≤D≤9만) → 증감 금액·% → `시작 → 끝` 순자산.
3. Hero 아래 `변화 원인`(`CauseBlock scope="week"`): 6줄 중 표시 기준을 넘는 줄만 고정 순서(시세 변동·평가 갱신·환율 효과·순유입·대출·기록 안 된 변화).
4. 원인 블록 푸터 행: 왼쪽 `기록 내역 N건 ⌄`(기존 `AttributionRecordList`, 기록 있을 때만), 오른쪽 `종목 등락 보기 ›`(주식 보유 시만). 둘 다 없으면 푸터 행 없음.
5. `종목 등락 보기` → 시장과 비교(목록 기간 1주, 이 진입에만). 뒤로 1회 = 자산 변화 전체·주.
6. 맨 아래 `날짜별 마감 기록 ⌄`(기본 접힘). 펼치면 캡션 + 지금의 7일 행(날짜·마감 순자산·전일 대비) 그대로.

## 5. 계산·정본 규칙
### 5-1. 기준점·공용 함수
- 신규 순수 함수 `computeAttributionView`(`views/activity/week-attribution.ts`, tech-review 2절). 본문은 `dashboard.tsx` `useHeaderNetChange` 계산부를 그대로 옮긴 것: `buildLiveAttributionCurr` → `computeAttributionSince` → `getAttributionRecords` → `matchRecordedTransferDetail(windowFrom ?? fromDate, windowTo ?? toDate)` → `getAttributionItems` → `attachCauseDates`·`sortCausesByDate`. 저장소 읽기는 호출부에 남긴다. 홈 훅과 B가 같이 부른다. `asset-report.ts`·`settlement.ts` 계산 함수 변경 0.
- **리팩터 커밋을 먼저 단독으로 하고 T4 골든 PASS 후 B를 얹는다.**
- `sinceDate` = today−7. today는 홈 Hero와 **같은 KST 날짜 함수**로 구한다(C69, T13). 직접 날짜 계산 금지.
- 시작점은 엔진이 고른 `attr.fromDate`(스냅샷 `_date`, 시스템 기록). 판별에 거래 날짜·이름·메모를 쓰지 않는다(LEARNINGS 11-11). 기록·짝은 `windowFrom/To`, 표기는 `fromDate/toDate`(Hero와 같은 변수).

### 5-2. 표기 (D = today − fromDate 일수, ui 2절)
| 조건 | 제목 `week-title` | 구간 `week-range` | 본문 |
|---|---|---|---|
| 7 ≤ D ≤ 9 | `최근 7일` | `M/D → 오늘` | 증감·%·`시작 → 끝` + 원인 분해 |
| D < 7, 10 ≤ D ≤ 14 | `M/D 이후` | **없음**(제목이 시작일을 말함) | 같음 |
| D > 14(월 스냅샷 폴백) | `최근 7일` | 없음 | `week-insufficient` `최근 7일 기록이 부족해요` + note `기록이 쌓이면 원인을 나눠 보여드려요`. 원인 블록 없음. 접힘 카드는 보인다 |
| `attr = null`(오늘 전 기록 0) | `최근 7일` | 없음 | `week-empty` `기록이 쌓이면 더 보여드려요`(기존). 원인·접힘 카드 없음 |
- O-2 확정: 이전 기록이 1건이어도 분해한다(홈 Hero와 같은 조건, direction 4절 '1건 이하 현행 유지'를 대체).
- `7일 전 대비`·`이번 주` 문구는 화면·팁 어디에도 쓰지 않는다. 구간은 늘 실제 시작일. Hero에는 `예측` 배지를 달지 않는다.

### 5-3. 원인 매핑 — 홈 Hero 항목을 결산 어휘로 합산만
| Hero 항목 키 | B 줄 |
|---|---|
| `price:stock` `price:crypto` | 시세 변동 |
| `price:realEstate` `price:physical` | 평가 갱신 |
| `fx` | 환율 효과 |
| `income` `buy:*` `sell:*`(realEstate·physical 포함) | 순유입 (O-1 확정) |
| `debt`(양·음 모두) | 대출 |
| `cash` `deposit` `unrecorded` **`price`(통합·레거시)** | 기록 안 된 변화 |
- **O-3 확정**: 레거시 시작점의 통합 `price`는 Δ순자산에서 추정 투입을 뺀 잔차 전부라 `기록 안 된 변화`(예측)로 둔다(월 탭 R3와 같음, C24).
- 각 줄 = 그룹 Hero 항목 원값의 합(원 반올림). **`기록 안 된 변화` = round(deltaNet) − 나머지 줄 합.** 이 줄은 Hero가 걸러 낸 1만 원 미만 잔차를 흡수한다(그룹 합과 차이 < `CAUSE_DISPLAY_MIN`).
- 줄 표시: |값| ≥ 10원(월 탭 `NOISE_WON`과 같음).
- **|round(deltaNet)| < 1만**이면 줄 없이 `뚜렷한 변화 원인이 없어요`(Hero `negligible`과 같은 기준). Hero 항목 0개라도 |deltaNet| ≥ 1만이면 `기록 안 된 변화` 1줄이다.
- `예측`: 그룹 항목 중 하나라도 `estimated`면 그 줄에 배지(흡수분은 예측을 만들지 않음). 2줄 이상이면 제목 옆 1개(기존 `CauseBlock` 규칙).
- `CauseBlock` 확장은 **scope `week` + `CAUSE_HINT` scope 분리 + footer 슬롯으로 한정**한다. `showUnrecordedHint`는 week에서 쓰지 않는다.

### 5-4. 정본 규칙
- **홈 Hero와 `fromDate`가 같으면 B 각 줄 = 같은 그룹 Hero 원인 금액 합, B 증감 = Hero 증감, B 끝 순자산 = Hero 순자산.** 예외 2개: ① `기록 안 된 변화`는 1만 원 미만 잔차를 흡수한다 ② 레거시 시작점의 통합 시세 잔차는 월 탭 R3와 같게 `기록 안 된 변화`(예측)로 둔다 — 이 경우만 홈 Hero 라벨(`시세(예측)`)과 다르다.
- 주 탭 Hero 증감은 '최근 마감 − 기준 마감'에서 `attr.deltaNet`(실시간 끝)으로 바뀐다. % = `deltaNet ÷ (순자산 − deltaNet)`(홈과 같은 식). 옛 값은 화면 어디에도 남기지 않는다(접힘 목록은 행별 전일 대비만).
- 전제 확인(developer → qa): `buildLiveAttributionCurr` 순자산이 홈 Hero 순자산(summary)과 원 단위까지 같은지. 다르면 기준을 cto에 올린다.

### 5-5. 연결·팁·측정
- `종목 등락 보기`: `rememberChangeInit({scope:"all", period:"week"})` 후 `navigate({type:"activity", tab:"change-market"})`. 1주는 **이 진입에만** 적용하고 사용자가 저장한 기간 선택은 바꾸지 않는다. 저장 구조라면 developer가 보고한다.
- 팁: `APP_FEATURES`에 `id:"week-causes"`, 아이콘 `ListChecks`, `isNew:true`, target `{type:"activity", tab:"change", init:{scope:"all", period:"week"}}`(O-4, 기존 패턴). **배열에서 `market-compare` 앞**에 둔다. **`market-compare` isNew는 내리지 않는다**(4.73 판독 창 ~12/8 보호. isNew 팁은 한 번에 1개라 중복 배지 없음).
- GA: `feature_use` category `change_week_all`, 제목 `성과·자산 변화·최근 7일`(ga.ts allowlist·제목 맵 추가, `change_scope_stock` 패턴). 전체 범위에서 `주`를 누를 때 1건. **팁으로 진입해도 1건 보낸다**(`source:"home_tip"` — ga.ts에 `method` 키가 없어 기존 allowlist 값 사용). 복원·첫 진입은 보내지 않는다. `visitKey`가 `change`와 섞이지 않는지(`viewToKey`가 init 무시) developer가 확인한다.

## 8. 수용 기준 (qa가 그대로 검사)
1. 주 탭에 `이번 주`·`7일 전 대비` 문구가 없다. 7≤D≤9면 `week-title` = `최근 7일`이고 `week-range` = `M/D → 오늘`(M/D = 실제 시작일). D<7 또는 10≤D≤14면 `week-title` = `M/D 이후`이고 `week-range`가 없다.
2. `cause-block[data-scope=week]`의 줄 `data-value` 합 = `change-hero-delta`의 `data-value`. 줄 순서가 고정 순서이고 |값| < 10원 줄이 없다. (|deltaNet| < 1만이면 `뚜렷한 변화 원인이 없어요`, 이 항목 면제)
3. `change-hero-end`의 `data-value` = 같은 시각 홈 Hero 순자산(원 반올림).
4. `change-hero-start`의 `data-value` = `날짜별 마감 기록`에서 fromDate 행의 마감 순자산(같은 반올림, C65).
5. T1~T13 vitest PASS, `npm run lint`·`npm run build`·`npx tsc --noEmit` PASS.
6. preview `?demo=1` 기본 상태(주입 없음, C66)에서 원인 줄이 1개 이상이고 푸터 오른쪽에 `week-market-link`(높이 ≥40px, 숫자·색 없음)가 있다. 누르면 시장과 비교가 1주로 열리고, 뒤로 1회면 전체·주로 돌아온다. 이후 시장과 비교에 직접 들어가면 사용자가 저장한 기간이 그대로다. 주식 미보유면 링크가 없다.
7. `week-closing-toggle`은 기본 접힘(`aria-expanded=false`, 패널 `inert`)이다. 펼치면 캡션과 `week-row`가 main과 같은 값·순서로 나온다. 시세 갱신 뒤에도 펼침이 유지되고, `주→월→주` 뒤엔 접힘으로 돌아온다.
8. 주↔월 0.3초 연타 뒤 Hero와 원인 블록이 같은 기간이다(C73).
