## 판단 기록
- **한도 초과 응답 = 429**(지시문의 '초과/실패 시 null'과 다름): spec §4가 정본이고, 200 null로 주면 기기가 '화면에 합계 없음(none)'과 구분하지 못해 §6 `skip`·철수선 `none` 비율이 서버 사정과 섞인다. 기기에서는 429·500·시간 초과 모두 '값 없음 → 줄 숨김 + skip'이라 사용자 화면은 같다.
- 판정 시점: `맞추기` 클릭 핸들러(`handleApply`) 안, 저장 성공 직후 같은 동기 구간. 저장 실패 시에는 합계 호출을 취소하지 않는다(다시 누르면 그때 판정).
- 합계는 '그 합계를 읽은 장이 지금 유일한 성공 장'일 때만 쓴다. 1장으로 인식한 뒤 2장째를 추가하면 호출은 이미 1회 나갔지만 줄은 숨김(okShots 2). 2장을 한 번에 올리면 호출 0.
- 2장을 올려 둘 다 성공한 뒤 1장을 지워 1장이 된 경우: 새 인식 동작이 없으므로 호출 0 → none.
- 구버전 서버 혼재(배포 순간·롤백): 구버전은 `stock-total`을 모르므로 행 인식으로 처리해 `{ stocks }`를 준다 → 기기는 `screenTotal` 없음 = null로 읽어 줄 숨김(none). 이때 서버 행 인식 몫 1회가 쓰이지만 기기 30회는 차감하지 않는다. 저장되는 값이 없어 기록 손실 0.
- 환율 추정·시세 실패 판정 한계는 5.161과 같다(해외 + `exchangeRateDate` 빈 값이면 숨김, 현재가 0만 감지).
