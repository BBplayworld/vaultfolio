# 5.159 상세에서 보는 배당 — spec (planner-designer, 2026-11-26)

정본: CEO(문구 최종 정본은 이 spec, ui.md §문구와 일치), `_discovery/2026-11-26-core-value/ceo.md` ②·③·④(5.159), business.md 과제 ①, planner.md ⑤-3·4, DECISIONS 11-26(v5.155 머지 후속: '예상금액' 열 용어). 코드 main 986057b(v5.155) `/home/user/vf-main`. risk:low(예상), 저장 변경 0, tech-review 불필요(CEO), ui.md 필요(종목 한 장 1줄·Hero 결론·320).
경로 약어: `A/` = `src/app/(main)/_components/views/activity/`, `P/` = `src/app/(main)/_components/views/detail/stock-page/`.

## 1. 문제
- 종목 한 장(`P/stock-page-view.tsx`, 해시 `#detail/stocks-item`, 상세·주식 행 → '종목 한 장' / 시장 비교·불리기에서 진입)에 배당 정보가 0줄이다. 배당주 사용자는 그 종목 배당을 보려고 성과 › 배당 표에서 종목을 다시 찾아야 한다.
- 성과 › 배당은 보조 장치가 결론을 가린다. 머리 오른쪽 '예상 포함/지급만' 토글, Hero 라벨 `올해 예상 배당`(실제로는 지급+예상 합), 도움말 4줄 중 2줄이 요약과 중복. "올해 얼마 받았고, 얼마 남았고, 다음은 언제"를 한 줄로 볼 수 없다(LEARNINGS 11-18).
- 표 다섯째 열 이름이 `예상금액`인데 값은 지급+예상 합(`displayTotal`)이다. 이름과 값이 다르다.
- 코드 확인: 배당 화면에 '월평균'은 **없다**(grep 0). 없으니 뺄 것도 더할 것도 없다(월평균 1줄 추가는 하지 않음).

## 2. 목표 행동
- 종목 한 장을 연 사용자가 스크롤 없이 이 종목의 올해 지급·예상·다음 지급 달을 읽는다. 더 보고 싶으면 그 줄을 눌러 성과 › 배당으로 간다.
- 성과 › 배당을 연 사용자가 토글을 누르지 않고 Hero 아래 1줄로 지급·예상·다음 지급을 읽는다.

## 3. 범위
- 포함: ① 종목 한 장 배당 줄 1개 ② 배당 Hero 아래 결론 줄 1개 ③ 토글 삭제·Hero 라벨 정리·도움말 2줄 삭제 ④ 표 열 이름 ⑤ 다음 지급 선택 함수 1개 ⑥ 훅에 대상 종목 인자 ⑦ GA title 1개 ⑧ 새 소식 1건.
- 계산 규칙: 금액은 v5.155 `computeDividends`(`src/lib/finance/dividend-calc.ts`) 결과만 읽는다. 새 금액 계산 0. 추가하는 것은 결과에서 고르는 순수 함수 1개뿐이다.
  - `nextDividendMonth(calc, todayKst, keys?)` → `{ month, count } | null`. 오늘(KST) 달 이상에서 `perMonth.expected[m] > 0`인 가장 이른 달, count = 그 달에 예상이 있는 종목 키 수. `keys`를 주면 그 키만 본다. `dividend-calc.ts`에 둔다.
  - `useDividendData({ enabled, stocks? })`: `stocks`를 주면 `assetData.stocks` 대신 그 행만으로 `buildDividendGroups`·쿼리·`computeDividends`를 돈다. 쿼리 옵션·키(`["dividend","v11",ticker,type]`)는 그대로다.
- 하지 않음: 월평균 추가, 세후, 작년 대비, 주기 배지를 종목 한 장에 반복, 허브 카드 변경, 성적표 입력 변경, 새 화면·새 저장 키, 서버 변경, 판 종목 복원.

## 4. 종목 한 장 배당 줄
- 위치: `stock-page-chart-card` 맨 아래, `거래내역 N건` 행 **바로 아래** 같은 모양의 링크 행(`border-t border-border/40`, `min-h-12`, 오른쪽 `ChevronRight`). 맨 아래라 나타나거나 없어져도 위 요소가 움직이지 않는다. 시각 세부는 ui.md에서 정한다.
- 대상: `groupStocks` 전체(전체 탭은 티커 단위로 여러 카테고리, 카테고리 탭은 ticker:category). 계좌별 원본 행으로 계산한 뒤, 그룹 안 `dividendStockKey`들의 `byStock` 값을 더한다.
- 문구(금액은 원화, `formatPriceByMode`. 원/달러 토글과 무관하게 원화. 배당 화면과 같은 기준):
  - 1행(text-sm): `올해 배당 지급 {P}원` · `예상 {E}원`. 지급 0이면 `올해 배당 예상 {E}원` 한 조각, 예상 0이면 `올해 배당 지급 {P}원` 한 조각(첫 조각에 늘 `올해 배당`). 조각 단위로만 줄바꿈(`DotWrap`, C25). 320에서 1행 최대 2줄(ui.md).
  - 2행(text-xs muted): `다음 지급 {m}월` · `세전 추정`. 다음 달이 없으면 `세전 추정`만.
  - 'P + E'는 배당 표에서 그 종목 행(들)의 `합계` 값의 합과 같다(반올림: P = round(paid), E = round(paid+expected) − P).
- 상태
  | 상태 | 판정 | 표시 |
  |---|---|---|
  | 조회 중 | 쿼리 isLoading | 줄 없음(나타날 때 subtle fade, `motion-safe`) |
  | 배당 있음 | P+E > 0 | 위 2행, 누르면 성과 › 배당(`navigate({type:"activity",tab:"dividend"})`) |
  | 배당 없음 | 조회 성공, P+E = 0(무배당·올해 지급분 모두 매수 전) | **줄 없음**(무배당 종목에 빈 정보 0줄) |
  | 조회 실패 | 그룹 쿼리 하나라도 isError | `배당을 불러오지 못했어요`(muted, 누름 없음·화살표 없음). 일부 성공분도 보이지 않는다 |
  | 엔화 | 그룹이 모두 JPY | `배당 조회 안 됨 · 엔화 종목`(muted, 누름 없음). 요청 0 |
  | 대상 아님 | 티커 없음·비상장·상장폐지만 | 줄 없음, 요청 0 |
- '세전 추정'은 이 화면에서 이 줄 1곳뿐이다.
- 뒤로: 성과 › 배당에서 브라우저 뒤로 = 종목 한 장(store 메모리 유지). 새로고침 후에는 현행대로 상세·주식.

## 7. 사용자 흐름
1. 상세 › 주식 → 종목 행 → 종목 한 장. 차트 카드 맨 아래 `거래내역 N건` 아래에 `올해 배당 지급 … · 예상 …` / `다음 지급 12월 · 세전 추정`이 보인다.
2. 그 줄을 누르면 성과 › 배당이 열린다(GA title `상세·주식·종목·배당`, 종목·금액 미전송).
3. 배당 Hero `올해 배당 {합계}` 아래 `지급 … · 예상 … · 다음 지급 12월 3종목`이 보인다. 토글은 없다.
4. 표에서 그 종목 행의 `합계`가 1번의 지급+예상과 같다.
5. 뒤로 → 종목 한 장.

## 8. 엣지 케이스
- 빈 데이터: 주식 0·배당 0 → 종목 한 장 줄 없음, 배당 화면은 현행 빈 화면. 결론 줄도 없음(Hero가 없을 때).
- 일부 갱신: 배당 화면은 현행(실패 안내 + 성공분 합). 결론 줄은 성공분 기준. 종목 한 장은 그룹 하나라도 실패면 실패 문구(일부 금액 표시 0).
- 오래된 데이터: CDN 6시간·서버 저장 캐시 응답을 그대로 쓴다(현행과 같음). 12월에 남은 예상이 없으면 `다음 지급` 조각을 뺀다(내년 예상 없음, 현행 서버).
- 날짜 지난 추정분: 예상으로 남지만(5.157 규칙) 오늘 달 이전이면 `다음 지급`에 잡지 않는다. E에는 들어간다.
- 첫 사용자·체험 데이터: 데모 데이터로 종목 한 장 줄·결론 줄이 보인다(preview 확인).
- 여러 계좌·나눠 산 종목: 계좌별 선계산 후 그룹 합. 전체 탭에서 국내·ISA 같은 티커는 두 키 합.

## 9. 서버 호출
- 종목 한 장은 그 그룹의 (ticker, type)만 조회한다. 국내·IRP·ISA·연금은 type이 같아 보통 1건, 최대 2건(국내+해외 혼재). 다른 종목 요청 0.
- 같은 쿼리 키라 react-query 메모리 캐시(staleTime 30일, 세션 메모리, 영속 저장 없음)를 배당 화면·허브와 공유한다. 이미 배당 화면을 본 세션은 추가 요청 0. 처음 여는 경우만 종목당 1건이고, 그 결과는 이후 배당 화면에서 재사용된다.
- 서버는 `ticker-type-v12` 저장 캐시를 사용자 공용으로 쓰므로 KIS 호출은 캐시 미스 때만이다. 배당 화면을 한 번 여는 것보다 요청이 적다. 엔화·비상장은 요청 0.
- 요청 값은 `ticker·type·excd`뿐, 사용자 자산 데이터 전송 0. 응답 형식·캐시 키 변경 0.

## 10. 완료 기준 (qa가 그대로 검사)
1. 같은 픽스처에서 종목 한 장 줄의 P+E = 배당 표 그 종목 행 `합계`(전체 탭 여러 카테고리면 행들 합)이고, 배당 Hero의 P·E와 같은 `computeDividends` 결과에서 나온다(vitest). `dividend-calc.ts`에 금액을 새로 계산하는 함수가 추가되지 않는다(`nextDividendMonth`만).
2. 결론 줄 `지급 P · 예상 E`의 P+E = Hero 금액(문자열 기준). `다음 지급 {m}월 {k}종목`의 k = 그 달 표 필터(막대 선택) 행 중 `예정` 배지가 있는 종목 수.
3. 배당 화면에 `예상 포함`·`지급만`·`올해 예상 배당` 문자열 0, 범례 `예상 (옅음)`은 연간 예상 > 0일 때만 1개(예상 0 픽스처에서 0), 도움말 줄 2개, 표 머리 `예상금액` 0·`합계` 1(월 선택 시 `{m}월 합계`).
4. 종목 한 장 상태표 6가지가 각각 위 표대로 나오고, 배당 있음 상태의 1행은 늘 `올해 배당`으로 시작한다. 무배당 종목은 줄 0, 엔화는 배당 요청 0, 실패는 금액 0.
5. 종목 한 장 진입 시 배당 요청은 그 그룹의 (ticker, type) 수 이하이고, 배당 화면을 먼저 본 세션에서는 0이다.
6. 줄 누름 → 성과 › 배당, GA page_title `상세·주식·종목·배당` 1건(종목·금액 파라미터 0). 뒤로 → 종목 한 장.
7. 저장 키·스키마·서버 전송 값 diff 0(`STORAGE_KEYS`·`local-storage` 변경 0). 허브 카드 금액·성적표 배당 입력 불변(5.155 픽스처 회귀).
8. 320·390: 종목 한 장 줄·결론 줄이 조각 단위로만 줄바꿈되고 줄 끝 가운뎃점 0, 한 글자만 따로 남지 않는다(C25). 월 선택·해제 시 차트가 밀리지 않는다. 히트영역 ≥ 40px.
9. 투자 조언 어휘 0. 'KIS' 노출 0(5.155 유지).

## 11. 새 소식
- 추가 1건(C82): id `YYYYMMDD-01`(머지일, 같은 날 다른 항목이 있으면 순번 조정), featureId `stocks`
- title `종목 한 장에서 그 종목 배당이 보여요`(19자)
- body `올해 지급·예상과 다음 지급 달을 한 줄로 보여 줘요`(27자). 금액·투자 판단 어휘 0. 배당 화면 압축은 줄이기라 따로 알리지 않는다.

## 12. 줄이는 순서 (spec보다 커질 때)
1. 결론 줄의 `{k}종목` 조각 → `다음 지급 {m}월`만.
2. 종목 한 장 실패·엔화 문구 → 줄 없음(배당 화면 안내가 대신).
3. 종목 한 장 줄 누름(링크) → 읽기 전용 줄(GA title도 뺀다).
※ 토글 삭제와 열 이름은 줄이지 않는다(하나를 더하면 하나를 뺀다).
