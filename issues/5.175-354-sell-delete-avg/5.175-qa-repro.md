## #355 다 판 코인 소실
- `saveAssetData`는 `assetDataSchemaLoose`를 쓰는데, 이 스키마는 주식만 완화했다. 코인은 strict `cryptoSchema`(수량 > 0, 평단 > 0, 현재가 > 0)를 따른다. 그래서 수량 0 코인은 저장되지 않는다.
- vitest 결과
  - 코인 0@0은 `false`, 코인 10@0도 `false`
  - 주식 0@0과 10@0은 `true`
- UI 결과: 전량 매도를 제출해도 저장되지 않는다. 상세 › 암호화폐에는 `비트코인 10개 1,500원`이 그대로 남는다(`coin-02-detail-after-fullsell.png`).
- 결론: 다 판 코인이 목록에서 사라지는 상태는 main에서 만들어지지 않는다. `crypto-tab.tsx:242`의 `value > 0` 필터는 지금 저장 가능한 데이터로는 아무것도 거르지 않는다.
- 렌더만 따로 확인했다. 저장 관문을 거치지 않고 수량 0 코인을 넣으면 '등록된 암호화폐가 없습니다'가 뜨고 내역 버튼은 0개다(vitest). 그래서 N1을 고쳐 0개 저장을 허용하면 #355가 그때 실제 결함이 된다.
- 통제군
  - 대출 잔액 0: '완납된 대출' 구역에 [내역]·[기록]이 있다(UI `coin-06-loan-paidoff.png`).
  - 주식 0주: 행이 남고 평단 0원, 0주로 표시된다(UI `coin-05-stock-zero-row.png`).
  - 두 거래소 중 한쪽만 0개인 코인: 카드가 유지된다(vitest 렌더).
- 참고(범위 밖): 저장소에 이미 수량 0 코인이 있으면 `getAssetData` 읽기가 ZodError를 내고 crypto 0개(빈 데이터 폴백)로 읽힌다(vitest). UI로는 만들 수 없는 상태다.

## N1 코인 전량 매도 저장 실패 (신규, 확정)
- 재현
  1. 상세 › 암호화폐에서 비트코인 카드를 펼치고 [내역]을 누른다.
  2. [매수/매도 기록] → 매도 → 전량(10) → 단가 130 → 반영 체크 상태로 [매도 기록]
  3. 창이 그대로 열려 있고 토스트·오류가 모두 0건이다. 저장값은 10@100, 거래 0건 그대로다.
  - 미리보기에는 `10 → 0개`, `100원 → 0원`이 표시된다(`coin-01-fullsell-submit.png`).
- 원인: 이 저장 거부(`crypto-tx-input` → `addCryptoTransactionWithPosition` → `saveData` → `saveAssetData`)는 prod에서 콘솔 출력 없이 `false`를 돌려준다. 폼은 실패 시 아무것도 표시하지 않는다.
- 같은 관문을 쓰는 코인 스크린샷 가져오기(`crypto-trade-screenshot-import.tsx:260`)도 전량 매도가 포함되면 실패할 것으로 본다. 코드 근거만 있고 UI로는 확인하지 않았다.
- 영향
  - 기존 사용자 전원이 코인 전량 매도를 반영 기록할 수 없다.
  - 우회 방법은 '반영 해제(기록만)'나 코인 삭제뿐이다.
  - 데이터 손실은 0이다(저장 자체가 일어나지 않음).
- 5.175 범위 판단에 주는 시사점
  - #354 코인 쪽과 #355는 N1이 있는 동안 실제로 생기지 않는다.
  - N1을 고치려면 코인 저장 스키마를 완화(수량·평단 0 허용)해야 한다. 이는 저장 스키마 변경 = risk:high다. 구버전이 수량 0 코인을 읽으면 위 '빈 데이터 폴백'이 생기므로 혼재 동기화·롤백 검증이 필수다.
