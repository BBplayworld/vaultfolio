## 4. 결함
### D1 [확정, 데이터 안전, FAIL] 구버전 기기 push 후 클라우드 사본에서 실물이 사라지고 신 기기가 다시 올리지 않는다
- 재현(실제 구버전 4fee68c 코드 + 신 코드, 동일 서버 모의): ① 신 A가 금 1건 추가 후 push ② 구 B가 pull(실물 strip)·수정·push → 서버 payload에 physicalAssets 키 없음 ③ 신 A pull → 로컬 금 유지(OK)이나 `pullAsset` 결과 `mergedAdditions:false` → `cloud-sync-provider.tsx:308`의 즉시 재push 미발생 ④ 신 C(새 기기)가 pull → 금 없음(`phys:null`).
- 기대: 로컬에만 있는 실물(원격 키 없음)이면 로컬 복구분을 서버에 되돌려 올린다(기존 항목들이 `mergedAdditions`로 하는 것과 동일). 실제: 서버 사본은 A가 다음에 편집·push할 때까지 실물이 없고, 그 사이 새 기기 복원·A 분실 시 실물 기록 손실.
- 원인 위치: `src/lib/asset/asset-storage.ts` `reconcileAdditiveMerge`의 `after.physicalAssets === undefined → {arr: undefined, changed:false}` (changed=false라 `mergedAdditions` 불발).
- 수정 제안: 원격 키 없음 & 로컬(before) 실물 1건 이상이면 `changed=true`로 반환하고 data에 로컬 실물을 실어 `mergedAdditions`가 true가 되게(→ runPush). 구 기기가 push할 때마다 신 기기가 1회씩 재push할 뿐 핑퐁 없음(구 기기는 편집 때만 push). 회귀 테스트: A(신,금1)/B(구) 순환 후 pull 결과 `mergedAdditions===true`, 이어 push 후 신 C pull에서 금 보임.
- 영향 범위: 4.55 머지 후 구버전 기기가 남아 있는 사용자 중 실물 등록자(신규 기능이라 기존 사용자 영향 0). 로컬 기록은 안전, 클라우드 사본·다른 신 기기 복원만 해당.
- 기존 vitest(physical-assets-sync)가 이를 못 잡은 이유: 구 기기 사본 로직이라 "A 로컬 유지"만 단언하고 서버 사본·재push는 검증 안 함.
