## 4. C5 결정
**① WebKit persist·ITP 7일.** 이 세션에서 webkit.org 접근이 프록시에 막혀 **원문 확인 못 함**. 기억·문서 근거는 다음과 같고, 확정이 아니다.
- WebKit ITP 정책(webkit.org/blog/10218 "Full Third-Party Cookie Blocking and More", 2020)은 7일 상한이 Safari 브라우저 사용(탭)에 적용되고 **홈 화면에 추가한 웹앱은 면제**라고 적는다. 이 면제는 persist 허용과 무관하다.
- `StorageManager.persist()`가 7일 삭제까지 면제하는지는 WebKit 문서에서 확인하지 못했다(webkit.org/blog/14403 "Updates to Storage Policy"에 persist 설명이 있다고 기억하나 미확인). **면제되지 않는다고 가정한다.**
- 결론: ③은 유지(비용 0, 저장 공간 부족 시 축출 방지). 판독은 '허용 응답 기기 수'로만 하고 '보호됨'이라는 표현은 쓰지 않는다(C5-1 그대로). 허용 조건은 구현 중 실기기(iOS Safari 탭)에서 `persist()` 반환값을 1회 확인해 dev-notes에 기록한다.
- Chromium은 프롬프트 없이 휴리스틱(설치·북마크·참여도)으로 허용하며, 거부가 정상 응답이다.

**② Firefox 제외.** `/\bFirefox\//i.test(navigator.userAgent)`로 제외한다(Gecko 데스크톱·Android 모두 포함). iOS Firefox는 UA가 `FxiOS`라 WebKit 동작이고 프롬프트가 없어 제외되지 않으며 정상이다. 대안(Permissions API `persistent-storage`)은 Chromium·WebKit 지원이 불확실해 쓰지 않는다. Gecko의 프롬프트 동작 자체는 MDN "Storage quotas and eviction criteria" 기준(미확인, 제외가 안전 측).

**③ iOS 16.4 미만 분기: 가능.** `detect-browser.ts`의 `parseIosMajor`는 private이고 minor가 없다. 같은 정규식으로 `os (\d+)[_.](\d+)`를 읽는 `isIosBelow164(ua)` 5줄 이내를 추가하고(iPhone/iPad UA의 `OS 16_3`, iPadOS 데스크톱 UA는 `Version/16.x` 폴백), 파싱 실패는 false(새 문장 사용)로 둔다. `install-nudge.tsx`는 이 값이면 기존 문장을 유지한다. Safari 26 이후 UA의 OS 버전 동결은 ≥16.4라 영향 없다.
