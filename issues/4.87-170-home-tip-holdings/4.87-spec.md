# #170 [4.87] 홈 팁 보유 필터 — spec

정본: `4.87-direction.md` 합의 절. 코드 근거는 main 19bb0df를 읽어서 확인했다. 저장 키·스키마·우선순위·팁 문구·카탈로그 순서·서버 전송 변경은 0이다.

## 1. 문제
`pickRecommendedFeature()`(`feature-usage.ts:78`)는 보유와 무관하게 방문 최소 항목을 고른다. 동률이면 카탈로그 순서를 따른다. 그래서 해외주식이 없는 사용자도 첫 기능 팁으로 '연말 절세 시뮬레이션'을 보고, 다음 팁으로 안 가진 자산군의 빈 화면에 도착한다.

## 2. 목표 행동
홈 기능 팁을 누르면 내가 가진 자산군과 주식이 쓰이는 화면에 도착하고, 미보유 때문에 생기는 빈 상태는 0이다. 해외주식 보유자의 첫 팁은 지금과 같다.

## 3. 필터 규칙 (기능 팁 층만, `pickRecommendedFeature(assetData)`)
- 시그니처: `pickRecommendedFeature(assetData: Pick<AssetData,"stocks"|"realEstate"|"crypto"|"cash"|"loans">)`. **필수 인자**로 두어 필터를 거치지 않는 호출이 없게 한다. 유일한 호출부는 `home-tip.ts:68`이고, 여기서 `pickHomeTip`의 `assetData`를 그대로 넘긴다.
- 순서: 기존 `tip !== false` 조건과 미dismiss 조건을 먼저 적용하고, **그다음 보유 조건**을 적용한다. 고르는 방식(방문 최소, 동률은 카탈로그 순)은 바꾸지 않는다.
- 걸러진 항목에는 dismiss를 기록하지 않는다. 그래서 보유가 생기면 다시 후보가 된다. 판별에는 수량과 건수만 쓰고 날짜·이름은 쓰지 않는다.

| featureId | 보유 조건 함수 | 데이터 출처 |
|---|---|---|
| `tax-simulator` | `stocks.some(isTaxSimCandidate)` (해외·상폐/정지 아님·수량>0). 시즌 조건은 없다 | `assetData.stocks`, `tax-utils.ts:176` 재사용 |
| `stocks`·`stocks-xray`·`dividend`·`market-compare`·`share-card`·`share-card-portfolio`·`share-card-type` | `hasStock = stocks.some(s => s.quantity > 0)` | `assetData.stocks` |
| `real-estate` | `realEstate.length > 0` | `assetData.realEstate` (실물 자산 `physicalAssets`는 포함하지 않는다. 별도 탭이고 카탈로그에 없다) |
| `crypto` · `cash` · `loans` | 각 배열 `length > 0` (#99 `heldRefreshCategories`와 같은 건수 기준. 완납 대출(balance 0)도 1건으로 센다) | `assetData.crypto`·`cash`·`loans` |
| `tax-schedule`·`change`·`week-causes`·`report` | 항상 통과 | — |
| `monthly-log`·`share-card-stock` | 기존 `tip:false`라 원래 후보가 아니다 | — |

- 조건 표는 `feature-usage.ts` 안에 상수 1개(featureId → 조건)로 둔다. 카탈로그(`app-features.ts`)는 바꾸지 않는다.
- 새 소식 시트의 `바로 가기`(`runFeatureEntry`)는 이 필터를 거치지 않는다. 동작은 그대로다.

## 5. 우선순위 불변 (C38·C82)
- `pickHomeTip`의 순서(백업 > 임박 세금 > 결산 창 > 새 소식 > relink > 그 외 세금 > 최신화 > 기능)와 diff는 0이다.
- 결산 창 날짜(예: `today="2026-11-28"`, 전월 스냅샷 있음)를 주입하면 F1~F6 모두 `kind:"settlement"`가 나온다.
- 안 본 새 소식이 있고 `whatsNewOk`이면 F1~F6 모두 `kind:"whats_new"`가 나온다. 개수는 main과 같다(C84).
- **후보가 0이면** `pickRecommendedFeature`는 `null`을 돌려준다. 상위 층도 해당이 없으면 `pickHomeTip`이 `null`을 돌려주고 박스(`home-tip`)는 DOM에 없다. 예: F1에서 5개를 모두 누르거나 X로 닫은 뒤.

## 6. GA page_title (맞춤 정의 0, utm 0)
- `ga.ts`에서 `feature_use`이고 `category:"home_tip"`이며 `method:"click"`이면 page_title을 **`홈 팁·누름`** 으로 보낸다. 이 이벤트는 `home-tip-box.tsx:109` `activate`에서 1곳만 나간다.
- `method:"view"`(`:80`)·`"close"`(`:103`), method가 없는 이벤트는 **`홈 팁`** 을 유지한다.
- 그대로: `data_action` source `home_tip`("백업"), `entryCategory` 진입 이벤트(예: `change_week_all` → "성과·자산 변화·최근 7일"), `whats_new` click("새 소식").
- 새 파라미터 값은 추가하지 않는다. `click`은 기존 허용 값이다.

## 7. p2 동승
**필수 1 — 수익 칸 전부 실패** (`profit-chart.tsx`)
- 조건: 네트워크 조회가 429·5xx로 끝나 `incomplete`가 되고 받은 종목이 0이다. 대상 조회는 현재 기간(ref) 또는 일간(daily, 일간이 아닌 기간일 때)이다. 지금은 `refData`나 `dailyData`가 `undefined`로 남아 스켈레톤이 계속 보인다(`:360` `isLoading`). abort와 일부 성공은 해당하지 않는다.
- 표시: `kisUnavailable`과 **같은 자리·같은 박스**에 표시한다. 히어로(`controlledPeriod`)이면 `ChangeHero` message, 카드이면 점선 박스다. 문장은 **원인을 단정하지 않는 새 문장 1개**이고 ui-designer가 확정한다(자리: `<전부 실패 문구>`). 방향은 "지금 못 불러왔고 다음에 열면 다시 불러온다"이다. 기존 상수와 문구 "외부 증권 API 점검으로…"(`:391`·`:407`, `market-compare-view.tsx:68`, `asset-report-view.tsx:142`)는 바꾸지 않는다(C70).
- 재조회: 불완전 결과는 캐시에 저장하지 않으므로(기존) 다음 진입이나 기간 전환 때 새로 조회한다. 기간 전환·데이터 리셋 때 실패 상태를 `kisUnavailable`과 같은 지점에서 끈다.
- 정상·점검·일부 실패 경로의 표시는 main과 같아야 한다.
- 범위 밖: 오프라인 등 fetch 예외(`catch` 무시 경로)는 이번에 다루지 않는다.

## 8. 엣지 케이스
- 빈 데이터: 홈 팁은 자산이 있을 때만 마운트된다(기존).
- 일부 갱신: `assetData`가 바뀌면 effect가 다시 판정한다(기존). 팁 키가 바뀌면 view 1회가 나간다(기존).
- 오래된 데이터: 수량 0 종목, 상폐 해외주식은 4절의 F7과 경계 항목으로 처리한다.
- 첫 사용자: 첫 저장 직후 첫 팁은 F1~F6 기대값과 같다. 웰컴·마법사·첫 저장 diff는 0이다.
- 알려진 한계(수용): 상장 국내주식에 배당이 없으면 배당 화면이 "배당 데이터가 없습니다"가 된다. 비상장·채권형만 있으면 시장과 비교가 `CompareNotice`가 된다. 첫 주 사용자에게 주간 원인은 "뚜렷한 변화 원인이 없어요"로 나온다. 모두 화면별로 판별을 쪼개지 않는다.

## 9. 수용 기준 (qa)
1. F1~F7 각각에서 홈 첫 기능 팁 제목이 4절과 같다. 상위 층(백업·세금·결산·새 소식·relink·최신화)은 끈 상태로 본다.
2. F1~F5에서 팁을 차례로 누르면 도착 화면 첫 화면에 **미보유 때문에 생긴 빈 상태가 0**이다("시장과 비교할 종목이 없어요", 미보유 자산군 탭의 빈 카드 등). 항목마다 제목 속 요소가 보이는 캡처를 남긴다(C87).
3. 결산 창 날짜 주입 시 결산 팁이 이긴다. 안 본 새 소식이 있으면 새 소식 팁이 이긴다. `pickHomeTip` diff는 0이다.
4. 후보가 0이 되면 `[data-testid="home-tip"]`이 DOM에 없다.
5. GA: 팁 누름은 `홈 팁·누름`, 보임·닫기는 `홈 팁`이다. `ga.test.ts`에 3행(click/view/close)을 추가한다. 기존 `{category:"home_tip"}` → `홈 팁` 행은 유지한다.
6. 수익 칸: 429·5xx 전부 실패 모의 응답이면 스켈레톤(`change-hero-loading`)이 사라지고 새 문장이 보인다. 점검 헤더면 기존 점검 문구, 정상과 일부 성공이면 main과 같다.
7. 320·375 배당 표에서 '분기' 배지가 겹치지 않는다(캡처).
8. 기존 테스트(`feature-usage.test.ts`·`entry-paths-483.test.ts`)는 **전 자산군 픽스처를 넘겨** 기대값을 바꾸지 않고 통과한다.

## 10. C76·C83 기본 경로 테스트 (신규 `home-tip-holdings.test.ts`)
- 입력 구간표: 보유 구성은 기본(F2 국내주식만, 가장 흔한 신규 저장)·경계(F7, 수량 0)·폴백(F6 전 자산군 = main 동일)으로 나눈다. 구간마다 단언을 1건 이상 둔다.
- 방문과 dismiss는 픽스처로 넣지 않고 **실제 `recordVisit`·`dismissTip`을 호출한 결과**로 판정한다. localStorage 스텁은 entry-paths-483과 같은 방식을 쓴다.
- 기본 경로 시나리오: F2 데이터로 `pickRecommendedFeature(data)`를 호출하면 `tax-schedule`이 나온다. 이어서 `dismissTip`과 `recordVisit("tax")`를 실제로 호출한 뒤 다시 호출하면 `stocks`가 나온다. 끝까지 반복하면 4절 F2 순서와 같고 마지막은 `null`이다.
- F5: 첫 결과는 `tax-simulator`다. 누름(dismiss + `recordVisit("tax")`)을 처리한 뒤에는 `tax-schedule`이 아니라 `stocks`가 나온다.
- 통합 1건: `pickHomeTip`을 실제 `pickRecommendedFeature`로 호출한다(모킹 없음). F1과 결산 창 밖 날짜로 `kind:"feature"`·`tax-schedule`이 나오는지, 결산 창 날짜이면 `settlement`가 나오는지 확인한다.

## 12. 뺀 것
안 가진 자산군에 '추가해 보세요' 팁을 띄우는 것, 시즌 조건, 팁 문구·카탈로그 순서 개편, 새 소식 등록(PR 줄 `새 소식: 해당 없음(보유 맞춤 필터·결함 수정, 새 기능 없음)`), 팁 종류별 GA 분리, 화면별 세부 판별(배당 유무·비상장)은 하지 않는다. 기존 점검 문구 수정과 fetch 예외 경로도 이번 범위가 아니다.
