# 4.38 direction — 가족과 같은 금고 함께 쓰기 (#57)

근거: docs/discovery/2026-10-31-growth-big-verdict.md ① (F1~F4·F8, 5절 이슈 초안), DECISIONS 2026-10-31(D 재개 선정)

## 사업 (business-pm, 2026-10-31)
1. **왜 지금**: 첫 발견(신규 활성) 기여. 가족 기기 1대 연결 = GA 활성 기기 1대로 유입 병목(신규 월 약 17기기)을 우회하는 유일한 경로. 리텐션 부가 기여: 부부가 같은 자산을 보면 둘 중 한 명이 고쳐도 다른 쪽이 열 이유가 생김. 대표 2026-10-31 지시(12월까지 신규 활성 확장)에 부합. 결산 창(11/27~) 화면 무접촉이라 #51·#54 판독과 충돌하지 않음
2. **누구를 위해**: 엑셀·노션 한 장으로 부부 자산을 함께 정리하던 3040 투자자 중, 이미 기기 동기화를 켠 사용자(초대 주체). 가족은 새 설치 없이 링크 + 금고 암호로 들어오는 사람
3. **성공의 모습** (익명 기기 기준, 기존 GA 가능)
   - 머지 후 8주 `sync_action{method:connect, result:success, source:family}` 고유 기기 수 4기기 이상(월 2기기). 현재 sync_action 기준선 28일 0건
   - 연결 기기 28일 재방문: connect 이벤트 발생 기기 중 연결 후 28일 안 session_start 재발생 비율(탐색 보고서). 사용자 속성 추가 없음
   - 가드레일: 충돌 뒤 편집 손실 0(자동 테스트), `result:conflict` 뒤 `method:reapply` 비율 참고용
4. **하지 않으면 잃는 것**: 약함~중간. 지금도 링크로 가족 기기 연결은 가능(F1)하지만 안내·고지가 없어 쓰는 사람이 드물고 동시 편집이 소리 없이 덮이는 위험이 남음. 대안(G2·#33·체험 모드)은 #48 퍼널 동결로 대기 중이라 이번 회차에서 신규 활성에 직접 닿는 선택지가 이것뿐이다. 수치 기여는 작음(business.md 산식, 100명까지는 못 미침)
- 참고(판정서 값): 머지 후 8주 가족 경로 connect 성공 기기 수 월 2기기 이상, 연결 기기 28일 재방문, 충돌 뒤 편집 손실 0

## 경험 (planner-designer)

### 1. 사용자가 이 기능 후 하게 될 행동 (관찰 가능)
- 동기화를 쓰는 사용자가 설정 > 기기 동기화에서 "가족 기기 연결"을 열어 고지를 읽고, 링크/QR을 가족에게 보낸다.
- 가족은 링크를 열어 금고 암호를 입력하고 같은 자산을 자기 기기에서 본다(GA: connect, source=family).
- 두 사람이 같은 시간대에 고쳐도, 이 기기에서 고친 값이 소리 없이 사라지지 않는다. 덮이면 어떤 항목인지 보이고 한 번에 다시 적용할 수 있다.

### 2. 범위
- 포함: ⓐ 기존 동기화 메뉴 armed 화면 안의 "가족 기기 연결" 블록(기존 링크·QR·공유 재사용, 새 URL·새 화면 없음) + 고지 ⓑ 편집 시작 전 원격 최신이면 먼저 받기 ⓒ 충돌 때 덮인 내 수정 알림 + 다시 적용 ⓓ GA source=family
- **줄일 수 있는 것**: 별도 가족 전용 화면·튜토리얼, 연결 완료 축하 화면, 연결된 기기 목록. "다시 적용"이 tech-review에서 위험하면 알림만(판정서 ⓒ 최소선)
- **하지 않을 것**: 소유자 태그·나/배우자 범위 토글, 권한 회수·기기 목록 관리, 두 금고 병합, 첫 화면 변경, 서버 변경, 스키마·저장 키 추가, 초대 문구에 금액·투자 조언, 알림(Push)

### 3. 기존 화면
- 바뀜: 더보기 > 기기 동기화 armed 상태(블록 1개 추가), 이 기기 연결 다이얼로그(가족 링크로 들어오면 고지 1줄, 이름 변경 없음), 충돌 시 토스트(알림 카드로 대체)
- 그대로: 홈·성과·결산·첫 화면·none/locked 상태 UI·"기기 데이터 가져오기" 등 기존 버튼

### 4. 사업 절에 대한 의견
- 사업 절 미작성 — 작성 후 `동의` 또는 `이견`을 이 자리에 기록한다.
- 사전 메모(사실): ① 링크만으로는 열 수 없고 금고 암호가 함께 필요하다 → 고지·초대 안내에 반영 ② 연결하는 가족 기기에 이미 자산이 있으면 연결 때 삭제·대체된다(현행 `merge=false`) → 초대 안내에 포함 ③ preview는 동기화가 꺼져 있어 가족 블록이 preview에 보이지 않는다 → 검증 방법을 spec에 명시

## 합의
business-pm 의견 (planner-designer 경험 절·spec.md 초안 검토 후)
- 최종 방향: 초대 고지 + 편집 전 최신화 + 덮인 항목 알림(다시 적용은 tech-review 위험 시 알림만) + GA source=family. 경험 절 범위·제외 목록에 사업상 동의. 목표는 월 2기기로 낮게 잡고 과대 기대를 하지 않는다
- **이견 1 (사실 오류, 수정 요청)**: spec 5절 보조 한 줄 "나중에 저장한 쪽 값이 남을 수 있어요"는 spec 1절·F2와 반대다. 현행은 409 뒤 force pull로 **먼저 push한 쪽(원격)이 이기고 늦게 저장한 쪽이 덮인다**. "실제와 다른 기능 설명 금지" 위반. 예: "같은 항목을 동시에 고치면 먼저 저장된 값이 남고, 나중에 저장한 쪽은 덮일 수 있어요. 덮인 항목은 알려드려요."
- **이견 2 (보안 문구)**: 고지·초대 문구에 "서버는 안 본다/아무것도 안 간다" 단정을 넣지 않는다(DECISIONS 2026-10-31). 필요 시 "금고는 이중 암호화되어 운영자도 열람할 수 없어요" 수준만. spec 현 고지는 서버 언급이 없어 그대로 두되 마케팅에서도 같은 기준
- **이견 3 (마케팅 연동 타이밍)**: 기능이 덮인 항목 알림까지 완성되기 전에는 "함께 써요" 홍보 금지. 11/26 qa PASS 전 외부 안내 초안만 작성
- 남은 쟁점: ① 위 이견 1·2 반영 여부 ② 고지 문구 대표 동의(spec 5절) ③ 초대 주체 규모(sync_enabled 기기 수)를 GA 사용자 속성으로 개발 전 확인 필요 — 대표 조회 요청
- (이견이 남아 합의 줄은 적지 않는다)
