# 4.38 spec — 가족과 같은 금고 함께 쓰기 (#57)

상태: draft (direction 합의·cto challenge 통과 전 초안. 코드 무변경)

## 1. 문제
- 동기화 금고는 소유자 구분이 없는 하나의 묶음이라 가족 기기를 붙일 수는 있으나(F1), 붙이는 경로가 "내 다른 기기" 문구뿐이고 공유 범위 고지가 없다.
- 충돌(409) 때 `force` pull이 원격으로 교체한다. 추가 항목은 보존되나(`reconcileAdditiveMerge`) **이미 있던 항목을 고친 값은 원격이 이긴다**(F2). 자동 push는 silent라 토스트도 "다른 기기의 변경을 반영했습니다." 한 줄뿐이라 내 수정이 사라진 사실이 안 보인다.
- 현재 보호는 있다: 편집 직후 10초 pull 보류, 마운트·온라인 복귀 pull-first, 60초 폴링·포커스 pull. **빈틈**: 다른 기기가 push한 지 60초 안에 stale 기기가 같은 항목을 고치는 경우, 기기가 오프라인이었던 경우.

## 2. 목표 행동
가족 링크로 연결한 기기가 생기고(connect source=family), 충돌이 나도 사용자가 고친 값이 사라진 채 모르는 일이 없다.

## 3. 범위
포함: 가족 기기 연결 블록·고지 / 편집 전 최신화 / 충돌 보호 / GA. 제외: 12절.

## 4. 사용자 흐름
**초대 (기존 사용자, armed)**
1. 더보기 > 기기 동기화 > "가족 기기 연결" 블록(기존 "다른 기기 동기화 링크" 카드 아래, 같은 카드 스타일)
2. 블록 상단 고지(5절) 노출. 접힘 없음, 항상 보임
3. [링크 복사][QR][공유] — 기존 `copyLink`/`showQr`/`shareLink` 재사용. 링크는 `#sync=<id>&theme=..&src=family`
4. 공유 텍스트: "시크릿에셋 가족 금고 — 링크를 열고, 금고 암호는 따로 알려줄게" (암호는 링크·공유 텍스트에 넣지 않는다)

**참여 (가족)**
1. 링크 열기 → 기존 "이 기기 연결" 다이얼로그 자동 노출(`src=family`면 설명 1줄: "가족 금고에 연결합니다. 이 금고의 모든 자산이 보이고 고칠 수 있어요.")
2. 이 기기에 자산이 있으면 기존 빨간 경고 유지 + 1줄: "연결하면 이 기기의 자산이 삭제됩니다. 필요하면 먼저 백업 내보내기를 하세요."
3. 금고 암호 입력 → 연결 → 자산 표시. 튜토리얼 스킵은 기존 동작

**동시 편집 (연결된 모든 기기)**
1. 자산·거래 편집 창을 열 때 armed이면 원격 버전을 확인, 최신이면 편집 창 입력값 채우기 전에 pull(상세 6절)
2. 저장 후 push가 409면 기존 force pull이 돌고, 덮일 뻔한 내 수정이 있으면 알림 카드 노출(6절)

## 5. 화면 구성과 고지 문구 (대표 동의 대기)
**가족 기기 연결 블록 (armed 전용)**
- 제목: `가족 기기 연결`
- 고지(주황 안내 박스, 기존 `amber-500/10` 패턴, 320px `break-keep`):
  > 이 링크와 금고 암호를 모두 아는 사람은 이 금고의 모든 자산을 보고 고칠 수 있어요. 한번 연결한 기기의 권한은 회수할 수 없고, 막으려면 새 금고를 만들어 옮겨야 해요. 믿는 가족에게만 보내고, 금고 암호는 링크와 따로 알려주세요.
- 보조 한 줄: `두 사람이 같은 항목을 동시에 고치면 나중에 저장한 쪽 값이 남을 수 있어요. 덮인 항목은 알려드려요.` (6절 동작이 구현된 범위만큼 사실로 쓴다)
- 버튼 3개는 기존 카드와 같은 구성. 가족 블록과 "다른 기기 동기화 링크"는 같은 링크이므로 **8절 정본 표** 참고

**대표 확인 포인트 (needs 아님, 문안 확인만)**
- 판정서 원문은 "링크를 받은 사람"이나 코드상 **링크 + 금고 암호가 모두 있어야** 열린다(`deriveKeys(passphrase, assetId)`). 사실대로 "링크와 금고 암호를 모두 아는 사람"으로 썼다. 더 강하게(링크만으로도 위험) 쓸지 대표가 정한다
- "회수할 수 없다"는 문구 수준 / 투자 조언·금액 표현 없음 확인

**덮인 항목 알림 카드 (6절 ⓒ)**
- 위치: **sonner 토스트 + 기기 동기화 다이얼로그 상단 카드**. 홈 팁 영역·결산 화면은 쓰지 않는다(결산 창 무접촉 규칙)
- 토스트(1회): `다른 기기의 변경이 우선 적용됐어요. 이 기기에서 고친 N개 항목을 확인하세요.` [확인] 액션 → 기기 동기화 다이얼로그 열림
- 카드: `덮인 항목 N개` 목록(항목 이름 + "내 값 → 지금 값" 한 줄, 금액은 화면 안에서만 보이고 GA·서버로 나가지 않음) / [내 값으로 다시 적용][그대로 두기]
- 320·375px 줄바꿈 안 깨짐(C25), 40px 히트영역

## 6. 동시 편집 보호 동작 (방식은 tech-review가 확정, 아래는 계약)
ⓑ **편집 전 최신화**
- 조건: status=armed, 앱 잠금 해제, `busyRef` 아님, 마지막 확인 후 15초 경과(과호출 방지)
- 동작: `fetchRemoteVersion` → 로컬 버전보다 크면 `autoPullIfNewer({force:true})` 후 편집 창 열기. 지연 상한 1.5초, 초과·오프라인·오류면 지연 없이 편집 진행(편집을 막지 않음)
- 이 호출은 pull-first 일부이며 사용자 편집 보류 가드(10초)와 충돌하지 않는다(편집 시작 전이므로)

ⓒ **충돌 화해 때 내 수정 보존**
- 대상: 409 → force pull 경로, 마운트/온라인 복귀 pull. 같은 id의 항목이 로컬과 원격에서 다르고, **이 기기에서 마지막 동기화 이후 고친 항목**
- 기준 필요 데이터: 마지막 동기화 시점 항목 지문(hash). 현재 `syncedIds`는 id만이라 "내가 고쳤는지"를 알 수 없다. 선택지: (1) `secretasset_sync` 객체에 `syncedHashes` 선택 필드 추가(키 추가 아님, 단 `forgetRemembered`가 필드를 골라 재기록하므로 누락 방지 필요) (2) 메모리 전용(새로고침 시 유실) → **(1)을 기본, 새 localStorage 키를 만들면 위험 high로 상향**(cto)
- 기본 동작: 원격 우선 유지(현행). 단 덮인 항목은 pull 직전 메모리에 보관했다가 알림 카드에 표시하고, [내 값으로 다시 적용]은 그 항목만 로컬에 되돌려 일반 편집으로 취급(→ 자동 push). 같은 항목을 그사이 다른 기기가 또 고쳤으면 다시 덮일 수 있음을 카드에 쓴다
- 삭제 존중: 원격에서 삭제된 항목을 내가 고쳤다면 "삭제된 항목"으로 표시하되 자동 부활 안 함
- 보존 불변: 1인 다기기의 기존 결과(추가 항목 보존, 월 스냅샷 병합 `mergeMonthlySnapshots`, 삭제 존중)는 main과 동일

## 7. 데이터 계약·무변경 범위
- 변경 없음: `assetDataSchema`·`assetData` 키·`STORAGE_KEYS`(새 키 없음)·`/api/sync` 서버·암호화·payload 형식(buildExportPayload)·월 스냅샷 보존·`pullAsset(merge:false)`(connect 의미)
- 추가(허용): ① 해시 `src=family`(옛 클라이언트는 `SYNC_HASH_PARAM`만 읽어 무시) ② `secretasset_sync` 안 선택 필드 `syncedHashes`(없으면 현행 동작 폴백, 구버전은 모르는 필드를 `forgetRemembered`에서 지울 수 있음 → 지워져도 기능 off, 데이터 손실 없음) ③ GA 값 2개(9절)
- 롤백: 4.38 코드로 되돌려도 데이터 구조가 같아 안전. `syncedHashes` 잔존은 무해
- 위험 등급: 판정서 기준 **medium**. 새 localStorage 키가 필요하면 **high**로 올림(tech-review)

| 연결 끊기 | 하단 "이 기기 연결 끊기" | 변경 없음. 권한 회수 아님을 고지에서 명시 |
| 충돌 안내 | 신규 "덮인 항목" 카드(정본) | 기존 토스트 "다른 기기의 변경을 반영했습니다."는 덮인 항목이 0개일 때만 유지, 있으면 새 토스트로 대체(중복 토스트 금지) |
| 성과·결산·홈 지표 | 해당 없음 | 건드리지 않음 |

## 9. GA 값
- `PARAM_VALUES.source`에 `"family"` 추가, 라벨 `가족 초대`. 기존 맞춤 측정기준 `source` 재사용 → GA 관리 작업 없음
- `PARAM_VALUES.method`에 `"reapply"` 추가, 라벨 `내 값 다시 적용` (덮인 항목 복원 클릭). GA 맞춤 측정기준 `method` 재사용
- 이벤트(모두 `sync_action`):
  - 초대 측: `{method: "copy"|"share"|"open"(QR 열기), source: "family"}`
  - 참여 측: `{method: "connect", result: "success"|"error", source: "family"}` — 링크 `src=family`일 때만 source 부여, 일반 연결은 현행과 동일(source 없음)
  - 충돌: 덮인 항목 알림 노출 `{method: "pull", result: "conflict", source: "family"}`는 가족 블록을 연 적 없는 기기도 있어 `source`를 붙이지 않는다 → `{method:"pull", result:"conflict"}` / 다시 적용 `{method:"reapply", result:"success"|"cancel"}`
- 금액·항목 이름·건수는 GA로 보내지 않는다. `ga.test`·PARAM_VALUES 스냅샷은 추가 값만 갱신
- 판독: 8주 connect source=family 기기 수, 연결 기기 28일 재방문(GA 조회 수단 없으면 대표 공유 수치 또는 정성 판정)

## 10. 엣지 케이스
- 첫 사용자(동기화 미사용): 가족 블록 없음(none 상태는 현행 "동기화 시작"). 시작 후 armed에서 노출
- locked 상태: 가족 블록 없음(잠금 해제 먼저)
- 빈 금고(자산 0건) 초대: 고지 동일, 참여 쪽 "자산이 아직 없어요" 별도 문구 없음
- 가족 기기에 이미 자산: 연결 시 삭제·대체(현행). 백업 권유 1줄. 두 금고 병합은 제외
- 오프라인/지연: 편집 전 최신화는 1.5초 후 포기하고 편집 허용. 온라인 복귀 pull-first(현행)
- 같은 항목 동시 수정·한쪽 삭제: 6절. 3대 이상 기기도 동일 규칙
- 인앱 브라우저·앱 잠금 뒤: 현행 `isBackgroundWorkBlocked`로 연결 다이얼로그 차단 유지
- 오래된 링크(금고 없음): 현행 "클라우드에 금고가 없습니다."
- 구버전 기기 혼재: 해시 `src` 무시, `syncedHashes` 모름 → 현행 동작
- preview: `isCloudSyncEnabled()`=false라 메뉴·다이얼로그가 렌더되지 않고 /api/sync 호출 0건. **UI 검증은 컴포넌트 테스트(provider mock)로 한다.** preview 안전 규칙은 바꾸지 않는다

## 11. 수용 기준 (qa 검사용)
1. [vitest] 두 기기 시뮬레이션: A가 항목 X를 고치고 push한 뒤, stale B가 X를 고치고 push → 409 → pull 후 B의 X 수정이 덮인 항목 목록에 정확히 1건으로 나오고 데이터가 소리 없이 사라지지 않는다
2. [vitest] A가 X, B가 Y(다른 항목)를 동시에 고치면 둘 다 최종 상태에 남는다(원격 우선 + 추가 항목 보존 현행 포함)
3. [vitest] 기준점(`syncedHashes`)이 없는 상태(구버전/첫 동기화)에서 pull 결과가 main과 동일하다. 추가 항목 보존·삭제 존중·월 스냅샷 병합 기존 테스트(`asset-storage-merge`·`monthly-sync-merge`) 무변경 통과
4. [vitest] 편집 전 최신화: 원격이 최신이면 pull 후 편집 창, 원격 동일/오프라인/1.5초 초과면 지연 없이 편집 창. busy·잠금 시 호출 0
5. [vitest/컴포넌트] armed 상태에서만 가족 고지·링크 버튼이 보이고 none/locked에는 없다. 링크에 `src=family`가 붙고 금고 암호는 링크·공유 텍스트에 없다
6. [컴포넌트] `#sync=..&src=family` 진입 시 연결 다이얼로그에 가족 설명 1줄, 자산 있으면 백업 권유 1줄. 연결 성공 시 `track("sync_action", {method:"connect", result:"success", source:"family"})` 1회. 일반 링크는 source 없음
7. [컴포넌트] 덮인 항목 0개면 새 토스트·카드 없음(기존 토스트 유지), 1개 이상이면 새 토스트 1회(중복 없음). [다시 적용]은 해당 항목만 되돌리고 push 대기(userEdit)로 표시
8. [vitest] PARAM_VALUES·라벨에 `family`·`reapply` 있고 `ga.test` 통과. 금액·항목명이 GA 페이로드에 없다
