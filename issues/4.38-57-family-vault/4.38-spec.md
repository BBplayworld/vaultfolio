# 4.38 spec — 가족과 같은 금고 함께 쓰기 (#57)

상태: draft r2 (cto challenge 축소 반영. direction 합의·재검토 전. 코드 무변경)

**r2 변경 요약(cto 축소)**: 편집 전 최신화 삭제 / "내 값으로 다시 적용"·GA reapply 삭제(v1은 덮인 항목 알림·목록만) / 링크 카드 합침 + 보조 버튼 "가족에게 보내기" / 위험 high / 감지는 별도 순수 함수 / 연결 다이얼로그 백업 버튼 / 고지 보강 / 일정 축소안

## 1. 문제
- 동기화 금고는 소유자 구분이 없는 하나의 묶음이라 가족 기기를 붙일 수는 있으나(F1), 붙이는 경로가 "내 다른 기기" 문구뿐이고 공유 범위 고지가 없다.
- 충돌(409) 때 `force` pull이 원격으로 교체한다. 추가 항목은 보존되나(`reconcileAdditiveMerge`) **이미 있던 항목을 고친 값은 원격이 이긴다**(F2). 자동 push는 silent라 토스트도 "다른 기기의 변경을 반영했습니다." 한 줄뿐이라 내 수정이 사라진 사실이 안 보인다.
- 현재 보호는 있다: 편집 직후 10초 pull 보류, 마운트·온라인 복귀 pull-first, 60초 폴링·포커스 pull. **빈틈**(v1은 막지 않고 드러낸다): 다른 기기가 push한 지 60초 안에 오래된 기기가 같은 항목을 고치는 경우, 오프라인이었던 경우.

## 2. 목표 행동
가족 링크로 연결한 기기가 생기고(connect source=family), 충돌로 내 수정이 덮이면 어떤 항목인지 알 수 있다.

## 3. 범위
포함: 합친 링크 카드 + 고지 + "가족에게 보내기" / 연결 다이얼로그 보강(백업 먼저·연결 끊김 안내) / 덮인 항목 알림·목록 / GA source=family. 제외: 12절.

## 4. 사용자 흐름
**초대 (기존 사용자, armed)**
1. 더보기 > 기기 동기화 > 합친 카드 "다른 기기·가족 기기 연결"(기존 "다른 기기 동기화 링크" 카드 자리)
2. 카드 안 고지(5절) 항상 노출
3. 기존 버튼 3개 [복사][QR 코드][공유]는 그대로(링크에 `src` 없음). 그 아래 보조 버튼 [가족에게 보내기] 1개
4. [가족에게 보내기]: 기존 `shareLink` 재사용, 링크 `#sync=<id>&theme=..&src=family` + 가족용 공유 문구 "시크릿에셋 가족 금고 — 링크를 열고, 금고 암호는 따로 알려줄게". 공유 미지원이면 기존처럼 복사 폴백. 금고 암호는 링크·공유 문구에 넣지 않는다. **이 버튼으로 공유한 링크에만 `src=family`가 붙는다**

**참여 (가족)**
1. 링크 열기 → 기존 "이 기기 연결" 다이얼로그 자동 노출. `src=family`면 설명 1줄: "가족 금고에 연결합니다. 이 금고의 모든 자산이 보이고 고칠 수 있어요."
2. 이 기기에 자산이 있으면 기존 amber 박스("연결 시 이 기기의 현재 자산이 삭제되고…") + 버튼은 기존 destructive "기존 자산 덮어쓰고 연결하기" 유지. 박스 아래 [먼저 백업 받기] 버튼 추가(다이얼로그는 닫히지 않음, 6절)
3. 이 기기가 이미 다른 금고에 연결돼 있으면(`getAssetId()` 있음) 1줄: "이 기기의 기존 금고 연결이 끊어져요."
4. 금고 암호 입력 → 연결 → 자산 표시. 튜토리얼 스킵은 기존 동작

**동시 편집 (연결된 모든 기기)**
1. 편집·push는 현행 그대로(편집 전 사전 pull 없음)
2. 409 → force pull 또는 마운트/온라인 복귀 pull로 내 수정이 원격 값에 덮였으면 알림(5절)

## 5. 화면 구성과 고지 문구 (대표 동의 대기)
**합친 카드 "다른 기기·가족 기기 연결" (armed 전용)**
- 기존 본문(복구용 백업 안내) 유지. 그 아래 고지(amber 안내 박스, 320px `break-keep`):
  > 이 링크와 금고 암호를 모두 아는 사람은 이 금고의 모든 자산을 보고 고칠 수 있어요. 한번 연결한 기기의 권한은 회수할 수 없고, 막으려면 새 금고를 만들어 옮겨야 해요. 이미 받은 자산은 그 기기에 남아요. 동기화 코드도 링크와 같은 권한이에요. 믿는 가족에게만 보내고, 금고 암호는 링크와 따로 알려주세요.
- 보조 한 줄: `같은 항목을 동시에 고치면 먼저 저장된 값이 남고, 나중에 저장한 쪽은 덮일 수 있어요. 덮인 항목은 알려드려요.`
- "서버는 안 본다/아무것도 안 간다" 류 단정은 쓰지 않는다. 필요 시 "이중 암호화되어 운영자도 열람할 수 없어요" 수준까지만
- 버튼: [복사][QR 코드][공유] 기존 3개 동일 + [가족에게 보내기] 보조(secondary 스타일, 40px 이상)
- "PWA/네이티브 앱 연동 코드" 카드는 그대로. 위 고지의 "동기화 코드도 같은 권한" 한 줄이 그 카드까지 포함한다(그 카드에는 문구를 더하지 않음, 정본 1곳)

**대표 확인 포인트 (needs-human 아님, 문안 확인만)**
- 판정서 원문은 "링크를 받은 사람"이나 코드상 링크 + 금고 암호가 모두 있어야 열린다(`deriveKeys(passphrase, assetId)`). 사실대로 "링크와 금고 암호를 모두 아는 사람"
- "회수할 수 없다"·"이미 받은 자산은 그 기기에 남아요" 문구 수준. 투자 조언·금액 표현 없음

**연결 다이얼로그 보강**
- amber 박스 + destructive 버튼은 현행 유지(빨간색 경고 아님). 추가: [먼저 백업 받기](hasAssets일 때), "기존 금고 연결이 끊어져요"(이미 연결된 기기일 때) 1줄

**덮인 항목 알림 (v1: 알림·목록만)**
- 위치: sonner 토스트 + 기기 동기화 다이얼로그 상단 카드. 홈 팁·결산 화면은 쓰지 않는다(결산 창 무접촉)
- 토스트(1회, 덮인 항목 1개 이상일 때만; 0개면 기존 토스트 유지): `다른 기기의 변경이 우선 적용됐어요. 이 기기에서 고친 N개 항목을 확인하세요.` [확인] → 기기 동기화 다이얼로그 열림
- 카드: `덮인 항목 N개` 목록(항목 이름 + "내 값 → 지금 값" 한 줄, 값은 화면 안에서만 보이고 GA로 보내지 않음) + 안내 "필요하면 다시 입력하세요" + [확인](닫기). 다시 적용 버튼 없음
- 목록은 앱 실행 중 메모리에만 보관(새로고침 시 사라짐, v1 한계). 저장 키 추가 없음
- 320·375px 줄바꿈 안 깨짐(C25), 40px 히트영역, 라이트/다크

## 6. 동작 계약 (방식은 tech-review 확정, 아래는 계약)
**백업 먼저 받기**: 기존 데이터 백업 내보내기 핸들러(`exportAssetData` 계열 및 설정 > 데이터의 기존 경로) 재사용. 신규 내보내기 구현 금지. 클릭해도 연결 다이얼로그·`pendingConnectAssetId`·해시는 유지. iOS WKWebView·PWA에서 동작해야 한다(C19, 형식이 아니라 전달 방식 확인). 내보내기가 stale 가드로 거부되면 사유 토스트 후 다이얼로그 유지

**덮인 항목 감지**
- 별도 **순수 함수**: 입력(pull 직전 로컬 `AssetData`, 원격 검증된 `AssetData`, 기준점) → 덮인 항목 목록. 저장·push·`notifyAssetUserEdit`·localStorage를 호출하지 않는다(C16). `applyImportedPayload`·`reconcileAdditiveMerge` 입출력은 바꾸지 않는다. 호출은 `pullAsset`이 pull 직전 로컬 사본을 잡아 결과(`PullResult.ok`에 선택 필드 추가)로 돌려준다
- **지문은 사용자 입력 필드만**으로 만든다. `currentPrice`·환율·평가액 같은 파생 필드는 제외(시세 갱신은 push하지 않아 로컬만 바뀐다). 필드 목록은 tech-review가 `types/asset.ts` 전수 대조로 확정
- **덮임 조건**: 같은 id 항목이 `로컬 ≠ 기준점`이고 `로컬 ≠ 원격`(둘 다 사용자 필드 기준)일 때만. 둘 중 하나라도 같으면 표시하지 않는다(오탐 방지). 원격에서 삭제된 항목은 표시하지 않는다(삭제 존중 현행). 기준점이 없는 항목(신규)은 표시하지 않는다(추가 항목은 병합이 살림)
- **기준점**: `secretasset_sync` 객체 안 필드 `syncedHashes`(id→지문) + `syncedHashesVersion`(= `markSynced` 버전). push 성공·pull 성공 때 갱신(pull은 병합 전 원격 기준, `syncedIds`와 같은 원칙). 저장된 버전이 현재 `getVersion()`과 다르면 기준점을 무시하고 **현행 동작**(감지 없음)으로 폴백 → 롤백 뒤 재업그레이드·구버전 혼재의 대량 오탐 방지
- `forgetRemembered`가 필드를 골라 재기록하므로 `syncedHashes`·`syncedHashesVersion`을 추가하고 **테스트로 고정**. `clearSyncState`(연결 끊기)가 지우는 것은 의도된 동작. 새 localStorage 키가 필요해지면 그대로 high + 마이그레이션·복원 테스트 필수
- 보존 불변: pull 결과 데이터(저장되는 값)는 main과 동일. 1인 다기기의 추가 항목 보존·삭제 존중·월 스냅샷 병합(`mergeMonthlySnapshots`)은 불변

## 7. 데이터 계약·무변경 범위
- 변경 없음: `assetDataSchema`·`assetData` 키·`STORAGE_KEYS`(새 키 없음)·`/api/sync` 서버·암호화·payload 형식(`buildExportPayload`)·월 스냅샷 보존·`pullAsset(merge:false)`·`applyImportedPayload`/`reconcileAdditiveMerge` 입출력·`notifyAssetUserEdit` 호출 지점
- 추가(허용): ① 링크 해시 `src=family`(옛 클라이언트는 `SYNC_HASH_PARAM`만 읽어 무시) ② `secretasset_sync` 안 선택 필드 `syncedHashes`·`syncedHashesVersion` ③ `PullResult` 선택 필드(덮인 항목) ④ GA 값 `source:"family"` 1개
- 롤백: 데이터 구조가 같아 4.38 이전 코드로 되돌려도 저장 데이터는 안전. 구버전이 `secretasset_sync`의 알 수 없는 필드를 지워도 기능만 꺼지고 데이터 손실 없음. 버전 불일치 폴백이 낡은 기준점을 막는다
- **위험 등급: high** (동기화 화해 경로 변경, WORKFLOW 6장·DECISIONS 2026-10-31). 새 키 없이도 high

## 9. GA 값
- `PARAM_VALUES.source`에 `"family"` 추가, 라벨 `가족 초대`. 기존 맞춤 측정기준 `source` 재사용 → GA 관리 작업 없음. **`method:"reapply"`는 추가하지 않는다**
- 이벤트(`sync_action`): 초대 측 `{method:"share", source:"family"}`([가족에게 보내기] 클릭, 공유 미지원 폴백 시 `copy`) / 참여 측 `{method:"connect", result:"success"|"error", source:"family"}` — 링크 `src=family`일 때만 source, 일반 연결은 현행과 동일 / 덮인 항목 알림 노출 `{method:"pull", result:"conflict"}`(source 없음)
- 금액·항목 이름·건수는 GA로 보내지 않는다. `ga.test`·PARAM_VALUES 스냅샷은 추가 값만 갱신
- 판독: 8주 connect source=family 기기 수(목표 월 2기기), 연결 기기 28일 재방문. GA 조회 수단 없으면 대표 공유 수치 또는 정성 판정

## 10. 엣지 케이스
- 첫 사용자(동기화 미사용): 합친 카드 없음(none은 현행 "동기화 시작"). 시작 후 armed에서 노출
- locked: 카드 없음(잠금 해제 먼저)
- 빈 금고 초대: 고지 동일
- 가족 기기에 이미 자산: 연결 시 삭제·대체(현행). [먼저 백업 받기]로 보존 경로 제공. 두 금고 병합은 제외
- 이미 다른 금고에 연결된 가족 기기: "기존 금고 연결이 끊어져요" 1줄(`aid !== getAssetId()` 조건으로 이 다이얼로그에 들어옴)
- 시세만 바뀐 항목: 덮인 항목으로 표시하지 않는다(파생 필드 제외)
- 기준점 없음·버전 불일치(구버전/첫 동기화/롤백 뒤): 감지 없음, 현행 동작
- 원격에서 삭제된 항목: 표시하지 않음(삭제 존중)
- 인앱 브라우저·앱 잠금 뒤: 현행 `isBackgroundWorkBlocked`로 연결 다이얼로그 차단 유지
- 오래된 링크(금고 없음): 현행 "클라우드에 금고가 없습니다."
- 구버전 기기 혼재: `src` 무시, 기준점 필드 모름 → 현행 동작

- 새로고침: 덮인 항목 목록은 사라짐(v1 한계, 고지에 약속하지 않음)

## 11. 수용 기준 (qa 검사용)
1. [vitest] 감지 함수: A가 X 수정·push, 오래된 B가 X 수정 후 pull → B의 X가 덮인 목록 정확히 1건. 다른 항목 Y만 고친 경우 목록에 없다. X·Y 모두 최종 데이터에 남는다(원격 우선 + 추가 항목 보존)
