# 4.38 challenge — 가족과 같은 금고 함께 쓰기 (#57)

작성: cto, 2026-10-31. 기준 코드 main e4f27c6. 대상: 4.38-direction.md, 4.38-spec.md(draft)

## 판정: `축소`
아래 축소 범위를 direction "경험·합의" 절과 spec에 반영한 뒤 재검토 1회. 반영되면 통과 처리한다.
절차 메모: direction 사업 절과 합의 절이 아직 비어 있고, spec이 challenge 전에 먼저 작성됐다(WORKFLOW 2장 ③). 축소 반영과 함께 합의 절을 완료한다.

## 축소 범위
1. **ⓑ 편집 전 최신화 제외.** 동기화를 쓰는 모든 사용자(1인 다기기 포함)의 편집 창을 열 때마다 네트워크 호출과 최대 1.5초 지연이 생기고, 편집 진입점이 여러 곳(자산 폼·trade-input·스크린샷 가져오기 등)이라 회귀 범위가 넓다. 빈틈(60초 이내 경합, 오프라인)은 ⓒ 알림이 드러내므로 v1에서는 겹친다.
2. **ⓒ "내 값으로 다시 적용" 제외. v1은 알림과 목록만**(direction 2절의 최소선). 근거(코드): 매수·매도 한 번이 거래 항목 추가와 보유 항목(quantity·averagePrice) 수정을 함께 만든다(`trade-input.tsx` → `addTransactionsBatch([tx],[],[stock])`). 새 거래는 `reconcileAdditiveMerge`가 살리지만 보유 항목 수정은 원격 값이 이긴다. 그래서 항목 하나만 되돌리면 거래와 보유가 서로 어긋날 수 있다. 카드 문구는 "내 값 → 지금 값"과 "필요하면 다시 입력하세요"로 하고, GA `method:"reapply"`도 뺀다.
3. **가족 링크 구분 방식 확정.** spec 8절은 카드를 하나로 합쳤는데, 링크가 하나뿐이면 `src=family`가 모든 연결에 붙어 성공 지표(source=family)를 읽을 수 없다. 합친 카드에 기존 3버튼은 그대로 두고 보조 버튼 1개("가족에게 보내기": 기존 shareLink 재사용, `src=family` + 가족용 공유 문구)만 더한다. 이 버튼으로 공유한 링크에만 source를 붙인다.
4. **위험 등급 `high`로 정정.** spec 7절의 "medium"은 DECISIONS 2026-10-31(규정상 high), WORKFLOW 6장(동기화는 high)과 충돌한다. 새 키를 만들지 않아도 high다.

## 질문별 사실 확인
**① 화해 로직 회귀(C5·C13)**: v1에서 pull 결과 데이터는 main과 바이트 단위로 같아야 한다. `applyImportedPayload`·`reconcileAdditiveMerge`의 입출력은 바꾸지 않고, 덮인 항목 감지는 따로 순수 함수(before·after·기준점 → 목록)로 만들어 부수효과를 없앤다. 이 함수는 저장·push·`notifyAssetUserEdit`를 호출하지 않는다(C16). 수용 기준 3에 "기존 테스트를 그대로 통과" 외에 "같은 입력에서 main과 출력이 같음" 비교를 추가한다. 감지 결과는 1인 다기기 사용자에게도 보이므로 오탐 방지가 핵심이다.
- **결함 의심(qa 확인 요청)**: 항목에 `currentPrice` 같은 파생 필드가 저장된다(`types/asset.ts`). 시세 갱신은 push하지 않는다(provider 38~42행). 그래서 항목 전체를 해시하면 시세만 바뀐 항목도 "내가 고침"으로 잡힌다. 지문은 사용자 입력 필드만으로 만들고, 덮인 항목은 "로컬 ≠ 기준점이면서 로컬 ≠ 원격"(사용자 필드 기준)일 때만 표시해야 한다. 이 조건이 없으면 FAIL이다.

**② syncedHashes 저장 위치**: `secretasset_sync` 객체 안에 필드로 두는 것을 허용한다. 새 localStorage 키가 아니다. 근거는 다음과 같다.
- `clearAssetData`의 keepKeys에 syncState가 있다(asset-storage 408행). 따라서 pull이 지우지 않는다.
- `patch()`는 객체 전체를 병합해 다시 쓴다.
- 필드를 골라 다시 쓰는 곳은 `forgetRemembered` 1곳뿐이다(sync-state 103~105행). 여기에 `syncedHashes`를 추가해야 하고, 이를 테스트로 고정한다.
- `clearSyncState`(연결 끊기)가 지우는 것은 맞는 동작이다.
- 추가 요구: 기준점에 버전을 함께 저장한다(`syncedHashesVersion` = markSynced 버전). 저장된 버전이 현재 버전과 다르면 기준점을 무시하고 현행 동작으로 폴백한다. 이렇게 해야 롤백 뒤 재업그레이드나 구버전 기기 혼재로 기준점이 낡았을 때 대량 오탐이 나지 않는다(C6·C14).
- 새 키가 필요해지면 그대로 high이며, 마이그레이션과 복원 테스트가 필수다.

**③ 가족 기기의 기존 자산 삭제**: 사실이다. 연결은 `merge:false`이고, 기존 경고는 빨간색이 아니라 amber 박스이며 버튼이 destructive다. spec의 백업 권유 1줄로는 부족하다. 다이얼로그를 닫으면 `clearPendingConnect`가 해시를 지워서, 백업하러 나갔다 오면 링크를 다시 열어야 한다. 요구 사항은 다음과 같다.
- (a) `hasAssets`일 때 다이얼로그 안에 "먼저 백업 받기" 버튼을 둔다. 기존 데이터 백업 내보내기 핸들러를 재사용하고, 다이얼로그는 유지한다. iOS WKWebView·PWA에서 동작해야 한다(C19).
- (b) 이 기기가 이미 다른 금고에 연결돼 있으면 "기존 금고 연결이 끊긴다" 1줄을 추가한다. `aid !== getAssetId()` 조건이라 이미 연결된 배우자 기기도 이 다이얼로그에 들어온다.

**④ 고지 문구 사실성**: "링크와 금고 암호를 모두 아는 사람"은 정확하다(`deriveKeys(passphrase, assetId)`, 링크와 `sync:` 코드에는 assetId만 있다). "권한 회수 불가"도 사실이다(서버에 DELETE·암호 변경이 없다). 다만 "새 금고를 만들어 옮기면 막을 수 있다"는 일부만 사실이다. 이전 금고와 가족 기기에 이미 받은 자산은 남는다. 문구를 "막으려면 새 금고를 만들어 옮겨야 하고, 이미 받은 자산은 그 기기에 남아요"로 고친다. 동기화 코드도 같은 권한이라는 안내를 카드에 1줄 넣는다(선택 아님). 투자 조언·금액 표현은 없다.

**⑤ 일정**: 원안(ⓑ·다시 적용·기준점 저장·UI 2곳·GA)으로 11/26 qa PASS는 비현실적이다. 동기화 high는 C5·C13·C14 순환 테스트가 필요하다. 또 preview에서 동기화 UI가 렌더되지 않아(C10) UI 검수·C25 스크린샷은 provider mock을 쓰는 테스트 하네스로만 찍을 수 있다. 이 하네스를 design-review에서 확정하지 않으면 qa가 막힌다. 축소안(합친 카드와 가족 보내기 버튼, 백업 버튼, 덮인 항목 감지·알림, GA source)이면 가능하다. 11/26까지 PASS가 아니면 결산 창(11/27~12/10)에는 무접촉 동결하고 12/11 재개한다. 재개 때 쪼개는 순서는 연결 블록·고지·백업을 먼저, 감지·알림을 나중으로 한다.
