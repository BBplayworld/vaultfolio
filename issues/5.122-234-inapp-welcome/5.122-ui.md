# 5.122 #234 인앱 웰컴 둘러보기 보조 버튼 — UI 사양 (ui-designer, 2026-11-16)

기준: main a1043d3(v5.121) `welcome-guide.tsx` 93·141·193·204~213·301~323·346~412, `in-app-browser-gate.tsx` 42~61. 운영 `https://www.secretasset.xyz` 실측(Playwright UA: Threads·카카오톡·Instagram × iOS·Android, 뷰포트 높이 844, GA 요청은 차단하고 캡처). 캡처 `screenshots/ui/` — `main-*` = 운영 현황, `mock-*` = 운영 DOM에 보조 버튼을 주입한 시안(구현 아님). 코드 수정 0.

## 1. 현황 (실측)
- 인앱 6종 UA 모두 `data-state="inapp"`, 배치 동일. 버튼 자리(`welcome-cta-slot`) 높이 216, 안쪽 내용 140(제목 2줄) → **주 버튼 아래 44px이 비어 있다**(430은 제목 1줄, 72px 빔).
- 칩 `직접 둘러보기`는 인앱에도 있다(y=218). 320·360에서는 칩이 제목 줄에 못 들어가 한 줄 더 차지한다(+24px).
- iOS 주 버튼 누름 → 가이드 396.5px(375)·419.3px(320)이 버튼 아래로 펼쳐진다.

## 2. 결정
**① 보조 버튼**
- 문구: **`예시로 먼저 둘러보기`**. '직접 둘러보기'는 '예시 데이터' 배지 옆에서만 뜻이 통하는 문구라 버튼 자리로 옮기면 무엇을 직접 하는지 알 수 없다. '예시로'(내 자산 아님) + '먼저'(이동 전에 가능) + '둘러보기'(칩과 같은 동사, `/ratio` '예시로 먼저 보기'와 같은 어순). 일반 브라우저 칩 문구는 그대로.
- variant: **`Button variant="secondary" size="lg"`**. design-system §5 버튼 규약(보조 = secondary, `outline` 신규 사용 지양)과 §12 `/ratio` 선례(brand 주 버튼 + secondary 보조)를 따른다. ghost 시안(`mock-ghost-*`)은 글자만 남아 각주처럼 읽혀 '둘러보기가 눈에 띄지 않는다'는 과제 문제를 그대로 남긴다. → **planner-designer 수정 요청: AC-4 '보조는 outline 또는 ghost'를 'brand가 아닌 secondary'로**(의도인 'brand 1개'는 그대로).
- 구성: `문구 + ArrowRight(size-4, text-brand, aria-hidden)` — 칩과 같은 화살표. 진행 중에는 화살표 자리에 `Loader2`(`motion-safe:animate-spin`), `disabled` + `aria-busy`.
- 위치: 주 버튼 바로 아래 8px(`gap-2`). 버튼 묶음 래퍼만 `flex justify-center` → `mx-auto flex w-full flex-col gap-2 sm:w-fit`로 바꾸고 보조 버튼은 `w-full gap-2 break-keep`. 주 버튼 클래스·문구·좌표는 diff 0(375에서 x28 y744 w319 h40 그대로). sm 이상에서는 두 버튼이 넓은 쪽(주 버튼 244px)에 맞춰 같은 폭이 된다(주입 시안의 199px 불일치는 이 래퍼로 해소).
- 동작: `WelcomeTrialLink`의 연타 1회 처리(`firedRef` + `busy`)와 `trackThenNavigate` + `TRIAL_ENTRY_URL`을 그대로 쓰고 source만 붙인다. 새 모션 0(슬롯 기존 fade-in 200ms 안에서 함께 나타남, 누름은 Button 내장 scale 0.96).

**② 버튼 자리 높이** — `min-h-[216px] sm:min-h-[160px]`는 바꾸지 않는다(세 상태가 같이 쓰는 셸, 일반 브라우저 diff 0).

- 빈 44px을 보조 버튼(8+40)이 채워 375·390은 +4px뿐이다. 판별 전(216) → 인앱(220) 전환 때 아래 내용이 4px 밀리지만 첫 화면 밖이다.
- **위험(planner·cto 확인 요청)**: 실제 인앱 화면은 앱 상·하단 바 때문에 높이가 650~700px 안팎이다. 보조 버튼(375에서 y 792~832)은 주 버튼(744~784)과 함께 첫 화면 밖이고, 지금 칩(y 218)은 첫 화면 안이다. 칩을 숨기면 첫 화면 안의 체험 진입이 0이 된다. 범위(진입 1개) 안에서 내가 바꿀 수 있는 것은 없으며, '체험 모드·인앱' 1/3 기준 판독 때 이 조건을 같이 적어야 한다.

**③ 칩 깜빡임 방지** — 칩 조건을 `mounted && …`에서 **`ctaState === "asset" && allowTrial && !restoreHash`**로. 보조 버튼은 `ctaState === "inapp" && allowTrial && !restoreHash`. 둘 다 같은 값(`ctaState`)에서 갈라지므로 한 렌더에 칩과 보조 버튼이 같이 있거나 칩이 먼저 뜨는 경우가 구조상 없다. 지금은 `usePWAInstall`의 effect와 `setMounted`가 같은 묶음으로 반영돼 우연히 맞는 상태다.

**④ 폭·테마 기대치** — 인앱은 모바일 전용이라 1280은 대상이 아니다. 검수 폭: 다크 320·360·375·390·430, 라이트 320·375·390, sm 경계 확인용 768 다크 1장.
- 보조 버튼 문구 1줄(글자 폭 133px + 화살표, 320에서 버튼 폭 264px). 높이 40, 폭 264(320)·319(375)·334(390)·374(430).
- 다크: 배경 `--secondary`(oklch 0.31) 위 밝은 글자. 라이트: 배경 oklch 0.895 위 어두운 글자. 두 테마 모두 brand 면은 주 버튼 1개.

**⑤ testId** — 보조 버튼 `welcome-inapp-trial`(칩 `welcome-trial-link`와 분리해 AC-2 '칩 없음'을 그대로 판정). 기존 `welcome-cta-slot`·`welcome-cta-inapp`·`welcome-inapp-guide`·`welcome-inapp-caption` 유지.

## 4. 품질 체크리스트 (ui-review·qa)
1. 인앱 UA 6종 × 375 다크: `welcome-trial-link` 0개, `welcome-inapp-trial` 1개, 화면 전체 체험 진입 1개.
2. 문서 시작부터 관찰(MutationObserver)했을 때 인앱에서 `welcome-trial-link`가 한 번도 DOM에 생기지 않는다.
3. 주 버튼 좌표·크기·문구·배경색이 main 캡처와 같다(375: x28 y744 w319 h40).
4. 보조 버튼은 주 버튼 아래 8px, 좌우 끝이 주 버튼과 같다(320~430, 768 모두).
5. 보조 버튼 높이 40 이상, 문구 1줄, 어절 중간 끊김 0(320·360·375, 캡처로 판정 — C25·C114).
6. brand 배경 버튼은 버튼 자리에 1개. 보조 버튼 배경 computed 값이 `--secondary`.
7. 버튼 자리 높이가 2절 표와 ±1px(320 240 / 360·375·390 220 / 430 216 / 768 211).
8. iOS 가이드 펼침 전·후 보조 버튼 좌표가 같고 가이드와 겹침 0(320·375, 실제로 눌러 캡처 — C113).
9. 보조 버튼을 빠르게 2번 눌러도 이동 1회, 누른 뒤 로더 표시 + `disabled`.
10. 라이트 320·375·390: 보조 버튼 글자·배경 구분이 뚜렷하고 카드 면과 버튼 면이 구분된다.
11. 일반 브라우저·설치 앱 UA: 칩 있음, 보조 버튼 0개, main과 캡처 diff 0(375·390·1280).
12. 복원 링크(`#share`) 인앱 진입: 보조 버튼·칩 모두 0개.
13. `prefers-reduced-motion`: 로더 회전·누름 scale 없음, 배치 동일.
14. C120: 3절 표의 모든 행을 preview 화면으로 1회 이상 캡처(설치 앱은 display-mode 흉내, 판별 전은 JS 차단 캡처).
