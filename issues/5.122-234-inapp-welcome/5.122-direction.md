## 경험 절 (planner-designer)
- **누구**: Threads·카카오톡·Instagram 글의 링크를 눌러 앱 안 브라우저로 처음 온, 자산 0건인 사람. 지금은 버튼 자리에 '외부 브라우저에서 시작하기'만 있고(346~), 둘러보기는 미리보기 제목 옆 작은 칩(193)뿐이다.
- **이후 관찰 가능한 행동**: 인앱 웰컴의 버튼 자리에서 보조 버튼을 눌러 예시 화면(`/?trial=1`)을 본다. 팀은 GA '페이지 및 화면' 표에서 인앱 도착 기기 수와 그중 둘러보기를 누른 기기 수를 title 행으로 읽는다.
- **인앱 웰컴 흐름**: 도착 → 버튼 자리에 주 버튼(현행)과 보조 버튼이 함께 보인다 → 보조 버튼 → 체험 홈(현행 배너 '내 자산으로 시작' → 외부 이동, 현행).
- **바뀌는 곳**: ① 인앱 상태(`ctaState === "inapp"`) 버튼 자리에 보조 버튼 1개 추가(동작은 `WelcomeTrialLink`와 같은 `trackThenNavigate` + `TRIAL_ENTRY_URL` 재사용) ② 인앱 상태일 때만 '직접 둘러보기' 칩 숨김 ③ GA title 분리(spec 표).
- **그대로인 곳**: 일반 브라우저·설치 앱 웰컴 전체, 인앱 주 버튼의 위치·문구·색, 제목 '자산 등록은 Chrome·Safari에서 시작해요', '이 화면에서는 입력한 내용이 사라질 수 있어요.', iOS 주소 복사 가이드, 체험 화면·배너, 인앱 게이트(자산 보유자), `/ratio`, 가이드.
- **줄이는 것**: 인앱 화면의 체험 진입을 2개가 아니라 1개로(칩 숨김). '앱 설치' 한 행에 섞인 5가지 의미를 3행으로 나눈다.
- **하지 않을 것**: iPhone 자동 이동 방식, 주 버튼 교체·순서 변경, 문구 수정, 체험 중 GA 켜기(4.38 결정), 새 URL, 맞춤 정의(11-06 결정), 인앱 판별 토큰 추가(`IN_APP_BROWSER_RE` diff 0), 새 소식 등록(기존 사용자에게 보이지 않음), 저장·서버·동기화 변경.
- **엣지**
  - Threads(`barcelona`)·카카오톡·Instagram, iOS·Android 모두 같은 배치다. 차이는 주 버튼 결과뿐(Android 자동 이동, iOS 주소 복사 + 가이드 펼침 — 현행).
  - iOS에서 가이드가 펼쳐진 뒤에도 보조 버튼은 같은 자리에 남고 가이드는 그 아래에 열린다.
  - 인앱 판별 실패(목록에 없는 앱): 일반 화면(asset 상태) 그대로, title도 '웰컴'. 이번에 고치지 않는다.
  - 인앱 + 복원 링크(`#share`·`#sync`)·공유 대기·자산 보유: 게이트가 덮으므로(62) 웰컴이 보이지 않는다. 보조 버튼 조건은 칩과 같게(`allowTrial && !restoreHash`) 둔다.
  - 마운트 전(pending): 칩·버튼 모두 없음(현행). 인앱 첫 로드에서 칩이 잠깐 보였다 사라지지 않아야 한다.

## spec
**문제**: 인앱 도착자는 등록이 막혀 있고 둘러보기 진입이 눈에 띄지 않는다. 몇 명이 그 화면을 보는지 GA로 알 수 없다(source·method 미전송, `ga.ts` 5~7).
**목표 행동**: 인앱 도착자가 버튼 자리에서 둘러보기를 누른다. 팀이 title 행으로 인앱 도착·둘러보기·이동 누름 기기 수를 읽는다.

**사용자 흐름**
1. 인앱에서 `/` 도착(자산 0건) → 웰컴. 미리보기 제목 옆 칩 없음.
2. 버튼 자리: 제목·안내 문구(현행) → 주 버튼 '외부 브라우저에서 시작하기'(현행) → 그 아래 보조 버튼.
3. 보조 버튼 → `/?trial=1` 체험 홈(현행). 연속 누름은 1회만 처리.
4. 주 버튼 → Android 자동 이동 / iOS 주소 복사 + 가이드(현행).

**신규 GA title (4개, 맞춤 정의 0)**
| title | 발생 조건 | main에서의 title |
|---|---|---|
| 웰컴·인앱 | `welcome_view`, source=inapp | 웰컴 |
| 체험 모드·인앱 | 인앱 웰컴 보조 버튼 누름(`feature_use` demo + source=inapp), 이동 직전 1회 | 체험 모드 |
| 인앱·외부 이동 | `pwa_install` method=inapp_move(웰컴 인앱 주 버튼, 인앱 게이트) | 앱 설치 |
| 앱 설치·설치창 | `pwa_install` method=prompt_view·accepted·dismissed | 앱 설치 |

불변: '앱 설치' = method=installed만. '웰컴'(source=web·pwa), '체험 모드'(일반 브라우저 칩), '가이드·체험', '웰컴·체험', `/ratio` 자체 이벤트. 체험 중에는 전부 미전송(체험 배너의 이동 누름 포함, 수용한 한계).

**상태별 배치 표 (C119)**
| 상태 | 둘러보기 칩(미리보기 제목 옆) | 버튼 자리 주 버튼 | 버튼 자리 보조 버튼 | 도착 title |
|---|---|---|---|---|
| 일반 브라우저 | 있음(현행) | 자산 등록 묶음(현행) | 없음 | 웰컴 |
| 설치 앱 | 있음(현행) | 자산 등록 묶음(현행) | 없음 | 웰컴 |
| 인앱 iOS | **없음** | 외부 브라우저에서 시작하기(현행) + 누르면 가이드 펼침 | **있음**(가이드 위) | 웰컴·인앱 |
| 인앱 Android | **없음** | 외부 브라우저에서 시작하기(현행, 자동 이동) | **있음** | 웰컴·인앱 |
| 체험 중(`?trial=1`) | 웰컴 없음 | 배너 '내 자산으로 시작'(현행) | 없음 | 없음(GA 꺼짐) |
| 복원 링크·공유 대기 | 없음(현행) | 현행 | 없음 | 현행 |

일반 브라우저·설치 앱의 칩 '현행 유지' 이유: 버튼 자리가 등록 버튼으로 차 있어 칩이 유일한 체험 진입이다. 통합 목표(진입 1개)와 맞다.

**지표 단위 전수 대조표**
| 항목 | 정본 위치 | 나머지 처리 |
|---|---|---|
| 체험 진입(인앱) | 버튼 자리 보조 버튼 | 칩 숨김 |
| 체험 진입(일반·설치 앱) | 칩 | 변경 없음 |
| 외부 이동 안내 | 버튼 자리 주 버튼 | 체험 배너 버튼은 체험 화면 전용(현행) |

**완료 기준 (AC, qa 그대로 검사)**
- AC-1 일반 브라우저·설치 앱 UA에서 웰컴 화면이 main과 같다(칩 있음, 버튼 자리에 보조 버튼 없음, 캡처 비교 diff 0). 도착 title은 '웰컴'.
- AC-2 인앱 UA(Threads·카카오톡·Instagram × iOS·Android)에서 웰컴에 `welcome-trial-link` 칩이 없고, 버튼 자리에 보조 버튼이 1개 있다. 화면 전체에서 체험 진입은 1개다.
- AC-3 인앱에서 보조 버튼을 누르면 `/?trial=1` 체험 홈이 열린다. 빠르게 두 번 눌러도 이동·이벤트는 1회다.
- AC-4 인앱 버튼 자리의 제목·안내 문구·주 버튼 문구와 순서(주 버튼이 보조 버튼보다 위)가 main과 글자 단위로 같다. brand 색 버튼은 주 버튼 1개, 보조는 outline 또는 ghost.
- AC-5 iOS 인앱에서 주 버튼을 누르면 가이드가 펼쳐지고, 보조 버튼은 사라지거나 밀려 겹치지 않는다. 보조 버튼 히트영역 40×40px 이상.
- AC-6 `featureTitleOf` vitest가 다음을 고정한다: welcome_view inapp→'웰컴·인앱', web·pwa→'웰컴' / pwa_install installed→'앱 설치', inapp_move→'인앱·외부 이동', prompt_view·accepted·dismissed→'앱 설치·설치창' / demo+inapp→'체험 모드·인앱', demo(source 없음)→'체험 모드', 가이드 화면 demo→'가이드·체험'. 신규 title은 4개뿐이다.
- AC-7 gtag로 나가는 값은 page_title·page_location뿐이다(매개변수 추가 0). 체험 페이지에서는 전송 0.
- AC-8 320·375 폭에서 보조 버튼 문구가 어절 중간에서 끊기지 않는다(C25). 인앱 첫 로드에서 칩이 깜빡이지 않는다.
- AC-9 판별 목록에 없는 UA는 일반 화면 그대로다(`IN_APP_BROWSER_RE` diff 0).
- AC-10 머지 시각이 4.86·5.115·#48 판독 메모 3곳에 기록된다(연속 비교는 '웰컴 + 웰컴·인앱', 전환율은 '웰컴'만, '알림 켜기 ÷ 앱 설치'는 머지 이후 구간만).
