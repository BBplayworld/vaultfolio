## spec
**문제**: 인앱 도착자는 등록이 막혀 있고 둘러보기 진입이 눈에 띄지 않는다. 몇 명이 그 화면을 보는지 GA로 알 수 없다(source·method 미전송, `ga.ts` 5~7).
**목표 행동**: 인앱 도착자가 칩 또는 버튼 자리 보조 버튼으로 둘러보기를 누른다. 팀이 title 행으로 인앱 도착·둘러보기(칩/버튼 구분)·이동 누름 기기 수를 읽는다.

**사용자 흐름**
1. 인앱에서 `/` 도착(자산 0건) → 웰컴. 미리보기 제목 옆 칩은 main과 같은 자리(현행).
2. 버튼 자리: 제목·안내 문구(현행) → 주 버튼 '외부 브라우저에서 시작하기'(현행) → 그 아래 보조 버튼.
3. 칩 또는 보조 버튼 → `/?trial=1` 체험 홈(현행). 연속 누름은 1회만 처리.
4. 주 버튼 → Android 자동 이동 / iOS 주소 복사 + 가이드(현행).

**신규 GA title (5개, 맞춤 정의 0)**
| title | 발생 조건 | main에서의 title |
|---|---|---|
| 웰컴·인앱 | `welcome_view`, source=inapp | 웰컴 |
| 체험 모드·인앱 | 인앱 웰컴에서 칩 누름(`feature_use` demo + source=inapp), 이동 직전 1회 | 체험 모드 |
| 체험 모드·인앱 버튼 | 인앱 웰컴 버튼 자리 보조 버튼 누름, 이동 직전 1회 | 없음(신규 진입) |
| 인앱·외부 이동 | `pwa_install` method=inapp_move(웰컴 인앱 주 버튼, 인앱 게이트) | 앱 설치 |
| 앱 설치·설치창 | `pwa_install` method=prompt_view·accepted·dismissed | 앱 설치 |

불변: '앱 설치' = method=installed만. '웰컴'(source=web·pwa), '체험 모드'(일반 브라우저 칩), '가이드·체험', '웰컴·체험', `/ratio` 자체 이벤트. 체험 중에는 전부 미전송(체험 배너의 이동 누름 포함, 수용한 한계).

**상태별 배치 표 (C119)**
| 상태 | 둘러보기 칩(미리보기 제목 옆) | 버튼 자리 주 버튼 | 버튼 자리 보조 버튼 | 도착 title |
|---|---|---|---|---|
| 일반 브라우저 | 있음(현행) | 자산 등록 묶음(현행) | 없음 | 웰컴 |
| 설치 앱 | 있음(현행) | 자산 등록 묶음(현행) | 없음 | 웰컴 |
| 인앱 iOS | 있음(현행, 제목 옆) | 외부 브라우저에서 시작하기(현행) + 누르면 가이드 펼침 | **있음**(가이드 위) | 웰컴·인앱 |
| 인앱 Android | 있음(현행, 제목 옆) | 외부 브라우저에서 시작하기(현행, 자동 이동) | **있음** | 웰컴·인앱 |
| 체험 중(`?trial=1`) | 웰컴 없음 | 배너 '내 자산으로 시작'(현행) | 없음 | 없음(GA 꺼짐) |
| 복원 링크·공유 대기 | 없음(현행) | 현행 | 없음 | 현행 |

칩 '현행 유지' 이유: 일반 브라우저·설치 앱은 버튼 자리가 등록 버튼으로 차 있어 칩이 유일한 체험 진입이다. 인앱은 칩이 첫 화면 안의 유일한 진입이고, 보조 버튼은 '등록이 막힌 자리의 대안'으로 위치와 역할이 다르다(cto 7절). 누름 title은 일반·설치 앱 칩 '체험 모드', 인앱 칩 '체험 모드·인앱', 인앱 보조 버튼 '체험 모드·인앱 버튼'.

**지표 단위 전수 대조표**
| 항목 | 정본 위치 | 나머지 처리 |
|---|---|---|
| 체험 진입(인앱) | 칩(첫 화면 안, 현행) | 버튼 자리 보조 버튼 1개 추가(등록이 막힌 자리의 대안). title로 구분, 0기기면 제거 |
| 체험 진입(일반·설치 앱) | 칩 | 변경 없음 |
| 외부 이동 안내 | 버튼 자리 주 버튼 | 체험 배너 버튼은 체험 화면 전용(현행) |

**완료 기준 (AC, qa 그대로 검사)**
- AC-1 일반 브라우저·설치 앱 UA에서 웰컴 화면이 main과 같다(칩 있음, 버튼 자리에 보조 버튼 없음, 캡처 비교 diff 0). 도착 title은 '웰컴'.
- AC-2 인앱 UA(Threads·카카오톡·Instagram × iOS·Android)에서 웰컴의 `welcome-trial-link` 칩은 main과 같은 자리에 그대로 있고, 버튼 자리에 보조 버튼(`welcome-inapp-trial`)이 1개 있다. 체험 진입은 칩 1개 + 보조 버튼 1개다.
- AC-3 인앱에서 칩 또는 보조 버튼을 누르면 `/?trial=1` 체험 홈이 열린다. 빠르게 두 번 눌러도 이동·이벤트는 1회다.
- AC-4 인앱 버튼 자리의 제목·안내 문구·주 버튼 문구와 순서(주 버튼이 보조 버튼보다 위)가 main과 글자 단위로 같다. brand 색 버튼은 주 버튼 1개, 보조는 `secondary`.
- AC-5 iOS 인앱에서 주 버튼을 누르면 가이드가 펼쳐지고, 보조 버튼은 사라지거나 밀려 겹치지 않는다. 보조 버튼 히트영역 40×40px 이상.
- AC-6 `featureTitleOf` vitest가 다음을 고정한다: welcome_view inapp→'웰컴·인앱', web·pwa→'웰컴' / pwa_install installed→'앱 설치', inapp_move→'인앱·외부 이동', prompt_view·accepted·dismissed→'앱 설치·설치창' / demo+inapp(칩)→'체험 모드·인앱', demo+inapp(보조 버튼)→'체험 모드·인앱 버튼', demo(source 없음)→'체험 모드', 가이드 화면 demo→'가이드·체험'. 신규 title은 5개뿐이다.
- AC-7 gtag로 나가는 값은 page_title·page_location뿐이다(매개변수 추가 0). 체험 페이지에서는 전송 0.
- AC-8 320·375 폭에서 보조 버튼 문구가 어절 중간에서 끊기지 않는다(C25). 인앱에서 칩의 위치·문구·조건은 main과 같다(칩 관련 diff 0).
- AC-9 판별 목록에 없는 UA는 일반 화면 그대로다(`IN_APP_BROWSER_RE` diff 0).
- AC-10 머지 시각이 4.86·5.115·#48 판독 메모 3곳에 기록된다(연속 비교는 '웰컴 + 웰컴·인앱', 전환율은 '웰컴'만, '알림 켜기 ÷ 앱 설치'는 머지 이후 구간만).

**qa 항목**: preview 캡처 = 인앱 UA 4종(Threads iOS·Android, 카카오톡 iOS·Android) + Instagram 1종 + 일반 브라우저·설치 앱 대조, 각 320·375. iOS는 가이드 펼침 전·후 2장. C119 표 전 행, C122(title마다 전송 코드 줄 확인), 데이터 안전(저장 키·스키마 diff 0).

**ui-designer에게 넘기는 것**: 보조 버튼 문구·간격(variant는 `secondary` 확정), 버튼 자리 최소 높이(`min-h-[216px]`) 영향. 칩 조건 변경은 없다.
**승인 트랙 전환 조건(cto)**: 주 버튼 교체·순서 변경, '사라질 수 있어요' 문구 수정, 일반 브라우저 diff 발생.
**성공·폐기(머지 후 2주, 절대 기기 수)**
- 가설 폐기: '웰컴·인앱' 2주 합계 0~1기기(LEARNINGS 기록, 홍보 도착지 `/ratio` 쪽으로 넘김).
- 유지: '웰컴·인앱' ≥ 주 2기기이고 ('체험 모드·인앱' + '체험 모드·인앱 버튼') ≥ 그 1/3.
- 보조 버튼 제거: '웰컴·인앱' ≥ 4기기인데 '체험 모드·인앱 버튼' 0기기면 버튼을 빼고 칩만 남긴다(줄이기).
- 도착은 있는데 진입이 1/3 미만이면 첫 화면 안 배치를 대표 승인 트랙 후보로 올린다.
