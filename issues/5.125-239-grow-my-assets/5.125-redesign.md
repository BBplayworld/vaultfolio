## 0. 피로 지점 (현재 390 첫 화면 기준)
- 요약 6줄(막대 1 + 범례 3 + 연결 문장 2)에 금액이 없다. "그래서 얼마나 달라졌나"가 답해지지 않는다.
- 행마다 사실 6줄(비중·매입가 대비 / 이름표 / 주기 / 가격 / 수량 / 매매 건수)에 3택 버튼과 점검 버튼까지 있어, 3행이 화면 한 장을 다 쓴다.
- 행 안에 기준이 다른 %가 2개(`내 매입가 대비`, `정한 날 가격 대비`) 있다. 막대는 범례 숫자를 다시 그린 것이라 새 정보가 없다.

## 1. 정보 위계 (위 → 아래, 390×844 첫 화면에 ①~③)
① **종합 카드**: 결론 1문장 + 이름표별 2줄 + '앞으로' 2줄
② **종목 줄**: 이름표 붙은 종목, 행당 2줄 셀(이름 / 정한 뒤 효과). 상위 3행과 `전체 보기`(기존 대표 예외 규칙 유지, 주기 지난 행은 접지 않음)
③ `점검 주기 3개월 ›` 설정 줄 1개
- 행을 누르면 **그 자리에서 펼침**: 세부 사실, 이름표 3택, `오늘 점검했어요`, `종목 페이지 보기 ›`. 지금 행 전체가 하는 종목 페이지 이동은 펼침 안 링크로 옮긴다.
- 이름표 0개(첫 사용자)일 때만 행에 3택을 바로 펼쳐 둔다(설정 모드). 1개라도 붙이면 ①②로 바뀐다.

## 4. 예측되는 효과 — 허용 2종, 금지 목록
- **배당**: `지금 수량이면 1년 약 N원 · 가정` = 오래 둘 키별 Σ(올해 주당 배당[지급+예정] × 지금 수량 × 환율). 예정분은 기존 서버의 `isEstimated`(전년 패턴 추정)이고, 배당 카드와 같은 출처다.
- **점검일**: `다음 점검 = 주기 기준일(cycleBase) + 주기 개월`. 지난 행은 `지금`으로 표시한다. 시장과 무관한 내 일정이다.
- **가정 표시**: 값 뒤에 muted 글자 `· 가정`을 붙이고, 제목 InfoHint에 한 문단을 둔다. `1년 배당은 올해 받았거나 받을 배당이 내년에도 같고, 지금 수량을 그대로 둔다고 가정한 계산이에요. 시세나 수익을 예상하지 않아요.`
- **금지**: 정한 뒤 수익률의 연환산·외삽(`이대로면 1년 뒤 +N원`), 목표가, 시장 전망, 수익률 예측, 이름표끼리 앞으로의 비교.

## 6. 데이터 — 계산식과 출처 (grow-rows.ts 기준, 새 함수는 같은 파일에 추가)
| 숫자 | 계산식 | 출처·재사용 |
|---|---|---|
| 행 정한 뒤 금액 | `held = min(base.qty, 지금 수량)`, `effect = held × (지금 시세 − base.price) × 지금 환율 배수` | base `stock-labels.ts:20-31`, 저장 `grow-rows.ts:147-164`, 지금 수량 `qtyByLabelKey :133-141`, 지금 시세 `:247-252`, 배수 `getMultiplier`(`:117`). 새 필드 `GrowRow.effect{amount,basis}` |
| 행 % | `(지금 시세 − base.price) ÷ base.price` | 기존 `priceFactOf :180-189` 그대로 |
| 종합·이름표별 금액, % | Σeffect, Σeffect ÷ Σ(held × base.price × 배수) | `summarizeGrowRows :328-362`에 합계 필드를 추가한다 |
| 비중 | 기존 무게 값 | `summarizeGrowRows :354-356` `weights.*.pctText` |
| `N개월째`·`주기 지남` | 붙인 뒤 경과, 주기 경과 | `elapsedSince :28-36`, `formatSince :53-57`, overdue `:266-269` |
| 수량 `10→12주`/`수량 그대로` | base.qty vs 지금 | `qtyFactOf :167-174`(문구만 축약) |
| 다음 점검일 | cycleBase + 주기 개월(말일 당김) | `cycleBase :95-99`, `threeMonthsBefore :201-208`을 n개월 앞으로 일반화 |
| 1년 배당 | Σ 올해 payout.amountPerShare × 지금 수량 × rate(매수일 필터 없이) | `performance-hub.tsx:31-82` 같은 루프에 `yearByLabelKey` 맵 1개를 추가한다(`:62-70`) |
| 매매 건수(펼침) | 기존 | `tradeCountsByLabelKey :216-228` |
| 금액·부호 표기 | 만원 단위 버림, 손익색 | `formatShortCurrency`(`number-utils.ts:27`), `profitTone`(`detail-summary-header.tsx:95`) |

- 환율은 정한 날 값을 저장하지 않으므로 지금 환율로 양쪽을 같게 환산한다. 결과는 가격 변화만 반영하고, InfoHint에 `환율은 지금 환율로 계산해요`를 적는다.
- `held`를 min으로 잡은 이유: 정한 뒤 산 수량은 정한 날 가격으로 산 게 아니고, 판 수량의 이후 등락은 내 돈이 아니다. 그래서 '정한 날부터 계속 가진 만큼'만 센다. 액면분할은 기존 한계로 남긴다.
- 서버로 가는 값은 0건 늘어난다(계산은 모두 기기 안에서 한다). GA는 기존 그대로이고 금액은 보내지 않는다.

## 7. 추천 아님 경계 (바뀐 점만)
- 금액 표시는 허용한다. 앱 안 내 데이터라 마케팅 금액 금지와 다르다. 다만 화면 공유 PNG 대상이 아니면 `data-screenshot-hide`를 기존 규칙대로 둔다.
- 손익색을 다시 도입한다. 대표 피드백에 맞춰 앱 전체 규약으로 되돌린다. 이전 '이름표 블록 무채색' 예외는 폐지한다.
- 순서는 늘 `오래 둘 → 점검할` 고정이다. 효과순 정렬은 없고, `더`·`보다 많이`·`잘한` 같은 비교·평가어도 쓰지 않는다. 문장은 `정한 날보다`처럼 사실 기준을 주어로 둔다.
