## 0. 결론 먼저 — 6절 ③은 **#250과 무관한 기존 결함**(재현됨)
| 재현(시작=레거시 일별, 끝=enrich) | 결과 |
|---|---|

| 같은 예측 구간의 월 결산 매핑(`estimatedPriceAsUnrecorded`) | `기록 안 된 변화 +500만 · 예측`(정상) |
- 원인: `asset-report.ts` `resolveAttribution` 예측 분기(892~939)에 `cash` 키가 없다. `estimatePeriodInflows`(632~691)는 주식·코인·부동산·실물·대출만 추정하고 현금은 0 → 현금 증감이 전부 잔차 `price`로 간다. 대출은 breakdown 없으면 `startDate`만 본다.
- 노출 화면: **Hero 원인 줄·펼침**(`dashboard.tsx` `useHeaderNetChange` → `computeAttributionView` → `getAttributionItems`)과 자산 변화 › 원인 목록(`asset-change-view.tsx`). 7일 카드·주 탭(`weekLineOf` price→unrecorded)·월/연 결산(`estimatedPriceAsUnrecorded`)은 이미 `기록 안 된 변화`라 안전.
- 해당 기기(운영): 시작점이 레거시인 경우만 — ① 공유 링크로 복원한 기기(packV7은 daily/monthly를 netAsset·financialAsset만 담음, `asset-storage.ts` 189) 복원 후 30일 이내 ② v2 enrich 도입(4.18, 2026-07-23) 이전 월 기록만 남은 채 30일 넘게 쉬다 온 기기. `saveSnapshots`는 이후 항상 breakdown·fx·fxBase·cost를 함께 쓰므로 breakdown만 있고 cost 없는 기록은 운영에 사실상 없다 → **spec 6절 ③의 "breakdown 있는 구간만 분리" 안은 실제 기기를 거의 고치지 못한다.**
- **판정·권고**: 기존 결함(`예측` 배지는 붙음, 빈도 낮음). 운영 이상 p0 빠른 경로 기준(즉시 피해·광범위)은 아니다 → **별도 `type:bug` `priority:p2` 이슈 생성 권고**, 열린 릴리스 규칙상 v5.134 같은 PR에 `Closes`로 함께 담는다(#250이 현금 등록을 유도해 노출을 늘리므로 #250 머지 전 수정 필수 — direction 중단 조건 충족 경로).
- **수정안(최소, 권고)**: `estimatePeriodInflows`에 현금·대출 **등록일 추정** 추가 — 4.94 `assetIdRegisteredDate`(`settlement.ts` 91, id의 13자리 ms, `cash_${Date.now()}`·`cash_import_…`·`loan_…` 모두 해당) 재사용. 구간 안 등록 현금 → `cash` 키(+잔액, 외화는 현재 환율 환산, estimated), 대출은 `startDate`가 구간 밖이고 등록일이 구간 안일 때만 `debt`(−잔액), `loanTxLoanIds` 제외 유지(이중 계상 0). `price` 잔차에서 같은 금액 차감 → 합계 = Δ순자산 불변. 정밀 분기·월/연 결산 매핑 코드 변경 0.
- 남는 한계: 기존 계좌 잔액 직접 수정(신규 아님)은 예측 구간에서 여전히 `시세`. 대안 = Hero에서 예측 통합 `price`를 월·주처럼 `기록 안 된 변화`로 표기(`getAttributionItems` 1곳) — 레거시 기기의 실제 시세 변동 이름까지 바꾸는 표시 변경이라 이 릴리스 범위 밖, bug 이슈에 후속 후보로 적는다(CEO 판정).
- 위험: 원인 **분류** 변경(금액 합계 불변)이라 `risk:medium` 유지 제안. 단 "금액 계산 규칙" 해석 여지 → cto 판정 요청.

## 4. 확인 항목
- **④ 도넛 누름**: 대상의 도넛은 `financial` 조각 1개(`useAssetTreemapData`). 조각·범례(`AssetDonutChart` 147·224) 모두 `onSegmentClick(key)` → Dashboard `handleSegmentClick`에서 대상이면 `financial`→상세 `stocks`/`crypto`(physical 분기와 같은 방식). `NetAssetSummaryBox` 내부 변경 0.
- **③ 다음 날 반복 — 재현됨(코드+단위)**: `saveSnapshots`는 `initAndSync`(앱 열 때)·자산 0→양수 전환에서만 호출(`asset-data-context.tsx` 928·944). 저장 후 재호출 없음 → 등록일 일별 기록·`lastVisitDate`=등록 전 값. 그날 재실행 없이 다음 날 열면 `sinceDate`=등록일, 시작=등록 전 기록 → `신규 현금 +X`(라벨 `전일 대비`)가 다시 나온다. 이름은 `신규 현금`이라 수익 아님. 모든 신규 등록 공통 기존 동작, 이 릴리스에서 고치지 않음(spec 13-3).
- **⑤ cashTracked 전환**: `change-hero.tsx` 293·331 `cashTracked = 시작 현금>0 || 끝 현금(실시간)>0 || 입출금 기록`. 현금 등록 즉시 **이번 달**과 **올해 결산 체인 전체**가 참으로 바뀐다 → 올해 주식 매수·매도가 `순유입`에서 내부 이동 풀로 옮겨 `기록 안 된 변화`가 (올해 매매 순액 + 등록 현금)만큼 커지고 `넣은 돈` 도움말(`yearIncomeHint`)도 바뀐다. 지난 달(끝=월 기록, 현금 0)은 불변. 합계 불변, 수익 이름 유입 0. **#237 판독(12/27~)에 직접 영향** → qa는 올해 결산 전/후 캡처, 판독 메모 기록 필수.
- **⑤-2 4.94 처음 결산**: `pickFirstRecordStart`(R=모든 id 등록일 최댓값) → 현금 등록일이 R이 되어 시작점이 등록 다음 날 이후로 밀린다. **이미 열려 있던 처음 결산이 등록 직후 닫히고**(`first_month`) 7일 뒤 다시 열린다. 대상(주식만 신규 사용자)과 4.94 대상이 겹친다 → spec 6절 ⑦ "수익 아님"은 맞으나 '닫힘' 상태 변화를 상태표·qa에 추가 권고(수정은 범위 밖).
