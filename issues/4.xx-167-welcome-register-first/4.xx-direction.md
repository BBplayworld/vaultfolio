### 6. iOS Safari 7일 저장소 위험 평가
- 사실: iOS Safari는 사용자가 사이트와 상호작용하지 않은 채 **Safari 사용 일수** 7일이 지나면 스크립트가 쓴 저장소(localStorage 등)를 지울 수 있다. 달력 일수가 아니다. 홈 화면 웹앱은 자체 사용 일수를 쓰므로 사실상 대상이 아니다.
- 지금과의 차이: 지금도 '웹에서 바로 시작' 1번으로 같은 미설치 상태가 된다. 설치 기준선이 0이라 '설치 먼저'는 실제로 아무도 보호하지 못한다. 그래서 위험 증가분은 작다. 판정: **수용**. 단 4.85(#78 튜토리얼 막힘 해제)를 운영에 먼저 올린다는 조건이 붙는다.
- **새로 확인할 쟁점 (cto·qa)**: iOS에서는 홈 화면 웹앱의 저장소가 Safari와 분리돼 있다는 것이 널리 알려져 있다. 그렇다면 **Safari에서 등록한 뒤 홈 화면에 추가하면, 추가된 앱은 빈 상태로 열린다.** 그러면 선정 문서의 iOS 보조 문구 "홈 화면에 추가하면 브라우저 정리로 기록이 지워지지 않아요"는 사실과 다르다. Safari의 기록은 그대로 Safari에 남아 7일 규칙을 받는다.
  - qa 실기기 확인 1건: iOS Safari에서 저장 → 홈 화면에 추가 → 앱에서 자산이 보이는지.
  - 분리가 확인되면 다음 중 하나로 정한다.
    - (a) iOS 문구를 '기록 보존'이 아니라 '백업으로 옮기기'로 바꾼다. 백업 저장 → 홈 앱에서 불러오기는 기존 기능이고 새 기능은 0이다.
    - (b) iOS 보조 문구를 빼고 백업 팁에 맡긴다.
  - 문구는 C26 문장 단위 사실 대조를 거친다. 이 쟁점은 기존 #78에도 이미 있다. 4.86이 그 경로를 주 경로로 만들 뿐이다.
- 남는 위험(대표 알림에 명시): iOS 미설치·미백업 상태로 월 1회만 오는 사용자는 기록을 잃을 수 있다. 영향 비율은 측정할 수 없다(CSV에 OS 분해 없음).

### 0. 코드로 확인한 사실 (사업 절 보정 2건)

- **웰컴에서는 상단바가 렌더되지 않는다**(`top-bar.tsx:127` `if (isWelcomeGuide) return null`). 사업 5절의 "상단 설치 아이콘(상시)"은 첫 저장 **뒤**에만 해당한다. 4.86 뒤 모바일 웹 웰컴의 설치 입구는 0개이고, 설치 입구는 첫 저장 뒤 상단 아이콘과 #78 안내 2곳이다. 의도와 맞으므로 문구만 고친다.

### 1. 사용자가 하게 될 행동 (관찰 가능)
1. 휴대폰 브라우저로 처음 온 사람이 웰컴 CTA 카드에서 **설치 버튼을 거치지 않고** `스크린샷으로 자산 등록` 또는 `직접 입력 · 가져오기`를 바로 누른다.
2. `직접 입력 · 가져오기`를 누른 사람이 팝오버에서 **자기 자산군(부동산·주식·암호화폐·현금성·대출)을 1번 눌러** 그 자산군의 추가 폼에 도착한다. 현재처럼 주식만 고를 수 있는 상태가 아니다.
3. 첫 저장 뒤 홈에서 #78 안내를 1회 보고, 원하면 `추가하기`로 설치한다. iOS는 이때 기존 설치 흐름(PIN → 복원 코드 자동 복사 → 앱 첫 실행 `웹에서 쓰던 자산이 있나요?`에 붙여넣기)으로 기록을 앱에 옮긴다.

### 4. 쟁점 판정 — iOS 저장소 분리와 보조 문구
- **분리 자체는 사실로 본다**(공개 정보 기준, 실기기 확인 불가). 다만 제품에는 **이미 옮기는 경로가 있다.** #78 `추가하기` → `PwaInstallFlow`는 iOS·자산 보유 시 PIN 다이얼로그를 열고(`pwa-install-flow.tsx:181-191`), 복원 코드를 만들어 자동 복사하며(`:84-117`), 설치된 앱 첫 실행 시 `PwaConnectPrompt`가 `웹에서 쓰던 자산이 있나요?`로 붙여넣기를 받는다(`pwa-connect-prompt.tsx:18-24·75-78`). 그래서 "Safari 저장 → 홈 화면 추가 → 빈 상태"는 **우리 버튼을 거치지 않고 Safari 공유 메뉴로 직접 추가한 경우**에만 남는다. 그 경우에도 첫 실행 화면이 웹 기록을 묻는다. 실물 자산은 복원 코드에서 빠지고, 안내 1줄이 이미 있다(`pwa-install-guide-content.tsx:135`).
- **권고: (b) 문구 삭제(넣지 않음).**
  - (a) '백업으로 옮기기'는 기존 복원 코드 경로보다 길고(파일 저장 → 파일 앱 → 가져오기), 같은 다이얼로그 안에 옮기는 방법이 두 개가 되어 헷갈린다.
  - 선정 문서 예시 "홈 화면에 추가하면 브라우저 정리로 기록이 지워지지 않아요"는 C26 기준 사실보다 넓다. Safari 쪽 기록은 그대로 7일 규칙을 받고, 앱 쪽 기록은 복원 코드를 붙여넣어야 생기며, 실물 자산은 빠진다.
  - 문구를 넣지 않으면 위임 조건 ⑤(보안·데이터 문구 변경)도 0이 된다. 대표 승인 근거는 10-29 '설치 주 버튼 유지' 번복 1건으로 줄어든다.
  - qa 실기기 확인 1건은 **"#78 `추가하기` → PIN → 복원 코드 → 앱에서 붙여넣기 → 자산 보임"**으로 바꾼다(기존 기능 회귀 확인. 실기기가 없으면 preview에서 코드 생성·복사 단계까지 확인하고 한계로 기록).
- **기존 #78 문구 C26 대조**
  - `홈 화면에 추가해 둘까요?`: 질문이다. 주장이 없다. 일치.
  - `다음부터 아이콘 한 번으로 바로 열 수 있어요.`: 앱 열기에 대한 문장이다. 기록이 옮겨진다고 말하지 않는다. 일치. 단 iOS에서는 다이얼로그의 복원 코드 단계를 거쳐야 기록이 보인다. 그 안내는 다이얼로그 본문이 맡고 있다(수정 불요).
  - 참고(범위 밖): 설치 다이얼로그 본문 `…데이터 유실을 막기 위해 앱으로 설치해야 합니다.`의 '해야 합니다'는 강하지만 4.86에서 건드리지 않는다. 다음 정돈 후보로 STATE에만 남긴다.
- **남는 위험**(대표 알림): iOS에서 설치하지 않고 Safari만 쓰며 Safari를 7일(사용 일수) 넘게 쓰지 않은 사용자는 기록을 잃을 수 있다. 지금도 버튼 1번으로 같은 상태이고, 홈 백업 팁(`home-tip.ts:39`)과 #78이 남는다.
