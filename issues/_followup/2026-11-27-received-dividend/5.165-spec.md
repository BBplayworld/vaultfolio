## 1. 문제
배당 화면의 `지급`·`예상`은 둘 다 세전 계산값이다(`dividend-calc.ts:63`). 실제 통장에 들어온 금액을 남길 곳이 없어 배당주 사용자는 시트에 따로 적는다. 현금 입금으로 적어도 일반 입금과 구분되지 않는다(`transaction.ts:27` type은 deposit·withdrawal뿐).

## 2. 목표 행동
- 배당이 들어온 날 현금 입금을 적으면서 `배당으로 받은 돈`을 켠다(추가 입력 0~1칸).
- 성과 › 배당에서 올해 받은 기록 합계와 달별 기록을 계산값과 나란히 확인한다.
- 지표: 배당 입금 기록 기기 2주 연속 2대 이상, 데이터 사고 0. GA는 category 1개만(금액·종목 미전송). 미달이면 후속(결산 배당 행 등)을 열지 않는다.

## 3. 범위
- 포함: ① 현금 입금 폼의 배당 체크 + 선택 종목 ② 현금 거래내역 행 `배당` 배지·종목 줄 ③ 배당 화면 결론 줄 셋째 자리 칩(연 합계)·월 선택 칩(그 달 기록).
- **축소 순서**(qa FAIL 2회 시): 월 선택 조각 → 종목 칸 → 거래내역 배지. 종목 칸을 빼도 맵 형식은 그대로(`{kind}`만 남음). **데이터 층(T1~T11)은 줄이지 않는다.**
- 하지 않을 것: 새 메뉴·새 라우트·장부 화면·배당 기록 목록, 내보내기·가져오기, 알림, 세후 토글, 차액·달성률, 차트 막대·표 열 추가, 허브 카드·종목 한 장·홈 반영, 공유 링크 전달, 이미 적은 입금을 배당으로 바꾸기(현금 거래는 수정 기능이 없다 — 삭제 후 다시 적기), 고아 항목 압축 코드, **결산 원인 행 분리(v1 제외, 6장)**.

## 4. 사용자 흐름
1. 현금 › 입출금 기록(`cash-tx-input.tsx`) → `입금` 선택.
2. `매월 정기 입금` 상자 아래 `배당으로 받은 돈` 체크 1개. 둘은 함께 켤 수 없다 — 배당을 켜면 정기 체크는 해제되고 **비활성(자리 유지, 숨기지 않음)**, 도움말이 `배당을 끄면 선택할 수 있어요`로 바뀐다. 저장 recurring은 false. 출금으로 바꾸면 배당 값은 false로 돌아간다.
3. 배당을 켜면 `종목 (선택)` 1칸이 펼쳐진다. 보유 주식을 티커 단위로 고르며(`groupStocksByTicker` 순서 그대로) 기본값 `선택 안 함`. 보유 주식 0이면 칸 없음. 금액·날짜·메모·`잔액에 반영`은 기존 그대로(기록만 입금도 배당으로 적을 수 있다 — 지난 분 소급용).
4. 저장 → 토스트 `배당 입금을 기록했어요`. 거래 행 제목 줄에 `배당` 배지(글자 고정), **종목명은 날짜 아래 한 줄**(고른 경우만). 중복 확인을 거쳐 저장해도 배당 표시가 유지되고 요약 줄은 `배당 입금`으로 시작한다.
5. 성과 › 배당 결론 줄 순서는 **`지급 N · 예상 N · [셋째 자리]`**. 셋째 자리는 언제나 1개다.

| 조건(위에서부터) | 셋째 자리 |
|---|---|
| 올해 받은 기록 합계 > 0 | 칩 `받은 기록 N` |
| 0이고 현금 계좌 1개 이상 | 칩 `받은 배당 적기` |
| 0이고 현금 계좌 0 | 현행 `다음 지급 M월 K종목` 유지 |

6. 칩을 누르면 화면 이동 없이 입금 폼이 `입금`·배당 체크·종목 칸 펼친 상태로 열린다(기존 `trigger-add-cash-tx` 이벤트에 `dividend: true` 확장, 저장 0). **기록이 생긴 뒤에도 같은 칩이 진입이다**(새 버튼·메뉴 0). 닫으면 포커스가 칩으로 돌아오고 금액은 저장 즉시 바뀐다.
7. 달을 고르면 그 달 기록 > 0일 때 같은 자리에 칩 `M월 받은 기록 N`(높이 불변), 기록 없는 달은 지금처럼 빈 자리.
- 더하면 뺀다(11-16): 칩이 보이는 동안 `다음 지급`은 보이지 않는다. 폼 컨트롤 +1(배당 체크), 배당 화면 컨트롤 줄 +0.

## 6. 표시 규칙·원인 체계
- **섞지 않는다.** `지급`·`예상`은 세전 계산값(지급일 기준), `받은 기록`은 사용자가 적은 실제 입금액(입금일 기준). Hero·차트·표·투입 대비 배당·허브 카드·성적표는 변경 0. 기록을 계산값에 더하거나 빼거나 대체하지 않는다. 구분은 면(적은 것 = 중립 회색 칩)/글자(계산값)와 InfoHint 1문장 추가·1문장 삭제(ui.md 4장).
- 합계(C150): 달별 기록을 원 단위로 반올림한 뒤 더한 값이 연 합계(`roundedAnnual` 방식), 같은 포맷터·같은 보기 모드. 외화 입금은 지금 환율(`krwMul`)로 환산, 엔화 포함. 기간은 입금일의 연·월, 반영·기록만 모두 합산.
- **결산 배당 행은 v1 제외.** 배당 표시는 분류만 더하고 금액·type·reflected를 바꾸지 않으므로 `income`·#293 기록만 이동 한도·출금↔매수 짝의 입력이 같다 → 홈·월·연 원인 전 행 불변(T9). 연 탭 도움말(`year-settlement.ts:196`) 문구 유지. 재개 조건: 기록 지표 충족 후 '배당을 불어난 돈으로 옮기기' 단독 과제.

## 8. 엣지 케이스·환경
- 첫 사용자·기록 0: 4-5 표. 현금 계좌 0이면 기록 불가(알려진 한계)이고 `다음 지급`이 그대로 보인다.
- 계산 합계 0인데 기록만 있음(다 판 사용자): Hero 없이 카드 본문 맨 위에 칩 **`올해 받은 기록 N`** 혼자. 기록도 0이면 아무것도 없음.
- 일부 갱신·시세 실패: 합계는 저장값이라 표시, 외화 환산만 마지막 환율.
- 고른 종목을 팔거나 지움: 종목 줄은 남긴 종목명 그대로. 거래·계좌 삭제: 합계·배지에서 빠진다(현금 거래 삭제에는 토스트 되돌리기가 없다). 3년 정리·원격 삭제: 표시에서 빠지고 #84 되돌리기 뒤 복귀.
- 구버전 기기: 일반 입금으로 보이고 금액·잔액 동일. 작년 기록: 올해 합계에서 빠진다(연도 전환 없음).
- 환경(C126): preview 데모(현금 계좌 3·배당 표시 0, 데모 주입이 키 clear) = 조작 없이 `받은 배당 적기` 칩이 보임. 체험(`?trial=1`, 메모리 저장소) = 같은 칩, 적은 기록은 체험 안에서만 유지(T11). 두 환경 모두 새 소식 항목 노출.
