## 사업 (business-pm)

### 1. 왜 지금 — 리텐션에 기여한다. 첫 발견에는 기여하지 않는다
- PRINCIPLES 4-1 '월말 결산 의식'에서 사용자가 실제로 하는 일은 잔액 맞추기다. 그런데 현금·대출은 이 일을 시작하는 입구 3곳(FAB '업데이트', 홈 최신화 팁, 결산 '다음 달 준비')이 모두 **새 계좌 추가 폼**으로 간다. 라벨이 약속한 것과 도착하는 화면이 다르니 결함에 가깝다.
- #91(4.50)이 주식·코인 맞추기를 맡는다. 이 과제가 들어가야 '보유 현황 최신화'가 네 자산군 모두에서 성립한다. 대표가 직접 요청한 방향을 이어서 완성하는 과제다.
- 시점: 12/11에 머지하면 첫 적용은 **12월 말 결산 창(12/28~)과 연초 정리**다. 1년 중 '잔액을 한 번 정리하자'는 동기가 가장 강한 시기다. 이 창을 놓치면 다음 기회는 1월 말이다.

### 2. 누구를 위해
엑셀·노션 시트에 **매달 통장·대출 잔액을 옮겨 적던** 3040 투자자가 대상이다. 그중에서도 계좌를 2개 이상(급여·비상금·외화 등) 쓰고 대출(전세·주담대 등)이 1건 이상 있으며, 월말에 은행 앱을 보며 숫자만 고치고 싶은 사람이다. 지금 이 사람은 계좌마다 '상세 › 탭 › 펼치기 › 수정(필드 6~10개)'을 반복해야 한다. 그래서 갱신을 중간에 멈추고 순자산이 낡은 채로 남는다(PRINCIPLES 4 진단).

### 3. 성공의 모습 — GA page_title 기준, 익명 기기 기준, 신규 맞춤 정의 0
GA는 page_title 하나만 쓴다(DECISIONS 2026-11-06). `asset_type`·`result`는 GA 보고서에서 나뉘지 않는다. 대표 기기는 `?ga-optout=1`로 제외한다.

- **계측 규칙(spec에 넘김)**: 시트 저장은 카테고리별로 `asset_save`(현금/대출, manual, update)를 **저장 1회당 1건만** 보낸다. 바뀐 행 수만큼 보내면 이벤트 수가 저절로 늘어 지표가 부풀려진다. 0건 사용자의 추가 폼 경로는 지금 그대로 둔다(`first_asset_saved`·#48 첫 등록 퍼널 무접촉).
- **귀속 지표가 필요한 이유**: 기존 title은 추가·상세 수정·스크린샷을 모두 합쳐 센다. 이것만 보면 시트를 썼는지 알 수 없다. 기준선이 작아서(asset_save 28일 4건/3명, 10/3~10/30, 전 자산군) title 1개 차이로 해석이 바뀐다. 이름은 4.50의 '보유 현황 맞추기 *'와 겹치지 않게 정한다.
- **판정(2/5 판독)**: 성공 = 귀속 지표 3기기 이상 + 이벤트/사용자 1.5 이상(월말 2회를 지난 재사용) + 주 지표 사용자 수 증가. 0기기 = 실패(발견 안 됨 → 입구 문구 재검토). 1~2기기 = 판별 불가(정성 판독, 의견 보내기 확인).
- 정직한 한계: 표본이 작다(월 신규 약 17명). 효과 크기는 판정하지 않고 '쓰였는가·다시 쓰였는가'만 본다. 4.50(주식·코인)과 판독 기간이 겹치지만 자산군 title이 달라 섞이지 않는다.

### 4. 하지 않으면 무엇을 잃나 — 사용자 수 근거는 약하고, 결함 근거는 강하다
- 약함: 현금·대출 갱신 사용자 수를 따로 본 수치가 없다(기준선은 전 자산군 3명).
- 강함: 결산 행·홈 팁이 '갱신하세요'라고 하고 추가 폼을 여는 현상은 매달 반복된다. 돌아온 사람이 첫 행동에서 막힌다. 그대로 두면 12월 말 결산에서도 현금·대출 숫자가 낡은 채 결산이 계산되고, 이것은 결산 신뢰로 이어진다.

### 5. 가드레일
- **데이터**: 시트는 로컬 데이터만 읽고 쓴다. 서버 전송, 스키마, 저장 키, 동기화 변경은 모두 0이다. GA에는 금액·계좌명·행 수를 보내지 않는다(page_title만).
- **문구**: 금액 예시, '갚으세요·모으세요' 같은 권유어, 새 보안 문구는 넣지 않는다. 버튼의 '바뀐 N개'는 건수만 쓴다.
- **반려 이력**: 경과일 알림·신선도 표시, 결산 홈 팁 노출 변경, 새 메뉴·진입점, 원인에 '부채 상환'을 넣는 것은 모두 하지 않는다(LEARNINGS 19·21·23, 11-06 반려).
- **판독 오염**: 결산 행·홈 팁의 도착지가 바뀐다. 그래서 #51·#54 판독(12/11) 이후에 머지한다. 머지일은 판독 메모에 기록한다.
- **결산 의미(C24)**: 매달 직접 고친 현금 차액은 '기록 안 된 변화'로 쌓인다. 실사용 픽스처에서 이 항목이 최대 항목이 되면서 사용자 행동과 연결되지 않으면 v2 '차액을 입출금으로 남기기(선택)'를 안건으로 올린다. v1에는 넣지 않는다.

### 1. 지금 실제 흐름 (코드 확인)
- 입구 3곳은 모두 FAB 시트의 `select-method` 단계(제목 `현금성 자산 추가`·`대출 추가`, `:145`)에 도착한다. 홈 팁과 결산 행은 `open-add-asset-sheet{category}` → `handleHoldingsClick`을 거친다. 여기서 `직접 입력`을 누르면 `trigger-add-*`가 `setEditingItem(undefined)`로 **추가 대화상자**를 연다. 즉, 갱신하려는 사람이 '추가' 제목을 두 번 본다.
- 기존 잔액은 상세 탭 카드의 수정(`trigger-edit-*`)으로만 고칠 수 있다. 수정 폼은 필드가 6~10개다.

### 2. 사용자가 하게 될 행동 (관찰 가능)
- 현금·대출 보유자는 월말에 한 화면에서 여러 계좌의 잔액을 입력하고 **저장 버튼을 1번** 누른다.
- 저장 뒤 결산 '다음 달 준비'에서 해당 카테고리 행이 사라진 것을 보고, 남은 카테고리 행을 이어서 누른다.

### 3. 바뀌는 화면·흐름
| 위치 | 바뀌는 것 |
|---|---|
| FAB `select-method`(현금·대출, **1건 이상 보유자만**) | 제목 `현금성 자산 추가`를 `현금성 자산 업데이트`로(대출도 같은 방식으로) 바꾼다. `직접 입력` 보조 문구는 `계좌별 잔액 고치기`(대출은 `대출별 잔액 고치기`)로 바꾼다. 스크린샷 항목은 그대로 둔다 |
| `직접 입력` 도착지 | 보유자는 **잔액 맞추기 화면**(제목 `현금성 자산 잔액 맞추기`·`대출 잔액 맞추기`, 카테고리마다 1화면)으로, 0건이면 지금처럼 추가 대화상자로 간다 |
| 홈 최신화 팁·결산 '다음 달 준비' | 코드 diff 0. 위 FAB 단계를 거쳐 같은 화면에 도착한다(탭 2번) |

**잔액 맞추기 화면 구성**
1. 머리말 1줄: `바뀐 잔액만 입력하세요. 입출금 기록은 생기지 않아요.` (권유어·금액 없음)
2. 행은 기존 상세 탭 순서를 따른다. 행에는 이름(외화는 `USD`·`JPY` 표기), 보조로 `현재 1,234,000원`(외화는 원통화), 오른쪽에 **비어 있는 새 금액 칸**(자리표시 `새 잔액`)이 있다. 외화는 소수 2자리를 허용한다. 비워 둔 행은 바뀌지 않은 행이다. 합계·비중·원화 환산·순자산은 넣지 않는다.
3. 바뀐 행은 현재 값과 다른 값을 넣은 행이다. 이 행은 한눈에 구분되게 표시한다(시각 표현은 ui.md). 현재 값과 같은 값을 넣으면 바뀐 행으로 세지 않는다.
4. 행 검사: 현금 0원은 칸 아래에 `0원은 상세에서 삭제해 주세요`를 띄우고 저장을 막는다(스키마 `balance>0`). 대출 0원은 허용한다(기존 수정과 같이 완납). 현재 값의 10배 이상 또는 1/10 이하로 바뀌면 `자릿수를 확인해 주세요` 경고만 띄우고 저장은 막지 않는다. 잘못된 행이 저장되는 것이 유일한 데이터 위험이라서 넣는 장치다.
5. 하단 고정 버튼 `바뀐 N개 저장`(brand)은 0개일 때 비활성이다. 그 아래 링크 1줄 `새 계좌 추가`(대출은 `새 대출 추가`)를 누르면 이 화면을 닫고 기존 추가 대화상자를 연다.
6. 저장을 누르면 바뀐 행만 기존 업데이트 함수로 `balance` 하나만 바꿔 저장하고, 나머지 필드는 그대로 둔다. 이어서 `markCategoryRefreshed`를 호출하고 토스트 `잔액 N개를 고쳤어요`를 띄운 뒤 닫는다. 사용자는 원래 있던 화면(홈·결산)으로 돌아간다.
7. 취소·이탈: 바뀐 행이 1개 이상이면 바깥을 누르거나 끌어내려도 닫히지 않고, `취소`·닫기 버튼으로만 닫힌다. 확인 대화상자는 새로 만들지 않는다. 닫으면 입력한 값은 버린다.

### 4. 줄이는 것 / 하지 않을 것
- **줄이는 것**: 계좌마다 '상세 › 탭 › 펼치기 › 수정 › 저장'을 반복하던 일이 한 화면, 저장 1회로 줄어든다. 갱신 흐름에서 '추가' 제목 2번이 사라진다. 현금·대출은 화면 1개(카테고리 인자)를 같이 쓴다. 현금·대출을 합친 화면은 만들지 않는다. 입구가 카테고리 단위이기 때문이다.
- **하지 않을 것**: 값을 하나도 바꾸지 않은 저장, 즉 '그대로 확인' 저장은 만들지 않는다. 철회된 '변동 없음 확인'(S-4.26)과 같은 것이기 때문이다. 이 밖에 차액 입출금 자동 생성, 금리·만기·이름 편집, 정렬·숨김, 행 삭제, 스크린샷 경로 변경, 새 메뉴·URL, 결산·홈 팁 코드 수정도 하지 않는다.
- **그대로인 곳**: 상세 현금·대출 탭의 개별 수정(세부 필드의 정본), 0건 사용자의 추가 흐름과 첫 등록 퍼널, 거래 기록 메뉴.
- **정보 구조(C1)**: 화면의 `현재 …원`은 입력 참고값이다. 잔액의 정본은 상세 탭 카드, 합계의 정본은 상세 탭 합계와 홈 도넛이다. 이 화면에서 새로 생기는 지표는 0개다(전수 대조표는 spec에서 작성).

### 5. 사용자 시나리오 — 12/31 월말 결산
홈 결산 팁 › 월 결산 › '다음 달 준비'에 `현금 34일 전 값 기준`, `대출 34일 전 값 기준`이 보인다 → `현금`을 누른다 → `현금성 자산 업데이트`에서 `직접 입력`을 누른다 → `현금성 자산 잔액 맞추기`에서 계좌 4개 중 2개 칸에 은행 앱 숫자를 입력한다 → `바뀐 2개 저장` → 토스트가 뜨고 결산 화면으로 돌아오면 현금 행이 사라져 있다 → `대출`도 같은 방식으로 고친다. 탭 수: 계좌당 약 5탭이던 것이 카테고리당 4탭 + 숫자 입력으로 바뀐다.
- spec에서 사례로 확정할 것: 결산 창 월초(1~10일)에 고친 잔액이 어느 달 결산에 반영되는지(현행 스냅샷 규칙 그대로 서술). 그리고 C24, 즉 직접 고친 현금 차액이 '기록 안 된 변화'로 보이는지.

### 6. 사업 절 쟁점 응답
- **귀속 title**: 동의한다. 이름은 화면명에 맞춰 `잔액 맞추기 저장` **1개**로 하고 자산 접미사는 붙이지 않는다. 자산별 구분은 `자산 저장·현금/대출`이 맡는다. 4.50의 `보유 현황 맞추기 *`와 겹치지 않는다. 저장 성공 1회당 1건만 보내고, 비활성·취소·실패일 때는 보내지 않는다. 전송 방식(새 feature_use category 1개 등)은 tech-review가 정하되 맞춤 정의는 0개다.
- **asset_save 카테고리별 1회**: 동의한다. `result:update`이고, 바뀐 행 수와 상관없이 1건이다. 화면이 카테고리 단위라서 저장 1회 = 1건이다.
- **'자산 추가 시작' 의미 변화**: 동의한다(현행 유지). 보유자는 `select-method`에서 `직접 입력`을 누를 때 이 이벤트를 보낸다. 이때 의미는 '갱신 화면 열기'다. `새 계좌 추가` 링크는 이 이벤트를 다시 보내지 않는다(중복 집계 방지). 판독 메모에 의미가 바뀐 시점(머지일)을 적는다. 0건 사용자의 경로와 의미는 그대로다.
