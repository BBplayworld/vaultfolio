## 7. qa 후 작은 수정 묶음 + O1 원인 조사 (2026-11-09)

- 경고 접근성: 공용 `ResyncTxWarning`(`forms/asset-update/resync-tx-warning.tsx`)으로 분리. 노드는 유지하고 grid-rows 펼침(재마운트 없음, 접힌 상태 aria-hidden), 체크박스에 `aria-describedby`(경고 표시 중에만), testId `cash-tx-resync-warning`/`loan-tx-resync-warning`(표시 중에만 부여). 기존 `tx-after-resync-warning`을 참조하는 테스트는 없었다.
- O1(`?demo=1`에서 저장 후 0.5~2초 뒤 데모 초기값으로 복귀) 원인 조사 - **코드 분석 결과, 브라우저 재현은 못 함(가설)**:
  - `asset-data-context.tsx`의 주식 시세 동기화(`syncTodayStockPrices`, :500~570)는 시작 시점의 `data`를 `current`로 잡고, 응답이 오면 `current = {...current, stocks}` 후 `setAssetData(current)` + `saveAssetDataNotify(current)`로 **assetData 전체를 되쓴다**. 코인(:626 `{...data, crypto}`)도 같다.
  - `isCanceled()`는 `refreshData`가 올리는 epoch/abort로만 취소된다. 사용자 편집 경로 `saveData`(:1180)는 epoch을 올리지 않아, 동기화 요청이 진행 중인 동안 저장하면 응답 도착 시 **편집 전 스냅샷이 현금·대출까지 덮어쓴다**. 데모는 가상 종목이라 응답이 늦거나 배치 사이 대기가 길어 창이 0.5~2초로 보이는 것으로 추정.
  - 기존 경로(상세 수정 등)에서도 재현된다는 관찰과 일치(잔액 맞추기와 무관, 같은 `saveData` 사용).
  - 운영 영향: **있을 수 있음**(앱을 연 직후 시세 요청이 도는 몇 초 안에 저장하면 그 편집이 사라질 수 있음, 사용자 기록 손실 형태). 데모에서만 두드러지는지는 미확인. 4.52 범위 밖(코드 위치가 `asset-data-context` 동기화 경로)이라 수정하지 않았다.
  - 수정 후보(별도 이슈, risk 판정 필요): ① `saveData` 성공 시 stock/crypto sync epoch 증가(진행 중 응답 폐기 -> 다음 sync가 다시 받음) ② 응답 반영 시 `current` 대신 `getAssetData()` 최신본에 stocks/crypto만 병합. ②가 정석, 4.55 이전에 처리 권고.

## 8. #104 (p0) 시세 동기화가 요청 중 사용자 편집을 덮던 결함 수정 (2026-11-09)
- 원인(7절 O1 확정): `syncTodayStockPrices`·`syncTodayCryptoPrices`가 시작 시점 `data` 스냅샷에 응답을 얹어 assetData 전체를 `setAssetData`+`saveAssetDataNotify`로 되썼다.
- 수정: `lib/asset/price-patch.ts` 신규. 응답을 id별 시세 필드 패치로만 만들고(`buildStockPricePatches`: currentPrice·baseDate·name·inactive*, `buildCryptoPricePatches`: currentPrice·baseDate), 저장 직전 `getAssetData()` 최신본에 `applyPricePatches`로 적용한다. 삭제된 id는 되살리지 않고, 사용자가 ticker/심볼을 고친 항목은 이전 키 시세를 받지 않으며, 수량 등 다른 필드 편집은 유지한다. 응답 실패·시세 없음은 패치 0(쓰기 없음 또는 같은 배열 참조).
- 다른 자동 저장 경로 대조(save-failure 6곳): 565 주식·626 코인은 이번에 수정. 802(연도별 순자산 보정)·891(외화 통화 마이그레이션)·1331(부동산 추정값)은 `setAssetData(prev=>…)` 최신 state 기준이라 해당 없음. 945는 공유 링크 반영(사용자 의도의 전체 교체)이라 대상 아님. 닉네임은 `getAssetData()` 최신본 기준.
- 동기화·overwrite-guard: 자동 저장은 `saveAssetData`(notifyAssetUserEdit 발행 없음)이고 패치 필드가 guard의 자동 갱신 제외 목록(stocks currentPrice·baseDate·name·inactive*, crypto currentPrice·baseDate)과 정확히 일치해 영향 없음. 오히려 사용자 필드를 덮어 guard에 오탐을 만들 여지를 없앴다.
- 테스트(`price-patch.test.ts` 7건): 요청 중 현금 변경·종목 추가·삭제 -> 편집 유지/시세 반영/삭제 종목 부활 0, ticker 편집 항목 제외, 수량 편집 유지, 응답 없음 무변경(같은 참조), 거래정지/상장폐지, 코인 동형. 훅 안의 비동기 흐름 자체는 DOM 환경이 없어 반영 단계를 순수 함수로 분리해 재현했다.
- 남은 한계: `finalData`(동기화 후 스냅샷 입력)는 쓰기가 없던 경우 시작 시점 data라 그 스냅샷에 요청 중 편집이 늦게 반영될 수 있다(다음 동기화에서 보정, 데이터 손실 아님). 구버전 기기 혼재·스키마 영향 0. 운영 영향: 앱을 연 직후 시세 요청 중 저장하면 편집이 사라지던 문제가 해소된다.
