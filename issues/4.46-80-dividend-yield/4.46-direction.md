## 사업 (business-pm 확정 2026-11-07 — 대리 초안 1~3·5 유지, 4·6·7 보강)
1. **누구의 어떤 문제**: 배당주·배당 ETF를 모으는 3040 보유자는 엑셀에 "투자금 대비 배당률(연 배당 ÷ 매입금액)"을 적는다. 앱 배당 화면은 금액(지급·예상)만 보여 주고 %가 없어, 이 숫자 하나 때문에 엑셀을 계속 연다. 코드 확인: 배당 화면·주식 탭에 배당률·yield 표시 0건. 성적표 `asset-grade.ts:163`의 divYield는 점수 계산에만 쓰고 화면에 보이지 않는다(분모도 평가금액이라 다른 지표).
2. **기여 유형**: 리텐션(엑셀 대체, PRINCIPLES 1 "진짜 경쟁자는 엑셀"). "등록된 자산 데이터로 새 가치를 주는 기능"(LEARNINGS #71) 기준에 맞는다. 신규 유입 기여는 없다.
   - **월 활성 100 기여 크기(솔직히): 작음.** 배당 화면 방문자는 10월 3명. 새 사용자를 데려오지 않고, 이미 배당 화면을 쓰는 소수가 엑셀 대신 앱을 한 번 더 여는 정도다. 그래도 비용이 화면 1곳·위험 low라 "작게 확실히 쓰이는 개선"으로 채택한다.
3. **왜 지금**: 12월은 올해 배당이 거의 확정돼 연간 배당을 정리하는 시점이다. 비용이 작고(화면 1곳, 저장·GA 무변경), 결산 영역과 겹치지 않아 4.46 위임 머지(≤12/5)에 들어간다.
4. **지표(4.41 page_title 단일 규칙, 새 이벤트·새 title 0)**: GA '페이지 및 화면' 보고서 `성과·배당` 행의 활성 사용자·사용자당 조회수. 코드 확인: `ga.ts` SCREEN_TITLES `activity:dividend` = "성과·배당" 기존 행. 체험 모드는 track no-op이라 집계에 안 섞인다.
   - 기준선: 머지 전 4주(11/6 page_title 구조 시작 이후 ~ 머지일). 참고값 10/3~10/30 3명(구 구조).
   - 판독: 머지 후 4주(≤1/2). 표본이 작아 **방향 확인(정성)**. 12월은 배당 정리 시즌이라 자연 증가가 섞인다 — 증가해도 "기능 효과"로 단정하지 않는다.
   - **판독 기준**: 활성 사용자가 기준선 이상이고 사용자당 조회수가 기준선 이상 → "쓰이고 있음, 유지".
   - **실패 판정선**: 머지 후 4주 활성 사용자·사용자당 조회수가 **둘 다 기준선 미만** → 기능은 유지(제거 비용 > 유지 비용)하되 **배당 % 확장 후속(종목별 열·허브 노출 등)은 제안하지 않는다.**
   - 한계: 진입 출처·% 줄을 실제로 읽었는지는 구분 불가(GA 단순화 결정상 포기한 정보).
5. **하지 않으면 잃는 것**: 배당 투자자에게 엑셀을 떠날 마지막 이유 하나. 대체 비용이 없는 기능이라 기회비용만 있다. 근거 강도: **중간**(요청 데이터 없음, 엑셀 습관에서 추론).
6. **알리기(출시 후)**: 위임 머지 후 Threads 기능 1건 후보("배당 화면에 투입 대비 %가 보여" 류, 금액·수치 예시 금지, 높다/좋다 평가 금지). 카페·GeekNews 대상 아님(작은 개선).
7. **planner 가정(분모 환율 규칙)에 대한 사업 의견 — 동의**: 엑셀 사용자가 해외 배당주를 계산할 때 가장 흔한 방식은 "연 주당배당(달러) ÷ 평단(달러)"이다. 분자·분모 모두 현재 환율이면 이와 같은 값이 나오고, 환율 뉴스가 있는 날 %가 흔들려 "왜 바뀌었지"라는 문의가 생기지 않는다. 매입 환율 분모는 환차손익이 섞여 엑셀 값과 달라지므로 기각에 동의. 보완: 원화·달러 혼합 보유자는 통화 간 가중이 환율에 따라 조금 바뀌어 %가 미세하게 움직인다 — 캡션 "해외는 현재 환율"로 충분하고 InfoHint에 "원화·해외 혼합이면 환율에 따라 조금 달라질 수 있어요" 1문장을 넣을지는 ui 단계 판단(필수 아님).

## 경험

### 1. 사용자가 하게 될 행동 (관찰 가능)
- 성과 › 배당에 들어오면 올해 배당 금액 바로 아래에서 "투입 대비 N%"를 읽고, 엑셀을 열지 않는다.
- '지급만'으로 바꾸면 지금까지 받은 배당 기준 %를 본다.
- 월 막대를 누르면 % 줄은 사라지고 그 달 금액만 본다(월 단위 %는 의미가 없어서).

### 2. 정의 (코드 근거)
- **분자** = 배당 화면 Hero와 같은 값. `dividend-chart.tsx` `buildMonthlyTotals`의 연 합계(예상 포함 = 지급 + 예상, 지급만 = 지급). 배당 API 주당금액 × 보유 수량 × (USD면 현재 환율), 매수일 이전 지급분은 제외. 예상분은 API가 작년 지급 기록으로 추정한 값(`route.ts` isEstimated).
- **분모** = 같은 종목 목록(종목코드 있음·비상장 제외·상장폐지 제외, 증권사 중복은 `mergeStockGroup` 합산)의 **매입금액 = 평단 × 수량 × 현재 환율**. 앱의 주식 원금(`computeAssetCost` stockCost)과 같은 환율 규칙이다. 분자·분모가 같은 현재 환율이라 USD 종목은 환율이 바뀌어도 %가 변하지 않는다(달러 기준 배당률 = 엑셀 계산과 같음). 매입 환율을 분모에만 쓰면 환율 변동이 배당률에 섞이므로 쓰지 않는다.
- **제외**: 평단 0 이하 종목, 엔화(JPY) 종목(기존 배당 계산이 엔화를 환산하지 않음 `rate = USD ? usdRate : 1` — 별도 버그 후보, 이번 범위 아님)은 분자·분모 모두에서 뺀다. 뺀 종목이 있으면 "N종목 제외" 캡션.
- **배당 없는 종목은 분모에 포함**: "보유 주식 전체 투입 대비"가 엑셀 습관과 같다. 배당 종목만의 배당률은 하지 않는다.
- **올해 매수 종목**: 매수일 이후 배당만 들어가 %가 낮게 나온다. Hero 금액과 같은 기준을 지키기 위해 그대로 두고, 기존 InfoHint의 "매수일 이전 지급분 제외" 문장으로 설명한다. (대안: 매수일 무시한 연 환산 — 같은 카드에서 Hero 금액과 분자가 달라져 C30 위반이라 기각)

### 3. 범위
- 포함: 배당 카드 Hero 금액 바로 아래 % 1줄 + 기준 캡션 1줄, InfoHint에 정의 문장 1개 추가, 계산 순수 함수 + vitest.
- **줄인 것**: 종목별 % 열(375 배당 표 붕괴 U2 악화, 선정 문서 축소), 월별 %, 허브 카드 % 노출.
- **하지 않을 것**: 성과 허브 배당 카드·자산 성적표·AI 프롬프트에 % 추가(C1 정본 1곳), 시가 배당률(현재가 기준), 목표 배당률·비교·평가 문구, 새 GA 이벤트, 저장 키·스키마 변경.

### 5. 탭 비교 단위·데이터 존재 (C32)
- 배당 탭 Hero 단위 = "올해(1~12월)". 새 % 줄도 "올해" 단위로 같다.
- 데이터: 배당 API가 매 조회 시 올해 지급 + 작년 패턴 추정을 돌려준다(`route.ts:228-243`). 기기에 쌓인 과거 기록이 필요 없어 기존 사용자 데이터 그대로 값이 나온다(C20). 스크린샷 등록 종목도 평단(추정값 포함)이 있어 계산된다.

### 6. 문구 원칙
- 사실·기준만: "투입 대비 3.2%", "매입금액 기준 · 해외는 현재 환율". 
- 금지: 높다/낮다·좋다·유리·추천·매수·매도·보장·확정·"받게 돼요". %에 손익색(빨강/파랑) 쓰지 않음(평가로 읽힘).
- 예상분은 "작년 지급 기록으로 추정"이라고 InfoHint에 명시(수익 보장 오인 방지).
