## 2. 구현 지점과 주의
- 복귀 리스너는 asset-data-context에 현재 없다(`visibilitychange`는 cloud-sync-provider.tsx:356과 layout.tsx SW만). 1010~1024의 0→양수 effect와 같은 패턴으로 doSync(환율→주식→코인→saveSnapshots)를 재사용한다.
- **함정 1**: `syncTodayStockPrices`는 진입 즉시 이전 sync·코인 sync abort, `abortAllProfitFetches`, `setDataResetVersion(+1)`(수익률 화면 재조회 유발), `saveSnapshotsBlockedRef=false`를 한다(589~598). outdated가 0이어도 실행된다. 그래서 **호출 전에** `getStockCacheSlot` 두 칸과 `getAssetData().stocks[].baseDate`(코인은 `getCoinCacheSlot`)를 비교하는 사전 판정을 두고, 칸이 같으면 함수를 부르지 않는다(요청 0건, 부작용 0건).
- **함정 2**: 인자는 state 클로저가 아니라 `getAssetData()` 최신본을 넘긴다.
- 토스트 조건: `notify.info` 3곳(631·646·719)과 catch의 `notify.error`(715)를 `silent`일 때 전부 억제한다. `notifyKisUnavailableOnce`·서킷(`X-KIS-Unavailable`)은 그대로 둔다(CEO 조건 1).
- 가드: `isDataLoaded`, `!isBackgroundWorkBlocked()`, 자산 있음, 진행 중 플래그(복귀 연타 방지), `navigator.onLine`. 타이머·폴링 추가 0.

## 3. 클라우드 pull과의 겹침 (CEO 요청 1건)
같은 복귀에서 cloud-sync tick(autoPullIfNewer → runPull → `initAndSync`)과 복귀 재조회가 동시에 돈다. 코드 확인 결과:
- **덮어쓰기**: 시세 응답은 저장 시점에 `getAssetData()` 최신본에 `applyPricePatches`(id+티커키 일치 항목의 시세 필드만)로 병합한다(704~710, #104, C44). pull이 먼저 로컬을 갈아끼워도 시세 응답이 stocks 전체를 되돌리지 않고, 삭제된 id는 패치가 무시된다. 반대로 pull이 시세를 옛값으로 덮을 수 있으나, pull 뒤 `initAndSync`가 다시 syncTodayStockPrices를 불러 곧 회복한다.
- **순서·이중 실행**: pull 후 `initAndSync`(cloud-sync-provider.tsx:293·403)가 `syncTodayStockPrices`로 `stockSyncEpochRef++`·abort 하므로 진행 중이던 복귀 sync는 `isCanceled()`로 자기 응답을 버린다(최신 우선). 약한 구간: pull 직후 `INITIAL_SYNC_DELAY_MS` 대기 중에는 이전 sync가 아직 살아 있으나, 위 병합 방식이라 손실은 없다.
- **이중 저장**: 시세 저장은 `saveAssetDataNotify`(userEdit 신호 없음)라 push 트리거가 아니고, `pull`은 `busyRef`·편집 보류 가드를 가진다. 두 경로 모두 saveSnapshots는 `lastSnapshotRef`·`saveSnapshotsBlockedRef`로 동일 값 재기록을 막는다. 복귀 sync가 pull 없이 단독으로 stocks를 바꿔도 push는 나가지 않는다.
- 결론: C44·epoch 취소 유지됨. 단 위 함정 1의 사전 판정을 빠뜨리면 복귀마다 `dataResetVersion`이 올라 수익률 조회가 중단되므로 필수 조건으로 spec에 넣는다.

## 5. 부분 실패 집계
- 현재: 응답에 없는 티커는 `buildStockPricePatches`(price-patch.ts:30)가 건너뛰어 baseDate가 옛값으로 남는다. 그런데 루프 끝(719)은 실패가 있어도 `STOCK_SYNC_COMPLETE`를 띄운다. 배치 예외(715)는 오류 토스트 뒤 계속 진행해 완료 토스트도 뜬다.
- 방안: 루프 전 `outdatedTickers` 집합과, 각 배치 후 패치가 만들어진 티커 집합의 차이로 `failedCount`를 센다(순수 함수로 분리해 단위 테스트). 수동 업데이트: `failedCount===0`일 때만 "모두 업데이트" 토스트, 아니면 "N종목은 이전 시세예요" 한 줄. 서킷 open 반환 경로(681·653)는 지금처럼 완료 토스트 스킵.
- 문구 '~요'·내부 용어 0은 `MSG`(297~301)의 `[주식 현재가 갱신 실패]`·`KIS_API_UNAVAILABLE` 교체로 처리.

## 6. '언제 시세' 파생 가능성
가능. `Stock.baseDate`가 "YYYY-MM-DD-HHH"(장중 시간 칸) 또는 "YYYY-MM-DD"(종가)이고, 실패 종목은 옛 baseDate를 유지하므로 `min(baseDate)`가 '가장 오래된 시세'가 된다. 순수 유틸(`lib/finance/today-chip.ts` 인접 또는 신규 `price-asof.ts`)로 문자열 패턴만 파싱하고 새 저장 키 0. 현재 칸과 다른 종목 수가 'N종목 이전 시세'. 코인은 `CoinCacheSlot` 형식을 같은 유틸에서 처리. 한계: 국내·해외가 서로 다른 칸이면 하나만 표시(CEO 조건 3).
