## 1. 문제
- 앱을 연 순간(첫 로드·첫 자산 등록·pull 후)에만 시세를 받는다. 백그라운드에 있던 PWA로 돌아오면 다시 받지 않아, 아침 홈에 어제 장중 값이 그대로 남는다(asset-data-context.tsx 980~1024, 복귀 처리 0).
- 몇 시 시세인지 보여 주는 곳이 없다. `DataSourceBadge`는 `return null`인 빈 컴포넌트다(4곳 호출).
- 일부 종목이 응답에서 빠지거나 배치가 실패해도 마지막에 "모두 업데이트했습니다"가 뜬다(719). 실패 문구는 "[주식 현재가 갱신 실패]", "외부 증권 API 점검으로 인한 오류"처럼 내부 용어다(297~301).
- Hero 퍼센트만 하이픈이라 "▼ −120만원 (-1.2%)"처럼 섞인다(dashboard.tsx:452).

## 2. 목표 행동
사용자가 앱으로 돌아와 홈 순자산 옆 한 줄을 보고 "지금 숫자가 몇 시 값인지" 안다. 실패한 종목이 있으면 몇 종목이 옛값인지 안다. 토스트로 방해받지 않는다.

## 4. 사용자 흐름
1. 사용자가 앱을 백그라운드로 보냈다가 돌아온다(`visibilitychange → visible`). bfcache 복원(`pageshow`, persisted=true)도 같은 처리로 본다.
2. 앱 잠금이 걸려 있으면 아무것도 하지 않는다. 잠금 해제 직후(`PWA_UNLOCKED_EVENT`) 같은 판정을 1회 한다. 이것은 '복귀의 연장'이며 타이머가 아니다. CEO가 원하면 이 줄만 빼도 다른 항목에 영향 0.
3. **사전 판정(호출 전, 필수, tech-review 함정 1)**: `getAssetData()` 최신본으로 아래를 비교한다. 하나도 다르지 않으면 어떤 함수도 부르지 않는다(요청 0, `dataResetVersion` 증가 0, abort 0).
   - 국내 계열(domestic·isa·irp·pension) 종목의 baseDate ↔ `getStockCacheSlot("domestic")`
   - 해외 종목의 baseDate ↔ `getStockCacheSlot("foreign")`
   - 코인 baseDate ↔ `getCoinCacheSlot()`, 환율 `exchangeSyncDate` ↔ 오늘(KST)
4. 다르면 기존 사슬(환율 → 주식 → 코인 → saveSnapshots)을 `silent`로 1회 실행한다. 각 단계는 지금처럼 자기 칸이 같으면 건너뛴다.
5. 가드: 데이터 로드 완료, 자산 있음, `!isBackgroundWorkBlocked()`(잠금·인앱 게이트·체험), `navigator.onLine`, 진행 중 플래그(연타·이중 이벤트 1회로).
6. 응답은 지금처럼 저장 시점 최신본에 시세 필드만 병합한다(#104, C44). 토스트 0.
7. 홈·주식 요약의 '언제 시세' 줄이 새 baseDate로 바뀐다.

동기화 pull과의 순서(tech-review §3 확인 결과 유지)
- 같은 복귀에서 cloud-sync tick이 pull하면, pull 뒤 `initAndSync`가 epoch를 올려 진행 중인 복귀 재조회 응답을 버리게 한다(최신 우선). 복귀 재조회가 pull보다 늦게 시작하면 사전 판정이 pull로 바뀐 baseDate를 보고 판정한다. 시세 저장은 `saveAssetDataNotify`라 push를 만들지 않는다.
- pull 경로(`initAndSync`)의 토스트는 기존 경로이므로 문구만 3장대로 바뀌고, 뜨는 조건은 그대로다.

## 5. '언제 시세' 줄 — 표시 규칙
대상 종목: ticker 있음, unlisted 아님, delisted 아님. 0개면 줄을 그리지 않는다.

slot → 기준 시각(순수 함수 `priceAsOf`, getStockCacheSlot 규칙의 역함수, vitest로 경계 고정)
- 주의: 장중 칸 `YYYY-MM-DD-Hhh`의 날짜는 달력 날짜가 아니라 effectiveDate다. 국내 09~16시는 **어제 날짜**, 해외 00~05/06시도 전날 날짜가 붙는다. 그래서 문자열 min 비교(tech-review §6)는 쓰지 않고 실제 KST 시각으로 바꿔 비교한다.
- 국내 날짜 칸 D = D 장 마감, 해외 날짜 칸 D = 미국 D 장 마감(KST 다음 날 새벽).

글자(쉼표 없이, 해요체 아님 — 라벨)
| 대표값 | 홈 | 주식 요약 |
|---|---|---|
| 오늘 장중 칸 | `주식 14시 시세` | `14시 시세` |
| 다른 날 장중 칸 | `주식 11/25 14시 시세` | `11/25 14시 시세` |
| 국내 날짜 칸(장 마감·주말·휴장) | `주식 11/21 종가` | `11/21 종가` |
| 해외 날짜 칸 | `주식 미국 11/25 종가` | `미국 11/25 종가` |
- 대표값 = 이번 세션에서 받기에 실패하지 않은 대상 종목 중 **가장 오래된** 기준 시각 1개. 국내·해외가 섞이면 오래된 쪽만 보인다(CEO 조건 3). 주말·휴장은 slot이 직전 영업일로 고정되어 있어 자동으로 그날 종가가 된다.
- 실패 표시: 이번 세션의 마지막 시세 받기에서 요청했는데 패치가 없었던 티커 수 N(같은 티커 여러 증권사 = 1)이 1 이상이면 뒤에 ` · N종목 이전 시세`. 전부 실패면 `N종목 이전 시세`만.
- N은 메모리 값이다(저장 키 0). 칸이 바뀌었다는 이유만으로 '이전 시세'로 세지 않는다(복귀 전 그대로 보던 중 정시가 지나도 줄이 바뀌지 않음 — 받은 시각을 그대로 보여 줄 뿐).
- baseDate 없음(방금 추가·첫 받기 전)은 대표값 계산에서 뺀다. 대표값이 없고 실패도 없으면 줄을 그리지 않는다.
- 주식 요약은 지금 고른 분류 탭(전체·국내·해외 등)의 종목으로 계산한다. 전체 탭 = 홈과 같은 값.
- 스크린샷 모드·인증카드·웰컴 미리보기·체험(`isTrialMode`)에서는 그리지 않는다(`data-screenshot-hide`).

## 8. 엣지 케이스
- 빈 데이터·주식 0: 줄 없음, 사전 판정은 코인·환율만.
- 일부 갱신: 대표값은 받은 종목 중 가장 오래된 값, 꼬리에 실패 수.
- 오래된 데이터(며칠 만에 복귀): 사전 판정이 다름 → 조용히 받고 saveSnapshots로 오늘 일별 행 생성(앱 열기와 같은 결과).

- 오프라인 복귀: 아무것도 안 함, 온라인 복귀 이벤트로 재조회하지 않음(트리거 추가 0).
- 서킷 open: 첫 배치에서 멈추고 토스트 0(복귀), 줄은 `N종목 이전 시세`.
- 해외 장중(KST 밤): 해외 장중 칸이면 `22시 시세`, 국내가 그날 종가면 대표값은 국내 `11/26 종가`.
