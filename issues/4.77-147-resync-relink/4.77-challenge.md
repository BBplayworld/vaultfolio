## 1~5 반대 검토
1. 꼭 해야 하나: 대표 결정(11-11 ②) '필수'. 재론 안 함.
2. 더 작게: 확인 화면 1개·종목 행 단위·백업 유도 없음·자동 복구 없음 — 이미 작다. 진입 2곳은 유지(홈 팁은 1회 안내, 거래내역 줄은 '그대로 두기' 뒤 유일한 재진입). 대상 2개 이상 선택 칸은 같은 종목 다계좌 사용자에게 실제로 필요해 유지.
3. 중복: 건수 정본 = 확인 화면 행, 안내 줄은 합계, 팁은 건수 없음 — 중복 없음.
4. LEARNINGS·DECISIONS: 홈 팁 우선순위만 충돌(아래 미결 3). 나머지 없음.
5. 측정: GA `feature_use category:relink`(view/apply/undo/keep) — 익명 기기 기준 적용률 판독 가능.

## 필수 보강 (spec 개정 → developer)
- **A1 여러 세대 고아 합산.** 4.73 이전에 같은 종목을 여러 번 맞추면 거래가 옛 id 여러 개로 흩어진다(id1에 매수, id2에 매도). 옛 id별로 전량 매도 판정(규칙 3)을 하면 id2가 매도로 시작해 '끝남'으로 잘리고 id1 매수만 이어져 **매수는 붙고 사이 매도는 빠지는** 엉킨 상태가 된다. → 같은 S에 짝지어지는 고아 묶음은 **합쳐서 한 줄로** 날짜·createdAt 순 누적 판정. 픽스처 ⓙ 추가.
- **A2 수량 역산 일관성(결함 의심: `trade-utils.ts` `reverseTransaction` 127행).** 거래 삭제·수정은 `rollbackTransaction` → `deriveBaseSnapshot`으로 S의 **모든** 반영 거래를 역산하는데, 매수 역산 결과가 0 미만이면 0으로 잘린다(133행). 앱 밖에서 판 뒤 맞추기한 S(현재 수량 < 기록된 순매수)에 옛 매수를 이으면, 이후 **이은 거래가 아닌 다른 거래를 하나만 지워도** 기준 0 절단 → 재적용으로 수량·평단이 커진다. 4.74 이어받기 종목에도 있는 현상이지만 #147은 이를 대량으로 새로 만든다. → 규칙 3b 추가: S 현재 포지션에서 (S 자기 반영 거래 + 후보)를 역순 역산할 때 **한 번도 0 미만이 되지 않는 가장 긴 뒤쪽 구간만** 후보로 남긴다(앞쪽은 잘라 냄, '덜 잇기' 원칙과 같음). 잘린 건수는 기존 `relink-row-cut` 줄 1개에 합산(문구는 `이전 거래 {k}건은 빼요`로 일반화, 새 줄 0). qa 확인 요청: 픽스처(현재 10주, 이은 매수 30주) → 무관한 새 거래 1건 삭제 시 미리보기 수량이 10 근처가 아니면 결함 확정.
- **A3 '그대로 두기' 유지(결함 의심: `asset-storage.ts` `clearAssetData` 487행 keepKeys).** `secretasset_feature_usage`가 보존 목록에 없어 **동기화 pull·백업 복원마다 지워진다**(pull도 `applyImportedPayload`→`clearAssetData`). 동기화 사용자는 매 실행 `relink-offer`가 풀려 팁이 다시 뜬다. → keepKeys에 `STORAGE_KEYS.featureUsage` 추가 + '모든 데이터 삭제'(settings-page 125행 근처)에서 명시 삭제. 새 키 0, 형식 불변. 기존 기능 추천 팁 해제가 pull 뒤 되살아나던 현상도 함께 고쳐짐(의도된 차이로 qa 표기).
- **A4 확인 화면 고지 문구.** 고아는 맞추기 외에도 생긴다: 평가액 0으로 지운 종목의 거래(`planDeleteStocks` keepTx), 닫힌 달 연결 거래(C24 `keepClosedMonthLinked`). 지웠다가 다시 산 종목이 '맞추기 때 끊긴'으로 기본 체크될 수 있다. → 고지 2번째 줄을 `전량 매도했거나 직접 지운 뒤 다시 산 종목이면 체크를 풀어 주세요`로(줄 수 불변). 설명 첫 문장은 유지.
- **A5 C74 소비처 표.** S.purchaseDate가 바뀌므로 dev-notes에 소비처(결산 예측 `resyncInflowDate`·배당·보유 기간·연환산) main 대비 판정. 새 매수일이 하필 만든 해 1/1이면 `resyncInflowDate`가 기본값으로 읽어 만든 날을 돌려준다 — 수용(배당은 같음), 픽스처로 명시.

## 미결 2 판정 — 결산 원인 분해·해외 양도세 변화 허용 범위
- 고정(FAIL 기준): 모든 구간 **순자산 증감 합계 main과 같음**. 이은 종목이 없는 자산·구간은 원인 분해 diff 0.
- 허용(의도된 차이): **'처음부터 끊기지 않은 대조 픽스처'와 같은 값**일 것. 대조 = 같은 데이터에서 후보 거래의 stockId가 처음부터 S.id이고 S.purchaseDate = 새 매수일인 상태. 이 대조와 다르면 FAIL.
  - `realizedSellGains`(asset-report 1097): 고아 매도는 현재 `positionOf`가 null이라 R=0 → 이으면 R 계산. 이은 반영 매도가 구간 안에 있는 구간만 변화.
  - `costFxRevaluation`(975): 이은 해외 반영 거래가 구간 안에 있는 구간만 변화.
  - 예측 투입일: 새 매수일 ~ 만든 날 사이 구간과 만든 날 구간만 변화.
  - `computeForeignRealizedGain`(tax-utils 80): 올해 매도 중 이은 것만 변화. 현재는 고아 매도가 `stockById` 실패 → 평단 0 → 매도 대금 전액을 이익으로 보던 폴백, 이으면 S 평단·매입 환율 사용(과대 → 정상 방향). `estimated` 플래그 변화 허용. 소비처는 세금 달력 1곳.
- COO 상한: 한 구간에서 실현손익 변화 절대값 ≤ 그 구간 이은 반영 매도 체결액 합. '기록 안 된 변화'(잔차) 절대값이 main보다 커지는 구간이 있으면 qa는 목록화하고 cto 재판정(자동 PASS 아님).

## 미결 3 판정 — 홈 팁 우선순위: **결산 아래로**
- 순서: 새 공지 > 백업 > 세금(임박) > **결산 창** > **relink** > 세금 > 최신화 > 기능 추천.
- 근거: C38(팁 순서 변경 시 다음 결산 창 가림 판정 → 가리면 불가), LEARNINGS 11-06(결산 팁 노출 설계 현행 유지). relink를 위에 두면 해당 사용자는 X를 누를 때까지 매 세션 결산 팁을 못 본다. relink는 결산 합계를 바꾸지 않아 '결산보다 먼저 바로잡기' 근거가 약하고, 거래내역 안내 줄이 상시 진입이라 손실 없음. 백업 넛지는 하루 1회라 relink를 막지 않는다.
- 머지가 11/27 전이면 창 전 2주 남짓은 relink가 먼저 보인다. 판독 경계일 = 머지일 기록.

## 미결 4 — qa 재현 방법(코드 확인)
- 경로: preview 접속(아무 상태) → 도구 메뉴 `데이터 가져오기`에 고아 픽스처 JSON 업로드. `applyImportedPayload`(asset-storage 371)는 스키마 검증만 하고 `stockId` 참조 검사를 안 해 고아가 그대로 들어간다. preview는 동기화 쓰기 꺼짐.
- 픽스처 형식: S = `stock_import_<과거 ms>_0`·purchaseDate = 그 ms의 KST 날짜(또는 그해 01-01), 고아 = `stockId:"stock_old_1"`·같은 ticker·S 만든 날 이전 날짜, reflected 포함. 코인은 `crypto_import_`/`stock_import_` 둘 다. developer가 vitest 픽스처와 **같은 JSON을 저장소에 커밋**해 qa가 그대로 쓴다.
- 금지 1: 첫 로드 전에 localStorage를 직접 심지 말 것 — 앱 시작 시 1회성 마이그레이션 `2026-08-prune-orphan-transactions`(one-time-migrations 134)가 고아를 지운다. 직접 심어야 하면 `secretasset_migrations_done`에 그 id를 먼저 넣는다.
- 금지 2: 공유 링크(토큰) 가져오기로 재현하지 말 것 — 디코드(asset-storage 916~926)가 고아를 **티커·이름으로 자동 연결**하고 거래 id·createdAt을 새로 만든다(기존 동작, 범위 밖). 완료 기준 7의 '공유 토큰 왕복'은 **이은 뒤** 연결 유지만 본다.
- 데모(`?demo=1`)에는 `stock_import_` id가 없어 후보 0 — 데모 첫 화면 불변 확인용.
