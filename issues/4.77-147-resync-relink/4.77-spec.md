# 4.77 #147 spec — 맞추기로 끊긴 거래 다시 잇기

planner-designer · 2026-11-11 (cto challenge A1~A5·미결 2~4 반영 개정) · 코드 기준 origin/main 89e7213 · 방향 = 대표 결정 2026-11-11(2) (direction 생략, DECISIONS 379행)
**risk:high · 대표 승인 머지** (기존 사용자 기록을 다시 씀). 근거: v4.74 dev-notes 4절(27행)·decision-brief 알려진 한계 2(55행).

## 1. 문제
- v4.73 이전 맞추기·첫 등록 `교체/초기화 후 등록`은 기존 종목을 지우고 새 id(`stock_import_<ms>_N`, 코인 맞추기도 `stock_import_`, 코인 첫 등록 `crypto_import_`)·매수일 = 만든 날로 다시 만들었다. 거래는 지워지지 않고 옛 id를 가리킨 채 남아(고아) 상세 거래내역에서 사라지고, 매수일이 늦어져 올해 배당 예상에서 빠졌다.
- 고아는 맞추기 외에도 생긴다: 평가액 0으로 지운 종목의 거래(`planDeleteStocks` keepTx), 닫힌 달 연결 거래(`keepClosedMonthLinked`), 4.74+ 맞추기에서 지우기만 한 종목. 남은 근거는 고아 거래(ticker·symbol·date)뿐이라 **사용자 확인 필수**.

## 2. 목표 행동
- 해당 사용자가 안내를 보고, 확인 화면에서 종목별 '거래 N건·매수일 바뀜'을 확인한 뒤 한 번에 다시 잇는다. 이후 거래내역에 옛 거래가 보이고 배당 올해 예상이 돌아온다.

## 3. 범위
- 포함: 주식·코인 감지(순수 함수) · 진입 2곳 · 확인 화면 1개 · 적용(저장 1회) · 되돌리기(결과 화면+닫은 직후 토스트) · '그대로 두기'(이 기기에서 홈 팁 끔) · `clearAssetData` 보존 목록 보강(A3).
- 줄일 수 있는 것: 종목별 상세 진입 대신 확인 화면 1개로 통합, 거래 1건 단위 선택 없음(종목 행 단위), 백업 유도 없음.
- 하지 않을 것: 자동 복구·1회성 마이그레이션, 수량·평단·매입 환율·positionSource 변경, 거래 삭제·수정, 전량 매도로 끝난 옛 거래 잇기, 부동산·현금·대출, 새 저장 키·필드, 매수일만 따로 고치기(종목 수정에 있음), 공유 토큰 디코드의 고아 자동 연결 정리(범위 밖, 후속 후보).

## 4. 감지 규칙 (데이터 계약, `lib/asset/resync/relink.ts` 순수 함수 제안)
1. **대상 종목 S**: id가 `^(stock|crypto)_import_(\d{10,})_\d+$`, 비상장 제외, 만든 날 = id 시각 KST 날짜(`resyncInflowDate`와 같은 계산). 매수일이 **만든 날** 또는 **만든 해 1월 1일**(4.74+·#146 기본값)인 것. 사용자가 다른 날로 고친 항목은 대상 아님.
2. **고아 묶음 G**: 고아 거래를 옛 id별로 묶는다. tickerKey(코인은 대문자 symbol) 같고, 시장 같음(주식: 거래 통화 KRW ⇔ S 국내 계열), **G의 모든 거래 날짜 ≤ S의 만든 날**인 것만.
3. **여러 세대 합산(A1)**: 같은 S에 짝지어지는 G들을 **합쳐 한 줄**로 날짜·createdAt 순 누적(매수 +, 매도 −). 옛 id별로 따로 판정하지 않는다(id1 매수·id2 매도로 흩어진 경우 매수만 붙는 엉킨 상태 방지).
4. **전량 매도 구분**: 합친 줄에서 매도 뒤 누적 ≤ 0이면 그 회차는 끝. **마지막으로 끝난 지점 이후 거래만** 후보. 후보가 비면 제외.
5. **역산 일관성(A2)**: S 현재 포지션에서 (S 자기 반영 거래 + 후보 반영 거래)를 날짜 역순으로 `reverseTransaction`할 때 **한 번도 수량 0 미만이 되지 않는 가장 긴 뒤쪽 구간만** 남기고 앞쪽은 잘라 낸다. 이후 아무 거래를 지워도 `deriveBaseSnapshot` 0 절단이 생기지 않게 하기 위함. 3~5에서 빠진 건수는 한 숫자 k로 합산.
6. **짝**: 같은 키 S가 1개면 그 S에 기본 체크. 2개 이상(증권사가 다른 같은 종목)이면 이을 종목 선택 필수, 기본 미체크.
7. **새 매수일** = 남은 후보 중 가장 이른 매수 날짜. 그 날이 현재 매수일보다 늦거나 매수 거래가 없으면 그대로. 새 매수일이 하필 만든 해 1/1이면 `resyncInflowDate`가 기본값으로 읽어 투입일 = 만든 날 — 수용(배당은 같음), 픽스처로 명시(A5).
8. 적용 결과: 후보 거래의 `stockId`/`cryptoId` → S.id, S.`purchaseDate` → 새 매수일. **그 밖 필드 변경 0.** 다시 돌리면 후보 0(멱등).
- **저장 스키마 변경: 없음.** 기존 필드 값만 바뀜. 새 키 0 — '그대로 두기'는 기존 `secretasset_feature_usage.dismissedTipIds`에 `relink-offer` 추가(기기 로컬, 동기화 제외, 형식 불변).
- **A3 보존**: `asset-storage.ts` `clearAssetData`(487행) keepKeys에 `STORAGE_KEYS.featureUsage` 추가(동기화 pull·백업 복원 때 지워지던 것). '모든 데이터 삭제'(settings-page 125행 근처)에서는 명시 삭제. 기존 기능 추천 팁 해제가 pull 뒤 되살아나던 현상도 함께 고쳐짐 — 의도된 차이.

## 5. 진입 (감지 시 안내 + 상시 1곳)
- **홈 팁** 새 kind `relink`: 후보 ≥1이고 `relink-offer` 미해제일 때. 우선순위(cto 미결 3 판정): **새 공지 > 백업 > 세금(임박) > 결산 창 > relink > 세금 > 최신화 > 기능 추천**. 결산 창 팁을 가리지 않는다(C38). X = 기존 세션 숨김. 클릭 → 확인 화면. 머지가 11/27 전이면 창 전에는 relink가 먼저 보임 — 판독 경계일 = 머지일.
- **상세 › 주식 거래내역·코인 거래 화면** 목록 위 안내 줄 1개(후보 있는 동안 항상, '그대로 두기'와 무관) → 확인 화면.
- 공유 보기·체험(`?trial=1`)·PWA 잠금 중 감지·안내 없음. 데모(`?demo=1`)는 `stock_import_` id가 없어 후보 0(첫 화면 불변).

## 6. 사용자 흐름
1. 홈 팁 또는 거래내역 안내 줄 → 확인 화면(Dialog).
2. 종목 행: 이름·증권사, `거래 {n}건 다시 잇기 · {첫날} ~ {끝날}`, `매수일 {현재} → {새 날}`(바뀔 때만), `이전 거래 {k}건은 빼요`(k>0일 때만). 체크박스(대상 2개 이상이면 선택 칸).
3. `다시 잇기` → 적용 직전 `getAssetData()`로 재감지, 체크 행 중 유효한 것만 적용, saveData 1회.
4. 결과: `{m}개 종목의 거래 {n}건을 다시 이었어요` + `이 창을 닫기 전에는 되돌릴 수 있어요` + [되돌리기][닫기]. 재감지로 전부 사라졌으면 `이을 거래가 더 없어요` + [닫기]. 닫은 직후 토스트 `끊긴 거래를 다시 이었어요` [되돌리기].
5. `그대로 두기` → 다이얼로그 닫힘, 토스트 없음, 홈 팁 다시 안 뜸(이 기기), 거래내역 안내 줄 유지. X는 아무것도 기록 안 함.
