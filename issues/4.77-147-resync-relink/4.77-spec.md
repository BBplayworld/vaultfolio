# 4.77 #147 spec — 맞추기로 끊긴 거래 다시 잇기

planner-designer · 2026-11-11 · 코드 기준 origin/main 89e7213 · 방향 = 대표 결정 2026-11-11(2) (direction 생략, DECISIONS 379행)
**risk:high · 대표 승인 머지** (기존 사용자 기록을 다시 씀). 근거: v4.74 dev-notes 4절(27행)·decision-brief 알려진 한계 2(55행).

## 1. 문제
- v4.73 이전 맞추기·첫 등록 `교체/전체 교체`는 기존 종목을 지우고 새 id(`stock_import_<ms>_N`, 코인 맞추기도 `stock_import_`, 코인 첫 등록 `crypto_import_`)·매수일 = 만든 날로 다시 만들었다. 거래는 지워지지 않고 옛 id를 가리킨 채 남아(고아) 상세 거래내역에서 사라지고, 매수일이 늦어져 올해 배당 예상에서 빠졌다.
- 남은 근거는 고아 거래(`transactions[].stockId`·`cryptoTransactions[].cryptoId`가 없는 id, ticker·symbol·date 보유)뿐. 자동 복구는 전량 매도 후 재매수 기록과 섞일 수 있어 **사용자 확인 필수**.

## 2. 목표 행동
- 해당 사용자가 안내를 한 번 보고, 확인 화면에서 종목별 '거래 N건·매수일 바뀜'을 확인한 뒤 한 번에 다시 잇는다. 이후 거래내역에 옛 거래가 보이고 배당 올해 예상이 돌아온다.

## 3. 범위
- 포함: 주식·코인 감지(순수 함수) · 진입 2곳 · 확인 화면 1개 · 적용(저장 1회) · 되돌리기(결과 화면+닫은 직후 토스트) · '그대로 두기'(이 기기에서 안내 끔).
- 줄일 수 있는 것: 종목별 상세 화면 진입 대신 확인 화면 1개로 통합, 거래 1건 단위 선택 없음(종목 행 단위), 백업 유도 없음.
- 하지 않을 것: 자동 복구·1회성 마이그레이션, 수량·평단·매입 환율·positionSource 변경, 거래 삭제·수정, 전량 매도로 끝난 옛 거래 잇기, 부동산·현금·대출, 새 저장 키·필드, 매수일만 따로 고치는 기능(종목 수정에 이미 있음).

## 4. 감지 규칙 (데이터 계약, `lib/asset/resync/relink.ts` 순수 함수 제안)
1. **대상 종목 S**: id가 `^(stock|crypto)_import_(\d{10,})_\d+$`, 비상장 제외, 만든 날 = id 시각 KST 날짜(`resyncInflowDate`와 같은 계산). 매수일이 **만든 날** 또는 **만든 해 1월 1일**(4.74+·#146 기본값)인 것. 사용자가 다른 날로 고친 항목은 대상 아님.
2. **고아 묶음 G**: 고아 거래를 옛 id별로 묶는다. tickerKey(코인은 대문자 symbol) 같고, 시장 같음(주식: 거래 통화 KRW ⇔ S 국내 계열), **G의 모든 거래 날짜 ≤ S의 만든 날**인 것만.
3. **전량 매도 구분**: G를 날짜·createdAt 순으로 누적(매수 +, 매도 −). 매도 뒤 누적 ≤ 0이면 그 회차는 끝. **마지막으로 끝난 지점 이후 거래만** 후보. 후보가 비면(전량 매도로 끝남) G 제외. 기준 보유분이 거래에 없어 일찍 0 이하가 되면 앞 거래가 빠짐 — 덜 잇는 쪽(오연결 0)으로 수용.
4. **짝**: 같은 키 S가 1개면 그 S에 기본 체크. 2개 이상(증권사가 다른 같은 종목)이면 행에서 대상 선택 필수, 기본 미체크.
5. **새 매수일** = 후보 거래 중 가장 이른 매수 날짜. 그 날이 현재 매수일보다 늦거나 매수 거래가 없으면 매수일 그대로(배당 예상을 줄이지 않음).
6. 적용 결과: 후보 거래의 `stockId`/`cryptoId` → S.id, S.`purchaseDate` → 새 매수일. **그 밖 필드 변경 0.** 같은 데이터에 다시 돌리면 후보 0(멱등).
- **저장 스키마 변경: 없음.** 기존 필드 값만 바뀜. 새 키 0 — '그대로 두기'는 기존 `secretasset_feature_usage.dismissedTipIds`에 `relink-offer` 1개 추가(기기 로컬, 동기화 제외, 형식 불변).

## 5. 진입 (감지 시 1회 안내 + 상시 1곳)
- **홈 팁** 새 kind `relink`: 후보 ≥1이고 `relink-offer` 미해제일 때. 우선순위 = 새 공지 바로 다음(백업보다 위) — 데이터 바로잡기가 결산·배당 숫자에 앞서고, 해당 사용자에게만 뜸. X = 기존 세션 숨김. 클릭 → 확인 화면.
- **상세 › 주식 거래내역·코인 거래 화면** 목록 위 안내 줄 1개(후보 있는 동안 항상, '그대로 두기'와 무관) → 확인 화면.
- 공유 보기·체험(`?trial=1`)·PWA 잠금 중에는 감지·안내 없음. 데모(`?demo=1`) 기본 데이터에는 후보 없음(데모 첫 화면 불변).

## 6. 사용자 흐름
1. 홈 팁 또는 거래내역 안내 줄 클릭 → 확인 화면(Dialog).
2. 종목 행마다: 이름·증권사, `거래 {n}건 다시 잇기 · {첫날} ~ {끝날}`, 매수일 변화 `{현재} → {새 날}`(바뀔 때만), 회차가 잘렸으면 `전량 매도로 끝난 이전 거래 {k}건은 빼요`. 체크박스(대상 2개 이상이면 선택 칸).
3. `다시 잇기`(brand) → 적용 직전 `getAssetData()`로 다시 감지, 체크된 행 중 그대로 유효한 것만 적용, saveData 1회.
4. 결과: `{m}개 종목의 거래 {n}건을 다시 이었어요` + `이 창을 닫기 전에는 되돌릴 수 있어요` + [되돌리기][닫기]. 닫은 직후 토스트 되돌리기(맞추기와 같은 패턴).
5. `그대로 두기`(secondary) → 홈 팁 다시 안 뜸(이 기기), 거래내역 안내 줄은 유지. 닫기(X)는 아무것도 기록 안 함.

## 8. 엣지 케이스
- 빈 데이터·거래 0: 감지 0, 진입 없음.
- 일부 적용: 체크 해제 행은 그대로 고아로 남고 안내 줄도 남음.
- 적용 사이 변경(다른 기기 동기화·직접 수정): 적용 직전 재감지로 사라진 행은 건너뛰고 결과 건수에 반영. 되돌리기는 #84 R1(맞춘 뒤 직접 고친 항목은 그대로) 규칙.
- 반영된 매도를 이은 뒤 그 거래 삭제: 기존 `rollbackTransaction` 동작(기준 0 절단 가능, 4.50 qa 확정 기존 현상, 삭제 확인 미리보기 있음) — 맞추기 연결 종목과 같은 상태라 새 위험 아님, 수용.
- 옛 백업 복원: 고아 상태로 돌아오면 다시 후보로 뜸(멱등).
- 구버전(4.76 이하) 기기: 바뀐 값만 받아 거래가 그 종목에 보임. 다시 끊지 않음.
