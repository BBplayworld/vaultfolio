## 1. 문제 / 목표 행동
- 문제: #293 뒤 엔진은 '기록만' 입출금을 원인에 넣는데, 화면은 여전히 `미반영`(계산에서 빠진다는 뜻으로 읽힘)·`반영`을 화면마다 반대 방향으로 단다. 주식의 기록만 거래는 한 번 누르면 확인 없이 지워진다. 연 결산은 출금이 더 많은 해에도 `넣은 돈 −`로 보인다.
- 목표 행동: 사용자가 거래 목록의 `기록만`을 보고 '잔액에는 안 더했지만 기록은 남아 있다'로 읽는다. 지우기 전에 한 번 확인한다. 출금이 더 많은 해에는 `꺼낸 돈`으로 읽는다.

## 2. 사용자 흐름
1. 상세 > 현금 > 입출금 내역 → 과거 입금을 '현재 잔액에 즉시 반영' 해제로 추가 → 도움말 문장 ①을 읽음 → 저장 → 목록에 `기록만` 배지.
2. 같은 행 휴지통 → 앱 안 확인 창 `이 기록만 지워요. 잔액은 그대로예요` → 취소하면 남고, 삭제하면 사라지며 잔액은 같다.
3. 주식·코인·대출도 1~2와 같은 모양으로 동작한다(주식은 지금까지 확인 없이 삭제했다).
4. 성과 > 자산 변화 > 연 탭: 출금이 더 많은 해에는 첫 묶음이 `꺼낸 돈 −N`이고, 도움말·help가 같은 이름을 쓴다.

## 3. 엣지 케이스·데이터 안전
- **구버전 데이터**: `reflected` 필드가 없거나 false인 기록은 4종 모두 `기록만` 배지를 달고 기록만 삭제 창을 쓴다. 엔진(`t.reflected` 필터)도 이미 같은 기준이라 표시와 계산이 맞다. 주식은 지금까지 필드가 없으면 배지 없이 바로 지웠는데, 이제는 배지와 확인 창이 붙는다. 이는 의도한 변경이다. 저장값을 보정·마이그레이션하지 않는다(쓰기 0).
- 빈 목록: 변경 0. 첫 사용자: 신규 종목은 잠금으로 늘 반영되므로 배지가 없다.
- 연 결산: `income === 0`이거나 묶음이 없으면(`null`) `넣은 돈` 문구를 쓴다. `|income| < 10`은 기존처럼 숨긴다.
- 롤백: PR을 revert한다. 저장 diff가 0이라 구버전 앱으로 되돌려도 데이터는 같다.
