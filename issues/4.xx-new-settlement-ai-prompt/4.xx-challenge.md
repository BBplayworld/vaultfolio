1. 결산 화면 원인 블록 아래 버튼 1개 "AI에게 이번 달 물어보기" → 기존 `PromptPreviewDialog`(탭 1개)
2. 프롬프트 = 그 달 결산 값만(시작·끝 순자산, 증감·%, 원인 항목 표시 그대로). 새 계산 금지, 화면에 없는 숫자 금지. 첫 달·오류 상태엔 버튼 없음
3. 질문은 "해석" 요청만(무엇이 바꿨나·다음 달 기록 점검). "매수·매도 추천" 류 요청 문구 금지(투자 조언 원칙)

## 6. 반대 검토
1. 꼭 해야 하나 — 결산은 숫자를 보여주고 끝난다. "그래서 뭐?"를 풀어 줄 다음 행동이 없다. AI 프롬프트는 강점인데 성적표 맨 아래라 체감이 낮고 측정조차 안 된다
2. 더 작게 — 화면 1곳·버튼 1개·탭 1개·기존 다이얼로그. 연 탭·금액 옵션 제외
3. 합치기 — 성적표 프롬프트와 템플릿 파일을 공유(`ai-prompts.ts`에 1종 추가), 다이얼로그 재사용. 새 컴포넌트 0 목표
4. LEARNINGS·DECISIONS — 새 진입점 없음, 공유·자랑 아님, 갱신 요구 문구 아님, 예측 항목 추가 없음(화면 값만). 원칙 변경 아님 → needs-human 아님
5. 익명 측정 — 기존 `feature_use` 기기 수로 가능
- COO 주의: 프롬프트 속 원인 라벨이 화면과 같은 말인지, "기록 안 된 변화"가 클 때 AI가 오해하지 않게 "기록되지 않은 금액" 설명 한 줄 포함 여부를 spec에서 정한다. 무조작 상태(`?demo=1` 새 브라우저)로 버튼 노출 확인(LEARNINGS 2026-10-30)
