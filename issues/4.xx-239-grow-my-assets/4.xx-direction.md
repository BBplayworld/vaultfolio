# 4.xx #239 내 자산 불리기 — Plus 기능 종합 정리

대표 지시(2026-11-17): "Plus 기능 종합 정리. '내 자산 불리기' — 좋은 자산은 오래 장기 유지하도록. 검토 필요 자산은 사용자에게 체크하도록. 절대 종목과 투자 추천은 아니어야 해."
코드 기준: 로컬 작업 트리 `/home/user/vaultfolio`(Bash 없음, origin/main 미대조. `ga.ts` 205행에 `year_settlement`가 있어 v5.124 상태로 보임).

## 문제
1. **Plus가 약속이 아니다.** `Plus` 글자는 배지 4곳뿐이다: 성과 허브 성적표 카드(`performance-hub.tsx:196`), 성적표 제목(`asset-report-view.tsx:393`), 동기화 대화상자(`cloud-sync-menu-entry.tsx:144`), 공유·동기화 선택(`tool-menu.tsx:330`). 분석 1개와 기기 연결 1개에 같은 배지가 붙어 있고, Plus가 무엇인지 말하는 문장은 없다. 결제는 100명 뒤로 보류됐다(HISTORY 21행).
2. **고급 기능이 흩어져 있고 거의 안 쓰인다.** 배지 없는 고급 기능: X-Ray(상세·주식), 절세 시뮬레이션(세금), 시장 비교·월별 기록·올해 결산(자산 변화), 배당, AI 프롬프트 2곳(`settlement-view.tsx:199`, `asset-report-view.tsx:767`), 가계 통계 비교(성적표 안). 성적표 진입은 주 1기기, 배당은 28일 3명이다(`_discovery/2026-11-15-d-business.md` 9행, STATE 기준선).
3. **성적표는 점수를 주지만 다음 행동이 없다.** 5축 점수 뒤에 "그래서 내 종목 중 무엇을 그대로 두고 무엇을 다시 볼지"는 사용자가 엑셀로 돌아가서 한다.
4. **지금 성적표 문장 일부가 권유에 가깝다.** `asset-grade.ts` 179행 "배당주·해외자산 등으로 … 만들어보세요", 208행 "저금리 레버리지는 자산 증식 속도를 높일 수 있습니다", 370행 "현금의 일부를 투자자산으로 옮겨". '내 자산 불리기' 이름 아래 묶이면 더 강하게 읽힌다. 이번 정리 범위에 넣을지는 열린 질문 3.

## 대상
엑셀·노션에 종목마다 '산 이유·점검일' 칸을 만들어 두고 채우다 만 3040 주식 투자자. 종목 5~20개를 여러 계좌에 오래 들고 있고, 이미 자산을 등록해 월 1회 이상 여는 기존 사용자다(11/07~13 홈 16기기). 신규·자산 미등록 기기는 대상이 아니다.
- 푸는 문제: "오래 들고 가기로 한 것"과 "다시 봐야 할 것"을 스스로 나눈 기록이 없어서, 숫자가 흔들릴 때마다 처음부터 다시 고민한다.
- Plus의 약속(안): **"기록한 자산을 내 기준으로 오래 지키고, 정기적으로 내가 점검한다."** 앱이 골라 주는 묶음이 아니라 사용자의 결정을 기록해 주는 묶음이다. 제품 정의('내 자산을 내가 정확히 아는 상태')의 연장이다.

## 사업 절 (business-pm)
1. **왜 지금 — 리텐션. 첫 발견 기여는 없음.** 월 결산이 "얼마 변했나"에서 끝난다. 결산 뒤 "그래서 무엇을 그대로 두고 무엇을 볼까"가 이어지면 월 1회 방문에 할 일이 하나 더 생긴다. 12/27 첫 12월 결산과 연말 점검 시기가 겹친다. 직접 근거는 대표 지시이고 GA 근거는 약하다(성적표 주 1기기). 이것만으로 월 100명에 닿지 않는다. 신규 병목(첫 저장 0~2)은 풀리지 않는다.
2. **규모(LEARNINGS 11-16 '버튼 1개 과제' 지적).** 새 진입 하나를 더하는 과제가 아니다. 흩어진 고급 기능의 정본 위치를 지표 단위로 다시 정하고(LEARNINGS 10월 전수 대조), 중복은 줄인다. 진입은 실사용 화면에서 출발한다(LEARNINGS 11-10: 상세 8명·성과 6명·홈 17명 / 28일). 배치는 경험 절에서 정한다.
3. **성공의 모습 (익명 기기 수, page_title만 — C122)**
   - 주 지표: 신규 title **`내 자산 불리기·체크`** — 사용자가 자산 1개 이상에 '오래 둠' 또는 '점검함'을 표시한 기기. 머지 후 4주(월 결산 창 1회 포함) **3기기 이상 성공 · 2기기 보류 · 1기기 이하 축소**(체크 저장을 걷고 사실 목록만 남김).
   - 보조: 신규 title **`내 자산 불리기`**(화면이 값과 함께 그려졌을 때 진입당 1회) 4주 5기기 이상. 기준선은 '성과·자산 성적표' 주 1기기다.
   - 3·5는 측정값이 아니라 가정이다. 대표·테스트 기기를 GA에서 뺄 수 없어 수치는 상한이다.
   - 전송 경로: `track("feature_use", { category })` → `CATEGORY_TITLES`(`ga.ts` 178~221행) → `page_title`(315~317행). **지금은 전송되지 않는 값이다.** 허용 목록(89행)과 `CATEGORY_TITLES`에 각 2줄이 필요하다. 빠지면 312행 폴백으로 현재 화면 title에 섞인다. 새 화면이면 `SCREEN_TITLES`(138~164행) 1줄. title 문자열은 vitest로 고정한다.
   - 보내지 않는 것: 종목코드·종목 수·체크 개수·금액·비중·기준값. 체험 중은 전송 없음(327행).
4. **하지 않으면 잃는 것 — 약~중.** Plus 배지가 뜻 없이 남고, 성적표는 주 1기기에 머문다. 당장 떠나는 사용자는 없다.

## 추천 아님 경계 (사업 안)
**원칙 한 줄: 앱은 내 기록에서 나온 사실만 보여 주고, 이름표는 사용자가 붙인다.**
| 층 | 누가 | 허용 | 금지 |
|---|---|---|---|
| 사실 | 앱 | 내 기록의 숫자·날짜: 보유 기간, 내 매입가 대비 %, 내 자산 안 비중, 마지막 기록 갱신일, 내가 받은 배당 기록, 거래정지·상장폐지 표시(기존 `inactiveStatus`) | 종목의 가치·전망·등급, 다른 종목과 우열 |
| 기준 | 사용자 | 사용자가 직접 정한 선(예: 한 종목 비중 상한, 점검 주기) | 앱이 정한 '적정' 숫자로 종목을 분류하는 것 |
| 결정 | 사용자 | '오래 둘 자산' 지정, '점검함' 체크, 점검 메모 | 앱이 먼저 붙이는 '좋은 자산'·'점검 필요' 딱지 |

- 대표 표현 '좋은 자산'은 화면에서 **'오래 둘 자산'(내가 고른 것)**으로, '검토 필요 자산'은 **'내 기준을 넘은 자산'·'기록이 오래된 자산'**처럼 사실 이름으로 쓴다.
- 기준을 아직 안 세운 사용자에게는 분류 없이 사실만 정렬해 보여 준다. 앱 기본값으로 종목을 나누지 않는다.
- 계산은 전부 기기 안에서 한다. 서버 전송 추가 0. AI 프롬프트에 '무엇을 팔까·살까'를 묻는 문장을 넣지 않는다.
- **쓰면 안 되는 단어**: 추천, 유망, 우량, 좋은 종목·나쁜 종목, 저평가·고평가, 전망, 오를·내릴, 목표가(앱 제시), 기대수익, 수익 보장, 불려 드려요, 사세요·파세요, 매수·매도 타이밍, 익절·손절, 물타기, 갈아타기, 비중을 줄이세요·늘리세요, 리밸런싱 하세요, 적정 비중, 위험 종목, 경고, 점수 낮은 종목, 남들은·평균 투자자는.
- **써도 되는 형식**: "보유 3년 2개월", "내 매입가 대비 −18%", "내 주식의 34%", "마지막 기록 5개월 전", "내가 정한 상한 30%를 넘었어요", "마지막 점검 4개월 전".
- 이름 '내 자산 불리기'는 대표 지시대로 쓴다. 다만 수익 약속으로 읽히지 않게 설명 줄에 "내 기준으로 지키고 점검"을 붙인다(열린 질문 4).

## 열린 질문
1. **체크를 저장하는가.** '오래 둠'·'점검함'·내 기준을 저장하면 새 저장 필드라 risk:high(마이그레이션·동기화·대표 승인)다. 저장하지 않으면 다시 올 이유("마지막 점검 N개월 전")가 사라진다. 사업 의견: 저장한다.
2. **보유 기간을 근거로 쓸 수 있는가.** 매수일은 사용자가 고칠 수 있고, 스크린샷 등록 시 1/1, 검색 추가 시 상장일로 채워진다는 관찰이 있다(STATE 191·192행, 결함 의심·qa 미확정). LEARNINGS 11-11은 판별에 사용자 수정 필드를 쓰지 말라고 한다. 표시는 하되 분류 근거로는 쓰지 않는 안을 권고한다.
3. **성적표 권유형 문장(문제 4) 정리를 이번 범위에 넣는가.** 넣으면 성적표 낱말이 바뀐다.
4. **이름이 수익 약속으로 읽히는가.** 대표 확인이 필요하면 방향 확정 알림에 1줄로 올린다.
5. **동기화의 Plus 배지.** '불리기'와 결이 다르다. 10-29에 배지 제거는 탈락(현행 유지)했다. 이번 '종합 정리'에 동기화를 포함할지 정해야 한다.
6. **배당을 기준에 넣는가.** 배당은 외부 조회 값이고 실패하는 날이 있다(4.98). 배당 화면 진입도 작다(LEARNINGS 11-10 반려). v1은 사실 표시만 권고한다.
7. **배치와 판독 창.** 홈·연 탭·웰컴을 건드리지 않고 상세·주식 또는 성과 허브에서 시작할 수 있는가(경험 절).
