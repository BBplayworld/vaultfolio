## 4. 사용자 흐름 (수정 후)
1. 코인 상세 → 코인 1개(또는 같은 코인 묶음) 삭제 → 그 코인의 `cryptoTransactions`도 한 번의 saveData로 함께 지워진다. 주식 묶음 삭제도 같은 규칙(그 종목들의 `transactions`). 4.58 연결 짝 기록(현금·대출)은 deleteStock과 같이 **건드리지 않는다**(잔액 불변, 고아 짝 기록 유지 — 4.58 qa F24 규칙).
2. 달러 계좌 반영 출금·입금 저장 → 잔액은 `roundMoney(값, 통화)`로 저장. 미리보기 줄(`:298`)도 같은 값.
3. 전액 출금 차단 → `{계좌명} 잔액을 {formatCurrencyDisplay(0, 통화)}으로 둘 수 없어요…`(KRW는 현행 그대로 '0원'). 4.58 연결 문구도 같은 방식.
4. 요약 손익이 반올림 후 0이면 부호 없이 `0원 (0.0%)`, 회색(`text-muted-foreground`). 0이 아닌 값은 현행 그대로.
5. 잔액 맞추기 창이 닫히면(저장·취소·Esc 모두) 포커스는 화면에 보이는 '자산 업데이트' FAB 버튼으로, FAB가 숨은 화면이면 창을 열기 직전 포커스 요소(아직 DOM에 있을 때) → 없으면 `main`.
6. 인식 API: 이미지 짧은 변이 200px 미만이면 **Gemini 호출·한도 차감 없이** 빈 결과를 돌려 #99 안내가 뜬다(PNG·JPEG·WEBP 헤더에서 크기 판독, 판독 불가·HEIC는 통과). 6종 프롬프트 끝에 1줄: `보유·거래 목록이 화면에 보이지 않으면 빈 배열 []만 반환하라.`(컷 가능 — 실제 캡처 회귀를 qa가 확인 못 하면 빼고 크기 가드만).

## 5. 엣지 케이스
- 빈 데이터: 코인 0개·거래 0건 삭제 → 오류 없음. 거래 없는 코인 삭제 → 거래 배열 그대로.
- 일부 갱신: 같은 코인에 반영·미반영 거래 섞임 → 그 코인 id 거래만 전부 삭제, 다른 코인 거래 불변.
- 오래된 데이터: 지난달 이전 거래를 지우면 그 달 결산 원인이 '매수'에서 '시세 변동' 쪽으로 바뀔 수 있다 — **deleteStock과 같은 기존 정책**(유령 원인 방지 우선). cto 판정 항목으로 올린다.
- 이미 남은 고아 거래: 정리하지 않음(이번 달 창이 지나면 원인에서 빠짐). 다시 같은 코인을 추가해도 id가 달라 연결되지 않음.
- 동기화: 거래 배열 축소는 deleteStock과 같은 경로(mergeById·syncedIds). 4.47 소실 알림(`overwrite-guard.ts:18` cryptoTransactions 포함) 오탐 여부 qa 확인.
- 첫 사용자: 영향 없음. 1×1·투명·단색 큰 이미지 모두 가짜 행 0.
