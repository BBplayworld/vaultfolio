# 4.xx challenge — #241 아침 알림 개선 (cto·COO, planning ②, 2026-11-18)

## 판정: 통과 (조건 7개)
대표 지시 과제이고 줄이는 변경이다(아침 조회 5 → 3회, 본문 약 85 → 54자, 알림 종류·시각·저장값 0). 하지 않으면 같은 거래일 값이 D-1 16시와 D 09시에 두 번 간다(`cron-run.ts:61`, `message.ts:114`). 범위를 더 줄일 곳은 없다. LEARNINGS·DECISIONS 충돌 없음(서버는 공개 지수·환율만, 보유 정보 0).

## 1. 대표 지시 충족 — 충족, 단 환율 처리 보완
- 고정 범위 3항목(아침 국내 지수 제외 / 아침 = 미국 + 환율 / 오후 = 오늘 국내)은 C131에 맞다.
- **보완 1**: "아침 환율은 전날 16시와 다른 날짜여야 한다"는 대표 말이 아니라 팀이 더한 조건이다. 대표가 지적한 것은 코스피·코스닥이다. 그래서 실측 결과별로 이렇게 정한다.
  - (a) 09시에 오늘 행 있음 → 가능. 단 Cron은 09:00~09:59 사이에 돈다. 개장 직후 행이 아직 없으면 날마다 환율이 있다 없다 한다 → 실측을 09:01·09:10 두 번 하고, 최근 2주 `[push-cron] round=morning` 로그의 실제 실행 시각과 대조한다.
  - (b) 전일 행이 16시 뒤 마감값(야간 거래 반영) → **가능으로 판정, 대표 확인 불필요.** 16시 알림과 숫자가 다르므로 중복이 아니다. 금액·등락률 모두 싣는다. (a)·(b)가 둘 다 되면 Cron 시각에 흔들리지 않는 (b)를 쓴다.
  - (c) 전일 행 = 16시 값 그대로 → 대표 확인(C131). 이때 '미국만' 하나만 들고 가지 않는다. **'환율 유지(전날 값, 날짜 표기)'와 '미국만' 두 안 + 팀 추천 1개**를 한 번에 묻는다. 지시 문구에 가장 가까운 안을 팀이 먼저 지우면 그것이 축소다. 앱 환율 금액만 싣는 안·외부 소스 추가는 기각(C68 재발, 날짜 검증 없음).
- **보완 2 (C139 선점검)**: `미국(11/23)`을 11/24 아침에 받으면 '어제 정보'로 읽힌다 — 대표가 지적한 인상 그대로다. 실제로는 그날 새벽 끝난 장이다. 괄호 날짜만 두지 말고 현지 날짜임이 읽히는 꼴로 바꾼다(기본안 `미국 11/23(현지) S&P 500 …`, 월요일은 `미국 11/20(현지)`). 최종 낱말은 대리 검토(C137)에서 3시나리오로 확정.

## 2. '큰 움직임만' 기준 변경의 손실 — 수용, 안내 문구는 수정
- 실제 손실은 direction이 적은 것보다 넓다. '큰 움직임만'뿐 아니라 **아침만 켠 모든 사용자가 코스피·코스닥을 더는 받지 못한다.** 다만 이는 대표 지시의 직접 결과이고, 빠지는 값은 전날 종가이며, 받을 길(16시)이 있다. 기본 구독은 빈 값(`prefs.ts:20`)이라 아침만 켠 것은 사용자가 고른 상태다. 수용.
- 새 소식 본문 "국내 지수는 오후 4시 알림에 담겨요"는 **부족**하다. 아침만 켠 사람은 '국내 장 마감'을 켜야 받는다. 다음 행동이 보이게 고친다: `국내 지수는 '국내 장 마감' 알림(오후 4시)에서 받아요. 설정 > 알림에서 켤 수 있어요`. 대신 켜 주기·별도 안내 푸시는 하지 않는다(사용자 선택값 변경).
- 받는 날 문구 `지수 ±2%·환율 ±1%`(`notify-section.tsx:78`)는 아침·오후 공용이라 그대로 맞다.

## 3. 주 지표 — 순서를 바꾼다
구독 기기가 적어 `알림 끄기` 증감은 판별 불가로 끝날 가능성이 크다. 이 과제는 성장 실험이 아니라 혼선 수정이다.
- **주 판정(정합성)**: 머지 후 5영업일 운영 로그·실수신에서 'D 아침 본문과 D-1 16시 본문에 같은 거래일·같은 값 0건', 아침 본문에 국내 지수 0건.
- **가드레일**: `알림 끄기` 미증가(2주·4주). 1~2대 변화는 '판별 불가'로 적는다.
- **한계 보완**: 새 GA 이벤트는 만들지 않는다. 대신 기존 로그 줄(`cron-run.ts:155`)에 종류별 구독 수 집계 숫자 1필드(`subs=morning:n,kr:n`)를 더해 '아침만 해제'를 직접 읽는다. 집계 숫자뿐이라 서버 전송·저장 변화 0.

## 4. 빈 날·휴장·월요일 규칙 — 빠진 경우 5건, spec 표에 추가
1. **시나리오 8은 환율 규칙에 따라 뒤집힌다.** (a)면 12/28(월) 09시에 환율이 있어 건너뛰지 않고 `환율 … | 미국 12/25 휴장`이 간다. 실측 뒤 다시 쓴다.
2. **환율 반복 방지 규칙이 없다.** 지금은 국내 묶음의 `isRepeatedClose(today,"kr")`(`cron-run.ts:107`)가 환율까지 막는다. 분리하면 (b)일 때 국내 연휴 중·다음 날 같은 행을 반복한다. 환율 전용 기대일·반복 판정과 연휴 행(설·추석 3일)을 표에 넣는다.
3. **휴장이 아닌 부분 실패**: 미국 조회 실패 + 환율 정상 → `환율 1,385원(+0.4%)`만(이유 표기 없음), 반대 경우 `미국 … `만. 문자열과 수용 이유를 적는다. 한 지수만 실패한 경우도 1행.
4. **하락·혼합 부호 예시 0건**(전부 +). C138대로 하락·혼합·값 없음 3가지 문자열을 넣는다. 예: `미국 11/23(현지) S&P 500 -2.3% · 나스닥 +0.1% | 환율 1,371원(-0.6%)`.
5. **미국 휴장이 월요일·금요일인 주**(화요일 아침 = 금요일 장 반복 → `미국 M/D 휴장`, 금요일 휴장 뒤 월요일 동일). 계산은 현행 `isRepeatedClose`로 맞으나 표에 행이 없다.
- 코드 주의: `needKr`(`:107`)·`hasContent`(`:114`)·KIS 호출 추정이 함께 바뀌어야 '값 0 → 건너뜀'과 중복 방지 플래그가 맞는다. qa 단독·합침 대조(C118)에 포함.
