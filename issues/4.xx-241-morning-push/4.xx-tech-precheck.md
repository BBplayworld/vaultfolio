## 2. 미국 지수 '그날 새벽 끝난 장' 판정 (기존, 변경 불필요)
- 기대 거래일 = 어제(KST)에서 미국 영업일로 롤백(`cron-run.ts:54-56`, `us-holidays.ts:79`), 일봉 마지막 행 날짜가 다르면 stale로 생략(`quotes.ts:38·74`).
- 휴장: 정적 표 2026~2030(`us-holidays.ts:5-64`, 반장은 영업일). 휴장 다음 날은 같은 종가 반복을 막아 조회하지 않고 '미국 M/D 휴장'만 표기(`message.ts:92-96·119-123`, `cron-run.ts:106`). 임시 휴장은 행이 없어 stale 생략.
- 주의: **월요일 아침의 미국 값은 금요일 장(토 새벽 종료)** 이다. '밤사이' 문구를 쓰면 월요일엔 사실과 다르다 → 문구는 경험 절에서 정한다.

## 4. 선행 실측과 결과별 처리
- 방법: preview 임시 진단 라우트(4.91 선례, 확인 후 삭제)로 **평일 09:00~09:10 KST**에 `FX@KRW` 일봉을 종료일 = 오늘로 1회 호출 + 같은 날 16시 로그 `kr.fx` 확인.
- (a) 오늘 날짜 행이 있다 → 아침 환율 = 오늘 행, 검증 `마지막 행 = 오늘`. **가능.** 단 Cron이 최대 59분 늦게 돌 수 있어 값은 '9시 무렵'이다.
- (b) 오늘 행은 없고 전일 행이 16시 이후 마감값이다 → 금액은 새 값이나 날짜·등락률 기준이 16시 알림과 같은 날. **부분 가능**(등락률을 빼고 금액만 싣는 안은 경험 절 판단).
- (c) 전일 행 = 16시 값 그대로 → **밤사이 환율 불가.**
- (c)일 때 대안: ① **환율 제외(아침 = 미국만)** — 가장 작고 안전, 단 대표 지시 미반영이라 대표 확인(C131). ② 앱 환율(`t_rate`) 금액만 표기 — 홈 카드 숫자와 일치하지만 날짜 검증·등락률이 없어 '모든 항목 날짜 검증' 원칙(`quotes.ts:10`)에서 벗어남, pm2 판정에서 환율 제외 필요. ③ 외부 공개 소스 추가 — 서버 측 허용 도메인 목록은 저장소에 없고(CSP `next.config.mjs:46`은 브라우저용) 약관·갱신 시각·가용성을 새로 검증해야 하며 홈 환율과 값이 달라질 수 있어(C65·C125) 비권장.
