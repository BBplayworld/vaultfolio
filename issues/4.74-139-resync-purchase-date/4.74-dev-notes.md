## 1. 원인 (확정)
- **연결(변경) 경로는 문제 없음**: 매칭 성공 시 `applyResync` change 분기는 기존 객체에서 수량·평단·증권사 채움만 바꾼다. id·purchaseDate·매입 환율·메모 유지, transactions 배열 불변(재현 R1).
- **원인 경로 = 매칭 실패 → `추가`+`삭제`**: 매칭 키(티커+category+증권사)가 어긋난 기존 종목은 미리보기에서 화면 행이 `추가`, 기존 항목이 `삭제`(같은 범위면 기본 체크) 또는 유지 묶음(사용자가 체크)으로 나뉜다. 적용하면 기존 항목은 지워지고 `stock_import_<ts>` 새 id·`purchaseDate = 오늘`로 다시 만들어진다(apply.ts:126).
  - '기존 매수 기록 초기화'의 정체: ① purchaseDate가 오늘로 바뀜(상세 `○○ 매수`·보유 기간), ② 거래 기록은 삭제되지 않지만 `stockId`가 지워진 옛 id를 가리켜 거래내역 화면(stockId 필터)에서 사라짐(고아 기록, 데이터에는 남음), ③ 스냅샷은 불변.
  - 배당: `dividend-chart.tsx:116`·`performance-hub.tsx:66`·`dividend-yield.ts:49`가 `payoutDate < purchaseDate` 지급분을 제외 → 올해 1~11월 지급분 전부 빠짐.
  - 재현된 기본 경로(사용자 추가 조작 없이): 해외 종목 티커 미인식(화면 이름 `애플` ≠ 저장 이름) → `확인 필요` 티커 입력 → `추가`, 같은 증권사·해외 범위의 기존 AAPL은 삭제 후보 **기본 체크**(범위 절반 미만). 그 밖에 증권사 미지정 ISA/연금 종목이 화면 계좌 추정(일반)과 달라 `추가`+유지 묶음으로 갈리는 경로, 기존 증권사 값과 화면 증권사가 다른 경로(사용자가 유지 묶음 삭제 체크 = '일괄 초기화').
- 수량 0(화면에 없음 = 전량): 삭제 후보로만 처리, 거래 기록은 고아로 남음(기존 설계 '거래 미삭제'). 이번 수정 범위 밖.

## 2. 수정
- `src/lib/asset/resync/apply.ts`: 추가 행이 **이번에 지우는 같은 종목**(tickerKey 같음 + 해외/국내 계열 같음, 비상장 제외)을 이어받는다. 고르는 순서 증권사 같음 → 계좌 같음 → 매수일 이른 것. 이어받으면 id·purchaseDate·purchaseExchangeRate·메모·비활성 필드 승계, 수량·평단(`evaluateLink` 규칙: 역산 평단은 기존 유지)·증권사·계좌는 화면 값, positionSource manual·positionEffectiveDate 오늘. 지우기 목록에서 빠지고 제자리 유지. 되돌리기 entry는 `modified`(되돌리면 원본 그대로). 코인은 `stocksToCrypto`가 원래 코인 객체를 승계하므로 같은 효과.
- 새 종목(이어받을 기록 없음, 코인 포함) 매수일 = **올해 1월 1일**(`resyncNewPurchaseDate(today)`, KST today의 연도). 대표 결정 11-10. DECISIONS 11-08 '신규 매수일 오늘'을 대체.
- `positionEffectiveDate`는 **오늘 유지**: 화면 수량은 오늘 기준. 1/1로 두면 1/1~오늘 사이 날짜의 거래를 반영할 때 `backdated` 확인 없이 화면 수량 위에 다시 더해져 이중 반영된다.
- 해외 `purchaseExchangeRate`는 **입력값/오늘 환율 유지**(1/1 환율 미사용): 실제 매입 환율은 어느 쪽도 모름. 1/1 환율은 과거 환율 조회(새 서버 호출)가 필요하고, 미리보기 입력(`기본값은 오늘 환율이에요`)과 어긋나며, 등록 첫날부터 근거 없는 환차손익이 생긴다.
- 미리보기 고지 1줄(`resync-notice-3`, 추가 행 있을 때만): `새 종목(코인)의 매수일은 올해 1월 1일로 들어가요. 나중에 수정할 수 있어요`. 판단: 저장 값이 실제와 다를 수 있음을 알리고 수정 경로(종목 수정의 매수일)를 남기기 위해 필요. 투자 조언 없음. **ui-designer 검수 필요**(문안·320 줄바꿈).

## 3. 결산·수익 영향 (확인 결과)
- 정밀 구간(시작·끝 스냅샷 모두 원가 기록): 원가 차이로 재므로 매수일 무관. 과거 스냅샷은 불변이라 1/1 이후 결산에 '보유 중'으로 소급되지 않음(테스트 (d), 구성 블록·월별 기록도 스냅샷 기반).
- **예측 구간(시작 스냅샷 원가 없음)에는 영향 있음**(`estimatePeriodInflows`가 현재 데이터의 purchaseDate로 신규 투입 추정): 1월 1일이 든 구간에 새 종목 원가가 `매수(추정)`로 잡히고 같은 구간 시세에서 같은 금액이 빠짐(합계 불변). 운영 사용자는 전년 12월 enrich 스냅샷이 없어 **연 탭 연초~첫 enrich 달 구간이 예측**이므로, 연 탭 원인에서 새 종목 원가가 '매수'로 한 번 더(맞춘 달 정밀 구간 + 연초 예측 구간) 잡히고 '시세'가 그만큼 작게 보인다. 이번 달 예측 구간(시작 원가 없음)에서는 반대로 빠진다. 테스트 `resync-flows.test.ts` (d')로 고정. 같은 현상은 기존에도 과거 매수일로 수동 등록한 종목에 있었음(엔진 한계). 완화안(제안만): 예측 추정에서 `positionSource=manual`이고 `purchaseDate < positionEffectiveDate`이며 id가 `stock_import_`/`crypto_import_`인 항목은 positionEffectiveDate를 투입일로 본다 — cto 판단 필요.
- 실현손익·양도세: 거래 기록만 사용, 영향 0. 연환산 수익률: 보유 1년 미만이면 렌더 없음(현행)이라 1/1 매수일은 표시 없음. 배당 월별 `매수 전` 표시: 1~12월 모두 포함.

## 4. 이미 잘못 덮인 데이터 복구 (제안만, 자동 복구 안 함)
- 남아 있는 근거: 고아 거래 기록(`transactions[].stockId`가 없는 id, `ticker`·`date` 보유 — 맞추기·삭제 후보는 거래를 지우지 않음, 2026-08 고아 정리 마이그레이션은 기기당 1회라 다시 돌지 않음). 스냅샷은 종목별 매수일이 없어 근거 불가. 맞추기 되돌리기 사본은 메모리 전용이라 사라짐. 사용자가 받아 둔 백업 JSON이 있으면 원본 매수일 그대로.
- 추정 규칙 안: 현재 종목 중 `id`가 `stock_import_`/`crypto_import_`이고 `purchaseDate == positionEffectiveDate`(맞춘 날)인 항목 → 같은 tickerKey 고아 매수 거래의 가장 이른 날짜를 매수일 후보로, 고아 거래의 stockId를 새 id로 다시 잇기. 단 전량 매도 후 재매수한 옛 거래와 섞일 수 있어 **사용자 확인 화면 필수**, 재연결은 롤백·결산 원인에 영향이 있어 별도 이슈(risk:high 후보)로.
- 지금 가능한 수동 복구: 종목 수정 창에서 매수일 직접 수정(배당 즉시 복원). 거래내역 화면 복원은 위 재연결이 필요.
