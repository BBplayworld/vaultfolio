## 5문항
1. **꼭 해야 하나 — 근거 약함, 그래도 진행.** 블록에는 새 진입점·새 소식·홈 노출이 없다(#180 파일 무접촉). 따라서 성적표 진입 기기 수를 늘릴 경로가 없고, 월 6기기 중 부동산 등록자만 본다. 진행 이유는 비용이 작고(정적 표 1 + 순수 함수 1 + 블록 1) 저장·서버 변경이 0이라는 것뿐이다. 성과로 보고하지 않는다는 합의 문장을 유지한다.
2. **더 작게 — 버튼을 뺀다.** 근거는 코드다.
   - `realEstateSchema.tenantDeposit`은 임대인이 받은 보증금(부채)이다. **세입자가 낸 전·월세 보증금을 넣을 자산 유형이 없다**(`cash.type`의 deposit은 예금, 대출 유형에도 전세자금대출 없음).
   - 그래서 무주택 3040의 가장 흔한 형태(보증금 미등록 + 전세대출을 신용·기타담보로 등록)는 버튼을 누르면 순자산이 보증금만큼 낮게 나온다. 통계는 보증금을 자산에 넣는다. 음수가 아니어도 틀리므로 조건으로 걸러낼 수 없다.
   - 버튼이 없어도 기능 0이 아니다. 분포 막대에 구간 경계 금액이 보여 스스로 위치를 읽을 수 있다. 버튼을 빼면 블록 조작 0, 화면 상태 0, 계측 ②도 필요 없다.
3. **빼거나 합치기** — 새 화면·메뉴 0, 블록 1개. 성적표 항목 중복 대조표(C1)는 spec에서 작성.
4. **원칙·반려 대조**
   - PRINCIPLES 3: 문언("서버가 사용자 자산을 알아야 하는 기능")에 저촉하지 않는다는 해석은 **타당**하다. 서버 전송 0, 비교 대상은 다른 사용자가 아니라 국가 통계다. 원칙 변경이 아니므로 needs-human 아님.
   - 다만 '하지 않는 것' 조항의 인접 영역을 팀 해석으로 처음 여는 것이고, "대표가 반대하지 않으면 진행"은 침묵을 승인으로 읽는 것이다. **위임 머지에서 제외하고 COO '대표 확인 필요'로 판정한다**(discovery 4절의 '위임 머지 가'를 정정). 방향 알림은 그대로 보내되 개발은 답을 기다리지 않는다.
   - LEARNINGS: 공유·자랑(10월) → 공유·인증카드·AI 프롬프트에 구간을 넣지 않는다. 외부 이탈(C54) 해당 없음. 판별 필드(11-11) → 부동산 건수는 사용자 임의 날짜·이름이 아니라 통과.
5. **익명 기기 측정** — 블록 단독 효과는 측정할 수 없다. ①(4주 8기기)은 이 블록이 움직일 수 없는 숫자라 **목표에서 빼고 가드레일(불감소)로만** 둔다. ② 삭제. 판독 문서에는 '효과 미측정'으로 적는다.
