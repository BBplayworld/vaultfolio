# [5.102] 내 순자산이 어디쯤인지 · spec

- 단계: planning ③. planner-designer, 2026-11-13. 근거: `5.102-direction.md` 3절(우선), `5.102-challenge.md`
- 코드 기준 origin/main: `views/activity/asset-report-view.tsx`, `contexts/asset-data-context.tsx` `computeNetAsset`
- **통계 값은 이 문서에 한 줄도 없다.** `〈원문〉` 표시는 원문 표 확보(컷 11/17) 뒤 채우는 자리다. 2차 보도 값 사용 금지.

## 1. 문제
성적표 5축은 전부 자기 과거 대비다. "가구 전체에서 어느 구간인가"는 앱 밖 기사에서 손으로 대조한다.

## 2. 목표 행동
부동산을 등록한 사용자가 성적표를 내려 통계 분포 위의 자기 구간을 읽는다. 누르는 것은 없다. 성공 목표 없음(효과 미측정).

## 3. 범위
- 포함: 성적표 '5축 측정'과 'AI 평가 프롬프트' 사이 블록 1개(기존 `SECTION`+`SectionHeader`), 통계 상수 파일 1개, 구간 판정 순수 함수 1개.
- 범위 밖: 연령대 비교 / 부동산 0건 사용자의 구간 표시·'등록한 자산만으로 보기' 버튼 / 상위 1%·5%·소수점 백분위 / 내 순자산 금액 표시 / 다음 구간까지 남은 금액 / 구간 변화 이력 / 공유·인증카드·AI 프롬프트 반영 / 홈 팁·새 소식·성과 허브 노출 / 부동산 등록 버튼·링크 / 블록 전용 InfoHint / 계측 / 세입자 보증금 자산 유형(후속, risk:high).

## 4. 화면 구성과 문구 (위→아래)
| # | 요소 | 문구·규칙 | testId 자리 |
|---|---|---|---|

| 2 | 점수 안내 | `등급 점수에는 반영되지 않아요` | `networth-benchmark-score-note` |

| 7 | 라벨 | `가구 기준 · 등록한 자산 기준 · {조사연도}년 조사` (연도는 상수에서 파생) | `networth-benchmark-label` |
| 8 | 출처 | `자료: 〈작성기관〉 「〈조사명〉」 {조사연도}년(〈기준일〉 기준)` — 기관명·조사명·기준일·공공누리 표기 형식은 원문 확인 후 확정 | `networth-benchmark-source` |

- N·M 규칙: 구간 아래 누적 L, 구간 포함 누적 U를 공표값으로 합산한 뒤 각각 정수 반올림. `N = U − L`, `M = 100 − U`. N+M은 100을 넘지 않는다. N이 0이면 `약 1곳 미만`. M이 0이면(최상위 포함) 뒷절을 쓰지 않는다 — "약 0곳" 금지.
- 금지: 상위·하위·평균 이하·부자, 목표·권유·축하·위로·승급 표현, 내 금액, 남은 금액.
- 5와 6은 동시에 나오지 않는다.

## 5. 사용자 흐름
1. 메뉴 → 성과·자산 성적표를 연다(진입점 그대로).
2. 5축 아래로 내리면 블록이 보인다. 조작 없이 막대·강조·문장·라벨·출처가 한 번에 보인다.
3. 부동산 0건이면 강조·문장 대신 안내 1줄을 읽는다. 막대의 경계 금액으로 스스로 위치를 읽을 수 있다.
4. 그대로 AI 평가 프롬프트로 내려간다. 블록에서 나가는 이동 0.

## 6. 상태표
| 상태 | 판별 | 표시 |
|---|---|---|
| 기본 | 부동산 1건 이상 | 3·4·5·7·8 |
| 부동산 0건 | `assetData.realEstate.length === 0` (건수만. 대출·금액 조건 없음) | 3·6·7·8. 4·5 없음. 순자산이 음수여도 같다 |
| 순자산 0 이하 | 부동산 1건 이상 + `netAsset ≤ 0` | 원문에 음수(또는 0 미만) 구간이 있으면 그 구간, 없으면 가장 낮은 구간에 강조. 문형은 일반과 같다(`〈원문〉` 확인 후 확정) |
| 최상위 | 원문의 마지막 열린 구간(예상 표기 '10억 이상', 〈원문〉 확인) | 4 + 최상위 문형 |
| 경계값 | `netAsset`이 구간 경계와 같음 | 원문 표기('이상'·'미만')대로 귀속. 원문이 하한 포함이면 경계값은 위 구간. 비교는 반올림 전 원 단위 값 |

| 로딩·시세 갱신 | — | 블록 전용 로딩·스켈레톤 없음. 성적표가 그리는 시점의 `summary.netAsset`으로 판정하고 값이 바뀌면 구간도 바뀐다. 축의 '측정 중'과 무관하게 표시 |
| 자산 0건 | `summary.totalValue ≤ 0` | 기존 `자산을 등록하면 성적표가 계산됩니다.`만. 블록 없음, 새 분기 0 |
| 체험 데이터 | preview·체험 모드 | 데모 데이터로 같은 규칙. 별도 문구 0 |
| 부동산 있음 + 담보대출 미등록 | 감지 불가 | 기본과 같다. '등록한 자산 기준' 라벨로 수용 |

## 8. 통계 상수 형식 (값은 원문 확보 후, 지금은 자리만)
- 파일 1개(위치는 tech-review). 형태:
  `meta: { surveyName, agencies[], surveyYear, referenceDate, tableSource(표 이름·번호·URL), transcribedAt }`
  `brackets: [{ min: number | null, max: number | null, sharePct: number }]` — 원 단위, 낮은 구간부터, `null`은 열린 끝.
- 라벨의 조사 연도·출처 줄은 전부 `meta`에서 파생한다. 화면 코드에 연도·기관명 문자열을 직접 쓰지 않는다(12월 교체 시 이 파일만 바뀐다).
- 공표값은 변형하지 않는다(재계산·보정·구간 합치기 금지).
- vitest: ① `sharePct` 합 100(원문 반올림 오차 허용 폭은 원문 확인 후 명시) ② 경계 단조 증가·구간 사이 빈틈/겹침 0 ③ 경계값 귀속 ④ 문장 N+M ≤ 100, "약 0곳" 미출력 ⑤ 라벨 연도 = `meta.surveyYear`.
- 재판정: 구간 5개 미만 또는 최상위 구간 30% 초과 → cto.

## 10. 완료 기준
1. 성적표에서 블록이 '5축 측정' 바로 아래, 'AI 평가 프롬프트' 바로 위에 1개 있다. 다른 화면에는 없다.
2. 블록 안에 버튼·링크·누름 동작이 0개다.
3. F1·F2에서 강조(`data-mine`)·문장이 0개, 안내 문구가 4절 6행과 글자까지 같다.
4. F3·F4에서 강조가 정확히 1칸이고 7절 기대 구간과 같다.
5. 일반 구간 문장이 4절 5행 문형이고 N·M이 4절 규칙 계산값과 같다.
6. 최상위 구간에서 뒷절이 없고 최상위 문형이 나온다. 어떤 구간에서도 "약 0곳"이 나오지 않는다.
7. 경계값·`netAsset ≤ 0`이 6절대로 귀속된다.
8. 블록 판정 순자산이 홈 헤더 순자산과 원 단위까지 같다(해외주식×환율 소수 픽스처, C65).
9. 막대의 구간·비중·라벨 연도·출처가 원문 표와 전 구간 일치한다(qa 전수 대조). 상수 `meta` 5항목이 채워져 있다.
10. 8절 vitest 5종이 통과한다.
11. 블록 어디에도 내 순자산 금액, 4절 금지어가 없다. `등급 점수에는 반영되지 않아요`가 보인다.
12. 자산 0건이면 블록이 없고 기존 한 줄만 보인다. 체험 데이터에서 블록이 같은 규칙으로 보인다.
13. 320·375에서 4절 문구 전부가 어절 중간 줄바꿈 없이 보인다(C25).
14. 데이터 안전: 블록·상수·판정 함수 코드에 `fetch`·`localStorage`·`track` 0, C11 grep 0줄. `asset-grade.ts`·`recordGradeSnapshot`·AI 프롬프트·공유 카드·`ga.ts`·#180 파일 diff 0. 저장 키·스키마·동기화 변경 0. 같은 데이터에서 등급·별점이 머지 전후 같다.
15. PR 본문에 `새 소식: 해당 없음(#180 파일, 머지 뒤 등록)`. 머지는 owner-review(COO '대표 확인 필요').
