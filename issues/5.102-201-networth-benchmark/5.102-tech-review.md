## 2. 통계 상수 형식
```ts
meta: { surveyName, agencies: string[], surveyYear: number, referenceDate: "YYYY-MM-DD",
        tableSource: { name, id, url }, transcribedAt, sourceUnit, shareDecimals: number,
        boundary: "lower-inclusive" | "upper-inclusive" } | null
brackets: { min: number | null; max: number | null; sharePct: number; label?: string }[]
```
- spec 8절에 3개 추가: `shareDecimals`(원문 소수 자리 — `number`는 `10.0`의 끝 0을 잃으므로 표시는 `toFixed(shareDecimals)`), `boundary`(원문 '이상~미만'/'초과~이하'), `label?`(음수 구간 등 원문 표기를 그대로 써야 할 때만. 없으면 `formatShortCurrency`로 파생).
- 금액은 원 단위, `3 * EOK` 꼴로 적어 0 개수 오기를 막는다. 원문 단위(만원)는 `sourceUnit`에 기록.
- **빈 상수 가드**: 원문 전에는 `meta: null, brackets: []`. `validateStats()`가 실패하면(빈 배열, meta 누락, 구간 5개 미만, 첫 `min`·끝 `max`가 `null` 아님, 경계 빈틈·겹침, 합 오차 초과) 블록은 `null`을 반환한다. 12월 교체 오타도 같은 가드에 걸리고, vitest가 `brackets.length === 0 || validate 통과`를 단언한다. 상수 커밋에서 `length >= 5` 단언으로 바꾼다.
- 라벨·출처는 전부 `meta`에서 파생. 블록 파일에 연도·기관명 문자열 0(정적 테스트로 `20\d\d` 0건 확인).

## 3. 순수 함수 규칙
- `findBracketIndex(netAsset, stats)`: `lower-inclusive`면 `min ≤ v < max`. `null`은 열린 끝. 음수 전용 분기 없음 — 원문에 음수 구간이 있으면 첫 구간 `max: 0`으로, 없으면 첫 구간 `min: null`로 표현돼 같은 코드로 귀속된다. 비유한값은 `null`(강조 없음).
- 최상위 판정은 `max === null`(구간 순번)로 한다. M 값으로 판정하지 않는다.
- 내 구간 표시 = `realEstateCount > 0 && index !== null`. 부동산 0건 판정이 음수 판정보다 먼저다.
- **spec 수정 제안 1(경계 비교값)**: spec 6절은 '반올림 전 값'이지만 `Math.round(netAsset)`으로 비교하길 권고. 외화 환산으로 `299,999,999.6`원이면 홈 헤더는 3억으로 보이는데 블록은 3억 미만 구간을 강조한다. 표시값과 같은 정수로 비교해야 완료 기준 8(C65)과 맞는다.

## 4. N·M 규칙 검토 (spec 4절)
누적은 부동소수 합이 아니라 `sharePct × 10^shareDecimals` 정수로 더한 뒤 반올림한다.
| 경우 | 문제 | 대응 |
|---|---|---|
| 원문 합이 100이 아님(반올림 표) | 최상위 U가 99.x·100.x | 최상위 U는 100으로 고정. 합 허용 오차 = `구간 수 × 0.5 × 10^-shareDecimals`(구간별 반올림 오차 상한), 넘으면 옮겨 적기 오류로 보고 검증 실패 |
| N이 막대 값의 반올림과 1 다름 | 누적 반올림의 차라서 발생(가공 예: 누적 60.3→79.6이면 N=20, 막대는 19.3%) | 수용('약'). 상수 커밋 때 전 구간 N·M 표를 dev-notes에 적어 qa·COO가 막대 값과 나란히 본다 |
| 비중 0.5 미만인데 N=1 | 누적이 .5를 넘는 자리에 걸리면 0.1%도 '약 1곳' | **spec 수정 제안 2**: `N === 0 || sharePct < 0.5`면 `약 1곳 미만` |
| 최상위가 아닌데 M=0 | spec은 뒷절 생략 → 위 구간이 있는데 말하지 않음 | **spec 수정 제안 3**: 뒷절을 `약 1곳 미만이 이보다 높은 구간이에요`로. '약 0곳' 금지는 유지. 재판정 조건(최상위 30% 이하·5구간 이상)에서는 실데이터로 나오기 어렵고 가공 표로만 시험 |
| 원문이 누적 비율만 공표 | 구간 비중을 빼서 만들면 '수치 변경 금지'에 닿는다 | 구현하지 않고 cto·planner 재판정(막대 값 표기를 바꿔야 함) |
| 구간 폭이 불균등 | 영향 없음(ui는 1구간 1행, 금액 비례 축 아님) | — |
- 부동산 0건 + 음수 숨김은 타당. 남는 구멍(부동산 1건 + 담보대출 미등록, 평가액 0인 부동산 1건)은 건수 판별의 한계로 수용.
