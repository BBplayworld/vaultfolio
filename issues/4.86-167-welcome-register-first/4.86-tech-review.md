## 2. spec 구현 경로 타당성 — 타당
- 리스너 5개 모두 웰컴 분기 숨김 마운트(`page.tsx:111-118`)에 있고 `trigger-add-{real-estate,stock,crypto,cash,loan}`를 듣는다. real-estate는 mode 무시, 나머지 4개는 `mode==="screenshot"`만 스크린샷, 그 외(`manual`)는 추가 다이얼로그를 연다 (cash-input:284-293, crypto:349-358, loan:412-421, stock:640-649). 주식은 `dispatchAddStock("manual")` = `CustomEvent("trigger-add-stock",{detail:{mode:"manual"}})`로 `ADD_TRIGGER_EVENTS.stock`과 동일 → 한 줄로 합쳐도 동작 동일.
- `ADD_TRIGGER_EVENTS`(asset-dispatch.ts:73) 사용 + `screenshot-fail-notice.tsx:34`와 같은 패턴. `runDirectInput` 미사용이 옳다: 그 함수는 `asset_add_start`를 추가 전송(31행)하고 현금·대출은 보유 시 잔액 맞추기로 분기한다.
- 입력 창 안의 `trackAssetSave`는 5개 모두 `create` 경로에서 `countAssets(assetData)`를 넘긴다 → 0건이면 `first_asset_saved` + `markFirstSave()`(ga.ts:442). 확인한 위치: real-estate-input:351, stock:145, crypto:119, cash:107, loan:125. 5개 경로 모두 #78 신호 정상.
- 주의 1건(구현 규칙): 행 아이콘·라벨은 `floating-add-button.tsx:33`의 `ASSET_TYPES`가 **비공개(export 없음)** 이고, 그 파일을 import하면 FAB 전체(시트·훅)가 웰컴 번들에 딸려온다. 권장: 웰컴 안에 5항목 상수(type·label·icon)를 두고 라벨은 FAB와 같은 값임을 테스트(소스 grep)로 고정. 또는 `asset-dispatch.ts` 인접에 작은 공용 상수 파일로 추출해 FAB·웰컴이 공유(FAB diff 증가, 범위 확대이므로 비권장).

## 4. C76 마운트 테스트 — 환경 확인 결과 (spec 수정 필요)
- `@testing-library/react` 16.3.2, `@testing-library/dom`, `jest-dom`은 설치돼 있으나 **jsdom/happy-dom은 설치 안 됨**, `vitest.config.ts`는 `environment:"node"`. 기존 테스트 전부 "node 환경(jsdom 없음)" 주석. 따라서 spec 12절의 "RTL로 WelcomeGuide 마운트(effect 실행 후 `data-state="asset"` 단언)"는 **현 환경에서 불가**.
- 대안 (권장 순):
  1. **CTA 슬롯을 순수 렌더 단위로 노출**(예: `WelcomeCtaSlot({ state, standalone, isIOS, focusCta })`로 분리하거나 기존 JSX를 export) 후 `renderToStaticMarkup`으로 기본 경로(`state=welcomeCtaState({mounted:true,isStandalone:false,isInApp:false})`=`asset`)의 슬롯 HTML을 단언: `data-state="asset"`, `welcome-cta-wizard` 포함, `welcome-install-btn`·`웹에서 바로 시작` 부재, 5행 testid·순서·라벨. 기존 main 테스트(134-148행)와 같은 방식이라 범위 작음.
  2. 5행 클릭 전송: `renderToStaticMarkup`은 클릭 불가 → 행 핸들러를 `handleManualAdd(type, deps)` 같은 순수 함수로 분리해 `window` 스텁(`vi.stubGlobal("window",{dispatchEvent})`)으로 이벤트명·`detail.mode`·`track` 1회 검증. 팝오버 닫힘은 qa Playwright.
  3. 선택(규모 확대, 비권장): `jsdom`을 devDependency로 추가 → `// @vitest-environment jsdom` 파일 단위 적용. 새 라이브러리·package-lock 변경이 생기므로 근거를 남겨야 함. 위 1·2로 충분하면 도입하지 않는다.
- 리스너 대응 grep 테스트(spec 12절)는 `physical-add-trigger.test.ts` 패턴(소스 grep)으로 그대로 가능. 첫 저장 5경로도 grep 테스트로 가능.
- 렌더/클릭의 런타임 단언(실제 `data-state` 전이, 포커스, 팝오버 닫힘)은 기존 관행대로 qa Playwright가 맡는다고 spec에 명시 필요.
