# #32 성과 메뉴 정리 + 월말 결산 — 방향 정의 (direction.md)

## 사업 (business-pm)

### 왜 지금
- 기여 대상: **리텐션** (첫 발견 기여는 직접적으로는 없음).
- 근거: 월 활성 사용자 약 50명에 감소 추세(PRINCIPLES 4장). 스크린샷 갱신 구조라 갱신을 안 하면 숫자가 낡아 다시 열 이유가 사라진다. 목표 지표가 "월" 활성이므로 "한 달에 한 번 오는 이유"를 만드는 것이 신규 유입보다 먼저다.
- 부가 효과: 결산을 보러 온 사람이 갱신(스크린샷 재입력)까지 하면 데이터 신선도 문제도 같이 풀린다. 단, 이는 가설이며 출시 후 지표로 확인한다.

### 누구를 위해
- 엑셀·노션으로 월말에 자산 시트를 정리하던 3040 주식 투자자 중, **월 1회 "이번 달 내 자산이 왜 이렇게 됐나"를 직접 계산해 보던 사람**.
- 주식·해외자산 비중이 있어 시세·환율 영향을 따로 구분하고 싶은 사람. 입출금을 거의 기록하지 않는 사람은 주 대상이 아니다(기록 안 된 변화가 크게 나올 수 있음 — 경험 절에서 다룸).

### 사용자가 결산에서 얻어가는 것 (한 문장)
"이번 달 내 순자산이 얼마 늘거나 줄었고, 그게 시세·환율·내가 넣은 돈 중 무엇 때문인지"를 엑셀 없이 한 화면에서 아는 것.

### 성공 지표 (1~2개, 현재 GA로 측정 가능 여부)
확인 근거: `.claude/specs/4.28-ga-event-tracking.md`, `src/lib/analytics/ga.ts`. GA는 gtag 기반 익명 기기(client_id) 측정이며 서버 전송·로그인 불필요. 단 production에서만 동작(preview·로컬은 no-op).

1. **월초 재방문율: 결산 창(말일 3일 전 ~ 다음 달 10일) 안에 앱을 연 기기 비율** (월 활성 기기 대비)
   - 현재 측정: **가능(기본 지표)**. GA4 기본 보고서의 활성/재방문 사용자 + 기간 비교로 확인. 이벤트 추가 불필요.
   - 한계: 출시 전 같은 창의 값을 기준선으로 먼저 기록해야 비교된다(출시 전 한 달분 확보 필요).
2. **결산 → 갱신 전환: 결산 화면을 연 기기 중 7일 내 자산을 저장한 기기 비율**
   - 현재 측정: **부분 가능**. `page_view`(`page_path=/v/<viewKey>`)로 월 탭 진입은 잡히지만 "결산"을 일반 월 탭 조회와 구분할 수 없고, 요약 카드 클릭도 구분 안 됨. 갱신 쪽 `asset_save`, `screenshot_parse`는 이미 있음.
   - **추가 제안 이벤트 `settlement_view`** (정의 보완: 결정 4-1에 따라 월 탭이 곧 결산이므로 **월 탭 진입 = `settlement_view`**): 파라미터 `source`=card/menu(진입 경로), `result`=normal/first_month(첫 달 여부; 지난달 없음). 금액·증감값은 보내지 않는다(sanitizer 원칙 유지). 사전·`PARAM_LABELS` 한국어 라벨 등록 필요(타입 강제). 사용자 데이터 서버 전송 없음, 기기→GA 직접 전송 기존 방식 그대로.
   - 분석: GA 탐색 퍼널 `settlement_view` → (7일 내) `asset_save`.
- 표본이 약 50명이므로 소수 변동에도 크게 흔들린다. 지표 판단은 최소 2개월(결산 2회) 누적 후에 한다 (추정 기준).

### 결산 카드 노출 기간과 근거
- 제안: **매월 마지막 3일 ~ 다음 달 10일 (약 13일, 추정)**. 이슈의 예시(3일~7일)보다 3일 길게 잡는 안.
- 근거(모두 추정, 실측 아님): 결산 값은 월말 기준이라 말일 직전에 미리 볼 수 있어야 하고, 월초에는 급여·카드대금 정리 후 시트를 갱신하는 습관이 있다고 가정. 월 1회 오는 사용자를 놓치지 않으려면 창이 길수록 유리하다.
- 약점: 창이 13일이면 한 달의 약 1/3이라 월 1회 방문자가 균등하게 방문한다고 가정해도 3명 중 1명만 카드를 본다. 그래서 카드가 없어도 월 탭 자체(항상 접근 가능)와 캘린더 .ics 리마인더가 보완해야 한다.
- 출시 후 `settlement_view source=card` 비율로 창이 맞는지 확인하고 조정한다.

### 출시 후 알릴 방법
- 앱 안: 기존 사용자는 앱을 열어야만 볼 수 있다(Push 없음). 이미 이탈한 사용자는 닿지 않는다는 한계를 인정한다. 첫 출시 시 기존 공지 기능(`feature_use category=notice`)으로 1회 안내하고, 이후는 결산 카드 자체와 캘린더 등록이 반복 접점이다.
- 앱 밖: 카페 월 1회 결산 연재(비중·%만, 금액 금지)의 말미에 "앱에서도 이번 달 결산을 볼 수 있다"고 연결. 연재 시점은 결산 창과 맞춘다(월초). Threads는 기능 1건으로 안내. GeekNews는 큰 출시가 아니므로 쓰지 않는다. 결산 공유 기능은 없으므로 사용자 공유에 의존하지 않는다.
- 문구 규칙: 반말 축약형, 과장·감성 금지, 실제 기능과 다른 설명 금지(원인 분해는 입출금 기록이 있어야 정확함을 숨기지 않는다).

### 하지 않으면 무엇을 잃나
- 잃는 것: 월 활성 감소를 되돌릴 "돌아올 이유"가 없는 상태가 이어진다. 갱신하지 않으면 낡은 숫자만 남는 구조 문제가 그대로다.
- 근거 강도: **중간**. 진단(낡은 숫자 → 이탈)은 대표 관찰이며 사용자 인터뷰·GA 이탈 데이터로 검증된 것은 아니다. 월말 결산이 실제로 재방문을 만든다는 것도 가설이다(그래서 위 지표로 검증). 반대로 성과 메뉴 통합(순자산+수익 → 자산 변화) 자체는 혼동 감소를 위한 정리 성격으로, 단독으로 리텐션을 올린다는 근거는 약하다.

## 경험 (planner-designer)

### 1. 현재 코드 기준 성과 화면 (이슈 3장과 다른 점 포함)
경로 기준 `src/app/(main)/_components/` (이하 생략). 라우트는 `#activity/<tab>` 해시, 탭 정의는 `layout/navigation/navigation-context.tsx` (`ActivityTab = hub|netasset|profit|dividend|report`), 렌더는 `layout/navigation/asset-page-tabs.tsx`.

| 화면 | 파일 | 실제 구성 |
|---|---|---|
| 성과 허브 | `views/activity/performance-hub.tsx` | KpiCard 4개(순자산·수익·배당·성적표). 순자산 카드 비교는 **전년 대비**, 수익 카드는 **일별 대비**(KIS 종가 조회, 실패 시 "점검 중"). 성적표의 `Plus`는 표시 배지일 뿐 별도 잠금 로직은 없음 |
| 순자산 | `views/activity/net-asset-chart.tsx` (`YearlyNetAssetChart`) | 년도별(기본) / 월별 / 일별. 월별 = 월 스냅샷(`MonthlyAssetSnapshot`) 막대 + 증감. 일별 = 일 스냅샷 캘린더 + "연속 N일 기록·기록률"(`lib/report/record-streak.ts`). 연도별 수동 입력 폼과 FAB 이벤트 `trigger-add-yearly-net-asset` |
| 수익 | `views/activity/profit-chart.tsx` | 일별/주간/월간/연간 × 전체/국내/해외(`MARKET_LABELS`), 기준 종가 비교표(기본 접힘), 종목별 증감. 영업일/접속일 기준은 `stores/profit-basis-store`. **주식 종목 종가 vs 종가 비교**이고 순자산은 **저장된 스냅샷** 비교 — 측정 원천이 다름 |
| 배당 | `views/activity/dividend-chart.tsx`, `monthly-dividend-stocks.tsx` | 이슈 표와 일치 |
| 성적표 | `views/activity/asset-report-view.tsx` (881줄) | 등급 Hero → 투입 대비 성과 → 5축 → **"순자산 변화, 왜?"** → AI 프롬프트 |

**이슈 3장과 다른 점 (중요)**
1. **원인 분해는 신규 기능이 아니다.** "순자산 변화, 왜?"가 이미 구현돼 있다: 기간 1주/1개월/3개월/올해(`computePeriodAttribution`, `lib/report/asset-report.ts`), 실측·"예측"·"일부 예측" 배지, 4.33으로 항목별 기록 날짜와 "기록 내역 N건" 펼침까지 있음(`.claude/specs/4.33-attribution-timeline.md`, 홈 헤더와 공용 컴포넌트). 이번 일은 **새로 만들기가 아니라 (a) 월 단위(달력 월)로 맞추고 (b) 월 탭으로 옮기고 (c) 결산 규칙(내부 이동 제외)에 맞게 항목을 정리**하는 것이다.
2. **현행 엔진은 결정 4-4와 다르게 동작한다.** 원인 항목에 `주식 매수/매도`, `대출 상환/추가 대출`, `현금 입금/출금`, `신규 현금/현금 정리`가 따로 나온다(`causeShortLabel`). 결정(내부 이동 제외, 외부 입출금만 순유입, 나머지 "기록 안 된 변화")과 LEARNINGS("원인에 상환·매수를 넣지 않는다")는 월 탭에서 이 항목들을 **순유입 / 기록 안 된 변화로 재분류**하라는 뜻이다. 홈 헤더·일/주/연 탭이 같은 엔진을 쓰므로 한 화면만 바꾸면 라벨이 갈라진다 → 공용 컴포넌트에서 일괄 적용을 제안(구현 방식은 design-review에서 developer 판단).
3. 월 스냅샷은 이미 `breakdown·fx·fxBase·cost·grade·date`를 갖는다(`types/asset.ts`). 별점 변화(블록 6)와 환율 분리는 **기존 기록으로 재구성 가능해 보이나**, 레거시 월 기록(enrich 없음)은 "예측" 처리됨 — 스키마 변경 필요 여부는 developer 확인 사항으로 남긴다.
4. 현행 원인 기간은 롤링(1개월=30일 전)이고 월 탭은 달력 월이다. 기준이 다르니 **월 탭 헤더에 기준일을 반드시 표기**(결정 4-3-1과 일치).

### 2. 사용자가 이 기능 후 하게 될 행동
- 월말~월초에 성과 화면을 열면 최상단 "N월 결산" 카드를 보고 **탭한다**(허브 → 자산 변화 월 탭, 해당 월 선택됨).
- 월 탭에서 **"무엇 때문에 바뀌었나"를 읽고**, 필요하면 항목 옆 "기록 내역"을 펼쳐 날짜를 확인한다.
- 맨 아래 "갱신 안 된 자산"을 보고 **자산을 갱신하러 간다**(스크린샷 재입력 또는 "변동 없음 확인"). 캘린더 일정 추가 버튼을 **한 번** 누른다.
- 엑셀 월말 시트에 숫자를 옮기던 일을 이 화면으로 대체한다(관찰 지표: `settlement_view` 후 7일 내 `asset_save`).
- 월 탭에서 지난 달로 **넘겨 보는** 행동(과거 달 선택)이 생긴다.

### 3. 범위
**포함 (v1)**
- 성과 메뉴 3개: 자산 변화 / 배당 / 자산 성적표. 허브 카드 4개 → 3개.
- 자산 변화: 일·주·월·연 탭 + 전체 자산/주식 범위 토글(현재 범위를 탭 위에 항상 표시).
- 월 탭 = 결산: 4-3의 **1(헤더·기준일) · 2(순자산 비교) · 3(원인 분해) · 7(다음 달 준비 + 캘린더 .ics)** + 과거 달 선택.
- 허브 최상단 "N월 결산이 준비됐어요" 카드(노출 기간은 사업 절 제안 따름), 성적표의 "순자산 변화, 왜?"는 월 탭으로 이동.
- 월 탭 원인 분해를 공용 컴포넌트로 일/주/연 탭에도 재사용(신규 UI 최소).

**줄일 수 있는 것 (v1에서 빼고 v2로 이월 제안)**
- 블록 4 자산 유형별 비교: 블록 3 원인 분해가 이미 자산군(주식·코인·부동산·현금·대출)별로 묶여 있어(`groupAttributionItems`) **같은 정보의 중복**. v1은 원인 분해 그룹 헤더에 지난달→이번달 값을 한 줄 얹는 정도로 흡수.
- 블록 5 그달 배당: 배당 메뉴에 월별 막대가 이미 있음. v1은 빼고 필요하면 한 줄 링크("배당 보기")만.
- 블록 6 성적표 별점 변화: Plus 성격이고 월 스냅샷 `grade` 유무에 따라 빈 상태가 잦음. 결산의 핵심 질문(왜 바뀌었나)과 거리가 있음.
- 원인 분해 기간 "3개월": 분기 탭이 없으므로 제거(1주→주 탭, 1개월→월 탭, 올해→연 탭으로 흡수).
- 결론: **v1 = 블록 1·2·3·7** (이슈 질문의 "핵심만" 안에 동의). 4·5·6은 출시 후 `settlement_view` 체류·이탈을 보고 판단.

**하지 않을 것**
- 결산 전용 메뉴·별도 화면, 결산 공유 이미지·카드, Push 알림, 투자 권유·종목 언급, 다른 사용자 비교(이슈 6장 확정 사항).
- "이번 달 잘하셨어요"류 평가 문구 외 점수화·등급화 신규 도입(성적표와 중복).
- 분기/사용자 지정 기간, 전년 동월 비교, 목표 대비 진행률.
- 기록 스트릭을 결산에 연결하거나 공유 소재로 쓰기(LEARNINGS: 스트릭 카드 반려).
- 월 탭에서 입출금을 바로 입력하는 새 폼 신설(기존 현금 거래 화면으로 이동 링크만).

### 4. 통합 시 빠지거나 옮겨지는 하위 기능
| 기존 기능 | 새 위치 | 변화 |
|---|---|---|
| 순자산 일별 캘린더(일별 순자산·증감) | 자산 변화 > **일 탭**(전체 자산) | 그대로 이동 |
| 연속 N일 기록·기록률 | 일 탭 캘린더 하단 | 이동만. 월 탭에는 노출하지 않음("기록 안 된 변화"와 혼동 방지) |
| 연도별 수동 입력·수정·삭제 | **연 탭** 하단 | 그대로 이동. FAB 이벤트·원인 분해 시작점(`yearlyAnchorPoints`)이 이 데이터를 쓰므로 삭제 불가 |
| 순자산 월별 막대 + 월별 증감 목록 | **월 탭**(월 선택기 겸 추이) | 월 선택 UI로 변형. 증감 목록은 결산 헤더·순자산 비교(2)로 흡수 |
| 수익 일별/주간/월간/연간 | 자산 변화 일/주/월/연 탭 × **주식 범위** | 용어 통일(주간→주). 월·연 탭의 주식 범위는 종가 비교 유지 |
| 국내/해외/전체 필터 | **주식 범위에서만** 보이는 보조 필터 | 전체 자산 범위에서는 숨김. 월 탭 원인 분해에는 v1 적용 안 함 |
| 영업일/접속일 기준(`profit-basis-store`) | 주식 범위 일/주 탭의 설정 | 전체 자산 범위에서는 숨김(스냅샷 기준이라 무관) |
| 기준 종가 비교표·종목별 증감 | 주식 범위 각 탭 하단 | 그대로 이동 |
| 성적표 "순자산 변화, 왜?" | 월 탭 블록 3 (일/주/연 탭도 재사용) | 성적표에서 제거. 성적표에는 "이번 달 결산 보기" 링크 1줄 |
| 허브 "순자산" 카드(전년 대비) + "수익" 카드(일별 대비) | "자산 변화" 카드 1개 | 비교 기준을 **전월 대비**로 바꾸는 것을 제안(결산 진입과 일치). 일별 종가 조회가 허브에서 빠져 로드도 가벼워짐 |

### 5. 범위 토글 "주식"에서의 월 탭
- 헤더에 "주식 N월 결산 · 전체 자산 아님" 고정 표기, 순자산 비교(2)는 **주식 평가액** 지난달→이번달.
- 원인 분해(3)는 **시세 변동 / 환율 효과 / 순매수 / 기록 안 된 변화**. 주식 범위의 매수는 "주식으로 옮겨 넣은 돈"이므로 순매수(매수−매도)가 순유입 자리를 차지한다. 결정 4-4는 **전체 자산 기준**의 규칙이고, 주식 범위는 경계가 다를 뿐 뒤집는 것이 아니다. 단 전체 범위의 "순유입"과 같은 이름을 쓰면 혼동하므로 **"순매수"로 라벨을 구분**하고 범위 표시를 항상 붙인다.
- 환율 효과는 해외주식 평가액 기준만 보여야 한다. 엔진의 `fxBase`가 통화별 외화 노출 전체 기준이라 주식만 분리 가능한지는 developer 확인 필요(불가하면 주식 범위에서 환율은 "시세에 포함" 한 줄로 합치는 대안).
- 블록 6(별점)은 전체 자산 기준이라 주식 범위에서는 숨김(v1은 어차피 제외). 7(갱신 안 된 자산)은 주식 종목만.
- 시세 데이터는 서버 종가, 거래는 로컬 기록이라 새로 서버로 보낼 값 없음(4-5 유지).

### 6. 기록을 거의 안 하는 사용자 / 첫 달 사용자
**입출금·매매 기록이 거의 없는 사용자**
- 원인 분해에서 **시세·환율은 기록 없이도 계산**되므로 항상 먼저 보인다. "기록 안 된 변화"는 맨 아래, 회색 톤, 금액만 담담하게(경고색 금지).
- 기록 안 된 변화가 순자산 변화의 절반 이상일 때만(임계값은 spec에서 확정, 50%는 추정) 항목 아래 한 줄: "입출금을 기록하면 더 정확해져요" + 기존 현금 거래 화면 링크. 그 미만이면 안내 없음. 같은 달 안에서는 접을 수 있게.
- 헤더 숫자(순자산 증감)는 스냅샷 기준이라 기록 여부와 무관하게 정확하다는 점을 유지(4.33 문구 "예측" 설명과 같은 원칙).
- 현행 엔진의 `신규 현금/현금 정리`·`savingEffect`(기록 없는 매수 잔여) 항목은 이 사용자에게 가장 많이 뜬다 → 월 탭에서는 모두 "기록 안 된 변화" 하나로 합쳐 항목 난립을 막는다.

**첫 달 사용자 (지난달 스냅샷 없음)**
- 허브 결산 카드는 **비교 가능할 때만 노출**(비교 대상 없는 카드는 돌아올 이유가 되지 않음). 월 탭은 직접 열 수 있다.
- 월 탭은 비교 대신 "첫 기록이라 비교할 지난달이 없어요. 다음 달 결산부터 변화를 보여드려요" 한 줄 + 현재 순자산·구성만 + 블록 7(갱신 안 된 자산, 캘린더 추가). 월 중간부터 기록이 있으면 "N월 D일부터의 변화"로 폴백 구간을 헤더에 명시(엔진이 가장 오래된 포인트로 폴백하는 현행 동작과 일치).
- 사업 절 지표 `result=first_month`에 해당.

### 7. 사업 절 의견
**동의.** 방향·지표·노출 기간(말일 3일 전~다음 달 10일)에 이견 없음. 보완 2건(이견 아님):
- 지표 2의 "결산을 일반 월 탭 조회와 구분할 수 없다"는 우려는 결정 4-1(월 탭이 곧 결산)로 해소된다. **월 탭 진입 = `settlement_view`**로 정의하고 `source`(card/menu)만 구분하면 충분하다.
- 노출 기간이 13일로 길어도 카드는 최상단 1개로 한정하고 첫 달·비교 불가 시 숨기는 조건을 spec에 넣을 것(빈 결산 방지).
