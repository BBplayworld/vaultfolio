# #32 spec — 성과 메뉴 정리 + 월말 결산 (v1)

근거: direction.md 합의 절(축소 반영본) + challenge.md 조건 1~9. 위험 medium. 괄호 `(c#)` = challenge 조건 번호.

## 1. 문제
- 스크린샷 갱신 구조라 다시 열 이유가 없다. 목표(월 활성 100명)에 맞는 "월 1회 의식"이 필요하다.
- 성과 메뉴 4개(순자산·수익·배당·성적표) 중 순자산·수익은 "기간 대비 변화"로 혼동된다.
- 월 스냅샷이 1월 첫 접속에 전년분을 삭제한다(`asset-data-context.tsx:770` `startsWith(currentYear)`, qa 확정). 보존을 고치지 않으면 두 번째 결산(12월분)이 깨진다.

## 2. 목표 행동
말일 3일 전~다음 달 10일에 홈 아닌 성과 허브 최상단 카드로 들어와, 자산 변화 월 탭에서 "지난 기록 대비 순자산이 왜 바뀌었나"를 보고, 갱신이 필요한 자산을 확인해 입력 화면으로 이동하거나 캘린더에 일정을 추가한다.

## 4. 사용자 흐름
1. 허브 진입 → 노출 기간이면 최상단에 카드 "11월 결산이 준비됐어요 · 10/31 → 11/30" (비교 가능할 때만). 탭 → 자산 변화 월 탭, 해당 달 선택(`source=card`).
2. 메뉴로 자산 변화 진입 → 기본 범위 전체, 기간 탭 일/주/월/연. 월 탭 진입 시 `settlement_view(source=menu)`.
3. 월 탭 위→아래: ①헤더 "N월 결산 · M/D → M/D 기준" + 월 선택기 ②지난 기록 / 이번 기록 순자산과 증감액·% ③변화 원인(5항목, §5) ④다음 달 준비: 갱신 안 된 자산 목록(`getStaleCategories`, 기존 입력 화면 링크) + "캘린더에 매월 결산일 추가" 버튼.
4. 주식 토글 → 기존 수익 화면 내용(일/주/월/연, 국내·해외, 영업일·접속일 기준)을 그대로 표시.
5. 전체·일: 기존 일별 캘린더(연속 기록·기록률 포함). 전체·주(c6): 기존 일별 스냅샷(30일 롤링)에서 최근 7일 목록(날짜·순자산·전일 대비)과 7일 전 대비 증감 한 줄. 신규 계산·원인 분해 없음, 7일치가 안 되면 있는 만큼만. 전체·연: 기존 연도별 라인 차트와 수동 입력·수정·삭제 그대로.
6. 성적표의 "순자산 변화, 왜?" 링크(`growth`)는 자산 변화 월 탭으로 이동. 성적표 본문의 원인 분해 표시는 유지.

### 5-2. 결산 기준일 정의 (c3)
- 월 스냅샷은 앱을 연 날만 저장되고 `date`=그 달 마지막 기록일. 결산은 "달력 월"이 아니라 **직전 기록 → 해당 기록** 구간이며 헤더에 실제 날짜를 항상 표기한다. 레거시(`date` 없음)는 날짜 대신 "YYYY-MM 기록 기준".
- 카드 대상 달: 말일−3일~말일 = 이번 달(진행 중 구간, 시작=직전 스냅샷, 끝=오늘). 1~10일 = 전월 스냅샷 `date`가 전월 21일 이후면 전월 결산, 아니면 이번 달 구간(시작=직전 스냅샷, 끝=오늘). 이 구간의 시작→끝 간격이 25일 이상이면 제목은 날짜 구간만("11/5 → 12/5 변화"), 25일 미만일 때만 "N월 변화 · 진행 중". 21일·25일은 추정값(임계, 조정 가능).
- 시작점 = 대상 달 직전의 가장 최근 스냅샷(달이 건너뛰어도 허용). 시작·끝 간격이 35일 초과면 헤더에 "기록 간격이 길어 N일 구간이에요" 한 줄.
- 예시 ①매일 접속, 12/5: 전월 `date`=11/30 → "11월 결산 · 10/31 → 11/30". 12월 선택 시 "11/30 → 오늘 · 진행 중".
- 예시 ②월 1회 접속(10/5, 11/5, 12/5), 12/5: 11월 `date`=11/5 <11/21 → 카드 "11/5 → 12/5 변화"(간격 30일, "진행 중" 표기 없음). 월 선택기에서 11월을 고르면 "10/5 → 11/5".
- 예시 ③첫 달(스냅샷 1개): 카드 숨김, 월 탭은 빈 상태 문구.

### 5-3. 표시 매핑표: 엔진 키 15종 → 결산 5항목 (c4)
월 탭 전용 순수 함수 `mapSettlementCauses(effects, ctx)`. 엔진 호출 결과(`computePeriodAttribution`)를 입력으로만 쓰고 엔진·홈 헤더는 변경하지 않는다.
| 엔진 키 | 결산 항목 |
|---|---|
| `price`, `price:stock`, `price:crypto` | 시세 변동 |
| `price:realEstate` | 평가 갱신 |
| `fx` | 환율 효과 |
| `income` | 순유입 (입금−출금) |
| `buy/sell:stock`, `buy/sell:crypto`, `buy/sell:realEstate`, `debt`, `cash` | 내부 이동 풀: 아래 규칙으로 서로 상쇄 |
| `deposit` | 기록 안 된 변화 |
- 내부 이동 풀: G=Σ(buy/sell·debt, 부호 포함), C=`cash`. 현금 등록 사용자(시작·끝 `breakdown.cash` 중 하나라도 >0)는 G와 C가 반대 부호일 때 `min(|G|,|C|)`만큼 서로 지워 표시하지 않고(매수·상환·추가 대출은 순자산을 안 바꿈), 남은 G·C는 기록 안 된 변화로 간다.
- 결정 4-4 예외: 시작·끝 `breakdown.cash`가 모두 0이고 현금 입출금 기록도 없으면 매수·매도(주식·코인·부동산)는 순유입으로 귀속. `debt`는 예외에 포함하지 않는다(보수적).
- 기록 안 된 변화 = Δ순자산 − (시세+평가갱신+환율+순유입). 항등식 합계=Δ순자산 유지(만원 반올림 오차 제외), 단위 테스트로 고정.
- 기록 안 된 변화 안내: |값|이 |Δ순자산|의 50% 이상(추정 임계)이면 "이번 달 입출금을 기록하면 더 정확해져요" 한 줄. 접기 저장 없음.
- 금액 0인 항목은 숨김.

### 5-4. 추정 배지 용어 (c5)
화면 문구는 기존 "예측"·"일부 예측" 배지로 통일하고 "추정"은 사용하지 않는다. 엔진이 `estimated`/`estimatedUntil`을 주면 항목에 배지. 갱신 안 된 자산은 블록 7에 "N일 전 값 기준"으로 표시하고 블록 2 아래 한 줄 "일부 자산은 이전 값 기준이에요". 재촉 문구 금지.

## 6. 엣지 케이스 (c9)
- 첫 달: 스냅샷 1개 → 카드 숨김, 월 탭 "다음 달부터 결산이 열려요". 2개월차 이후 활성.
- 일부 갱신: 부동산 등 미갱신 자산은 이전 값 이월 → 블록 7 목록 + 블록 2 한 줄. 평가 갱신 항목은 값이 있을 때만.
- 기록 없음(입출금·거래 0건): 순유입 숨김, 변화 대부분 시세·기록 안 된 변화. 안내 한 줄만.
- 해외자산만: 환율 효과·시세 변동만 표시, 현금 미등록이면 매수는 순유입.
- 1월 경계: 1/1~1/10 "12월 결산"의 시작(11월)이 13개월 보존으로 존재. 월 선택기는 연 경계를 넘어 정렬.
- 레거시 스냅샷(enrich·`date` 없음): 원인 분해는 엔진 예측 경로, 배지 "예측"/"일부 예측", 날짜 대신 YYYY-MM 표기.
- 자산 0건/스냅샷 0건: 카드 숨김, 월 탭 빈 상태.
- 스냅샷이 13개월 미만이면 있는 달만 선택 가능. 선택 가능 달 밖은 비활성.

## 7. 옛 해시·진입점 이전·회귀 (c7, c8)
- 해시: `#activity/netasset` → `#activity/change`(전체·연), `#activity/profit` → `#activity/change`(주식·일). `ActivityTab`을 hub/change/dividend/report로 줄이고 옛 값은 `parseHash`에서 리다이렉트(북마크·공유 링크 보호).
- 진입점: `config/app-features.ts` 카드 2개→1개("자산 변화", 저장된 옛 id 기록은 무시), `tutorial-store.ts` step5 `profit` 하위 단계 대상, `top-bar.tsx:111` 뒤로가기 조건, `asset-report-view.tsx:423` growth, `floating-add-button.tsx:110` 연도별 순자산 입력(자산 변화·연 탭의 입력 다이얼로그를 연다, 기존 이동 후 이벤트 패턴 유지), `performance-hub.tsx` 카드, `ga.ts:191-192` 화면키·`ga.test.ts`.
- `.ics`(c8): 이벤트 1개 "시크릿에셋 월말 결산" 매월 마지막 날 21:00 KST, `RRULE:FREQ=MONTHLY;BYMONTHDAY=-1`, 제목·설명에 금액 없음. 서버 호출 없음. 검증은 표준 .ics 형식(RFC 5545) 유효성 자동 검증(필수 속성·RRULE·줄바꿈 CRLF)으로 한다. iOS 홈 화면 PWA(standalone)에서의 실동작은 알려진 한계로 기록하고 사람 확인은 요청하지 않는다. 실패 시 대체: 버튼 아래 "캘린더 앱에서 매월 말일 저녁에 반복 일정을 추가해 주세요" 안내 문구 상시 노출.
- 회귀 F-*: F-ACTIVITY(순자산·수익 이전, 원인분해 R23·R29 불변, 항등식 테스트), F-HOME-TIP(기능 카드 15→14, `pickRecommendedFeature`·`getStaleCategories` 재사용), F-NAV(해시·뒤로가기), F-ONBOARD(step5), F-ANALYTICS(화면키), F-SYNC·F-SHARE(스냅샷 보존·토큰), 홈 헤더 원인 분해(엔진 미변경 확인).

## 8. 완료 기준 (preview 데모 데이터, #31 선행)
1. 성과 허브에 카드가 자산 변화·배당·자산 성적표 3개만 보이고 순자산·수익 카드는 없다.
2. 자산 변화에서 기간 탭 일/주/월/연과 범위 토글 전체/주식이 보이고 현재 범위 이름이 상단에 항상 표시된다.
3. 주식 범위의 일·주·월·연 화면은 기존 수익 화면과 같은 값을 보인다. 주식·월 탭에는 결산 블록이 없다.
4. 전체·월 탭에 블록 헤더·순자산 비교·변화 원인·다음 달 준비만 있고 유형별 비교·배당·별점 블록은 없다.
5. 헤더에 "M/D → M/D 기준" 실제 기록일이 표기된다(§5-2 예시 ①②③ 각각의 날짜 상황을 데모 또는 단위 테스트로 재현).
6. 변화 원인 5항목 중 0원인 것은 숨겨지고, 표시된 항목 합계가 순자산 증감액과 같다(만원 반올림 오차 제외). 매수·매도·상환 문구는 월 탭 어디에도 없다.
7. 현금 미등록 데모에서 주식 매수는 "순유입"에, 현금 등록 데모에서는 매수가 표시되지 않는다(단위 테스트로 키별 금액 단정).
8. 월 스냅샷 입력 [2025-10, 2025-11, 2025-12] + 현재월 2026-01에서 보존 결과가 4건이다(vitest). 14번째로 오래된 달은 삭제된다. "올해분만 있는 이전 버전 데이터"를 읽어도 오류 없이 결산이 열린다.
9. 말일−3일~다음 달 10일 밖에는 허브에 결산 카드가 없고, 첫 달에는 기간 안이어도 없다. 카드 탭 시 월 탭의 해당 달이 선택된다.
10. 월 선택기에서 저장된 달만 선택되고 그 밖은 비활성이다.
11. 블록 7은 30일 이상 미갱신 카테고리를 "N일 전 값 기준"으로 보여주고 입력 화면으로 이동시키며 재촉 문구가 없다.
12. "캘린더에 추가" 탭 시 반복 일정 1개짜리 `.ics`가 받아지고 파일이 표준 .ics 자동 검증(`BEGIN:VCALENDAR`/`VEVENT`, `UID`·`DTSTAMP`·`DTSTART`, CRLF, `RRULE:FREQ=MONTHLY;BYMONTHDAY=-1`, 금액 없음)을 통과한다. iOS PWA 실동작은 알려진 한계로 기록한다. 안내 문구가 항상 보인다.
13. `#activity/netasset`, `#activity/profit`으로 진입하면 자산 변화 탭(각각 전체·연, 주식·일)이 열린다. FAB 연도별 순자산 입력, 성적표 growth 링크, 튜토리얼 5단계, 뒤로가기가 모두 동작한다.
14. 레거시 스냅샷(enrich 없음) 데모에서 결산이 열리고 "예측" 배지가 보인다.
15. 홈 헤더 원인 분해 표시와 성적표 결과가 변경 전 preview와 같다. `npx vitest run`·`tsc`·`lint` 통과.
16. 서버로 새로 보내는 값이 없다(네트워크 요청에 자산 값 없음). 결산 화면에 투자 권유 문구가 없다.
17. `settlement_view`가 월 탭 진입 시 `source`(card/menu), `result`(`settled`=전월 결산 / `in_progress`=진행 중 구간(간격 25일 미만) / `first_month`)만 담아 월 탭 진입당 1회 발생한다. 탭 재진입 없이 월 선택기만 바꿔도 중복 발생하지 않는다. 월 1회 방문자의 날짜 구간 표기는 `settled`로 분류.

## 교차 검토 (business-pm)

수정 요청: 아래 3건. 나머지는 동의.

1. (수정 요청) iOS 실기기 확인 제거. §7 `.ics` 항의 "developer가 실기기 1회 확인"은 사람 작업을 전제하므로 불가. qa 자동 검증(표준 .ics 형식: `BEGIN:VCALENDAR`/`VEVENT`, `RRULE:FREQ=MONTHLY;BYMONTHDAY=-1`, CRLF, `UID`·`DTSTAMP`·`DTSTART` 존재, 금액 없음)으로 대체하고, iOS PWA 동작은 "미검증" 보고로 남긴다. 안내 문구 상시 노출 대체안은 그대로 유지. 완료 기준 12와도 맞춘다.
2. (수정 요청) `result` 값 추가. 현재 `normal/first_month`만 있어 지표 2에서 "전월 결산"과 "진행 중 구간"을 구분할 수 없다. 월 1회 방문자(진행 중 구간)의 갱신 전환이 따로 보여야 21일 임계를 조정할 근거가 생긴다. `result`를 `settled`(전월 결산) / `in_progress`(진행 중 구간) / `first_month`로 하고 `PARAM_VALUES`·`PARAM_LABELS`에 등록. 파라미터 개수는 `source`, `result` 두 개 유지, 금액 미전송.
3. (수정 요청) 카드·헤더 문구. 월 1회 방문자에게 "12월 변화 · 11/5 → 12/5 기준 · 진행 중"은 결산을 받았는데 미완성으로 읽혀 결산 의식과 어긋난다. 그 사용자에게 11/5→12/5가 사실상 한 달 결산이기 때문이다. 전월 스냅샷 `date`가 21일 이전이어도 시작→끝 간격이 25~35일이면 "진행 중" 대신 날짜 구간만 표기("11/5 → 12/5 변화"), "진행 중"은 간격이 25일 미만일 때만 쓴다(25일은 추정). 월 선택기 11월 항목의 "10/5 → 11/5"는 유지.

검토 쟁점별 의견
- 임계값 3개(21일, 50%, 35일): 지표 1(결산 창 재방문)은 카드 노출 기간(말일-3일~10일)만 쓰므로 세 임계값과 무관해 기준선 비교는 영향 없음. 영향은 지표 2의 해석에만 있어 위 2번으로 풀린다. 50%·35일은 표시용이라 지표 영향 없음. 세 값 모두 추정이므로 출시 후 `result` 분포를 보고 조정한다.
