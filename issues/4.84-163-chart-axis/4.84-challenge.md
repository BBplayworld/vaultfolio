## 판정 ① 행 미니 차트 → 이름 줄 아래 전폭 밴드 80px — 채택, 위임 ⑦ 비해당(조건부)
- 32px×48~160px 스파크에는 눈금 2~3줄+현재가가 물리적으로 안 들어간다. 대표가 요청한 내용(y눈금+오늘 주가)의 필연적 결과이고, 요소의 역할(이름 줄 = 종목 한 장 입구 + 1년 흐름 + 평단 점선)·위치 블록·탭 동작은 R-A 그대로다. "대표가 모르는 방향 변경"·"반려 방향 재도입"이 아니므로 ⑦ 비해당.
- 단 대표가 오늘 승인한 R-A의 **모양**(오른쪽 작은 스파크)을 키우는 변경이므로: 방향 확정 알림(대시보드)에 **다크 전/후 캡처 1쌍(375)** 과 "펼친 행 +88px"를 정보로 올린다(승인 요청 아님). 대표가 이견을 내면 즉시 대표 승인 트랙으로 전환(4.81과 같은 방식).
- 64px 대안 비교: 64px는 현재가 태그(2줄)와 눈금이 겹쳐 눈금이 1줄로 줄어드는 경우가 잦다 → "축"이 아니라 숫자 1개가 된다(대표 요청 미충족). 높이 차는 16px뿐. **80px 확정**, 폭별 분기 없음(320·375·1280 동일).

## 판정 ② 렌더 방식 — 실측 픽셀 SVG(ui안) 확정
- 찌그러짐 원인은 `preserveAspectRatio="none"`이다. 이를 폐기하고 price-chart.tsx의 `useBoxSize` 패턴을 재사용하면 SVG `<text>`가 정상이고, 행·종목 한 장이 같은 좌표계(가격 칸 gutter)를 쓴다. HTML 오버레이는 좌표를 두 번 맞춰야 해 더 크다.
- `useBoxSize`는 price-chart.tsx 내부 함수 → 공용 위치(hooks 또는 stock-page 폴더)로 옮겨 재사용, components/state-and-utils에 등록. 측정 전(폭 0) 첫 렌더는 같은 80px 슬롯만 그린다(높이 점프 0).
- 컴포넌트 통합은 `PriceAxisLayer`(눈금선·눈금 라벨·현재가 점·태그)까지만. 선·점·칩은 각자.

## 판정 ③ 현재가 vs 선 끝점 — 값은 currentPrice, 라벨은 `현재가`
- 값: 행 패널의 `현재가` 칸과 **같은 값·같은 포맷 함수**(`formatCurrencyDisplay(currentPrice, stock.currency)`)로 그린다. ui안의 `formatPrice`가 아니다(C65: 같은 화면 200px 아래 `현재가 70,000원`과 문자열이 같아야 함). 그룹 합산 행이면 `head.merged.currentPrice`, 패널 칸 값과 일치 확인.
- 라벨: **`오늘` 대신 `현재가`**. 해외주식은 한국 낮에 `11/10 종가`, 주말·휴장일·개장 전도 전일 종가라 `오늘`은 틀린 시점 라벨이다(C69). `현재가`는 같은 카드에서 이미 쓰는 말이라 새 용어도 아니다. 행 aria-label도 `…, 현재가 70,000원`.
- 선 끝점: history는 그대로 그리고(값을 덧붙여 조작하지 않음), 점은 `currentPrice` y에 찍는다. 장중 어긋남은 허용. 도메인에 currentPrice 포함(태그가 범위 밖 0). currentPrice 없음/0이면 점·태그 생략, 눈금 유지.

## 판정 ④ 매도 점 — 범위 축소 안 함(1y·5y 모두)
- `placeBuyDots`가 5년 주봉을 이미 처리해 "1년만"으로 줄여도 절감이 거의 없다. 비용의 본체(선택 키 `{kind,index}`·합친 배열 히트 반경·같은 봉 ±6px)는 1년에도 그대로 필요하다.
- 최소 구현 지시: 거래 추출은 `pickBuyTransactions`에 `type` 인자 추가(기본 buy, 기존 호출 불변). 이름 일반화(TradeTx) 금지. 평단·성적표 계산 불변(점 표시 전용).
- 문구는 ui.md §3대로(매수만 종목은 기존 문구 그대로, 매도 포함 시에만 `매수·매도`·`거래 N건`). **매도만 기록한 종목**에서 점·힌트·창 밖 건수·`거래내역 n건`이 서로 모순 없음(C80).

## 판정 ⑤ 공통 로딩 UI — 축소 통과
- 대표 지적의 원인은 ① 막대가 카드와 거의 같은 색 ② 문구가 없거나 카드 맨 아래(스크롤 밖)다. 이 둘만 고치면 해결된다.
- **포함**: `ui/skeleton.tsx` 색을 `bg-foreground/[0.13] motion-safe:animate-pulse`로(신규 keyframe 없음, shimmer 제외), `LoadingNote`(스피너 14px·13px muted·영역 맨 위·0.5초 뒤 표시·5초 뒤 지연 문구·sr-only `role=status` 1개), 훅 `useLoadingPhase`. 적용 화면: 시장 비교(표·종목별 리스트·허브 타일 부제), 종목 한 장 차트·헤더 1년 등락, 행 밴드(문구 없음, 스켈레톤만), 배당 4곳(허브 값 자리 스켈레톤 + 문구 통일), 자산 변화 히어로·profit-chart(문구만 통일).
- **제외**: shimmer keyframe, X-Ray 0% 불확정 하이라이트(현행이 이미 가장 양호), 시작 로딩 덮개, `sync-qr`, 로딩이 아닌 `animate-pulse`(stock-tab 막대·dashboard 글자)는 손대지 않는다.
- Skeleton 교체 회귀: 기존 사용처 `sidebar.tsx`·`ratio-preview.tsx`도 색이 진해진다 — 허용, qa가 두 화면 다크·라이트 캡처 1장씩. 기존 테스트가 `animate-pulse` 문자열을 확인(hub-change-rows·stock-entry-tools) → 클래스 유지로 통과해야 한다.
- 문구: `기준가 조회 중…`·`조회 중…`·`조회 중...` → `시세를 불러오는 중…`(시장 비교·profit-chart·히어로), `배당 정보를 불러오는 중…`(배당). `기준가`는 내부 용어라 폐기 승인. **`점검 중`(KIS 점검, asset-report-view)과 API 오류 토스트 `조회 중 오류가…`는 변경 금지**(다른 의미).
- 시장 비교 스켈레톤은 **최종 내용과 같은 행 수**(현재 4기간×2시장 블록 그대로). ui 목업의 3행·1블록은 목업 생략으로 보고 따르지 않는다.
- 실패: 시장 비교 기존 60초 자동 재시도(최대 2회) 유지, 소진 후에만 `불러오지 못했어요`+`다시 시도`(secondary, min-h-10). 종목 한 장은 현행 `다시 시도` 유지.
