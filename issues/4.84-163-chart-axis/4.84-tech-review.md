## 1. y축 눈금 + 오늘 주가 (stock-row-flow.tsx · price-chart.tsx 공용화)
영향: `src/lib/finance/stock-page.ts`(신규 순수 함수 `niceTicks(lo,hi,count)`, 눈금 라벨 `formatAxisPrice`), `stock-row-flow.tsx`, `stock-page/price-chart.tsx`, `src/lib/finance/__tests__/stock-page.test.ts`. 규모 약 +80줄 + 테스트 약 60줄.
- **nice tick**: 신규 1개를 stock-page.ts에 둔다. 도메인은 기존 `computeYDomain`(평단 포함·PAD 8%) 결과를 그대로 입력으로 써서 선·평단 y와 눈금이 어긋나지 않게 한다. 눈금은 도메인 안에 들어오는 1·2·5×10^n 배수 2~3개만(도메인 밖 값은 버림). 폭 0 방어(span 최소값은 computeYDomain이 이미 보장).
- **통화별 표기**: KRW `₩`가 아닌 기존 `formatCurrency`(원) 재사용, USD는 `$` + 소수 2자리까지. 눈금은 좁은 공간이라 축약 필요: KRW 만 단위(`8.5만`)·USD 정수 우선(눈금 간격이 1 이상이면 소수 생략). 축약 함수는 `formatAxisPrice` 1개로 신규. 마우스 호버·칩 같은 정밀 표기는 기존 `formatPrice` 유지. 중복 정의된 `formatPrice`는 이번에 합치지 않는다(범위 밖, 정리 후보로만 기록).
- **다운샘플(40점) 영향**: 눈금은 도메인에서 계산하므로 점 수와 무관. 단 `buildSparkGeometry`가 **다운샘플 40점의 min/max**로 도메인을 만들어 원본 1년 고저와 약간 다르다(점 사이 극값 누락). 지금은 모양만 그려 문제없지만, 눈금 숫자는 사용자가 읽으므로 **눈금·도메인은 원본 points 기준**으로 계산하도록 `buildRowFlow`에서 원본 min/max를 넘기거나 geom을 원본 도메인으로 다시 계산(선만 40점)해야 한다. 안 하면 "최고가 눈금보다 선이 위로 삐져나가는" 오표시 위험. 이 경우 다운샘플은 선 좌표용으로만 유지.
- **미니 차트 공간**: 현재 SVG가 `h-8`(32px)·`preserveAspectRatio="none"`이라 SVG 내부에 텍스트를 넣으면 가로 늘어남으로 글자가 찌그러진다. 눈금 라벨은 **SVG 밖 HTML 오버레이/별도 칼럼**(우측 정렬 `text-[10px] tabular-nums`)로 그려야 한다. 320px 폭에서 스파크가 `w-12`(48px)까지 줄어드는 구간이 있어 눈금 라벨 칼럼을 더하면 이름 줄이 좁아진다 → ui 사양에서 최소폭 이하 숨김 규칙 필요(폭 부족 시 눈금 생략, 오늘 주가만 유지).
- **오늘(최신) 주가 출처 — 권고: 실시간 시세 필드(`head.merged.currentPrice`)**. 이유: 접힌 행·종목 한 장 머리의 평가금액이 `merged.currentPrice`(저장된 시세)로 계산되므로(`computeStockMetrics`), history 마지막 점(종가·갱신 시차·일봉 마감 전/후 차이·5년은 주봉이라 마지막 주 값)을 쓰면 같은 화면에서 숫자가 갈라진다(C65 위반). `currentPrice`는 종목 통화 단위로 `price-history`의 `currency`와 같다(KRW/USD). 단 **차트 선 끝점(history 마지막 점)과 라벨 값이 다를 수 있음**(장중). 라벨은 "오늘 주가"가 아니라 중립 표기 + 선 끝점에 점을 찍지 않는 방식으로 어긋남을 숨긴다(ui 판단). history가 없을 때 라벨만 단독 표시하는 경로는 만들지 않는다(fallback 행 높이 불변 유지).
- **종목 한 장 공용화**: 눈금 계산(`niceTicks`)과 라벨 함수만 공용(stock-page.ts). 렌더는 분리 유지 — 미니(HTML 칼럼)와 큰 차트(SVG `<text>` + 가로 격자)는 좌표계가 달라 컴포넌트 통합은 과설계. 큰 차트는 `M.left/right = 12`라 눈금 라벨이 선과 겹치므로 좌측 여백을 늘리거나 라벨을 격자선 위 안쪽 정렬로 둔다(spec 판단). 큰 차트 눈금은 평단 칩·호버 라벨과 충돌 검사 필요.
- **줄이는 안**: 큰 차트(종목 한 장) y눈금은 이번 범위에서 제외하고 미니만 하는 것도 가능하나, spec이 둘 다 원하면 유지. 최소안 = 눈금 2줄(최저·최고 nice 값).
- 테스트: `niceTicks` 단위(KRW 대·소형, USD 소수, 폭 0, 평단 포함 도메인, 눈금이 도메인 안), 원본 vs 다운샘플 도메인 일치, 최신가 = `merged.currentPrice`와 행·머리 문자열 동일(C65), 320px 눈금 숨김.

## 5. us-stock-master NAS 편중
- **현상**: `src/lib/data/us-stock-master.json` 7,013건 **전부 `exchange: "NAS"`**(NYS·AMS 0). 실제 NYSE 종목(JPM·KO·XOM·DIS·WMT·V·JNJ·BA·T·F·GE·IBM)도 NAS로 기록, 이중 상장 표기 종목(`BRK.B` 등)은 마스터에 아예 없음.
- **원인**: `src/lib/data/README.md` 재생성 절차가 `nasdaq.com` 스크리너 CSV 전부를 대상으로 하고 거래소는 `other-listed.csv`의 ACT Symbol 매핑으로 NYS/AMS를 보강한다. 매핑이 비었거나(other-listed 미제공·키 불일치) 기본값 `'NAS'` 폴백으로 전부 채워진 것으로 보인다(4.12 `[#4.12] 주식 자동완성` 생성 커밋 `dc81161` 이후 갱신 없음). 근거는 파일 분포와 README 로직으로 추정이며 생성 당시 입력 CSV는 저장소에 없어 확정은 못 함.
- **규모·영향**: 소비처 3곳. ① `us-master.ts:66` `EXCHANGE_BY_TICKER` → `getUsExchange`가 `price-history.ts:157`에서 거래소 **힌트**로만 사용. 코드가 이미 "마스터 거래소는 힌트일 뿐" 주석과 함께 `[힌트, NAS, NYS, AMS]` 순 폴백·성공 시 고정으로 방어(4.81 이후). NYSE 종목은 첫 호출(NAS)이 빈 응답·오류면 NYS로 넘어가므로 **결과는 올바르나 KIS 호출이 최대 2~3배**(종목당 첫 회차만, 이후 `excdList` 고정). ② `ticker-search/route.ts:72` 검색 결과 `market: e.exchange` — 자동완성에 **NYSE 종목이 NAS로 표기**되고 이 값은 `stockMarkets` localStorage(`STORAGE_KEYS.stockMarkets`, 종목 한 장 `marketLabel`)로 저장돼 화면에 `· NAS`로 표시될 수 있다 → 사용자 눈에 보이는 **오표기**. ③ 시세 조회(`/api/finance`)는 거래소 힌트가 쓰이는지 별도 확인 필요(이번 grep에서는 사용처 없음).
- **권고: 이번 4.84에서 제외.** 이유: 마스터 재생성은 외부 CSV 입력이 필요하고(저장소 외부 데이터·대량 JSON diff 7천 줄), 가격 이력은 이미 폴백으로 정상 동작하며, 표기 오류는 4.84 범위(차트 축·점·시트)와 무관하다. 대신 **별도 이슈(정리/버그, risk:low)**로 분리: (a) 재생성 입력 재확보 후 NYS/AMS 반영 + `BRK.B` 처리, (b) 최소 임시 조치로 `ticker-search` 응답에서 마스터 exchange를 신뢰하지 않고 `market`을 비우거나 'US'로 표기. 둘 다 저장 스키마 영향 없음(단, 이미 저장된 `stockMarkets` 값은 그대로 남아 있음 — 재생성 후 기존 값 갱신은 별도 판단).
