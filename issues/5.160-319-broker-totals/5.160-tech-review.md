# 5.160 증권사별 합계·마지막 맞춘 날 — tech-review (main 최신 기준, 코드 수정 없음)

## 결론
- **증권사별 합계 v1 = 저장 변경 0, 계산·표시만. risk:low.**
- **'마지막 맞춘 날'은 기존 필드로 증권사 단위를 정확히 낼 수 없다. v1에서 뺀다.** 넣으려면 새 필드가 필요하고 high로 재판정한다.

## 1. 영향 파일
- `src/app/(main)/_components/views/detail/tabs/stock-tab.tsx`
  - `useFilteredStockData`(166~264, 카테고리 필터·그룹·totals 정본), 카테고리 `InlineSelector`(1250), `StockSummaryHeader`(370, `DetailSummaryHeader` 래퍼)
- 신규 순수 함수 1개(예: `src/lib/asset/broker-totals.ts`): `Stock[]`을 증권사별로 묶는다. `computeStockTotals`(`asset-detail-tabs`, grow-board도 사용)와 `computeStockMetrics`를 그대로 재사용한다. 평가·손익·종목 수를 따로 계산하지 않는다. 여기서 값을 다시 계산하면 허브·헤더와 값이 어긋난다.
- 증권사 정규화: `isUnassignedBroker`·`sameBroker`(`src/lib/asset/resync/match.ts:10,16`)를 재사용한다. 이 둘은 resync가 이미 쓰는 동일 판정이다.
- 미지정은 '증권사 미지정' 한 묶음으로 둔다. 여러 계좌에서 같은 종목을 갖는 경우를 위해 합산은 `filteredStocks`(행 단위)를 기준으로 하고, 그룹 병합 결과(`groupedStocks`)에서 거꾸로 나누지 않는다. 같은 ticker가 여러 증권사에 있으면 병합 행에서는 증권사 분리가 안 된다.
- 상장폐지(`inactiveStatus="delisted"`)는 평가·원가 합에서 제외한다. `computeStockTotals`가 이미 처리한다(217행 주석). 합이 어긋나는지는 테스트로 확인한다.
- 코인(`Crypto.exchange`, types/asset.ts:116)은 v1 범위 밖이다. 요청은 상세·주식이다. 코인 탭은 1줄 후속으로 분리한다.
- 비상장·`unlisted`는 broker가 비어 있는 경우가 많아 '미지정' 쪽으로 간다. 이 점을 문구에 반영한다.

## 보기 위치 (재사용 지점)
- **권장(최소)**: 카테고리 selector 아래·목록 위에 접기형 '증권사별' 블록 1개를 둔다. 읽기 전용이고 상태 키를 새로 만들지 않는다. 열림 상태는 컴포넌트 `useState`에만 둔다. 기존 `stock-category-row`와 목록은 건드리지 않는다.
- 비권장: selector에 '증권사' 탭을 추가하는 안. `activeCategory`가 `useFilteredStockData`·`groupByTickerOnly`·`visibleCategories`·`denseCategories`에 퍼져 있어 영향이 크다. 보기 상태를 localStorage에 남기면 키 추가로 재판정 대상이 된다.
- 인증카드(SHOT): `StockSummaryHeader`·`StockCategorySection`은 `screenshotMode`/`shotBig`으로 같이 쓰인다. 신규 블록은 `!screenshotMode`에서만 렌더하면 SHOT DOM이 0 변경이다. 블록을 인증카드에 넣는 일은 이번에 하지 않는다. 넣으려면 `ASSET_THEME_SHOT` 토큰 고정과 PNG 캡처 스냅샷이 필요하다. 기존 `decision-unset-baseline` 스냅샷이 깨지지 않는지 확인한다.
- 금액 마스킹(`maskFn`/hideAmounts)과 원/달러 토글(`displayCurrency`)을 따른다. KRW 환산은 `computeStockTotals(..., displayCurrency)`로 한다.

## 2. '마지막 맞춘 날' — 기존 필드 점검
| 필드 | 단위 | 판정 |
|---|---|---|
| `lastRefreshedAt("stock")` (`asset-refresh-status.ts`, 로컬 `secretasset_asset_refresh`) | 자산군 전체 | 증권사 단위 불가. 기기 로컬(동기화 안 됨)이고, 수동 저장 때도 갱신된다 |
| `Stock.positionEffectiveDate` | 종목 행 | resync가 수량·평단이 바뀐 행만 갱신한다(`resync/apply.ts:225`). 변경이 없는 'same' 행은 갱신하지 않는다. 거래 입력은 거래일로 덮는다(`trade-input.tsx:466`). '맞춘 날'이 아니라 '수량이 바뀐 날'이다 |
| `Stock.positionSource` | 행 | "manual"/"computed" 구분뿐, 날짜 없음 |
| `Stock.purchaseDate` | 행 | 산 날 |
| 증권사 단위 맞춤 이력 | — | **없다.** resync 결과는 `markCategoryRefreshed(kind)`로 자산군 단위만 기록한다(`holdings-resync-dialog.tsx:387`) |

- 증권사 행에 `max(positionEffectiveDate)`를 '맞춘 날'로 표시하면 거짓 정보가 된다. 동일 수량으로 다시 맞춘 날은 반영되지 않고, 거래 입력일이 섞인다. 이 표시를 쓰지 않는다.
- 새 필드가 필요한 경우의 선택지(전부 v1에서 하지 않음)
  - (A) `Stock.syncedAt?`(행 단위): `assetData` zod 스키마 변경이다. **C151**: 구버전 기기가 저장·복원할 때 zod strip으로 필드가 소실된다. 동기화·백업 스키마가 바뀌어 **risk:high**이고 마이그레이션·복원 테스트가 필수다.
  - (B) 증권사별 날짜 맵을 별도 로컬 키(#58 분리 키 방식)에 둔다: `assetData` strip을 피하고 저장 스키마 변경이 0이다. 기기 로컬이라 다른 기기에 전달되지 않는다. `assetRefresh`가 `clearAssetData` 보존 키(`demo-inject.ts:28`)인 점, 백업·복원에서 이 키가 어떻게 취급되는지를 qa가 점검한다. 새 저장 키 추가는 저장 키 변경에 해당해 **medium 이상으로 재판정하고 위임 머지 조건 ④에서 제외**된다.
  - 권장: 이번 릴리스는 소계만. 날짜는 보류하고, 필요가 확인되면 (B)로 별도 릴리스를 연다.

## 3. 맞추기 바로가기 진입점
- 현재 `HoldingsResyncDialog`는 `open/onOpenChange/kind`만 받는다(`holdings-resync-dialog.tsx:135`). 증권사는 스크린샷에서 인식하거나 사용자가 고른다(`brokerOverrides`). 증권사 사전 지정 prop은 없다.
- v1 바로가기: 증권사 행에서 기존 보유 현황 맞추기를 그대로 연다(`stock-input.tsx:578` 방식). **증권사 프리셋은 넣지 않는다.** 프리셋은 `resolveScreens` 흐름을 건드리고, 맞춤 범위(그 증권사 외 종목은 삭제하지 않음) 규칙과 얽히기 때문이다.
- 진입점은 `StockInput`을 감싸는 기존 FAB·시트 경로를 재사용해야 한다. stock-tab에 새로 `HoldingsResyncDialog`를 두면 이중 마운트가 된다. 구현 전에 기존 오픈 이벤트(`CATEGORY_REFRESHED_EVENT` 반대편)가 있는지 확인한다.
- 증권사 프리셋이 꼭 필요하면 `initialBroker?: string` prop 1개를 추가한다. 이 prop은 UI 상태일 뿐 저장 변경은 0이다. 이 경우 resync 회귀 테스트(`resync.test.ts`)를 넓힌다.

## 4. 저장·서버·동기화·데이터 영향
- 저장 스키마 변경 0, 새 저장 키 0, 마이그레이션 0, 동기화·공유 토큰·백업·성적표 계산 입력 변경 0. 구버전 혼재·롤백으로 인한 기록 손실이 없다(읽기 전용 파생값).
- 서버 전송 값 증가 0. 증권사별 합은 클라이언트에서만 계산한다. 시세 조회 파라미터(ticker)도 그대로다.
- 증권사명은 사용자가 입력한 값이다. 서버로 보내는 신규 경로를 만들지 않는다. GA 이벤트 title에도 증권사명·금액을 넣지 않는다(새 GA title은 '증권사별 열기' 정도의 고정 문자열 1개).
- 문구: '합계'는 평가 사실 표기만 한다. 비중 변경·매수 권유 문구를 쓰지 않는다.

## 5. 테스트
- 단위(vitest): `broker-totals` 순수 함수. 증권사 3개+미지정+delisted+USD 종목+동일 종목이 2개 증권사에 걸친 경우+적립식으로 나눠 산 경우. 증권사 합계의 총합이 `computeStockTotals`(전체)와 같은지 확인한다. 이 값 일치 테스트가 핵심이다.
- 컴포넌트: `stock-tab` — `screenshotMode`에서 블록이 렌더되지 않음(SHOT DOM 불변), 마스킹 시 금액이 가려짐, 320·390 폭에서 긴 증권사명이 줄바꿈되는지.
- 기존 스냅샷(`decision-unset-baseline`)과 `stock-entry-tools.test.tsx`, `price-asof-309.test.tsx`가 그대로 통과해야 한다.
- 데모 데이터(`src/lib/preview/demo-data.json`)의 broker 분포로 preview에서 확인한다.
- qa: CHECKLIST 전 항목(C151은 N/A로 명기, 스키마 변경 0 확인), 증권사 필드가 비어 있는 데이터, 코인 탭 불변.

## 6. 위험 등급 초안
- v1(소계만, 읽기 전용, 상태 저장 없음, SHOT 불변): **risk:low**. CEO 판정의 위임 머지 조건 ①~⑧ 충족 가능.
- 보기 상태를 localStorage 키로 저장하거나 '맞춘 날'용 날짜 맵(B)을 추가하면 **medium 이상으로 재판정**한다. 행 필드(A)를 추가하면 **high**다(C151·마이그레이션·복원 테스트·대표 승인).

## 7. 줄이는 방법
- v1은 (1) 순수 함수 1개 (2) 접기형 블록 1개 (3) 증권사 행의 기존 맞추기 열기 버튼 1개로 제한한다. 행에 '맞춘 날' 대신 이미 있는 자산군 단위 `lastRefreshedAt("stock")`을 상단 1줄로 쓰는 안은 증권사 단위가 아니라 오해 소지가 있어 권장하지 않는다. 5.155 시세 신선도 표시와도 혼동된다.
