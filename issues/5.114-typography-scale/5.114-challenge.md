# 5.114 #215 텍스트 크기 체계 — 반대 검토 (cto/COO, 2026-11-14)

근거: `5.114-audit.md` · `5.114-ui.md` · `5.114-tech-review.md` · DECISIONS 11-14 대표 지시 · LEARNINGS UI 지적 · CHECKLIST C97·C99·C103·C104.
**판정: `통과` (조건 6개, 커밋 4 SVG는 후속으로 분리)**

## 1. 꼭 해야 하나 · 더 작게 할 수 있나
- 대표가 직접 지시한 핵심 과제다. 근거도 충분하다. 세 환경 본문이 모두 14px(61~67%)이고, 페이지 제목이 3종(16/24px), 모바일에서 위계가 뒤집혀 있으며(뒤로 18 > 제목 16), 9~10px 글자가 40곳 있다.
- 핵심(토큰 전환 1b + 반응형 쌍 정리 2)은 더 줄일 수 없다. 1b만 넣으면 `sm:`/`lg:` 쌍과 겹쳐 PC 제목이 과하게 커지므로 둘은 같은 릴리스에 들어가야 한다.
- 뺄 것: **커밋 4(SVG `fontSize`)** 는 토큰과 무관하고 차트 폭 계산과 묶여 있으니 후속 릴리스로 뺀다. 그 밖에는 tech-review §9의 컷 순서(설명 문장 12→14 → 다이얼로그 제목 통일)를 일정이 밀릴 때만 쓴다. 9·10→11 최소 크기와 `#sync=` 모달의 어절 중간 줄바꿈(STATE C25)은 남긴다.

## 2. 스케일 숫자 판정 (①)
- 모바일 본문 14 / 태블릿 15 / PC 16, 경계 768·1280, 최소 11px: **맞다.** "모바일 줄밀림 0"은 값을 유지해 지키고, "PC 쾌적"은 16px로 채운다. 1024는 2열이 막 시작돼 칸이 가장 좁아 PC 값에서 깨지는데, 이는 실측으로 확인됐다. 경계를 두 개로 줄인 것은 C99(같은 숫자 쌍)와도 맞는다.
- **조건 A (작아지는 값 한정):** 지금보다 작아지는 값은 태블릿 페이지 Hero(30→27)·1차 네비(24→22)·조밀 표(14→13)·TopBar 뒤로 라벨 4가지로 한정한다. 그 밖의 역할은 모든 폭에서 감소 0을 qa 체크 항목에 추가한다. 대표가 이미 태블릿 표시를 지적했으므로(#202 "절반 폭") 태블릿에서 숫자가 작아 보이는 곳이 늘면 안 된다.
- LEARNINGS 충돌 없음: 반려 방향(4.44 비중 % 제거, 4.66 텍스트 "홈")의 재도입이 없고, 문구 변경도 0이다. 상단 컨트롤(뒤로·1차 네비·세그먼트) 변경은 L31 기준에 따라 엄지 동선을 그대로 두고 크기만 바꾼다.
- 모바일 위험은 치환 줄에 몰려 있다(섹션 제목 14→16, 페이지 제목 16→18, 설명 12→14). 이 줄들은 프로토타입에 넣어 보지 않았다. 특히 섹션 제목 + 칩 + 정보 아이콘 줄(`자산 구성 변화 [총자산 기준] ⓘ`)과 배당 제목 + 세그먼트 줄은 360에서 1줄인지 확인해야 한다.

## 3. 방식 위험 (②)
- CSS 변수 덮어쓰기는 tech-review에서 빌드 CSS와 브라우저로 실측해 통과했다. 롤백은 squash 1커밋 revert로 끝나고, 저장·동기화 변경도 0이다.
- 인증카드: `type-fixed`가 없으면 R32가 깨지는 것이 확인됐다. 체크리스트 13(390·1280·main PNG 동일)을 **머지 게이트**로 둔다.
- 차트: SVG 글자는 영향이 없지만 HTML로 그리는 툴팁·범례·절대 위치 라벨은 함께 커진다. 1280에서 겹침·잘림을 확인한다(조건 B).
- 다이얼로그·폼 336회는 검증이 비어 있다. 고정 폭 입력(PIN·수량·`w-20` 류), 고정 높이 배지(`h-5`), 토스트, Radix Portal(팝오버·셀렉트)을 tech-review §7-1의 자동 판정 3종으로 390·1280에서 전수 확인한다(조건 B).

## 4. tech-review 수정 요청 4건 (③) — 모두 수용
1. grep 기준을 "허용 목록 10줄 외 0건"으로 바꾼다. 2. 수정 범위를 `share-menu.tsx` 셸만으로 정하고 카드 본체 3파일과 SHOT은 고치지 않는다. 3. 높이 대조는 ±1px까지 허용한다. 4. 확인 경로에 `/ratio`·`/guide/*`·`/asset`·`/invalid-access`를 넣는다. 여기에 툴팁·토스트·Portal을 4번에 덧붙인다.

## 5. 위험 등급·머지 방식 (④)
- **`risk:medium`.** 데이터 변경은 0이지만 전역 CSS가 약 60파일, 모든 화면에 걸리고 시트·폼 검증 공백이 커서 low로 보지 않는다.
- **위임 조건 ⑦에 해당한다 → 대표 승인 머지.** 홈 첫 화면을 포함해 태블릿·PC 모든 글자가 바뀌는 전 화면 시각 방향 변경이고, 대표가 "핵심 과제"로 직접 지정했다. 5.105(첫 화면 방향 변경 → 대표 데모 승인)와 같은 선례다. 승인 요청은 🟥 양식으로 하고 preview + 대표 화면 before/after 비교 이미지(390·1280 각 3장)를 붙인다. 화면 확인을 요청하는 문장은 쓰지 않는다.
