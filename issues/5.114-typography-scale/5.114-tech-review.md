## 1. 토큰 덮어쓰기 (확인 ① — 실측 통과)
- ui.md §5.1 CSS를 그대로 쓴다. `--text-2xs`와 `--text-2xs--line-height`는 **`@theme {}`(inline 아님)** 블록에 넣는다. 기존 `@theme inline`(색·radius)에 넣으면 값이 클래스에 박혀 미디어쿼리 덮어쓰기가 듣지 않는다.
- 레이어 순서는 `theme, base, components, utilities`. `@theme` 변수는 `@layer theme`의 `:root,:host`에 나오고, 덮어쓰기는 `@layer base`의 `:root`라서 소스 위치와 무관하게 이긴다. `npm run build` 산출 CSS(turbopack 압축 후)에서 `.text-sm{font-size:var(--text-sm);line-height:var(--tw-leading,var(--text-sm--line-height))}`와 48rem·80rem 블록이 유지되는 것을 확인했다.
- 브라우저 실측(`text-sm`): 767 = 14px, 768 = 15px, 1279 = 15px, 1280 = 16px.
- **줄높이 변수는 덮어쓰지 않는다.** 기본값이 단위 없는 비율(`calc(1.25 / 0.875)`)이라 크기를 따라간다. 실측 줄높이 20px / 21.43px / 22.86px. 소수 줄높이가 생기므로 높이 대조는 ±1px 반올림을 허용해야 한다.
- 주의: `.type-fixed`는 그 요소 아래에만 듣는다. Radix Portal(팝오버·다이얼로그)은 body로 빠져나가 고정되지 않는다. 인증카드 안에는 Portal이 없어 해당 없음.

## 2. 인증카드 캡처 (확인 ② — 실측 통과, 앱 화면은 preview에서 재확인)
- html-to-image는 요소마다 `getComputedStyle` 결과를 인라인으로 복제한다(`clone-node.js:164~190`). `font-size`·`line-height`는 px로 풀린 값이 복사되므로 변수 직렬화 여부와 무관하다.
- 실험(`tools/type-fixed-capture.mjs`, 680px 화면 밖 래퍼, 390·767·768·1279·1280): `.type-fixed` 안은 PNG 해시가 5개 폭 모두 같고, 밖은 768·1280에서 달라졌다(높이 219 → 234 → 249). **`type-fixed` 없이는 R32가 깨진다.** `portfolio-ring-card`·`portfolio-sector-bar`·`share-card`가 `text-xs/sm/base/xl/2xl` 토큰 클래스를 쓰기 때문이다.
- 이 실험은 정적 HTML이다. 실제 ShareCard 3종(주식·포트폴리오·유형)은 preview에서 390·1280 저장 PNG를 main 저장본과 대조해야 한다(체크리스트 13).
- 프리뷰 인스턴스의 `ASSET_THEME_SHOT`(`text-xs sm:text-sm`)은 `type-fixed` 안에서 지금과 같은 12/14px이다.
- 캡처 경로(`screenshotMode`)와 화면 경로가 한 파일에 섞인 6개(`stock-tab`·`stock-row-flow`·`stock-tools`·`detail-summary-header`·`dashboard`·`welcome-guide`)는 치환 시 **화면 분기만** 바꾼다. 예: `stock-tab.tsx:67,301`은 `screenshotMode ? shotTok.* : "text-[9px] sm:text-[10px]"`의 뒤쪽만.

## 3. tailwind-merge (확인 ③ — 설정 추가 불필요)
- 실행 결과: `cn("text-sm","text-2xs")` → `text-2xs`, `cn("text-2xs","text-muted-foreground")` → 둘 다 유지, `cn("text-[11px]","text-2xs")` → `text-2xs`. `extendTailwindMerge`는 넣지 않는다.
- `text-caption`은 색으로 오인돼 지워지는 것도 확인했다(이름 선택 근거 맞음).
- 기존 동작 그대로인 점 1개: `cn("leading-tight","text-2xs")`는 `leading-tight`를 지운다(`text-sm`도 동일). 크기 클래스를 줄높이 클래스보다 앞에 둔다.
- 위 3건을 단위 테스트 1개로 고정한다.

## 7. 미검증 영역 검증 방법 (확인 ⑦)
1. **시트·다이얼로그·폼**(52개 파일이 Dialog·Sheet 사용): preview(데모 데이터 — 체험 화면과 달리 FAB가 뜨는지 먼저 확인, 안 뜨면 저장소에 데모 자산을 주입)에서 Playwright로 ui.md §7-1의 6종 + 인증카드를 390·768·1280에서 연다. `tools/capture.mjs`에 자동 판정 3개를 추가한다 — 컨테이너 가로 넘침(`scrollWidth > clientWidth`), 잘림(`overflow` 숨김인데 `scrollHeight > clientHeight + 1`), 버튼·제목 줄 수(`Range.getClientRects`). 같은 스크립트를 운영에도 돌려 **차이만** 본다.
2. 온보딩·잠금·PWA 안내: 저장소 비운 첫 진입과 잠금 설정 상태를 각각 390·1280 1회. 프로토타입이 덮지 않은 `/ratio`(28회)·`/guide/*`(14회)·`/asset`·`/invalid-access`도 같은 판정으로 1회.
3. 실물 탭·거래 내역 3종: preview에서 항목 1건씩 입력 후 확인(체험 데이터 0건).
4. **실기기 글꼴은 팀 환경에서 직접 확인할 수 없다.** 대신 (a) 모바일은 토큰 값이 그대로라 위험이 치환 줄(9·10 → 11, 13 → 14, 제목 16 → 18, 섹션 14 → 16, 설명 12 → 14)로 한정되고, (b) 그 줄들에 `letter-spacing: .03em` 주입(글자 폭 +약 5%)으로 줄 수가 늘어나는 블록을 찾아 여유 없는 곳을 미리 보정한다. dev-notes에 "실기기 미확인"을 한계로 적고 머지 후 운영 스모크에서 재확인한다.
5. 고정 높이 안 글자(`h-5` 배지에 PC `text-xs` 14px 등)는 1의 잘림 판정으로 전 화면을 훑는다. 스켈레톤 → 완료 전환 높이(ui.md §9)는 허브·시장 비교에서 확인.
