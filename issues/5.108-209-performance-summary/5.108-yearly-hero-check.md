# 5.108 연 탭 Hero '작년 말 값 없음' 결함 의심 확인 (qa, 반쪽)

기준: origin/main 코드 대조. **실행 재현(Playwright·픽스처)은 하지 않음** — 코드 분석 결론이며 실행 근거 없음(미확인 부분은 아래 명시).

## 코드 대조
- Hero와 연도별 목록은 **같은 배열**(`allYearlyData = assetData.yearlyNetAssets` 정렬)을 읽는다. 월말·스냅샷은 Hero 값에 쓰이지 않는다(캡션·원인분해에만).
  - Hero: `latest = 마지막 항목`, `prev = 마지막에서 두 번째`. prev 없음 → '작년 말 순자산을 넣으면…' 메시지 (net-asset-chart.tsx 318~332, 376)
  - 목록: 같은 배열 전체 (517~)
- 따라서 "목록엔 2025가 있는데 Hero는 없음"이 성립하는 조건은 **배열이 2025 한 건뿐일 때**(올해 2026 자동 항목 부재). 이때 2025가 latest(=올해 취급), prev=null.
- 올해 항목은 `saveSnapshots`의 종가 업서트(asset-data-context.tsx ~815)에서만 생성. 시세 조회 후 스냅샷 저장이 스킵되면(KIS 점검 `kisUnavailable`, 삭제·차단 ref, abort) 생성되지 않음.
- 오해 소지: Hero는 "직전 해"를 연도로 판정하지 않고 배열 순서로만 판정 → 2025만 있으면 라벨이 '작년 말 없음'으로 나오지만 실제로는 '올해 값 없음'.

## 재현 판정
- 체험 데이터: demo-data.json은 yearlyNetAssets에 `@PY`(2025) 한 건만 있고 올해 항목은 없음. 올해 항목은 앱 구동 후 스냅샷 저장이 성공해야 생김. preview/체험은 쓰기·시세 경로가 제한될 수 있어 **체험에서 올해 항목이 안 생기면 Hero 메시지 + 목록 2025 동시 발생** — 개연성 높음(코드상). 실제 운영 체험 화면 재현은 미실시.
- 일반 데이터: 2025 월말·스냅샷이 있고 yearly 항목이 없는 경우는 목록에 2025가 **나오지 않으므로** 질문 시나리오와 무관. 일반 사용자는 방문 시 스냅샷 저장으로 올해 항목이 생겨 보통 2건 이상 → 재현 안 됨(코드상). 단 스냅샷 저장이 스킵되는 날(KIS 점검 등) 첫 방문 + 올해 항목 없는 사용자(예: 1월 첫 방문, 2025만 존재)는 동일 증상 가능.

## 판정
- 판정: **조건부 결함(경미) — 주로 체험 데이터 경로, 실사용자도 '올해 항목 미생성 상태'에서 일시적 발생 가능.** 데이터 손실 없음, 표시·안내 문구 문제.
- 영향: 읽기 전용 표시. 저장·동기화 영향 없음. 스냅샷 저장 성공 시 자동 해소.
- 수정 방향(developer): Hero prev 판정을 `year === currentYear-1` 기준으로 분리하거나, latest.year<currentYear면 "올해 값 계산 중" 계열 문구로 구분. 체험 데이터는 올해 항목을 시드에 포함하는 방법도 가능.
- 후속 필요: 운영 체험(www.secretasset.xyz)에서 localStorage의 yearlyNetAssets 길이와 스냅샷 저장 여부를 Playwright로 확인해 확정 → 위 판정은 코드 추론 단계.
