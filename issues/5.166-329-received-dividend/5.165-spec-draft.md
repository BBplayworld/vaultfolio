# 5.165 받은 배당 기록(최소형) — spec 초안 (planner-designer, 2026-11-27)

상태: 초안(커밋 전, 이슈 미생성). 근거: `_discovery/2026-11-26-core-value-2/`(planner D·business ⑤·ceo ⑤⑥), `5.164-327-schema-passthrough/`(tech-review 3·6장, challenge ④), LEARNINGS 11-09(내보내기)·11-10(배당 장부)·11-16(같은 표 반복), CHECKLIST C150·C151, 코드 main 9c13292(v5.160).

## 1. 문제
배당 화면의 `지급`·`예상`은 둘 다 계산값이다(`dividend-calc.ts:63` 지급 = 지급일이 지난 추정, 세전). 실제 통장에 들어온 금액을 남길 곳이 없어 배당주 사용자는 시트에 따로 적는다. 현금 입금으로 적어도 일반 입금과 구분되지 않는다(`transaction.ts:27` type은 deposit·withdrawal뿐).

## 2. 목표 행동
- 배당이 들어온 날 현금 입금을 적으면서 `배당`을 켠다(추가 입력 0~1칸).
- 성과 › 배당에서 올해 받은 기록 합계와 달별 기록을 계산값과 나란히 확인한다.
- 지표: 배당 입금 기록 기기 2주 연속 2대 이상(business ⑤), 데이터 사고 0. GA는 category 1개만(금액·종목 미전송).

## 3. 범위
- 포함: ① 현금 입금 폼의 `배당` 체크 + 선택 종목 ② 현금 거래내역 행 `배당` 배지 ③ 배당 화면 결론 줄 1조각(연 합계)·월 선택 시 1조각(그 달 기록).
- 줄일 수 있는 것(qa FAIL 2회 시 이 순서로 뺀다): 월 선택 조각 → 종목 선택 칸 → 거래내역 배지.
- 하지 않을 것: 새 메뉴·장부 화면·배당 기록 목록, 내보내기·가져오기, 알림, 세후 토글, 차트 막대·표 열 추가, 허브 카드·종목 한 장·홈 반영, 공유 링크 열 추가, 이미 적은 입금을 배당으로 바꾸기(현금 거래는 수정 기능이 없다 — 삭제 후 다시 적기), **결산 원인 행 분리(6장)**.

## 4. 사용자 흐름
1. 현금 › 입출금 기록(`cash-tx-input.tsx`) → `입금` 선택.
2. 기존 `매월 정기 입금` 체크 아래 `배당으로 받은 돈` 체크 1개. 둘은 함께 켤 수 없다(배당을 켜면 정기 체크 해제·숨김, recurring 저장값 false).
3. 배당을 켜면 `종목(선택)` 1칸이 열린다. 보유 주식을 티커 단위로 고르며(`groupStocksByTicker` 재사용) 기본값은 `선택 안 함`. 금액·날짜·메모·`잔액에 반영`은 기존 그대로(기록만 입금도 배당으로 적을 수 있다 — 올해 지난 분 소급용).
4. 저장 → 토스트 `배당 입금을 기록했어요`. 거래내역 행에 `배당` 배지(정기 배지 자리, 종목을 골랐으면 종목명).
5. 성과 › 배당 결론 줄: `지급 N · 받은 기록 N · 예상 N`. 달을 고르면 지금 비는 결론 줄 자리에 `M월 받은 기록 N` 1조각(높이 불변).
6. 기록이 0건이고 현금 계좌가 1개 이상이면 같은 자리에 `받은 배당 적기` 1조각(누르면 1번 폼이 입금·배당 켠 상태로 열림). 기록이 생기면 그 자리가 합계로 바뀐다(한 자리 한 조각).
- 더하면 뺀다(11-16): `받은 기록` 조각이 보이는 동안 결론 줄의 `다음 지급 M월 K종목`을 뺀다(조각 최대 3, 320 한 줄 유지 여부는 ui.md에서 C152 기준 확정).

## 6. 표시 규칙·원인 체계
- **섞지 않는다.** `지급`·`예상`은 세전 계산값(지급일 기준), `받은 기록`은 사용자가 적은 실제 입금액(입금일 기준, 세금 뗀 금액일 수 있음). Hero·차트·표·투입 대비 배당·허브 카드·성적표는 지금 계산 그대로(변경 0). 기록을 계산값에 더하거나 빼거나 대체하지 않는다(이중 계산 0). InfoHint에 차이 설명 1문장을 넣고 1문장을 줄인다.
- 합계 규칙(C150): 달별 기록을 원 단위로 반올림한 뒤 더한 값이 연 합계(`roundedAnnual` 방식). 같은 포맷터·같은 보기 모드. 외화 입금은 지금 환율(`krwMul`)로 환산하고 엔화 입금도 포함한다(계산값은 엔화 제외 — 서로 비교하지 않으므로 충돌 없음). 기간은 입금일의 연·월, 반영·기록만 모두 합산.
- **순유입·원인(#293)**: v1은 엔진 변경 0. 배당 표시는 분류만 더하고 금액·type·reflected를 바꾸지 않으므로 `income`(넣은 돈·순유입), #293 기록만 이동 한도, 출금↔매수 짝(`matchedTransfer`)의 입력이 같다 → **충돌 없음**. 연 탭 도움말(`year-settlement.ts:196` '받은 배당은 … 넣은 돈 또는 기록 안 된 변화에 포함돼요')이 현행을 그대로 설명하므로 문구도 유지.
- 확인 요청: CEO 판정문은 5.165 축소 조건에 '결산 배당 행'을 두면서 ⑥에서 '월 결산 배당 줄'은 보류로 적어 서로 다르다. 기획 의견은 **제외**(오케스트레이터 최소형과 일치). 분리하려면 기록만 배당 중 #293이 income으로 옮긴 몫의 배분 규칙, 꺼낸 돈이 큰 달의 +/− 나란히 표시, 홈·월·연 원인 일치(5.152) 재검증이 필요해 별도 릴리스 감이다. 재개 조건: 기록 지표 충족 후 '배당을 불어난 돈으로 옮기기' 단독 과제.

## 8. 엣지 케이스
- 첫 사용자·기록 0: 4-6. 현금 계좌 0개면 조각 없음(알려진 한계 — 현금 미등록 사용자는 기록 불가).
- 배당 종목 0·계산 합계 0인데 기록만 있음(다 판 사용자): Hero 없이도 `받은 기록` 조각은 보인다.
- 일부 갱신·시세 실패: 기록 합계는 저장값이라 표시, 외화 환산만 마지막 환율.
- 고른 종목을 팔거나 지움: 배지는 남긴 종목명 그대로. 거래 삭제(되돌리기 포함)·3년 정리: 합계에서 빠지고 표시도 사라진다.
- 구버전 기기: 일반 입금으로 보이고 금액·잔액 동일. 작년 기록: 올해 합계에서 빠진다(연도 전환 없음).

## 9. 완료 기준
1. 입금에서만 `배당으로 받은 돈` 체크가 보이고, 켜면 정기 입금 체크가 사라지며 저장 레코드의 recurring은 false다.
2. 배당 입금 2건(반영 1·기록만 1, 다른 달) 저장 → 결론 줄 `받은 기록` = 두 금액 합, 각 달 선택 조각 = 그 달 금액, 12개 달 표시 문자열 합 = 연 합계 문자열(C150).
3. 기록 전후로 Hero·`지급`·`예상`·차트·표·투입 대비 배당·허브 카드 값이 같다(스냅샷).
4. 같은 금액의 입금을 배당으로 적은 경우와 일반 입금으로 적은 경우, 홈·월·연 원인 전 행이 같다(vitest, #293 기록만 픽스처 포함).
5. 거래 삭제 → 합계·배지에서 빠지고 잔액 되돌림은 기존과 같다. 고아 표시가 합계에 잡히지 않는다.
6. 데이터 안전(C151): 이전 → 새 복원, 새 → 5.163 동결 사본 → 새 왕복에서 금액·잔액·건수 불변. A안이면 구 기기 push 뒤 신 기기에서 배당 표시 복구, B안이면 5.164 기기 왕복 보존. 모든 데이터 삭제·`?demo=empty`에서 표시도 지워진다.
7. 새 메뉴·새 라우트 0, 서버 평문 body 키·공유 토큰 불변, GA에 금액·종목 0.
8. 390·320, 라이트·다크에서 결론 줄 조각이 조각 안에서 꺾이지 않는다(C152). 금지어(투자 조언) 0.

## 10. 위험
- high(새 저장 키 또는 스키마·동기화). CEO 승인 머지 + 대표 사후 알림, 5.164 운영 확인 +7일, 반영 뒤 5.164 revert 금지.
- 11-10 반려 대조: 입구는 기존 입금 폼, 출력은 기존 화면 조각 2개 → 장부 형태 아님. 다만 배당 화면 진입이 작다는 반려 근거는 그대로라 지표 미달 시 확장하지 않는다.
- 오독: `지급`(계산)과 `받은 기록`(입금) 금액 차이를 오류로 볼 수 있다 → 라벨·InfoHint로 구분, 차액·달성률은 만들지 않는다.
- 배당 화면 재수정(11-16): 결론 줄·InfoHint만 건드리고 차트·표는 손대지 않는다.
- 미확인(tech-review): 이름표 방식의 재-push 복구가 id 맵에도 성립하는지, 배당 화면에서 입금 폼을 여는 기존 트리거 유무, 백업 파일에 분리 키 포함 여부.
