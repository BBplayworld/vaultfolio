## 1. 결론 — 2단 경계는 `sm`(640px) 미만 전체

**`max-[360px]:` → `max-sm:`(폭 < 640). 640 이상은 현행 5열 그대로.**

근거: 360~639의 5열은 열 폭이 뷰포트와 무관하게 고정(`52 / 56 / 56 / 56px`, 간격 4)이라 폭이 넓어져도 겹침이 줄지 않는다. 남는 폭은 전부 이름 열로만 간다. 따라서 390·430 같은 중간 경계는 근거가 없고, 겹침이 사라지는 첫 폭은 열 템플릿이 바뀌는 640이다. 중간 경계를 만들려면 5열 폭을 다시 나눠야 하는데 이는 C155가 막은 재배분이다.

**판단**
- **사용자에게 보이는 결함은 아니다.** CSS 폭 359.x인 실기기는 사실상 없다(주요 폭 320·344·360·375·384·390·393·402·412·414·430). 영향 대역은 1px이고, 그 안에서도 360 배치가 1px 좁게 보일 뿐이다. 이것만으로 릴리스를 열 가치는 없다.
- **그래도 일괄 `max-[360px]:` 치환을 권한다(배당 경계 변경과 같은 릴리스, 별도 커밋).** 이유: ① 짝 빈틈 2건·혼합 5건이 사라진다 ② qa가 '320 대역 끝'으로 재는 359 캡처(C99·C115)가 지금은 이 17개 파일에서 360 배치를 찍고 있어, 치환해야 359 검수가 뜻한 배치를 본다 ③ 사양·KB가 `359px 이하`라고 적는 뜻과 코드가 일치한다 ④ 같은 파일 안 표기 혼재(#5·6·7)가 끝난다.
- **일괄 치환의 영향**: 계산 스타일이 바뀌는 폭은 359.00~359.99뿐(360 배치 → 320 배치). 320 배치는 320에서 이미 검수됐고 359는 그보다 39px 넓어 넘침 위험이 낮다. 358 이하·360 이상은 컴파일 결과가 조건식 1곳만 달라 화면 변화 0.
- 함께 바뀌는 것: 테스트 3곳(`stock-entry-tools.test.tsx:196`, `market-compare-view.test.tsx:152`, `invest-r3-ui.test.tsx:23`)과 스냅샷 1개(`decision-unset-baseline.test.tsx.snap`), KB 4줄(design-system 223·379행, components 138행, qa-full-test-plan 48·90행 — 379행은 이미 코드와 어긋나 있음).
- 재발 방지: `src`에 `max-[359px]:`가 0개임을 고정하는 테스트 1개(기존 `type-scale-guard`류 정적 검사에 추가).
- 범위 밖(기록만): 같은 종류의 1px 어긋남 후보 `max-[389px]`(invest-view, 다른 곳은 390), `max-[399px]`·`max-[374px]`(market-compare-view), `max-[358px]`(pwa-install-button). 의도 확인이 필요해 이번 치환에 넣지 않는다.
