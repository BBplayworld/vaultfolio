# 4.71 dev-notes — GA 화면별 참여 시간 귀속 수정 (#131)

## 원인 (코드·GA4 동작 근거, 실측 불가 — 아래 한계 참조)
- `layout.tsx` config `send_page_view:false` → 자동 page_view 없음. `ga.ts trackScreen`이 화면 전환 때 **새 화면 title**로 page_view를 보낸다.
- gtag는 직전 전송 이후 누적된 참여 시간(`_et`)을 "다음에 나가는 이벤트"에 싣는다. 전환 시 가장 먼저 나가는 것이 새 화면 page_view라 직전 화면 머문 시간이 새 title에 귀속. 마지막 화면은 이탈 시 자동 user_engagement가 문서 제목(기본 제목 행)으로 나간다. direction 6절 관찰(홈 2초·상세 허브 62초)과 일치.

## 수정
- `src/lib/analytics/ga.ts trackScreen`: 직전 화면이 있으면 page_view 직전에 `gtag('event','user_engagement',{page_title:<직전 title>,page_location:<직전 /v/경로>,page_path})` 1회. page_view 호출·같은 화면 중복 무시·체험 가드·해시/쿼리 제외 불변. `pageLocation(screenKey?)` 인자 추가.
- 서버 전송 값 종류 증가 없음(기존 title·가상 경로 사전만), 저장 스키마 0.
- 테스트: `src/lib/__tests__/ga.test.ts` 5건 추가(호출 순서·파라미터·중복·debug·체험), 기존 1건은 page_view만 필터하도록 조정. vitest 1508 통과, tsc·lint(에러 0)·build 통과.

## 한계 (정직 보고)
- **collect 요청 실측 못함**: 샌드박스 프록시가 googletagmanager.com을 403 차단하고, GA 스크립트는 `VERCEL_ENV==="production"`에서만 렌더(preview·로컬 없음)라 preview에서 dt·_et 확인 불가. 단위 테스트는 gtag 호출 순서·인자까지만 검증.
- 후속 확인(운영): 머지 후 GA DebugView(`?ga-debug=1`)에서 화면 전환 시 user_engagement의 page_title=직전 화면·`_et` 값 확인 권장. 판독 경계일=머지일, 이전 창 참여 시간과 비교 금지.
- 남는 한계: 화면 안 track() 이벤트(feature title)가 먼저 나가면 그 시간은 해당 이벤트 title에 붙는다(기존 동작, 이번 범위 밖). 전환마다 user_engagement 이벤트 수가 늘어난다(page_view·활성 사용자 불변).
