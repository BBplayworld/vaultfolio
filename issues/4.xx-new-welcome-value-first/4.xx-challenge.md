## 묶음·범위 (v1)
1. **첫 화면 순서**: 히어로(제목 + 쉬운 말 한 줄) → 신뢰 한 줄(예: "로그인 없음 · 자산은 내 기기에만 · 기기 간 암호화 동기화") → 예시 미리보기(기존 컴포넌트·데이터 그대로) → 주 CTA → 설치 안내 → 보안 상세
2. **보안 카드 3장 → 신뢰 한 줄 + "자세히" 펼침**: 기존 3장 내용은 펼침 안으로(삭제 아님, 강점 2 유지). 첫 화면 텍스트 총량 감소
3. **모바일 웹 CTA**: 설치 버튼(주)은 유지, "웹에서 바로 시작"을 설치 버튼 바로 옆/아래 보조 버튼으로 올림(기존 `skip_install` → 자산 등록 노출 흐름 재사용). 맨 아래 보조 링크 제거
4. **완료 기준 핵심**: 375×812 첫 화면 안에 제목·신뢰 한 줄·예시 순자산 숫자·시작 CTA(모바일 웹은 설치+바로 시작 둘 다)가 보인다. 데스크톱 1280도 같은 순서
5. **동승(G2 최소)**: 링크 공유 미리보기용 OG 이미지 1장(정적, 브랜드·"안전한 자산 관리, 시크릿에셋"만, **금액 없음**) + twitter `summary_large_image`. `src/app/layout.tsx` metadata만

## 기준선 측정 (GA 실제 전환율 미확인 한계 처리)
- GA4는 과거 이벤트를 보존하므로 기준선은 **배포 전 캡처가 아니라 날짜 구간 비교**로 확보한다: 기준선 = 머지일 직전 28일, 비교 = 머지일 +1일부터 28일. 4.28(GA 도입) 이후 이벤트는 이미 쌓여 있다
- 필수 조건 3가지 ① 머지 일시를 DECISIONS에 기록(구간 경계) ② business-pm이 business.md에 GA 탐색 보고서 레시피(유입경로 탐색: welcome_view → onboarding_action → first_asset_saved, 기기 기준, 기간·필터) 명시 ③ GA 데이터 보존 기간이 2개월 설정이면 머지 후 8주 안에 읽어야 함 — 보존 기간 확인을 "확인 필요"에 기록
- 한계: 에이전트 환경에 GA 조회 권한이 없다. 지표 판독은 조회 수단(GA Data API 비밀값 등)이 생기면 팀이 수행하고, 대표에게 판독·QA를 요청하지 않는다. 판독 전까지 #33·체험 모드 재개 판정은 "지표 미확인"으로 유지하되, 8주 경과 시 cto가 정성 근거(qa preview 첫 화면 실측)로 판정한다
- 개발 중 회귀 방지: `welcome_view`·`onboarding_action`·`skip_install` 호출 위치가 재배열 후에도 같은 조건에서 1회씩 발생함을 vitest/qa로 확인(지표 시계열 연속성)
