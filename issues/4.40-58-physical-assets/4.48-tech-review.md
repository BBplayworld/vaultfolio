## 2. 저장 스키마·마이그레이션·구버전 혼재
### 2-1. 분리 키 이름 확정: `secretasset.physical_assets` (점 구분)
- 구버전 `clearAssetData`(`asset-storage.ts:431-439`)는 `startsWith("secretasset_")`만 지운다. 점 구분 이름은 걸리지 않는다.
- 키 순회 지점 전수 확인(grep `Object.keys(localStorage)`·`localStorage.key(`): `asset-storage.ts:431·456`, `storage-stats.ts:25`, `profit-cache-cleanup.ts:34`(prefix `secretasset_profit:`), `local-storage.ts:117·171`(`profit:`·공지 레거시 prefix), `one-time-migrations.ts:86`(`secretasset_profit:`), `use-gemini-usage.ts:58`(`secretasset-gemini-`). **전부 이 이름을 건드리지 않는다.**
- `storage-stats.ts:26`은 `startsWith("secretasset")`라 용량 집계에 자동 포함된다.
- 스키마: `assetDataSchema.physicalAssets: z.array(physicalAssetSchema).optional()`(default 없음, 키 없음≠빈 배열). `physicalAssetSchema`는 `.passthrough()`, `type`은 `.catch("other")`.
- **읽기는 관대, 쓰기 검증은 폼에서만**: 저장소→메모리 읽기에는 min 제약 없는 loose 스키마를 쓴다(제약 위반 항목이 읽기에서 탈락해 다음 저장 때 영구 소실되는 경로 차단, C6).

### 2-2. 신버전 동작
- `getAssetData`: 기존 반환 직전(`:111`)에 분리 키를 읽어 `physicalAssets`로 합친다. 키가 없으면 `undefined`(필드 없음).
- `saveAssetData`·`saveAssetDataRaw`(`:121-123·399`): `physicalAssets`를 **떼어** 분리 키에 쓰고 `secretasset_asset_data`에는 넣지 않는다(spec 완료 기준 2). 쓰기 순서는 분리 키 → 본 키(분리 키 쓰기 실패 시 본 키를 건드리지 않음). 값이 `undefined`면 분리 키는 손대지 않는다.
- `buildExportPayload`(`:150`)는 `getAssetData`를 쓰므로 동기화·백업 payload에 자동 포함된다(키가 없으면 필드 생략).
- `clearAssetData`는 **수정하지 않는다**(분리 키가 접두 밖이므로 지우지 않음). 대신 `clearPhysicalAssets()`를 신설해 명시 삭제 지점에서만 호출한다(5절 경로 표).
- 마이그레이션: 기존 데이터에 키가 없어 변환 없음. 롤백 시 키가 그대로 남는다.

### 2-3. 구버전(4.46 이하)이 이 키를 다루는 방식
| 구버전 동작 | 결과 |
|---|---|
| `getAssetData`·`saveAssetData` (zod strip) | 분리 키를 읽지도 쓰지도 않음. 키 보존 |
| 동기화 pull·백업 가져오기 (`clearAssetData`) | 접두 밖이라 보존 |
| 구버전 push | payload에 `physicalAssets` 없음 → 신버전 pull은 "키 없음 = 로컬 유지"(5절) |
| 구버전이 신버전 payload pull (`assetDataSchema.parse`) | 모르는 키를 오류 없이 버림 |
| 구버전 "모든 데이터 삭제" | **키가 남는다**(알려진 한계). 이후 신버전으로 열면 실물이 다시 보임 — 삭제 의도와 어긋나므로 브리프 위험 절·qa-report에 명시(C14·C17) |
| 구버전이 같은 달 월 스냅샷을 다시 씀 | `physical` 필드 없는 스냅샷이 push됨 → 신버전 `mergeMonthlySnapshots`가 로컬 `breakdown.physical > 0`을 유지(spec 3-5) |
| 구버전 일별 스냅샷 | 통째 교체(`:358`)라 보호 불가 → 일·주 그래프가 실물만큼 내려가는 날이 생김(v1 제외, 알려진 한계). 월 스냅샷은 보호 |
- 롤백 위험 시작일: 4.48 머지일부터 구버전 기기가 쓰는 동안(SW 갱신 지연 포함). 기록 손실은 없고 표시만 일시 불일치한다. 단 구버전에서 한 입력은 실물에 반영되지 않는다.

## 3. 서버 전송·공유 payload
- 동기화: `sync-client.ts:51`에서 `encryptPayload(buildExportPayload(), encKey)`로 **클라이언트 AES-GCM 암호화 후** 전송. `/api/sync` PUT은 `iv`·`ciphertext`·`baseVersion`·`pubKey`만 받는다(`route.ts:76-86`, 4MB 상한). 평문 필드 추가 0, 암호문 길이만 건당 수백 바이트 늘어난다(기존에도 건수에 비례). 서버는 값을 복호화할 수 없다.
- 공유 토큰·복원 코드(packV7, `asset-storage.ts:625-668`): **실물 미포함**, 포맷 변경 없음(C7 불필요). 코드 생성 시 실물 1건 이상이면 안내 1줄.
- GA: `trackAssetSave{asset_type:"physical"}`·`countAssets`는 건수·유형만, 금액·이름 금지(기존 규칙).
- AI 프롬프트(`ai-prompts.ts`): 사용자가 복사하는 문자열 생성. 개발 시 서버 라우트 전송 경로가 없음을 grep으로 재확인하고 qa-report에 남긴다.
- 서버 전송 값이 늘어나지 않으므로 사용자 보유 정보 역산 불가 원칙(CLAUDE.md 4장)은 유지된다.
