- 원인: 지난달 결산은 거래↔짝 기록 id 짝 상쇄로 닫혀 있었다. 거래를 지우면 짝 기록이 고아가 되어 외부 출금으로 읽히고, 코인 원가 증가는 돈의 출처가 없어 기록 안 된 변화가 된다. A6(대출)은 엔진이 대출 다리와 원가 증가를 묶어 줘서 문제가 없다.
- 기각한 대안: 엔진에서 고아 짝 기록을 매수와 다시 짝짓기(결산 계산식 변경이라 자체 승인 조건 위반) / 자산 삭제 때 짝 기록도 지우기(잔액 불변·4.58 F24·#103 '되돌림은 거래 삭제 다이얼로그만' 설계와 충돌) / 연결 거래를 모두 보존(A3·A5 이번 달 잔차 −X가 돌아와 challenge (4) 조건에 걸림).
- **채택: 지난달 이전 연결 거래 보존(예외 ②).** 결과: A4·A6의 10월·11월·연 = main과 같음(각 0줄 / 기록 안 된 −X 1줄 / 기록 안 된 −X 1줄). A3·A5 개선은 유지된다. 대가로 A4·A6 연 탭이 '출금/대출 −X'에서 main과 같은 '기록 안 된 −X'로 돌아간다(악화 아님). 남은 거래는 자산이 없어도 조회가 `?.`로 처리한다(A7·A8과 같은 상태).
- 11월 `기록 안 된 변화 −X`(보유 중인 자산 삭제 자체)는 main 현행과 같은 1줄이라 수용한다.

risk:medium 유지(스키마·동기화·서버 변경 0, 수정 후 거래 삭제 범위는 더 줄어든다). 자체 승인 가능성은 **아래 지시 반영 + qa 재PASS 조건으로 유지**한다. A4 두 줄이 남은 채로는 challenge (4) 전환 조건(C24)에 해당해 '대표 확인 필요'다.
