# #61 보안 안내 문구 정정 — spec (design-final 2026-10-31 반영)

기준(대표 확정): ①자산은 동기화를 켜지 않는 한 기기에만 저장 ②동기화는 이중 암호화로 관리자도 알 수 없음 ③서버 역할 나열·단정 금지. cto 축소 반영(대상 10건 → **7건**, risk:low). 문구는 팀 확정이며 최종 확인은 반영 결정으로 갈음한다. **"대표 확인 필요"는 "이중 암호화" 표현 항목만**(아래 3절 근거 참조).

## 1. 문제
실제 동작과 다르거나 단정적인 안내가 있다. 예) "데이터가 기기를 절대 벗어나지 않습니다"는 동기화·스크린샷 인식 사용 시 사실과 다르고, 업로드 박스의 "개인정보 측면에서 문제없습니다"는 법적 단정이며 이미지가 분석 요청으로 전송된다는 사실(`/api/parse-screenshot`)을 알리지 않는다.

## 2. 목표 행동
사용자가 스크린샷 업로드 전 안내를 읽고 오해 없이 진행/중단한다. (측정: 정성 — 기존 `screenshot_parse` 지표는 0건이라 판독 불가.)

## 4. PRINCIPLES 2장 — 4.38에서 분리 (본 이슈 산출물 아님)
- #61은 PRINCIPLES를 고치지 않아도 진행 가능(`needs-human` 아님). 에이전트는 수정하지 않는다(대표 소관).
- 별도 대표 안건 1줄(STATE): 2장 "서버 역할은 두 가지뿐"은 스크린샷 분석·부동산 실거래 조회와 이미 맞지 않는다. 문안은 "동기화한 자산은 이중 암호화돼 관리자도 내용을 알 수 없다"로 범위를 한정하고, **사용자가 명시적으로 실행한 스크린샷 인식(이미지 원본 전송)은 예외**로 명시한다.
