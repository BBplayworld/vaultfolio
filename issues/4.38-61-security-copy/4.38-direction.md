# #61 보안 안내 문구 정정 — direction (경험 절)

상태: planning ① / 사업 절·합의 절: 아래 작성됨(business-pm, 2026-10-31)
대표 확정 기준(DECISIONS 2026-10-31 ②): 자산 데이터는 **동기화를 켜지 않는 한 기기에만 저장** / 동기화는 **이중 암호화로 관리자도 알 수 없음** / **서버 역할 나열·단정 금지**.

## 경험
### 1. 사용자가 하게 될 행동
- 웰컴·앱가이드·동기화·스크린샷 업로드 화면의 안내가 실제 동작과 같아서, 사용자가 스크린샷 업로드 전 "이미지가 어디로 가는지" 오해 없이 판단한다.

### 2. 범위
- 포함: 정정 대상 문구 7건(spec 표), 중복 원문의 단일 상수화(welcome-guide·app-guide 동일 원문 3카드).
- **줄일 수 있는 것**: 기술 용어(localStorage·IndexedDB·PBKDF2·Ed25519·pubKey·blob) 노출 — 카드는 짧은 문장 2~3줄로 / 카드 3개 → 유지하되 내용만 교체.
- **하지 않을 것**: PRINCIPLES 2장 수정(별도 대표 안건으로 분리), 메타 title·홈 백업 팁·금고 암호 안내(현행 유지, 사실과 일치), 거래 스크린샷 2종·마법사 단계에 고지 박스 신설(구조 변경 — 후보로만 기록), 신규 보안 기능·화면, 법적 판단 문구("문제없습니다" 류 단정), 서버 역할 나열, 마케팅 문구 변경(별도), 앱 동작 변경.

### 3. 기존 화면 변화
- 문구만 변경: 웰컴(trust 한 줄 + 보안 카드 3), 앱가이드, 기기 동기화 설명, 스크린샷 업로드 박스 4종. 레이아웃·구조 무변경.

### 4. 사업 절에 대한 의견 (쟁점 3건 모두 수용)
1. 카드2 금고 암호 문장: 코드 확인 결과 "이 기기 기억하기"가 보관하는 것은 암호 원문이 아니라 파생값을 기기 비추출 키로 감싼 값이다. 암호 원문은 저장·전송되지 않으므로 해당 문장은 사실이며 **현행 유지**(동기화 메뉴·연결 창의 같은 문장도 무변경). 단정 우려는 사실 근거로 해소.
2. PRINCIPLES 2장: 이 이슈에서 **분리**(별도 대표 안건). 안건 문안은 "동기화한 자산은 이중 암호화돼 관리자도 내용을 알 수 없다"로 범위 한정, 스크린샷 인식(이미지 원본 전송)·실거래 조회 등 서버 경유 기능은 예외 항목으로 명시.
3. 메타 title "오프라인": 제외(SEO·#48 판독 영향, G2와 묶어 후속).

### 5. 대표 확인 필요
- "이중 암호화" 표현만. 대표 확정 표현(DECISIONS ②)이므로 그대로 쓰되, 코드상 자산 암호화는 AES-256-GCM 1겹(종단 간) + 전송 구간 HTTPS임을 spec에 기록. 다른 문구는 팀 확정, 최종 확인은 반영 결정으로 갈음.
- 일정: 11/8(1일, 첫 번째 커밋). 컷 규칙은 #59 direction 5절 참조.

## 사업 (business-pm, 2026-10-31)
1. **왜 지금**: 리텐션·첫 발견 직접 기여는 **없음**. 근거는 사실 정합: 안내가 실제와 달라(예: 동기화·스크린샷 전송 시 "기기를 절대 벗어나지 않습니다") 대표의 보안 우선 메시지 기준과 마케팅 글(W45 정정분)이 앱 안 문구와 어긋난다. 보안 민감층이 업로드를 망설이는지는 `screenshot_parse` 0건이 간접 신호일 뿐 원인은 구분되지 않는다. 대표 확정(10/31) 사항이고 저비용 문구 변경이라 보류 대신 "신뢰성 정정으로 동승" 권고(기여 가설 없음)
2. **누구를 위해**: 스크린샷을 올리기 전 "이미지가 어디로 가는지"를 읽는 보안 민감한 3040 투자자
3. **성공의 모습**: 성장 지표 없음. 확인은 정합성: 구 문구 grep 0건·카드 상수 단일화·신 문구에 서버 역할 나열/단정 없음(spec 7절). 부수 관찰(판독 불가 가능성 명시): `screenshot_parse` 기기 수 — 사실 고지가 시도를 줄일 수도 있으나 사실이므로 가드레일이 아니라 참고값
4. **하지 않으면 잃는 것**: 중간(성장이 아닌 신뢰). 사실과 다른 안내는 반복 노출되는 정체성 문구라 마케팅을 늘릴수록 어긋남이 드러난다

## 합의 (business-pm 잠정 — 쟁점 있음)
- 최종 방향: 문구만 교체, 구조 무변경, 카드 단일 상수. 정정 자체를 홍보하지 않는다(정정 공지는 오히려 문제 인정으로 읽힘). 마케팅은 대표 기준 ①②만 사용
- 남은 쟁점(이견):
  1. **spec 3행 카드2 "금고 암호는 저장·전송되지 않아요"는 8행이 지적한 단정과 같은 문제**("이 기기 기억하기" ON이면 기기에 암호화 보관). 카드2에서 해당 문장 삭제 또는 "전송되지 않아요"만 남기기 제안
  2. **PRINCIPLES 2장 제안문 "서버는 자산 내용을 알 수 없다"는 단정**이고 스크린샷 분석·실거래 조회가 서버 경유라는 사실과 어긋난다. "동기화한 자산은 이중 암호화돼 관리자도 내용을 알 수 없다"로 범위를 한정하고, 서버 경유 기능 항목(스크린샷·실거래 조회) 누락도 대표 결정 사항으로 남김(원칙 변경은 대표만)
  3. 메타 title("오프라인" 제거): SEO 노출 변경이라 대표 확인 필수에 동의. 이견 시 제외해도 사업상 손실 없음
- 쟁점 해소 후 `business-pm 합의함` 표기
- planner-designer 합의함 (사업 절 쟁점 3건 수용·해소)
