## 1. 확정 사항

### 단일 상수 파일 `src/config/security-copy.ts` (tech-review 채택 + 보완)
- `SECURITY_COPY`(카드 3개 `{ id, title, desc }`), `SCREENSHOT_UPLOAD_NOTICE`(업로드 박스 4곳), 그리고 **"이중 암호화"가 들어가는 문장 전부를 이 파일의 한 블록에** 둔다. 텍스트만, React·아이콘 import 없음.
- **"이중 암호화" = 대표 확인 대기 항목**. 반영(머지)하면 현 표현으로 확정, 대표가 `수정:` 코멘트로 다른 표현을 원하면 이 블록 하나만 바꾼다. 블록 바로 위 주석: `// 대표 확인 대기: '이중 암호화' 표현 — 바꿀 때는 이 블록만 교체(4.38 #61 design-final 대안 참조)`.
  - 조사가 붙는 형태("이중 암호화돼", "이중으로 암호화된")가 섞여 단어 1개 상수 치환은 문법이 깨진다 → **문장 단위로 한 블록**에 모은다.
  - 블록 구성(5문장): 카드2 제목·본문, 카드3 본문, 앱가이드 설명(73행), 동기화 메뉴 설명(cloud-sync-menu-entry 146행). 동기화 메뉴도 이 파일에서 import한다.
  - 정적 테스트: `src/` UI 문자열 중 `이중 암호화|이중으로 암호화`가 `security-copy.ts` 밖에 0건.
- 현 표현(spec 3절)과 교체 대안(대표가 정밀 표현을 원할 때, 미리 확정해 둠):
  | 위치 | 현 표현 | 대안 |
  |---|---|---|
  | 카드2 제목 | 이중 암호화 동기화 | 암호화 동기화 |
  | 카드2 본문 | 동기화를 켜면 자산이 기기에서 이중으로 암호화된 뒤 전송돼요. 금고 암호는 저장·전송되지 않아요. | 동기화를 켜면 자산을 기기에서 암호화한 뒤 전송 구간도 암호화해 보내요. 금고 암호는 저장·전송되지 않아요. |
  | 카드3 본문 | 동기화한 자산은 이중 암호화돼 있어 관리자도 내용을 알 수 없어요. 금고 암호를 잊으면 복구할 수 없어요. | 동기화한 자산은 기기에서 암호화돼 관리자도 내용을 알 수 없어요. 금고 암호를 잊으면 복구할 수 없어요. |
  | 앱가이드 설명 | 자산은 내 기기에 저장되고, 동기화는 이중 암호화로 보호돼요. | 자산은 내 기기에 저장되고, 동기화는 기기에서 암호화해 보호돼요. |
  | 동기화 메뉴 | 동기화한 자산은 이중 암호화돼 관리자도 알 수 없어요. 금고 암호가 있어야 열 수 있어요. | 동기화한 자산은 기기에서 암호화돼 관리자도 알 수 없어요. 금고 암호가 있어야 열 수 있어요. |
- 근거 1줄(qa·마케팅 공통): 코드상 자산 암호화는 AES-256-GCM 1겹(기기 종단 간) + 전송 구간 HTTPS = "기기 종단 암호화 + 전송 구간 암호화". decision-brief "무엇이 바뀌나"에 대표 확인 대기 항목으로 1줄 적는다(중간 확인 요청 아님).
