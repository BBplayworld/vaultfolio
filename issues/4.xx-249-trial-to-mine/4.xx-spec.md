## 1. 문제 · 목표 행동
**문제**: 둘러보는 사람은 홈에서만 시작할 수 있고, 돌아온 화면은 방금 본 것과 이어지지 않는다. 상세·성과에는 예시 표시가 없다.
**목표 행동**: ① 상세·주식(또는 종목 한 장·부동산 등)을 보다 그 화면에서 `내 자산으로 시작`을 누른다 ② 복귀한 등록 칸에서 방금 본 자산군의 등록 방법을 고른다 ③ 첫 자산을 저장한다.

## 2. 체험 전 화면 목록과 표시 자리
현재: `page.tsx:138` `isTrialMode() && view.type === "home" && <TrialBanner />` — 홈에서만, `AssetPageTabs` 위 in-flow. 하단 탭은 홈·상세·성과 3개(`bottom-nav.tsx:86~88`), FAB 없음(`page.tsx:143`), 상단 더보기·설치 없음(`top-bar.tsx:116~118`).

**자리 규칙(기획 고정)**
1. 표시 `예시 자산` 1개 + 버튼 `내 자산으로 시작` 1개가 한 덩어리. 전 화면 같은 컴포넌트·같은 문구·같은 모양. 화면당 1개.
2. 그리는 곳은 공통 자리 1곳(화면별 컴포넌트에 흩지 않는다). 상단 바 안은 불가 — PWA 허브에서 상단 바가 숨는다.
3. 하한: 어느 화면이든 **들어선 직후 보이는 화면**(390×844·320×568)에 표시와 버튼이 다 보인다. '스크롤 0'이 아니다 — 세금 관리는 들어서는 순간 '이번 달'로 자동 스크롤돼(`tax-calendar-view.tsx:53~55`, 실측 scrollY 약 2,000) 지금 배너 자리(in-flow)로는 이 기준을 채우지 못한다.
   - **확정 = 상단 sticky 1줄**(ui.md 0절, `page.tsx` 공통 자리 1곳, 전 화면 같은 컴포넌트, 카드 48px·가림 면 56px). 수치·꼴의 정본은 ui.md 2절.

   - 비용(10절-8 tech 조건): 세금 화면 자체 sticky 2곳 오프셋, 설치 앱 top(PC 내비·모바일 safe-area), 인앱 iOS 안내 펼침 최대 높이 + `닫기`(ui.md 3·4절).

1. 쓰는 곳: 시작 버튼 누름 1곳. 현행 `trial_exit = "1"`(sessionStorage, `TRIAL_EXIT_KEY`)은 그대로 쓰고, **같은 저장소에 화면 키 1개를 더 적는다**(제안 키 `trial_exit_from`, 값 = `viewToKey(view)` 결과 문자열).
   - 키를 나눈 이유: 옛 번들이 읽어도 `"1"`은 그대로라 현행 복귀로 동작한다(CEO 수용). 키 상수는 `trial-mode.ts`의 `TRIAL_EXIT_KEY` 옆에 둔다(`STORAGE_KEYS` 밖). 탭 한정·1회용 표식이라 '저장 키 변경 0'에 걸리지 않는다(CEO 판정 ③) — C95 비해당임을 dev-notes에 한 줄.
   - 인앱 경로(외부 브라우저 이동)에서는 둘째 값을 쓰지 않는다.
2. 넣는 값: 화면 키만. 종목·금액·건수·자산 데이터 0. localStorage(체험 중에는 메모리로 교체됨) 저장 키 0, URL·쿼리·해시 0.
3. 읽는 곳: 복귀한 웰컴의 기존 복귀 처리 1곳(`welcome-guide.tsx:129~138`). `trial_exit`가 `"1"`일 때만 둘째 값을 읽고, **두 키를 함께 지운다**(1회). `trial_exit`가 없으면 둘째 값은 읽지 않고 지운다.
4. 판정은 순수 함수 1개(단위 테스트): 화면 키 → `{ 자산군 | 없음, title 꼬리 | 없음 }`. 허용 목록(3-2)에 없는 문자열·빈 값·읽기 실패는 전부 `없음` = 현행 동작.
5. 새로고침·재방문·다른 탭에는 이어지지 않는다(1회용). 등록 칸 상태가 유지되는 범위는 **복귀한 웰컴이 화면에 떠 있는 동안**뿐이다.
   - 직접 입력 팝오버·입력 창을 열었다 닫는 것은 웰컴이 그대로라 상태가 남는다.
   - **스크린샷 마법사를 열었다 닫으면 일반 웰컴이 된다.** 마법사가 웰컴을 대체해 그리므로(`page.tsx:88`) 닫을 때 웰컴이 새로 뜨고, 표식은 이미 지워졌다. 이때 `welcome_view`(`웰컴`)도 현행대로 1건 더 나가고 `웰컴·체험`은 다시 나가지 않는다. 다시 스크린샷 버튼을 누르면 현행 재개 규칙(pending인 첫 단계)이다.
   - 유지하지 않는다(기획 판정). 유지하려면 모듈 메모리 변수 1개가 더 필요한데, 닫은 사람은 이미 한 번 그 자산군 단계를 보았고 상태가 남는 조건이 하나 더 늘어난다. 필요해지면 그 방식(저장소 0)으로만 하고 CEO 판정을 받는다.

- 버튼 수·순서·문구·testid·GA method는 전 상태 같다. 새 버튼·새 링크 0. 부동산 상태는 두 버튼의 variant와 포커스만 맞바꾼다(CEO 판정 ②, 지금 확정). 이유: 마법사에 부동산 단계가 없어(`WIZARD_CATEGORIES` 4종) 색 버튼을 누르면 주식 캡처 안내가 나온다.
- 마법사 시작 단계 규칙(조건 3)
  1. 그 자산군이 `pending`일 때만 그 단계에서 연다. 아니면 현행 재개 규칙.
  2. 시작 단계는 메모리로만 넘긴다(`onboarding-wizard-store` 인자 1개). `onboardingWizardStatus` 저장 형식 무변경. **store 인자 1개를 넘는 구조 변경이 필요하면 멈추고 CEO 재판정.**
  3. 그 단계 뒤는 현행 `goToNextCategory`(뒤쪽 단계만) → 완료. 앞 단계(주식 등)는 `pending`으로 남아 다음에 열면 거기서 재개된다.
  4. `wizard_step` start를 **새로 보내지 않는다**. 전송은 현행 그대로(인트로 `시작하기`·단계 done/skipped·exit·complete).
- 짚는 표시: 기존 토큰·컴포넌트만(새 패턴 0), 줄 수 +0. 새 문장·표시는 전부 C139 전수표에 넣는다.
- 짚는 표시 모양(CEO 대리 검토 C): 주식·암호화폐·현금·대출·부동산 5개 상태 모두 같은 면(`bg-accent`·`font-semibold`)만. 터치로 열 때 어느 상태에서도 행에 링이 생기지 않는다(부동산만 테두리 링이던 목업은 첫 포커스 겹침 결과 — 고침). 키보드 포커스 링(`focus-visible`)은 별개로 유지.
- 실물: 현행 등록 칸 + title만.
- **허용 축소(CEO challenge 조건 2)**: 팝오버 '짚는 표시' 생략(첫 포커스만 남김)뿐이다. 암호화폐·현금·대출의 시작 단계와 부동산 상태는 줄일 수 없다 — 이것이 '복귀 뒤 이어짐'의 실체다. D10의 '주식 1종만'은 삭제(주식은 제목만 바뀌어 금지된 축소와 같아진다).
- 정직한 한계: 주식에서 돌아온 사람이 새로 보는 것은 제목·설명과 팝오버 포커스다. 체감은 암호화폐·현금·대출·부동산과 '어디서든 나갈 수 있음'에서 나온다.

## 7. 엣지 케이스
1. 처음 온 사람·보유자: diff 0. 2. 예시 데이터가 빈 자산군(실물 0건): 표시는 같다. 3. 체험 중 예시를 편집·삭제해 자산 0건이 되면 체험 페이지에 웰컴이 뜬다 — 이때 공통 표시는 그리지 않아도 된다(웰컴에 등록 칸이 있다, 현행 유지). 4. sessionStorage 쓰기 실패: 현행 주석대로 일반 웰컴 복귀. 5. 시작 버튼 연타: 1회만(현행 `busy`). 6. 뒤로가기로 체험 주소에 돌아옴: 체험이 다시 시작된다(현행), 전달값은 이미 지워짐. 7. 오래된 탭(배포 전 번들)의 체험에서 누름: 둘째 값이 없어 현행 복귀. 8. 복귀한 웰컴이 인앱 상태로 판정되는 경우는 없다(인앱은 외부로 나간다) — 만에 하나면 인앱 칸 현행.
