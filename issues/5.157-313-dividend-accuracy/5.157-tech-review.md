## 4. 공용 함수 설계

### 위치·시그니처 (`src/lib/finance/dividend-calc.ts`, 순수 함수, React 의존 0)
```ts
interface DividendRowInput { stock: Stock; payouts: DividendPayoutResult[]; }   // stock = 계좌별 원본 행(병합 금지)
computeDividends(rows: DividendRowInput[], txs: Transaction[], usdRate: number, todayKst: string): {
  months: Array<{ month: number; byCategory: Record<Cat, { paid: number; expected: number }> }>;   // 1..12
  byStock: Map<tickerCategoryKey, { paid, expected, perMonth: {paid: number[], expected: number[]}, qtyUsed: 'derived'|'current', heldQty }>;
  annual: { paid, expected, total };
}
```
- 현행 3곳이 쓰는 `groupStocksByTickerCategory→mergeStockGroup`은 **쿼리 대상(ticker 단위 fetch)과 표시 행 묶기에만** 쓴다. 계산 입력은 병합 전 계좌별 행이다. `mergeStockGroup`은 `purchaseDate`를 가장 이른 날로, `id`를 `__merged__…`로 바꿔 거래 `stockId`와 매칭이 끊기므로 병합 후 역산은 불가능하다.
- 같은 ticker·카테고리의 payouts는 동일(쿼리 키 `["dividend","v11",ticker,type]`)이라 계좌별 행에 같은 배열을 붙이면 된다. 훅은 지금 구조(병합 기준 `useQueries`)를 유지하고 `payoutsByKey` Map만 만든다. fetch 횟수는 불변.
- 1행당 계산: `qty(payout) × amountPerShare × rate`, 계좌별로 먼저 계산한 뒤 월·카테고리·종목 키로 합산한다. 반올림은 마지막 합산 뒤 1회(현행은 월·카테고리별 반올림이라 차트 합과 허브 합이 1~수 원 어긋날 수 있다. 허브도 연 합계를 월 합 합으로 구한다).

### 시점 수량 역산 `heldQtyAt(stock, txs, payoutDate)`
1. 대상 거래: `tx.stockId === stock.id && tx.reflected`(미반영 거래는 현재 수량에 안 들어갔으므로 무시). `tx.date >= payoutDate`인 거래를 되돌린다.
2. `qty = stock.quantity − Σ(buy, date ≥ 지급일) + Σ(sell, date ≥ 지급일)`. (지급일 당일 거래는 보유로 안 친다. 매수 당일은 권리 없음 쪽으로 보수적.)
3. **현재 수량 폴백**: ① 해당 행에 반영 거래가 0건 ② `qty < 0` ③ `qty`가 NaN ④ 거래 합계가 맞지 않는 징후(`positionSource==="manual"`이고 `positionEffectiveDate`가 지급일 뒤인 경우, 즉 사용자가 직접 수량을 덮어쓴 뒤 그 이전 거래를 되돌리면 의미가 없음). 이 경우는 지금 수량을 쓰고 `qtyUsed:'current'`로 표시한다(현행 유지).
4. `qty === 0`은 폴백이 아니라 '그 시점 미보유'로 0원이다(매수 전 지급분 제외를 거래로 정확히 표현).
5. 매수일 규칙 통일: 거래 기록이 있는 행은 3번 판정으로 충분하다. 거래 기록이 없는 행은 `payoutDate < stock.purchaseDate`이면 제외(날짜 단위, 차트·허브와 같은 규칙). 종목 표의 '매수 월 이후' 월 단위 규칙은 폐기해 3곳을 일치시킨다. 표의 '매수 이전' 흐린 월 뱃지(`beforePurchaseMonths`)는 같은 판정(0원 또는 제외)으로 유지.
6. 거래 로그 보존이 3년이라 올해 이전 지급분은 안 쓰므로 누락 영향 0. 병합 행이 아니라 `stock.id` 매칭이므로 #310 증권사 이관(`stockId` 유지 여부)은 이관 후 개발에서 `Transaction.stockId`가 이관된 행을 따라가는지 확인한다(5.156 머지 후 착수 조건과 일치).

### 지급 판정 (날짜 기준)
- 지급 = `payoutDate <= todayKst`(KST `YYYY-MM-DD` 문자열 비교) **그리고** `!p.isEstimated`. 아니면 예상.
- 연-월 단위(`<= currentYM`)는 폐기한다. 현행은 이번 달 15일에 해당하는 예상치를 26일에 '지급'으로 보이게 하고, 이번 달 30일 확정 지급도 '지급'으로 앞당긴다. 확정이지만 미래 날짜는 '예상'으로 둔다.
- 영향: 차트 Hero `isPastMonth`(`dividend-chart.tsx:221`, 월 번호 비교)는 이번 달을 항상 '지급'으로 라벨한다. 이번 달은 지급·예상이 섞일 수 있으니 월 선택 Hero는 데이터 기준(지급 합 / 예상 합 둘 다 있으면 합계에 '일부 예상')으로 바꾼다. 이 문구는 ui-review에서 검수.
- 해외 `payoutDate`는 KIS `acpl_bass_dt`(현지 기준일)이고 국내는 `divi_pay_dt`(실제 지급일)이다. 수량 역산 기준일을 해외는 기준일로 쓰는 편이 오히려 권리 기준에 맞다. 기존 안내문 '한 달쯤 밀릴 수 있어요'는 유지.
