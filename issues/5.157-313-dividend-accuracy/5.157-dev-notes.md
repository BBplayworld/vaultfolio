## 알려진 한계
- 같은 결과의 '반올림 전' 월 합·종목 합·연 합은 부동소수 덧셈 순서가 달라 마지막 자리(1e-8 이하)까지 같지 않을 수 있다 → 테스트는 `toBeCloseTo(…, 8)` + 반올림 값 `toBe` 동일로 검사. 화면 문자열은 모두 `annual.*` 1회 반올림이라 같다. 표 행 합은 행별 반올림으로 종목 수(원) 이내 차이 가능(spec 9-2 허용).
- 표 주당 금액은 '수량이 잡힌 첫 지급' 기준(이전: 매수 후 첫 지급). 표 통화는 `stock.currency`(이전: 지급 행 currency 우선) — 차트·허브와 같은 환율 규칙으로 통일.
- 지급일 당일 manual 덮어쓰기(`positionEffectiveDate === 지급일`)는 spec 문구('지급일 뒤')대로 역산한다.
- 매수일 규칙은 거래 기록이 있는 행에도 적용(spec 4-3 '그 행은 0원'). 매수일보다 이른 날짜로 거래를 뒤늦게 적은 행은 매수일 이전 지급이 0원(현행과 같은 방향).
- CDN 6시간 동안 예전 캐시 응답(추정분 false)이 남을 수 있음(spec 8장, 악화 0).
- 새 소식 id `20261126-01`은 머지일에 맞춰 조정 필요(같은 날 5.155·5.156 항목이 있으면 순번 충돌 — 리베이스 때 확인).
- 데이터 안전: 저장 키·스키마·동기화·공유·백업·서버 요청 파라미터(`ticker·type·excd`) 변경 0. 바뀌는 것은 화면 배당 숫자와 성적표 배당 입력(신규 기록부터). 판독 경계 = 머지일.
