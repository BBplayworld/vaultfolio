## 2. 점검 한 장 외부 열기 (spec 10-2·10-5)
- `report-tab.ts`에 1회용 `growOpenKey: string | null`(이름표 키) 추가. 해시·저장소·store 0.
- 진입: `resetReportTab()` → `setGrowView("stock")` → 키 설정 → `navigate({type:"activity", tab:"report"})`. 타일은 키 없이 앞의 둘만. **`resetReportTab` + `setGrowView("stock")`으로 충분하다** — `StockLabelBlock`의 `picked` 초기값이 `getGrowView()`이고 `lastTab`도 `grow`로 돌아간다. 홈 팁은 `resetReportTab()`만(허브와 같은 `firstGrowView`).
- 블록: `GrowViewPanel`의 `openKey` 초기값을 그 키의 행(`row.labelKey === 키`)으로 잡고, 마운트 effect에서 키를 비운 뒤 그 행으로 스크롤. 마운트 시점에는 거름(`filter`·`pickFilter`)이 없어 행이 항상 목록에 있다. 읽기는 초기값, 비우기는 effect로 나눈다(개발 모드 이중 호출에 안전).
- 스크롤 위험: `navigate`가 먼저 맨 위로 올리고, 블록은 `ready` 뒤에 그려지며 접힘 전환(200ms)이 있다. 그린 다음 프레임에 `scrollIntoView`. 어긋나면 하한 '주식 보기 도착'으로 내린다(preview에서 qa 확인).

## 3. 뒤로가기 — **spec에 없는 수정 1건이 필요하다**
- 지금 `back()`은 성과 하위 화면에서 항상 성과 허브로 `navigate`한다(pop 아님). 그대로면 머리 화살표 뒤로가기가 출발 화면이 아니라 허브로 가 **AC-5·AC-14가 실패**한다(기기 뒤로가기만 맞는다).
- 방법: `marketCompareEnteredInApp`과 같은 모듈 플래그. `navigate`에서 도착이 `activity/report`일 때 `직전 화면이 detail인가`를 기억하고, 참이면 `history.back()`, 라벨은 중립 `뒤로`. 순수 함수 1개로 빼 테스트한다. 허브·홈 팁·새 소식 진입은 직전이 detail이 아니라 지금과 같다(성과 허브).
- 왕복(spec 7절): 종목 한 장 대상은 `stock-page-store`에 남아 pop으로 돌아오면 `guardStockPageView`를 통과한다. 다만 점검 한 장에서 `종목 페이지`를 누르면 대상이 덮여(원화·티커 전체 묶음·`origin: market-compare`) 돌아온 종목 한 장이 처음과 통화·묶음이 다를 수 있고, 다른 종목을 열었다면 그 종목이 보인다. 기존 동작이며 고치지 않는다(알려진 한계).

## 4. 성능
- 행마다 계산하지 않는다. `StockTab`에서 1회, 행은 `Map.get`. 비용은 보유 건 + 거래 + 종목 × 점검 기록(종목당 12건 상한) — 50종목 기준 1ms 안팎으로 **추정**(미측정). 다시 도는 때는 `assetData.stocks`·환율·이름표가 바뀔 때뿐. `now`는 블록처럼 마운트 때 1번 고정.
- 홈: `HomeTipBox`에 `useStockLabels` + `buildGrowBoards` `useMemo` 1개. 허브 카드가 이미 같은 일을 한다. 번들: `asset-page-tabs.tsx`가 `PerformanceHub`를 정적으로 불러 grow 모듈은 이미 첫 묶음에 있다 — 증가는 새 코드뿐(빌드 출력으로 확인 필요).
- **홈 팁 판정은 이름표 읽기(`ready`) 뒤로 미뤄야 한다.** 안 그러면 첫 판정이 아래 순위(`refresh`)를 골라 `오늘 노출` 기록을 써 버리고 `홈 팁` 노출 GA를 보낸 뒤 차례 팁으로 바뀐다(떴다 사라짐 + 잘못된 집계).

## 6. 미정 기기 diff 0 보장·테스트 전략
1. 구조: 새 노드는 전부 Map 조회 결과가 있을 때만 그린다. Map에는 keep·check 행만 넣어 미정·`정하지 않음`·티커 없음·상장폐지·수량 0은 prop이 `undefined`. 빈 span·래퍼 추가, 기존 요소 class 조건 변경 금지. `pickHomeTip`은 차례 입력이 없으면 기존 분기 그대로.
2. 기준 스냅샷 선커밋: 분기 직후 **코드 변경 전** 첫 커밋으로 행 머리·펼침·종목 한 장 머리·타일 묶음의 마크업 스냅샷을 고정한다. 구현 뒤 스냅샷 diff가 타일 1개뿐임을 PR에서 본다(= 분기 시점 main 대비).
3. 동치 테스트: 이름표 0개 / 전부 `정하지 않음` / 티커 없는 종목만 → 마크업 동일.
4. 주의: 기존 화면 테스트는 `renderToStaticMarkup`이라 `useEffect`가 돌지 않아 `ready`가 늘 false다. 훅 결선과 표시를 나눠 값을 prop으로 넣어 테스트한다(블록의 `store` prop 선례).
5. 단위: 4-1 상태 2~13 문장, 4-3 이유 3경우·단위, 4-4 값 줄, 팁 = `growStatus().due ≥ 1`, 순위(기존 `home-tip.test.ts` 무수정 통과 + `due` 묶음), 외부 열기 1회 소비, 뒤로가기 함수, GA 조건. AC-9는 qa가 preview 시나리오로.

## 8. 쟁점 — 코인만 차례일 때 타일 값 ≠ 허브 수
- 값은 **주식 범위(`boardStatus`) 유지**를 권한다. 전 종류 합으로 바꾸면 `점검 차례 1종목`을 누르고 도착한 주식 보기에 차례가 없다(도착 불일치가 더 큰 결함). 계산도 `StockTab`의 rows 하나로 끝난다.
- 다만 이름을 `내 자산 점검`으로 바꾸면서 **같은 이름 두 곳(타일·세그먼트·허브)의 수가 다르게 보이는 문제가 새로 생겼다**(수 정합 C84). 값 줄에 범위 낱말을 넣는 안을 ui에 넘긴다: `주식 점검 차례 2종목` / `주식 6종목 · 정하기 전`(새 낱말 0, 문자열만 차이, 구현 비용 같음).
- 참고: 값의 차례 수는 도착 목록의 `점검 차례` 행 수와 같다. 종합 카드 둘째 줄은 점검 대상의 차례만 세므로 장기 보유 12개월 차례가 생기는 2027-11부터는 카드 문장과 다를 수 있다.
