## ① 툴팁 `M월 합계` → `M월 배당`: 채택
- 월을 선택하면 표 머리 `M월 합계`(종목 한 개)와 툴팁이 한 화면에 함께 보인다. 같은 이름이 다른 범위를 가리키는 문제가 다시 생기므로 ceo.md 틀 2를 고친다.
- 고정 규칙: `배당` = 전 종목(Hero `올해 배당`·`M월 배당`·툴팁), `합계` = 종목 한 행(표 `올해 합계`·`M월 합계`). 툴팁 마지막 줄 금액은 같은 달 월 Hero와 ±0원이어야 한다(수용 기준 12).

## ② Hero `지급` emerald vs 표 brand: 범위 밖
- 모양 규칙(면 = 지급, 점선 = 예상)은 이번에 Hero와 표가 같이 쓴다. 대표가 지적한 것은 뜻과 검산이었고 색은 지적하지 않았다. 색을 맞추면 Hero 배지 디자인까지 바뀌어 범위가 커진다.
- 이 건은 예약하지 않는다. 사용자 신호가 있을 때만 다시 연다(LEARNINGS 11-16, spec 9절). qa는 '같은 뜻에 색 2개'를 알려진 차이로 기록하고 FAIL로 처리하지 않는다.

## ③ B 월배당 규칙 '올해 >4건' → 'n≥7': 채택
- 근거: qa 패턴표 S-4(분기 + 특별 2회 = 올해 5건)는 '>4건' 규칙으로 통과할 수 없다. 출발점으로 정했던 규칙을 기대값(사용자 상식)에 맞게 고친 것이고, 수락 기준은 그대로다. 그래서 철회선을 옮기는 것이 아니다. qa 초안이 40/40과 기존 route 테스트 4건을 통과해 규칙끼리 모순되지 않는다는 것도 확인됐다.
- 남은 위험: 분기에 특별배당 3회가 겹쳐 7건이 되면 월배당으로 오판한다. 드물고 main 동작보다 나빠지지 않으므로 받아들인다.
- 구현 규칙은 qa 초안을 따르되 정본은 테스트다. 40행 전부 통과, main 통과 30행 악화 0, 기존 route 테스트 통과, 데모 예상 5,364·Hero 165,376(±1, 수용 기준 5)을 모두 채워야 한다. 데모 기대값은 패턴표 밖이므로 qa가 qa-facts 목으로 따로 대조한다.

## ⑤ 커밋 구성·risk·폐기선
- 커밋 순서(issue-5.184 한 브랜치·PR 1개):

  2. **B 구현**: route.ts 빈도 판정 + `DIVIDEND_CACHE_VERSION`·쿼리 키를 각각 한 단계 올린다(5.183 방식, `withinUpstreamBudget` 안). 40/40을 통과한 구현만 qa에 넘긴다. developer가 qa에 넘기기 전에 스스로 고친 것은 FAIL 횟수에 들어가지 않는다.
  3. **C 문구·배지·최근 1주당**: B와 다른 커밋(여러 개 가능). B를 되돌려도 C가 깨지지 않는 구조로 만든다.
