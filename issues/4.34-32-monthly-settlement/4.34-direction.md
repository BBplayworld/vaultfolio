# #32 r2 — 성과 정보 구조 재설계: 결산·자산 변화·성적표 중복 제거 (direction.md)

## 사업 (business-pm)

### 중복이 생긴 이유 (r1 되짚기, 코드 확인)
- r1은 "메뉴 수"만 줄였다(4개 -> 3개). 항목(지표) 단위 대조를 안 했다(LEARNINGS 신규 2줄과 같은 원인).
- 코드 확인: 성적표(`asset-report-view.tsx`)에 "순자산 변화, 왜?"가 그대로 남아 있고(r1 계획은 "월 탭으로 이동"이었으나 이동이 아니라 복제), 월 탭 결산(`settlement-view.tsx`)에도 "변화 원인"이 있다. 같은 엔진·같은 질문이 두 화면에 있다.
- 겹치는 후보 항목: 순자산 증감(결산 "순자산 비교" / 자산 변화 월 탭 / 허브 카드), 변화 원인(결산 / 성적표), 투입 대비 성과의 "남긴 돈"(성적표 / 결산 비교와 혼동).

### 사용자가 성과 탭에서 답을 얻어야 할 질문 (3개, 정본 화면 1개씩)
| 질문 | 정본 화면 | 정본이 되는 핵심 항목 |
|---|---|---|
| 1. 기간 동안 내 자산이 얼마나 변했나 | 자산 변화 (일·주·월·연) | 순자산(또는 주식) 증감액·% |
| 2. 이번 달은 왜 그렇게 됐나 (월 1회) | 자산 변화 월 탭 = 결산 | 변화 원인 분해 (정본은 여기 하나) |
| 3. 내 돈이 이자 빼고 실제로 얼마를 남겼나 / 자산 상태는 어떤가 | 자산 성적표 | 투입 대비 성과, 5축, 등급 |
- 배당은 별도 질문("얼마 받나")이라 기존 화면 유지.
- 규칙: 한 지표는 정본 1곳에만 두고, 다른 화면은 값을 다시 계산해 보여주지 않고 링크 한 줄로만 연결한다. 성적표의 "순자산 변화, 왜?"는 제거 대상(질문 2의 정본이 월 탭), 결산의 "순자산 비교"는 월 탭 헤더 1곳으로 합친다. 정확한 제거·통합 목록은 경험 절에서 항목 전수 대조표로 확정한다.

### 리텐션 관점: 월 1회 돌아오게 하는 핵심 1가지
- **"이번 달 왜 이렇게 됐나"를 한 화면에서 끝내는 것.** 성적표와 결산에 같은 설명이 나뉘어 있으면 어디가 답인지 몰라 월 1회 의식이 약해진다. 결산을 정본 한 곳으로 모으면 돌아와서 볼 곳이 분명해진다.

### 성공 지표 (기존 합의 재검토)
- 유지: 지표 1(결산 창 재방문 기기 비율, GA 기본 지표, 기준선은 business.md 절차 그대로), 지표 2(`settlement_view` -> 7일 내 `asset_save` 퍼널). 이벤트 `settlement_view`(source, result)는 월 탭 진입 1회 정의 그대로이며 구조 변경과 무관하다.
- 추가 점검(신규 이벤트 없이): 성적표 화면 방문(`/v/activity/report`)이 개편 후 줄지 않는지만 본다. 성적표에서 중복 항목을 빼도 고유 질문(질문 3)의 가치가 유지되는지 확인하는 용도다. 줄면 성적표 고유 항목이 약하다는 신호로 별도 후보를 올린다.
- 상단 탭 UI 개선의 효과 측정은 별도 지표를 두지 않는다(표본 50명, 이벤트 추가는 과함). 완료 기준(전환 횟수·터치 영역)을 qa가 본다.
- 판단은 여전히 결산 2회 누적 후.

### 하지 않으면 무엇을 잃나 / 중복이 남으면 무엇을 잃나
- 하지 않으면(r2를 안 하면): v4.34 출시 시점부터 같은 설명이 두 군데에 있는 화면이 라이브에 나간다. 대표가 이미 지적한 품질 문제이고, 출시 후 고치면 GA 화면키·사용자 습관이 한 번 더 바뀐다. 근거 강도: **중간**(대표 관찰 + 코드로 중복 확인. 사용자 혼동이 실제로 있는지는 데이터 없음).
- 중복이 남으면: 월 1회 방문의 답이 어디인지 흐려져 결산 가설(재방문 -> 갱신) 검증이 어렵고, 성적표와 숫자가 조금이라도 다르면 "숫자가 안 맞는다"는 신뢰 문제로 번진다. 한 번 잃은 숫자 신뢰는 스크린샷 갱신 의욕까지 꺾는다.
- 상단 탭 UI: 근거 **약함**(정량 데이터 없음). 다만 월 1회 오는 사용자는 첫 화면에서 막히면 이탈하므로 비용 대비 우선순위는 중복 제거 다음이다.
