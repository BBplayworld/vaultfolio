# #32 r2 — 성과 정보 구조 재설계: 결산·자산 변화·성적표 중복 제거 (direction.md)

## 사업 (business-pm)

### 중복이 생긴 이유 (r1 되짚기, 코드 확인)
- r1은 "메뉴 수"만 줄였다(4개 -> 3개). 항목(지표) 단위 대조를 안 했다(LEARNINGS 신규 2줄과 같은 원인).
- 코드 확인: 성적표(`asset-report-view.tsx`)에 "순자산 변화, 왜?"가 그대로 남아 있고(r1 계획은 "월 탭으로 이동"이었으나 이동이 아니라 복제), 월 탭 결산(`settlement-view.tsx`)에도 "변화 원인"이 있다. 같은 엔진·같은 질문이 두 화면에 있다.
- 겹치는 후보 항목: 순자산 증감(결산 "순자산 비교" / 자산 변화 월 탭 / 허브 카드), 변화 원인(결산 / 성적표), 투입 대비 성과의 "남긴 돈"(성적표 / 결산 비교와 혼동).

### 사용자가 성과 탭에서 답을 얻어야 할 질문 (3개, 정본 화면 1개씩)
| 질문 | 정본 화면 | 정본이 되는 핵심 항목 |
|---|---|---|
| 1. 기간 동안 내 자산이 얼마나 변했나 | 자산 변화 (일·주·월·연) | 순자산(또는 주식) 증감액·% |
| 2. 이번 달은 왜 그렇게 됐나 (월 1회) | 자산 변화 월 탭 = 결산 | 변화 원인 분해 (정본은 여기 하나) |
| 3. 내 돈이 이자 빼고 실제로 얼마를 남겼나 / 자산 상태는 어떤가 | 자산 성적표 | 투입 대비 성과, 5축, 등급 |
- 배당은 별도 질문("얼마 받나")이라 기존 화면 유지.
- 규칙: 한 지표는 정본 1곳에만 두고, 다른 화면은 값을 다시 계산해 보여주지 않고 링크 한 줄로만 연결한다. 성적표의 "순자산 변화, 왜?"는 제거 대상(질문 2의 정본이 월 탭), 결산의 "순자산 비교"는 월 탭 헤더 1곳으로 합친다. 정확한 제거·통합 목록은 경험 절에서 항목 전수 대조표로 확정한다.

### 리텐션 관점: 월 1회 돌아오게 하는 핵심 1가지
- **"이번 달 왜 이렇게 됐나"를 한 화면에서 끝내는 것.** 성적표와 결산에 같은 설명이 나뉘어 있으면 어디가 답인지 몰라 월 1회 의식이 약해진다. 결산을 정본 한 곳으로 모으면 돌아와서 볼 곳이 분명해진다.

### 성공 지표 (기존 합의 재검토)
- 유지: 지표 1(결산 창 재방문 기기 비율, GA 기본 지표, 기준선은 business.md 절차 그대로), 지표 2(`settlement_view` -> 7일 내 `asset_save` 퍼널). 이벤트 `settlement_view`(source, result)는 월 탭 진입 1회 정의 그대로이며 구조 변경과 무관하다.
- 추가 점검(신규 이벤트 없이): 성적표 화면 방문(`/v/activity/report`)이 개편 후 줄지 않는지만 본다. 성적표에서 중복 항목을 빼도 고유 질문(질문 3)의 가치가 유지되는지 확인하는 용도다. 줄면 성적표 고유 항목이 약하다는 신호로 별도 후보를 올린다.
- 상단 탭 UI 개선의 효과 측정은 별도 지표를 두지 않는다(표본 50명, 이벤트 추가는 과함). 완료 기준(전환 횟수·터치 영역)을 qa가 본다.
- 판단은 여전히 결산 2회 누적 후.

### 하지 않으면 무엇을 잃나 / 중복이 남으면 무엇을 잃나
- 하지 않으면(r2를 안 하면): v4.34 출시 시점부터 같은 설명이 두 군데에 있는 화면이 라이브에 나간다. 대표가 이미 지적한 품질 문제이고, 출시 후 고치면 GA 화면키·사용자 습관이 한 번 더 바뀐다. 근거 강도: **중간**(대표 관찰 + 코드로 중복 확인. 사용자 혼동이 실제로 있는지는 데이터 없음).
- 중복이 남으면: 월 1회 방문의 답이 어디인지 흐려져 결산 가설(재방문 -> 갱신) 검증이 어렵고, 성적표와 숫자가 조금이라도 다르면 "숫자가 안 맞는다"는 신뢰 문제로 번진다. 한 번 잃은 숫자 신뢰는 스크린샷 갱신 의욕까지 꺾는다.
- 상단 탭 UI: 근거 **약함**(정량 데이터 없음). 다만 월 1회 오는 사용자는 첫 화면에서 막히면 이탈하므로 비용 대비 우선순위는 중복 제거 다음이다.

### 2. 통일 후 화면별 역할과 구성
**"이번 달 결산"과 "자산 변화 월 탭"은 같은 질문("이번 달 왜 이렇게 됐나")에 답하므로 하나다.** "이번 달 결산"이라는 별도 카드·블록은 없애고, 월 탭 Hero의 이름("10월 결산")과 허브 카드 배지로만 남긴다.

- **성과 허브** — 역할: 3개 화면으로 들어가는 입구. 카드 4개 → **3개**(DECISIONS·PRINCIPLES 5장 "3개"와 일치)
  1. 자산 변화 카드(결산 카드 흡수): 결산 창(말일 3일 전~다음 달 10일)에는 배지 "10월 결산" + "9/28 → 10/28" + 증감액·%, 창 밖에는 "11월 · 진행 중" 증감. 첫 달은 "다음 달부터 결산이 열려요". 누르면 월 탭
  2. 배당(기존) 3. 자산 성적표(기존)
- **자산 변화** — 역할: "기간 동안 얼마나, 이번 달은 왜" (질문 1·2 정본). 위→아래:
  1. 제목 행: "자산 변화" + 오른쪽 범위 선택 [전체 자산 | 주식]
  2. Hero 카드: 기간 이름(+월 이동) → 증감액·% → "A → B" → 기간 선택 [일 주 월 연]
  3. 본문(기간별): 일=달력 / 주=일자 목록 / **월=변화 원인 → 다음 달 준비** / 연=연도별 차트·목록. 주식 범위=시장 필터(전체·국내·해외) → 종목별 수익
- **자산 성적표** — 역할: "내 돈이 이자 빼고 얼마를 남겼나, 자산 상태는 어떤가" (질문 3 정본). 위→아래: 등급 Hero → 투입 대비 성과 → 5축 측정 → AI 프롬프트. **"순자산 변화, 왜?" 섹션 삭제**(5→4섹션)
- **홈 Hero** — 변경 없음(지난 접속 이후 실시간 증감·원인)

### 3. 상단 컨트롤 재설계 (대표 지시 ②)

1. **위계 역전**: 데이터보다 컨트롤이 먼저, 크게 나온다. 범위(48px)·기간(48px)·월 칩(40px) 3줄이 쌓이고, 결산의 핵심 숫자(+20,665,442원)는 **y≈525px**에서야 보인다(q-375-dark-month). §4 "Hero → 필터/컨트롤 → 리스트" 순서와 반대

5. **월 칩 줄의 잡음**: 13개월 칩 중 기록 없는 달이 40% 흐림으로 줄지어 있고, 왼쪽 칩이 잘려 보인다(q-375 "4월" 반쪽). 가로 스크롤인지도 안 보인다

7. **엄지 거리·시선 흐름**: 조작 3곳이 화면 상단 1/4(y 105~350)에 몰려 있고, 조작 → 결과 사이 거리가 멀다(기간을 바꾸면 결과는 400px 아래에서 바뀜). 전환해도 바뀐 곳을 알려주는 움직임이 없다

- **① 범위 선택**: `InlineSelector` 신규 모드 `fullWidth`(같은 폭 칸 + 미끄러지는 선택 썸), 폭 `w-[164px]`, 칸 80×40px, 라벨 `text-sm`. h2는 기존 `text-base sm:text-lg lg:text-2xl font-bold` 유지. 범위 배지 삭제
- **② Hero**(신규 공용 `ChangeHero`, `layout/ui/`): 이름 줄 = 기간 이름 `text-sm font-semibold text-foreground` + 구간 `text-sm text-muted-foreground tabular-nums`. 월만 오른쪽에 이전/다음 달 화살표(각 `size-10` 둥근 버튼, `hover:bg-muted`, 상단바 뒤로가기와 같은 형태). 증감 = 홈 Hero 타이포 + `getProfitLossColor`. 보조 줄 = "시작값 → 끝값"(주식 행 "기준 → 현재" 표기와 동일). 기간 선택 = `InlineSelector fullWidth` `w-full`, 칸 약 79×40px, 라벨 `text-sm`(12px 탈피)
  - 기간 이름: 일 "10/27 기록 대비" · 주 "7일 전 대비" · 월 "10월 결산"(진행 중이면 "11월" + `GROUP_BADGE` "진행 중", 전년도 달은 "25년 10월 결산") · 연 "2025년 말 대비" · 주식 범위는 "10월 주식 수익"(시장 필터가 국내·해외면 "국내 · " 접두)
  - 월 이동: 기록 없는 달은 건너뛰고, 끝에서는 화살표 비활성. 월 칩 줄 삭제
- **트랙·썸 토큰**(라이트/다크 쌍, 하드코딩 금지): 트랙 `rounded-lg bg-muted/70 dark:bg-muted/50 p-0.5`, 썸 `rounded-md bg-card dark:bg-foreground/15 shadow-sm`(동심 radius 10→8). 선택 글자 `text-foreground font-semibold`, 비선택 `text-muted-foreground hover:text-foreground`. 다크에서 썸이 트랙보다 어두워 "눌린" 것처럼 보이는 현 InlineSelector 문제를 이 모드에서 해결. 테두리 없음
- **상태**: 선택(썸+굵기) / 비활성(`disabled`, 40% + `title` "기록이 없는 달이에요") / 로딩(주식 기준가 조회 중: 증감 자리 `h-8 w-44 rounded-md bg-muted motion-safe:animate-pulse`, 보조 줄 "기준가 조회 중…", 컨트롤은 계속 조작 가능, 조회 실패 "점검 중") / 오류("결산을 불러오지 못했어요. 다른 달을 선택해 보세요", 화살표는 동작) / 빈 상태("아직 기록된 달이 없어요. 앱을 계속 쓰면 다음 달부터 결산이 열려요", 증감 줄 없음) / 첫 달("다음 달부터 결산이 열려요") / 추정(원인 행 "예측" 배지 유지, Hero "일부 이전 값" 배지)
- **모션(§6, 모두 `motion-safe`)**: 썸 이동 `transition-[transform] duration-200 ease-[cubic-bezier(0.2,0.8,0.2,1)]`(CSS transform이라 연타 시 중간에서 자연스럽게 방향 전환 = 인터럽터블), 글자색 `transition-[color] duration-150`, 칸 누름 `active:scale-[0.96]`. Hero 숫자는 위치 고정 + `fade-in duration-200`(자리 이동 없음). 본문은 `fade-in slide-in-from-bottom-1 duration-300`, 원인 행 40ms 간격 stagger. 월 이동은 방향에 맞춰 4px 좌/우 진입. 퇴장 애니메이션 없음(즉시 교체). `transition-all`·`will-change` 사용 안 함
- **접근성(§7)**: `role="radiogroup"`+`aria-label`("범위 선택"/"기간 선택"), 칸 `role="radio" aria-checked`, ←/→·Home/End 키 이동(로빙 tabindex, 신규). 모든 히트영역 ≥ 40×40px. 화살표 `aria-label` "이전 달"/"다음 달". Hero 숫자 영역 `aria-live="polite"`로 전환 결과 읽기. 포커스는 전역 `outline-ring/50`
- **공유 이미지**: 범위·기간 선택은 상태 표시를 겸하므로 **남긴다**(그래서 범위 배지가 필요 없음). 월 화살표·"일부 이전 값" 배지·다음 달 준비만 `data-screenshot-hide`
- **수치 효과**: 결산 증감 첫 노출 y≈525 → **≈185px**, 첫 화면에 변화 원인 5항목까지 들어온다. 화면 위 컨트롤 3줄(주식 4줄) → 제목 행 1 + Hero 안 1(+주식 시장 필터 1). 탭 수: 허브 → 결산 1탭(동일), 지난달 1탭(동일), 범위+기간 변경 2탭(동일)이지만 기간 선택이 결과 바로 아래로 내려와 엄지 이동 거리 감소
- **재사용/신규**: 재사용 = `InlineSelector`(모드 추가), `SECTION`·`SectionHeader`·`SpecRow`, `getProfitLossColor`, `formatPriceByMode`, 홈 Hero 타이포, `GROUP_BADGE`. 신규 = `InlineSelector`의 `fullWidth` 모드(미끄러지는 썸·키보드 이동), `ChangeHero` 1개. `NetAssetChart`·`ProfitCard`에 "제목·요약 숨김" prop 1개씩(제어 모드에서만). 기존 `tabList2/3` 토큰은 다른 화면용이라 건드리지 않음. developer는 design-system §5에 `fullWidth` 모드와 Hero 패턴을 등록

### 4. 사용자가 이 개편 후 하게 될 행동 (관찰 가능)
- 결산 창에 허브 "자산 변화" 카드(배지 "10월 결산")를 눌러 월 탭에 들어오고, 스크롤 없이 증감액과 변화 원인을 읽는다
- Hero 아래 기간 선택으로 일·주·월·연을 바꿔 보며, 같은 자리에서 숫자가 바뀌는 것을 본다
- 원인을 보려고 성적표에 가지 않는다(성적표 방문은 등급·투입 대비 성과 확인 목적만 남음)

### 5. 바뀌는 곳 / 그대로인 곳
- 바뀜: 자산 변화 화면 상단(제목 행·Hero·기간 선택), 결산 블록 1·2(→ Hero), 월 칩 줄(→ 화살표), 주 탭 SpecRow, 일·연·주식 하위 카드 제목·요약, 허브 카드 4→3, 성적표 "왜?" 섹션 삭제, 성장 축 링크 대상(월→연)
- 그대로: 홈 Hero와 원인 펼침, 원인 엔진·결산 계산 함수, 13개월 보존, `settlement_view` 이벤트, 배당 화면, 성적표 나머지 섹션, 일 탭 달력·연 탭 차트·주식 종목 목록 본문, 다른 화면의 InlineSelector

### 6. 줄일 수 있는 것
- 허브 카드 4→3, 상단 컨트롤 3줄→1줄+Hero 내장, 월 칩 13개→화살표 2개, 결산 블록 4→3, 성적표 섹션 5→4
- 같은 정보 반복 5건 제거(범위 배지, 범위 캡션, "무엇이 바꿨나요", "일부 자산은 이전 값 기준이에요" 문장, 하위 카드 제목·설명)
- 성적표의 1주·3개월·올해 원인 분해(3개월은 대체 없이 줄임. 필요 신호가 오면 후보로)

### 7. 하지 않을 것
- 일·주·연 탭의 원인 분해 신설(DECISIONS 2026-10-27 cto 축소 유지), 원인 엔진·결산 계산 변경
- 홈 Hero 원인 어휘("주식 매수/매도·대출 상환") 변경 — 후보 목록 [type:simplify] 별건. 단 #8에서 홈과 월 탭의 어휘가 다른 것은 "핵심 항목 통일"과 맞닿으므로, 이번 릴리스에 포함할지 cto 판정을 요청한다
- 하단 고정 바·범위 드롭다운, 앱 전체 InlineSelector 스타일 일괄 교체(회귀 범위), 마지막 선택 기간 기억(저장 키 추가 = 스키마 변경), 연도별 수동 입력 UX 변경, 신규 지표

### 8. 사업 절에 대한 의견
**동의.** 질문 3개·정본 3화면·"값 재계산 금지, 링크 1줄" 규칙을 그대로 대조표에 적용했다. 보완 2건(이견 아님):
1. 허브 결산 카드가 "자산 변화" 카드에 흡수되므로 `settlement_view` `source=card`는 **결산 창 안에서 그 카드를 누른 경우만**, 창 밖 클릭은 `menu`로 둔다. 지표 1·2의 정의는 바뀌지 않는다
