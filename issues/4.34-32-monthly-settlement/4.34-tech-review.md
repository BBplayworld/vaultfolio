## 2. InlineSelector `fullWidth` — 29곳(21파일) 회귀 방지
- 구조: 함수 맨 앞에 `if (fullWidth) return <FullWidthSelector … />`(같은 파일 내부 함수) 분기 1줄만 둔다. 기존 `base` 계산과 `return` JSX는 글자 하나도 바꾸지 않는다. 결과적으로 diff는 props 타입 1줄, 구조분해 1줄, 분기 1줄로 끝난다.
- FullWidth: 트랙 `relative grid rounded-lg bg-muted/70 dark:bg-muted/50 p-0.5`, `style={{gridTemplateColumns:`repeat(${n},minmax(0,1fr))`}}`. 썸은 `absolute inset-y-0.5 left-0.5 w-[calc((100%-0.25rem)/n)]`(n은 inline style)에 `translateX(${idx*100}%)`를 적용한다. 자기 폭 기준 이동이라 JS 측정이 필요 없다(S3). 키 이동은 순수 함수 `nextEnabledIndex(idx, key, disabled[])`를 같은 파일에서 export하고 로빙 tabindex는 이 분기에만 둔다(S2).
- 스냅샷 고정(S1, 완료 기준 11): vitest 환경이 `node`이고 jsdom이 없으므로 `react-dom/server`의 `renderToStaticMarkup`으로 HTML 문자열을 비교한다. **구현 전 첫 커밋에서 테스트만 추가해 `toMatchInlineSnapshot`을 현재 코드 기준으로 생성한다.** 대상 케이스: size sm·md·lg·xl, disabledValues+disabledTitle, className·ariaLabel·testId·dataTutorial, ariaLabel 미지정. 이후 커밋에서 이 스냅샷이 바뀌면 회귀로 본다. 같은 파일에서 fullWidth 썸 style의 index별 `translateX` 값과 `nextEnabledIndex`(비활성 건너뛰기, Home/End, 끝에서 정지)도 단정한다.
- 실제 키보드 이동·Tab 순서(완료 기준 10)와 reduced-motion(13)은 preview에서 Playwright로 확인한다(`page.emulateMedia({reducedMotion:"reduce"})`).

**기존 엔진의 "올해"(`computePeriodAttribution("ytd")`, 예전 성적표)**: 시작 = 1/1 이하 최근 포인트. 운영에서는 `yearlyAnchorPoints`가 만든 **전년 수동값 앵커(전년-12-31, 레거시)**가 된다(월 스냅샷 _date는 월말이라 1/1 이후, 아카이브는 후보 아님). 앵커가 레거시라 하이브리드로 나뉜다. 가장 오래된 enrich daily(=30일 전)가 mid가 되고, 앵커→mid는 예측(매수일·반영 거래·입출금, 환율 이력 없음 → 환율 0, 나머지는 통합 "price"), mid→끝은 실측이다. **월 스냅샷은 mid 후보에서 제외**된다(_date 월말 강제 때문, 엔진 주석). 즉 지금 엔진으로도 작년 수동값 시작 원인은 이미 계산되지만, 실측은 최근 30일뿐이다.

### 2. 실현 가능한 안 (둘 다 엔진 `asset-report.ts` 변경 0)
- **A안 — 기존 ytd 그대로**: `computePeriodAttribution(daily, monthly, 환율이력, "ytd", assetData, rates, live)` → `mapSettlementCauses(effects, { deltaNet: Hero 증감 })`.
  - 장점: 예전 성적표 "올해"와 같은 결과이고 새 코드가 가장 적다.
  - 단점: 실측이 최근 30일뿐이다. 8~9월 enrich 월 스냅샷이 있어도 예측 구간에 묻힌다. 월 탭 원인의 합과 연 원인이 어긋난다(규칙이 다름). 13개월 보존된 전년 1~11월 월 스냅샷이 1/1 이하 후보로 들어가 앵커 대신 시작이 될 수 있다(C8 위반 소지, `monthly`를 올해분으로 걸러 넘겨야 함).
- **B안(권고) — 월 스냅샷 체인**: 점 = [전년 수동값 앵커(`${prevYear}-12-31`, Hero 시작과 같은 값), **올해 월 스냅샷 중 enrich 완비분만**(월 탭과 같은 점), 실시간 끝점]. 인접 쌍마다 `computeAttributionBetween(prev, curr, …, includeStartDay=false)`(월 탭과 같은 함수·경계)를 부르고, effects를 이어 붙여 `mapSettlementCauses`(키별 합산 확인됨)에 `deltaNet = Hero 증감`으로 넘긴다.
  - 첫 구간(앵커 → 첫 enrich 월)은 예측 경로다: 반영 거래·입출금은 실측이고 시세·평가는 통합 "시세 변동(예측)". 이후 구간은 실측이다.
  - **실측 구간의 원인 = 해당 달 월 탭 원인의 합**이 된다(같은 점·같은 함수·시작일 제외, C15). 이것이 정본 일관성이다.
  - 레거시 달(1~7월)은 체인에서 빠지고 첫 예측 구간에 흡수된다. enrich 달이 하나도 없으면 앵커 → 실시간 단일 예측 구간이 된다(A안의 mid 없음과 같다).
- **항등식**: 각 구간 effects 합 = 구간 Δ(엔진 보장)이므로 체인 합 = 실시간 − 앵커 = 실시간 − 전년 수동값이다. Hero 증감(올해 종가 upsert − 전년 수동값)과의 차이(실시간 vs 종가, 소액)는 `mapSettlementCauses`가 "기록 안 된 변화"로 흡수한다 → **합계 = Hero 증감 항상 성립**. 별도 보정 줄은 없다.
- 구현 범위(B): `change-hero.tsx` `computeSettlementCauses`에 체인 입력(점 배열) 분기 1개, `net-asset-chart.tsx` 연 원인 계산 교체. `resolveYearWindow`는 "전년 12월 스냅샷이 있으면 앵커 대신 그 점을 시작으로" 쓰는 보조로 유지하거나 삭제(추가 함수라 기존 diff 무관). `cause-insufficient`는 사실상 쓰이지 않는다(Hero 전년 값이 있으면 앵커가 항상 있음). 첫 해(전년 값 없음) 미표시는 유지.
