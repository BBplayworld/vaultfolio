## 2. 사양과 다르게 구현한 2곳 → 둘 다 타당
1. **바깥 div 한 겹**: 타당하다. Tailwind v4의 `space-y`는 `:where`라서 특이도가 0이다. 그래서 `-my-0.5`가 간격을 덮어 버린다. 사양에서 놓친 부분이고, 마진 상쇄로 높이 차 0을 실측으로 확인했다. 의미 없는 래퍼지만 주석으로 이유가 남아 있다.
2. **onFocus nearest 스크롤**: 타당하다. 크롬은 몇 px만 잘린 칸에 포커스가 와도 스크롤하지 않는다. 모든 폭·테마에서 Tab으로 마지막 칸까지 가 보았고, 포커스 칸이 줄 안에 있으며 위아래 여유 4px로 링이 잘리지 않았다. 마우스 클릭 포커스에도 동작하지만, 선택 effect와 같은 nearest라서 부작용이 없다.

## UI 수정 요청
`src/app/(main)/_components/views/detail/tabs/category-scroll-row.tsx` — 넘침 끝 페이드를 추가한다. 내가 ui.md §2의 "페이드 없음"을 철회한다.
1. 상태 `edge: { start: boolean; end: boolean }`을 둔다.
   - 계산식: `start = scrollLeft > 1`, `end = scrollLeft + clientWidth < scrollWidth - 1`
   - 갱신 시점: 컨테이너 `onScroll`(passive), `ResizeObserver`(컨테이너), `options.length` 변경
   - 넘치지 않으면 둘 다 false라서 main과 같은 모양이다.
2. 마스크는 정적 문자열 3종으로 두고, 전환하지 않는다(즉시).
   - end만: `[mask-image:linear-gradient(to_right,#000_calc(100%-24px),transparent)]`
   - start만: `[mask-image:linear-gradient(to_left,#000_calc(100%-24px),transparent)]`
   - 둘 다: `[mask-image:linear-gradient(to_right,transparent,#000_24px,#000_calc(100%-24px),transparent)]`
3. 컨테이너에 `scroll-px-6`을 추가한다. 선택·포커스 칸을 nearest로 스크롤할 때 페이드 24px 밖에 놓여 링·글자가 흐려지지 않게 하고, 다음 칸이 일부 보이게 해서 그 자체가 힌트가 되게 한다. 마지막 칸은 end=false라서 페이드가 없다.
4. 확인 기준(qa 판정 가능):
   - (a) 부동산 8칸 320·360 라이트·다크 스크린샷에서 오른쪽 끝 24px이 배경으로 사라지는 페이드가 보인다.
   - (b) 끝까지 스크롤하면 오른쪽 페이드가 없고 왼쪽 페이드가 있다.
   - (c) 1280·4칸처럼 넘치지 않는 줄에는 `mask-image`가 `none`이다.
   - (d) Tab·선택으로 이동한 칸의 rect가 페이드 영역(컨테이너 양끝 24px) 밖에 있다. 단, 첫 칸과 마지막 칸은 해당 끝에 페이드가 없으므로 예외다.
   - (e) 카드 높이 main 대비 0, 페이지 넘침 0을 유지한다.
5. design-system §5 반응형 줄에 "카테고리 가로 스크롤 줄 = 넘치는 쪽 끝 24px 마스크 페이드 + `scroll-px-6`"으로 흡수 등록한다. components.md의 `CategoryScrollRow` 설명도 갱신한다.
