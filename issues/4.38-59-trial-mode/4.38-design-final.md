## 1. 확정 사항

### C-1 체험 중 fetch 거부 래퍼 — **채택**
- 대안 비교
  | 안 | 막는 것 | 판정 |
  |---|---|---|
  | **A 래퍼(채택)** | `/api/parse-screenshot`·`/api/share`·`/api/sync`·`/api/feedback` 전부. 상세 탭 입력 다이얼로그의 스크린샷 탭(호출처 6곳: 자산 4·거래 2)까지 한 곳에서 | 수정 1곳, fail-closed. 실제 스크린샷 이미지가 체험 중 Gemini로 나가 예시 금고에 섞였다 사라지는 일도 없앤다 |
  | B Gemini 사용량 키 복사 | 클라 15회 한도만 | 실제 이미지 전송·share·sync를 못 막는다 → 기각 |
  | C 진입점 개별 숨김 | 숨긴 곳만 | 스크린샷 탭 6곳 + 마법사 + 다이얼로그 탭마다 가드, 누락 위험 → 기각(FAB·더보기 숨김은 보조로 유지) |
- 서버 전역 300회/일(`GEMINI_SERVER_DAILY_LIMIT`, cache-storage.ts:131): 래퍼가 있으면 체험이 추가로 쓰는 호출은 **0**이다. 저장소를 지우면 클라 한도를 우회할 수 있는 기존 위험은 체험과 무관(범위 밖).
- 구현(`trial-boot.ts`, 동적 import)
  - 설치: 게이트 ② 메모리 Storage 설치와 같은 단계에서 `window.fetch = trialFetch`. 원본 복구 코드 없음(S2와 같은 원칙).
  - 판정: 입력(string·URL·Request)을 `new URL(raw, location.href)`로 풀어 **같은 출처**이고 pathname이 거부 목록 `p`와 같거나 `p + "/"`로 시작하면 거부. URL 해석이 실패하면 거부(fail-closed). 그 밖은 원래 fetch로 통과.
  - 거부 응답: 네트워크를 타지 않는 **합성 응답** `new Response(JSON.stringify({ error: TRIAL_BLOCKED_MESSAGE }), { status: 403, headers: { "Content-Type": "application/json" } })`. reject하지 않는 이유: 6개 스크린샷 호출처와 피드백이 모두 `!res.ok`이면 `toast.error(data.error …)`를 띄우므로(코드 확인) **컴포넌트 수정 없이** 체험 전용 문구가 나온다. 사용량 증가는 성공 시에만이라 카운트도 0.
  - 검증 4종에 **5번째** 추가: `window.fetch === trialFetch && globalThis.fetch === trialFetch`. 실패하면 주입하지 않는다.
- 거부 토스트 문구(확정, `trial-mode.ts`의 상수 `TRIAL_BLOCKED_MESSAGE`): **"체험 중에는 사용할 수 없어요"** — 320 토스트에서 한 줄(약 200px)이라 C25 줄바꿈 위험 없음.

### C-2 인앱 + 체험 — `!isTrialMode()` 가드 **필수**

### C-4 거부 판정 — 읽기 전용
- 게이트는 메모리 설치 **전에** 원본 Storage 참조를 잡고 `getItem`·`Object.keys`·`JSON.parse`만 쓴다. `getAssetData()` 호출 금지(구버전 데이터에 마이그레이션 쓰기, asset-storage 78~100).
- 거부 조건(하나라도 해당하면 거부 → 쿼리만 제거하고 일반 화면):
  1. `secretasset_asset_data` 값이 있고 파싱 실패, 또는 객체가 아님, 또는 5배열 중 배열이 아닌 값이 있음, 또는 `hasAnyAssets` 참(없는 배열은 빈 배열로 본다)
  2. 구버전 키 `secretasset-asset-data`(LEGACY_KEYS)가 **있음**(값 무관 — 아직 이전되지 않은 기존 사용자)
  3. `secretasset_sync` 키가 **있음**(값 무관. assetId 파싱 없이 존재만으로 거부 — 더 단순하고 보수적)
  4. `secretasset_pwa_auth`로 시작하는 키가 하나라도 있음(실제 키 `_enabled`·`_pin_hash`, app-lock.ts 8~9)
  5. URL 해시에 `share=`·`sync=`·`asset=`·`vault=`가 있음(#60 restoreHash와 같은 목록)
- probe 키: `__secretasset_trial_probe__` + 난수(접두가 `secretasset_`가 아니라 clearAssetData 대상 아님). 검증 직후 메모리·원본 양쪽에서 `removeItem`. 원본에서 발견되면 지운 뒤 거부. 원본에 대한 쓰기는 이 removeItem 1건뿐이다.

### GA
- 진입: `trackThenNavigate(name, params, url)`를 ga.ts에 추가(채택). 순서: `isTrialMode()`면 즉시 이동 → gtag 없으면 즉시 이동 → `track`과 같은 sanitize 경로로 `gtag("event", …, { event_callback: done, event_timeout: 300 })` + `setTimeout(done, 300)`. `done`은 1회만 `location.assign`. 이유: gtag 큐는 hydration 전에 정의되지만(layout 134~139) gtag.js가 늦게 로드되면 이동과 함께 큐가 유실된다. 최악 지연 300ms, 칩은 탭 즉시 disabled.
- **추가(코드 사실)**: 루트 `layout.tsx` 헤드 인라인 GA 스크립트는 hydration 전에 `gtag('config')`를 실행하고 gtag.js의 자동 측정(스크롤 등)은 앱의 `track`을 거치지 않는다. 그래서 ga.ts 1줄 가드만으로는 "체험 페이지 GA 전부 끔"이 성립하지 않는다 → 인라인 스크립트의 `params` 처리 옆에 **`if (params.get('trial') === '1') window['ga-disable-' + GA_ID] = true;` 1줄**을 넣는다. 거부·검증 실패로 일반 화면이 된 그 1회 로드도 GA가 꺼진다(쿼리 직접 입력한 기존 사용자 등 극소수) — 알려진 한계.
- 복귀 이벤트 `onboarding_action{trial_start}`는 spec 그대로(별도 effect).
