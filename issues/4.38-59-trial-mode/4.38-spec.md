# #59 체험 모드 — spec (cto 축소 반영: 방식 B, risk:high · design-final 2026-10-31 반영)

근거 코드: issue-4.37. 신규 문구는 팀 확정(최종 확인은 반영 결정으로 갈음). 위험 등급 **high**.

## 1. 문제
- 첫 방문자는 등록 전에 "내 것이 되면 이런 화면"을 만질 수 없다. 웰컴 미리보기는 정적(`welcome-guide.tsx` ③⑤)이라 성과·결산을 볼 수 없다. GA: welcome_view 7기기 → onboarding_action 1기기 → first_asset_saved 0.

## 2. 목표 행동
- 웰컴 → "직접 둘러보기" → 결산/성과 열람 → "내 자산으로 시작" → 웰컴 CTA. 성공: 진입률 `feature_use{demo}` ÷ `welcome_view` 8주 ≥ 20%, 시작 `onboarding_action{trial_start}` ≥ 2기기(사업 절). 진입률 10% 미만이면 링크 위치·크기 재검토.

## 3. 범위
direction 2절. 새 URL은 `/?trial=1` 쿼리 1개뿐(새 라우트 없음).

## 4. 사용자 흐름
1. 웰컴(UI 조건: 자산 0건·`isSharePending=false`)의 ③ 라벨 행 "직접 둘러보기" 탭. 이동 직전 `trackThenNavigate("feature_use", {category: demo}, "/?trial=1")`(event_callback 또는 300ms 타임아웃 뒤 `location.assign`, gtag 없으면 즉시 — 실제 페이지에서, 체험 페이지에서 보내지 않음). (design-final C-1~4·GA)
2. 페이지 로드 → `TrialGate`(provider 바깥, PreviewGate와 같은 위치·패턴)가 `?trial=1`을 감지할 때만 동작. 쿼리 없으면 게이트는 즉시 children을 그대로 렌더(5.1).
3. 게이트 순서(fail-closed, 어느 단계든 실패하면 주입 없이 쿼리만 제거하고 일반 화면): ① 거부 판정(5.3 S3) → ② 메모리 Storage·fetch 거부 래퍼 설치 → ③ 검증 5종(5.2) → ④ `materializeDemo(demo-data, kstToday())` + `applyImportedPayload`(메모리 대상) + 튜토리얼 건너뛰기(`applyDemoTutorialSkip` 로직을 함수로 추출) → ⑤ 쿼리 제거(`stripQueryParams(["trial"])`, demo-inject로 일반화) → ⑥ children 렌더.
4. 체험 페이지: 홈 상단 배너 상시. 상세·성과·결산 탐색 가능. 상세 행 편집은 허용(메모리 내, 새로고침 시 소멸). FAB·더보기·설정 진입 숨김. GA 전부 끔.
5. 종료 ①: 배너 "내 자산으로 시작" → sessionStorage `trial_exit=1` → `location.assign("/")`(복구 코드 없음, 페이지를 버릴 뿐). 복귀한 실제 웰컴이 플래그를 읽고 `onboarding_action{method: trial_start}` 1회 전송 → 플래그 삭제 → CTA 슬롯을 asset 상태로 연다(기존 `showAssetCta` 경로 재사용). `welcome_view`는 억제하지 않는다(기기 단위 집계라 영향 없음).
6. 종료 ②: 새로고침(쿼리 제거 후이므로 일반 웰컴)·탭 닫기. 확인창 없음.
7. 인앱(#60)에서도 노출. 인앱 종료 버튼은 `location.assign("/")` 대신 외부 이동(`useExternalMove`).

## 5. 저장 차단 설계
### 5.1 구조 (방식 B)
- `TrialGate`는 `layout.tsx`에서 `ReactQueryProvider` 안·`AssetDataProvider` 바깥에 둔다(preview-gate.tsx 패턴 재사용: `resolvePreviewAction`류 순수 판정, `stripDemoQuery`).
- **쿼리가 없을 때 게이트는 children만 반환한다.** init 단계에서 children을 숨기지 않는다(일반 방문자 첫 렌더 지연·빈 화면 0). demo-data는 동적 import 유지(운영 번들 증가 최소).
- 체험 판정 `isTrialMode()`는 게이트가 설정한 모듈 변수. 체험 아닌 경로의 코드는 1줄 가드만 추가.

### 5.2 메모리 Storage와 주입 전 검증 5종
- 메모리 Storage는 **키가 `Object.keys`로 열거되는 객체**여야 한다(`clearAssetData`가 `Object.keys(localStorage)`의 `secretasset_*`를 지움 — asset-storage.ts 402~438. Map 내부 필드만 쓰면 정리가 안 됨). 체험 시작 시 테마·GA 옵트아웃 키만 원본에서 복사.
- 검증 5종 모두 통과해야 주입(하나라도 실패 = 주입 안 함, 원본 무접촉): ① `window.localStorage === mem` ② 전역 식별자 `localStorage === mem` ③ 원본 Storage에 probe 키 없음(probe `__secretasset_trial_probe__`+난수 기록 후 원본 확인, 직후 양쪽에서 제거 — 원본에서 발견되면 지우고 거부) ④ `Object.keys(mem)`이 기록한 키를 열거 ⑤ `window.fetch === globalThis.fetch === trialFetch`(아래 fetch 거부 래퍼).
- 원본 복구 코드를 두지 않는다(S2: 복구~reload 사이 디바운스·visibilitychange·pagehide 저장이 예시 데이터를 원본에 쓰는 경로 차단).

### 5.3 거부 판정 (S3)
- UI 노출과 별개로 **게이트가 메모리 설치 전 원본 저장소에서 읽기 전용으로** 판정한다(`getItem`·`Object.keys`·`JSON.parse`만, `getAssetData()` 호출 금지 — 구버전 데이터에 마이그레이션 쓰기 발생). 하나라도 해당하면 거부 → 쿼리 제거 후 일반 화면:
  1. `secretasset_asset_data`가 있고 파싱 실패·객체 아님·5배열 중 배열 아닌 값·`hasAnyAssets`(asset-storage.ts, #60) 참(없는 배열은 빈 배열)
  2. 구버전 `secretasset-asset-data` 키 존재(값 무관)
  3. `secretasset_sync` 키 존재(값 무관)
  4. `secretasset_pwa_auth`로 시작하는 키 존재
  5. 해시에 `share=`·`sync=`·`asset=`·`vault=`

### 5.4 차단 지점
| 경로 | 처리 |
|---|---|
| localStorage 쓰기 전체 | 부팅 시 메모리 Storage가 provider보다 먼저 설치되어 처음부터 메모리만 읽고 쓴다(S4 해소) |
| IndexedDB | 동기화 상태 없음 → 미접근. 테스트: 체험 중 `indexedDB.open` 0회 |
| 동기화 push/pull | `isCloudSyncEnabled()`에 `&& !isTrialMode()`(1줄, 이중 안전장치). 웰컴 "기존 동기화 자산 연결"은 체험 페이지에 웰컴이 없어 도달 불가 |
| 백그라운드 시세·환율·스냅샷 | `isBackgroundWorkBlocked()`에 `|| isTrialMode()`(initAndSync가 이를 거침 — asset-data-context 869) → 네트워크 0 |
| 외부 전송 API | **fetch 거부 래퍼**(게이트 ②에서 `window.fetch` 교체, 복구 없음): 같은 출처 pathname이 `/api/parse-screenshot`·`/api/share`·`/api/sync`·`/api/feedback`(또는 그 하위)면 네트워크 없이 합성 403 `{error: "체험 중에는 사용할 수 없어요"}` 반환 — 기존 호출처가 `data.error`를 토스트로 띄움. URL 해석 실패도 거부. 그 밖은 통과 |
| 외부 전송·등록 진입점(보조) | FAB, 하단 내비 update, 더보기(상단·하단) → 설정, 상단 설치 버튼(설치 흐름이 /api/share 사용) 숨김. 인증카드(로컬 PNG)는 유지 |
| 인앱 게이트(#60) | `resolveInAppGate`에 `isTrial` 입력, 체험이면 맨 앞에서 `none`(PIN 게이트가 체험을 덮고 예시 데이터를 /api/share로 올리는 경로 차단) |
| GA | `ga.ts`의 `track`·`trackScreen`·`setUserProps`가 `isTrialMode()`이면 no-op(체험 여부 1줄) + 루트 `layout.tsx` 헤드 인라인 GA 스크립트에서 `trial=1`이면 `ga-disable-<ID>=true`(gtag.js 자동 측정 차단, 1줄). 허용 목록 없음. 진입 이벤트는 이동 직전, 종료 이벤트는 복귀 페이지 |
| sessionStorage | 격리하지 않음(home-tip 세션 닫기·app-lock 세션 키). 체험 중 닫은 팁이 같은 탭 세션 동안 닫힌 채 남는 것은 알려진 한계 |
| 타 탭 `storage` 이벤트(S5) | 체험 탭은 `getAssetData()`로 메모리만 다시 읽음 — 무해, 테스트 1건 |

### 5.5 재사용
- 재사용: `materializeDemo`·`buildDemoRefreshMeta`·`stripDemoQuery` 패턴·`demo-data.json`·`applyDemoTutorialSkip` 로직(함수로 추출). PreviewGate는 preview 환경 전용이라 그대로 쓰지 않고 패턴만 재사용.

### 5.6 데이터 안전·알려진 한계
- 스키마·저장 키 무변경, 마이그레이션 없음. 구버전 혼재·롤백 영향 없음(체험은 메모리).
- S1 발생 시(교체가 일부만 적용) 실제 기기 데이터가 삭제될 수 있어 high. 검증 5종이 유일한 방어선 — 테스트에서 각 항목을 개별 모킹.
- **알려진 한계(C9)**: iOS Safari·WKWebView·삼성 브라우저에서 `defineProperty`가 실제로 동작하는지 실기기로 검증할 수 없다. fail-closed로 막히면 체험은 열리지 않고 일반 화면이 된다(데이터 무접촉).

## 6. 엣지 케이스
- 첫 사용자: 진입 가능(주 대상). 자산 보유 기기: 거부(5.3). 동기화 기기·잠금 기기: 거부.
- `#share`·`#sync` 해시 URL: 링크 숨김 + 게이트 거부.
- 오래된 데이터: `kstToday()` 재계산이라 항상 최신 월. 일부 갱신: 시세 갱신 차단이므로 변동 없음.
- 결산 창(11/27~12/10): 체험 중 `settlement_view` 미전송(GA 전면 끔). 4.38은 창 안에 머지 요청하지 않음.
- 뒤로 가기: 체험은 같은 페이지 내 view 전환이므로 브라우저 뒤로 = 앱 밖 이동(종료).
- 직접 입력한 `/?trial=1`도 같은 경로로 처리(진입 이벤트 없음 — 측정은 웰컴 경유분만).
- 다중 탭: 체험은 해당 탭 메모리만. 다른 탭 실제 저장소는 영향 없음.

## 10. 완료 기준 (qa 검사용)
1. 웰컴(자산 0건)에 "직접 둘러보기"가 있고 해시 URL에서는 없다.
2. **S1** 원본 `secretasset_*` 키·값 해시가 체험 진입·탐색·종료 후에도 불변이다.
3. **S1 모킹**: ①defineProperty 무시 ②전역 식별자 불일치 각각에서 `clearAssetData`가 원본에 호출되지 않고 체험이 열리지 않으며 원본 해시가 같다.
4. 원본에 자산 1건 / sync assetId / `secretasset_pwa_auth`가 있으면 `/?trial=1`이 일반 화면으로 열리고 원본이 변하지 않는다.
5. `?trial=1`이 없을 때 렌더 결과·첫 렌더 지연이 main과 같다(게이트 미동작, children 숨김 없음).
6. 체험 페이지에서 앱 코드의 gtag 호출 0건(`settlement_view`·`page_view`·`asset_count_bucket` 포함)이고 인라인 스크립트가 `trial=1`에서 `ga-disable-<ID>`를 켠다(정적 검사). 진입 이벤트 1건(이동 직전, 실제 페이지, 연타해도 1건)·종료 이벤트 1건(복귀 페이지).
7. 체험 중 `indexedDB.open` 0회, `/api/sync*`·`/api/share`·`/api/parse-screenshot`·`/api/feedback` **실제 네트워크 요청 0건**(스크린샷 탭에서 업로드해도 합성 403 + 토스트 "체험 중에는 사용할 수 없어요"), 무조작 탐색(홈·상세·성과·결산) 중 **자동 시세 갱신 0건**(`/api/finance?type=exchange|stock`·`/api/finance/crypto`·`/api/realestate`). 성과·결산 열람 시 `/api/finance/dividend`·`/api/finance/profit`·`/api/xray-classify` 예시 티커 조회는 허용. FAB·하단 update·더보기·설정·설치 버튼 없음, 인증카드는 있음.
8. "내 자산으로 시작" 후 `/`의 웰컴 CTA 슬롯이 asset 상태로 열리고 원본 저장소는 비어 있다. 새로고침 시 일반 웰컴.
9. 체험 결산 화면이 "기록 부족" 없이 월 결산·연 탭을 보여준다(LEARNINGS 2026-10: 작년 연도별 수동값 `@PY` 형태 포함).
10. 타 탭에서 실제 데이터를 수정해도 체험 탭·원본에 해가 없다(S5). 상세 행 편집이 메모리에서만 일어나고 새로고침 시 사라진다.
11. 기존 vitest 전체 통과 + 신규: 검증 5종, 거부 판정, fetch 래퍼, 메모리 Storage `Object.keys` 열거, GA no-op 테스트.
12. iOS 실기기 검증 불가는 qa-report에 알려진 한계로 명시.
13. fetch 래퍼: 거부 목록(문자열·URL·Request 입력, 쿼리 포함 `/api/sync?meta=1`)은 네트워크 호출 없이 403, `/api/finance`·다른 출처는 통과, 래퍼 미설치(검증 ⑤ 실패) 시 주입 0·원본 해시 동일(vitest).
14. 인앱 UA + 체험: 인앱 게이트가 렌더되지 않고(`resolveInAppGate` isTrial → none) 체험 홈이 보인다. 구버전 키(`secretasset-asset-data`)만 있는 원본·손상 JSON·`secretasset_sync`만 있는 원본도 거부되고 원본 바이트가 같다.
