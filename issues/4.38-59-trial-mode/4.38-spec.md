# #59 체험 모드 — spec (초안, challenge·tech-review 전)

문서 상태: planning ③ 선작성. 신규 문구는 모두 **[대표 동의 대기]**. 근거 코드는 issue-4.37.

## 1. 문제
- 첫 방문자는 등록 전에 "내 것이 되면 이런 화면"을 만질 수 없다. 웰컴 미리보기는 정적(`welcome-guide.tsx` ③⑤)이라 성과·결산을 볼 수 없다. GA: welcome_view 7기기 → onboarding_action 1기기 → first_asset_saved 0.

## 2. 목표 행동
- 웰컴 → "직접 둘러보기" → 결산/성과 1회 이상 열람 → "내 자산으로 시작" → 웰컴 CTA. 성공 기준(사업 절 확정 전 초안): 체험 진입 기기의 first_asset_saved율 > 미진입 기기(표본 작아 정성 병행).

## 3. 범위
포함/제외는 direction 2절. 새 URL·라우트 없음(`/` 안에서 상태로만).

## 4. 사용자 흐름
1. 웰컴(자산 0건, `isSharePending=false`)에서 ③ 라벨 행의 "직접 둘러보기" 탭. 공유/동기화 해시 진입 중이면 링크 숨김.
2. 진입 처리(순서 고정): ① 저장소 격리 설치 → ② 격리 검증 실패 시 중단 + 토스트(체험 불가, 아무것도 바뀌지 않음) → ③ GA 억제 켜기 → ④ `materializeDemo(demo-data, kstToday())` 주입 → ⑤ 튜토리얼 건너뛰기(`applyDemoTutorialSkip` 재사용, 격리 저장소에 기록) → ⑥ 홈 이동, `feature_use{category: demo}` 1회(억제 켜기 직전 허용).
3. 홈에서 상세·성과·결산 탐색(기존 화면 그대로). FAB·TopBar 더보기·설정 진입 숨김. 배너 상시 표시.
4. 종료 ①: 배너 "내 자산으로 시작" → `onboarding_action{method: trial_start}` → 격리 해제 → sessionStorage 플래그 `trial_exit=1` → `location.reload()`. 재로딩된 웰컴은 플래그를 읽어 `showAssetCta`와 동일한 상태(CTA 슬롯 asset)로 열고, `welcome_view`는 재전송하지 않으며 플래그를 지운다.
5. 종료 ②: 새로고침·탭 닫기 = 즉시 종료. 확인창(beforeunload) 없음.
6. 인앱 브라우저(#60): 4번의 "내 자산으로 시작"은 reload 대신 외부 이동(`go(origin)`)을 호출한다.

## 5. 저장 차단 설계 (핵심)
### 5.1 코드 사실
- 자산·설정 쓰기는 `localStorage.setItem/removeItem` 직접 호출이 ~27개 파일에 분산(asset-storage 13, asset-data-context 13, local-storage 13, one-time-migrations 14 등). 쓰기 지점을 하나씩 막는 방식은 누락이 확정적이다.
- IndexedDB는 `cloud-sync/device-key.ts`(동기화 "이 기기 기억"용 래핑 키)뿐. 동기화 상태(`secretasset_sync`)가 없으면 접근하지 않는다.
- 동기화 push는 `CloudSyncProvider`에서 `isCloudSyncEnabled()` && `status==="armed"`일 때만(armed는 sync-state의 assetId 필요). `ASSET_USER_EDIT_EVENT`가 push 트리거.
- 재사용 가능: `lib/preview/demo-payload.ts`의 `materializeDemo`·`buildDemoRefreshMeta`(순수 함수, 운영 번들에 이미 포함), `demo-data.json`(자산 12건+스냅샷, 동적 import), `applyDemoTutorialSkip`/`injectDemo` 로직(preview-gate.tsx 내부 — 함수로 추출해 공용화 필요). **재사용 불가**: `PreviewGate`(preview 환경 전용·쿼리 기반·실제 localStorage에 기록).

### 5.2 방식: 전역 localStorage 대체(메모리 Storage)
- 체험 진입 시 `window.localStorage`를 메모리 전용 `Storage` 구현으로 교체(`Object.defineProperty`). 원본 참조는 보관·종료 시 복구. 교체 이후의 모든 읽기/쓰기(설정·스냅샷·튜토리얼·환율 캐시 포함)가 자동으로 메모리에만 닿는다. 체험 시작 시점의 테마·GA 옵트아웃 키만 원본에서 복사한다.
- **fail-closed 검증**: 교체 직후 `setItem("__trial_probe","1")` 후 원본 Storage에 키가 없음을 확인. 실패하면 체험 시작 중단(브라우저가 교체를 막는 경우 대비 — iOS WKWebView·Safari 실기기 확인은 tech-review 필수).
- 새 파일 후보 `src/lib/trial/trial-mode.ts`: `enterTrial()`, `exitTrial()`, `isTrialMode()`(모듈 변수 + 구독). 상태는 메모리 전용이라 새로고침 시 자동 소멸.

### 5.3 차단 지점 (isTrialMode 단일 판정)
| 경로 | 처리 | 근거 |
|---|---|---|
| localStorage 쓰기 전체 | 5.2 교체로 격리 | 분산된 직접 호출 |
| IndexedDB | 동기화 상태 없음 → 미접근. 테스트: 체험 중 `indexedDB.open` 0회 | device-key.ts |
| 동기화 push/pull | `isCloudSyncEnabled()`에 `&& !isTrialMode()`; 웰컴 "기존 동기화 자산 연결" 체험 중 미노출 | config.ts 단일 지점 |
| 백그라운드 시세·환율·스냅샷·부동산 갱신 | `isBackgroundWorkBlocked()`에 `|| isTrialMode()` → 네트워크 0, 예시 값 고정 | background-gate.ts 단일 지점 |
| 공유 링크(/api/share)·피드백·스크린샷 파싱 | 진입점(더보기·FAB) 숨김으로 도달 불가 | tool-menu, FAB |
| GA | `ga.ts`의 `track`·`trackScreen`·`setUserProps`에 억제 플래그: 체험 중에는 허용 목록(`feature_use{demo}`, `onboarding_action{trial_start}`)만 전송. 결산 `settlement_view`·`ai_prompt`·`asset_count_bucket` 사용자 속성(6+로 오염)·`first_asset_saved` 차단 | ga.ts 단일 지점, #51 판독 보호 |
| 서버로 가는 자산 값 | 체험 데이터는 예시 값이며 어떤 요청 본문에도 담기지 않음 | — |

### 5.4 데이터 안전 (스키마·저장 키 무변경)
- 신규 저장 키·스키마 변경 없음, 마이그레이션 불필요. 체험은 원본 저장소를 읽지도 쓰지도 않으며(교체 후), 종료 시 원본은 진입 직전과 동일. 구버전 기기 혼재·롤백 영향 없음(체험 상태는 메모리).
- 위험 시나리오: 교체 복구 실패로 체험 데이터가 원본에 남는 경우 → 종료는 reload로 처리하여 코드 경로 단순화, 진입 전 원본 `secretasset_*` 키 스냅샷 해시를 개발 테스트에서 종료 후 비교.
- 예상 위험 등급(초안): medium(전역 객체 교체). cto 판정 대기.

## 6. 엣지 케이스
- 첫 사용자: 진입 가능(주 대상). 자산 1건 이상: 웰컴이 안 보이므로 진입 불가.
- 체험 중 앱 잠금·공유 해시 도착: 해시 포함 URL이면 링크 숨김. 체험 중 해시 변경은 무시.
- 오래된 데이터: `kstToday()` 기준 재계산이라 항상 최신 월로 보임.
- 일부 갱신: 시세 갱신 차단이므로 가격이 어제와 달라지는 일 없음. 예시 값은 "예시" 배지로 구분.
- 결산 창(11/27~12/10): 체험 중 settlement_view 미전송(5.3) — 창 안 머지는 피한다.
- 다중 탭: 체험은 한 탭 메모리. 다른 탭의 실제 저장소는 영향 없음.
- 뒤로 가기: 체험은 내부 view 상태이므로 브라우저 뒤로 = 앱 밖 이동(종료). 별도 처리 안 함.
- 데이터 가져오기 파일 input: 웰컴 CTA 슬롯은 체험 중 렌더되지 않음(홈 화면만 존재).

## 7. 정보 구조 — 지표(항목) 단위 전수 대조표
체험은 새 지표를 만들지 않고 기존 화면의 지표를 예시 값으로 보여준다.
| 지표/항목 | 정본 위치 | 체험 중 처리 |
|---|---|---|
| 순자산·증감 | 홈 Hero | 기존 화면 그대로(예시 값) |
| 자산 구성·손익 | 상세 탭 | 기존 화면 그대로 |
| 월 결산·기간 변화·배당·성적표 | 성과 | 기존 화면 그대로(GA만 억제) |
| 웰컴 정적 미리보기 순자산·주식 | 웰컴 ③⑤(`welcome-preview-data.json`) | 유지. 체험 데이터와 별개 소스이므로 숫자가 다름 → 라벨은 둘 다 "예시 데이터" 배지 유지 |
| "예시 데이터" 표기 | 웰컴 `PreviewLabel` 배지 | 체험은 상단 배너 1곳에서만 표기(화면별 중복 배지 금지) |

## 8. 지표(GA) — 사업 절 확정 전 초안
- `feature_use{category: demo}`(진입), `onboarding_action{method: trial_start}`(종료 후 시작). `PARAM_VALUES` 각 1줄 + 한국어 라벨. 맞춤 정의는 기존 차원 재사용(신규 등록 불필요).
- 체험 시간·화면 조회는 억제되므로 측정하지 않음(참여 시간 대리 지표 없음 — 한계 명시).

## 9. 구현 순서·충돌
- 웰컴 접촉 3이슈 충돌 지점: `welcome-guide.tsx`(#61 trust 줄·카드 문구 / #60 CTA 상태 `inapp` / #59 ③ 링크 + 종료 후 상태). **순서: #61 → #60 → #59**. 이유: #61 문구 전용(구조 불변)으로 분쟁 최소, #60이 `WelcomeCtaState`를 확장한 뒤 #59가 같은 타입의 종료 후 진입(`trial_exit`)과 인앱 분기(4-6)를 얹는다. 한 브랜치 `issue-4.38`에서 이슈별 커밋. `welcome-guide.test.tsx` 공유 → 이슈별 케이스를 별도 `describe`로 추가.
- 개발 가능 일정: 기획 11/1~11/7, 개발 11/8~11/21.

## 10. 완료 기준 (qa 검사용)
1. 웰컴(자산 0건)에 "직접 둘러보기"가 있고, 공유/동기화 해시 URL에서는 없다.
2. 진입 후 홈에 예시 자산이 보이고 배너 "내 자산으로 시작"이 항상 보인다. FAB·더보기·설정 진입이 없다.
3. 체험 중 `localStorage`의 `secretasset_*` 원본 키가 진입 전과 동일하다(키 목록·값 해시 비교).
4. 체험 중 `indexedDB.open` 호출 0회, `/api/sync*`·`/api/share`·`/api/finance*` 요청 0건.
5. 체험 중 gtag 호출은 `feature_use{demo}` 1건만(진입 시). 결산 화면을 열어도 `settlement_view`·`page_view` 미전송, 사용자 속성 `asset_count_bucket` 변경 없음.
6. "내 자산으로 시작" 후 웰컴 CTA 슬롯이 asset 상태로 열리고 `welcome_view`가 재전송되지 않는다. 원본 저장소는 비어 있다.
7. 새로고침 시 웰컴(자산 0건)으로 복귀, 체험 데이터 없음.
8. 격리 검증이 실패하는 환경 모킹에서 체험이 시작되지 않고 토스트가 뜬다.
9. 체험 결산 화면이 예시 데이터에서 "기록 부족" 없이 월 결산·연 탭을 보여준다(LEARNINGS 2026-10: 실제 사용자 형태 점검 — 예시 데이터는 작년 연도별 수동값 포함, `@PY`).
10. 기존 vitest 전체 통과 + 신규: trial-mode 격리 단위 테스트, GA 허용 목록 테스트.

## 11. 확인 필요 (tech-review 이관)
- `Object.defineProperty(window,"localStorage")`의 iOS Safari·Android WebView·삼성 브라우저 동작.
- 쓰기 진입점 숨김 범위: FAB·더보기 외 상세 탭 행 편집/삭제 버튼 존재 여부(읽기 전용 완전성).
- `initAndSync`가 `isBackgroundWorkBlocked`를 거치는지, 체험 데이터를 context에 주입하는 가장 작은 경로(import hook과 동일 경로 `bumpSnapshotVersion`+`initAndSync` 재사용 가능 여부).
- `profit-basis-store` 등 persist 스토어가 모듈 로드 시 원본 localStorage를 캡처하는지.
