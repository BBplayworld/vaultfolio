# #59 체험 모드 — tech-review

작성: developer, 2026-10-31. 기준 코드 issue-4.37 e4f27c6. 위험 등급 초안 **high**(cto와 같음). 방식 B(`/?trial=1` + provider 바깥 `TrialGate`)로 구현할 수 있다고 확인했다. 단, 아래 **C-1~C-4는 spec 보완이 필요하다**.

## 1. 구조 확인 (코드 근거)
- **layout**
  - 루트 `src/app/layout.tsx`에는 provider가 없다(`PreferencesStoreProvider`만 있음).
  - 실제 트리는 `src/app/(main)/layout.tsx`이며 구조는 `ReactQueryProvider > (isPreviewEnv ? PreviewGate : ·) > AssetDataProvider > CloudSync > Navigation > Tutorial > … InAppBrowserGate`이다.
  - `TrialGate`는 **PreviewGate 바깥**에 둔다: `<ReactQueryProvider><TrialGate>{preview분기}</TrialGate></ReactQueryProvider>`.
  - 이유: PreviewGate가 데모를 주입한 메모리를 읽어야 0건 선택 카드가 뜨지 않는다.
- **provider 바깥 주입은 가능하다.** PreviewGate가 이미 `applyImportedPayload`·`tutorialStore.initTutorial`을 provider 바깥에서 하고, children 렌더를 늦춘다.
  - `AssetDataProvider`는 `useState(STATIC_DEFAULT)` 뒤 effect에서 저장소를 읽는다(296~306행).
  - 그래서 children을 주입 뒤에 마운트하면 처음부터 메모리만 읽는다.
  - React effect는 자식이 먼저 실행된다. 따라서 "TrialGate effect에서 설치 + children 동시 렌더"는 **불가**하고, 쿼리가 있을 때는 반드시 children을 보류해야 한다.
- **SSR 일관성**
  - 쿼리가 있을 때만 보류하려면 서버도 쿼리를 알아야 한다.
  - `(main)/layout`이 `cookies()`를 써서 동적 렌더이므로 `TrialGate`가 `useSearchParams()`로 SSR·hydration 결과를 맞출 수 있다고 판단한다(**미확정 U1**, 빌드로 확인).
  - `stripQuery`(replaceState) 뒤 Next가 searchParams를 동기화하므로 판정은 마운트 시 1회 고정한다(state 래치).
- **모듈 로드 시 localStorage 캡처**: 0건(cto grep 결과와 같음). zustand persist도 0건이다.

## 3. spec 보완 필요 (C-1~C-4)
- **C-1 외부 전송 진입점 누락**
  - 상세 탭의 추가·편집(`stock-tab`·`crypto-tab`·`cash-tab`·`loan-tab`·거래 뷰가 `dispatchAdd*` 호출)이 여는 입력 다이얼로그 안에 스크린샷 탭이 있어 `/api/parse-screenshot`(Gemini)에 닿을 수 있다.
  - 한도 문제: 클라 한도 15회/일은 localStorage(`secretasset_gemini_usage`) 기반이다. 체험 메모리에서는 0으로 시작하므로, 체험 진입을 반복하면 서버 **전역 300회/일**(`cache-storage.ts:131`, 전 사용자 공용)을 소진할 수 있다.
  - 권고: `TrialGate`가 체험 중에만 `window.fetch`를 감싸 `/api/parse-screenshot`·`/api/share`·`/api/sync*`·피드백을 거부한다. 수정은 1곳이고 fail-closed다. 화면 숨김(FAB 등)은 보조로 둔다.
  - 거부 시 오류 토스트 문구는 ui-designer가 정한다.
- **C-2 인앱 + 체험 충돌**: 체험 메모리는 자산이 1건 이상이다. 그래서 #60 게이트가 **PIN 게이트를 덮고**, PIN 이동 시 `generateShareArtifacts`가 예시 데이터를 `/api/share`로 올린다. 게이트에 `!isTrialMode()`를 넣는 것이 필수다.
- **C-3 완료 기준 7과 사실의 불일치**
  - 성과·결산 화면은 사용자 탐색 시 `/api/finance/dividend`(performance-hub 23, dividend-chart 56, monthly-dividend-stocks 32), `/api/finance/profit`(profit-utils 361), `/api/xray-classify`를 직접 호출한다. `isBackgroundWorkBlocked`를 거치지 않는다.
  - 차단하면 "결산·성과 화면 코드 무수정" 원칙과 화면 품질이 깨진다.
  - 권고: `/api/finance*`·`xray-classify`는 **예시 티커 시세 조회라 허용**한다(사용자 자산 아님). 기준 7은 "`/api/sync*`·`/api/share`·`/api/parse-screenshot` 0건, 자동 시세 갱신 0건"으로 고친다. cto 판정이 필요하다.
- **C-4 거부 판정은 읽기 전용**
  - `getAssetData()`는 구버전 데이터를 만나면 **원본에 마이그레이션 쓰기**를 한다(asset-storage 78~85 nickname, 88~ 거래소 라벨).
  - 거부 판정은 `getItem` + `JSON.parse` + `hasAnyAssets`로만 한다. 파싱 실패는 거부(fail-closed)다.
  - `pwa_auth`는 실제 키가 `secretasset_pwa_auth_enabled`·`_pin_hash`(app-lock.ts 8~9)이므로 prefix로 판정한다.
  - probe 키는 검증 직후 원본·메모리 양쪽에서 제거한다. 새면 원본에서 지운 뒤 거부한다.

## 6. 테스트 계획 (vitest node 환경, jsdom 없음)
- **하네스**
  - `vi.stubGlobal("window", win)`·`vi.stubGlobal("localStorage", orig)`를 쓴다. 기존 preview-safety 10번 패턴과 같다.
  - 원본 Storage 가짜 객체는 own 열거 키를 가진 클래스로 만든다.
  - 원본 해시는 정렬된 `[k, v]` JSON으로 계산한다.
  - Node 22 기준이며, Node 25 이상은 전역 `localStorage`가 존재하므로 항상 명시적으로 stub한다.
- **S1 모킹**
  - ① `win`에 `localStorage`를 `configurable:false` getter로 정의하면 defineProperty가 throw하거나 무시된다.
  - ② `win`≠globalThis이면 `window.localStorage===mem`이지만 전역 식별자는 원본을 가리킨다.
  - ③ 원본 probe 누출
  - ④ `Object.keys` 미열거 mem
  - 네 경우 모두 `inject` spy 0회, `clearAssetData`가 원본을 건드리지 않음, 원본 해시 동일, `isTrialMode()=false`를 확인한다.
- **정상 경로**: 실제 `materializeDemo`(fs로 demo JSON 읽기) + `applyImportedPayload`를 메모리 대상으로 실행한다. 원본 해시가 같고, 메모리 `assetDataSchema`가 통과하고, `@PY` 연도값이 있어야 한다.
- **거부 판정**: 자산 1건 / `secretasset_sync.assetId` / `secretasset_pwa_auth_enabled` / `#share=`·`#sync=` 해시 / 손상 JSON. 각각 설치 0, 원본 불변이어야 한다.
- **기존 사용자 불변**
  - 구버전 형태 fixture(legacy `secretasset_nickname` + 영문 거래소 코인 + 자산 1건)로 `/?trial=1` 거부 경로를 실행한다.
  - 원본 바이트가 동일해야 한다. `getAssetData` 마이그레이션 쓰기가 일어나지 않는다는 회귀 테스트다.
- **GA**: `setTrialMode(true)`에서 `track`·`trackScreen`·`setUserProps`가 gtag stub 0회(ga.test 패턴). `trackThenNavigate`는 callback 또는 타임아웃 뒤에 이동하고, gtag가 없으면 즉시 이동한다.
- **가드**: 체험 중 `isCloudSyncEnabled()=false`, `isBackgroundWorkBlocked()=true`. 기존 매트릭스(2번)는 trial=false에서 그대로다.
- **fetch 래퍼**(C-1): 거부 목록은 reject, `/api/finance`는 통과
- **쿼리 없음**: `renderToStaticMarkup(<TrialGate>x</TrialGate>)`가 x와 같아야 한다. trial-boot는 정적 import 0건이어야 한다(grep).
- **S5**: 메모리 설치 상태에서 `storage` 이벤트 핸들러가 `getAssetData()`로 메모리만 읽는다(asset-data-context 1024 경로를 grep과 단위로 확인).

## 8. 위험·미확정
- **U1**: `useSearchParams` SSR 일관성(Next 16.4, 동적 layout). 안 되면 대안은 인라인 head 스크립트로 `html[data-trial]`을 표시하고 게이트가 읽는 방식이다. 이 경우 hydration 경고 처리를 검토해야 한다.
- **U2**: iOS에서 `window.localStorage` defineProperty와 전역 식별자 해석은 실기기로 확인할 수 없다.
- **U3**: 인앱 체험 종료 시 외부 이동 경로
  - `trial_exit`(sessionStorage)가 외부 브라우저로 넘어가지 않아 `trial_start`가 집계되지 않는다.
  - 이동 이벤트 `pwa_install inapp_move`도 체험 중 GA가 꺼져 있어 빠진다.
  - 인앱 체험 전환은 측정할 수 없다(한계로 기록).
- **U4**: 일반 방문자 영향. 게이트 셸과 `useSearchParams`가 쿼리 없는 첫 렌더를 바꾸지 않는지 qa가 main preview와 비교한다(완료 기준 5).
- sessionStorage 미격리(팁 닫힘 지속)는 알려진 한계이며 spec과 같다.
- 일정: 테스트 분량상 11/13~11/21이 빠듯하다. C-1(fetch 래퍼)을 넣어도 +0.5일 이내로 본다.
