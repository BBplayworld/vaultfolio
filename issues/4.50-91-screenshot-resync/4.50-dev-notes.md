## 3. preview에서 확인할 경로와 시나리오
경로: `?demo=1` → FAB → 보유 현황 업데이트 → 주식(또는 코인) → 스크린샷. 데모 증권사 `데모증권`은 목록 밖이라 ②(기존 항목 과반)로 확정되거나 장마다 1회 선택하는 경로가 함께 보인다.
1. 제목 `스크린샷으로 보유 현황 맞추기`, `덮어쓰기`·`초기화 후 등록` 없음. 보유 0건(데이터 비운 뒤)이면 기존 첫 등록 대화상자.
2. 합성 잔고 이미지 2~3장(qa가 데모 보유에 맞춰 제작, 실캡처 금지) 선택 → 6장 선택 시 5장만 + 토스트. 장별 상태·남은 횟수 `1장에 인식 1회 · 오늘 N회 남음`.
3. 증권사 미확정 장 Select 1회 선택 → `변경 내용 보기` → 요약 1줄, 변경 행 전→후, 삭제 후보 기본 체크(실패·잘림 장이 있으면 전부 해제), 유지 묶음 접힘, 고지 2줄.
4. `맞추기` → 결과 화면 `되돌리기` → 복원. 닫은 직후 토스트 `되돌리기`.
5. 국내 탭만 올린 경우 같은 증권사 해외·ISA 항목이 유지 묶음에 있는지, 같은 종목 두 증권사 중 한 곳만 바뀌는지.
6. 320·375·1280 라이트·다크.

## 4. ui.md·spec과 구현 차이 (ui-designer 검수에서 확인)
- 남은 횟수 문구: spec `1장에 인식 1회 · 오늘 N회 남음` 채택(ui.md `오늘 AI 인식 N회 남음` 대신).
- 결산 고지 2줄째: spec 원문 `바뀐 수량·평단은 이번 달 결산에 주식 매수·매도로 잡혀요`(마침표 없음, 코인은 `코인 매수·매도`). ui.md 문구보다 spec 우선.
- 평단: 화면 실값(`averagePriceEstimated=false`)이면 `평단 a → b` 표시·변경, 역산이면 기존 유지(1% 넘을 때만 `평단은 화면에 없어 기존 값 유지`). ui.md의 `평단 변경 미표시`보다 spec 우선.
- sticky 묶음 헤더 생략(v1). 묶음 안 `확인 필요`는 별도 묶음 한 곳에 모음(spec 5절 순서: 변경·추가 → 확인 필요 → 삭제 후보 → 접힌 유지 → 접힌 그대로).
- 인식 횟수 차감 시점: 응답을 받은 호출(ok 또는 422)에 차감. 서버가 실패도 차감하는 점을 남은 횟수에 반영(기존 컴포넌트는 성공 시에만 차감).
- 합성 failed 장: `빼기`로 실패 장을 제거해도 삭제 기본 해제를 유지하려고 `index:-1` failed 장을 계산에만 추가한다(UI 표시 없음).
- 증권사 Select 목록: 기존 보유 broker 값(자유 텍스트 포함) 먼저, 이어서 증권사 목록(코인은 거래소 목록 라벨). 국내 계좌 Select는 국내 종목이 있는 장에만(코인은 없음).
- 되돌리기 토스트는 해당 맞추기의 사본을 직접 붙잡는다(대화상자를 다시 열어도 다른 맞추기를 되돌리지 않음). 새 맞추기 적용 시 이전 토스트를 닫는다.
- 확인 필요 칸 입력: 수량 미인식은 수량 입력, 수량 충돌(K1)은 입력 칸 + 두 값 보조 문구(탭 전환 대신 항상 입력 표시), 후보 2건은 Select, 티커 미인식은 티커 입력.
- **새 문구 1건(ui-designer 확정 요청)**: 수량 미인식 행 사유 `수량을 읽지 못했어요`. spec 6절에 사유 원문이 없어 임시로 정했다.
- 코인: 문구만 증권사→거래소, 주식→코인. 달러 화면은 기존 가져오기처럼 오늘 환율로 원화 환산 후 비교.

## 5. 알려진 한계
- 화면에 평단·매입 환율이 없으면 기존 값 유지(완전 동일해지지 않음). 신규 해외 종목 매입 환율은 일괄 값(기본 오늘 환율).
- 거래 기록은 만들지도 지우지도 않음: 삭제 종목의 거래는 계산에 남고 거래 화면에는 안 보임. 양도세는 매도 기록이 따로 필요.
- 되돌리기는 결과 화면·닫은 직후 토스트까지. 이후 복구는 백업뿐. 되돌리기 push가 409이면 기존 경로로 클라우드가 이긴다.
- `rollbackTransaction`(`deriveBaseSnapshot`)의 음수 기준 0 절단(100→60 후 매수 100 삭제 시 보유 0·평단 0)은 `updateStock`과 같은 기존 현상. vitest로 현상 고정, 근본 수정은 후속 이슈 후보.
- 수량 비교 허용오차 1e-6(코인 초소수 수량은 같은 값으로 볼 수 있음).
- preview는 동기화 쓰기가 꺼져 있어 전파·#84 알림은 vitest S8 하네스로만 검증됨.

## 6. UI 검수 반영 (4.50-ui-review.md, 커밋 UI 보정)
- P0: NeedsRow `맞추기에 포함` 체크박스에 `relative` 추가(::after가 대화상자 전체를 덮어 푸터 `맞추기`를 가로채던 문제). `after:absolute`를 쓰는 요소 전수 점검(CheckRow·썸네일 빼기 버튼은 이미 위치 기준 있음) + 정적 회귀 테스트(`after:absolute`가 있는 className은 relative/absolute 필수, `resync-sync.test.ts`).
- ②유지 묶음 제목 `스크린샷에 없는 다른 증권사·미지정·비상장 종목 N개`(코인 `다른 거래소·미지정`). ③푸터 문구 `text-pretty break-keep`, 고지의 `손익·세금`·`매수·매도`·`{주식|코인} 매수·매도` nowrap. ④캡션 `종목 N개`, 일부만 인식됨은 두 줄 분리. ⑤거래정지·상장폐지 후보 행 `resync-inactive-note-{id}`. ⑥삭제 해제 이유 2종(미리보기: 증권사/거래소 못 정한 장, 업로드: `resync-incomplete-note`). ⑦토스트 액션 `actionButtonStyle minHeight 40`. ⑧brokerFill이 있으면 연결 줄 생략. ⑨스크롤 중에만 헤더 `border-b border-border/40`. ⑩썸네일 번호 배지. ⑪묶음 마지막 행 `last:pb-0`. ⑫결과 요약은 `summaryParts` 재사용.
- 승인 유지: 수량 사유 문구, 남은 횟수 문구, 결산 고지 마침표 없음, sticky 헤더 생략, 푸터 h-9.
- 정적 테스트의 주석 제거 정규식이 `accept="image/*"`를 블록 주석으로 오인해 코드 일부를 가리던 문제도 함께 수정(공백·`{` 뒤 `/*`만 주석 취급).

## 8. qa FAIL D1·D2 수정
- D1: `doUndo(u, fromToast)`를 명시 인자로 바꿔 토스트 경로가 닫힌 대화상자 상태(`undoInfo`·`undoing`)를 건드리지 않게 했고, `handleApply` 시작 시 `undoInfo`·`undoing`을 초기화한다. 정적 회귀 테스트로 고정.
- D2: `NeedsRow`에 `증권사 미지정 → ○○`(brokerFill)와 `증권사 미지정 줄과 연결`을 둘 다 표시(변경 행 `ItemRow`는 중복이라 화살표만). 수량 감소 연결 행의 brokerFill 값을 vitest에 추가.
- 기록 사항: 코인 수량 충돌 단위 `주`→`개`(코인), 티커 미인식 확인 필요 행 사유 `티커를 읽지 못했어요`(새 문구 1건, ui-designer 확인 필요), 320px 상태 문구 돌출은 썸네일 칸 `min-w-0` + `overflow-wrap:anywhere`로 방지. 잘림 문구 두 줄 분리는 UI 검수 승인된 형태 유지.
