## 2. 공통 표시 자리 — 실측과 제약
- 현행 배너: 390·320 모두 top 68·높이 122px(버튼 40px). 홈 밖은 0개(실측). 브라우저에서는 하단 탭이 `display:none`(PWA 전용), FAB는 체험 중 미렌더.
- ★ **세금 관리는 들어서는 순간 '이번 달'로 자동 스크롤된다**(`tax-calendar-view.tsx:53~55`, 실측 scrollY 약 2,000). page 상단 in-flow로 두면 이 화면에서는 도착 직후 표시가 화면 밖 → AC-1 불충족. 세금 화면은 자체 `sticky top-0 z-10`(+시뮬레이터 `top-28`)도 있다.
- 선택지(ui-designer 결정, 화면별 예외 코드 0 조건):
  - **A. 상단 sticky(권장)**: page.tsx 한 곳, 자리를 차지하므로 하단 탭·토스트·맨 위로 버튼과 구조상 겹치지 않는다. 비용 = 세금 화면 sticky 2곳을 CSS 변수 오프셋(`top-[var(--trial-bar-h,0px)]`)으로. 비체험은 계산값 같지만 class 문자열이 바뀐다(세금 화면 마크업 diff 1토큰 — AC-9의 웰컴·홈 범위 밖). z는 `Z_LAYER.raised(20)`~`floating(40)`: 대화상자(10001) 뒤. PWA는 `top: env(safe-area-inset-top)` 필요(노치 아래), 허브에서 `[data-content-area]` 상단 패딩과 이중 여백 확인.
  - B. 하단 fixed: **토스트와 겹친다**(Toaster는 루트 `layout.tsx:177` — 오프셋을 바꾸려면 수정 금지 파일). PWA는 하단 탭 높이(safe-area 포함 가변) 위로 계산, 세금 화면 맨 위로 버튼(`bottom-18`), 본문 하단 패딩 추가 필요. **비권장**.
  - C. in-flow 그대로: 코드 최소지만 세금 화면이 AC-1 예외가 된다(예외를 spec에 명시해야 함).
- 인앱 iOS 안내 펼침: 배너 안에서 아래로 펼쳐진다. sticky면 펼친 높이가 320×568에서 화면 대부분을 덮을 수 있음 → ui.md에 최대 높이·닫힘 방법 명시 필요. `data-screenshot-hide`는 현행 속성 유지로 충분.
- 체험 중 자산 0건(예시를 다 지움)은 웰컴 분기라 표시 없음(spec 7-3 그대로, 코드 0).

## 3. 전달값 (`trial_exit` + `trial_exit_from`)
- **`trial-boot.ts`는 sessionStorage를 교체하지 않는다(확정)**: 교체는 `Object.defineProperty(win, "localStorage")`와 `win.fetch` 2건뿐(`:190~191`), 파일 전체에 sessionStorage 0회. 실측: 체험 중 `localStorage`는 메모리 객체, `sessionStorage`는 원본 `[object Storage]`. 종료 누름 → `/` 복귀 → `trial_exit` 소비 후 삭제까지 현행 동작 확인. 주입부 변경 불필요.
- 쓰기: 한 try 안에서 둘째 키 → `trial_exit` 순(둘째만 남는 경우는 읽는 쪽이 지움). 읽기: `trial_exit === "1"`일 때만 둘째 값을 읽고 두 키 삭제, 아니면 둘째 키만 삭제. 전부 try/catch → 실패는 현행.
- 순수 함수는 **`Map` 또는 `Object.hasOwn`으로 대조**(`"constructor"`·`"__proto__"` 같은 값이 통과하지 않게 — 테스트 케이스로 고정). 값은 `viewToKey`가 만드는 고정 문자열 15종뿐, 자산 데이터 0.
- 옛 번들 혼재: 옛 웰컴은 `"1"`만 읽어 현행 복귀, 남은 둘째 키는 탭을 닫으면 사라진다. revert도 같다. `STORAGE_KEYS`·백업·동기화·스냅샷 영향 0 → 마이그레이션 없음.
- ★ **spec 3-1-5 정정**: 복귀 뒤 마법사를 열었다 닫으면 `WelcomeGuide`가 재마운트된다(`page.tsx:88` 마법사 분기가 웰컴을 대체). 표식은 이미 소비됐으므로 **닫은 뒤는 일반 웰컴**이다(`welcome_view`도 현행대로 다시 1건). 유지하려면 모듈 메모리가 더 필요 → 넣지 않기를 제안.

## 4. 등록 칸·마법사
- 실측(새 기기, preview): 스크린샷 버튼 → 곧바로 `주식 스크린샷 업로드`(인트로 없음, 전송 0) — CEO 정정과 일치. 팝오버를 열면 첫 포커스는 지금도 첫 행(`부동산`), 터치에서는 `:focus-visible`이 false라 **포커스만으로는 보이지 않는다** → '짚는 표시'는 포커스 링이 아니라 별도 속성(`data-*` + 기존 `bg-accent` 토큰)으로 그려야 한다. 포커스 이동은 `PopoverContent onOpenAutoFocus`에서 `preventDefault` 후 해당 행 `focus()`.
- 시작 단계: store 인자 1개로 충분(조건 2 통과). `resolveWizardStart` = 시작값이 pending이면 그 단계, 아니면 `getResumeCategory(status) ?? "intro"`. `close()`에서 초기화. 여는 순간 `wizard_step` 0건(start는 인트로 버튼에만 있음 — 무변경).
- `goToNextCategory`는 뒤쪽 단계만 본다 → 앞 단계는 pending으로 남는다(코드 그대로, 변경 0).
- ★ **AC-16 정정**: '현금 저장 뒤 닫고 다시 열면 주식에서 재개'는 화면으로 재현할 수 없다 — 저장하면 자산이 생겨 웰컴이 사라지고, 마법사를 여는 곳은 웰컴 등록 칸 1곳뿐이다(`open()` 호출처 전수). 화면 검사는 '현금 단계에서 `이 카테고리는 없어요` → 대출 → 닫기 → 다시 열면 주식'으로, 저장 경로는 단위 테스트로만.
- 부동산 상태의 variant 맞바꿈·포커스는 prop 1개 분기. 값 없음일 때 마크업이 현행과 같아야 한다(6절 스냅샷).

## 5. GA
- 전송은 복귀한 웰컴의 mount effect 1곳: 기존 `track("onboarding_action", { method: "trial_start" })` 뒤에 꼬리가 있을 때만 1건 더. 그 페이지는 `?trial=1`이 없고 `isTrialMode()`가 false인 실제 페이지다. 체험 페이지의 버튼은 `track`을 부르지 않고, 인앱 분기의 `useExternalMove` 계측은 체험 가드로 no-op.
- `ga.ts`: `case "onboarding_action"`에 `method === "trial_start"`일 때 `asset_type`(기존 `ASSET_TYPE_TITLES` 6값) 또는 `source`(`detail` 기존값 → `·상세`, **`activity` 신규 1값** → `·성과`)로 꼬리를 붙이는 갈래 1개. 다른 method는 `asset_type`을 넘기지 않으므로 영향 0. `trial-guards.test`의 '체험 GA 값' 검사는 꼬리 없는 호출이라 무수정 통과, 정적 검사 5건도 대상 줄 무변경.
- 나가는 값 증가: title 고정 문자열 8종뿐. 자산 0건 기기가 '예시의 어느 화면에서 나왔나'만 담겨 보유 정보 역산 불가.
