# 4.42 #70 공식적 UI 고도화 — UI 사양 (ui-designer)

근거: 승인 계획 `gentle-scribbling-dream.md`, design-system.md §0~§7·§11, 현재 코드. 대표 결정: 시스템 글꼴 / 토스에 더 가깝게 / 별도 버전 preview 데모 후 대표가 반영 여부 결정. 신규 라이브러리 없음.

## 0. 사전 발견 (문서-코드 드리프트, 이번에 함께 바로잡음)
- design-system §3.3은 라이트 `--background`를 `oklch 0.91`이라 적었으나 **코드는 `0.96`**, 카드 radius도 문서 lg / 코드 xl, 다이얼로그 문서 2xl / 코드 `rounded-lg`. 이번 작업 후 문서를 코드 수치로 고정(§9).
- **라이트 톤차는 이번에 바뀌지 않는다**: 캔버스 L 0.96 유지, muted .88·secondary .895·accent .905 유지. 즉 박스 구분력의 손실은 "테두리·그림자 제거"에서만 생긴다(§8 점검 대상).
- `--border`를 .65 -> .91로 낮추면 **`border-border/NN`(28곳) 라이트 선이 사라진다**. 일괄 치환 규칙 필요(§3-1 표 아래). 다크는 `--border: white/10` pin이라 불변.
- 그라데이션은 계획의 6곳 외에 **FAB 상단 페이드(`floating-add-button.tsx:171`)가 1곳 더** 있다(총 7곳). `investor-avatar.tsx` radial-gradient는 인증카드 일러스트라 제외.

`border-border/NN` 라이트 치환 규칙(구 선 밝기와 동치 계산: 구 .65 기준 alpha a -> 신 .91 기준 alpha 3.5a):
- 구 `/30~/60`(보이던 선: 구분선·`divide`·`bg-border/40` 헤어라인) -> **`border-border`(풀 알파)** + 다크는 기존 값 유지를 위해 `dark:border-border/NN` 쌍으로 적는다(다크에서 풀 알파는 두 배 진해지므로 반드시 쌍). 예 `border-border/50` -> `border-border dark:border-border/50`.
- 구 `/10`(거의 안 보이던 박스 외곽선) -> **삭제**(+ 짝인 `dark:border-0`도 삭제). 해당 8곳이 SECTION·ROW·KpiCard·`subCard`·`cardExpandBox` 등.
- 총 28곳은 `grep -rn "border-border/" src` 로 개발자가 일괄 처리하고, 치환 목록을 dev-notes에 남긴다.

## 4. 박스 패턴 (테두리·그림자 제거 -> 톤차)
- **SECTION** (`layout/ui/report-section.tsx:8`): `rounded-xl bg-card border border-border/10 dark:border-0 shadow-sm p-4 space-y-3` -> `rounded-xl bg-card p-4 space-y-3 dark:shadow-sm`.
- **SectionHeader 칩 제거**: `<span className="flex size-7 ... rounded-lg ${SECTION_TONE[tone]}"><Icon className="size-4"/></span>` -> `<Icon aria-hidden className={`size-5 shrink-0 ${SECTION_TONE[tone]}`} />`. `SECTION_TONE`을 글자색만으로: brand `text-primary` · important `text-orange-600 dark:text-orange-400` · gold `text-amber-600 dark:text-amber-400` · info `text-sky-600 dark:text-sky-400` (기존 4색 팔레트 재사용, 신규 색 없음). 제목 `text-sm sm:text-base font-bold text-foreground` 불변. (다크도 칩 배경이 사라진다 — 의도된 공통 변경.)
- **ROW** (`settings-page.tsx:188`, `tool-menu.tsx:190` 동일 문자열 2곳): `... rounded-xl bg-card border border-border/10 dark:border-0 shadow-xs hover:bg-accent ...` -> `... rounded-xl bg-card dark:shadow-xs hover:bg-accent ...` (두 곳 같은 변경. 상수 공용화는 범위 밖, 후속 후보로만 기록).
- **KpiCard** (`kpi-card.tsx`): Card className `... shadow-xs border border-border/10 dark:border-0` -> `... dark:shadow-xs dark:border-0`. 아이콘 칩 `size-9 sm:size-10 rounded-full bg-primary/10 text-primary flex ...` -> `size-6 shrink-0 text-primary mt-0.5`(칩 없는 단색 24px; 행 `gap-3` 유지). 텍스트 폭이 36~40px 늘어 줄바꿈이 줄어든다.
- **ASSET_THEME** (`config/theme.ts`):
  - `cardWrapper` `rounded-lg overflow-hidden border-0 bg-transparent` — 불변(12px로 자동).
  - `subCard` `rounded-md overflow-hidden bg-transparent border border-border/10 dark:border-border/60` -> `rounded-lg overflow-hidden bg-card dark:bg-transparent dark:border dark:border-border/60` (라이트는 캔버스 위 흰 카드 = 톤차 분리, 다크 현행).
  - `cardExpandBox` `divide-y divide-border/10 dark:divide-border/50 border-t border-border/10 dark:border-t` -> `divide-y divide-border dark:divide-border/50 border-t border-border dark:border-t` (헤어라인으로 읽히는 구분선은 유지; 위 치환 규칙).
  - `tabList1`·`tabList3Wrap`의 `border border-border`는 segmented 트랙(기능성 허용) — 새 헤어라인으로 자동 가벼워짐, 클래스 불변.
  - `liabilityBadge`·`cardLoanItem`의 의미색 `border-rose-200/30` 류는 이번 범위 밖(불변).
  - `summaryHeader` `rounded-lg`, `categoryBox` `rounded` 등 radius는 토큰 자동 반영.

## 5. 잠금 화면 (`pwa/pwa-lock-screen.tsx`)
**루트**: `fixed inset-0 bg-background flex flex-col items-center justify-center gap-5 px-6` -> `... justify-center gap-8 px-6 pb-8 overflow-y-auto` (pb-8로 시각 중심을 살짝 위로, 낮은 화면 스크롤 허용). z=Z_LAYER.lock 불변.
**헤더 블록** `flex flex-col items-center gap-3` 유지:
- 칩 div + `ShieldCheck` 삭제 -> `<Lock aria-hidden className="size-8 text-foreground" strokeWidth={1.75} />` (lucide `Lock`, 32px, 칩·배경·그림자 없음). `ShieldCheck`·`MAIN_PALETTE` import 정리(lint).
- `h1` `text-lg font-bold` "시크릿에셋" 불변, `p` `text-sm text-muted-foreground` "비밀번호를 입력해주세요" 불변. 아이콘-제목 12, 제목-부제 12(현행).
**PIN 도트**: 위치는 헤더 아래 gap-8 (32px). 크기 `size-3.5`(14px 원) 유지, 간격 `gap-3` -> `gap-4`. 채움 `bg-foreground` / 빈 `bg-muted-foreground/30` 유지, 전환 없음(즉시 반응) 유지. `role="status" aria-label="N자리 입력됨"` 유지.
**오류 문구 슬롯(레이아웃 점프 방지)**: 도트 바로 아래에 항상 마운트되는 `<div className="min-h-5 -mt-4 flex items-center justify-center" role="alert" aria-live="polite">`(root gap-8 중 도트-슬롯 간격을 -mt-4로 16px로 축소) 안에서 기존 두 문구를 조건 렌더. failCount 1~2: `text-sm text-muted-foreground` "비밀번호가 일치하지 않습니다"; failCount>=3: `text-sm text-amber-600 dark:text-amber-400` + `AlertTriangle size-3.5` "비밀번호를 다시 확인해주세요" (문구·조건 불변, 위치만 키패드 아래 -> 도트 아래).
**키패드(모바일)**: 컨테이너 `grid grid-cols-3 gap-x-5 gap-y-2 w-fit` (키 72px: 가로 3x72+2x20=256px, 세로 4x72+3x8=312px; 320px 화면 여백 32px 이상). 각 `KeypadKey`:
- 전 `Button variant="secondary"|"ghost" ... h-14 text-xl font-semibold` -> `Button variant="ghost" static` + `h-[72px] w-[72px] rounded-full bg-transparent text-2xl font-medium tabular-nums hover:bg-transparent active:bg-muted transition-[background-color] duration-50 select-none touch-none`. 테두리·배경 없음; **눌렀을 때만** `bg-muted` 원형 하이라이트(라이트 .88 vs 캔버스 .96, 다크 .269 vs .145 — 모두 식별 가능). `static`으로 scale 제거(하이라이트와 이중 피드백 방지), hover 제거(터치 sticky hover 방지). `focus-visible` 링은 Button base 그대로(키보드/보조기기 포커스 가시).
- 삭제 키: `Delete` 아이콘 `size-5` -> `size-6`, `text-foreground`, 같은 72px 원.
- 빈 칸 `<span />` -> `<span aria-hidden className="size-[72px]" />`.
- 낮은 화면(`[@media(max-height:620px)]`): 키 `size-16`(64px), root `gap-5`로 축소. 높이 예산(667px 기준): 헤더 104 + 32 + 도트 14 + 슬롯 20 + 32 + 키패드 312 = 514px -> 여유 충분.
- 접근성: `aria-label` "숫자 N"·"한 자리 지우기" 유지, 키패드 컨테이너에 `role="group" aria-label="비밀번호 숫자 키패드"` 추가, 히트영역 72px(>=40), 물리 키보드 입력 로직 불변, `pointerdown` 즉시 발화 로직 불변, `checking` 시 `pointer-events-none opacity-60` 유지.
**PC 분기(isPC)**: 네이티브 `Input` 유지(`type=password inputMode=numeric autoFocus maxLength` 불변). 클래스 `w-40 text-center text-2xl tracking-[0.6em] tabular-nums dark:border dark:border-ring` -> `h-12 w-48 rounded-xl ...` 나머지 동일(큰 입력칸으로 키패드 없는 대신 존재감 확보). 도트·오류 슬롯·헤더는 모바일과 공유.

## 8. 라이트에서 박스 구분이 약해지는 곳 점검 규칙
1. 카드(흰) vs 캔버스(#F0F2F4): 상대 대비 **>= 1.10:1** (현재 1.123 유지). 캔버스 위 박스에 `bg-transparent`+테두리만 쓰던 곳은 `bg-card`로 전환(`subCard`).
2. 중첩 박스(부모 -> 자식) 톤차 **>= 1.08:1**: 흰 부모 위 최소 `bg-muted/30`(L .964), 캔버스 위 최소 `bg-muted/50`. `bg-muted/20`·`/10`은 흰 부모에서 구분 불가 -> 라이트에서 `/30`으로 상향(다크 값은 `dark:`로 pin).
3. 같은 색끼리 겹치는 곳(흰 팝오버 on 흰 카드, 회색 시트 on 회색 캔버스)은 톤차가 없으므로 **헤어라인 border 또는 shadow-md 이상 유지**(Popover border, Sheet shadow-lg+dim 오버레이). 이 규칙 때문에 Popover/Select content는 border를 지우지 않는다.
4. 입력·체크박스·세그먼트 트랙 경계는 `--input`/기능성 보더 유지(>=3:1).
5. 구분선(행·헤더)은 `border-border`(풀 알파, 흰 위 1.31:1)로 최소 보장, `/NN` 알파 결합 금지(라이트).
6. 점검 방법: Playwright에서 라이트 12개 화면 스크린샷 + `getComputedStyle` 배경색으로 부모-자식 대비 계산(qa 스크립트화). 1.08 미만 항목은 ui-review에서 `UI 수정 요청`.
7. 박스가 서로 맞닿는 리스트(ROW 연속)는 간격 `gap-2`(8px) 이상으로 톤 분리 확보. 맞붙은 `space-y-0` 카드 스택이 발견되면 divider(`divide-y divide-border`) 추가.

## 9. design-system.md에 반영할 수치 (§3·보조)
- §0.3 보더리스 문구에 "라이트 카드 외곽선·그림자 없음, 배경 톤차가 1순위" 명시.
- §1.1 보더 행: 라이트 `oklch(0.91)` (장식 헤어라인). 배경 라이트 `oklch(0.96 0.004 250)` #F0F2F4.
- §3.2 반경: `--radius: 0.75rem` -> sm 8 · md 10 · lg 12 · xl 16 · **2xl 20(`--radius-2xl` 신규)**. 역할표: 카드 `xl` / 내부박스·컨트롤(Button·Input·Select) `lg` / 다이얼로그·시트·배너·Drawer 상단 `2xl` / 칩·배지·점·키패드 `full`. 동심표(§3) 수록.
- §3.3: 라이트 캔버스 수치 오기(0.91) -> 0.96 정정; `--shadow-2xs/xs/sm` 불투명도 .03~.06; "카드/행/KPI/섹션은 border·shadow 없이 `bg-card` 톤차" 규약; 라이트 박스 점검 규칙 §8(1.10 / 1.08); `--input` 불변 재확인; 경계 헤어라인 치환 규칙(`border-border dark:border-border/NN`).
- §5.1 SECTION 레시피를 `rounded-xl bg-card p-4 space-y-3 dark:shadow-sm`로, 헤더는 **칩 없는 단색 아이콘 `size-5`**(톤 4종 글자색만)로 수정. "아이콘 칩 톤 구분" 문단을 "아이콘 색 톤 구분"으로 개정.
- 신규 규약 3줄: ① 장식용 색 그림자·그라데이션 금지(그림자는 중립 검정 저불투명) ② 컬러 아이콘 칩 금지 — 아이콘은 단색, 의미는 색·굵기로 ③ 시스템 글꼴 스택 `--font-sans`.
- §8에서 `floating-add-button.tsx`의 hex 사본 언급 삭제(토큰화됨). §5 컴포넌트 규약에 "키패드: 테두리·배경 없는 72px 숫자, 눌림만 `bg-muted` 원" 추가.
