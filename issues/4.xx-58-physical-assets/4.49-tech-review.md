## 3. 저장 스키마·분리 키 `secretasset.physical_assets`
### 3-1. 분리 키가 기존 경로와 무관함 (재grep 확인)
- **`clearAssetData`(`:431-439`)**: `startsWith("secretasset_")`만 대상. 점 구분 `secretasset.`는 걸리지 않음 → 수정 안 함. 명시 삭제 지점(모든 데이터 삭제 `settings-page.tsx:126`, 데모 주입 `preview-gate.tsx:89`, 공유 반영 `asset-data-context.tsx:940`)에서만 `clearPhysicalAssets()` 호출
- **키 순회 전수(`Object.keys(localStorage)`·`localStorage.key(`)**: `asset-storage.ts:431·456`, `storage-stats.ts:25`(`startsWith("secretasset")`라 용량 집계에 자동 포함), `profit-cache-cleanup.ts:34`, `local-storage.ts:117·171`, `one-time-migrations.ts:86`, `use-gemini-usage.ts:58`. 전부 접두 `secretasset_profit:`·`secretasset_notice_seen_`·`secretasset-gemini-` 한정 → 무영향
- **백업(파일 내보내기)·동기화 payload**: `buildExportPayload:150`가 `getAssetData()`로 만들므로 분리 키 값이 `assetData.physicalAssets`로 자동 포함(키 없으면 필드 생략). 분리 키를 따로 읽는 코드를 추가하지 않는다
- **공유 토큰·복원 코드(packV7)**: `generateShareToken:972`/`parseShareToken:994` 포맷 변경 0, 실물 미포함
- **체험(trial)**: 메모리 Storage라 원본 무영향. 거부 판정(`trial-boot.ts:66-81`)은 `ASSET_ARRAYS` 5종 정규화 후 `hasAnyAssets`를 쓰므로, **원본의 `secretasset.physical_assets`가 비어 있지 않은 배열이면 `asset_data` 거부**를 별도 한 줄로 추가(C28)
- **4.53 sync 형식 검증**: 위 2절대로 무관

### 3-2. 쓰기 규칙 (핵심 안전장치)
- `saveAssetData`(`:118`)·**`saveAssetDataRaw`(`:396`, `{...data}`를 그대로 기록하므로 반드시 같이 처리. 호출처 `stock-screenshot-import.tsx:278`, `asset-data-context.tsx:1351`)**: `physicalAssets`를 떼어 분리 키에 쓰고 본 키에는 넣지 않는다. 쓰기 순서 분리 키 → 본 키. 값이 `undefined`면 분리 키를 **손대지 않는다**(전개 누락·EMPTY 객체로 저장해도 실물이 지워지지 않는 안전 기본값)
- 명시적 `[]`는 분리 키에 `[]` 기록(삭제 의도). 키 없음(undefined)≠빈 배열
- 읽기는 loose(min 제약 없음, `physicalAssetSchema.passthrough()`, `type`은 `.catch("other")`). 제약 검증은 폼에서만(읽기 탈락→다음 저장 때 영구 소실 차단, C6)
- 순환 비의존: `getAssetData`의 닉네임/거래소 마이그레이션 분기(`:82-107`)는 원본 `parsed`(본 키)만 다시 쓰고 합치기는 `:111` 직전이므로 분리 키 값이 본 키로 새지 않는다(테스트로 고정)

### 3-3. 마이그레이션·신구 혼재
- 기존 데이터엔 키가 없어 변환 없음. 이전 버전(4.51 이하) 데이터 → 신버전 로드 시 5종·스냅샷 동일(복원 테스트 ①)
- 구버전 기기 동작: 분리 키를 읽지도 쓰지도 않고 보존(zod strip). 구버전 pull `clearAssetData`도 보존. 구버전 push는 `physicalAssets` 없음 → 신버전 pull은 undefined면 로컬 유지. 알려진 한계 4개(구버전 '모든 삭제' 후 잔존·노출 / 구버전 일별 그래프 하락 / 복원 코드 제외 / 구 백업 가져오기 시 기존 값 유지)만 존재, 5번째가 생기면 대표 승인 전환
- 데이터 영향 범위: 저장·동기화·스냅샷·백업·성적표 계산을 건드림. 거래 데이터·공유 토큰 포맷은 무변경. 롤백 시 분리 키가 남아 기록 손실 0(재머지 시 복귀)
