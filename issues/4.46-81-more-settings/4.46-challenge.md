## 1~5 검토
1. **꼭 해야 하나**: 성장 기여는 작다(정리 과제). 그러나 4.45에서 세금 관리 이관을 이 이슈로 넘겼고(같은 파일 2회 수정 방지), 백업·복원 짝 분리는 실재하는 결함형 구조다. 비용 소. 통과.
2. **더 작게**: 행 수 증감 0, 이동 3건이 핵심. 테마 배지·톤·폭 제한은 같은 두 파일 안 소규모라 분리 이득 없음. 세금 화면 톤은 이미 제외. 축소 불요.
3. **중복**: 저장 현황 줄·가져오기를 옮기며 설정에서 제거(두 곳 표시 0). 웰컴 '기존 데이터 가져오기'는 자산 0 기기 입구라 유지 타당.
4. **LEARNINGS·DECISIONS**: 반려 영역 아님. "메뉴는 사용자 인식 단위"(LEARNINGS 2026-10)와 같은 방향.
5. **측정**: 기존 `백업`·`데이터 관리` page_title, 정성. 통과.

## 쟁점 판정
- **섹션 제목 '공유 · 동기화'→'공유 · 백업'과 조건 ⑤**: ⑤에 걸리지 않는다. ⑤는 데이터 저장·전송·보호 방식을 **주장하는 문장**(C26 유형: 암호화·서버·저장 위치)이다. 섹션 제목은 묶음 이름이고 아무 주장도 하지 않는다. 행 라벨 "자산 공유 · 동기화"와 백업·가져오기·캐시·삭제의 라벨·설명·토스트·확인 창은 문자 단위 diff 0(spec 7-4)이어야 하며, 이것이 깨지면 ⑤ 위반으로 승인 요청 전환.
- **삭제 행 설정 잔류**: 동의. 되돌릴 수 없는 동작을 한 단계 안쪽에 두는 현행 유지 = 노출 증가 0. 맨 아래 + 간격 16px은 오조작을 줄이는 방향.
- **가져오기 이동의 데이터 안전**: 같은 훅(`useAssetImport`, 원래 tool-menu·welcome 공용)을 그대로 쓰는 위치 이동이라 저장 경로·push 트리거 불변. 개발·qa 필수 확인 3가지:
  1. 숨은 `<input type=file>`은 tool-menu에서 **조건부 블록 밖**(자산 0·체험·백업 비활성 조건과 무관)에 항상 렌더된다. 자산 0에서도 가져오기 동작.
  2. settings-page에서 훅 호출·ref·input을 모두 제거(고아 ref 0), 가져오기 경로는 더보기 1곳.
  3. 가져오기는 확인 창 없이 현재 데이터를 대체하고 동기화 연결 시 push된다(현행 동작). 백업 행 바로 아래로 오지만 파일 선택 단계가 있어 오조작으로 실행되지 않는다 — 현행 유지 수용, qa-report 데이터 안전 표에 "동작·문구 불변"으로 기록.
- **⑦(큰 UI 방향)**: 두 메뉴 화면의 순서·톤 정돈이라 경량. 섹션 제목 인디고→중립은 4.42 기준점(대표 만족) 톤과 충돌하지 않는 단색화 방향. 충족.
