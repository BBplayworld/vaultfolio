## 대표 지적 R2 (0c05de1) — iOS "월 열·순자산 영역에 가로 스크롤 두 개"
**판정: 스크롤러는 1개. iOS 네이티브 가로 스크롤 인디케이터 1개가 sticky 월 열에 덮여 두 조각으로 보인 것.** 근거(캡처 `owner-r2-ios-sheet.jpg` 1179px 폭 = 393pt×3 픽셀 실측):
- 막대(y 1103–1111) 밝은 구간 = x 33–224 · 405–875. 바깥 끝 33·875는 y마다 34→33→36으로 변하는 **둥근 끝**, 안쪽 끝 224·405는 모든 y에서 같은 **직각 절단** → 막대 2개가 아니라 1개가 가려진 것.
- 끊긴 구간 225–404 = 월 열 칸 정확히 일치(머리줄 아래 가로선 시작 x=225, 월 열 `border-r` x=402–404). 반면 순자산 열 경계선(x=561, 비 sticky)은 막대 **아래**에 깔림(x=560·562 막대 색) → 비 sticky 칸은 인디케이터 밑, sticky 월 칸만 위.
- 표 세로 경계선이 y=1120(스크롤러 바닥)까지 내려옴 → 마지막 줄 월 칸이 인디케이터 띠(바닥 3–6pt)를 덮는 위치.
- 표 스크롤러 왼쪽 = 24px(래퍼 px-2), 인디케이터 왼쪽 끝 33 = 그 안쪽 inset. 월 열이 225에 있음 = 내용이 +201px(67pt) 오른쪽으로 밀림, 막대는 왼쪽 끝 → **가로 rubber-band(scrollLeft<0) 중 캡처**. sticky left-0은 음수 스크롤에선 제약이 없어 내용과 함께 이동 → 월 열 왼쪽 빈 공간.

**원인(WebKit 동작)**: 표 스크롤러(`overflow-auto`)가 쌓임 맥락이 아니어서 z-index(Z_LAYER) 가진 sticky 칸은 바깥 쌓임 맥락(SheetContent) 소속. iOS 13+ WebKit은 이런 칸을 스크롤러의 UIScrollView 바깥 형제 레이어로 합성(overflow scroll proxy)해 스크롤을 따라가게 하므로, UIScrollView 서브뷰인 네이티브 인디케이터보다 **위에** 그려진다. 불투명 면(`SURFACE`)의 월 칸 사각형만큼 막대가 지워짐. Chromium 에뮬레이션은 스크롤바가 레이아웃 트랙(비오버레이)이라 재현 불가 → 지금까지 "스크롤러 1개"만 확인하고 해결로 오판.

**조치**(`monthly-log-sheet.tsx` 표 스크롤러 클래스 3개, 다른 변경 0):
1. `isolate` — 스크롤러를 쌓임 맥락으로 만들어 sticky 칸이 스크롤 내용 레이어 안(인디케이터 아래)에 합성되게. 근본 조치.
2. `pb-3` — 인디케이터 띠(바닥 3–6pt)에 월 칸이 닿지 않게 하는 보강(세로 스크롤 없거나 바닥까지 내린 상태는 레이어 순서와 무관하게 안전).
3. `overscroll-x-none` — 가로 바운스(Safari 16+) 차단으로 월 열 왼쪽 빈 공간 제거. 세로는 그대로.
- 인디케이터 숨김(`scrollbar-width:none`)은 쓰지 않음: 막대 0개가 되면 "가로 스크롤 하나로 좌우를 본다"는 단서가 잘린 열뿐이 되고, 데스크톱 좁은 창 스크롤바도 사라짐.
- 테스트 1건 추가(스크롤러 클래스), vitest 1466 통과·tsc·lint 0 error.
