## 2. 토스트 (자동 pull에서 덮임 N≥1)
```ts
toast.info("다른 기기 변경을 반영했어요", {
  id: "sync-overwrite",            // 고정 id: 재발생 시 새 토스트가 쌓이지 않고 건수만 갱신
  testId: "sync-overwrite-toast",
  description: `이 기기에서 고친 ${n}건이 바뀌었어요. 앱을 닫기 전까지 되돌릴 수 있어요.`,
  duration: 12000, closeButton: true,
  action: { label: "확인하기", onClick: () => setShowOverwriteList(true) },
  classNames: { description: "!text-sm text-pretty break-keep", actionButton: "!h-10 !px-3 !text-sm", closeButton: "after:absolute after:-inset-2" },
  actionButtonStyle: { background: "var(--brand)", color: "#fff" },
});
```
- 아이콘은 기존 info 단색 `size-4`(warning·빨강 금지: 사실 중심·불안 최소). 건수 N은 `tabular-nums`.
- **지속 12초 + 닫기 버튼**(기본 2초는 읽고 누르기에 짧음). 사용자가 닫아도 카드가 정본이라 소실 없음. 호버/포커스 중 일시정지는 sonner 기본.
- **대체 규칙**: 덮임>0이면 "다른 기기의 변경을 반영했습니다."(runPull 245)와 "클라우드가 더 최신이라…"(runPush 217, 비-silent)를 **띄우지 않고** 이 토스트 1개만(동시 2개 금지). 덮임 0이면 기존 토스트 그대로. runPush conflict 직후 runPull이 이어지므로 "덮임 여부는 pull 결과로 판정, 217번 토스트는 pull 완료 뒤에 필요할 때만" 순서로 구현.
- 되돌리기 완료: 같은 id로 `toast.success("되돌렸어요")`(기본 2초)가 덮어씀. push 실패: `toast.info("이 기기에서는 되돌렸어요. 연결되면 다른 기기에도 반영돼요.")`(오류색 금지, 로컬은 이미 성공).
- 접근성: sonner 영역은 aria-live 폴리트 기본. 위 id 갱신 시 스크린리더가 새 문구를 다시 읽음.
- 375/320: 토스트 폭 = 화면-24px(≈296px at 320), `break-keep`로 어절 보존, 설명 3줄 이하. 1280: 우하단 기본 위치·폭 356px.

## 3. 안내 카드 (기기 동기화 다이얼로그, armed 한정)
```tsx
<div aria-live="polite">  {/* 항상 마운트된 라이브 영역 */}
  {n > 0 && (
    <div data-testid="sync-overwrite-card"
         className="rounded-lg bg-muted/40 shadow-xs p-3 space-y-2 motion-safe:animate-in motion-safe:fade-in motion-safe:slide-in-from-top-1 duration-200">
      <p className="flex items-center gap-1.5 text-sm font-semibold text-foreground">
        <History className="size-3.5 text-primary" /> 바뀐 내 변경 <span className="tabular-nums">{n}</span>건
      </p>
      <p className="text-sm text-muted-foreground leading-relaxed text-pretty break-keep">앱을 닫기 전까지 되돌릴 수 있어요.</p>
      <Button variant="secondary" size="sm" className="min-h-10 w-full sm:w-auto sm:ml-auto sm:flex" data-testid="sync-overwrite-open">확인하기</Button>
    </div>)}
</div>
```
- **위치**: 상태줄(`bg-primary/5`) 바로 아래, 링크 카드 위. armed `space-y-4` 안이라 간격 16px 자동. 덮임 0이면 DOM 자체가 없어 레이아웃 diff 0.
- 톤: 칩·뱃지·amber/빨강 없음, 아이콘 `History`(lucide) 단색 primary(기존 카드 헤더 아이콘과 동일 규격 size-3.5). 문구는 사실 한 줄 + 기한 한 줄.
- 색은 `bg-muted/40`(§3.3 팝업 내부 박스) — 인접 카드 `bg-card/50`과 톤차로 구분, 상태줄 primary와 겹치지 않음. 다크/라이트 모두 토큰만.
- 버튼 `min-h-10`(40px 히트영역), press scale 내장. 열릴 때만 fade+slide-in(재마운트 아님: 건수 변경은 텍스트만 갱신, key 부여 금지), 사라질 때 즉시(subtle exit).

## 4. 목록 다이얼로그 (`sync-overwrite-dialog.tsx`)
`DialogContent className="sm:max-w-md max-h-[85vh] overflow-y-auto touch-pan-y"` (기기 동기화 다이얼로그와 동일 규격, 모바일 폭 가득·PC 448px).
```
DialogHeader(text-left)
  DialogTitle  flex items-center gap-2  [History size-5 text-primary] 바뀐 내 변경 N건
  DialogDescription text-left text-pretty break-keep
     다른 기기에서 먼저 저장한 내용이 반영됐어요. 이 기기에서 아직 올라가지 않은 변경이 아래처럼 바뀌었어요.
ul  data-testid="sync-overwrite-list"
    rounded-lg bg-muted/40 divide-y divide-border dark:divide-border/40 max-h-[40vh] overflow-y-auto scrollbar-themed
  li  data-testid="sync-overwrite-row" px-3 py-2.5 min-h-10  flex flex-col gap-0.5
      이름  text-sm font-medium text-foreground line-clamp-2 break-words        (자산 이름 · 거래 요약 · "연도별 순자산 2025" · "닉네임")
      상태  text-sm text-muted-foreground text-pretty break-keep
p  text-sm text-muted-foreground  앱을 닫거나 새로고침하면 되돌릴 수 없어요.
DialogFooter  [되돌리기 variant="brand"] [그대로 두기 variant="secondary"]   (DOM 순서 주요→취소, 기본 반응형 규칙)
```
- **행 상태 문구 3종**(색 구분 없음 — 손익 빨강/파랑은 손익 전용, 상태는 글로만): 
  - 수정 덮임: "내 수정이 다른 기기 값으로 바뀌었어요"
  - 삭제 부활: "내가 삭제한 항목이 다시 생겼어요"
  - 원격 삭제: "내가 수정한 항목이 다른 기기에서 삭제됐어요"
- 정렬: 부동산·주식·코인·현금·대출·거래 → 연도별 순자산 → 닉네임(spec 대상 순서). 같은 항목은 1행(최근 값).
- 세로 스택(이름 위/상태 아래)이라 320px에서도 가로 넘침·잘림 없음. 값 비교표 없음. 행 수가 많으면 목록만 스크롤(다이얼로그 푸터·한계 문구는 항상 보임).
- **한계 표기**: 목록 아래 1줄 고정(위 문구). 토스트·카드의 "앱을 닫기 전까지"와 같은 사실을 같은 어조로.
- **되돌리기 확인 단계**(같은 다이얼로그 안, 푸터 영역 교체, `data-testid="sync-overwrite-confirm"`): 
  `rounded-lg bg-muted/40 p-3 space-y-2` — 제목 `text-sm font-semibold` "이 기기에서 고친 값으로 되돌릴까요?" / 본문 `text-sm text-muted-foreground leading-relaxed text-pretty break-keep` "목록의 N건을 이 기기 값으로 되돌리고 다른 기기에도 반영해요. 같은 항목을 다른 기기에서 바꾸거나 지운 내용도 함께 되돌려질 수 있어요." / 버튼 `[되돌리기 확정 brand][취소 secondary]` flex gap-2 각 `flex-1`(모바일 가로 2분할, 40px↑). amber·destructive 사용 안 함(파괴가 아니라 복원이므로 brand, 경고는 문구로).
  - 진입 `motion-safe:animate-in fade-in duration-150`, 포커스는 확인 박스 제목(`tabIndex={-1}`)으로 이동, 취소 시 [되돌리기]로 복귀. 박스는 `role="group" aria-labelledby`.
  - 처리 중: 확정 버튼 `disabled` + `Loader2 animate-spin`, 다이얼로그 닫기(Esc·바깥 탭·취소) 잠금으로 연타·중간 닫힘 방지(인터럽트 대신 잠금: push 1회 보장).
- **확정 시 건수 변동(COO R1)**: 목록은 다이얼로그를 열 때와 [되돌리기 확정] 때 다시 계산한다. 이후 이 기기에서 다시 고쳤거나 다음 pull로 또 바뀐 항목은 목록·되돌리기 대상에서 빠진다(무음 덮어쓰기 금지).
  - 확정 시점에 빠진 항목이 1건 이상이면 **바로 적용하지 않고** 확인 박스 본문을 갱신 건수로 바꿔 한 번 더 보여 준다: 제목 유지, 본문 첫 줄 "목록의 N건을 이 기기 값으로 되돌리고…"의 N을 갱신하고, 본문 위에 안내 1줄 `text-sm text-foreground` "그사이 바뀐 M건은 목록에서 뺐어요." 추가. 목록 행도 같이 줄고 카드·토스트 건수도 갱신(`tabular-nums`, 텍스트만 교체·재마운트 없음). 사용자가 [되돌리기 확정]을 다시 눌러야 적용(포커스는 확인 박스 제목).
  - 빠진 뒤 0건이면 빈 상태("되돌릴 변경이 없어요.")로 전환. 변동 없으면 곧바로 적용.
  - 열 때 재계산으로 빠진 항목은 안내 문구 없이 갱신된 목록만 보임(카드 건수도 동기 갱신).
- **빈 상태**(이미 처리됐거나 연결 끊김 후 stale 진입): 목록 대신 `py-6 text-center text-sm text-muted-foreground` "되돌릴 변경이 없어요." + [닫기 secondary] 1개. 로딩 상태는 없음(목록은 메모리 즉시).
- **첫 사용·예측·오류**: 첫 사용 = 알림 0이라 진입 경로 없음. 예측/추정 값 없음. push 오류는 2절 토스트 문구로 처리, 목록은 닫고 상태줄이 기존 방식으로 재시도 표시.
- 확정 후 닫힘 + 토스트 "되돌렸어요", [그대로 두기] 닫힘 + 카드·보관 폐기(토스트 없음 — 조용히). 모션은 기본 Dialog 진입(fade+zoom) 그대로, 목록 stagger는 두지 않음(2~10행, 노이즈).

## 5. 보안·문구 규칙

## 6. 접근성 · 반응형 · 계측
- 히트영역: 토스트 action 40px, 카드 버튼 40px, 목록 보조 버튼 40px, 푸터 버튼 기본 h-9→모바일 `min-h-10` 확인(필요 시 클래스 추가).
- aria: 카드 래퍼 `aria-live="polite"`, 확인 박스 `role="group"`, 목록 `ul/li`, 아이콘은 `aria-hidden`. 키보드: Tab 순서 = 목록(스크롤 가능 시 `tabIndex=0`) → 되돌리기 → 그대로 두기, Esc 닫기(처리 중 제외).
- 대비: 문구 전부 `text-foreground`/`text-muted-foreground`(투명도 중첩 없음, §11), brand 버튼 흰 글씨는 기존 표준.
- 폭: 320(다이얼로그 내폭≈272, 모든 문구 break-keep·줄바꿈 허용), 375, 1280(`sm:max-w-md`) 라이트·다크 6조합.
- `data-screenshot-hide`: 해당 없음(공유·인증카드 캡처 영역 밖 오버레이/다이얼로그).
- 계측(COO 판정 ③): GA `feature_use` category 2개 — page_title `동기화 덮임 알림`·`동기화 되돌리기`. 호출은 UI 계층(덮임 토스트 표시 지점, 되돌리기 확정 핸들러)에서만, `pullAsset`·`applyImportedPayload`·`runPush` 내부 금지. 덮임 알림은 실행당 1회. 건수·항목 등 파라미터 비전송. `ga.test` 매핑 2줄 추가.

## 7. 품질 체크리스트 (qa 스크린샷·Playwright 판정)
1. 덮임 0건 자동 pull: 새 토스트·카드 없음, 기존 "다른 기기의 변경을 반영했습니다." 유지, armed 다이얼로그 DOM diff 0.
2. 덮임 N≥1: 토스트가 **1개만**(`[data-testid=sync-overwrite-toast]` count 1, 기존 2종 문구 0), 12초 유지, 닫기 가능.
3. 연속 덮임 시 토스트가 쌓이지 않고 같은 토스트 건수만 갱신.
4. 토스트 [확인하기] → 기기 동기화 다이얼로그가 닫힌 상태에서도 목록 다이얼로그가 열림. 다이얼로그 2개 동시 열림 없음.
5. armed 다이얼로그: 상태줄 바로 아래에 카드, 건수·문구가 토스트와 일치, 카드 [확인하기] 높이 ≥40px.
6. 카드·목록·확인 박스에 `border` 클래스·칩·amber/red 색 없음(보더리스, 단색 primary 아이콘만).
7. 목록 행 = 이름 + 상태 1줄, 상태 문구 3종만 사용, 신규 추가 항목 행 없음. 행 15개 이상에서 목록만 스크롤되고 푸터 버튼이 항상 보임.
8. [되돌리기] 클릭 → 같은 다이얼로그에서 확인 박스 노출, 문구에 "다른 기기에서 바꾸거나 지운 내용도 함께 되돌려질 수 있어요" 포함, 확정 전 데이터 변화 0, 취소 시 포커스 [되돌리기] 복귀.
