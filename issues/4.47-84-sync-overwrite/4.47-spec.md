# #84 [4.47] 동기화 충돌 시 로컬 편집 소실 방지 (A안) — spec

작성: planner-designer 2026-11-07 · 상태: **확정** (direction 합의 완료·cto challenge 2026-11-07 조건 반영) · 위험 **risk:high** · 기준 main dee5be9 · 근거 `4.47-direction.md`, `4.47-challenge.md`, `4.47-tech-review.md`, `_discovery/2026-11-06-sync-overwrite-repro.md`, `4.38-57-family-vault/4.38-spec.md` 1절(문제 정의 재사용)

## 1. 문제
자동 pull(`runPull` ← 409 화해·online·폴링·포커스)이 로컬을 원격 payload로 통째 교체한다(`applyImportedPayload`). 기준점이 id 집합뿐이라 **신규 추가만 보존**되고, 이미 동기화된 항목의 수정(무관 항목 포함)은 소실, 로컬 삭제는 부활한다. 알림은 없다(자동 push silent, 토스트 "다른 기기의 변경을 반영했습니다." 한 줄). 4.38 spec 1절의 문제 정의와 같고, 그 r2가 다루지 않은 무관 항목 소실·삭제 부활·복원을 여기서 다룬다.

## 2. 목표 행동
덮임이 생긴 사용자가 ① 알림으로 사실을 알고 ② 목록에서 어떤 항목인지 확인하고 ③ 앱을 닫기 전에 되돌리거나 그대로 둔다.

## 3. 범위
direction 경험 2절과 같다. 핵심 규칙:
- **기준(baseline)**: 이 앱 실행 안에서 마지막으로 push 또는 pull이 성공한 시점의 데이터 사본(메모리만). 기준이 없으면(앱 시작 직후 첫 pull 전) 감지하지 않는다.
- **덮인 항목 = 내가 바꿨고(기준 ≠ pull 직전 로컬) pull 결과가 내 값과 다른 항목**. 구분 3종: `수정 → 다른 기기 값으로 바뀜` / `삭제 → 다시 생김` / `수정 → 다른 기기에서 삭제됨`. 신규 추가(보존됨)와 내가 안 바꾼 항목은 목록에 없다.
- **대상 기록**: 사용자가 직접 입력하는 것 — 부동산·주식·코인·현금·대출·거래 4종(reconcile 9개 배열), 연도별 순자산, 닉네임. 월 스냅샷(이미 보호)·시세 파생값 제외.
- **노출 조건**: 덮인 항목이 1건 이상일 때만. 0건이면 화면·토스트는 main과 같다.
- **되돌리기**: 목록 전체를 한 번에. 현재 데이터 위에 목록 항목만 내 값으로 되돌림(수정은 내 값, 부활은 다시 삭제, 원격 삭제분은 내 값으로 다시 추가) 후 일반 push. 목록 밖 항목(다른 기기의 무관한 변경)·월 스냅샷·설정은 건드리지 않는다.
- **재계산(R1)**: 목록은 열 때와 확정 때 다시 계산한다. 현재 값이 '덮인 직후 값'과 다른 항목(이후 이 기기에서 다시 고쳤거나 다음 pull로 또 바뀐 항목)은 되돌리기에서 빼고 목록에서 지운다. 0건이 되면 목록·카드를 닫는다.
- **저장 경로(R2)**: 사용자 편집과 같은 경로(클릭 핸들러에서 저장 + `notifyAssetUserEdit`) 후 일반 push. `applyImportedPayload`·`clearAssetData` 사용 금지. push 409면 같은 감지 흐름으로 다시 들어간다(전용 경로 없음).
- **GA**: 기존 `feature_use`에 category 2개(page_title `동기화 덮임 알림`·`동기화 되돌리기`). 호출은 UI 계층(감지 후 토스트 표시 지점, 되돌리기 확정 핸들러)에서만, 덮임 알림은 실행당 1회, 건수·항목 파라미터 0. `pullAsset`·`applyImportedPayload`·`runPush` 내부 호출 금지.
- **보관 수명**: 새로고침·앱 종료·연결 끊기·다른 금고 연결 시 폐기. 같은 실행 중 덮임이 또 생기면 목록에 합치고, 같은 항목은 가장 최근에 덮인 내 값을 쓴다.
- 새 저장 키·스키마·payload·`/api/sync`·서버 전송 값 변경 0. 감지는 순수 함수(저장·push·notifyAssetUserEdit 호출 없음, C16).

## 4. 사용자 흐름
1. 자동 pull 직전 로컬 사본 보관 → pull 결과와 기준 비교 → 덮인 항목 N건.
2. N≥1: 토스트 1개(기존 반영 토스트 대체, 오래 유지·닫기 가능)
   - 문구: "다른 기기 변경을 반영하면서 이 기기에서 고친 N건이 바뀌었어요" / 보조 "앱을 닫기 전까지 되돌릴 수 있어요" / 액션 [확인하기]
3. [확인하기] → 목록 다이얼로그 "바뀐 내 변경 N건"
   - 설명: "다른 기기에서 먼저 저장한 내용이 반영됐어요. 이 기기에서 아직 올라가지 않은 변경이 아래처럼 바뀌었어요."
   - 행: 항목명(자산 이름·거래 요약·"연도별 순자산 2025"·"닉네임") + 구분 1줄
   - 한계 1줄: "앱을 닫거나 새로고침하면 되돌릴 수 없어요."
   - 버튼: [되돌리기](brand) [그대로 두기](secondary)
4. [되돌리기] → 같은 다이얼로그 안 확인 단계: "목록의 N건을 이 기기 값으로 되돌리고 다른 기기에도 반영해요. 같은 항목을 다른 기기에서 바꾸거나 지운 내용도 함께 되돌려질 수 있어요." [되돌리기 확정](brand) [취소]
5. 확정 → 목록 재계산(R1) → 로컬 반영(R2) + push → 토스트 "되돌렸어요" · 목록·카드 사라짐. push 실패(오프라인 등)면 로컬은 되돌린 상태로 두고 기존 자동 push 경로로 재시도(별도 오류 화면 없음, 기존 오류 토스트 규칙).
6. [그대로 두기] → 목록 폐기, 카드 사라짐.
7. 토스트를 놓친 경우: 더보기 > 기기 동기화 > armed 상태줄 바로 아래 안내 카드 "바뀐 내 변경 N건 · 앱을 닫기 전까지 되돌릴 수 있어요 [확인하기]" → 3번.
- 보안 문구: 이 기능은 새 보안 문구를 넣지 않는다. 불가피하면 "동기화 데이터는 기기에서 암호화되어 관리자가 읽을 수 없어요." 한 문장만, '절대·모든·원천·이중·완벽' 등 수식어와 "서버로 아무것도 안 간다" 류 단정 금지(DECISIONS 2026-10-31·11-01, C26).

## 5. 엣지 케이스
- **빈 데이터·첫 사용자**: 연결 직후(다른 금고 연결·기기 데이터 가져오기)는 사용자가 덮어쓰기를 확인한 경로 → 감지 안 함. 기준 없음 → 알림 0.
- **일부 갱신**: 같은 push 안에 수정·삭제·추가가 섞이면 수정·삭제만 목록, 추가는 보존·미표시.
- **오래된 데이터(앱 재시작)**: 이전 실행에서 못 올린 편집이 시작 pull로 덮이면 기준이 없어 감지·복구 불가 — 현행과 같은 동작(악화 없음), **알려진 한계**로 명시. 오탐 알림(다른 기기 변경을 내 변경으로 표시)을 막기 위해 기준 없는 폴백 알림은 두지 않는다(tech-review 4절 5의 "폴백 표기"를 대체).
- **편집 없음**: 폴링 pull로 다른 기기 변경만 들어오면 알림 0, 기존 "다른 기기의 변경을 반영했습니다." 토스트 유지.
- **되돌린 뒤 또 충돌**: 같은 흐름 반복(새 목록). 무한 반복 없음(사용자 행동으로만 push).
- **앱잠금·인앱 게이트**: pull 자체가 막혀 해당 없음.
- **preview**: 동기화 쓰기 꺼짐이라 화면 확인은 vitest 하네스로 대체(C9: 사람 확인 전제 완료 기준 없음).

## 7. 데이터 안전 점검 (C5·C6·C11·C13·C14·C16·C17)
- **구버전 혼재**: pull·push 저장 결과는 main과 동일. 되돌리기는 사용자가 손으로 다시 고친 것과 같은 일반 payload push라 구버전 기기가 그대로 읽는다. 구버전 기기 push가 다시 덮는 것은 현행과 같음(악화 없음).
- **롤백**: 저장 변경 0 → 코드 revert만으로 복구. 메모리 사본은 저장되지 않아 잔존물 없음.
- **복구 범위**: 실행 중 = 목록 항목 되돌리기(목록 밖·이후 변경 무접촉). 재시작 후 = 복구 불가·알림 없음(한계, 현행과 같음). 기존 설정 백업 내보내기는 그대로.
- **서버·E2EE**: 서버 전송 값 증가 0. GA는 page_title 값만(자산 값·건수 원값 미전송).

## 8. 완료 기준 (qa 재현 하네스: 기기 2개 localStorage 분리 + 409 모의, 공통 c1=1000·c2=500·S1=10 v1 → B가 c1=2000 push → A 편집 후 push 409 → force pull)
1. **같은 항목 수정**(A c1=3000): pull 후 c1=2000(원격 우선 유지), 목록에 c1 "다른 기기 값으로 바뀜". 되돌리기 후 A·B 모두 c1=3000.
2. **무관 항목 수정**(A S1=99): pull 후 S1=10, 목록에 S1. 되돌리기 후 A·B 모두 S1=99, 이때 c1=2000 유지(목록 밖 원격 변경 보존 — 1번과 분리 실행 시).
3. **삭제 부활**(A c2 삭제): pull 후 c2 존재, 목록에 c2 "다시 생김". 되돌리기 후 A·B 모두 c2 없음.
4. **신규 추가**(A c3): pull 후 c3 보존, 목록에 c3 없음. 4건 모두 섞은 경우 목록 정확히 c1·S1·c2 3건.
5. **오프라인 복귀**(같은 실행): A 오프라인 편집 → online 이벤트 pull → 1~4와 같은 목록. **재시작 후** 시작 pull: 알림 0, 저장 결과 main과 동일(한계).
6. 편집 없는 pull·덮임 0건: 알림·카드 0, 기존 반영 토스트 유지, 저장 결과 main과 동일.
7. [그대로 두기]·새로고침 후 카드·목록 없음. 수동 "기기 데이터 가져오기"·다른 금고 연결에서 알림 0.
8. 새 localStorage 키 0, `secretasset_sync` 필드 변화 0, `/api/sync` 요청 형식 변화 0(diff grep 목록, C11). 감지 함수가 save·notify를 호출하지 않음(grep, C16).
9. 새 문구 전부 320·375에서 어절 중간 줄바꿈 없음(C25), 보안 수식어 금지어 0건·새 문자열에 '서버' 0건(C26).
10. **R1 이후 변경 제외**: 덮임 후 A에서 목록 항목(c1)을 다시 고치거나 다음 pull로 c1이 또 바뀌면, 목록을 열 때·확정 때 c1이 목록에서 빠지고 되돌리기 후 c1은 현재 값 유지.
11. **목록 밖 무접촉·409 재감지**: 되돌리기 후 A·B의 월 스냅샷·설정·목록 밖 항목이 main 로직 결과와 동일. 되돌리기 push가 409면 같은 감지 흐름으로 다시 들어가 새 목록이 생긴다(전용 경로 없음).
12. **메모리 사본 0**: [그대로 두기]·새로고침 후 보관 사본·목록이 메모리에 남지 않는다(하네스로 확인), localStorage 잔존물 0.

## 9. 후속 (이번 범위 아님)
B안 항목 단위 3-way 병합(`secretasset_sync`에 지문 필드 추가, 마이그레이션·복원 테스트, risk:high) — 대표가 "막기"를 원할 때 별도 승인. C안(push 전 선확인)은 B와 묶음.
