# 4.48 #83 월 탭 자산 구성 변화 블록 — 명세

작성: planner-designer, 2026-11-07. 방향: 4.48-direction.md. 비주얼 사양(ui.md)은 ui-designer가 쓰고, 4.44-ui-v3-composition 2절의 막대·행 규격 가운데 리본을 뺀 나머지를 재사용 후보로 한다. 코드 기준 main@5352e42.

## 1. 문제
월 결산은 "얼마가 왜 바뀌었나"(금액·원인)만 보여준다. "이 구간 동안 자산 비중이 어떻게 바뀌었나"는 앱 어디에서도 보이지 않는다. 현재 비중은 홈 도넛에만 있고, 비교할 수 없다.

## 2. 목표 행동
월 탭 사용자가 클릭 없이 결산 구간 시작→끝의 자산군 비중과 증감(%p)을 읽고, 월 화살표로 다른 결산 달과 비교한다.

## 3. 범위
- 포함: `settlement-view.tsx`의 `CauseBlock`과 AI 행 사이에 블록 1개(`composition-block`). 계산은 `composition.ts`에 순수 함수 `computeMonthComposition(w, live)` 하나로 둔다. GA 화면 키 `activity:change:composition`(기존 등록분)을 재사용한다.
- 제외: 리본·범례·선택·보정·금액·상시 캡션, AI 프롬프트 반영, 연 탭·주식 범위, 저장·스키마·동기화·서버 전송 변경, **#58 실물(4.49로 분리, COO 4.48 challenge 조건 5)**.
- 예외 1개: 배지 뒤 `InfoHint` 1개(상시 캡션 아님, 펼칠 때만 보임). 문구는 4절 2번에 확정.

## 4. 사용자 흐름
1. 성과 > 자산 변화 > 전체·월(기본)로 들어간다. Hero(결산 구간)와 원인을 본다.
2. 원인 아래에 "자산 구성 변화" 블록이 보인다. 헤더 오른쪽에 배지 **"총자산 기준"**("부채 제외" 덧붙이지 않음, COO 판정)과 `InfoHint` 1개(`data-screenshot-hide`)가 있다. 힌트 문구 확정(planner-designer, COO 조건 충족): **"홈 도넛은 부채도 함께 나눠 보여줘서 같은 항목도 %가 다를 수 있어요. 이 블록은 부동산·주식·암호화폐·현금성의 합을 100%로 봐요."** — "부채를 뺀"·"소수 첫째 자리" 표현은 쓰지 않는다.
3. 사실 문장 1줄: "이 구간 동안 주식 +4%p, 현금성 −3%p". 반올림한 정수 비중의 차이가 큰 순서로 2개까지 쓰고, 전부 0이면 "이 구간 동안 구성이 거의 같아요"를 쓴다.
4. 막대 2줄: 위 막대는 시작점(라벨은 Hero 시작점 표기와 같음, 예 "9/30"), 아래 막대는 끝점("10/31" 또는 "지금")이다. 폭은 실제 비중에 선형으로 맞춘다.
5. 행: `색점 · 주식 · 31% → 35% · +4%p`. 차가 0이면 "변화 없음"으로 쓴다. 손익색 대신 전경색과 부호(+, U+2212)를 쓴다.
6. 월 화살표로 달을 옮기면 Hero와 블록이 같은 구간으로 함께 바뀐다. 블록이 숨는 달로 가면 블록이 사라지고 AI 행이 원인 바로 아래로 온다.
7. 계산 규칙
   - 비중 = 자산군 값 ÷ (해당 시점 자산군 값의 합)이다. 키는 `COMPOSITION_KEYS` 4개(부동산·주식·암호화폐·현금성)이고 부채는 넣지 않는다. `physical`은 #58(4.49) 완료 기준으로 옮겼다.
   - 끝값: `w.end`가 있으면 `w.end.breakdown`을 쓰고, 없으면(이번 달) **Hero·원인과 같은 출처**인 `settlement-view.tsx` memo의 `buildLiveAttributionCurr(...)` 반환값 `live.breakdown`(realEstate·stocks·crypto·cash)을 쓴다. summary를 블록에서 따로 합산하는 경로는 만들지 않는다(COO 조건 2). 그래서 #58 합류 시 키 1줄로 끝난다.
   - 행 표시: 두 시점 중 한쪽이라도 0보다 큰 자산군만 보인다.

## 5. 엣지 케이스
| 상황 | 처리 |
|---|---|
| 첫 달(`first_month`) | 숨김. Hero가 "다음 달부터 결산이 열려요"로 안내한다 |
| 시작 또는 끝(결산 완료 달)에 `breakdown` 없음(7월 결산·레거시 시작) | 숨김. 대체 문구를 쓰지 않는다 |
| 어느 한 시점의 자산군 합이 0 | 숨김 |
| 두 시점 모두 자산군 1개(100%→100%) | 숨김. 비교할 구성이 없다 |
| 구간 안에 새 자산군 등록(0%→n%) | 그대로 보인다. 기록 사실이므로 캡션을 달지 않는다 |
| 일부 자산만 갱신(오래된 값) | 블록 자체에는 표시하지 않는다. Hero의 "일부 이전 값" 배지가 같은 화면에서 안내한다 |
| 긴 간격(`longGap`) | Hero 노트를 그대로 따른다. 블록은 같은 구간이다 |
| 1% 미만 자산군 | 행 수치는 반올림 결과가 0이면 "<1%"로 쓴다. 막대 폭은 실제 값 그대로(최소 폭 없음) |
| 결산 계산 오류(`computed.ok=false`) / 기록 0 | 기존처럼 Hero만 보인다. 블록 없음 |
| #58 실물 | 이번 릴리스 범위 밖(4.49). 합류 시 처리는 #58 spec 완료 기준에 있다 |

## 6. 문구 원칙
평가어·권유·목표 비중·투자 조언·금액을 쓰지 않는다. 새 문자열은 모두 `COMPOSITION_FORBIDDEN_WORDS` 테스트를 통과해야 한다. 320·375에서 어절 중간 줄바꿈이 없어야 한다(C25).

## 8. GA
블록이 화면에 들어오면 `trackScreen("activity:change:composition")`을 마운트당 1회 보낸다(IntersectionObserver). 월 화살표로 이동해도 다시 보내지 않는다. 숨김 상태에서는 보내지 않는다. 새 이벤트·파라미터는 없다.

## 9. 완료 기준 (qa가 그대로 검사)
1. 8월 이후 결산 달(데모·실사용 형태 픽스처)에서 월 탭에 들어가면 클릭 없이 원인 블록 바로 아래에 `composition-block`이 보이고, AI 행·다음 달 준비가 그 아래에 있다.
2. 블록 안에 버튼(InfoHint 1개 제외)·`aria-pressed`·리본·범례·금액 문자열이 0개다. 배지 글자는 정확히 "총자산 기준"이고, InfoHint 문구는 4절 2번과 같으며 "부채를 뺀"·"소수"를 포함하지 않고 `data-screenshot-hide`가 있다.
3. 막대 위·아래 라벨이 Hero의 `settlementRangeLabel` 시작점·끝점과 같은 글자다(이번 달은 "지금").
4. 월 화살표로 이동하면 블록 값이 그 달의 `w.start`·`w.end` breakdown으로 다시 계산된다(픽스처 2개 달 대조).
5. 각 행의 증감 = round(끝 비중) − round(시작 비중)이고, 0이면 "변화 없음"이다. 증감 텍스트에 손익색 클래스가 없다.
6. 세그먼트 폭 비율 = 실제 비중(오차 1% 이내)이며 최소 폭·보정이 없다. 두 막대 모두 폭 100%다.
7. 첫 달, 시작 `breakdown` 없음, 총자산 0, 두 시점 단일 자산군에서 블록 DOM이 없고 GA 화면 이벤트도 0건이다.
8. 이번 달(진행 중) 끝 비중이 Hero·원인과 같은 `live.breakdown`(`buildLiveAttributionCurr`)으로 계산되고(블록 전용 합산 코드 0), 홈 도넛과 분모 차이 외의 불일치가 없다.
9. `COMPOSITION_KEYS`는 4개이고 비중 합이 100%(반올림 오차 ±1)다. `physical` 키 검사는 #58(4.49) 완료 기준이다.
10. 새 문자열이 금지어 테스트를 통과하고, 320·375 라이트·다크에서 가로 스크롤과 어절 중간 줄바꿈이 없다.
11. 저장·스키마·동기화·서버 전송 diff가 0이다(C11). `settlement-view.tsx`의 diff는 import, 렌더 1줄, (필요하면) memo 반환값에 `live` 1개뿐이고 Hero·원인·AI 행 코드 diff는 0이다.
11-1. 실사용 형태 픽스처(C20)로 확인: 7월 결산·레거시 시작에서 블록 숨김, 8월 이후 달·대출 많은 사용자에서 같은 이름의 %가 홈과 다른 화면 스크린샷, 손익색 0, 320 줄바꿈(C25).
12. 머지일이 12/11 이후이고 12/26 이전(목표 12/18)이며, run-log·DECISIONS에 "#54 2차 판독·구성 title 판독 시작일"로 기록되어 있다.
13. 같은 블록 비교 단위가 월 탭 Hero와 같다는 문장이 승인 요약에 있다(C32).
