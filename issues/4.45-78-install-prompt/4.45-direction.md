# #78 [4.45] 첫 저장 직후 홈 화면 추가 안내 1회 — direction

작성: planner-designer 2026-11-06 · 기준 main dee5be9(v4.44) 코드 확인 · 근거 `_discovery/2026-11-06-d6-selection.md` ②, `-d6-business.md` 후보 3, `-d6-dev.md` B

## 문제·지표 (공동 근거 — business-pm 사업 절에서 보강·수정)
- **누구의 어떤 문제**: 모바일 웹으로 와서 웰컴의 "웹에서 바로 시작"을 고른 사람은 첫 자산을 저장해 가치를 확인한 뒤에도 다시 설치 제안을 받지 않는다. 설치 진입점은 홈 상단바 다운로드 아이콘(`top-bar.tsx:180`) 하나뿐이고 설명이 없다. 홈 화면 아이콘이 없으면 다시 열 계기가 북마크·검색밖에 없다(PRINCIPLES 4장 진단 "다시 열 이유가 사라져 이탈").
- **기준선**: `pwa_install` 28일 0건(설치 창 열기 `prompt_view` 포함 전부 0), `first_asset_saved` 0/17(10월 신규). GA는 v4.41 규칙대로 page_title 하나만 보며 새 맞춤 정의는 만들지 않는다. 대표 기기는 `?ga-optout=1`로 제외한다.
- **지표**(머지 후 4주·8주): ① 노출 기기 수(page_title "설치 안내") ② 누른 기기 수("설치 안내 누름") ③ "앱 설치" 기기 수(안드로이드 설치 창·설치 완료, 기존 이벤트 그대로). iOS는 설치 감지가 안 되므로 ②를 대리 지표로 쓴다.
- **정직한 한계**: 첫 저장 자체가 월 0~수 건이라 노출 표본이 아주 작다. 8주 판독은 "노출 대비 누름이 0이 아닌가"를 보는 정성 판정이다. 효과는 #77(검색 입구) 유입과 첫 저장이 늘 때 함께 커진다.

## 사업 (business-pm 2026-11-06 확정)
### 1. 왜 지금 — 리텐션 기여(1차), 첫 발견 연계(2차)
- 월 활성 100 목표의 병목은 신규 유입보다 "첫 저장한 사람이 다시 오는가"다. 28일 기준 신규 17명 중 첫 저장 0, 자산 저장은 기존 보유자 3명뿐이라 새로 들어온 사람이 정착하는 경로가 비어 있다. 홈 화면 아이콘은 이 서비스가 쓸 수 있는 유일한 재방문 계기다(알림·로그인 없음, iOS 푸시도 설치 상태에서만 가능 — LEARNINGS 기술 환경).
- 같은 릴리스의 #77(검색 입구)이 신규 유입을 늘리면, 그 사람들이 첫 저장 뒤 아이콘을 남기고 가게 하는 것이 이 이슈다. 둘은 한 깔때기(first_visit → first_asset_saved → 설치 안내 → 누름 → 앱 설치)로 같이 읽는다.
- 새 저장 키 0, 기존 설치 흐름 재사용, 기존 아이콘에 붙는 1회 카드라 비용이 작다. 첫 저장 시점은 가치를 막 확인한 순간이라 설치 요청이 가장 덜 무례하다.

### 2. 누구를 위해
- 엑셀·노션으로 계좌별 자산을 정리하던 3040 주식 투자자 중, 지인 추천·검색으로 **휴대폰 브라우저에서 처음 열어 "웹에서 바로 시작"을 고르고 첫 자산을 저장한 사람.** 설치는 미뤘고, 다음 달 결산 때 다시 들어올 방법이 북마크·검색뿐이다.
- 기존 보유자·데스크톱·인앱 사용자는 대상이 아니다(direction 2절 범위와 같음).

### 3. 성공의 모습 — 지표와 판독 기준 (익명 기기, 기존 GA page_title만)
| 순서 | 지표 | 출처 |
|---|---|---|
| ① | "설치 안내" 노출 기기 | 신규 category 값 → page_title(새 맞춤 정의 0) |
| ② | "설치 안내 누름" 기기 | 같음. **iOS 대리 지표** |
| ③ | "앱 설치" 기기 | 기존 `pwa_install`(28일 0건 기준선) |
| 참고 | first_visit, first_asset_saved 기기 | 기존 이벤트. 깔때기 분모 |

- **목표**: 머지 후 8주 안에 ② 누름 ≥1기기 또는 ③ 앱 설치 ≥1기기(기준선 0 → 0이 아님). 비율 목표는 두지 않는다. 표본이 월 0~수 건이라 %는 의미가 없다.
- **판독 방식(정성 판정, 4주·8주 두 번)**: GA 탐색 보존이 2개월이라 4주차 수치를 그 자리에서 `.memory/STATE.md` 지표 절에 숫자로 남긴다(분모 포함, 기기 수 그대로).
  | 8주 결과 | 판정 | 다음 행동 |
  |---|---|---|
  | first_asset_saved ≥1인데 ① 노출 0 | **조건 결함 의심**(효과 판정 아님) | 노출 조건(모바일 폭·설치 가능 판정·튜토리얼 종료) 점검을 버그 후보로 |
  | ① 노출 > first_asset_saved 기기 | **중복 노출 결함** | 즉시 버그 수정 경로 |
  | ① 0 이고 first_asset_saved도 0 | **판독 불가·보류** | 실패로 보지 않는다. #77 유입 판독과 묶어 8주 연장 1회 |
  | ① ≥1, ②·③ ≥1 | **유지(성공)** | 그대로 둔다 |
  | ① 1~4기기, ②·③ 0 | **보류** | 8주 연장 1회. 연장 후에도 0이면 아래 실패선 적용 |
  | **① 누적 ≥5기기인데 ②·③ 0** | **실패** | 카드 제거(상단바 아이콘만 유지)를 축소 후보로 올린다. 문구·시점 재실험은 하지 않는다(표본이 작아 A/B가 성립하지 않음) |
- 한계: 누름 이후 iOS 실제 홈 화면 추가 여부와 설치 기기의 재방문 횟수는 기기 단위로 이어 볼 수 없다. 재방문 기여는 "설치 기기 ≥1이 생겼다"까지만 주장한다. 대표 기기는 `?ga-optout=1`로 빠진다.

### 4. 하지 않으면 무엇을 잃나 — 중간
- 첫 저장 사용자가 생겨도 재방문 계기 없이 흘려보낸다. 다만 지금 첫 저장 자체가 월 0~수 건이라 단기 손실 규모는 작다. 가치는 #77로 유입이 늘 때 커지므로 **같은 릴리스에 함께 나가는 것**이 근거의 핵심이다. 단독이었다면 "약함"이다.

### 5. planner 이견 판단 — 대안(튜토리얼 종료 후 노출) 채택 권고
- 사업 관점에서도 대안이 낫다. ① 튜토리얼 2·3단계가 상단바를 가리키는 동안 카드가 겹치면 둘 다 덜 읽히고, 첫 저장 직후 화면에 요청이 두 개 쌓여 이탈 위험이 커진다. ② 튜토리얼은 "다음"만 누르면 수 초 안에 끝나 손실 창이 작다. ③ 튜토리얼이 상단바를 짚은 직후 그 아이콘 아래 카드가 뜨면 맥락이 이어진다.
- 남는 손실은 "튜토리얼 도중 새로고침·이탈" 1경로뿐이고 spec 6절에 의도된 손실로 적혀 있다. 받아들인다.
- 확인 요청 1건(차단 아님): 튜토리얼을 **X로 건너뛴 경우**도 종료로 보고 노출되는지 spec 4절 조건 7(`isTutorialFinished` 또는 `activeStep === null`)이 덮는지 tech-review에서 확인해 달라. 건너뛴 사람이 안내까지 놓치면 대상의 상당 부분이 빠진다.

### 6. 문구 검토 — 동의
- 제목 "홈 화면에 추가해 둘까요?" / 본문 "다음부터 아이콘 한 번으로 바로 열 수 있어요." / 버튼 "추가하기"·"나중에" 그대로 동의한다.
- 점검: 금액 0, 투자 권유 0, 보안·데이터 보존 수식어 0(위임 머지 조건 ⑤ 충족), 실제와 다른 기능 설명 0(설치 후 아이콘 실행은 사실). 감성·과장 표현 없음.
- 관찰(문구 변경 요청 아님): iOS는 "추가하기"를 누르면 홈 화면 추가 전에 PIN 4자리 단계가 먼저 나온다. 기대("바로 추가")와 다른 단계라 누름 뒤 이탈이 있을 수 있으나 설치 흐름 diff 0이 확정이라 손대지 않는다. 8주 판독에서 iOS 누름 대비 실제 설치를 알 수 없다는 한계로만 기록한다.

## 경험
### 1. 사용자가 하게 될 행동
1. 모바일 웹에서 첫 자산을 저장하고 홈 튜토리얼(5단계)을 마친다. 그러면 상단바 설치 아이콘 바로 아래에 작은 안내 카드가 한 번 보인다.
2. **추가하기**를 누르면 기존 설치 흐름이 그대로 이어진다. 안드로이드는 브라우저 기본 설치 창이 뜨고, iOS는 지금과 같은 PIN 4자리·복원 코드 단계 안내가 나온다.
3. 이후에는 홈 화면 아이콘으로 앱을 연다. **나중에**를 누르면 이 기기에서는 안내가 다시 나오지 않고, 상단바 아이콘은 지금처럼 남는다.

### 2. 범위
- **포함**: 첫 저장 신호를 세션 메모리에 보관(새 저장 키 0) · 상단바 설치 아이콘에 붙는 1회 안내 카드(누르면 `PwaInstallFlow`를 수정 없이 재사용) · GA page_title 2종 · manifest 아이콘 purpose 분리·`lang`·`categories`
- **줄일 수 있는 것(줄였음)**: 노출 대상은 모바일 폭이면서 iOS이거나 안드로이드 설치 창을 띄울 수 있는 기기로 좁힌다. 데스크톱·인앱 브라우저·설치 창을 띄울 수 없는 안드로이드(이미 설치했는지 구분 불가)는 뺀다. 카드는 문장 1줄과 버튼 2개만 둔다. 노출 위치는 새 자리를 만들지 않고 기존 아이콘에 붙인다.
- **하지 않을 것**: 이미 자산이 있는 기존 웹 사용자에게 다시 제안하기(경과 리마인더 성격이고 새 키가 필요해 LEARNINGS 알림 교훈에 걸린다) · 홈 팁 칸 사용 · 웰컴 화면 수정 · 설치 다이얼로그 문구·단계 변경 · 보안·데이터 보존 문구("더 안전", "데이터 유실 방지" 등. 위임 머지 조건 ⑤) · manifest `id`·`start_url`·`share_target`·screenshots·shortcuts 변경 · 미사용 `PwaInstallBanner` 재사용(자체 localStorage 키가 있어서. 삭제는 4.46 정리 p2 후보로 넘김) · 아이콘 새 에셋
- **manifest 범위**: 현재 192는 `any`만, 512는 `maskable`만 있다. 512 파일은 글리프가 maskable 안전 영역(지름 80%) 안에 있는 풀블리드 정사각형이라(파일 확인) **같은 파일로 512 `any` 항목을 하나 더 선언**한다. 192 `any`와 512 `maskable`은 유지한다. `lang: "ko"`, `categories: ["finance"]`를 추가한다. `id: "/asset"`을 바꾸면 기존 설치가 다른 앱으로 취급되므로 손대지 않는다.

## 합의
1. 모바일 웹에서 첫 자산을 직접 저장한 기기에, **홈 튜토리얼이 끝난 뒤(건너뜀 포함)** 상단바 설치 아이콘 아래 1회 안내 카드를 보여 준다. 원안 "저장 직후 바로"는 버리고 planner 대안을 채택한다.
2. 누르면 기존 `PwaInstallFlow`를 그대로 부른다. 새 저장 키·새 흐름·보안 문구는 0이다. 문구는 경험 5절 그대로 쓴다.
3. 지표는 page_title "설치 안내"·"설치 안내 누름"과 기존 "앱 설치". 목표는 8주 누름 또는 설치 ≥1기기다. 판독은 사업 3절 표대로 정성 판정하고, 실패선은 노출 누적 ≥5기기에 누름·설치 0이며 이때 카드를 제거한다. 4주 수치는 STATE에 기록한다.
4. #77과 한 깔때기로 함께 판독한다.
- 남은 쟁점: 없음. 확인 요청 1건(튜토리얼 X 건너뜀 = 종료 처리 여부)은 tech-review 확인 사항이고 방향 쟁점은 아니다.
- 이견 기록: 노출 시점 원안(저장 직후)과 대안(튜토리얼 종료 후)은 대안으로 정리됐다.
