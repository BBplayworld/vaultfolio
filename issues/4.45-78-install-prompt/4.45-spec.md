# #78 [4.45] 첫 저장 직후 홈 화면 추가 안내 1회 — spec

작성: planner-designer 2026-11-06 · 방향 `4.45-direction.md` · 시각·인터랙션 세부는 ui-designer `4.45-ui.md`

## 1. 문제
웹으로 시작한 사람이 첫 자산을 저장해 가치를 본 시점에 설치 제안이 없다. 설치 진입점은 설명 없는 상단바 아이콘 하나뿐이고, `pwa_install`은 28일 동안 0건이다.

## 2. 목표 행동
첫 저장 직후 같은 세션에서 안내를 한 번 보고 **추가하기**를 눌러 기존 설치 흐름을 끝까지 따라간다.

## 3. 범위
direction 2절과 같다. 새 저장 키 0, 기존 키 쓰기 추가 0, 서버 전송 추가 0(iOS 복원 코드 업로드는 기존 흐름 그대로). `PwaInstallFlow` 파일은 diff 0이다.

## 4. 트리거·노출 조건 (모두 참일 때 1회)
1. **첫 저장 신호**: 이번 세션에서 `trackAssetSave`의 첫 저장 판정과 같은 조건이 성립했다. 조건은 사용자 직접 저장(수동·스크린샷), `result: create`, 직전 보유 0건, 기기의 기존 `gaFlags.firstAssetSent`가 아직 없음이다. 공유 복원·백업 가져오기·동기화 pull은 이 함수를 거치지 않으므로 자연히 빠진다. 신호는 **모듈 메모리에만** 둔다. 새로고침하면 사라지고, 기존 플래그 덕분에 기기당 최대 1회다.
   - 구현 선택(tech-review에서 택1): **A** 판정 분기에서 메모리 신호를 발신한다 / **B** 로드 시점과 현재의 `firstAssetSent`·보유 여부를 비교한다. 둘 다 저장 쓰기를 추가하지 않는다. gtag가 없는 환경(preview·광고 차단)에서도 플래그 판정은 돌아가므로 안내는 뜬다.
2. 체험 모드가 아니다(`isTrialMode()`. 상단바도 체험에서는 설치 아이콘을 숨긴다)
3. 설치 상태가 아니다(standalone이면 `PwaInstallFlow`가 `null`을 반환한다)
4. 인앱 브라우저가 아니다
5. 모바일 폭이다(`useIsMobile`, 768 미만)
6. `isIOS` 또는 `isInstallable`(안드로이드에서 설치 창을 띄울 수 있음)이다. 둘 다 거짓이면 노출하지 않는다(이미 설치했는지 미지원인지 구분할 수 없음)
7. 현재 화면이 홈이고, 자산이 1건 이상이며, 튜토리얼이 진행 중이 아니고(`isTutorialFinished` 또는 `activeStep === null`), 온보딩 마법사가 닫혀 있고, 열린 다이얼로그가 없다
- 한 번 보이면 **추가하기·나중에·홈을 벗어남** 중 하나로 닫히고 이 세션에서 다시 나오지 않는다.

## 5. 사용자 흐름
1. 웰컴(모바일 웹) → "웹에서 바로 시작" → 자산 입력 → 저장
2. 홈 전환 → 튜토리얼 1~5단계(기존) → 끝남
3. 상단바 설치 아이콘 아래 안내 카드 등장(GA "설치 안내" 1회)
4. 추가하기(GA "설치 안내 누름") → `PwaInstallFlow` `onClick`과 같은 동작
   - 안드로이드(`isInstallable`): 기본 설치 창 → 기존 `pwa_install` 이벤트("앱 설치")
   - iOS: 기존 PIN 4자리 다이얼로그 → 복원 코드 → 홈 화면 추가 단계 안내(동기화 기기는 기존 동기화 분기)
5. 카드는 사라지고 상단바 아이콘은 그대로 남는다
- 이미 튜토리얼을 끝낸 기기(예: 전부 지운 뒤 다시 시작)는 2단계가 없으므로 저장 직후 홈에서 바로 3단계로 간다.

## 8. GA (v4.41 규칙: page_title만, 새 맞춤 정의 0)
- 노출 1회: `feature_use`의 새 category 값 → page_title **"설치 안내"**
- 추가하기: 새 category 값 → **"설치 안내 누름"**
- 그 뒤 안드로이드 설치 창·완료는 기존 "앱 설치"를 그대로 쓴다. 체험 모드에서는 `track`이 no-op인 기존 규칙이 적용된다. 값 이름은 developer가 정한다(`PARAM_VALUES.category`에 추가)

## 9. 완료 기준 (qa가 그대로 검사)
1. preview 375 모바일 에뮬레이션, 저장소를 비운 새 세션(iOS UA)에서 수동으로 첫 자산을 저장하고 튜토리얼을 "다음"으로 끝내면 상단바 설치 아이콘 아래에 direction 5절 문구의 카드가 1개 보인다.
2. 1에서 튜토리얼이 진행 중인 동안에는 카드가 DOM에 없다.
3. **추가하기**를 누르면 기존 설치 다이얼로그가 열리고(iOS UA: "데이터 전송용 PIN 번호" 단계), 카드는 사라진다. **나중에**를 누르면 카드만 사라지고 설치 아이콘은 남는다.
4. 1의 상태에서 새로고침하면 카드가 다시 나오지 않는다. 카드를 닫은 뒤 설정 "모든 데이터 삭제"로 0건을 만들고 다시 첫 저장을 해도 나오지 않는다(`clearAssetData`가 `gaFlags`를 보존하기 때문, `asset-storage.ts:428`).
5. 데모 주입(`?demo=1`)·공유 링크 복원·백업 가져오기로 자산이 생긴 기기, 체험(`/?trial=1`), 인앱 UA(카카오톡), 1280 폭, standalone 에뮬레이션에서는 카드가 DOM에 없다.
6. iOS도 아니고 설치 창도 띄울 수 없는 안드로이드 UA에서는 카드가 없다. `beforeinstallprompt`를 합성으로 보내면 카드가 나온다(vitest 또는 Playwright).
7. `git diff --name-only main...issue-4.45` 결과에 direction 3절 "그대로" 목록의 파일이 하나도 없다(#77·#79가 같은 브랜치에서 바꾼 파일은 해당 이슈 범위로 따로 표기). `localStorage`·`sessionStorage`·`STORAGE_KEYS`에 새로 닿는 줄은 0이다(C11 grep).
8. 운영 `/manifest.webmanifest`의 icons는 192 `any`, 512 `any`, 512 `maskable` 3항목이고 `lang`은 `ko`, `categories`에 `finance`가 있으며 `id`·`start_url`·`share_target`은 main과 같다.
9. 새 문구 전부가 320·375에서 어절 중간 줄바꿈 없이 보인다(C25). 금액·투자 권유·보안 수식어는 0이다.
10. GA: gtag 목으로 노출 1회에 "설치 안내" 1건, 누름에 "설치 안내 누름" 1건이 가는지 vitest로 확인한다. 체험 모드에서는 0건이다.
- **알려진 한계**: 실기기 iOS 홈 화면 추가와 안드로이드 실제 설치 완료는 자동 검증할 수 없다. 설치 흐름은 diff 0이라 기존 검증을 그대로 쓴다(C9).
