## 결론
구현 가능. 신규 파일 3개(신호 모듈·판정 순수 함수·카드) + 수정 3개(`ga.ts`·`top-bar.tsx`·`manifest.ts`). 저장 키·gaFlags 쓰기 추가 0, 서버 전송 추가 0. 개발 약 1.5일로 11/10~16 안에 여유 있게 들어간다. 위험 등급 초안 **risk:low**.

## 1. 트리거 A vs B
| | A. `trackAssetSave` 판정 분기에서 모듈 메모리 신호 | B. 로드 시점 대비 `gaFlags.firstAssetSent` 비교 |
|---|---|---|
| 방식 | `writeFlags` 직후(`ga.ts` 약 391행) `markFirstSave()` 1줄 호출 | 마운트 때 플래그를 읽어 두고 이후 true로 바뀌었는지 비교 |
| 장점 | 판정이 기존 AC8 조건(create·직전 0건·플래그 없음)과 정확히 같다. 폴링·구독 불필요 | ga.ts 수정 0 |
| 단점 | ga.ts 1줄 추가 | 플래그는 localStorage라 변경 이벤트가 없어 폴링/저장 후 재읽기가 필요. 상단바 마운트 시점이 저장 전·후 어느 쪽인지에 따라 오판(웰컴에서는 상단바가 `null`이라 로드 시점 값을 못 잡음). 다른 탭이 쓴 플래그도 신호가 됨. localStorage 읽기 줄이 새로 닿아 C11 grep 대상 |
- **추천 A.** 신호는 `src/lib/pwa/first-save-signal.ts`(신규, 순수 모듈: `markFirstSave()`·`getFirstSave()`·`subscribe`, `useSyncExternalStore`용)에 두고 ga.ts는 import 후 호출 1줄만 추가한다. `markFirstSave`는 `track` **앞**, `try` 안에서 호출해 gtag 유무와 무관하게 동작(preview 포함)하고 예외가 저장 흐름으로 번지지 않는다.

## 2. 튜토리얼 종료 후 노출
- 신호 위치: `src/stores/tutorial/tutorial-store.ts`의 `isTutorialFinished`(`completeStep`·`skipStep`이 갱신). 구독은 `useTutorialStore`(`tutorial-overlay.tsx:220`과 같은 방식).
- **주의(spec 4-7 보정)**: 초기값이 `activeStep: null, isTutorialFinished: false`라 `initTutorial()` 전에는 `activeStep === null`이 참이다. 조건은 **`isTutorialFinished === true`만** 쓴다(`activeStep === null` 병기 금지). 튜토리얼을 이미 끝낸 기기는 `initTutorial`(page.tsx:43)에서 true가 되므로 저장 직후 바로 노출된다.
- 다이얼로그 열림: 기존 `screenshot-dialog-toggle`처럼 개별 이벤트가 없으므로 `document.querySelector('[role="dialog"][data-state="open"]')`를 노출 판정 시점(조건 변화 시)에만 읽는다. 온보딩 마법사는 `src/stores/onboarding-wizard-store.ts`의 열림 상태를 구독.

## 3. 카드 마운트·닫기·위치
- `top-bar.tsx`는 `{showInstall && <PwaInstallButton />}`(180행) 옆에 `<InstallNudge />` 1줄만 추가. 헤더가 이미 `relative`이므로 카드는 `absolute right-0 top-full mt-2`, 폭 `min(18rem, calc(100vw - 2rem))`, `z-40`. 모바일(`useIsMobile` 768 미만, 초기 `undefined`는 미노출)에서만 렌더. 헤더 `overflow` 클리핑 여부는 개발 시 확인한다(클리핑이면 portal 없이 헤더 밖 래퍼로 이동).
- 닫기 3경로(추가하기·나중에·홈 이탈)는 모두 모듈 메모리 `dismissed=true`로 처리 → 이 세션 재노출 0. 새로고침 시 신호 소멸(의도). 기기당 1회는 기존 `firstAssetSent`가 보장.

## 4. `PwaInstallFlow` 재사용
render-prop `children({ onClick, loading, isIOS, isInApp, isInstallable })` 시그니처(`pwa-install-flow.tsx:26-33,233`)가 필요한 값을 이미 모두 준다. 카드는 `<PwaInstallFlow>{(t) => ...}</PwaInstallFlow>`로 감싸 `t.onClick`만 쓴다 → **파일 diff 0**. 상단바 아이콘과 별개 인스턴스라 다이얼로그 상태가 둘이 되지만, 한 번에 하나만 열린다(카드가 닫히며 인스턴스가 언마운트되면 다이얼로그도 사라지므로, **카드는 닫지 말고 눌린 뒤 숨김 상태로 유지**하거나 `onClick` 직후 다이얼로그가 열린 뒤에만 카드를 숨기는 방식이 필요). 권장: 카드 컨테이너만 `hidden`, 컴포넌트는 마운트 유지. `isStandalone`이면 Flow가 `null`을 반환 → 조건 3 자동 충족. 인스턴스가 하나 늘어도 `usePWAInstall`이 `__bipEvent`를 전역 캡처하므로 안드로이드 설치 창 이벤트 유실 없음.

## 5. 환경 분기 (순수 함수 `shouldShowInstallNudge(input)` 로 분리)
입력: `{ firstSave, dismissed, trial, standalone, inApp, isMobile, isIOS, isInstallable, isHome, assetCount, tutorialFinished, wizardOpen, dialogOpen }`. 모두 참이고 `isIOS || isInstallable`일 때만 true.
- iOS: `isIOS` 참 → 노출. 안드로이드: `beforeinstallprompt`가 늦게 와도 `isInstallable` state가 바뀌어 재평가됨. 이미 설치한 안드로이드 탭: 이벤트 없음 → 미노출. 인앱·데스크톱·체험·standalone은 각각 위 입력 하나로 차단.
- 체험: `isTrialMode()`(상단바와 동일). GA는 `track`이 이미 no-op.
