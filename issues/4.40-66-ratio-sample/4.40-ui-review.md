## 오류 상태의 예시 버튼 위치 (dev-notes 어긋난 사실 1)
수용(PASS). 오류 시 순서는 dropzone → 고지 → 예시 버튼 → 콜아웃(버튼과 20px, 375에서 y 509~571, 320도 viewport 안). 업로드 계열(dropzone·고지·예시)이 한 덩어리로 묶이고 콜아웃이 그 아래에 붙어 읽기 흐름이 자연스럽고, limit에서 "마감 → 예시로 보기" 연결도 자연스럽다. 버튼-콜아웃 간격·레이아웃 점프 없음. ui.md 2절 위치 문구는 "콜아웃 위"로 정정하면 된다.

## UI 수정 요청 (1건)
**U1. 포커스 이동 실패 — `src/app/ratio/ratio-preview.tsx` 결과 진입 effect(약 L127-134)·`handleSampleExit` rAF(약 L204-207)**
- 실측(375 다크, 일반 모션): 예시 버튼 클릭 1.2초 후 `document.activeElement`=BODY(기대: `ratio-sample-label`). CTA 복귀 후도 BODY(기대: `ratio-dropzone`). reduced-motion에서는 라벨에 정상 포커스.
- 원인 추정: `Unfold`가 열리는 같은 커밋에서 `focus()`를 호출하는데, `visibility` 전환의 시작 시점(진행 0)에는 계산값이 hidden이라 포커스가 거부되고, 클릭한 버튼이 `inert`가 되며 포커스가 body로 빠진다. 4.39 실제 결과(`ratio-count`)도 동일하게 BODY(모킹 real 확인)여서 기존 결함이 예시 모드로 드러난 것.
- 기대값: 일반 모션·reduced 모두 sample 진입 후 activeElement=`ratio-sample-label`, 복귀 후 `ratio-dropzone`(오류 limit 복원 시에는 비활성이라 제외). 방법은 developer 판단(예: 열림 후 첫 프레임 이후/`transitionstart` 시점에 focus, 또는 열릴 때 visibility 지연 제거). 스크롤 동작은 현행(scrollY 0, label y≈177) 유지. 실제 결과 쪽 포커스도 같은 수정으로 함께 고쳐지면 좋음(범위 확대 아님, 같은 공용 로직).
- 영향: 스크린리더·키보드 사용자가 전환 후 문맥을 잃음(§7). 시각 사용자 영향은 없음.
