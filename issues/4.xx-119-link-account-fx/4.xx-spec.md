# 4.xx #119 거래 연결 계좌 — 해외주식을 원화 계좌·대출로 연결 — spec

기준: origin/main 9a28a9f(v4.62). 정본: 같은 폴더 direction(합의)·challenge(축소 통과, B 필수 구현 규칙·G1~G7). 승인 경로: 대표 결정 11-09 '기획 누락 보완' → COO 자체 승인, 대표 보고 없음. risk:medium.

## 1. 문제
v4.58 `연결 계좌`는 같은 통화 현금만 후보로 둔다(`linkCandidates`). 원화 예수금으로 미국·일본 주식을 사는 사용자(USD·JPY 현금 없음)는 해외 종목을 고르면 행이 안내 없이 사라지고, 원화 현금을 따로 고쳐야 한다. 고치지 않으면 결산에 '해외주식 증가'와 '현금 감소'가 짝 없이 따로 보인다. 원인: #103 흐름 표(C42)에 통화 축이 없었다(C49).

## 2. 목표 행동
해외주식 거래를 기록할 때 `연결 계좌`에서 원화 통장(또는 대출)을 고르고, 보조 줄의 환산식(`$1,235.73 × 1,390원 …`)을 확인한 뒤 저장한다. 현금 화면에 따로 가지 않는다. 거래를 지우면 원화 통장이 저장 때 바뀐 금액 그대로 돌아온다.

## 3. 범위
- **포함**: 외화(USD·JPY) 주식 거래의 후보 = 같은 통화 현금 + **원화 현금 + 대출**(매도 시 잔액 0 대출 제외). 원화 연결 짝 기록은 KRW, 금액 = 거래 금액 × 체결 환율. 계좌 선택 시 빈 `체결 환율` 칸 채움. 보조 줄 환산식. 지난달 거래일 때 안내 1줄(국내·코인 공용 행에도 동일).
- **줄일 수 있는 것(축소 순서)**: ① 외화 거래의 대출 연결 → ② 지난달 안내 1줄. 원화 현금 연결과 데이터 안전(G2~G4)은 줄이지 않는다.
- **하지 않을 것**: 외화 현금 ↔ 원화 종목(국내·코인) 연결, 환전 기록 모델, 스크린샷 가져오기·보유 현황 업데이트·잔고 맞추기·즉시 반영 끔의 연결, 처음 사는 티커의 거래 입력, USDT, 이번 달 제한 해제, 거래 수정 화면, 새 GA 이벤트.

## 4. 사용자 흐름
1. FAB > 매수/매도 거래 기록 > 주식 > 직접 입력(또는 주식 상세 '거래 추가'·거래 목록 '+') → 해외 종목(예: Apple) 선택.
2. 즉시 반영 켬 + 거래일 이번 달 → `연결 계좌` 행 표시. 후보 순서: 같은 통화 현금 → 원화 현금 → 대출.
3. 원화 통장 선택 → `체결 환율` 칸이 비어 있으면 현재 환율로 채워 보인다(USD 원/$, JPY 원/100엔, 수정 가능). `연결 안 함`으로 되돌려도 채운 값은 유지.
4. 보조 줄이 환산식으로 바뀐다(예: `$1,235.73 × 1,390원만큼 현금이 줄어요 (수수료 포함)`, 금액·통화 = 선택 계좌 통화 원화). 문구는 ui.md.
5. 저장 → 거래(`exchangeRate` 채움) + KRW 짝 기록(`ctx_/ltx_link_<거래 id>`) + 계좌 잔액 변경을 saveData 1회.
6. 거래 삭제 → 다이얼로그에 원화 금액 표시 → 짝 기록의 현재 원화 금액으로 되돌림(환율 재계산 없음).
7. 거래일을 지난달로 바꾸면 행이 숨고, 후보가 있었다면 muted 안내 1줄(뜻: 지난달 거래는 계좌 잔액을 함께 바꾸지 않음)이 남는다. 저장 결과 = 연결 안 함.

## 6. 엣지 케이스
- **환율 빈칸·지운 채 저장**: buildTransaction이 현재 환율로 채워 저장(화면 setValue만으로 처리 금지). 저장 데이터 `exchangeRate` > 0.
- **현재 환율 0·미수신 + 칸 빈칸**: 사유 `rate`로 저장 차단, 오류 줄(문구 ui). 연결 안 함으로는 저장 가능.
- **소수 수량·USD 중간 반올림**: 0.5주×$123.45 = $61.725 → 원화 = round(61.725×1,390) = **85,798원**(USD 0.01 먼저 반올림한 85,805원이 아님). 원화 금액 = roundMoney((수량×단가 ± 수수료) × `tradeKrwRate`, "KRW").
- **`priceInKrw` 모드**: 미리보기 = 저장 = 짝 금액이 같은 식(달러 단가 × 환율). 입력 원화 총액과 차 ≤ 수량×0.0005×환율 + 1원.
- **잔액 = 대금**: 원화 통장 1,717,665원에서 위 USD 매수 → `zero` 오류(0원 현금 불가), 문구 통화 = 원화.
- **잔액 부족**: `balance` 오류, 금액 원화 표시.
- **지난달 거래일**: 행 숨김 + 안내 1줄(후보가 있을 때만), 저장 데이터 = 연결 안 함. 즉시 반영 끔·계좌 0개면 안내 없이 숨김.
- **빈 데이터·첫 사용자**: 현금·대출 0개 → 행 숨김(기존). 보유 종목 0 → 거래 입력 자체 불가(기존).
- **구버전 기기(v4.58~v4.62)·롤백**: 원화 짝 기록은 기존 KRW 기록 형식 → 읽기·삭제 되돌림·결산 정상. 롤백 시 새로 만들 수만 없어짐, 손실 0.
- **부수 효과(의도)**: 원화 연결 매수는 가중평균 환율에 채운 환율 반영(`trade-utils.ts:75`), 원화 연결 매도는 양도세 추정의 `estimated` 표시 빠짐. 연결 없는 외화 거래 diff 0.

## 7. 데이터 계약
- 새 필드·저장 키·zod·동기화·공유 토큰·서버 전송 diff **0**. 마이그레이션 불필요.
- 거래 `exchangeRate`(기존 optional)를 원화 연결 시 **저장 시점에 반드시 채운다**. 짝 기록 = 기존 KRW `CashTransaction`·`LoanTransaction`, id 규칙 그대로.
- 메모리 전용 `LinkTrade`에 `exchangeRate?` 추가 허용(저장 형식 아님). `tradeKrwRate` export 1줄 외 엔진(change-hero·asset-report) 로직 수정 0. 환산은 `buildLink` 한 곳(미리보기 `evaluateLink`도 같은 함수). 표시 통화 = 선택 계좌 통화.
