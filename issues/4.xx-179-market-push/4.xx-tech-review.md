- 신규: `src/app/api/push/{subscribe,test,cron}/route.ts`, `src/lib/push/*`(VAPID·발송·문구), 설정 UI(더보기 설정, #81 계열), 로컬 설정 헬퍼
- 수정: `public/sw.js`(push·notificationclick 추가, CACHE_NAME 올림), `vercel.json`(crons), `src/lib/cache-storage.ts`(구독 메서드 추가), `package.json`

## 2. 판정 ① Web Push 구성
- payload 암호화(RFC 8291 aes128gcm)+VAPID JWT(ES256) 직접 구현은 가능하나 보안 코드 자작 위험. **`web-push` 도입 권고**(Node 런타임 전용, 의존성 소수, 검증됨). 근거 기록 필요(CLAUDE.md 신규 라이브러리 규칙). 대안 "빈 push+SW가 공개 API fetch"는 라이브러리 불필요·VAPID JWT만 직접 서명하면 되지만, fetch 실패 시 폴백 문구가 약하고 iOS에서 불안정 → 비권고.
- VAPID 키: `VAPID_PUBLIC_KEY`(클라이언트용은 `NEXT_PUBLIC_`)·`VAPID_PRIVATE_KEY`·`VAPID_SUBJECT`는 Vercel 환경 변수로만. 저장소·로그·메모리 기록 금지. 키 생성·등록은 대표(운영자) 작업이며 개발자는 값을 보지 않는다.

## 3. 판정 ② 구독 저장소
- 기존 Upstash Redis(`getCacheStorage()`, 락·카운터·share 키와 같은 패턴) 재사용. **동기화 금고(`csync:asset:*`)와 키 공간·로직 분리**. CacheStorage 인터페이스에 `putPushSub/deletePushSub/listPushSubsByTopic` 추가(로컬 FileCacheStorage 구현도 필요).
- 저장 항목: `id=sha256(endpoint)`, endpoint, p256dh, auth, 토픽 목록, 조건 코드, 생성·갱신 시각. **IP·UA·assetId·기기정보 저장 금지**, 로깅 금지(rate limit 카운터가 IP를 쓰는 기존 방식은 해시/단기 TTL 유지).
- 삭제: 발송 시 404/410 즉시 삭제, 설정에서 해지 시 DELETE(endpoint 소지가 인증), TTL 90일+앱 열 때 갱신(pushsubscriptionchange 포함)으로 고아 정리, "모든 삭제"·체험 모드 경로에 구독 해제 포함.
- 토픽 역색인(`push:topic:{id}` set)으로 발송 시 전체 스캔 회피.
- 익명성 주의: 자유 선택 종목은 관심·보유 힌트가 되므로 **대상은 서버 고정 카탈로그(지수·대표 ETF·시총 상위 10여 개)로 한정**, 가능하면 프리셋 3개 묶음. 조합 수가 적을수록 지문화·역산 위험 낮음.

## 4. 판정 ③ 스케줄러(Vercel Cron)
- `vercel.json`에 crons 신설(현재 없음). Cron은 **UTC 고정·DST 미반영**, production에서만 실행, `CRON_SECRET` Bearer 검증 필수(미설정 시 거부).
  - 국내 마감 15:40 KST = 06:40 UTC 평일
  - 미국 마감: 06:10 KST(=21:10 UTC, 서머타임) / 07:10 KST(=22:10 UTC, 표준시) **두 개 모두 등록**, 핸들러가 미국 시장 마감 여부·휴장일을 확인하고 Redis 날짜 키로 중복 발송 방지
  - 큰 변동 체크: 장중 평일 N분 간격(권고 국내 30분, 미국은 KST 22:30~06:00 구간 30분). 일일 상한 기기당 1~2건, 같은 대상 쿨다운으로 스팸 방지
- **확인 필요: Vercel 플랜.** Hobby는 하루 1회·시각 정밀도 ±1시간이라 위 구성 불가(Pro 필요). 미확인 → 가정.
- KIS: 시세 조회는 **구독자 수와 무관**하게 고정 카탈로그(약 10~15개)를 cron 1회에서 일괄 조회(해외는 종목별 호출이라 상한 있음). `withinUpstreamBudget("kis", n)`·서킷 open 시 건너뜀(알림 생략, 재시도 안 함)·기존 `getStock` 캐시 우선. 분당 900 대비 미미. 발송은 `Promise.allSettled` 청크 병렬, `maxDuration` 상향 필요(구독자 수천 시 분할·재진입 설계 필요 → P2 위험).

## 5. 판정 ④ SW·플랫폼
- `push`: `event.waitUntil(showNotification(title,{body,tag,data:{url}}))`, payload 파싱 실패 시에도 중립 문구로 항상 표시. `notificationclick`: 열린 창 focus 또는 `openWindow`. 이동 화면은 홈 `/`(또는 기존 시장 화면이 있으면 그쪽 — 확인 필요). **앱 잠금(PIN)은 UI 게이트라 앱이 열리면 자연히 잠금 화면 표시, 알림 본문에 개인 정보가 없어 충돌 없음.**
- 권한 요청은 반드시 버튼 클릭(사용자 제스처) 핸들러 안에서 `Notification.requestPermission()` → `pushManager.subscribe({userVisibleOnly:true, applicationServerKey})`. 앱 첫 진입·자동 요청 금지.
- iOS 16.4+: **홈 화면 설치 PWA에서만**, 미설치 Safari 탭은 불가 → 설치 안내(#78)와 연동, 미지원 시 설정 항목 숨김/안내. 기능 감지(`PushManager`·`Notification`). iOS는 구독 정리·지연이 잦아 신뢰도 낮음(고지). Android Chrome은 안정. 거부 상태는 설정 앱 안내로 복구 문구.
- 문구: 시세 사실만 중립 서술, 투자 조언·권유·금액 마케팅 금지.

## 6. 판정 ⑤ 설정 저장·동기화
- 로컬 키 1개 신규(예: `secretasset_push_prefs` = 토픽·조건·구독 여부). **기존 자산 스키마 변경 없음 → 마이그레이션 불필요**(키 없으면 기본 off). 단 "저장 키 추가"로 머지 위임 조건 ④ 해당 → 위임 불가(대표 승인).
- 동기화 금고에는 **넣지 않는다**: 구독은 기기별이고 서버가 금고 내용을 모르는 구조 유지. 다기기는 기기별 설정. 백업·공유 토큰·성적표 계산 영향 0. 구버전 혼재·롤백 시 신규 키는 무시되어 자산 기록 손실 없음(서버에 고아 구독만 남고 TTL로 정리).

## 7. 판정 ⑥ preview 데모
- Cron은 preview에서 실행되지 않음 → **테스트 발송 버튼**(`/api/push/test`: 호출한 구독 자기 자신에게만 샘플 알림 1건, `isPreviewEnv()` 또는 레이트리밋으로 제한)으로 시연. 장 마감·큰 변동 문구는 샘플 데이터로 미리보기.
- preview 전용 VAPID 키쌍을 Vercel Preview 스코프 환경 변수로 분리(구독은 공개키에 묶여 운영과 호환 안 됨 = 안전). 운영 Redis 오염 방지: preview는 키 prefix 분리 또는 별도 Redis(확인 필요; 현재 preview 동기화 쓰기는 꺼져 있음).
- 한계: 알림 권한·SW는 origin별 → preview URL에서 따로 허용·(iOS는) preview 도메인으로 홈 화면 설치 필요. Vercel Deployment Protection이 켜져 있으면 SW·push 등록 영향 가능(확인 필요).

## 8. 서버로 나가는 값
늘어남: endpoint·p256dh·auth, 토픽(고정 카탈로그 ID)·조건 코드. 자산 수량·금액·보유 종목은 0. 역산 불가 근거: 토픽은 보유와 무관한 고정 목록 선택, 알림 내용은 전원 공통 시장 정보, 서버는 구독자별 개인 데이터를 보유하지 않음. 잔여 위험: endpoint가 기기 식별자(IP·UA 저장 금지로 완화), 토픽 조합 지문(프리셋화로 완화).
