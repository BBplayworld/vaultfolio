작성: ui-designer, 2026-11-06 / 대상: `/guide/stock-ratio`, `/guide/net-worth` / 근거: 4.45-direction·spec, design-system §1~§3·§6·§7, `src/app/ratio/page.tsx` 코드 판독

## 1. 결론
- **신규 공용 컴포넌트 0.** `/ratio` 껍데기(main > max-w-480 > header)를 가이드 2편이 같은 마크업으로 쓴다. 두 글의 중복은 `src/app/guide/_components/guide-article.tsx`(라우트 로컬 1개, 공용 카탈로그 등록 대상 아님)로 묶는다. 본문 데이터는 문구 상수 파일의 배열(단계 {title, body}[])을 받는다.
- 기존 재사용: `Logo`, `Button variant="brand"`·`variant="secondary"`, `MAIN_PALETTE[0]`, `APP_CONFIG.name`. 새 토큰·색·그림자 0.
- 푸터: `/ratio`에는 푸터가 없다. 가이드 푸터는 새 영역을 만들지 않고 "다른 가이드 링크 + 브랜드 문장" 한 블록으로 끝낸다.

## 4. 면·radius·간격 (톤차 면, 헤어라인, 단색)
- 이미지 없음 전제의 시각 리듬은 **번호 + 헤어라인 + 톤차 면 1장** 세 가지로 만든다.
  1. 단계 번호: 원형 칩이 아니라 **단색 숫자 텍스트**. `text-[11px] font-semibold tabular-nums text-primary`(캡션 단계: 스텝 숫자 허용 항목), h2 위 줄에 "1단계" 식 말고 숫자만 `01`~`04`로 둔다. 컬러 아이콘 칩 금지(§3.2). 번호 장식은 `aria-hidden`, 순서 의미는 `<ol>`이 전달.
  2. 단계 구분: 단계 사이 헤어라인 `border-t border-border dark:border-border/40 pt-5` (첫 단계 제외). 라이트에서 `border-border` 단독 사용(알파 단독 금지).
  3. "시크릿에셋으로 하면": `rounded-xl bg-card p-4 dark:border dark:shadow-sm` 면 1장(라이트=톤차만, 다크=card 톤 + 기존 카드 규칙). 안쪽 강조 박스가 필요하면 `rounded-lg bg-muted/30`(동심 xl->lg).
- 이 면 하나만 카드다. 단계를 카드로 쪼개지 않는다(카드 난립 방지, 글 읽기 흐름 유지).
- 그림자·그라데이션·색 아이콘 없음. lucide 아이콘은 쓰지 않거나, 쓰면 단색 `text-muted-foreground`(링크 화살표 `ArrowRight size-4` 정도).

## 5. 행동 블록
- 컨테이너 `flex flex-col gap-2`.
- 주 버튼: `<Button variant="brand" className="h-11 w-full text-sm font-semibold break-keep">` (44px >= 40). `/ratio`로 가는 경우 `asChild` + `<Link href="/ratio">`(링크 시맨틱, UTM 없음), 체험은 `<Button>` 클릭 핸들러(`trackThenNavigate`). 가이드2의 주 버튼=체험이므로 button, 가이드1의 주 버튼=링크.
- 보조: `<Button variant="secondary" className="h-11 w-full ...">`로 통일(텍스트 링크로 낮추면 두 번째 입구가 약해지고 히트영역 미달 위험). secondary는 `outline` 금지 규칙에 부합.
- 버튼 문구 최종: "캡처로 내 비중 보기" / "예시 데이터로 둘러보기"(spec 그대로, 어절 2~3개라 320에서 1줄). 버튼 안 `whitespace-nowrap` 기본이므로 320에서 넘침 없는지 ui-review 필수.
- 눌림은 Button 기본 tapScale(0.96) 사용. 추가 모션 없음, 페이지 진입 모션 없음(정적 SSR, FOUC·CLS 방지). 로딩·빈·오류 상태 없음(데이터를 읽지 않음). 체험 클릭 직후 이동까지 `disabled` 불필요(연타는 trackThenNavigate 기존 처리 따름 — 연타 시 이벤트 중복이면 developer가 1회 가드).
- 하단 링크: `<nav aria-label="다른 가이드"><Link class="inline-flex min-h-10 items-center text-sm font-medium text-primary">월말 순자산 정리하는 법 -></Link></nav>`. 앞에 muted "다른 가이드" 라벨 없이 링크 텍스트 자체가 글 제목.
- 브랜드 마무리: `mt-2 text-center text-sm text-muted-foreground` "안전한 자산 관리, 시크릿에셋".

## 6. 다크·라이트
- 전부 시맨틱 토큰만(`background/card/foreground/muted-foreground/primary/border`) -> 자동 대응. 하드코딩 hex 0.
- 링크·번호 `text-primary`(#5b6fbf 계열): 라이트 배경(#F0F2F4)에서 대비 약 4.3:1 근처라 **본문 크기(14px) 링크는 `font-medium` + 밑줄(`underline underline-offset-4`)을 기본 상태에 둔다**(색만으로 링크 구분 금지, 대비 보강). card 면 위(흰색)는 4.9:1 수준. 정확한 대비는 ui-review에서 측정, 4.5 미달이면 `text-primary` 대신 `text-foreground` + 밑줄로 후퇴.
- 번호 `01`은 11px 장식이라 대비 비필수지만 `aria-hidden`이므로 정보 손실 없음.
- 다크: card #191C22 면이 bg #0B0D12 위에서 분리되는지, 헤어라인(`border-border/40`)이 보이는지 확인.

## 7. 접근성
- 제목 위계: h1 1개 -> h2(단계 3~4 + "시크릿에셋으로 하면") 전부 같은 레벨. h3 사용 안 함. `<main>` 1개, `<header>`, `<nav>`, `<ol>` 시맨틱. 단계 h2를 `<li>` 안에 둔다(`ol > li > h2 + p`).
- 스킵 링크 불필요(DOM 길이 짧음). 로고는 장식 -> `aria-hidden`(서비스명 텍스트가 이름).
- 링크 이름이 목적을 말함(복수 "자세히 보기" 금지). 외부 이동 없음. 포커스 링은 전역 규칙 유지(`outline-none` 임의 추가 금지).
- 히트영역: 버튼 h-11, 텍스트 링크 `min-h-10`(본문 중간 링크는 줄 안 인라인이라 예외 불가 -> 본문 중간 링크도 별도 줄 `block min-h-10 py-2`로 둔다).
- 대비: 본문 `text-foreground/90`, 보조 `text-muted-foreground` 모두 §1.1 토큰(AA 이상 보장 범위).
- `prefers-reduced-motion`: 모션 자체 없음.

- 금액·%·종목명·권유어 0(spec 5절). 새 보안 문장 0: 필요 시 `RATIO_PREVIEW_UPLOAD_NOTICE` 원문을 "시크릿에셋으로 하면" 면 마지막 줄에 `text-muted-foreground` 그대로 인용.
- `data-screenshot-hide` 대상 없음(스크린샷 기능과 무관한 공개 페이지).

## 11. 품질 체크리스트 (qa·ui-review 판정용)
1. 375·1280 × 라이트·다크 4장: 컬럼 max-w-480 중앙, 좌우 거터 12px, `/ratio`와 헤더 높이(40)·로고 크기(22)·서비스명 같음.
2. h1은 text-xl(1280은 2xl) bold, 375에서 2줄 이내, h2는 모두 같은 크기(16px semibold). 위계가 한눈에 4단계(h1>h2>본문>보조)로 읽힌다.
3. 본문 계산 스타일: font-size 14px(sm 이상 15px), line-height >= 1.5(권장 28px), `word-break: keep-all`, `text-wrap: pretty`.
4. 320·375 모든 한글 블록(h1·요약·단계·면·버튼·링크·브랜드 문장)에서 어절 중간 줄바꿈 0, 가로 스크롤 0 (C25: 전수 확인, 슬래시 어구 nowrap).
5. 버튼 2개 높이 >= 44px, 폭 100%, 텍스트 링크 클릭 박스 높이 >= 40px(Playwright boundingBox).
6. 주 버튼 배경이 `--brand`(#5b6fbf) = MAIN_PALETTE[0], 보조는 secondary(테두리 없음). 라이트에서 카드 외곽선·그림자 없음, 다크에서만 `dark:border`.
7. "시크릿에셋으로 하면" 면이 캔버스 대비 톤차로 분리(상대 대비 >= 1.10:1), 다른 카드는 없음.
8. 단계 번호는 단색 숫자(칩·아이콘 배경 없음), 단계 사이 헤어라인이 라이트·다크 모두 보인다.
9. 본문 링크는 밑줄 포함, 링크 텍스트 대비 >= 4.5:1(라이트·다크), 키보드 Tab 순서가 위->아래이고 포커스 링이 보인다.
10. JS 끈 상태에서 레이아웃 동일(정적 SSR, CLS 0, 진입 모션 없음).
11. 제목 구조: h1 1개, h2만 사용(h3 없음), `ol > li` 단계, `nav` aria-label 존재(접근성 트리 스냅샷).
12. 새 색·그림자·그라데이션·이미지·아이콘 칩이 diff에 0, 하드코딩 hex 0. `/ratio` 파일 diff 0.
13. 두 글의 레이아웃·간격·위계가 서로 동일하고 글 길이 차이만 다르다(스크린샷 나란히 비교).
14. 체험 버튼 연타 시 이동 이벤트 1건(developer 가드 확인).

## 12. 스크린샷 검수 항목 (ui-review)
- 해상도: 320·375·1280 × 라이트·다크 × 2편 = 12장 + `/ratio` 1장(톤 비교).
- 각 장에서 체크: 어절 끊김(C25), 하단 버튼이 첫 화면에서 안 보여도 스크롤 도달 가능, 단계 번호 정렬(좌측 광학 정렬, 번호와 h2 기준선), 헤더와 `/ratio` 겹쳐 놓았을 때 위치 일치.
- 결과 표기: `UI 승인` 또는 `UI 수정 요청: <파일·요소·기대값>`.

## 13. 교차 검토 메모
- spec: 승인. 단 "푸터"가 spec 구조에 없으므로 이 문서에서 "다른 가이드 링크 + 브랜드 문장"으로 정의했다(새 영역 아님). 본문 문구는 한 문장 40자 내외 요청(9절).
