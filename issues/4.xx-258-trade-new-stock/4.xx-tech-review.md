## 2. 판정
**1) 구현 경로**
- 가능. 검색 로직은 `selectResult`가 `form.setValue`·`fetchPrice`(주식 추가 폼 전용 state)에 묶여 있으므로, 공용 컴포넌트는 **검색·드롭다운·키보드만** 소유하고 선택 결과는 `onSelect`로 올린다. 시세 조회는 공용에 넣지 않는다(주식 추가는 기존 `fetchPrice` 그대로, 거래 입력은 새로 작성).
- 주의: `stock-input.tsx fetchPrice`는 성공 시 `financeApiErrorCount`를 `removeItem`(쓰기)한다. spec 6절은 "읽기만"이므로 거래 쪽 조회는 카운터 읽기만 하고 쓰지 않는다. 조회 코드를 공용화하지 말 것(공용화하면 주식 추가 동작이 바뀌거나 spec 위반).
- **AC-12 회귀 위험(중)**: 주식 추가는 `editData`일 때 검색 비활성, `selectedCategory` 변경 시 검색 상태 초기화, 선택 시 `fetchPrice` 호출 순서가 있다. 공용 컴포넌트에 `disabled`(=`!!editData`)와 `market` 변경 시 내부 초기화를 그대로 옮기고, 기존 F-STOCK 회귀 + 추출 전후 키보드·빈 결과 문구 단언 테스트(컴포넌트 단위)로 막는다. 추출이 위험하면 폴백: 거래 입력 쪽에 검색을 복제하지 말고 추출을 마지막 커밋으로 분리해 단독 revert 가능하게 한다.
- `addTransactionsBatch([tx], [], [newStock], link)` **그대로 사용 가능**(`asset-data-context.tsx:1627`). 현재 기존 신규 자산 경로(`trade-input.tsx onSubmit`)와 동일 호출이며 `link`는 `txs.length===1`일 때만 허용. 실패 시 `buildLink` !ok → false 반환, 저장 안 됨 = AC-8 충족.
- 구조 포인트: 현재 `newStockDraft`는 `groupRep`(보유 종목) 복제에 의존한다. 검색 경로는 보유가 없으므로 `pickedNew`(ticker·name·market→category·currency) state를 두고 `newStockDraft`가 `groupRep` 또는 `pickedNew`에서 만들도록 분기한다. `selectedGroupId` effect(`setTarget` 초기화, 139~147)가 검색 선택 직후 target을 지우지 않도록 `pickedNew` 있을 때는 건너뛴다(핵심 버그 후보). 보유 0개 시 `categoryOptions`가 비므로 카테고리 필터는 이미 숨겨진다.

**2) AC-4·AC-17**
- AC-4: 비교는 **trade-input 호출부**에서 한다. 양쪽 모두 `normalizeTicker({ticker, category})`(`finance-service.ts:147`)를 통과. 검색 결과의 category는 선택한 시장(국내→`domestic`, 해외→`foreign`)로 만들어 넣어야 하고, 보유 쪽은 각자 category로 정규화된다. 국내 4종(domestic/irp/isa/pension)은 6자리 추출, 해외는 대문자+`.`→`/`. 즉 `005930.KS`↔`005930`, `aapl`↔`AAPL` 일치. 해외 vs 국내 category 교차 비교는 하지 않는다(코드가 같은 6자리 영숫자일 때 오일치 방지: 보유 후보를 시장 군으로 먼저 거른 뒤 비교). 일치 시 `setSelectedGroupId(rep.id)`로 기존 경로 진입 → 저장은 기존 거래 경로.
- AC-17: **UI만으로 가능, 저장 함수 diff 0.** `StockTargetPicker.onChange`는 `{kind:"new", broker, category}`를 올려보낸다. 호출부(`trade-input.tsx` `onChange={setTarget}` 자리)에서 `groupCandidates` 중 `broker===새 broker && category===새 category`인 항목이 있으면 `setTarget({kind:"existing", stockId})`로 바꿔 보낸다(검색 경로는 정규화 티커 비교 후 같은 후보군 사용). picker 안에서 처리하지 않는 이유: picker는 스크린샷 가져오기도 쓰므로 화면 diff 0(AC-14) 보장. 단 스크린샷 쪽 같은 결함 가능성은 "AC-17 판정 변경 제외" 문구대로 이번엔 trade-input만 고친다. 경계: broker 빈 값("")은 매칭하지 않는다(미선택 상태).

**3) AC-9 임시 현재가·baseDate 비움**
- `stockSchema`(`types/asset.ts:41~53`): `currentPrice`>0 필수, `baseDate` optional → 체결 단가(USD 환산 후)를 넣고 baseDate 생략하면 통과. 저장 경로(`saveData`)는 `asset-storage.ts:37` 스키마도 `baseDate` optional.
- 시세 갱신: `asset-data-context.tsx:505` `if (s.baseDate === currentSlot) continue;` — baseDate가 undefined면 항상 outdated로 판정돼 다음 갱신에서 조회·`buildStockPricePatches`(`price-patch.ts:37`)가 currentPrice·baseDate를 채운다. 문제 없음. 조회 실패가 계속되면 체결 단가가 현재가로 남아 손익 0%로 보이는 것은 spec 안내 줄로 고지(알려진 한계).
- 오늘 날짜를 baseDate에 넣으면 해당 슬롯 스킵되어 갱신이 안 되므로 spec대로 비움 유지(구현 시 단언 테스트 필수).
- 요약 안내 줄 조건은 "조회 실패"이지 "체결일이 이번 달"이 아니다(AC-9 마지막 문장) — 연결 행 숨김 규칙과 분리해 구현.

**4) GA 충돌**
- 5.134 head는 main 대비 `ga.ts`에 `home_my_stock`(#246)을 같은 category 배열(89행, 한 줄)·`CATEGORY_TITLES`(213행)에 추가했다. #258은 5.134 브랜치 위에서 작업하므로 이 상태를 기준으로 2개를 덧붙이면 충돌 없음. 주의: 배열이 한 줄이라 다른 이슈가 같은 줄을 동시에 건드리면 병합 충돌이 나기 쉽다 → 맨 끝(`stock_decision_view` 뒤)에 추가하고 push 직전 `git pull --rebase`. `track()` 기존 기대값 변경 0, 새 title 2줄만 추가.
- 전송 시점: `onSubmit` 신규 분기의 `addTransactionsBatch` 성공 직후, `pickedNew` 경로일 때만(기존 증권사 분할 신규 자산·AC-4/17 전환은 미전송). `trackLinkedTrade(link)` 옆에 호출.

**5) 수정 금지 영역**
- 무변경 가능: `addTransactionsBatch`·`buildLink`·`removeLink`·`stockSchema`·`effects`·`link-text`·`linked-record`·동기화·공유 토큰·저장 키. 새 stock은 기존 신규 자산 경로가 만드는 필드와 동일(positionSource=computed, positionEffectiveDate=체결일). 삭제 되돌림(AC-11)은 기존 신규 자산 거래와 같은 데이터 형태라 코드 변경 없음(테스트로 확인).
- 서버 전송 증가: 없음(`/api/ticker-search` 검색어, `/api/finance` 티커 — 기존 호출). 사용자 보유 값 전송 0.
- 중단 조건(spec 7절): 위 영역 수정·기존 테스트 기대값 변경이 필요해지면 즉시 중단, risk:high.

## 3. 로컬 스키마·데이터 영향
스키마·키·마이그레이션 변경 0 → 마이그레이션 테스트 불필요(대신 AC-10·AC-11로 데이터 영향 확인). 영향 범위는 저장·스냅샷·거래·백업·성적표에 "새 stock 1개 + 거래 1건 + 짝 기록 1건" 추가뿐이며 모두 기존 형식. 구버전 기기 혼재: v4.56+가 읽음. 롤백(revert) 후 이미 저장된 데이터는 그대로 유지·표시(기존 신규 자산 경로 산출물과 동일).

## 4. risk 재판정
**medium 유지.** 근거: 저장 함수·스키마·effects 0변경, 서버 전송 0. 다만 (a) 결산 단언 대상(원인 분류) (b) `stock-input.tsx` 추출로 기존 화면 회귀 가능성이 있어 low로 낮추지 않는다. 상향(high) 조건은 spec 7절의 중단 조건과 같다.

## 5. 규모와 줄이는 방법
**M**(신규 컴포넌트 1 + 파일 5 수정, 테스트 3~4). spec보다 커질 위험 지점: 검색 추출. 줄이는 순서: ① 공용 컴포넌트는 입력·결과·키보드만(조회·토스트 제외) ② 추출이 어려우면 거래 입력용 얇은 검색 UI를 만들되 `runSearch` fetch 부분만 `src/lib/` 유틸 1개로 공유(AC-12 위험 최소, 대신 키보드 중복) — 이때는 CEO 확인.

## 6. 테스트 계획
- 유틸·순수 로직 단위: 새 종목 초안 빌드(국내/해외, 환산 USD 가격, baseDate 비움), AC-4 정규화 일치 판정 함수(005930.KS↔005930, aapl↔AAPL, 국내/해외 교차 불일치), AC-17 판정 함수(broker·category 일치/빈 broker). 판정 로직은 `src/lib/trade/`의 순수 함수로 빼서 테스트한다(컴포넌트 렌더 의존 최소).
- AC-10 결산 단언(별도 파일·describe, 기존 `linked-c42.test.ts`·`linked-krw-conv.test.ts` 패턴 재사용): 픽스처 ⓐ국내+원화통장 ⓑ해외+원화환산 ⓒ대출 ⓓ연결 안 함. 저장 결과를 만든 뒤 주·월·연 causes에서 `주식 매수`·`신규 현금`·`기록 안 된 변화` 부재, Σ원인=Δ순자산(ⓐ~ⓒ), ⓓ는 기존 `주식 추가` 분류와 동일. 비교 기준은 착수 직전 5.134 head(dev-notes에 SHA).
- 저장: AC-8(오류 시 stocks 길이 불변)·AC-11(삭제 되돌림 후 stock·짝·잔액).
- `ga.test.ts`: 기대값 2줄 추가(spec 8절 그대로), 기존 기대값 변경 0.
- AC-12: 공용 검색 컴포넌트 단위 테스트(키보드 ↑↓Enter Esc·0건 문구·market 변경 초기화) + F-STOCK 수동 회귀(qa).
- 실행: `npx vitest run`, `npm run lint`, `npm run build`, `npx tsc --noEmit`.

## 7. 주의점 요약
1. `selectedGroupId` effect가 검색 선택 target을 지우지 않게 할 것.
2. 시세 조회에서 `financeApiErrorCount`는 읽기만, 성공 시 삭제(쓰기) 금지.
3. picker는 `allowedCategories` prop만 추가, AC-17은 호출부에서(스크린샷 diff 0).
4. 검색 추출은 마지막 커밋으로 분리(단독 revert 가능), 5.134 동승·#258 단독 revert 가능하게 커밋 접두 `#258`.
5. ga.ts는 5.134 head 기준 맨 끝 추가 후 rebase.
