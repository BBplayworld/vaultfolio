# 4.xx #258 처음 사는 종목도 거래로 기록 — spec

작성: planner-designer · 2026-11-20 · 기준 `origin/main` 1aaeb62 · 방향 `4.xx-direction.md`

## 1. 문제
거래 입력 종목 목록이 보유 종목뿐이라(`trade-input.tsx:191·466`) 처음 사는 종목은 `주식 추가`로만 등록되고, 그 경로엔 연결 계좌가 없어 산 돈이 현금·대출에 반영되지 않는다. 보유 0개면 거래 입력이 막다른 길이다.

## 2. 목표 행동
처음 사는 종목을 거래 입력 한 창에서 검색 → 매수 기록하고, 고른 통장·대출에 같은 저장으로 반영한다.

## 3. 범위
주식 수동 거래 입력(FAB 진입, `lockedStock=false`)의 매수. 국내·IRP·ISA·연금(KRW, 검색 시장 `kr`), 해외(USD, `us`). 코인 폼은 안내 1줄만. 제외는 direction 1절 그대로.

## 4. 사용자 흐름
1. FAB › 거래 › 주식 › `직접 입력`.
2. 보유 1개 이상: `종목` 칸 아래 `다른 종목 찾기` 버튼. 보유 0개: `종목` 칸 자리에 검색이 바로 열림.
3. 검색 위 `국내`·`해외` 2칸 선택(기본: 카테고리 필터가 해외면 해외, 그 밖은 국내) → 이름·코드 입력 → 결과 목록(이름·코드·시장).
4. 결과를 고름 → 이미 보유한 종목이면 기존 `종목` 선택으로 전환(아래 AC-4). 아니면 고른 종목 요약(이름·코드) + `StockTargetPicker`가 `신규 자산 등록`이 선택된 상태로 열림 → 증권사·종류 선택(종류는 국내 검색이면 국내·IRP·ISA·연금, 해외면 해외만).
5. 수량·체결 단가·(해외) 체결 환율·체결일 → 즉시 반영은 켜진 채 잠김(기존 신규 동작).
6. `연결 계좌`(체결일이 이번 달일 때, 기존 규칙)에서 통장·대출 선택 → 미리보기.
7. `매수 기록` → 저장 1회 → 토스트(기존 `linkSavedToast` 또는 `매수 거래가 기록되었습니다.`) → 창 닫힘 → 상세·주식에 새 행.

## 5. 수용 기준 (qa가 그대로 검사)
- AC-1 보유 1개 이상, 매수 상태에서 `종목` 칸 아래 `다른 종목 찾기`가 보이고, 누르면 검색 입력이 열린다. 매도 상태에서는 버튼이 없다.
- AC-2 보유 0개(delisted만 있는 경우 포함)면 `종목` 선택 칸 대신 검색이 처음부터 열려 있고, 빈 Select는 보이지 않는다.
- AC-3 검색 결과를 고르면 `신규 자산 등록`이 선택된 채 증권사 Select가 보이고, 증권사를 고르기 전 `매수 기록`을 누르면 기존 문구 `신규 자산의 증권사를 선택하세요.`로 막힌다.
- AC-4 이미 보유한 티커(같은 ticker, delisted 제외)를 고르면 새 항목을 만들지 않고 기존 종목 선택과 같은 상태(보유 항목 카드 + `신규 자산 등록`)가 된다. 저장 뒤 같은 ticker·broker·category 조합 stock이 2개 생기지 않는다.
- AC-5 해외 검색으로 고르면 통화 USD, 체결 단가 `(USD)`·`원화로 입력`·`체결 환율` 칸이 기존 해외 종목과 같게 보인다. 종류 Select에 해외만 있다.
- AC-6 연결 계좌를 고르고 저장하면 `assetData` 한 번의 저장으로 ① 새 stock(수량=입력 수량, 평단=체결 단가, purchaseDate=체결일, positionSource=computed) ② 거래 1건(reflected=true) ③ 짝 기록 1건 ④ 계좌 잔액(현금 −금액 / 대출 +금액)이 모두 들어간다. 해외+원화 계좌는 체결 환율 환산 금액(#119와 같음).
- AC-7 `연결 안 함`으로 저장하면 ①②만 들어가고 현금·대출은 그대로다.
- AC-8 연결 계좌 오류(잔액 부족·1원 하한·환율 없음)면 저장되지 않고 새 stock도 생기지 않는다(기존 오류 문구·위치 그대로).
- AC-9 현재가 조회 실패 시에도 저장된다. 이때 새 stock의 currentPrice = 유효 체결 단가(USD 환산 후)이고, 요약 아래 `현재가를 못 가져와서 체결 단가로 먼저 표시해요` 1줄이 보인다. 다음 시세 갱신에서 현재가로 바뀐다.
- AC-10 결산 단언(C42·C143): 픽스처 ⓐ 처음 사는 국내 종목 + 원화 통장 연결 ⓑ 처음 사는 해외 종목 + 원화 통장 환산 ⓒ + 대출 연결 ⓓ 연결 안 함. ⓐ~ⓒ는 월 결산·홈 원인에 `주식 매수`·`신규 현금`·`기록 안 된 변화` 줄 없음(Σ원인=Δ순자산, 같은 달 시세 변동만), ⓓ는 기존 `주식 추가`와 같은 원인 분류. 원인 엔진(effects) diff 0이므로 main 대비 주·월·연 causes 동일 단언.
- AC-11 거래 삭제(상세·주식 거래내역): 기존 신규 자산 경로와 같은 되돌림(짝 기록 삭제·잔액 역가감). 되돌림 로직 diff 0.
- AC-12 `주식 추가` 화면의 검색은 공용 컴포넌트 교체 뒤에도 동작·문구·키보드(↑↓·Enter·Esc)가 같다(화면 diff 0, 기존 F-STOCK 회귀).
- AC-13 코인 거래 폼 코인 칸 아래 `처음 사는 코인은 '암호화폐 추가'로 먼저 등록해 주세요` 1줄(상세 진입 locked일 때는 없음). 보유 0개면 빈 Select 대신 이 줄만.
- AC-14 상세 진입(종목 고정)·스크린샷 거래 가져오기 화면 diff 0.
- AC-15 새 화면 문자열에 `연동`·`자동`·`동기화`·`추천`·`인기`·금액 예시 0. 보이는 표기 전수표(C139) 첨부.
- AC-16 320·360·390 폭에서 검색 결과 행·요약 줄이 넘치거나 겹치지 않는다. 히트영역 40px 이상.

## 6. 상태별 동작
| 상태 | 동작 |
|---|---|
| 빈 검색어 | 결과 목록 없음, 안내 없음 |
| 결과 0건 | `찾는 종목이 없어요. 이름이나 종목코드를 다시 확인해 주세요.` (`주식 추가`의 '조회' 안내는 이 화면에 조회 버튼이 없어 쓰지 않는다) |
| 검색 API 오류 | 결과 0건과 같은 줄(문구 1개 유지, 새 오류 문구 0) |
| 시세 조회 실패 | AC-9 |
| 시세 오류 3회 차단(`financeApiErrorCount`≥3) | 조회 생략, AC-9와 같게 체결 단가로 채움(카운터 키 읽기만, 쓰기 규칙은 기존) |
| 체험 중 | 그대로 동작(메모리 저장, `/api/ticker-search`·`/api/finance`는 체험 차단 목록 밖). GA는 기존 체험 처리 따름 |
| 연결 계좌 없음(현금·대출 0개) | 기존: 연결 행 없음, `연결 안 함` 저장 |
| 체결일이 지난달 | 기존: 연결 행 숨김 + `account-link-note` |
| 잔액 부족·1원 하한 | AC-8 |
| 매수→매도 전환 | 검색·고른 종목 해제, 종목 칸 초기 상태 |
| 카테고리 필터 변경 | 고른 새 종목 해제(국내/해외 기본값만 따라감) |
| 창 닫기 | 검색어·결과·고른 종목 모두 초기화(기억 저장 없음) |

## 7. 저장 데이터 계약
- **새 저장 키 0, 스키마 변경 0, 마이그레이션 0, 동기화·공유 토큰 변경 0.** 새 stock은 기존 `stockSchema` 필드만 사용(ticker·name·category·currency·currentPrice>0·purchaseDate·broker·baseDate·positionSource·positionEffectiveDate). 거래·짝 기록은 기존 `Transaction`·4.56 짝 기록 형식.
- 저장 함수 변경 0: `addTransactionsBatch([tx], [], [newStock], link)` 그대로. 바꿔야 하면 **즉시 중단 → risk:high 재판정**.
- 서버 전송: 검색어(`/api/ticker-search`)와 티커(`/api/finance`)만 — `주식 추가`와 같은 요청, 수량·단가·금액·보유 목록 0. 새 API 0.
- 구버전 기기 혼재: 새 stock·거래는 4.56 이후 형식이라 구버전(v4.56+)이 그대로 읽는다. qa는 데이터 안전 점검(구버전에서 열기·삭제, 롤백 PR revert 후 데이터 유지) 수행.
- 예상 risk: **medium**.
