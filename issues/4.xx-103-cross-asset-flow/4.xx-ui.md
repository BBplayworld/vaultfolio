## 1. 홈 '지난 접속 이후' 원인 목록 (dashboard.tsx:298-340, 접힘 영역 안)
컴포넌트 트리(위→아래, 모두 기존): 구간 라벨 `rangeLabel`(text-xs) → 원인 `ul` → **[신규 1줄] 캡션** → `AttributionRecordList`.
- 원인 `ul`: 구조·타이포 변경 0 (`w-full max-w-xs space-y-0.5`, 라벨 text-sm foreground / 금액 text-sm semibold tabular-nums 손익색). 상쇄 후 항목이 줄어들 뿐.
- 캡션: `<p data-testid="home-cause-offset-caption" className="mt-1.5 text-xs text-muted-foreground break-keep text-pretty leading-relaxed max-w-xs">자산 사이에 옮긴 돈은 원인에서 뺐어요</p>`
  - 위치 = 원인 `ul` 바로 아래(원인과 한 덩어리로 읽힘), 기록 목록 위. `rangeLabel`과 같은 text-xs muted(메타 캡션 역할, §2). 굵기·색 강조 없음(§11 muted+semibold 금지). 금액·아이콘·툴팁 없음. 투명도 `/NN` 금지(안내 문장, 라이트 대비).
  - 조건: 상쇄 합 ≥ 1만일 때만. `screenshotMode`에서도 원인과 함께 표시(원인 목록이 보이므로 문맥 필요), `data-screenshot-hide` 아님.
  - 높이: 12px×1.5 = 18px 1줄. 19자 ≈ 215px라 320·375 모두 1줄(`max-w-xs`=320 이내, 320뷰포트 컨텐츠 288px < ... 215px OK). 1280도 같은 `max-w-xs` 좌정렬. 컷 사유 없음 → **유지**(컷 기준: 320에서 2줄이 되면 뺌 — 현 문구는 해당 없음).
- 상쇄 후 모습 (S1b/S4b/S5b, 시세 +5% 가정; 375, 접힘 펼친 상태):
  ```
  ▲ +105만원 (+x.x%) 지난 접속(11/8) 이후 ⌄
  11/8 → 11/9
  주식 시세 상승            +105만원
  자산 사이에 옮긴 돈은 원인에서 뺐어요
  [기록 목록: 주식 매수 / 현금 출금 등 그대로]
  ```
  S4b `주식 시세 상승 +85만원`, S5b `+75만원`. 부분 상쇄는 `기록 안 된 변화 +40만원` 행(날짜 없음, 목록 맨 아래, 금액 손익색) + 캡션. 단방향(상쇄 0)은 캡션 없음.
- 폭: 320(컨텐츠 ≈288) / 375(≈343) / 1280(max-w-xs 320 좌정렬). 라벨 `break-keep` 유지, `기록 안 된 변화`(8자)+금액 `+1,234만원`은 320에서 한 줄(≈190px). 2줄 필요 없음. C35: 행 수가 줄거나 같고 캡션 +18px만 증가 → 폭×금액(수십만·수백만·억) 표에서 행 높이 증가 = 캡션 18px 한 가지뿐이 의도.
- 모션: 기존 chevron 펼침 그대로. 캡션은 목록과 같이 나타나며 별도 모션 없음(재마운트로 사라질 모션 없음).
- 접근성: 캡션은 일반 `p`(스크린리더가 목록 뒤에 읽음). 다크 대비 muted-foreground 기존 토큰(rangeLabel과 동일).
- 문구 최종: `자산 사이에 옮긴 돈은 원인에서 뺐어요`. 남는 몫 라벨 `기록 안 된 변화`(결산과 동일). 투자 조언·금액 없음.

## 2. 거래 입력 `현금 계좌에서도 반영` 행 (B')
대상: `trade-input.tsx`(주식)·`crypto-tx-input.tsx`(코인) 수동 폼. 위치 = `보유 수량에 즉시 반영` 행(`FormItem rounded-lg bg-muted/40 dark:bg-muted/20 p-3`) **바로 아래**, 포지션 미리보기 위.
순서: 즉시 반영 행 → **B' 행** → (4.52 경고) → (잔액 오류) → 포지션 변경 미리보기 → 버튼.
- 재사용: 즉시 반영 행과 **같은 박스 마크업**(Checkbox 기본 brand, `text-sm font-medium` 라벨, `text-sm text-muted-foreground mt-0.5` 보조 문구). 신규 컴포넌트 없음. Select = 입출금 입력(cash-tx-input.tsx:170)과 같은 `Select`(Trigger h-9급 기본, radius lg).
- 레이아웃(375): 박스 `p-3 flex flex-row items-center gap-2`, 체크박스 히트영역은 라벨 `cursor-pointer` 전체(행 높이 ≥ 40px: 라벨+보조 2줄 ≈ 44px). 켜면 박스 안 아래에 확장 영역(계좌 Select + 예상 잔액).
- 상태
  - 기본(꺼짐): 라벨 `현금 계좌에서도 반영`, 보조 매수 `거래 금액만큼 현금이 줄어요` / 매도 `거래 금액만큼 현금이 늘어요`. 계좌 1개면 보조에 이름: `{계좌명}에서 거래 금액만큼 줄어요`(1줄 넘으면 줄바꿈 허용, `break-keep text-pretty`).
  - 켬: 확장(`grid grid-rows-[0fr→1fr] motion-safe:transition-[grid-template-rows,opacity] duration-300`, **항상 마운트**·`inert`·`invisible` 닫힘, §6 높이 펼침) — 계좌 2개 이상일 때만 `Select`(기본=cash 목록 첫 항목, placeholder `계좌 선택`) + 그 아래 미리보기 줄 `{계좌명} 잔액 1,000만원 → 900만원`(`text-sm tabular-nums`, 전→후 화살표 muted/60, 후 semibold — cash-tx-input 미리보기 패턴과 동일 문자열 구조, 별도 박스 없이 같은 박스 안 `mt-2 border-t` 없이 muted 텍스트). 금액 미입력이면 미리보기 숨김.
  - 숨김: 즉시 반영 해제, 같은 통화 현금 0개, 스크린샷 가져오기·거래 수정 폼. 즉시 반영을 다시 켜도 B'는 꺼진 상태로 복귀(기억 없음).
  - 수수료 있으면 보조 문구 끝 `(수수료 포함)`.
  - 4.52 경고(켬 + `shouldWarnTxAfterResync` 참): **기존 마크업 그대로 재사용**(`data-testid="tx-after-resync-warning"`, `AlertCircle` + important 주황, text-sm break-keep text-pretty, `resyncWarningText("cash", …)`), B' 행 바로 아래. 차단 아님.
  - 오류(잔액 부족): `rounded-lg bg-destructive/10 dark:bg-destructive/20 p-3 text-sm text-destructive font-medium` (포지션 oversell 박스와 동일) 문구 `{계좌명} 잔액이 부족해요. 다른 계좌를 고르거나 끄고 저장해 주세요.`, testid `cash-link-error`. 입력 중 실시간 표시, 제출 시에도 동일 차단(거래 미저장).
  - 중복 거래 다이얼로그: 문구 변경 없음.
- 모션: 확장은 CSS grid 전환(재탭 시 현재 값에서 역전, reduced-motion 즉시), 체크박스·Select 기본 press 피드백. 연타·중간 해제 시 값만 토글(재마운트 없음).
- 접근성: 라벨-체크박스 `FormLabel` 연결, Select `aria-label="현금 계좌"`, 오류 `role="alert"`, 경고는 기존 유지. 키보드: Tab 순서 즉시 반영 → B' → Select → 수량 미리보기. 다크: 박스 `dark:bg-muted/20`, 오류 destructive/20.
- 긴 문구: 계좌명 긴 경우 Select 값 `truncate`, 보조 문구는 줄바꿈.
- 토스트(B' 켜고 저장): `매수 거래가 기록되었습니다. 현금 기록도 남겼어요` / 매도 동일. 한 `toast.success` 한 문자열(2000ms 기본, 2문장이라 `duration=3000`). 별도 액션 없음.
- GA: 금액·계좌명 없음(spec 9).

## 3. 거래 삭제 확인 안내 1줄 (B')
spec 원안(삭제 후 토스트 아래)을 **삭제 확인 다이얼로그 안 1줄로 변경 제안**(planner 확인 요청): 사용자가 결정하기 전에 알아야 하고, 토스트 2줄은 2000ms에 읽기 어렵다. 삭제 후 토스트는 변경 없음.
- 주식 `DeleteRollbackDialog`(delete-rollback-dialog.tsx): `삭제 시 자동 롤백` 박스(`bg-muted/30 p-3`) **아래** `space-y-3` 슬롯에 `<p data-testid="delete-cash-record-note" className="text-sm text-muted-foreground break-keep text-pretty">현금 입출금 기록은 삭제되지 않고 따로 남아요</p>`. 코인 `crypto-tx-view.tsx:190` 커스텀 모달도 같은 위치·같은 문구·같은 클래스.
- 조건: 삭제 대상과 **같은 날짜·같은 금액의 반영 입출금 기록**이 있을 때만. 없으면 현행 그대로. 미반영 거래 삭제는 다이얼로그 없이 즉시(현행) → 안내 없음.
- 아이콘·색 강조 없음(destructive 제목 아래 muted 안내). 다이얼로그 높이 +20px, 모바일 스크롤 불요.
