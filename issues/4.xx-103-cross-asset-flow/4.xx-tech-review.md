## 3. 검토 결과
1. **결산 엔진 최소 변경 – 단, "래퍼 1곳"은 부족**. `settlement.ts:224`가 `matchedTransfer > 0`일 때만 `acc.income`에 더한다. 래퍼가 `출금 짝 − 입금 짝`이면 입금 짝만 있는 달은 **음수라 무시되어 F6·완료 기준 9가 실패**한다. 해결: 가드를 `!== 0`으로(+주석) 바꾸는 1줄. 또 한 달에 출금 짝과 입금 짝이 함께 있으면 순합이 상쇄돼 합계는 맞으나 개별 의미가 가려지므로, 래퍼 대신 `matchedTransfer`는 순합 유지하고 단위 테스트로 항등식만 보장(허용). `asset-report.ts`는 4.55가 키 추가로 큰 diff(+45)라, A 변경은 **함수 추가 위주로 기존 줄 수정 최소화**.
2. **과거 결산 표시 변화 범위(planner 결정 3)**: 변화 조건 = 구간 내 반영 입금(비정기) ↔ 반영 매도(주식·코인) ±3일 보유자. 합계·Δ 불변, `순유입`/`기록 안 된 변화` 두 줄만 이동. 측정법: (a) 합성 픽스처(F6, 정기 입금 제외 F12, 부분 짝, 짝 창이 달 경계) 전후 `computeSettlementCauses` 스냅샷 비교; (b) 실제 사용자 데이터 대신 `src/lib/preview/demo-data.json`·기존 settlement 테스트 데이터에 같은 비교 스크립트를 돌려 변화 건수 확인(vitest 일회성 측정 테스트, 커밋 시 단언만 남김); (c) 수정 전 기대값을 테스트에 선기재(C21). 기존 `settlement-flows` 테스트가 입금+매도 조합을 가지면 기대값이 바뀌므로 diff를 dev-notes에 명시.
3. **홈 헤더**: `getAttributionItems` 앱 내 소비처는 홈 1곳(+ 성적표 그룹 함수 경로), 인자 생략 시 동일 결과를 테스트로 고정. 4.55가 `physical` 키(`buy:physical`·`sell:physical`)를 추가했으므로 spec 3-A 1의 대상 다리에 이미 포함, **detail 반환에 `physical`(신규 실물 후보 `p:`) 포함 필요**(spec 반환형 `{out:{stock,crypto,loan}}`에 `physical` 추가). `dashboard.tsx`는 4.55가 18줄 수정, `useHeaderNetChange` 영역이 겹칠 수 있으나 호출부 2줄 수준.
4. **원자성(C37)**: 기존 `addTransactionWithPosition`류가 모두 `saveData(newData)` 한 번이므로, 신규 함수 `addTradeWithCashRecord`(주식/코인 각 1개 또는 제네릭 1개)도 같은 패턴으로 구현 가능. 신규 종목 경로는 `addTransactionsBatch(newStocks)`와 합쳐야 하므로 **옵션 인자(`cashLink?: { tx, cashId, patch }`)를 기존 함수에 추가**하는 안이 신규 함수 3~4개보다 작다(호출 시그니처만 확장, 기존 호출 불변). `saveData` false면 상태 불변(기존 구현이 성공 시에만 `setAssetData`)이므로 롤백 보장. 잔액 가드는 `isCashWithdrawalValid`를 저장 전에 호출.
5. **4.52 경고 재사용**: `balance-edits.ts`의 `shouldWarnTxAfterResync`·`resyncWarningText`는 순수 함수라 그대로 호출. 4.52와 4.55가 공통 조상(4fee68c) 이후 갈라져 있어 **4.52가 4.55보다 먼저 머지되어야 함수가 존재**; 합류 시 4.55 브랜치에 4.52(또는 main) 병합 선행.
6. **충돌**: 4.55 변경 파일 중 겹치는 곳 = `settlement.ts`(4줄), `asset-report.ts`(+45), `change-hero.tsx`(4줄), `dashboard.tsx`(18), `asset-data-context.tsx`(74), `trade-input.tsx`는 4.55 미수정. 충돌 위험: asset-report(중), context(중), 나머지 낮음. 대응: 4.55 최신 위에 병합 후 작업, 새 코드를 파일 끝/신규 함수로 추가.
7. **한계 보강**: 외화 매매의 체결환율 vs 현재환율 잔여는 spec대로 `기록 안 된 변화`로 남음. 입금 후보에서 `recurring` 제외는 기존 `CashTransaction.recurring`을 읽기만 하므로 스키마 0.
