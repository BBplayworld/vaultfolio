## 1. 문제
- 홈 '지난 접속 이후' 원인이 앱 안에서 옮긴 돈을 두 원인으로 보여준다(qa 확정): `주식 매수 +100만 / 현금 정리 −100만`, `주식 매도 −500만 / 대출 상환 +500만`. 합은 맞지만 서술이 틀리고 LEARNINGS 위반 형태다(→ 3-A, 4.55).
- 매수·매도가 현금·대출과 이어지지 않는다. 거래를 기록해도 현금·대출 잔액은 따로 고쳐야 하고, 거래를 지워도 돈 쪽은 그대로다(대표 지적 11-09, 결정 ②+③).

## 2. 목표 행동
- 매수·매도·상환 뒤 홈을 열면 원인에 **순자산을 실제로 바꾼 것만** 보고, 캡션 1줄로 '옮긴 돈은 뺐다'를 읽는다.
- 주식·코인 매수·매도를 즉시 반영으로 저장할 때 `연결 계좌`에서 현금 계좌 또는 대출을 골라, 보유·계좌 잔액·입출금(상환) 기록·결산이 한 번에 맞는다. 거래를 지우면 계좌도 함께 되돌아간다.

## 3. 범위

### 3-A. 홈 헤더 내부 이동 상쇄 — **4.55(9a582ac)에 반영 완료**, 4.56은 2항 id 짝만 추가
1. **대상 다리**: 매매 다리 `buy:*`·`sell:*`(stock·crypto·realEstate, 4.55 `physical` 포함) / 자금 다리 `cash`(잔차)·`debt`·`deposit`(보증금) / 기록 다리 `income`.
2. **1단계 — 기록 짝(정본: 결산과 같은 함수)**: `matchRecordedTransfers`를 확장해 짝 내역을 돌려준다(새 규칙 금지, 같은 ±3일·날짜 근접·id순·금액 한도).
   - 기존: 반영 출금 ↔ 반영 매수(주식·코인)·대출 상환. 4.55 합류분: 후보에 **실물 신규 등록(매입)** 추가(4.55 저장 경로·날짜 필드 기준, tech-review 3df41ae).
   - **4.56 추가(id 짝, 3-L 8)**: 연결 쌍 4종(출금↔매수·입금↔매도·대출 증가↔매수·상환↔매도)을 id로 먼저 정확히 짝짓고, 그 기록·거래는 ±3일 추정 후보에서 뺀다. 비연결 입금↔매도 추정 짝은 **만들지 않는다**(`prep-103-b-settlement` 폐기, 과거 결산 diff 0).
   - 반환(`matchRecordedTransferDetail()`, tech-review 5절): `{ out: { stock, crypto, physical, loan }, in: { stock, crypto }, viaLoan: { buy, sell } }`(KRW). `out.physical` = 실물 신규 등록 ↔ 출금(4.55 추정 짝, 그대로). `in` = **id 짝 입금↔매도만**(4.55에선 0). `viaLoan` = 대출 증가↔매수·상환↔매도 id 짝 — 현금을 거치지 않으므로 `matchedTransfer`에 넣지 않고, 홈 헤더 상쇄와 `withLoanCause`의 `debtIncrease`/상환 쪽에서 짝 금액만큼 뺀다. **`viaLoan` 소비 방식은 개발 첫 작업으로 현재 엔진의 '대출로 매수' 픽스처 분해를 측정한 뒤 확정**(dev-notes 기록). id 짝 금액 = `min(기록 금액 KRW 환산, 거래 금액)`, 쓴 만큼 양쪽에서 빼고 남은 몫만 기존 ±3일 추정 코드(무변경)로 간다.
   - `matchRecordedTransfers()` 래퍼 = `out 합 − in 합`(음수 가능). **결산 변경**: 래퍼 + `settlement.ts:224` 가드 `ctx.matchedTransfer > 0` → `!== 0`(입금 짝만 있는 달의 음수를 버리면 완료 기준 11 실패). 기존 데이터는 `in = 0, out ≥ 0`이라 동작 같음.
   - 홈 헤더: `income`(−)과 해당 `buy:*`·`debt`(+), `income`(+)과 해당 `sell:*`(−), 대출 연결은 `debt`와 해당 `buy:*`·`sell:*`를 짝 금액만큼 줄인다.
3. **2단계 — 잔차 짝(구간 금액 한도)**: 1단계 뒤 남은 매매·`debt`·`deposit`·`cash` 다리를 하나의 풀로 보고, 양(+) 합과 음(−) 합 중 작은 쪽만큼 서로 지운다(결산 풀 G↔C와 같은 의미). **같은 부호끼리는 지우지 않는다.** 이 다리들이 단방향뿐이면(반대 부호 없음) 지금과 같게 둔다.
4. **남는 몫 라벨(LEARNINGS 2026-10)**: 상쇄가 일어난 풀의 남는 몫은 한 줄로 합친다. 남는 몫이 `cash` 다리에서만 왔으면 `신규 현금`/`현금 정리` 유지, 매매·`debt`·`deposit`가 섞이면 **`기록 안 된 변화`**(결산 라벨과 같은 문자열, 새 표시 키 `unrecorded`, 날짜 없음). `매수`·`매도`·`상환`·`추가 대출` 라벨로 남기지 않는다.
5. **임계값**: 상쇄 뒤 `|금액| < CAUSE_DISPLAY_MIN`(1만) 항목은 숨기고 그 몫은 `getAttributionItems`의 기존 잔차 규칙(같은 부호 최대 항목, 없으면 `cash`)으로 얹는다.
6. **항등식**: 표시 항목 합 = `attr.deltaNet`(vitest 단언).
7. **적용 위치**: `getAttributionItems(attr, transfer?)`·`formatAttributionSentence(attr, transfer?)`에 선택 인자 추가. 홈(`dashboard.tsx:496`)만 넘긴다. 인자 없으면 기존 결과와 같다(기존 테스트 diff 0).
8. **캡션**: 상쇄 금액 합 ≥ 1만이면 원인 목록 아래 muted 1줄 `자산 사이에 옮긴 돈은 원인에서 뺐어요`(금액 없음). 360px에서 높이 부담이면 ui-review에서 뺀다(컷 가능).
9. 바꾸지 않음: 구간 기록 목록(`records`)·Δ순자산·구간 라벨.

### 3-L. 연결 계좌 (4.56, 스키마 0)
1. **대상**: 주식 `trade-input`·코인 `crypto-tx-input` **수동 입력의 즉시 반영 저장만**(신규 종목 경로 포함). 미반영 저장·스크린샷 일괄 가져오기·4.50 보유 맞추기·부동산·실물은 제외(행 없음).
2. **선택 행**: `즉시 반영` 아래 `연결 계좌` 1행 — `연결 안 함`(기본) / 같은 통화 현금 계좌들 / 대출들. **매번 `연결 안 함`으로 열림, 기억 저장 없음(새 키 0)**. 후보:
   - 현금: 거래와 **같은 통화**만(코인=KRW, 주식=종목 통화). 원화 계좌로 외화 환산 연결 없음.
   - 대출: **원화 거래일 때만**(대출 기록은 KRW 고정). USD·JPY 주식이면 대출 후보 없음.
   - 후보가 0개면 행을 숨긴다. 선택 시 `반영 후 잔액 A → B` 미리보기 1줄(ui.md).
3. **동작**: 매수 = 현금 출금(`withdrawal`) 또는 대출 증가(`borrow`) / 매도 = 현금 입금(`deposit`) 또는 대출 상환(`repay`). 금액 = 수량×단가(매수 +수수료, 매도 −수수료, 거래 통화), 날짜 = 거래일, `reflected: true`, 메모 `{종목명} 매수|매도`, `recurring` 없음. 잔액 가감은 기존 `balancePatch`(cash/loan-tx-input) 규칙 그대로.
4. **연결 저장 방식 = 짝 기록 id 규칙**: 짝 기록 id = `ctx_link_<거래 id>`(현금) / `ltx_link_<거래 id>`(대출), 거래 id는 `tx_…`/`crtx_…` 그대로. 연결 계좌는 그 기록의 `cashId`·`loanId`. **정본 `src/lib/trade/linked-record.ts`**(id 생성·`linkedTradeIdOf`·`findLinkedRecord`·`buildLink`·`removeLink`) 1곳만 import, 접두어 문자열 직접 사용 금지(테스트 grep 단언). 기존 id(`ctx_<숫자>`·`ltx_<숫자>`·`demo_ctx_*`)와 접두어 충돌 0. **새 필드·타입·zod 스키마·저장 키·동기화 형식 diff 0, 마이그레이션 코드 없음.**
   - 구버전 보존 근거: 저장소는 `assetDataSchemaLoose.parse`(zod 기본 = 모르는 키 제거)로 읽고 쓴다. 거래에 새 필드를 넣으면 구버전 기기가 저장하는 순간 지워지고 `mergeById`(원격 우선)로 전 기기에서 연결이 사라진다(4.55 D1형). id 문자열은 기존 필드 값이라 구버전도 그대로 보존한다.
5. **원자성(C37)**: 거래 + 보유 패치(신규 종목 포함) + 짝 기록 + 계좌 잔액을 **`saveData` 1회**. 실패 시 전부 이전 값. 중복 확인 '추가'도 같은 함수, '기존 유지'면 아무것도 저장 안 함. 신규 저장 함수 0 — **기존 함수에 옵션 인자 `link`**(`addTransactionWithPosition`·`addTransactionsBatch`(신규 종목)·`addCryptoTransactionWithPosition`, `{kind:'cash',cashId}|{kind:'loan',loanId}`)를 더하고, 짝 기록·잔액 패치는 함수 안 `buildLink`가 만든다(금액 공식 1곳). 함수 안에서도 출금·상환 한도와 통화 불일치를 다시 검사해 `false`. 옵션을 안 넘기는 기존 호출(스크린샷·맞추기·미반영)은 그대로.
6. **가드**: 현금 출금이 `isCashWithdrawalValid` 불통과 → 오류 1줄 + **전체 저장 차단**(거래만 저장되지 않음). 대출 상환 > 대출 잔액(`isLoanRepaymentValid` 불통과) → 같은 방식 전체 차단(분할 없음). 4.52 `shouldWarnTxAfterResync`가 참이면 `resyncWarningText` 그대로 표시(차단 아님, 현금·대출 각각).
7. **삭제 = 되돌림**: 연결된 반영 거래 삭제 시 확인 다이얼로그(주식 `DeleteRollbackDialog`·코인 삭제 모달)에 되돌릴 계좌·금액 1줄. 확인하면 보유 롤백 + 짝 기록 삭제 + 계좌 잔액 역가감을 **`saveData` 1회**(기존 `deleteTransactionWithPosition`·`deleteCryptoTransactionWithPosition`에 옵션 `{ revertLink }`, 기본 false). 다이얼로그 금액은 실제 되돌림과 같은 `removeLink` 계산으로 표시(하한 0 clamp 시에도 표시 = 결과). 역가감 하한은 기존 기록 삭제 규칙과 같다(`Math.max(0, …)`). 짝 기록이나 계좌가 이미 없으면 1줄 없이 거래만 지운다(현행과 같음).
   - 짝 기록을 입출금·상환 목록에서 따로 지우면 기존 삭제 그대로(잔액 되돌림), 거래는 남고 연결만 풀린다.
8. **결산·홈 id 짝**: 연결 쌍 4종(출금↔매수·입금↔매도·대출 증가↔매수·상환↔매도)은 id로 정확히 짝(같은 날짜라 달 경계 분리 없음). 연결 기록·거래는 ±3일 추정 후보에서 뺀다. 연결 없는 기록의 추정 규칙은 그대로 → **과거 달 결산 diff 0(C8)**. 가드 `>0 → !==0`(3-A 2).
9. **수정·소급**: 거래 수정 화면이 없다(`updateTransaction` UI 호출 0) → 수정 = 삭제(되돌림) 후 재입력. 새 수정 화면 만들지 않음. 기존 거래 소급 연결 없음, 연결 없는 거래의 동작·표시·삭제는 main과 같다.
10. **토스트**: 저장 성공 토스트 1개(연결 시 문구는 ui.md). 토스트 액션 `현금도 맞추기`는 **넣지 않는다**(3-T 폐기).
11. **문구**: `연결`은 사용 가(실제로 잇고 되돌림이 있음, cto 5-5로 business-pm 11-09 반대 사유 해소). `연동`은 금지(마이데이터 오해). 입출금·상환 목록 행은 메모로 충분, 별도 배지 없음.
12. **GA**: feature_use page_title `거래 저장·계좌 함께 반영` 1개, 연결 저장 성공 1회 = 1건(금액·계좌명 금지). 확정은 business-pm.

## 4. 사용자 흐름
1. 주식 탭 → 거래 입력 → 매수 100만(KRW), `즉시 반영` ✓.
2. `연결 계좌`에서 `증권 예수금`(또는 `신용대출`) 선택 → `반영 후 잔액 1,000만 → 900만` 미리보기.
3. 저장 → 토스트 1개. 보유 수량·평단, 계좌 잔액, 입출금(또는 대출 기록)이 한꺼번에 바뀐다.
4. 다음 날 홈 → 원인에 `주식 시세 상승 +X`만, 캡션 1줄. 기록 목록에는 `주식 매수`·`현금 출금`(`추가 대출`) 2건.
5. 월말 결산 → 이 매수는 원인에 나오지 않는다(id 짝).

## 7. 엣지 케이스
- 빈 데이터·첫 사용자·지난 접속 없음: 헤더 숨김·캡션 없음(현행). 연결 후보 0개(현금·대출 없음, 외화 종목 + 같은 통화 계좌 없음)면 행 숨김.
- 일부 갱신: 부분 상쇄(매수 100·현금 −60) → `기록 안 된 변화 +40만`, 캡션 표시.
- 오래된 데이터: 과거 데이터엔 `_link_` id가 없으므로 결산·헤더 결과가 수정 전과 같다. 측정: F1~F12·부분 짝·달 경계 픽스처의 **수정 전 기대값을 먼저 커밋**하고 수정 후와 나란히 단언(C21).
- 짝 한쪽 소실: 짝 기록·거래 중 하나가 없으면(따로 삭제, 보존 기간 3년 정리, 계좌 삭제) 연결 없음으로 읽는다. 오류·자동 복구 없음.
- 외화: USD 종목 + USD 계좌 연결 → 짝 기록은 USD. id 짝 금액 환산 기준(체결 환율 vs 현재 환율)은 tech-review가 결산 엔진과 같게 정하고, 차이는 `기록 안 된 변화` 또는 1만 미만 흡수.
- 두 기기 동시 편집: 거래+짝 기록은 한 번에 저장되나 다른 기기가 같은 계좌 잔액을 동시에 고치면 기존 병합 규칙대로 갈라질 수 있다(새로 생기지 않음).
- 공유 토큰(packV7): 받는 쪽은 id를 새로 만든다 → 기록·잔액은 같고 연결만 풀림(토큰 형식 변경 금지).
- 구버전 기기 혼재: 짝 기록은 일반 입출금·상환 기록으로 읽히고 id는 보존된다. 구버전 결산은 id 짝이 없어 F6·F13·F14가 수정 전 모양(추정 규칙)으로 보인다.
