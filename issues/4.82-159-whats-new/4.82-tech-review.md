## 2. 저장·데이터 영향
- 스키마·키 변경 0. 마이그레이션 코드 불필요, "이전 값 → 새 로직" 복원 테스트는 필요(아래 ①).
- 건드리는 데이터: `secretasset_notice_seen`(기기 로컬, 동기화 제외·import 보존 514행 그대로) 1개뿐. 자산·스냅샷·거래·공유·백업·성적표 무접촉.
- ① 구현 경로·검증
  - `readNoticeSeen()`은 `{id,seenAt}` 반환. 만료(`expiresAt<=now`)·id 비문자열·`parseEntryId` null이면 "기록 없음".
  - 쓰기는 `markNoticeSeen(latestId, now+90일)`(seenAt=now). 호출처는 spec 6장의 셋(팁 클릭·X, 시트 열기, 첫 실행 조용한 기록).
  - id 비교는 `{date,seq}` 숫자 비교(문자열 금지). `20260924`는 seq 0이라 `20261112-01`보다 작음.
  - 날짜 30일·60일은 KST 날짜 일수 차이로 계산(`todayKst` 재사용, 시각 의존 제거).
  - 테스트: 구 값 `{id:"20260924",seenAt,expiresAt}`, 만료 값, 깨진 JSON, `{}`(체험 원본)이 모두 예외 없이 "기록 없음/구 id"로 해석되는지.
- 롤백: spec 6장 그대로(구버전이 9월 공지를 1회 재노출, 결산 창 중이면 그 세션 결산 1회 가림, 데이터 손실 0). 구버전 기기 혼재는 기기별 키라 충돌 없음. decision-brief에 기재.

## 4. 판정 ②: 불러오기 완료 후에만 (S7)
- `isDataLoaded`는 `useAssetData()`가 이미 제공(asset-data-context 88·1893행). HomeTipBox effect 맨 앞에 `if (!isDataLoaded) return`을 두고 deps에 추가. 이 가드는 **팁 판정 전체**보다 **조용한 기록**에 필수.
- 조용한 기록은 순수 함수 `silentFirstRun({isDataLoaded, hasAssets, hasRecord, eligible})`로 분리해 단위 테스트. 조건은 `isDataLoaded && !hasAssets && 기록 없음 && 목록 비지 않음 && 체험·잠금 아님`.
- 테스트 필수 4건
  - isDataLoaded=false + hasAssets=false → 쓰지 않음(기존 사용자 전원 읽음 처리 방지)
  - 로드 후 자산 있음 → 쓰지 않음
  - 로드 후 자산 0 + 기록 없음 → 쓰기 1회
  - 목록이 빈 경우 쓰지 않음
- 확인 필요(구현 때 검증): `setIsDataLoaded(true)`가 자산 상태 반영과 같은 배치인지(361행 주변). 분리돼 있으면 `isDataLoaded`가 true가 된 렌더에서도 `assetData`가 초기값일 수 있으므로 반드시 구현 때 effect 순서를 확인한다.
- 쓰는 위치는 HomeTipBox(홈 마운트)로 한정. 자산 0 사용자가 홈을 열면 기록되고 이후 등록한 자산에 구 소식은 '새'가 아니다(spec 9번 부합).
- 체험(`isTrialMode`)·앱 잠금(`isPwaLocked`)에서는 판정·기록 모두 하지 않음(relink 판정과 같은 가드 재사용).

## 5. 판정 ③: pickHomeTip·공지 제거 영향
- 순서: 백업 > 임박 세금 > 결산 > **whats_new** > relink > 세금 > 최신화 > 기능. 결산 분기 바로 뒤에 삽입하므로 기존 분기 변화 0.
- `pickHomeTip` 입력에 `whatsNewOk?: boolean`(= 체험·잠금 아님 + `isDataLoaded`, `hasRelink`와 같은 방식으로 호출부가 판정)을 추가하고, 기록·날짜 판정은 `lib/whats-new.ts` 함수를 호출한다. 기존 테스트가 `readNoticeSeenId`를 mock하므로 같은 지점에서 mock하면 churn이 최소.
- `HomeTip`에 `{kind:"whats_new"; count; title}` 추가, `homeTipViewKey` 기본 분기(`tip.kind`)로 처리됨.
- X 처리: `SESSION_DISMISS_KEY` 분기는 단순화(강제 노출 예외 삭제). X = 읽음 기록 후 박스 숨김.
- `isNew` 삭제: 팁 배지, `pickRecommendedFeature` 분기, `AppFeature.isNew`, 2건. DECISIONS 11-11 'market-compare isNew 유지'를 대체하는 항목을 STATE·DECISIONS에 기록.
- 바로 가기: 홈 팁의 feature 이동 블록(168~174행: `beforeNavigate`→`action`/`navigate(target)`)을 헬퍼로 추출해 시트가 호출한다. **`dismissTip`은 호출하지 않는다**(spec 4장 6번). 추출은 중복 방지용 최소 리팩터링.

## 6. 판정 ④: GA 측정
- 사실: `track()`은 params를 이벤트로 보내지만 `page_title`은 `CATEGORY_TITLES[category]`로만 정해진다. 즉 `entryCategory` 이벤트의 `source`는 이벤트 파라미터로 가지만 "페이지 및 화면" CSV(주 판독원)에는 안 나온다(4.79 qa 발견). 따라서 spec S6의 `source:"whats_new"`는 **보내도 CSV에서 홈 팁과 구분되지 않는다.**
- 판정(추가 이벤트 없이): ① 시트 열기 `category:whats_new, method:view`(page_title `새 소식`, 주 지표) ② 바로 가기 `category:whats_new, method:click`(page_title `새 소식`, CSV에서 "클릭 수"는 이 이벤트 합으로 판독) ③ 이어 `entryCategory`가 있으면 `{category:entryCategory, source:"whats_new"}`를 보낸다. ③은 4.72·4.79 진입 카운트의 연속성을 지키는 용도이고 경로 분리는 되지 않는다.
- 필요한 보정: PARAM_VALUES에 `source:"whats_new"` 추가(없으면 타입·검증 실패). 이 한계를 qa 완료 기준 12번과 지표 11장의 "경로 분리 불가" 문구에 이미 반영돼 있어 충돌은 아니다. entryCategory 별도 이벤트(예: `whats_new_go`)는 **만들지 않는다**(이벤트·이름 증가, C67). 경로 분리가 꼭 필요해지면 GA 보고서에서 이벤트 파라미터 source 맞춤 측정기준을 등록하는 운영 작업이지 코드 작업이 아니다.
- `ga.test.ts` 111행의 notice 케이스를 `whats_new`→`새 소식`으로 교체하고 `entryCategory` 이벤트가 기존 title을 유지하는지 1건 추가.
