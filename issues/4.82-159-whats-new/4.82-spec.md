# 4.82 새 소식 (#159) — spec (planner-designer)

작성 2026-11-11 · 입력: `4.82-direction-draft.md`(합의), `4.82-business.md`, `4.82-challenge.md`(축소·통과, risk:medium, COO 자체 승인) · 코드 origin/main cca5dbb(v4.81)
화면의 시각·모션은 `ui-designer`가 ui.md에서 정한다. 이 문서는 흐름·문구·데이터·규칙만 정한다.

## 1. 문제
- 공지(`notice.tsx`, `NOTICE_ID="20260924"`)는 9월 내용에서 멈춘 채 홈 팁 최상위에 강제로 노출된다. 세션 숨김을 무시하고 `hasAssets`와 무관하게 뜨므로, 첫 방문자도 9월 공지를 본다.
- v4.69~v4.81 13건은 공지에 없다. 신규 기능 안내는 기능 팁 `isNew` 2개(최하위, 1개씩, X 누르면 영구 제외)가 전부다.
- 대부분 주 1회 방문하는데 배포는 하루 여러 번이다. 버전마다 알리면 피로하고, 알리지 않으면 놓친다.

## 2. 목표 행동
지난번 이후 새 소식이 있는 기존 사용자가 홈 팁 1개를 누른다 → 시트에서 놓친 항목을 한 번에 훑는다 → 관심 항목의 바로 가기로 그 화면에 들어간다. 같은 소식은 다시 팁으로 보지 않는다.

## 4. 사용자 흐름
1. 앱을 연다. 자산 데이터 불러오기가 끝난(`isDataLoaded`) 뒤에만 판정한다.
2. 홈 팁은 다음 순서로 1개만 고른다: 백업 > 임박 세금 > 결산(창 안) > **새 소식** > relink > 그 외 세금 > 최신화 > 기능 추천(저방문만).
3. 새 소식 팁 노출 조건(모두 충족):
   - 보유 자산 있음(`hasAssets`)
   - 체험·앱 잠금 아님
   - 안 본 항목 1개 이상
   - 기록 없음, 또는 기록의 `seenAt`에서 7일(7×24h) 이상 지남
4. 팁은 배지 `새 소식`, 제목 `새 소식 N개`(N = 안 본 항목 수), 설명 = 안 본 항목 중 맨 위 항목의 `title`로 구성한다.
5. 팁을 누르면 시트가 열린다. 같은 순간 기록을 목록의 최신 id로 바꾸고 `seenAt`을 지금으로 쓴다. '새' 표시는 열기 직전 상태로 계산해 시트가 열려 있는 동안 유지한다.
6. 시트 구성
   - 머리: 제목 `새 소식`, 보조 `지금 버전 v{APP_VERSION}`
   - 본문: 목록 1개(최근 60일, 최대 20개). 항목은 제목 + 본문(있으면) + 날짜(`M/D`)이고, 안 본 항목 모두에 `새` 표시를 단다(팁 N과 같은 개수, COO U1 11-11).
   - 바로 가기: `featureId`가 있는 항목에만 `바로 가기 ›`를 둔다. 누르면 시트를 닫고, 그 기능의 기존 이동(`beforeNavigate` → `action` 또는 `target`)을 그대로 실행한다. 기능 팁 dismiss는 하지 않는다.
   - 닫기: 닫기 버튼(brand), 바깥 탭, 스와이프
7. 팁의 X는 읽음 처리(5와 같은 기록)를 하고, 그 세션의 팁 박스 전체를 숨긴다(기존 규칙). 시트는 열리지 않는다.
8. 다시 보기 경로: 더보기 > `앱 가이드 · 새 소식` > `새 소식 보기`. 같은 시트가 열리고 5와 같이 읽음 처리된다. 7일 조건과 무관하게 언제든 열 수 있다.
9. 첫 실행: 불러오기가 끝났는데 기록도 없고 자산도 없으면 기록을 최신 id로 조용히 쓴다(GA 없음). 이후 자산을 등록해도 그 시점까지의 소식은 '새'가 아니다.

결산 창 안팎의 노출 순서(C82 대조표)

| 상황 | 이번 세션 홈 팁 | 새 소식 |
|---|---|---|
| 결산 창 밖, 상위 팁 없음 | 새 소식 | 지금 |
| 결산 창 안(결산 팁 뜸) | 결산 | 대기. 결산을 X로 닫아도 그 세션은 박스 전체 숨김. 창이 끝난 뒤 묶음으로 노출 |
| 결산 창 안, 결산 팁 없음(첫 달·스냅샷 없음) | 새 소식 | 지금 |
| relink 후보 있음 | 새 소식(7일에 1회) → 다음 세션부터 relink | relink보다 먼저 |
| 백업·임박 세금 해당 | 그 팁 | 대기 |

## 5. 데이터 계약
```ts
// src/config/whats-new.ts — 사용자용 변경 안내의 단일 출처
export interface WhatsNewEntry {
  id: string;          // "YYYYMMDD-NN": 게시일(KST)과 같은 날 안의 순번(01~99)
  title: string;       // 이득 한 줄, 해요체, 2~32자
  body?: string;       // 보조 한 줄, 48자 이하
  featureId?: string;  // APP_FEATURES의 id(바로 가기). 없으면 버튼 없음
}
export const WHATS_NEW: WhatsNewEntry[]; // 정렬: 날짜 내림차순, 같은 날은 NN 오름차순(= 큰 것부터)
```
- `version` 필드는 두지 않는다(K1). AssetView를 직접 지정하지 않는다(K3).
- 같은 날짜 안에서 NN이 표시 순서다. 큰 것(새 화면·기능) → 개선 → `고쳤어요` 순으로 매긴다.
- 문구 금지: 금액(숫자+원·만·억), 투자 판단 어휘(사도·팔아·싸다·비싸다·물타기·추천), 과장(완벽·혁신), 보장 어휘(안전·보호·차단), 실제와 다른 범위.
- 등록 시점: 사용자가 체감하는 변화가 있는 릴리스 PR에서 developer가 등록한다. PR 본문에는 `새 소식: <id> | 해당 없음(사유)` 한 줄을 넣는다(C82).

판정(순수 함수, `src/lib/whats-new.ts`)
- `parseEntryId(id) → {date:number, seq:number} | null`. 순번 없는 `YYYYMMDD`는 seq 0으로 읽는다. 해석 안 되면 null. **문자열 비교 금지.**
- `compareIds(a, b)`: 날짜 먼저, 그다음 순번을 숫자로 비교한다.
- 안 본 항목: id > 기록 id이고, 게시일이 오늘(KST) 기준 30일 이내. 기록 없음(키 없음·만료·해석 불가)이면 최근 30일 항목 전부다.
- 시트 목록: 게시일이 오늘 기준 60일 이내, 위에서 20개.

## 6. 저장 키 의미 (명세 대상, 새 키 없음)
- 키 `secretasset_notice_seen`, 값 `{ id, seenAt, expiresAt }`. 모양은 그대로 두고 의미만 바꾼다.
  - id: 공지 1건 → 마지막으로 읽음 처리한 새 소식 id
  - seenAt(ms): 7일 시계의 기준
  - expiresAt: 쓰는 시점 + 90일(S2. 구버전이 같은 키를 읽으므로 유지). 만료되면 기록 없음으로 본다.
- 쓰는 곳은 셋이다: 팁 클릭·X, 시트 열기(홈·더보기), 첫 실행 조용한 기록. 쓰는 값은 항상 `WHATS_NEW`의 최신 id다. 목록이 비면 쓰지 않는다.
- 그대로 유지
  - 동기화 payload 제외, 가져오기·pull 보존(`asset-storage.ts` 514행)
  - 레거시 `secretasset_notice_seen_*` 정리는 init 정리만 남긴다(`cleanExpiredNoticeKeys`에서 `currentId` 경로 제거, S5).
- 체험 모드: 판정하지 않고 쓰지도 않는다. 원본 보존 테스트(`trial-boot.test.ts` 141·205행)는 유지한다.
- preview `?demo=1`(S4): `skipDemoTutorial`은 더 이상 기록을 쓰지 않는다. 새 브라우저 데모의 결산 창 밖에서는 아무것도 조작하지 않은 상태로 새 소식 팁이 첫 팁이 된다(LEARNINGS 10-30). `?demo=empty`는 데모 표식이 있을 때만 키를 지우는 현행을 유지한다. `preview-safety.test.ts` 20번은 이 규칙에 맞춰 고친다.
- 구버전 기기 혼재: 기기 로컬 키라 기기마다 따로 동작한다. 충돌은 없다.
- 롤백(S3, decision-brief에 그대로 적는다)
  - 구버전은 `id !== "20260924"`로 9월 공지를 최우선·세션 숨김 무시로 1회 다시 띄운다. 결산 창 중이면 그 세션 한 번 결산을 가린다.
  - 다시 올리면 최근 30일 항목이 한 번 더 '새'로 보인다.
  - 자산 데이터 손실은 0이다.

## 8. GA (page_title '새 소식')
- `CATEGORY_TITLES.whats_new = "새 소식"`. 값 목록에 `category: whats_new`, `source: whats_new`를 추가한다. `notice`는 사용처 0으로 정리한다.
- 시트 열기: `feature_use {category:"whats_new", method:"view", source:"home_tip"|"more"}` → page_title `새 소식`. 같은 열림에 1회만 보낸다.
- 바로 가기: `feature_use {category:"whats_new", method:"click"}`. 이어서 대상 기능에 `entryCategory`가 있으면 `feature_use {category: entryCategory, source:"whats_new"}`를 보낸다(S6. 기존 진입 GA 이름 유지, 경로는 source로 구분. 예: `change_week_all`).
- 홈 팁 view·click·close는 기존 `home_tip` 그대로 둔다(종류 구분 없음).
- 예약 이벤트명은 쓰지 않는다(C67). 머지 시각을 4.72·4.73·4.79·4.81 판독 경계로 기록한다.

## 9. 엣지 케이스
- 빈 데이터: `WHATS_NEW`가 비었거나 60일 안 항목이 0개면 팁은 없다. 시트는 `최근 60일 동안 새 소식이 없어요`를 보여 준다(더보기 경로).
- 일부 갱신: 시트를 연 뒤 새 항목이 배포되면, 다음 판정 때 새 항목만 안 본 항목이 된다. 7일이 지나야 팁이 뜬다.
- 오래된 기록: 9월 `20260924`, 만료, 해석 불가 → 최근 30일 항목. 시드 8개 모두에 '새'가 붙고 팁은 `새 소식 8개`로 나온다(COO U1).
- 첫 사용자: 자산 0 → 팁 없음. 불러오기가 끝나기 전에는 판정·기록을 하지 않는다(S7). 동기화 복원 전 새 기기는 조용히 기록된다(손실은 소식뿐, 수용).
- 모든 데이터 삭제 뒤: 키가 지워지면 첫 실행과 같다.
- 앱 잠금 화면, 체험 모드: 판정하지 않는다.

## 10. 완료 기준 (qa가 그대로 검사)
1. 새 브라우저 `?demo=1`, 아무것도 조작하지 않은 상태, 결산 창 밖에서 홈 팁이 `새 소식 8개`이고 설명이 `합친 평단을 가격 흐름 위에서 봐요`다.
2. 결산 창 날짜로 고정하면 같은 조건에서 홈 팁은 결산이다. 결산을 X로 닫으면 그 세션에는 팁이 없다. 새로고침(같은 세션)해도 없다.
3. 팁을 누르면 `whats-new-sheet`가 열리고 항목 8개가 시드 순서대로 보인다. 8개 모두 `whats-new-item-new`가 있다(팁 N과 일치, COO U1). 머리에 `v{APP_VERSION}`이 보인다.
4. 시트를 닫고 새 세션으로 홈을 열면 새 소식 팁이 없다. `secretasset_notice_seen.id`는 시드 최신 id다.
5. 팁 X 뒤 새 세션에서도 새 소식 팁이 없다(읽음 처리).
6. 기록의 `seenAt`을 6일 전으로 두고 새 항목을 1개 추가하면 팁이 없다. 7일 전으로 두면 `새 소식 1개`가 뜬다.
7. `바로 가기 ›`를 누르면 시트가 닫히고 해당 화면이 열린다. D-02는 시장과 나란히, D-03은 자산 변화 주 탭, D-07은 인증카드가 열린다. D-08은 버튼이 없다.
