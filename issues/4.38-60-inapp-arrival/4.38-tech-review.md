## 2. 저장소·데이터 영향
- 스키마·키는 무변경이다.
- 데이터 영향이 있는 곳은 **감지 정규식 오탐**이다. `isInAppGateActive()` → `isBackgroundWorkBlocked()`로 이어져 시세·환율·스냅샷·부동산 갱신·자동 push가 멈춘다. `app_mode` 속성과 `welcome_view source` 값도 바뀐다.
- 음성 UA 고정 테스트로 막는다. `band\/`는 부분 문자열이라 이론상 다른 UA에 섞일 수 있다. 음성 샘플을 실제 브라우저 UA 그대로 고정한다.
- 롤백하면 이전 게이트로 돌아갈 뿐이고 데이터 손실은 없다.

## 3. 서버로 나가는 값
늘지 않는다. 0건 이동은 `origin + "/"`이며 쿼리·해시가 없다. 기존 GA 이벤트만 쓴다.

## 4. 게이트 판정 (순수 함수, spec 5절 표 그대로)
`!mounted ‖ standalone ‖ !isInApp → none` / `!isDataLoaded → cover` / `!hasAnyAssets && !isSharePending && !syncAssetId && !restoreHash → welcome(null 렌더)` / 그 외 `gate`(현행)
- **`restoreHash`는 게이트 마운트 시점에 1회 캡처(ref)한다.**
  - 공유 해시는 처리 후 `replaceState`로 지워진다(asset-data-context 1005·1044·1145).
  - 로드 후 시점에 읽으면 복원 링크 방문자가 웰컴으로 빠질 수 있다.
  - 대상: `share=`·`sync=`·`asset=`·`vault=`(cloud-sync-provider 357 기준)
- 동기화 해시 감지는 인앱이면 `isBackgroundWorkBlocked`로 막혀 해시가 남는다(provider 175). 그래도 캡처 방식으로 통일한다.

## 6. 테스트 계획 (node 환경, jsdom 없음)
1. `detect-browser`
   - 양성: Threads(`Barcelona`)·다음(`DaumApps`)·밴드(`BAND/`) iOS·Android 샘플
   - 음성: iOS·Android의 Chrome·Safari·삼성·웨일·Edge·Firefox 고정 샘플
   - standalone은 `isInAppGateActive`에 `window` 스텁(`matchMedia`·`navigator`)을 넣어 false 확인
2. `resolveInAppGate` 표 전 경우: 0건/1건/공유 대기/sync assetId/해시/로드 전/standalone
3. `hasAnyAssets` 5배열 경우와, 교체 3곳의 기존 동작 동일성(같은 입력에서 같은 bool)
4. `welcomeCtaState`: inapp 우선, standalone이면 inapp 아님. `renderToStaticMarkup(<WelcomeInAppCta/>)`에 `welcome-cta-wizard`·`welcome-cta-more`가 없는지 확인
5. `moveExternal`: iOS면 `clipboard.write` mock 호출 → fallback=true, Android면 `openExternal` mock 호출. `track` mock으로 `pwa_install inapp_move` 1회 확인
6. 기존 welcome-guide grep 불변 조건(C16 저장 경로 미접촉, `welcome_view` 1곳)이 계속 통과하는지 확인

## 8. 위험·미확정
- `InAppExternalGuide`의 고정 문구 "현재 웹페이지 주소가 복사되었습니다! … 앱 설치 기능이 지원되지 않으므로"가 spec iOS 캡션 "주소가 복사됐어요…"와 겹치고 맥락("앱 설치")도 어긋난다. `lastStep`만 주입하면 두 문구가 함께 보인다(질문 1).
- 완료 기준 5(전 진입점 0건 유지)
  - 슬롯 교체로 wizard·직접 입력·가져오기·동기화 연결 버튼은 렌더되지 않는다.
  - FAB·하단 네비는 웰컴에서 이미 숨겨진다(`page.tsx` 웰컴 분기에 FAB 없음, `bottom-nav:62`, `top-bar:121`).
  - 남는 경로 2개는 qa가 전수 확인한다.
    - 웰컴 분기에 숨겨 마운트된 입력 다이얼로그(`page.tsx` 웰컴 hidden div)에 이벤트(`dispatchAddStock`)로 진입하는 경로
    - Share Target 진입 경로
- 1건 이상인 Threads·밴드 사용자는 이번부터 PIN 게이트를 본다. 의도된 동작이다(합의).
