# #60 인앱 브라우저 도착 개선 — spec (design-final 2026-10-31 반영)

cto 통과(조건 4, risk:medium). 문구는 팀 확정(최종 확인은 반영 결정으로 갈음). 근거: issue-4.37 코드.

## 1. 문제
- `InAppBrowserGate`는 노출 조건이 `isInApp && !standalone`뿐이라(`in-app-browser-gate.tsx:44`) 자산 0건 방문자도 앱을 보기 전에 전체 차단된다. `hasAssets`는 PIN 분기에만 쓰인다(`:74-79`). 카페·카톡·Threads 유입이 인앱이면 첫 화면 접촉 자체가 없다.
- 감지 정규식 `kakaotalk|instagram|fbav|fban|fb_iab|line\/|naver\(inapp`(`detect-browser.ts:18`)에 Threads·다음·밴드가 없어, 이 인앱에서는 게이트 없이 일반 화면으로 열려 **자산을 등록하면 외부 브라우저로 옮길 때 유실되는 위험 구간**이 있다.

## 2. 목표 행동
- 인앱 + 0건 방문자가 웰컴을 보고 "외부 브라우저에서 시작하기"로 이동한다. 지표(기존 이벤트): `welcome_view{source: inapp}` 기기 대비 `pwa_install{method: inapp_move}` 기기 비율.

## 3. 범위
direction 2절. 인앱 + 1건 이상은 변경 없음.

## 4. 사용자 흐름
1. 인앱 도착. `isDataLoaded` 전까지는 **문구 없는 빈 덮개**(`bg-background`, 같은 z-layer). 경고 본문·버튼은 로드 후 판정이 false일 때만 보인다 — 0건 방문자에게 경고가 잠깐 보였다 사라지는 깜빡임과, 1건 이상 사용자에게 웰컴이 깜빡이는 것을 모두 방지.
2. 로드 후 판정 `showWelcomeInApp = 0건 && !isSharePending && !isSyncMode(sync assetId 없음) && 공유/동기화 해시 없음`.
   - true: 게이트 미렌더, 웰컴 렌더. CTA 슬롯 `data-state="inapp"`(아래 4).
   - false: 현행 게이트(PIN/동기화 링크 이동).
3. 웰컴 상단/하단 네비는 이미 웰컴에서 숨김(`top-bar.tsx:121`, `bottom-nav.tsx:62`). 자산 생성 진입점은 슬롯 교체로 렌더되지 않음: wizard 버튼·직접 입력·가져오기·동기화 연결 모두 `inapp` 상태에서 미노출.
4. 슬롯 `inapp`: 제목·본문·버튼 "외부 브라우저에서 시작하기"(brand) → 기존 `go(origin + "/")` 재사용(`track pwa_install inapp_move`). Android는 스킴 자동 이동, iOS는 주소 복사 + 슬롯 안에 `InAppExternalGuide`(기존 컴포넌트에 선택 prop `notice` 추가 — 상단 앰버 블록 안쪽을 캡션 "주소가 복사됐어요. 브라우저에 붙여넣어 주세요."로 대체, `lastStep`에 "이동한 브라우저에서 주소로 접속하면 이어집니다." 주입. 미전달 시 현행 그대로).
5. `go`는 게이트 컴포넌트 내부 로직이므로 훅(`useExternalMove`)으로 추출해 게이트·웰컴이 공유(중복 구현 금지).
6. (#59와 결합) 웰컴 ③의 "직접 둘러보기"는 인앱에서도 노출. 체험 중 종료 버튼은 외부 이동.

## 5. 경계 조건 (0건/1건)
| 상태 | 결과 |
|---|---|
| 인앱, 0건(5개 카테고리 모두 0), 동기화 없음, 해시 없음 | 웰컴 + inapp 슬롯 |
| 인앱, 1건 이상 | 현행 게이트(PIN 이동) |
| 인앱, 0건, `#share`/`#sync` 해시 | 현행 게이트(복원 링크를 외부로 넘겨야 데이터가 살아남음) |
| 인앱, 0건, 동기화 assetId 보유 | 현행 게이트(PIN 없이 sync 링크) |
| standalone(PWA) | 게이트 자체 비활성(변경 없음) |
| 데이터 로드 전 | 문구 없는 빈 덮개(경고 문구 미표시) |
| 체험 중(#59 `isTrialMode()`) | 게이트 미렌더(`resolveInAppGate` 맨 앞 `none`, #59 커밋에서 추가) |
- 0건 판정은 같은 5배열 판정이 4곳에 중복(`page.tsx:34`, `use-share-artifacts.ts:21`, `preview-gate.tsx:27`, `asset-data-context.tsx:857`). **`hasAnyAssets(data)` 헬퍼 1개를 `src/lib/asset/asset-storage.ts`에 export하고(preview-gate.tsx 27의 로컬 const 삭제) `page.tsx`·`use-share-artifacts.ts`·`preview-gate.tsx` 3곳만 교체**(`asset-data-context`는 요청 외 변경 금지로 제외). #59 `TrialGate`가 이 헬퍼를 재사용.
- 유실 위험 방어: 인앱 0건에서 자산이 생길 수 있는 경로가 하나라도 남으면 안 된다 → qa가 "wizard/직접 입력/가져오기/FAB/Share Target/튜토리얼 이벤트(`dispatchAddStock`)" 전수 확인.

## 6. 감지 보강
- 추가 토큰은 **3개만**: `barcelona`(Threads), `daumapps`(다음), `band\/`(밴드). `kakaostory`·`snapchat`은 국내 유입 채널 근거가 없어 제외. `line\/`처럼 느슨한 패턴 추가 금지.
- 오탐 영향이 게이트 화면 차단보다 크다: `isInAppGateActive()` → `isBackgroundWorkBlocked()`가 시세·환율·스냅샷 자동 갱신을 끄고 `welcome_view source`·사용자 속성 `app_mode`에도 쓰인다. 오탐 시 일반 브라우저 자산 보유자의 시세 갱신까지 멈춘다.
- 테스트: 양성 샘플 UA(Threads·다음·밴드)와 **음성 샘플 UA 고정** — iOS·Android의 Chrome·Safari·삼성·웨일·Edge·Firefox, 그리고 PWA standalone. 실기기 UA를 수집하지 못하면 알려진 한계(C9)로 기록(토큰은 알려진 UA 형태 기준 추정).
- 1건 이상 Threads·밴드 인앱 사용자는 이번 릴리스부터 게이트를 본다(의도된 보호, PIN 이동 경로 존재, 앱 공지 불필요 — 사업 절 합의).

## 8. 문구 (팀 확정)
- 제목 "자산 등록은 Chrome·Safari에서 시작해요" / 본문 "이 화면에서는 입력한 내용이 사라질 수 있어요." / 버튼 "외부 브라우저에서 시작하기" / iOS 캡션 "주소가 복사됐어요. 브라우저에 붙여넣어 주세요."
- 기존 게이트 본문("데이터가 유실될 수 있어 안전하게 이용할 수 없습니다")은 변경 없음.

## 10. 완료 기준
1. 카톡 UA + 0건 + 해시 없음: 전체 차단 없이 웰컴이 보이고 슬롯에 등록 버튼이 없다(`welcome-cta-wizard`·`welcome-cta-more` 부재).
2. 같은 조건 Android: 버튼 탭 시 외부 이동 스킴 호출, iOS: 주소 복사 + 가이드 표시.
3. 인앱 + 1건 이상 / `#share` / `#sync` / 동기화 보유: 현행 게이트와 동일.
4. 로드 전 순간에 웰컴·경고 문구 모두 보이지 않는다(빈 덮개). 0건 인앱: 이후 웰컴. 1건 이상 인앱(카톡 UA): 로드 뒤 현행 게이트가 보인다.
5. **인앱 0건 웰컴에서 모든 진입점을 눌러도 자산 0건이 유지된다**(`secretasset_assetData` 키 유무는 부트스트랩이 빈 기본값을 저장하는지에 따라 거짓 FAIL이 날 수 있어 기준으로 쓰지 않음 — qa가 확인).
6. Threads/다음/밴드 샘플 UA는 `isInApp=true`, 음성 샘플 UA(위 6절)는 false(테스트).
7. `welcome_view source=inapp` 1회, `pwa_install inapp_move` 버튼당 1회.
8. `hasAnyAssets` 교체 3곳(`page.tsx`·`use-share-artifacts.ts`·`preview-gate.tsx`)의 동작이 기존과 동일하다.
9. iOS 웰컴 펼침 후 "주소가 복사됐어요…"가 1회만 보이고 "앱 설치 기능" 문장이 없다. 설치 흐름·1건 이상 게이트의 iOS 가이드는 기존 문구 그대로다(`notice` 미전달 회귀).
