# #60 인앱 브라우저 도착 개선 — direction (경험 절)

상태: planning ① / 사업 절: (business-pm 작성 대기 — 비워 둠) / 근거: `in-app-browser-gate.tsx`, `detect-browser.ts`, `welcome-guide.tsx`

## 경험
### 1. 사용자가 하게 될 행동
- 카페·카톡·Threads 링크로 인앱에 도착한 자산 0건 방문자가 전체 차단 화면 대신 **웰컴 화면을 먼저 본다**.
- 웰컴의 CTA 슬롯에서 "외부 브라우저에서 시작하기" 한 번으로 Chrome/Safari로 이동한다(Android 자동, iOS 주소 복사 + 가이드).
- (#59와 결합) 인앱에서도 예시 둘러보기는 가능하다(메모리 전용이라 유실 위험 없음).

### 2. 범위
- 포함: 게이트 노출 조건 변경(0건·동기화 없음·공유/동기화 링크 없음일 때만 웰컴 노출), 웰컴 CTA 슬롯 4번째 상태 `inapp`, 감지 정규식 보강(Threads·다음·밴드 등), 자산 생성 진입점 인앱 차단 검증.
- **줄일 수 있는 것**: iOS 가이드 신규 제작(기존 `InAppExternalGuide` 재사용) / 신규 GA 이벤트(기존 `pwa_install{method: inapp_move}`·`welcome_view{source: inapp}` 재사용) / PIN 흐름 변경(1건 이상은 현행 유지).
- **하지 않을 것**: 인앱에서 자산 등록 허용, 자산 1건 이상 게이트 완화, 새 진입점·딥링크 스킴 추가, 외부 이동 후 "이어서 보기" 맥락 전달(쿼리 파라미터 금지 — `/`로 이동).

### 3. 기존 화면 변화
- 바뀌는 곳: 인앱 + 0건일 때 `InAppBrowserGate` 미노출(웰컴 노출), 웰컴 CTA 슬롯 `data-state="inapp"` 추가. 
- 그대로: 인앱 + 1건 이상 = 현행 게이트(PIN), 동기화 기기 = 현행, 앱 잠금, `isBackgroundWorkBlocked`(인앱이면 계속 true).

### 4. 사업 절에 대한 의견
- 대기 (사업 절 비어 있음). 미리 밝힐 입장: 효과 크기는 GA `welcome_view source=inapp` 비율을 모르는 상태 — 사업 절이 이 값을 사전 확인 조건으로 두는 것에 동의.

### 5. 대표 동의 대기 항목 (신규 문구)
- 슬롯 제목 "자산 등록은 Chrome·Safari에서 시작해요" / 본문 "이 화면에서는 입력한 내용이 사라질 수 있어요." / 버튼 "외부 브라우저에서 시작하기" / iOS 캡션 "주소가 복사됐어요. 브라우저에 붙여넣어 주세요."

(합의 절 미작성 — 합의 표기 없음)
