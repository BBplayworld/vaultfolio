## 3. 기술 위험과 필수 조건 (spec·tech-review에 그대로 옮긴다)
코드 사실은 다음과 같다(origin/main).
- `page.tsx`는 client 컴포넌트이고 SSR된다. 서버와 클라이언트 첫 렌더 모두 `isDataLoaded=false`(useState 초기값, effect에서 true)다.
- `html`에는 이미 `suppressHydrationWarning`와 `data-device` 사전 스크립트가 있다.
- CSP는 Report-Only이며 `'unsafe-inline'`을 허용한다.

| 위험 | 판정·조건 |
|---|---|
| 보유자 깜빡임(FOUC) | head 스크립트는 body 파싱 전에 동기로 실행되고 CSS는 렌더를 막는다. 그래서 속성과 CSS 방식이면 첫 페인트 전에 숨겨진다. **조건 K1**: 키 3개 중 하나라도 `getItem!==null`이면 `html[data-has-assets]`를 붙인다. 키는 `secretasset_asset_data`, `secretasset.physical_assets`(실물만 보유한 사용자), 레거시 `secretasset-asset-data`다. 값은 parse하지 않고 읽지도 않는다. 오판은 한쪽으로만 난다. 자산을 전부 지워 키만 남은 기기는 숨김 → 웰컴으로 지금과 같은 동작이 되고, 보유자가 웰컴을 보는 경우는 없다. |
| 새 인라인 스크립트 | **K2**: 새 `<script>`를 만들지 않는다. 기존 `data-device` try 블록에 붙인다. CSP 주석의 '인라인 5개 nonce 전환 대상'을 늘리지 않기 위해서다. |
| hydration 불일치 | **K3**: 사전 조각은 `isMobile`·`mounted`·`window`·기기 판정을 쓰지 않는 정적 마크업이다(히어로 h1·부제, 신뢰 한 줄 텍스트). 보안 펼침 버튼·미리보기·CTA·설치 박스는 넣지 않는다. 숨김은 CSS로만 하고 React 분기로 하지 않는다. |
| 웰컴 전환 시 재깜빡임 | WelcomeGuide 히어로·신뢰 줄에는 ENTER(fade·slide) 애니메이션이 있다. 그래서 사전 조각 → WelcomeGuide로 바뀔 때 '보임 → 사라짐 → 다시 떠오름'이 생긴다. **K4**: 전환 시 두 블록의 위치 이동 0, 재진입 애니메이션 0. 구현 방식(히어로·신뢰 줄 공용 컴포넌트 추출 또는 사전 페인트 시 ENTER 생략)은 ui-designer가 ui.md에서 정한다. h1은 동시에 2개가 되면 안 된다. |
| 인앱 브라우저(핵심 대상 a) | 덮개 문제가 있다. `InAppBrowserGate`는 mount 후부터 데이터를 읽기 전까지 `cover`(빈 전면 덮개)를 띄운다. 그래서 인앱 0건 방문자는 히어로 → 빈 덮개 → 웰컴 순서로 본다. 이번 과제의 효과를 바로 이 경로에서 깎는다. **K5**: html에 `data-has-assets`가 없고 restoreHash·syncAssetId도 없으면 `cover` 대신 `welcome`(미렌더)으로 판정한다. 순수 함수 `resolveInAppGate` 단위 테스트를 추가한다. 보유자·`#share`·`#sync` 진입은 지금처럼 덮개를 쓴다. |
| PWA 잠금 | 잠금 사용자는 자산 키가 있어 조각이 숨겨진다. 잠금 화면은 effect 뒤에 뜨지만 그 전 화면은 지금도 비어 있으므로 변화가 없다. 키 없이 잠금만 켠 기기는 웰컴이 잠금 화면 뒤에 깔린다. 이는 자산이 없어 노출할 데이터도 없는 경우라 수용한다. |
| 체험 `?trial=1` | TrialGate가 SSR에서도 로딩 덮개를 렌더하므로 조각 위를 덮는다. 영향 없음. qa 확인 1건만 한다. |
| preview `?demo=1` | 첫 주입 때는 키가 없어 조각이 잠깐 보인다. 이는 preview 전용 현상이며 결함이 아니다. **보유자 검증은 주입 후 새로고침으로** 한다. |
| localStorage 예외 | try/catch로 감싼다. 접근이 막혀 속성이 없으면 조각이 보이고, 그 기기는 자산도 읽지 못하므로 웰컴이 맞다. |
| SEO 클로킹 오해 | 수집기와 새 방문자는 같은 HTML을 같은 모습으로 본다. 숨김은 그 기기에 사용자 데이터가 있을 때만 걸리는 개인화라 클로킹 요건(수집기와 사람에게 서로 다른 내용)에 해당하지 않는다. 숨김 텍스트도 키워드도 없다. |
| SW 오프라인 폴백 | 캐시된 `/` HTML에 조각이 들어가도 보유자는 속성으로 숨겨진다. 영향 없음. |
| GA | `welcome_view`는 WelcomeGuide가 mount될 때만 보내므로 조각은 이벤트를 보내지 않는다. 이중 집계 0, 새 이벤트 0. |
| 데이터 안전 | 저장·스키마·키 쓰기·동기화·서버 전송 0. head에서 키 존재만 읽는다. 데이터를 잃을 경로가 없다. |
