## 판정: 통과(조건부) · 위험 등급 **risk:medium** (릴리스 4.77은 #147 때문에 high·대표 승인 머지)
- 근거: 저장 스키마·키·마이그레이션·동기화·서버 전송 0. 바뀌는 것은 기록 생성 규칙(신규 매수일 값, 첫 등록 교체 시 id 이어받기)과 입력 1줄. 기존 데이터를 다시 쓰지 않는다.

## 1~5 반대 검토
1. 꼭 해야 하나: 대표 결정(11-11 ①) 그대로. 재론 안 함.
2. 더 작게: 입력 1개·기본값·InfoHint 1개로 이미 최소. `resync-notice-3` 삭제(흡수)는 빼기라 찬성.
3. 중복: 매수일 정본 = 입력 줄 1곳, 행 표시 없음 — 중복 없음.
4. LEARNINGS·DECISIONS: v4.74 이어받기 원칙·C74(기본값 날짜 소비처)와 정합. 충돌 없음.
5. 측정: 익명 기기 기준 별도 지표 없음(GA 새 이벤트 안 만듦). 효과 판독은 운영 스모크(상세 `매수` 날짜·배당 올해 예상)로 한정 — 수용.

## 미결 1 판정 — 첫 등록 '교체'(merge)·'초기화 후 등록'(reset) 이어받기: **#146에 포함**
- 기획 주장 검증
  - "포함 안 하면 대표 결정 위배": **과장.** 결정 문장은 '새 종목' 매수일이고 교체 항목은 기존 종목이다. 다만 미포함 시 교체 항목이 새 id·입력 날짜로 다시 만들어져 기존 매수일·거래 연결을 잃는다 → v4.74 이어받기 원칙(DECISIONS 11-10)의 **취지 위배**는 맞다.
  - "#147 감지 불가": **부분적으로만 참.** 기본값(1/1)을 그대로 두면 #147 감지 조건(만든 해 1/1)에 걸린다. 사용자가 날짜를 바꾼 경우에만 감지 불가 → 그 거래는 영구 고아.
  - 결정적 근거: 미포함이면 #146이 **새 고아를 계속 만들고 #147이 뒤에서 치우는 구조**가 된다. 원천 차단이 '고치기 우선'에 맞고 코드도 작다.
- 도달 경로(코드 확인): 보유 ≥1이면 FAB는 맞추기로 분기(`stock-input.tsx:636`, `crypto-input.tsx:345`). 첫 등록 화면의 충돌 단계는 **/ratio 인계(`canOpenHandoff`에 보유 조건 없음)·온보딩 마법사 더보기 재진입**에서만 나온다. 드문 경로라 영향 작음.
- 구현 조건(필수)
  - C1. `holdings-conflict.ts`의 `resolveKept`는 **건드리지 않는다**(현금·대출 가져오기 공용). 주식·코인 전용 짝짓기 함수를 따로 두고, 고르는 순서는 맞추기 `pickPredecessor`와 같게(증권사 같음 → 매수일 이른 것 → 기존 순서), 1:1.
  - C2. 이어받은 항목 = `{...기존, 수량·평단·증권사·계좌(category)=화면값, positionSource:"manual", positionEffectiveDate: 오늘}` — 맞추기 이어받기(`apply.ts` 202행)와 같은 필드 규칙. id·purchaseDate·purchaseExchangeRate·description·비활성 필드 유지.
  - C3. merge에서 같은 키 기존 항목이 화면 행보다 많으면 남는 것은 현행대로 삭제(거래 고아 가능 — 기본값이면 #147이 잡음). 범위 확대 금지.
  - C4. 보조 줄 N·입력 줄 노출 = 선택 행 − 이어받는 행. 0이면 줄 없음(C75: 충돌 단계 `교체` 배지·중복 건수와 같은 판정 함수 사용).
  - C5. 충돌 단계 문구(`덮어쓰기`/`초기화 후 등록` 설명)는 바꾸지 않는다(보유 목록 기준으로는 여전히 참). 문구 추가 0.
- reset 포함 이유: 현행도 거래를 지우지 않고 숨길 뿐(고아)이라 '초기화'가 기록 삭제를 뜻하지 않는다. 같은 종목 기록을 살리는 쪽이 데이터 손실 0.

## 데이터 안전·누락 지적
- D1(C74 필수): dev-notes에 `purchaseDate` 소비처 표(결산 예측 `resyncInflowDate`·배당·보유 기간·연환산·거래 기준일) + main 대비 판정. 첫 등록 신규도 `stock_import_`/`crypto_import_` id라 기본 1/1 → 투입일 = 만든 날(현행 `resyncInflowDate` 그대로)임을 vitest로 고정. **첫 등록 경로도 (d') 대응 테스트 추가**(현재 맞추기만 있음).
- D2: 사용자가 작년 이전 날짜를 고르면 지난 결산 예측 구간이 그 날 기준으로 바뀐다 — 기존 '사용자가 고친 매수일' 규칙과 같아 수용. qa는 의도된 차이로 표기.
- D3: 첫 등록 주식 id 시각은 서버 `Date.now()`(route.ts 206) — 만든 날 계산에 문제 없음(epoch). 클라이언트에서 id 재생성 금지(#147 감지 기준 유지).
- D4: 이어받은 해외 종목 매입 환율은 기존 값 유지 — 첫 등록 화면의 오늘 환율로 덮지 않음을 픽스처로 확인.
