# 4.77 #146 spec — 스크린샷으로 새로 생기는 종목 매수일 일괄 입력

planner-designer · 2026-11-11 · 코드 기준 origin/main 89e7213 · 방향 = 대표 결정 2026-11-11(1) (direction 생략, DECISIONS 379행)
위험 등급 제안 **risk:medium** (기록 생성 규칙 + UI 입력 1개, 스키마 0). 릴리스 4.77은 #147(high) 동승이라 대표 승인 머지.

## 1. 문제
- 스크린샷으로 새로 생기는 종목의 매수일을 사용자가 고를 수 없다. 맞추기(`HoldingsResyncDialog`)는 1월 1일 고정 + 안내 줄(`resync-notice-3`)뿐이고, 첫 등록(`StockScreenshotImport`·`CryptoScreenshotImport`)은 서버가 준 **오늘**(`parse-screenshot/route.ts:215·346`)이라 올해 배당이 빠진다(v4.74 dev-notes §8 한계 4).
- 첫 등록의 `교체`(같은 티커·계좌 기존 항목이 있을 때 `resolveKept`) 항목은 새 id·오늘 매수일로 다시 만들어져 거래가 끊긴다. #147 감지 조건(매수일 = 만든 날)에도 걸리지 않게 바뀌면 안 되므로 같이 정리한다.

## 2. 목표 행동
- 스크린샷 미리보기에서 새 종목 매수일을 **한 번** 확인하거나 고치고 저장한다. 저장 후 상세 `YYYY-MM-DD 매수`가 고른 날, 성과 › 배당 올해 지급 예상에 그날 이후 지급분이 들어간다.

## 3. 범위
- 포함: 경로 4개 — ① 맞추기 주식 ② 맞추기 코인 ③ 첫 등록 주식(보유 0개, 온보딩 마법사, /ratio 인계) ④ 첫 등록 코인(보유 0개, 온보딩 마법사).
  - 입력 1개(일괄), 기본값 **올해 1월 1일**(KST today 연도, `resyncNewPurchaseDate` 재사용), 사용자 수정 가능.
  - 주식만 입력 옆 `InfoHint`(inModal) 1개. 코인은 배당이 없어 InfoHint 없음.
  - 첫 등록 `교체` 항목은 기존 항목을 이어받음(id·매수일·매입 환율·메모 유지, 수량·평단·증권사·계좌는 화면 값) — v4.74 이어받기와 같은 원칙.
- 줄일 수 있는 것: `resync-notice-3` 안내 줄을 **삭제**(입력 줄로 흡수). 결과 화면·토스트 문구는 그대로.
- 하지 않을 것: 종목별 매수일 입력, 매입 환율 1월 1일 조회, 서버 응답 변경(클라이언트 저장 시 덮어씀), GA 새 이벤트, 직접 추가 폼(이미 1/1 기본값, 4.75).

## 4. 사용자 흐름
1. 스크린샷 인식 → 미리보기.
2. 이번에 **정말 새로 생기는 항목**이 1개 이상이면 미리보기 하단(맞추기는 `새 해외 종목 매입 환율` 줄 바로 위, 첫 등록은 공통 적용 설정 아래)에 `새 종목 매수일` 줄이 보인다. 0개(전부 연결·이어받기·교체)면 줄이 없다.
3. 기본값 올해 1월 1일 그대로 두거나 날짜를 바꾼다. 주식은 ⓘ를 눌러 배당 영향 안내를 본다.
4. `맞추기`/`등록` → 새 항목 전부 그 날짜로 저장(저장 1회). 이어받은·교체 항목은 기존 매수일 유지.
5. 맞추기 되돌리기는 현행대로 새 항목 제거(매수일 입력값 무관).

## 5. 화면 문구 (ui-designer 검수 대상, 320 줄바꿈)
| 위치 | 문구 |
|---|---|
| 줄 제목 | 주식 `새 종목 매수일` / 코인 `새 코인 매수일` |
| 보조 줄 | `새로 들어가는 {N}개에 모두 적용돼요` (N = 실제 신규 건수) |
| InfoHint summary(주식) | `매수일 이전에 지급된 배당은 성과 › 배당의 올해 지급 예상에서 빠져요` |
| InfoHint 상세(주식) | `올해 1월 1일로 두면 올해 배당이 모두 들어가요. 나중에 종목 수정에서 바꿀 수 있어요` |
| 오류(빈 값·오늘 이후) | `오늘이나 그 이전 날짜를 골라 주세요` — 이때 `맞추기`/`등록` 비활성 |
- 투자 조언·금액 없음. 입력은 기존 `Input type="date"`(직접 추가 폼과 같은 것), `max` = 오늘(KST).

## 6. 데이터 계약
- `ResyncSelection`에 `purchaseDate?: string` 추가(메모리 상태, 저장 아님). `applyResync` 신규 항목 `purchaseDate = sel.purchaseDate ?? resyncNewPurchaseDate(today)`. `freshAdds`(이어받기 제외 신규 수) 판정 재사용.
- 첫 등록: 저장 시 선택 항목 중 같은 키(`keyOfStock`·`keyOfCrypto`) 기존 항목이 **없는** 것만 `purchaseDate = 입력값`. 있는 것은 기존 항목 이어받기(여럿이면 증권사 같음 → 매수일 이른 것), `merge`·`reset` 두 모드 모두. `reset`은 이어받지 않은 나머지만 지운다.
- id 규칙 불변(`stock_import_<ms>_N`·`crypto_import_<ms>_N`). `resyncInflowDate` 불변: 기본값 1/1 그대로면 결산 예측 투입일 = 만든 날, 사용자가 바꾼 날짜면 그 날(기존 '사용자가 고친 매수일' 규칙).
- **저장 스키마 변경: 없음.** 새 필드·키·마이그레이션·동기화·공유 토큰·서버 전송 diff 0. 결과 키 ⊆ 기존 Stock·Crypto 필드.

## 7. 엣지 케이스
- 신규 0개: 입력 줄 미노출, 저장 결과 main과 동일.
- 연초(1/1 당일): 기본값 = 오늘 = 1/1, 정상.
- 사용자 날짜가 작년 이전: 허용. 상세 보유 기간·연환산 수익률(1년 이상이면 표시)·결산 예측 구간이 그 날 기준으로 바뀜(직접 수정과 같은 동작).
- 해외 신규: 매입 환율은 현행(입력/오늘 환율), 매수일과 무관.
- 혼합(이어받기 + 신규): 입력은 신규에만 적용, 보조 줄 N은 신규만 셈.
- 첫 등록 `교체`에 거래가 있던 종목: 거래 연결 유지(거래내역 화면에 그대로 보임).
- 체험(`?trial=1`)·데모: 같은 동작, 저장은 기존 경로 그대로.

## 9. 완료 기준 (qa가 그대로 검사)
1. 맞추기 주식: 새 종목 2개 + 연결 1개 장 → `resync-new-date` 줄 1개, 값 `올해-01-01`, 보조 줄 `2개`. 날짜를 `2025-06-02`로 바꿔 적용 → 새 2개 상세 `2025-06-02 매수`, 연결 종목 매수일 불변.
2. 이어받기만 있는 장 → 입력 줄 미노출, `resync-notice-3` 어디에도 없음.
3. 맞추기 코인 신규 → `새 코인 매수일` 줄, InfoHint 없음, 저장 값 = 입력값.
4. 보유 0개 주식 첫 등록·온보딩·/ratio 인계 각각 → 입력 줄, 기본 1/1 그대로 저장 시 상세 `올해-01-01 매수`(오늘 아님).
5. 첫 등록 `교체`(같은 티커·계좌 기존 항목에 반영 거래 2건) → 저장 후 id·매수일 동일, 거래내역 2건 그대로 보임. `reset`도 동일, 화면에 없는 기존 항목만 삭제.
6. 빈 값·내일 날짜 → 오류 문구 + 버튼 비활성, 저장 0회.
7. InfoHint: 다이얼로그 안에서 열림(가려지지 않음), 히트영역 40px, 320·375 라이트·다크 줄바꿈 어절 갈림 0.
8. 배당: 새 종목(배당주) 기본 1/1 저장 → 성과 › 배당 올해 지급 예상에 1월 이후 지급분 포함. 6/2로 저장 → 6/2 이전 지급분 제외.
9. 결산 예측: 기본 1/1 저장 시 예측 구간 effects가 main(89e7213)과 동일(`resync-flows.test.ts` (d') 유지). 사용자 날짜는 그 날 투입(기존 (d'')와 같음).
10. 데이터 안전: 결과 키 ⊆ Stock·Crypto 스키마, JSON 백업 왕복·4.76 기기 동기화 수신 시 값 그대로, `git diff` 저장·키·서버 전송 0.
