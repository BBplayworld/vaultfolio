# 4.99 dev-notes — #193 스크린샷 2줄 헤더 평단·현재가 (빠른 경로)

## 원인
- `parse-screenshot/route.ts` 프롬프트에 "한 칸에 라벨 2개가 위·아래로 쌓인 표" 규칙이 없어, AI가 머리 라벨의 위·아래 순서(증권사마다 다름: 메리츠 매입가/현재가, 키움 현재가/평균단가)를 행의 숫자에 대응시키지 못하고 둘을 바꿔 읽음.
- 후처리(`processStockResults`)는 AI의 averagePrice를 그대로 신뢰했고(수익률은 평단이 없을 때만 역산에 사용), 수익률과의 정합 검사가 없었음.
- 클라이언트(`resync/diff.ts evaluateLink`)는 `averagePriceEstimated`가 아닌 평단이 기존과 0.1% 넘게 다르면 '변경'으로 덮어씀 → 바뀐 값이 그대로 기존 평단을 덮어쓴 것이 대표 지적 화면(평단이 현재가로 '변경').

## 수정
1. 프롬프트: 2줄 헤더 규칙(머리 순서 대응·순서 가정 금지·라벨별 필드·수익률 검산).
2. `price-consistency.ts reconcilePrices(cur, avg, rate)` 순수 함수: 일치 keep / 바꿔야 일치 swap / 둘 다 불일치 estimate(평단 0 → 기존 역산·`averagePriceEstimated` 경로, 클라이언트는 기존 평단 유지). 수익률 0·값 없음은 검증 생략. 허용 3%p.
3. route.ts는 `processStockResults` 맵 진입부에서 교정값으로 s를 대체(그 외 로직 무변경).
- 저장 스키마·키·동기화·GA·서버 전송 값 변경 0. 위험 등급 low.

## '메리츠증권' 그룹 진단 (대표 추가 화면)
- 그룹 증권사는 `confirmScreenBroker`(resync/match.ts): ① AI brokerHint가 목록명과 맞으면 그 값(다수결), ② 힌트가 없으면 화면 티커의 과반이 같은 broker를 가진 기존 항목과 일치할 때 그 broker, ③ 아니면 사용자가 선택. 사용자 선택 UI는 미확정일 때만 뜸.
- 키움 화면이 메리츠로 붙은 경로는 코드상 ①(AI가 화면 밖 단서로 '메리츠' 오인식) 또는 ②(키움 화면에 증권사 글자가 없고, 같은 티커 다수가 기존에 메리츠로 등록됨) 두 가지. 이미지의 요약만으로는 ②가 유력(기존 평단이 키움 값과 같은 항목이 메리츠 소속으로 매칭됨)하나 확정 불가. 둘 다 기존 설계 동작이며 오류 입력을 검증할 근거가 없어 이번 PR에서는 코드 변경하지 않음. 후속 후보: ②로 확정 시 '증권사 자동 추정' 표시 또는 사용자 확인 단계 강화(별도 이슈).
