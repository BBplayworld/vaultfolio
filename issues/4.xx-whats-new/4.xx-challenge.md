# 4.xx 새 소식 — cto 반대 검토 (planning ②)

작성 2026-11-11 · 대상 4.xx-direction-draft.md + 4.xx-business.md · 코드 origin/main cca5dbb(v4.81) 실측

## 판정: 축소 (방향 A 통과) · risk:medium · 머지 COO 자체 승인(대표 이견 시 승인 전환)

## 1. 꼭 해야 하는가 — 통과
- 대표 직접 지시(11-11). 그리고 지금 공지는 **9월 내용으로 멈춘 채 최우선·세션 숨김 무시로 살아 있다.** `pickHomeTip`은 `hasAssets`와 무관하게 공지를 먼저 고르므로, 지금 첫 방문자도 9월 "투자 유형 인증카드" 팁을 먼저 본다. 바꾸지 않아도 고쳐야 할 코드라 "새 소식으로 교체"는 정리를 겸한다.
- **가장 강한 반대 논거**: 주 활성 27명 규모에서 업데이트 목록은 효과를 거의 측정할 수 없고, 릴리스마다 사용자용 문장을 써야 하는 운영 부담과 "적는 걸 잊음" 같은 새 실패 경로가 생긴다. 하루 5건 배포가 "고쳤어요"로 줄줄이 보이면 안정감이 떨어져 보일 수 있다. → 반박: 기존 기능 팁 `isNew`도 릴리스마다 손으로 켜고 끄는 같은 부담이 있고, 이걸 흡수하면 부담은 늘지 않는다. 버그는 기간 단위 1줄로 묶고 목록 상한을 둔다(아래 축소).

## 2. 우선순위 — 결산 아래, relink 위 (대표 '강조'를 일부 줄임 → 알림에 명시)
- 판정 순서: 백업 > 임박 세금 > **결산(창 안)** > **새 소식** > relink > 그 외 세금 > 최신화 > 기능 추천. 지금의 "필수 노출·세션 숨김 무시"(`NOTICE_SHOWN_SESSION_KEY`)는 없앤다.
- 결산 위로 올리지 않는 이유: 결산 창은 매달 약 14일(말일−3일~10일). 결산은 월 1회 돌아오게 만드는 장치(원칙 4-1)이고 11/27~12/10에 #51·#54 판독이 걸려 있다(C38). 새 소식은 미뤄도 **쌓였다가 묶여서 나오므로 잃는 것이 없다.**
- relink 위로 올리는 이유(초안과 다름): relink는 X가 세션 단위라 처리 전까지 매 방문 이긴다. 그 아래면 끊긴 거래가 있는 사용자는 새 소식을 영영 못 본다. 새 소식은 7일에 최대 1회라 relink를 하루 늦추는 정도다.
- '강조'는 순위 대신 사업 검토의 장치로 채운다(수용): 7일 시계는 **열람·닫기 시점부터**(노출 시점 아님, `seenAt`), 문구 "새 소식 N개 · 가장 큰 이득 한 줄", 목록은 큰 것부터, 시각 강조는 ui-designer(빨간 점·모달 없음). 머지가 11/26 이전이면 첫 노출이 결산 창 밖에서 기존 사용자 전원에게 한 번 나간다.
- **사업 검토 정정(코드 확인)**: "결산 팁을 세션에서 닫으면 다음 팁으로 새 소식이 뜬다"는 **사실이 아니다.** 어떤 팁이든 X는 `SESSION_DISMISS_KEY`로 그 세션 박스 전체를 숨긴다(`home-tip-box.tsx` 114행). 결산 창 중 새 소식은 결산 팁이 안 뜨는 사용자(첫 달·스냅샷 없음)를 빼면 창이 끝난 뒤 묶여 나온다. 이 규칙은 바꾸지 않는다(LEARNINGS 11-06 '세션 단위 닫기 현행 유지', 바꾸면 모든 팁의 닫기 규칙이 바뀜). 알림 문안에 이렇게 적는다.
- relink와의 순서는 사업 검토(초안 순서 유지)와 다르게 판정한다 — 위 이유(relink 세션 닫기 반복 시 새 소식 영구 차단)로 새 소식 > relink.

## 3. `secretasset_notice_seen` 의미 확장 — 수용(새 키 만들지 않음), 명세 대상
- 키 이름·값 모양 `{id, seenAt, expiresAt}` 그대로, 동기화 제외·가져오기 보존(`asset-storage.ts` 514행) 그대로라 새 키보다 작다. 단 **값의 의미가 바뀌므로 spec.md 작성 대상**(specs 판정 '저장 키')이고 위험은 medium.
- 조건
  - S1 id 형식 `YYYYMMDD-NN`(2자리 순번). **문자열 비교 금지**(`-10` < `-9`). 날짜·순번을 숫자로 나눠 비교하고, 순번 없는 옛 값 `20260924`는 순번 0으로 읽는다. 해석 안 되는 값은 "기록 없음".
  - S2 `expiresAt`은 지금처럼 90일로 쓴다(구버전이 같은 키를 읽으므로). 만료 = 기록 없음.
  - S3 롤백 영향(확인함, 수용): 구버전은 `id !== "20260924"`로 9월 공지를 **최우선·세션 숨김 무시로 1회** 다시 띄운다. 결산 창 중이면 그 세션 한 번 결산 팁을 가린다. 다시 올리면 `20260924`가 가장 오래된 값이라 최근 30일 항목이 한 번 더 "새"로 보인다. 둘 다 데이터 손실 없음. decision-brief 롤백 절에 그대로 적는다.
  - S4 `?demo=1` 주입(`demo-inject.ts` 43행)과 체험 모드 원본 보존(`trial-boot` 테스트)을 새 함수로 옮기고 테스트 유지. preview 기본 상태에서 새 소식 팁이 보여야 한다(LEARNINGS 10-30: 아무것도 조작 안 한 상태로 확인).
  - S5 레거시 per-id 키 정리(`cleanExpiredNoticeKeys`)는 `NOTICE_ID` 없이 init 정리만 남긴다.

## 4. 공지·isNew 흡수 — 둘 다 흡수
- `notice.tsx`(본문·`NOTICE_ID`·`NOTICE_TITLE/SUMMARY`), 홈 팁 `notice` 종류, 세션 강제 노출 키, 더보기 공지 다이얼로그를 삭제하고 새 소식 시트 하나로. 9월 공지 내용은 옮기지 않는다(앱 가이드가 인증카드 사용법을 이미 다룸).
- `isNew` 우선 추천 제거 → 기능 팁은 저방문 추천만. 같은 기능을 두 팁이 따로 알리는 중복이 없어진다.
- 조건 S6: 4.72·4.79 판독 보호(DECISIONS 11-11 'market-compare isNew 유지')를 대신하려면 새 소식의 바로 가기가 **그 기능의 기존 진입 GA(`entryCategory` 예: `change_week_all`)를 같은 이름으로** 보내고 method만 `whats_new`로 둔다. 머지일을 4.72·4.79 판독 경계로 기록.

## 5. 등록 누락 방지 — PR 체크 + 형식 테스트(누락 자체를 CI로 막지 않음)
- 릴리스 PR 본문에 `새 소식: <항목 id> | 해당 없음(사유)` 한 줄 필수, qa가 확인(CHECKLIST C82 추가).
- vitest: id 형식·중복 없음·최신순 정렬·`target`이 실제 `APP_FEATURES` id·제목 길이 상한·금액 표기(숫자+원/만/억) 없음·투자 조언 어휘 없음.
- "항목이 없으면 실패"는 넣지 않는다 — 내부 수정만 있는 릴리스가 정상적으로 존재한다.

## 6. 신규 사용자 판별 — 시스템 신호만
- 판별 입력은 `notice_seen` 키 존재 여부와 `hasAssets`(보유 여부)뿐. 매수일·거래일·`lastUpdated` 같은 사용자 입력·가져오기로 바뀌는 날짜는 쓰지 않는다(LEARNINGS 11-11 #147).
- 조건 S7(결함 의심, spec·qa 확인): "기록 없음 + 자산 없음 → 최신으로 조용히 기록"은 **자산 데이터 불러오기 완료 뒤에만** 실행한다. 첫 렌더에 `hasAssets=false`로 판정되면 기존 사용자 전원이 조용히 읽음 처리돼 기능이 죽는다. 동기화 복원 전 새 기기도 같은 경로(손실은 소식뿐이라 수용).
- 자산 없음 → 팁 없음은 유지(지금 첫 방문자가 9월 공지를 보는 문제도 함께 해결).

## 7. 더보기 '공지사항 보기' → '새 소식 보기' — 수용
- 같은 자리의 라벨·대상만 바꾼다(새 진입점 아님, 기능을 더보기로 옮기는 것도 아님 → LEARNINGS 11-09·C57 비해당). 위임 ⑦ "큰 UI 방향 변경 아님" 충족.

## 8. 축소 (v1에서 뺌)
- K1 항목의 `version` 필드 제거 → 날짜만. 머지 순서로 표시 버전이 재배정되는 일이 잦아(C43) 항목 버전이 틀릴 수 있다. 시트 상단 `APP_VERSION` 1곳만.
- K2 "안 본 항목 / 지난 항목" 두 구역 → **목록 1개**. 표시 순서 = 파일에 적힌 순서(등록 시 큰 것부터 놓음, 사업 3절), 안 본 항목에 '새' 표시 최대 5개(사업 1절 수용), 최근 60일·20개 상한. "그 외 N개" 접기 없음.
- K3 `target`은 `APP_FEATURES` id 하나로(이동·GA가 이미 붙어 있음). AssetView 직접 지정 경로 없음.
- K4 기존 사용자 특례를 따로 두지 않고 일반 규칙 1개로: 안 본 항목 = 기록 뒤의 항목 중 최근 30일, '새' 최대 5개. 시드는 사업 6절 8개(v4.69 이후).
- 첫 목록 7번(4.80 인증카드 수량 가림) **위임 ⑤ 비해당**: ⑤는 저장·암호화·서버 전송·동기화에 관한 보안·데이터 문구다. 7번은 공유 이미지의 표시 동작 설명이다. 조건: 4.80이 실제로 가리는 범위만 쓴다. "안전·보호·노출 차단" 같은 보장 어휘는 쓰지 않는다. qa가 인증카드 종류별로 문구와 동작이 일치하는지 확인한다. 1·2·6번 진입 경로·용어도 qa 사실 확인.
- 그대로 뺌(초안 8절 동의): 자동 팝업·빨간 점·푸시, 공개 변경 기록 페이지·외부 게시, 내부 변경 항목, 이미지, 항목별 닫기.

## 9. 위험·버전·머지
- risk:medium — 홈 팁 우선순위 변경 + 저장 값 의미 변경(스키마·서버·동기화 0, 자산 데이터 무접촉).
- 버전: 다음 **4.82**(열린 릴리스 없음). 개발 진입 시 다른 릴리스가 먼저 열려 있으면 거기에 합류(위험은 높은 쪽).
- 머지: 위임 ④가 "저장 키 변경 0"으로 깔끔히 충족되지 않으므로 위임 머지(저위험)가 아니라 **risk:medium COO 자체 승인 트랙**(11-09 결정). 대표가 방향 확정 알림에서 우선순위에 이견을 내면 대표 승인으로 전환.
- 지표·가드레일: 사업 4절 수용 — `새 소식` 활성 머지 직후 7일 6명↑, 2·4주차 각 4명↑, 결산 창 `월 결산`·`홈` 활성 불감소(close 비율은 CSV 판독 불가라 제외). 미달 시 간격 7→3일 하나만 조정. GA page_title "새 소식"(예약 이벤트명 금지, C67). 머지 시각을 4.72·4.73·4.79·4.81 판독 경계로 기록.
