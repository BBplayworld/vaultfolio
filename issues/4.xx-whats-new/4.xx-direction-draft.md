# 4.xx 새 소식 — 놓친 업데이트를 홈 팁 1개로 묶어 안내 (direction 초안, planner-designer)

작성 2026-11-11 · 근거: 대표 지시(11-11) · 코드 origin/main(9394371) 실측 · GA 11/03~09
상태: 초안. business-pm "사업" 절·cto 반대 검토 전.

## 1. 문제 (현재 코드 근거)
- **공지가 9월에 멈춰 있다.** `notice.tsx` `NOTICE_ID = "20260924"`, 본문은 투자 유형 인증카드(v4.2x). 이후 v4.69~v4.81(11/09~11/11 사흘에 13건, 11/11 하루 5건)은 공지에 하나도 없다.
- **지금 살아 있는 홍보 통로는 기능 팁 `isNew` 2개뿐**(week-causes·market-compare). 우선순위 맨 아래(백업·세금·결산·relink·최신화 다음)이고, 한 번에 1개, X 누르면 그 기능은 영구 제외. 주 1회 오는 사용자는 한 방문에 최대 1개만 보고, 버그 수정·보존 개선(4.74 맞추기 후 매수일 보존 등)은 알릴 통로가 없다.
- **공지를 버전마다 바꾸면 결산을 가린다.** 공지는 "필수 노출"로 최상위 + 세션 숨김 무시(`NOTICE_SHOWN_SESSION_KEY`). 11-08 #93 challenge에서 같은 이유로 공지 ID 교체를 뺐다.
- **"지난번 이후 뭐가 바뀌었는지" 묶어서 보는 곳이 없다.** 더보기 > 앱 가이드·공지사항(GA 더보기 2명/주)은 최신 공지 1건만 보여 준다. `changelog.md`는 개발용이라 사용자에게 쓸 수 없다.
- 규모: 홈 활성 27명/주, 홈 팁 노출 5명·이벤트 19건. 하루 여러 번 배포하는데 대부분은 주 1회 오므로 버전마다 알리면 피로하고, 알리지 않으면 놓친다.

## 2. 사용자가 하게 될 행동 (관찰 가능한 행동)
1. 지난 방문 뒤 새 소식이 있으면 홈 팁 1개("새 소식 N개 · 가장 큰 항목 제목")를 보고 누른다.
2. 시트에서 놓친 항목(새 표시)을 한 번에 훑고, 관심 항목의 "바로 가기"로 그 화면에 들어간다(예: 시장과 나란히, 자산 변화 주 탭).
3. 다음 방문에는 같은 소식을 다시 보지 않는다. 다시 보고 싶으면 더보기 > 앱 가이드·공지사항에서 같은 목록을 연다.

## 3. 안 (권고: A)
| | A. 홈 팁 1개 + 새 소식 시트 (권고) | B. 홈 팁 안에 목록 펼침 | C. 배지 점 + 새 소식 화면 |
|---|---|---|---|
| 모양 | 팁 1줄(N개 요약) → 하단 시트에 항목 목록 | 팁 박스 안 최대 3줄, 줄마다 바로 가기 | 하단 네비·헤더에 점, 별도 화면 |
| 장점 | 첫 화면 높이 그대로, 공지 다이얼로그 자리를 시트로 바꾸는 정도 | 클릭 1번 줄어듦 | 상시 진입 |
| 단점 | 클릭 1번 더 | 홈 팁 높이 변동 → 첫 화면 최소(원칙 5) 위반, 다른 팁과 모양이 달라짐 | 새 진입점·점 → 첫 화면 최소·UI 피로, 하단 네비 "업데이트"(자산 맞추기)와 이름이 겹침 |

**A 상세**
- **데이터 출처**: 정적 목록 `src/config/whats-new.ts` 1개(단일 출처). 항목 = `{ id(YYYYMMDD-순번), version, title(한 줄, 담백한 해요체·금액 없음), body?(한 줄), target?(AssetView 또는 APP_FEATURES id) }`. 사용자가 체감하는 변화만 등록한다(GA·리팩토링·내부 수정 제외, 버그 묶음은 "고쳤어요" 한 줄로 묶음). 등록은 developer가 릴리스 PR에 함께 넣는다.
- **묶기 규칙**: "마지막으로 본 표시" 뒤에 나온 항목을 안 본 항목으로 보고 한 번에 보여 준다. 시트 위쪽에 안 본 항목(최대 5개 + "그 외 N개"), 아래에 지난 항목(최근 60일). 시트 상단에 현재 버전(`APP_VERSION`) 표시.
- **팁 노출 간격**: 마지막 열람 뒤 **7일이 지났고** 새 항목이 있을 때만 팁을 띄운다(자주 오는 사용자도 팁은 주 1회 이하). 시트는 7일 안이라도 더보기에서 바로 열 수 있다. → business-pm 확인
- **우선순위(제안)**: 백업 > 임박 세금 > 결산 > relink > **새 소식** > 그 외 세금 > 최신화 > 기능 추천. 결산(원칙 4-1 리텐션)을 가리지 않는다. 지금의 공지 "필수 노출·세션 숨김 무시"는 없앤다.
- **닫기·다시 보기**: 팁 누름(시트 열기) 또는 X = 읽음(#51 cto 판정과 같음), 표시를 최신 항목으로 옮긴다. 다시 보기는 더보기 > 앱 가이드·공지사항 > "새 소식 보기"(기존 "공지사항 보기" 자리를 바꿈, 새 메뉴 아님).
- **신규 사용자에게는 안 보임**: 보유 자산이 없으면 팁을 띄우지 않는다. 표시 기록이 없는데 자산도 없으면(첫 실행) 표시를 최신으로 조용히 맞춘다. 표시 기록이 없는데 자산이 있으면(90일 만료·기기 이전) 최근 30일 항목만 보여 준다.
- **기존 사용자 이행**: 지금 표시 `20260924`도 날짜라 그대로 비교된다 → 이후 항목 중 최근 30일·최대 5개만 "새"로 보이게 자른다(9월 이후 전부를 쏟지 않음).

## 4. 범위
- 포함: 새 소식 목록(정적)·홈 팁 종류 교체(notice → 새 소식)·시트 1개·더보기 공지 자리 교체·GA.
- **줄일 수 있는 것(합치기)**: ① 공지(`notice.tsx` 본문·`NOTICE_ID`·필수 노출 세션 로직)를 새 소식으로 흡수 → 공지 종류 삭제 ② 기능 팁의 `isNew` 최우선 추천을 새 소식으로 흡수 → 기능 팁은 저방문 기능 추천만 ③ 공지 다이얼로그 → 같은 시트 재사용.

## 7. 저장 키·명세 판정·지표
- **저장 키: 기존 `secretasset_notice_seen`(값 `{id, seenAt, expiresAt}`) 재사용 권고.** id = 마지막으로 본 항목 id(날짜 기반, 기존 `20260924`와 비교 가능), seenAt = 7일 간격 판정. 동기화 제외·가져오기 보존(`asset-storage.ts` 514행)이 이미 돼 있다. 새 키는 만들지 않는다. `feature_usage`는 기능 팁 전용이라 섞지 않는다.
- 명세 판정: 키·값 모양은 그대로지만 **id 의미가 넓어진다**(공지 1건 → 목록 표시) + 화면 2곳(홈·더보기)의 새 기능 → spec.md 작성 대상. 롤백 시 구버전은 `id !== "20260924"`로 옛 공지를 1회 다시 띄운다(무해, cto 확인). 예상 위험 medium(홈 팁 우선순위 변경).
- 지표(GA, 페이지 및 화면 CSV로 판독): 주 지표 = 새 소식 팁 노출 사용자 중 시트 연 비율, 시트 → 바로 가기 클릭 사용자 수. 보조 = 바로 가기 대상 화면(성과·자산 변화, 시장과 나란히 등) 활성 사용자 머지 전후. 가드레일 = 결산 팁 노출·월 결산 활성 사용자 감소 없음, 홈 팁 close 비율 상승 없음. 시트는 page_title "새 소식"으로 CSV에 잡히게 한다. 기존 `feature_use` category `notice` → `whats_new`(view·click).
