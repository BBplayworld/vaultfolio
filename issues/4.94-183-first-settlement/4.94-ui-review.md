## 판정: **UI 수정 요청 1건(필수)** — 나머지 승인

### 수정 요청 R1 (S3 체험 홈 Hero — 목표 미달) — `src/lib/preview/demo-data.json` 종목 `currentPrice`
- 현상: 375·320 모두 Hero `570,530,806원 ▲+1,940만원 (+3.5%) 전일 대비`, 아래 줄 `주식 시세 상승 +1,971만원`(ui-home-375-dark.png). 기대값 |Δ| ≤ 0.5%(ui.md 8-14, spec S3).
- 원인(실측): 체험 홈은 실시간 시세 API로 가격을 덮어쓴다. 지금 응답이 삼성 213,500·SK하이닉스 1,288,500·AAPL 354.88·BTC 95,840,000인데 JSON 기준가는 70,000·190,000·225·140,000,000이라 주식·코인 평가가 약 2.4배가 된다. dev-notes의 스트레스(주식·코인 ±10%)는 이 격차를 덮지 못한다. 방금 같은 세션에서 562.6M → 568.3M → 570.5M로 시세가 들어오는 동안 숫자가 계속 움직인다(첫 화면에서 보이는 숫자가 로딩 중 바뀜).
- 부작용: 같은 이유로 허브 `+28,917,636원 +5.4%`(월), `최근 7일 +17,496,857원`, 7일 화면 `시세 변동 +17,788,196원`이 모두 가짜 급등으로 보인다. 홈의 `11/12 종가 코스피 -0.6%`와 `주식 시세 상승 +1,971만원`이 서로 모순.
- 기대(developer 선택 가능, 디자인 의도는 "처음 열어도 숫자가 얌전하다"):
  (a) JSON 종목·코인 `currentPrice`·`averagePrice`와 스냅샷 값을 현재 시세 수준(위 가격대)으로 올리고, 부동산 `currentValue`를 순자산 웰컴 ±1% 유지되게 다시 맞춘다. 또는 (b) 체험에서는 실시간 시세 덮어쓰기를 끄고 JSON 가격을 그대로 쓴다(preview-safety 허용 시). (a)면 `demo-rebase.test.ts` 스트레스에 "라이브 가격 ×2.5" 케이스 추가.
- 확인법: preview 새로고침 후 5초 대기, Hero `전일 대비` |%| ≤ 0.5, 허브 월 증감 5% 미만 상식 범위.

- 팁 `볼 / 수 있어요` 줄바꿈은 `text-pretty`로 허용 범위.
