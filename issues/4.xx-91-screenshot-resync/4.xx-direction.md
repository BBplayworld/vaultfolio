## 경험

### 0. 지금 화면에서 실제로 일어나는 일 (코드 사실)
- 진입은 FAB `자산 업데이트` > `보유 현황 업데이트` > 주식/코인 > 스크린샷. 한 번에 **1장**. 기존과 겹치면 `덮어쓰기` / `초기화 후 등록` 중 고른다.
- `덮어쓰기`: 종목 키가 `티커:계좌유형`이라 **증권사를 구분하지 않는다**. 같은 종목을 두 증권사에 나눠 둔 사람이 한 곳만 올리면 두 줄이 지워지고 한 줄만 남는다(`holdings-conflict.ts:7,36`). 스크린샷에 없는 종목(판 종목)은 계속 남는다.
- `초기화 후 등록`: 다른 증권사·ISA·연금·비상장까지 **주식 전체를 지운다**(`resolveKept` reset이면 빈 배열).
- 두 방식 모두 항목을 **새 id로 통째 교체**한다. 매수일=오늘, 해외 매입 환율=오늘 환율로 덮이고, 거래 기록(`stockId`)은 옛 id를 가리킨 채 남아 **거래 화면에서 사라진다**(거래 화면은 현재 종목 id로만 거른다).
- 변경 전후 비교와 되돌리기가 없다.

→ 문제는 기능이 없어서가 아니라, 현행 두 선택지가 각각 "덜 지움"과 "너무 지움"이고 기록을 끊는다는 것이다. **새 기능을 더하지 않고 이 두 선택지를 하나의 흐름으로 바꾼다.**

### 1. 사용자 시나리오와 관찰 가능한 행동
| # | 상황 | 사용자가 하게 될 행동 |
|---|---|---|
| S1 | 3달 만에 연 사용자, 증권사 2곳(국내·해외 혼합) | 증권사 잔고 화면 4장을 한 번에 고른다 → 요약 `추가 2 · 변경 6 · 삭제 1 · 그대로 9`를 보고 삭제 1건을 확인 → `맞추기` 1번으로 끝낸다 |
| S2 | 한 증권사에서만 매매함 | 그 증권사 화면 1~2장만 올린다 → 다른 증권사 종목은 요약에 `그대로`로도 안 뜨고 건드려지지 않는다 |
| S3 | 같은 미국 종목을 증권사 2곳에서 다른 환율로 삼 | 한 증권사만 맞춰도 다른 증권사 줄과 두 줄의 매입 환율이 그대로 남는다. 새로 생긴 해외 종목만 `매입 환율` 1줄을 확인한다 |
| S4 | 코인 거래소 별도 | 주식과 같은 흐름으로 거래소 화면을 올린다. 범위 단위가 증권사 대신 거래소다 |

### 2. 정보 구조 — 하나의 흐름 `스크린샷으로 보유 현황 맞추기`
- **진입점은 기존 1곳 그대로**(FAB > 보유 현황 업데이트 > 주식·코인 > 스크린샷). 새 화면·URL·메뉴 0. 상세 화면의 같은 스크린샷 버튼도 같은 흐름.
- **모드 선택 0개**: `덮어쓰기`/`초기화 후 등록` 단계를 없앤다. 범위는 사용자가 고르는 게 아니라 **올린 스크린샷이 정한다** — "이 스크린샷에 나온 증권사(거래소)를 화면과 똑같이 맞춘다".
- 삭제 후보는 두 묶음으로만 보인다.
  1. `○○증권 화면에 없는 종목` — 기본 **삭제 체크**(나온 증권사 안에서 판 종목).
  2. `스크린샷에 나오지 않은 증권사·증권사 미지정 종목` — 기본 **유지**, 접힌 1줄. 펼쳐서 체크하면 삭제(S1에서 "전부 맞추기"를 원할 때). 비상장은 항상 기본 유지.
- 이것으로 대표 요구 ②의 "전체 교체"와 "이 증권사만 교체"가 선택지 없이 하나의 화면에서 해결된다.
- 대상: **주식·코인을 1건 이상 가진 사용자.** 0건 사용자의 첫 등록, 온보딩 마법사, /ratio 인계는 현행 대화상자 그대로(#48 판독 12/25 전 첫 등록 퍼널 무접촉). 현금·대출 스크린샷도 현행 유지.

### 3. 단계 (한 대화상자 안, 4단계)
1. **올리기**: 최대 5장 동시 선택. 장수만큼 AI 인식 횟수가 줄어든다는 사실과 `오늘 N회 남음`을 선택 전에 보인다. 보안 고지는 기존 문구 그대로(`SCREENSHOT_UPLOAD_NOTICE`).
2. **인식**: 장별 진행 표시. 실패한 장만 `다시 시도`/`빼기`, 성공한 장은 유지. 스크롤 캡처로 겹친 종목은 한 번만 센다. 같은 증권사·같은 종목이 두 장에서 수량이 다르면 그 종목만 `어느 값이 맞나요` 선택.
3. **변경 미리보기**(핵심 화면): 맨 위 요약 1줄(`추가 · 변경 · 삭제 · 그대로` 건수) → 묶음별 목록. 변경은 `수량 10 → 12`, `평단 변경` 처럼 **바뀌는 칸만** 전후로 보인다. `그대로`는 접힘. 입력 칸은 **확인이 필요한 칸만**(4절) 노출하고, 남아 있으면 `맞추기` 버튼 위에 `확인 필요 N개`.
4. **적용과 되돌리기**: `맞추기` → 결과 1줄 + `되돌리기` 버튼(같은 화면·토스트). 되돌리기는 앱을 닫기 전까지, 맞추기 이후 사용자가 직접 고친 항목은 제외하고 복원(#84 R1과 같은 원칙). 사본은 메모리만 — 저장 키·스키마 변경 0.

### 4. 자동 선택 우선, 수동 입력 최소화
- **기존 항목 찾기(순서)**: ① 티커+계좌유형+증권사 일치 ② 증권사가 비어 있는 기존 항목이 하나뿐이면 그것과 연결하고 증권사를 채움 ③ 티커 미인식이면 종목명으로 기존 항목 찾아 티커 재사용 ④ 후보가 둘 이상이면 그 종목만 `어느 증권사 줄인가요` 선택.
- **연결된 항목은 id·매수일·메모·매입 환율·증권사를 그대로 두고 수량·평단만 바꾼다** → 거래 기록 연결 유지(상세의 `나누기`가 이미 쓰는 "기존 값 보존" 방식, `stock-tab.tsx:514`).
- **증권사(거래소)**: 화면 글자 인식 → 그 장의 종목 대부분이 한 증권사의 기존 종목과 일치하면 그 증권사로 추정 → 그래도 없으면 **장마다 1번** 선택(종목마다 아님).
- **계좌유형(ISA·연금 등)**: 기존 항목에서 이어받음. 신규만 장 단위 1번.
- **매입 환율(해외)**: 기존 항목 = 기존 값 유지(수량이 바뀌어도). 신규 = 그 종목의 기록된 매수 거래 환율 → 없으면 오늘 환율 기본값, 신규 해외 종목 전체에 `매입 환율 일괄 설정` 1줄(1회). 과거 날짜 환율 조회는 API가 없어 하지 않는다.
- **매수일**: 기존 항목 유지. 신규는 수익률로 추정하는 기존 함수(`estimatePurchaseDateFromReturn`), 불가하면 오늘.
- **평단**: 화면에 평단이 없어 역산한 값이 기존 값과 반올림 차이뿐이면 `그대로`로 둔다(오차 기준은 spec).

### 5. 기록 보존과 숫자 영향 고지 (정확성 원칙)
- **맞추기는 거래 기록을 만들지도 지우지도 않는다.** 미리보기 하단 1줄: `거래 기록은 그대로 남아요. 손익·세금 계산에 쓸 매수·매도는 거래 기록으로 남겨 주세요.`
- **보유 현황이 정본, 거래 기록은 이력**(Manual-Wins, DECISIONS 2026-07). 기록 합계와 현재 수량이 달라도 v1은 경고·자동 보정하지 않는다(보정 거래 생성은 결산 원인을 바꿔 정확성 원칙과 충돌).
- 삭제된 종목의 거래 기록도 보관한다(개별 삭제와 다른 규칙 — tech-review 확인 대상, 7절 Q1).
- 결산·스냅샷: 계산 코드는 건드리지 않는다. 거래 기록 없이 바뀐 원가는 현행 규칙대로 `주식(코인) 매수·매도`에 합산되고(`asset-report.ts:709-711`), 지난 스냅샷은 바뀌지 않는다. 미리보기에 `이번 달 결산에는 직접 고친 값과 같은 방식으로 반영돼요` 1줄(C24: 사용자가 자기 행동과 연결 가능).
- 삭제 묶음 아래 1줄: `팔아서 없어진 종목이면 매도 기록을 남겨야 양도세 계산에 들어가요`(해외주식 보유자에게만).

### 6. 범위
- **포함**: 주식·코인 보유자의 스크린샷 흐름 교체(여러 장, 변경 미리보기, 증권사 단위 자동 범위, 기존 값 승계, 되돌리기), 증권사 미구분 삭제 결함 해소.
- **줄일 수 있는 것**: 코인(용량 부족 시 v2로, 주식 먼저) · 두 장 수량 충돌 선택(v1은 큰 값 + 확인 필요 표시로 대체 가능) · 결산 영향 1줄(판독 후 문구 조정).
- **하지 않을 것**: 마이데이터·계좌 연동·자동 매매 연동 / 투자 조언·매매 권유 문구 / 차이를 거래 기록으로 자동 생성 / 과거 환율 조회 API / 되돌리기 사본 저장(새 저장 키) / 주식·코인 한 번에 섞어 올리기 자동 분류 / 마지막 맞춘 날 알림(LEARNINGS 경과일 알림 반려) / 새 보안 문구 / 현금·대출 스크린샷 변경 / 0건 사용자·마법사·/ratio 흐름 변경.

### 8. 결산·첫 화면 충돌
- 결산 화면·홈 결산 팁·웰컴·첫 등록 퍼널 코드 변경 0 → 결산 창(11/27~12/10) 제약 대상 아님. 다만 창 중 머지되면 사용자가 맞추기를 결산 직전에 써서 월 원인의 `주식 매수·매도` 크기가 커질 수 있다 — 판독(#51·#54) 메모에 머지일 기록.
- 위험: 대량 교체·삭제 + 동기화 전파 → **risk:high, 대표 승인**(위임 머지 ⑦ 큰 UI 변경에도 해당).
