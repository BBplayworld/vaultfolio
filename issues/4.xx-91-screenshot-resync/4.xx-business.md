## 0. 앱 안 기존 기능 대조 (#71 교훈)
이미 있는 것: 보유현황 스크린샷 재등록(주식·코인·현금·대출) + "덮어쓰기/초기화 후 등록" 선택(`holdings-conflict.ts`), FAB 허브 "보유 현황 업데이트"(InfoHint에 '재동기화'라고 안내 중). **"스크린샷으로 다시 맞추기" 자체는 이미 있다.** 새로 만드는 이유는 아래 빈틈 4개뿐이고, 이 빈틈을 못 메우면 착수 이유가 없다.
1. **덮어쓰기는 판 종목이 남는다** — 같은 종목만 바꾸고 나머지는 유지. 매도 기록을 빠뜨린 종목이 계속 남아 현황이 어긋난다(대표 문제 그대로).
2. **초기화는 증권사 구분 없이 주식 전체를 지운다** — 증권사 2곳 이상인 사람은 쓸 수 없다.
3. **한 번에 1장** — 보유 종목이 한 화면에 안 들어가면 맞출 수 없다.
4. **바뀐 내용 요약·되돌리기 없음** — 무엇이 늘고 줄고 사라지는지 보고 적용할 수 없다.

→ 권고: **새 화면·새 URL이 아니라 기존 보유현황 스크린샷 흐름을 고친다**(줄이기 우선). "증권사(거래소) 단위로 맞추기 + 여러 장 + 변경 요약 + 되돌리기"가 이번 과제의 전부.

## 1. 누구의 어떤 문제 / 월 활성 100 기여
- **누구**: 엑셀·노션에서 넘어와 주식을 2곳 이상 증권사에 두고, 매매 때마다 기록하지 못하는 3040. 한두 달 안 열다가 "숫자가 틀렸겠지" 싶어 다시 안 여는 사람.
- **가설("숫자가 낡아서 떠나는 사용자")**: PRINCIPLES 4장 진단(스크린샷 갱신 구조라 숫자가 낡고 다시 열 이유가 사라진다) 그대로. 지금은 낡은 걸 고치는 비용(종목별 수정·거래 입력)이 돌아올 이유보다 크다. 5분 안에 다시 맞출 수 있으면 돌아올 문턱이 낮아진다.
- **기여 경로와 솔직한 크기** (기준선: GA 28일 활성 약 33, 자산 저장 3명·거래 입력 3명)
  - 재활성(낡아서 멈춘 기존 보유자 복귀): 가장 큰 경로지만 **월 2~5명 수준**.
  - 잔존(매달 결산 전에 맞추고 결산을 보는 습관): 결산 의식(우선순위 1)의 전제 조건. 숫자가 틀리면 결산도 안 본다.
  - 재방문 빈도: 소폭.
  - **신규 유입: 직접 기여 없음.** 병목(월 신규 약 17명)은 그대로. 간접 효과는 마케팅 문구 1개("오랜만에 열어도 한 번에 맞춰") 정도.
- 결론: 100명 달성의 주 엔진은 아니고 **이탈을 막는 바닥 다지기**. 대표 직접 요청이고 결산 리텐션의 전제라 진행 권고. 신규 유입 과제를 대체하지 않는다.

## 3. 성공 지표 (GA page_title 단일 규칙, 신규 맞춤 정의 0)
- **page_title 3개 확정(2026-11-08, planner 화면명 채택)**: `보유 현황 맞추기 시작`(인식 1장 이상 성공 후 변경 미리보기 첫 열림, 흐름당 1회 — 장수만큼 보내지 않음) · `보유 현황 맞추기 적용`(맞추기 완료, 1회) · `보유 현황 맞추기 되돌리기`(되돌리기 실행, 1회). 주식·코인 구분 접미사는 붙이지 않는다(표본 분산 방지, 자산군은 직전 `스크린샷 등록·주식/코인`으로 참고).
- **퍼널**: 시작 기기 수 → 적용 기기 수. 기존 `스크린샷 등록·주식`(인식 시도)은 그대로 두되, 여러 장이면 장수만큼 늘어나므로 머지 전후 비교에 쓰지 않고 입구 참고만.
- **asset_save 중복 전송 금지 조건(planner 확인 완료)**: ① 맞추기 적용 경로는 `asset_save`를 보내지 않고 `보유 현황 맞추기 적용` 1건만 ② 되돌리기도 `asset_save` 없음 ③ 맞추기 흐름은 **그 자산군 보유 1건 이상**일 때만 열리고, 0건이면 현행 첫 등록 대화상자(현행 `asset_save`·first_asset_saved 그대로) — 판정 단위(자산군별 vs 전체)는 spec에서 확정 ④ 미리보기에서 사용자가 직접 고친 칸도 같은 1건에 포함. first_asset_saved 0 문제는 이 과제로 풀리지 않는다.
- **판독(머지일 기준 8주, 대표 기기 `?ga-optout=1` 제외)**
  - 성공: 적용 기기 3대 이상 + 시작 대비 적용 50% 이상 + 되돌리기/적용 30% 미만.
  - 판별 불가: 적용 1~2대 → 숫자로 판정하지 않고 8주 연장, 정성 기록.
  - **실패**: ①시작 5대 이상인데 적용 30% 미만(요약 화면에서 믿지 못함 → 인식 품질 문제) ②8주 적용 0(입구가 안 보임) ③되돌리기/적용 50% 이상(인식 오류). ①③은 v2 확장 중단·원인 수정, ②는 입구만 손본다.
  - 보조(표준 기능만): GA 탐색 코호트로 `재동기화 적용` 기기의 4주 내 재방문 여부 — 표본이 작아 참고만.

## 4. 위험과 사업적 안전장치
- **AI 인식 입구 비용·한도**: 현행 기기 15회/일·IP 30회/일·서버 전역 300회/일. 여러 장 허용 시 증권사 2곳×3장+코인 1장 = 7회로 기기 한도 절반. **v1은 한 번에 최대 5장, 남은 횟수 표시, 한도 상향 없음.** /ratio 입구 풀(전역 60·IP 5)과 분리 유지. 현재 규모(전역 300 대비 실사용 미미)에선 비용 위험 낮음.
- **인식 오류 → 신뢰 훼손(최대 위험)**: 틀린 수량으로 판 종목이 지워지면 "자산 앱이 내 자산을 지웠다"가 된다. 안전장치(전부 v1 필수):
  1. 적용 전 **변경 요약 미리보기**(늘어남·줄어듦·새로 생김·사라짐), 사라짐은 항목별 체크로 보존 가능.
  2. **되돌리기**(직전 상태 복원). #84의 메모리 보관+복원 패턴 재사용, 저장 키·스키마 무변경이 조건.
  3. 범위는 **고른 증권사(거래소)만** — 다른 증권사·다른 자산군 무접촉.
  4. 거래 기록은 만들지 않는다는 사실을 화면에 1줄(손익·세금 기록은 거래 입력으로). 사실과 다른 기대 차단.
- **보안 문구**: 신규 문구 만들지 않고 확정 문구 재사용 — "스크린샷은 AI 인식을 위해 전송돼요. 인식된 자산 값은 이 기기에 저장돼요." 새 문구가 생기면 위임 머지 ⑤ 위반 → 대표 승인.
- **결산 판독 오염**: 수량 정정이 월 결산 원인에 어떻게 잡히는지 tech-review 확인 필요(결산 코드 무접촉이 원칙). 위험 등급은 **risk:high, 대표 승인**(planner 판단 동의, 2026-11-08 — 여러 증권사 대량 삭제·교체가 동기화로 다른 기기에 전파, 기존 화면 흐름의 큰 변경으로 위임 머지 ⑦ 비해당).
- **여러 증권사 v1의 추가 위험**: 장의 증권사를 잘못 붙이면 다른 증권사 종목이 삭제 후보가 된다. 안전장치: 증권사가 확정되지 않은 장(인식 실패·사용자 미선택)은 삭제 후보를 만들지 않음, 스크린샷에 없는 증권사 묶음은 기본 유지(접힘이라도 건수는 보이게).

## 대표 판단 포인트 (권고안)
- **코인 포함** → v1 포함 권고. 대표 요청 원문이고 기존 코인 스크린샷도 같은 구조라 범위 단위만 거래소로 바뀐다. 용량 부족 시 가장 마지막에 줄인다.
- **거래 기록 미생성 수용** → 수용 권고. 차이를 거래로 자동 생성하면 결산 원인·양도세 계산이 실제 매매와 달라진다. 미리보기 1줄로 알리고, 해외주식 삭제 종목엔 매도 기록 안내 1줄.
- **기기 하루 15회 한도 유지** → 유지 권고. 1회 최대 5장이면 증권사 2곳+코인 1곳을 하루에 맞추고도 남는다. 8주 판독에서 한도 초과(`limit`) 실패가 반복되면 그때 재검토.
