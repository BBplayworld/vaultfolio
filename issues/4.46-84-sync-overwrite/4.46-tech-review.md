세부(A): 사전 사본은 `runPull` 진입 시 `getAssetData()`를 ref에 보관(해제는 다음 pull/새로고침). 목록 diff는 사용자 입력 필드 기준 순수 함수(저장·push·notifyAssetUserEdit 미호출, CHECKLIST C16). 기준점이 세션 메모리(`lastSyncedData`: push 성공·pull 성공 시 갱신)에 있을 때만 3-way 판정, 없으면 "내 변경 보관됨(전체 복원/백업)" 문구로 폴백. 복원은 백업 내보내기 재사용 + `applyImportedPayload` 후 push(baseVersion 최신이라 통과).

## 3. 데이터 영향 범위·CHECKLIST 대조
- 건드리는 것: 동기화(pull/push)·로컬 저장(복원 시)·스냅샷(`keepLocalSnapshots` 유지, 변경 없음). 거래·공유·백업·성적표 계산 변경 없음(데이터 값 자체는 B에서만 달라짐).
- C5·C13(구/신 혼재): A는 pull 결과 동일하므로 해당 없음. B는 A(신)/B(구) 별도 storage push->pull->저장->push 순환 테스트 필수.
- C6·C14(롤백): A 저장 변경 0. B 필드 추가만(구버전 무시)·혼재 시 폴백.
- C16: 감지 함수는 순수, 렌더·effect에서 save/notify 호출 금지(grep 검증).
- C17: 복구 경로 = 세션 내 사전 사본 복원 + 백업 JSON. 새로고침 후 소실은 알려진 한계.
- 보호 불변: 닉네임 등 payload 필드 원격 우선, 월 스냅샷 `mergeMonthlySnapshots` 불변.

## 4. 회귀 테스트 설계 (기기 2개 localStorage 분리, 서버 409 모의 — qa 재현 하네스 재사용)
공통: 현금 c1=1000·c2=500, 주식 S1 수량 10 동기화(v1), B가 c1=2000 push(v2) 후 A(v1)가 편집·push -> 409 -> force pull.
1. 같은 항목 수정(c1): 결과 c1=2000(원격 우선 유지), 알림 목록에 c1 포함(A) / B안에서도 원격값.
2. 무관 항목 수정(S1=99): A안 = 일단 덮이되 목록·복원으로 99 복구 가능 / B안 = S1=99 보존·push됨.
3. 삭제(c2): A안 = 부활 후 "삭제 취소됨" 알림·복원 / B안 = 삭제 유지, B기기 pull 후에도 삭제.
4. 신규 추가(c3): 보존(현행 불변) + 알림 목록에 오탐으로 안 뜸.
5. 오프라인 복귀: A 오프라인 편집 -> online 이벤트 force pull. 세션 유지(기준 있음) / 재시작(기준 없음 -> 폴백, 오탐 표기, 데이터 불변).
6. 추가: 편집 없음(userEdit=false) pull은 알림 0건, 닉네임·스냅샷 불변, 지문 버전 불일치 시 현행 폴백(B), forgetRemembered가 신규 필드 보존(B), 마이그레이션 "필드 없는 옛 `secretasset_sync` -> 새 버전" 복원 테스트(B).

## 5. 추천
**1단계 A(스키마 무변경)**: 소실을 "복구 가능+알림"으로 즉시 막는 최소안. 저장 키·sync-state·payload·서버 무변경, 롤백 = revert. 삭제 부활도 알림·복원으로 커버(방지는 아님).
**B는 후속(대표 승인 시)**: 근본 해결이지만 sync-state 필드 추가 + 병합 규칙 변경 = 명시적 high. C는 B 도입 때만 묶음.
(A로도 사용자 기록 손실은 "복구 가능"이지 "방지"는 아님 -> 대표가 방지를 원하면 B 필요.)

## 6. 위험 등급 초안
**risk:high**(동기화 경로·복원 push). A 증분은 medium, B는 high. 서버 전송 값 증가 없음 = E2EE 원칙 준수.

## 7. 일정
A 2~3일(순수 diff 함수+테스트 1일, provider 연결·UI 1일, qa 재현 4케이스 회귀 0.5일) / B 추가 5~7일 / spec 대비 범위: 4.38 r2의 "알림만"에서 "세션 내 복원"이 늘지만 가족 UI·고지는 제외로 상쇄.

## 8. 대표 승인 결정점 (한 줄)
스키마 무변경 A(소실 복구 가능+알림)로 먼저 갈지, `secretasset_sync`에 `syncedHashes` 필드를 추가하는 B(소실·삭제부활 근본 방지, risk:high)까지 이번에 포함할지.
