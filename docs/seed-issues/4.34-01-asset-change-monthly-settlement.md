# [시드1] 성과 메뉴 정리 + 자산 변화 월 탭 = 월말 결산

## 1. 한 줄 요약
성과 메뉴를 **자산 변화 / 배당 / 자산 성적표** 3개로 정리하고, 자산 변화의 **월 탭을 "월말 결산"** 으로 만들어 사용자가 한 달에 한 번 확실히 돌아오게 한다.

## 2. 왜 지금인가
- 월 활성 사용자 약 50명, 감소 추세. 목표는 100명 이상.
- 진단: 시크릿에셋은 스크린샷으로 갱신하는 구조라, 갱신하지 않으면 화면이 낡은 숫자가 되고 다시 열 이유가 사라진다. 마이데이터 앱과 달리 "가만히 있어도 숫자가 바뀌는" 경험이 없다.
- 그래서 신규 유입보다 **돌아올 이유**가 먼저다.
- 목표 지표가 "월" 활성 사용자이므로, 매일 습관이 아니라 **한 달에 한 번의 의식**을 설계한다. 자산관리는 매일 볼 필요가 없다.
- 결산은 "갱신하러 오는 날"이기도 하다. 결산을 보려고 들어온 사용자가 스크린샷을 올리면 데이터 신선도 문제도 함께 풀린다.

## 3. 현재 성과 화면 (2026-08 스크린샷 기준 — 반드시 현재 코드로 재확인)
> 라이브 코드와 버전 차이가 있을 수 있다. planner-designer는 direction.md 작성 전 실제 컴포넌트·라우트를 읽고 이 표를 고친다.

| 현재 메뉴 | 카드 요약 | 내부 구성 |
|---|---|---|
| 순자산 | 자산 총액과 추이, 전년 대비 | 년도별(라인 차트 + 연도별 수동 입력·수정·삭제) / 월별(막대 + 월별 증감 목록) / 일별(캘린더에 일별 순자산·증감, "연속 N일 기록 · 기록률 %") |
| 수익 | 기간별 수익, 일별 대비 | 일별/주간/월간/연간 × 전체/국내/해외, 기준 종가 비교, 종목별 증감. 영업일·접속일 기준 선택 가능 |
| 배당 | 올해 배당 (지급 + 예상) | 예상 포함/지급만, 월별 누적 막대(국내·해외·IRP·ISA·연금저축), 종목별 배당월·주당·지급액·예상액 |
| 자산 성적표 (Plus) | 이자 뺀 실수익, AI 진단 | 종합 등급·별점, 투입 대비 성과(넣은 돈·이자·남긴 돈), 5축 측정, 순자산 변화 "왜?", 전체 자산 AI 프롬프트 |

홈에도 "지난 접속 이후 증감"과 "순자산 추이(최근 7일)"가 있다.

## 4. 이미 결정된 것 (대표 결정, 다시 논의하지 않음)

### 4-1. 메뉴 구조
- 순자산과 수익을 **"자산 변화" 하나로 통합**. 이유: 사용자에게는 둘 다 "기간 대비 자산이 얼마나 변했나"로 인식되어 혼동된다.
  - 기간 탭: **일 / 주 / 월 / 연**
  - 범위 토글: **전체 자산 / 주식** — 지금 무엇을 보는지 상단에 항상 표시 (기존 수익은 주식만, 순자산은 전체라 측정 대상이 다름)
- **결산은 별도 메뉴를 만들지 않는다.** 자산 변화의 **월 탭이 곧 결산 상세**다.
- 성적표 안의 "순자산 변화 왜?"는 자산 변화 월 탭으로 이동한다.
- 결과적으로 성과 메뉴: **자산 변화 / 배당 / 자산 성적표** 3개.

### 4-2. 결산 진입점
- 매월 말~초 기간에만 성과 화면 최상단에 **"N월 결산이 준비됐어요" 요약 카드** 노출 → 탭하면 자산 변화의 월 탭(해당 월)으로 이동.
- 리마인더는 Push가 아니라 **캘린더 등록(.ics)**: "매월 결산일" 일정을 사용자 캘린더에 한 번 추가. 서버·푸시 권한 불필요, iOS PWA 제약 회피.

### 4-3. 월 탭(결산) 구성 — 위에서 아래로
1. 헤더: "N월 결산" + 기준일 (전월 마지막 기록 → 당월 마지막 기록, 진행 중인 달이면 현재)
2. 순자산 비교: 지난달 / 이번 달 나란히, 증감액과 %
3. **무엇 때문에 바뀌었나 (변화 원인 분해)** ← 이 기능의 핵심
4. 자산 유형별 비교: 부동산·주식·코인·현금·대출 각각 지난달 → 이번 달
5. 그달 받은 배당
6. 성적표 별점 변화 (오른 축 / 내린 축)
7. 다음 달 준비: 이번 달 갱신 안 된 자산 표시 + 캘린더 추가 버튼

### 4-4. 변화 원인 분해 규칙
| 항목 | 의미 | 근거 데이터 |
|---|---|---|
| 시세 변동 | 주식·코인 가격이 움직인 효과 | 보유 수량 × 가격 변화 |
| 환율 효과 | 해외 자산의 원화 환산 변화 | 외화 평가액 × 환율 변화 |
| 평가 갱신 | 부동산 등 직접 재입력한 평가액 변화 | 수동 수정 이력 |
| 순유입 | 바깥에서 넣은 돈 − 뺀 돈 | 입금·출금 기록 |
| 기록 안 된 변화 | 위로 설명되지 않는 나머지 | 순자산 변화 − 위 합계 |

- **매수·매도·대출 상환은 앱 안의 이동이므로 제외한다.** 현금으로 주식을 사거나 대출을 갚아도 순자산은 변하지 않는다. (이중 계산 방지)
- 예외: 현금 자산을 앱에 등록하지 않은 사용자의 매수는 외부 투입으로 계산한다.
- 매수·매도·입금·출금 기록은 이미 날짜와 함께 입력 가능하므로 월 기준으로 구분해 쓴다.
- 설명되지 않는 나머지는 다른 항목에 끼워 넣지 않고 **"기록 안 된 변화"로 솔직하게** 보여준다. 값이 크면 "이번 달 입출금을 기록하면 더 정확해져요" 정도만 가볍게 안내한다.
- 그달 갱신되지 않은 자산은 이전 값을 이어 쓰고 **"추정"** 표시.

### 4-5. 공통 원칙
- 모든 계산은 기기 로컬에서. 서버로 새로 보내는 값 없음.
- 투자 조언 문구 금지 ("이번 달 잘하셨어요" 같은 평가는 가능, "더 사세요"는 불가).
- 공유 이미지에 노출될 요소는 `data-screenshot-hide` 규칙 준수.

## 5. 열린 질문 (direction.md에서 답할 것)

### business-pm — "사업" 절
1. 결산이 "돌아올 이유"가 되려면 사용자가 결산에서 **무엇을 얻어가야** 하는가? (한 문장)
2. 성공의 모습: 로그인 없이 익명 기기 기준으로 측정 가능한 지표 1~2개 (예: 월초 7일 내 재방문 기기 비율, 결산 화면 진입 후 스크린샷 갱신 비율). 현재 측정 가능 여부도 확인
3. 결산 카드 노출 기간(예: 매월 마지막 3일 ~ 다음 달 7일)의 근거
4. 출시 후 알릴 방법: 기존 사용자 재활성화(앱 안), 카페 월 1회 결산 연재와의 연결

### planner-designer — "경험" 절
1. 기존 순자산·수익 하위 기능 중 **통합하면서 빠지거나 바뀌는 것** 목록 (일별 캘린더, 연속 기록·기록률, 연도별 수동 입력, 영업일/접속일 기준, 국내/해외 필터 각각 어디로 가는지)
2. 범위 토글 "주식"에서 월 탭 원인 분해를 어떻게 보여줄지 (주식만 볼 때 순유입은 매수 기준이 되는가)
3. 거래 기록을 거의 안 하는 사용자에게 결산이 "기록 안 된 변화"로 가득 차 보이지 않게 하는 방법
4. 첫 달 사용자(비교할 지난달이 없음)의 결산 화면
5. **하지 않을 것** 목록

### 공통 (합의 절)
- v1 범위: 4-3의 7개 블록을 한 번에 낼지, 핵심(1·2·3·7)만 먼저 낼지
- 월별 스냅샷을 새로 저장해야 하는가, 기존 기록으로 재구성 가능한가 → 로컬 저장소 스키마 변경 여부 = 위험 등급을 좌우 (developer 의견은 design-review에서)
- 캘린더 기본 일정 (매월 마지막 일요일 밤 / 매월 1일 아침 / 사용자 선택)

## 6. 하지 않는 것 (이미 확정)
- Push 알림으로 결산 알리기 (캘린더 .ics로 대체)
- 결산 공유 기능 (사용자는 자산 카드를 공유하지 않는다 — LEARNINGS)
- 결산 결과에 따른 투자 권유·종목 언급
- 서버 집계, 다른 사용자와 비교
