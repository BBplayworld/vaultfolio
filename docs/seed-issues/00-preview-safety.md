## 한 줄 요약
Vercel preview 환경에서 QA 에이전트가 사람 없이 안전하게 결과물을 점검할 수 있도록, preview 전용 안전장치와 데모 데이터를 만든다. **다른 모든 개발 이슈보다 먼저 끝낸다.**

## 배경
- 이슈마다 `issue-4.NN` 브랜치 → Vercel preview URL에서 QA가 실제 점검 → 대표는 반영 여부만 결정(머지)한다.
- preview는 운영과 다른 주소라 브라우저 저장소가 분리되어 있어, 실제 자산이 보이지 않는다 → 확인용 데이터가 필요하다.
- preview에서 E2EE 동기화를 켜면, 검증 전 코드가 실제 동기화 데이터를 덮어쓸 수 있다. 데이터가 각 기기에만 있는 구조라 되돌릴 방법이 없다.

## 이미 결정된 것
- preview 환경 판별: Vercel 환경 변수(`VERCEL_ENV=preview`)를 빌드 시점에 앱에 전달
- preview에서는
  - 화면 상단에 작은 "PREVIEW · 이슈 #<번호>" 표시 (공유 이미지에서는 숨김)
  - E2EE 동기화 **쓰기 비활성화** (읽기도 기본 비활성화)
  - 첫 진입 시 "데모 데이터로 보기" / "빈 상태로 보기" 선택. 데모 데이터는 저장소에 고정 파일로 두고 모든 자산 유형(주식 국내·해외·연금·ISA, 부동산, 코인, 현금, 대출, 배당, 거래 기록 3개월치)을 포함
  - 데모 데이터는 실제 사람의 자산이 아닌 가상 데이터
- 운영 환경 동작은 변하지 않는다 (운영에서 이 코드 경로가 실행되지 않음을 테스트로 보장)
- Vercel preview 접근 보호는 끈다 (데모 데이터만 쓰므로 위험 낮음). QA 에이전트가 Playwright로 preview를 직접 점검·스크린샷하는 것이 대표 결정 단계의 전제다
- 데모 데이터 진입은 자동화 가능해야 한다 (예: `?demo=1` 쿼리 또는 버튼 셀렉터 고정) — QA가 사람 없이 끝까지 조작할 수 있도록

## 열린 질문
- 데모 데이터 시나리오: 월말 결산(#1)과 투자 유형(#2) 확인에 필요한 데이터 특성 (예: 지난달 대비 변화가 있도록 2개월 이상 기록)
- 기존 데모 계정 데이터를 재사용할 수 있는가
