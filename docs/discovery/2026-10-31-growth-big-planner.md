# 신규 서비스 기준 대형 성장 확장 (기획 관점, r2) — 2026-10-31

작성: planner-designer / 대표 지시 반영: 엑셀·CSV·붙여넣기 가져오기 제외(스크린샷 등록 유지), "개선 단위"가 아니라 새 사용 목적·새 사용자층·새 핵심 가치. 5개 이내. 커밋·push 안 함.
이전 r1의 SSR 소개문·첫 자산 투자유형 시트·결산 일괄 최신화·체험 모드는 개선/유입 단위라 이번 목록에서 제외(필요 시 보조로만).

## 0. 현재 코드가 말하는 빈 곳
- 자산군은 부동산·주식(국내/해외/IRP/ISA/연금저축/비상장)·코인·현금·대출 5개뿐. 자동차·금/실물·보험·퇴직/국민연금, "내가 낸 전세금"을 담을 곳이 없다(`realEstateSchema`는 매입가·현재가 필수, `tenantDeposit`은 집주인이 받은 보증금으로 순자산에서 차감).
- 사용 목적은 "내 숫자 확인 + 월 결산"뿐. 소유자 개념이 없는 1인 금고(`types/asset.ts` 소유자 필드 0건). 부부가 같은 금고를 쓰는 사례는 `/api/share` 주석에만 있다.
- 습관 장치는 월 결산 1개. 기록 스트릭 공유는 반려, 월 스냅샷은 13개월 롤링이라 회고성 데이터가 남지 않는다(`snapshot-archive.ts`).
- 세금 관리(일정·연말 양도 시뮬)·성적표·배당·AI 프롬프트는 있으나 외부(세무사·은행·가족)에 건네는 출구가 없다. 외부 전달물은 백업 JSON·인증카드 PNG뿐.
- 알림/Push 코드 0건, 목표 기능은 4.22 롤백 전례.

## 1. 제안 (순위순)

### 1위. 가구(부부) 단위 — "같이 쓰는 금고" — 규모 L, 위험 단계별
- **새 사용자층/가치**: 신혼·맞벌이 가구. 월 결산을 "우리 집 가계 결산"으로. 1명의 설치가 2명의 활성이 된다(MAU 100명 목표에 직접 승수 효과, 추천 행동이 자랑이 아닌 필요).
- **설계 방향**
  - **1단계 (위험 low~medium, 스키마 무변경)**: 이미 되는 E2EE 동기화 금고 공유를 제품으로 정리. 동기화 설정에 "배우자/가족 초대"(기존 `sync-qr.tsx`·`cloud-sync-connect-dialog.tsx` 재사용) + 동시 편집 시 병합 안내 문구 + 웰컴 "기존 동기화 자산 연결" 문구에 가족 초대 케이스 추가.
  - **2단계 (risk:high, 스키마 변경)**: 자산·계좌·대출에 optional `owner` 태그(예: 본인/배우자/공동, 이름은 닉네임 `use-nickname` 재사용). 홈·상세·결산에 "전체 / 나 / 배우자" 범위 토글(기존 성과 화면의 전체/주식 토글 패턴 재사용). 결산 원인에 소유자별 순유입 구분은 3단계 후보.
  - 마이그레이션: 필드는 optional 가법이라 구버전 데이터는 owner 없음 = "공동"로 해석(변환 불필요). 단 구버전 기기 pull이 필드를 지우는 혼재 위험(LEARNINGS 데이터 안전) → pull 월 단위 병합 규칙 확장 + "이전 버전 데이터 → 새 버전" 복원 테스트 필수.
  - 서버 변경 없음: 둘 다 같은 금고 암호로 접속, 서버는 암호문 중계만(원칙 부합). 서버가 가구 합산을 알 수 없음.
- **지표(GA)**: `sync_action`(connect) 중 한 금고에 2기기 이상 연결 비율(사용자 속성 `sync_enabled` 재사용), 초대 흐름 진입→연결 완료율, 2단계 후 owner 태그 사용 사용자 비율, 가구 범위 토글 사용률.
- **결산 창 충돌**: 1단계는 동기화 설정·웰컴만 접촉 → 충돌 없음. 2단계는 결산 화면 접촉 → 12/11 이후.
- **대표 판단**: 2단계 스키마 변경 착수 여부, 구버전 혼재 시 owner 소실 허용 범위.

### 2위. 월 회고 + 연말 "올해의 자산 리포트" — 습관 형성 루프 — 규모 M~L, 위험 medium
- **새 사용 목적**: 숫자 확인을 넘어 "자산 일기". 반려된 스트릭 공유가 아니라 개인 회고(공유 전제 없음).
- **흐름**: 월 결산 화면 하단 "이번 달 한 줄 메모"(왜 늘었나/줄었나 내 말로) → 저장은 기기 로컬 → 12~1월 홈 팁/결산 연 탭에 "올해의 12개월 돌아보기": 월별 순자산 궤적·가장 크게 변한 달·원인 요약·월별 메모 타임라인. 이미지 저장으로 개인 보관(금액 가림 옵션, 워터마크 없음).
- **재사용**: 연 탭 원인(`year-causes`), 결산 정본 `settlement.ts`, 월 스냅샷, 캡처 `use-share-artifacts`, 금액 가리기 패턴(v4.37 AI 프롬프트 후속 후보와 공유).
- **스키마**: 메모는 월 스냅샷에 넣지 않고 별도 키(13개월 롤링 prune과 분리). 새 저장 키 + 동기화 포함 여부 → risk:high 판정 대상. 동기화 병합은 월 단위 키 병합.
- **지표**: 메모 작성 기기 비율(결산 본 기기 대비), 연말 리포트 진입→이미지 저장률, 12월·1월 재방문 기기 수(session_start). #51·#54 지표와 분리 판독.
- **결산 창 충돌**: 결산 화면 접촉 → 메모 블록은 12/11 이후 착수. 연말 리포트는 1월 시즌 목표로 12월 개발 가능(결산 창 후).

### 3위. 신고·상담용 자산 요약 내보내기 — "세금 시즌 + 은행·세무사 전달" — 규모 M, 위험 low~medium
- **새 사용 목적/층**: 종합소득세·양도세 신고, 대출 상담, 가족 간 정리 때 자산·배당·양도 내역을 정리해 전달해야 하는 사용자. 시즌성 재방문(5월·연말).
- **흐름**: 세금 관리 → "신고 준비 요약" → 연도·항목 선택(보유 현황 / 배당 합계 / 해외주식 양도 시뮬 결과 / 부채 현황) → 기기에서 생성(PNG/PDF 또는 인쇄 레이아웃) → 저장·공유. 공식 증빙 아님·참고용 고지, 세무 조언 문구 없음.
- **재사용**: `tax-year-end-simulator`, `tax-calendar-view`, 배당 데이터, 성적표 부채/자산 요약, 캡처 파이프라인. 서버 전송 0(로컬 생성). 스키마 무변경.
- **지표**: 요약 생성 수/기기, 4~5월·12월 세금 관리 진입 기기, `feature_use` 신규 category 값 추가(PARAM_VALUES 1줄).
- **제약**: 금액이 들어가는 결과물이므로 서비스 마케팅 문구와 분리(마케팅에 금액 노출 금지 불변), iOS 저장 방식은 LEARNINGS(.ics·blob 다운로드)에 따라 설계 시 브라우저별 전달 방식 명시.
- **결산 창 충돌**: 없음(세금 관리 영역).

### 4위. 새 자산군 — 실물·보장·임차 보증금 — 규모 L, risk:high(스키마)
- **새 사용자층/가치**: 전월세 거주 2030(내가 낸 전세금을 자산으로), 자동차·금/실물 보유자, 연금·보장 자산 보유자 → "내 자산 전부"의 완결. 현재는 이들이 현금이나 "기타"로 위장 입력하거나 이탈한다.
- **설계 방향**: 새 배열 `otherAssets` 1개 + 유형 태그(임차보증금·차량·실물·연금/보험 환급·기타), 값은 수동 갱신(시세 연동 없음, 서버 무관), 선택적으로 만기일(전세 계약 만료는 달력 `.ics`·세금 달력 패턴 재사용). 순자산·트리맵·성적표(분산)·결산 원인(수동 갱신은 "기록된 가치 변화")에 합산 — 항목(지표) 단위 전수 대조 필요(LEARNINGS 2026-10). 부동산 `tenantDeposit`(받은 보증금, 부채)와 짝이 되는 임차인 보증금(낸 보증금, 자산)을 구분 표기.
- **위험**: 순자산 정의가 바뀌는 사용자 발생 → 기존 사용자 숫자 불변 보장(신규 배열 비어 있으면 현행과 동일), 구버전 pull 시 배열 소실 방지 병합 규칙, 마이그레이션 코드와 복원 테스트 필수. 자동 risk:high.
- **지표**: 신규 자산군 저장 기기 비율, 첫 자산이 신규 자산군인 기기(`first_asset_saved asset_type`에 값 추가), 신규 유입의 이탈 감소는 표본이 작아 정성 판단.
- **결산 창 충돌**: 결산 원인 합산 접촉 → 12/11 이후.

### 5위(대표 판단). 목표 시나리오 — "목표까지 며칠/몇 달" — 규모 L, 위험 medium
- **새 핵심 가치**: 현재 확인 → 미래 계획(내집마련·은퇴 등 목표 순자산 대비 현재 진행). 월 결산에 "목표 진행" 한 줄이 붙으면 재방문 동기가 강화된다.
- **걸림돌**: 2026-08 승인 후 4.22에서 "목표 설정·신선도 알림 효용 낮음"으로 롤백된 전례(`level-meter.tsx` 주석). 수익률 가정을 넣으면 투자 조언 소지 → 산술 진행률(과거 월평균 증감 기준 "이 속도면")만 허용, 가정 입력 금지.
- **권고**: 1·2위 지표 확인 전에는 착수하지 않음. 재도입 사유(결산 맥락의 목표 한 줄, 알림 없음)를 대표가 확인할 때만.

## 2. 대표 판단 필요 항목
1. 1위 2단계(소유자 태그, risk:high) 및 4위(새 자산군, risk:high) 스키마 변경 착수 여부와 순서. 권고: 1위 1단계(스키마 무변경)를 먼저, 2단계는 1단계 지표(2기기 연결 비율) 확인 후.
2. 5위 목표 기능 재도입 — 롤백 전례 대비 재도입 사유 승인 여부.
3. 3위 결과물 문구: "공식 증빙 아님·참고용" 고지 수준(세무·금융 조언 오해 방지).
4. 제외 확인: 엑셀/CSV 가져오기(대표 지시), 알림 Push(투자 대비 불확실, 이전 보고에서 대표 판단 요청한 상태 유지), 소셜 비교/랭킹(PRINCIPLES 3장).
