- 흐름: 인앱 + 자산 0건 → 게이트 대신 웰컴 노출, 등록 CTA 슬롯만 "외부 브라우저에서 시작하기"(기존 `go()`/iOS 가이드 재사용)로 대체. 감지 정규식에 누락된 인앱(Threads·다음·밴드) 보강으로 **데이터 유실 위험 구간 정리**. 외부 브라우저 도착 시 "방금 보던 화면에서 이어서" 맥락 유지(쿼리 없이 `/`).
- 지표(GA): welcome_view `source=inapp` 대비 `pwa_install{method: inapp_move}` 기기 비율(변경 전 게이트 클릭률 대비), 이동 후 같은 기기 first_visit 재집계 불가 한계는 정성 병행.
- 규모·위험: M, risk medium(데이터 안전 경로). 0건 방문자에게만 완화, 자산 1건 이상이면 현행 하드 게이트 유지. 쓰기·동기화·시세 경로가 열리지 않는지 `isBackgroundWorkBlocked` 소비처 전수 확인, 자산 생성 진입점이 인앱에서 막히는지 검증.
- 코드 근거: `in-app-browser-gate.tsx:44,48-68,74,94-104`, `detect-browser.ts:18`, `welcome-guide.tsx:84-89`(CTA 슬롯 상태 확장 지점).
- 기존 후보 A와 동일 계열이나 대형 묶음의 도착부로 재배치한 것이다. 사전 확인(무비용): GA에서 welcome_view source별 비율. 인앱 비중이 낮으면 우선순위 하향.
- 결산 창: 접촉 없음. #48: inapp 코호트만 변경 → 분모에서 분리 가능.

### 제안 5. 공유 시트로 스크린샷 보내기 — 설치형 사용자의 등록·갱신 마찰 제거 (병목 1 보조, 재방문)
- 새 가치: 증권앱에서 캡처 → 공유 → "시크릿에셋" 선택 → 인식 미리보기가 바로 열림(웹 공유 대상 PWA, manifest `share_target`). 앱을 열어 업로드 버튼을 찾는 단계 제거. 갱신(재방문 핵심 행동)도 같은 경로.
- 한계: 안드로이드 Chrome 설치형 PWA만 지원, iOS 불가. 설치 전 첫 방문자에겐 효과 없음(첫 등록 0/17의 직접 해법 아님). PWA 설치 이벤트도 0건.
- 지표(GA): 신규 `screenshot_parse{source: share_target}` 값, 설치 기기의 주간 등록·갱신 횟수.
- 규모·위험: M, risk medium(서비스 워커·manifest 변경, 공유 대상 POST 처리, 이미지 서버 전송 유지). 순위 최하: 신규 유입 병목과 거리가 있어 대형 과제로는 약하다.

## 3. 순위와 대표 판단

순위 근거: 병목에 직접 닿는 정도 × 근거 강도(H1~H6) × 규모 대비 위험.

| 순위 | 제안 | 병목 | 규모/위험 | 비고 |
|---|---|---|---|---|
| 1 | 제안 2 체험 모드 | 첫 등록 | L / medium~high | H1이 가장 강한 가설. 선결: 로컬 저장 차단 설계, 결산 GA 억제 |
| 2 | 제안 1 한 번에 전체 등록 | 첫 등록 | L / medium | 제안 2와 한 릴리스로 묶으면 "보고 → 쉽게 등록". 서버 한도 재설계 필요 |
| 3 | 제안 4 채널 도착 파이프라인 | 첫 등록 연결·유입 | M / medium | source별 welcome_view 확인 후 착수 여부 결정 |

| 5 | 제안 5 공유 시트 | 재방문 | M / medium | 신규 유입 기여 약함, 후순위 |

권고 묶음: 제안 2 + 제안 1(+ H4 문구 정정 동승)을 4.38 후속 릴리스로, 제안 4는 GA source 비율 확인 뒤 소형으로 동승. 제안 3은 #34(SEO) 닫힌 상태이므로 대표가 "검색 유입 구조 투자" 방향을 승인할 때 별도 이슈로.

판단이 어려운 지점(이번 문서의 솔직한 한계): 모든 제안의 효과 추정은 표본(welcome_view 7기기, first_visit 17)이 너무 작아 통계로 검증할 수 없다. 12/25 #48 판독까지 기다리면 한 달이 더 지나간다는 점과, 아직 H1(CTA 비클릭)·H4(신뢰 모순)가 실제 원인인지 알 수 없다는 점 사이에서 판단해야 한다. 단일 원인이 아니라면 어느 제안도 0/17을 단독으로 바꾸지 못한다.

대표 판단 필요 항목
1. 체험 모드(제안 2) 허용: 위 설계(메모리 전용·새 URL 없음)로 E2 동결 해제 여부.
2. 업로드 전 "이미지는 서버(AI)로 전송, 저장하지 않음" 고지 문구 방향(H4): 첫 화면 "기기를 절대 벗어나지 않습니다" 정정이 포함된다. 대표 보안 메시지 기준(2026-10-31: 서버 단정 금지)과 정합하는 문안 확인.
3. 엑셀·노션 화면을 캡처해 올리는 경우를 "엑셀 가져오기 제외" 범위로 볼지 (제안 1의 자동 판별을 확장할 때 경계 사례; 이번 제안에는 포함하지 않음).
4. 제안 3의 새 공개 URL(종목 페이지) 허용 여부와 외부 시세·배당 데이터 노출 범위.
5. 서버 AI 한도 상향 여부(제안 1의 다중 이미지: 전역 300/일 기준 일 40~75 신규가 상한).
