# 월 신규 활성 유저 성장 과제 후보 (business-pm, 2026-10-31)

전제: 대표 지시(2026-10-31, D 동결 해제). 병목 = 월 신규(first_visit) 약 17명. 결산 창 11/27~12/10 결산 화면·홈 팁 무접촉. 사용자 자산 서버 전송·투자 조언·금액 문구·새 URL 진입점 금지.
제외(중복·반려): G2 SSR·sitemap, G3 #33, E2 체험 모드, E3 v2, AI 프롬프트 v2, #45. 닫힌 #33·#34는 재제안하지 않음.

## 먼저 알아둘 사실 (코드 확인)
- 현재 신규 유입 채널을 구분할 수단이 없다. 이벤트 CSV에는 first_visit 17명뿐이고, 어떤 채널(검색·Threads·카페·블로그·지인 링크)에서 왔는지는 GA 표준 "사용자 획득" 보고서(대표 조회)로만 알 수 있다. 어떤 후보든 착수 전 이 보고서 1장(기본 채널 그룹·소스별 신규 사용자, 10/3~10/30)을 받으면 우선순위가 확정된다.
- 카카오톡·인스타그램·페이스북·라인·네이버 인앱 브라우저로 열면 앱 전체를 가리는 하드 게이트가 뜬다(`in-app-browser-gate.tsx:44,93-146`, 판별 정규식 `detect-browser.ts:18`). 링크로 들어오는 신규 방문자가 가장 먼저 보는 화면이 이것이다.
- 사이트 주소 불일치 의심: canonical·sitemap·robots·OG는 모두 `APP_CONFIG.siteUrl`(`config/app.ts:15`, env 미설정 시 `https://secretasset.xyz`)을 쓰는데, STATE 기준 루트 도메인은 www로 리다이렉트된다. Vercel의 `NEXT_PUBLIC_SITE_URL` 값 확인 필요(코드만으로 확정 불가).

## 후보 1 (우선) 인앱 브라우저 게이트: 신규 방문자 계측 + 첫 문구 개선
- 누구의 어떤 문제: 카톡·네이버·인스타 인앱으로 링크를 연 신규 방문자. 첫 문장이 "데이터가 유실될 수 있어 안전하게 이용할 수 없습니다"(`in-app-browser-gate.tsx:102`)라 앱 가치를 보기 전에 경고부터 본다. 로그인 없음·내 기기에만 저장이라는 브랜드 약속과 첫인상이 반대다. 계측도 없다(클릭만 `pwa_install method=inapp_move`, `:49`; 게이트 노출 이벤트 없음).
- 개선안: ① 게이트 노출 이벤트 추가(기존 `pwa_install`에 method 값 1개, PARAM_VALUES `ga.ts:60`에 추가, 스냅샷 테스트 갱신) ② 자산 0건·미동기화 방문자(`!hasAssets && !isSyncMode`, 이미 `:41,74`에서 구분 중)에게만 문구를 "Chrome·Safari에서 열면 입력한 자산이 내 기기에 안전하게 남아요. 한 번만 이동하면 돼요" 방향으로 바꿈. 게이트를 푸는 것(인앱에서 바로 사용)은 하지 않는다 — 세션 끊김 데이터 유실 위험, 대표 데이터 안전 우선 기조.
- 성공 지표: `pwa_install(method=inapp_view)` 기기 → `inapp_move` 클릭 기기 비율(게이트 통과 의향). 주의: 외부 브라우저로 넘어가면 GA에서 새 기기·새 first_visit으로 잡히므로 같은 기기 연속 전환은 측정 불가. 간접 확인은 `welcome_view source=web` 비중 증가와 `first_visit` 대비 `welcome_view` 비율. 현재 기준선: pwa_install 0건(28일) — 게이트를 본 사람이 거의 없거나 클릭이 없었다는 뜻이라, 병목 크기는 계측 후 판정.
- 왜 지금: 대표가 카페·Threads·블로그에 링크를 올리는 채널이 모두 인앱 브라우저 경유 가능성이 높고(Threads 앱의 UA가 정규식에 걸리는지는 미확인, 실기기 확인 필요), 신규 17명을 늘리려는 이번 시기에 유입이 생겨도 첫 화면에서 버려질 수 있다. 계측 자체가 이후 마케팅 판단 근거가 된다.
- 규모·위험: S(계측 + 문구 분기), 위험 low. 데이터 무접촉.
- 근거: `in-app-browser-gate.tsx:41-44,74,100-104`, `detect-browser.ts:18,74-77`, `ga.ts:60`, `(main)/layout.tsx:51`.
- 충돌: 결산 화면·홈 팁 무접촉. #48 첫 화면 본문은 건드리지 않으나, 게이트 뒤에서도 WelcomeGuide가 마운트되어 `welcome_view source=inapp`이 집계되므로(`page.tsx:87-90`, `welcome-guide.tsx:101`) 변경일 이후 inapp 코호트를 #48 판독에서 분리 기록해야 한다(대표 지시의 "변경 시점·코호트 기록" 적용).

## 후보 2 검색 스니펫 정비: title·description·구조화 데이터 + 사이트 주소 정합
- 누구의 어떤 문제: "엑셀로 자산 정리"하다 "로그인 없는 자산관리", "주식 포트폴리오 정리"를 검색하는 3040. 지금 검색 결과 제목은 "안전하게 보관되는 오프라인 자산 관리 시스템"(`config/app.ts:19`)이라 엑셀·노션 대체라는 정체성이 안 드러난다. 또 "오프라인"은 시세·스크린샷 분석이 서버를 쓰는 실제와 어긋나 보안 메시지 기준(단정 금지)과 충돌할 소지가 있다.
- 개선안: head 메타만 수정 — title·description을 "엑셀·노션 대신 / 로그인 없이 / 내 기기에만 저장 / 주식·부동산·코인·대출 한 화면" 중심으로 재작성, WebApplication JSON-LD 1개(무료 앱, 카테고리 Finance), canonical·sitemap·OG의 호스트를 실제 서비스 도메인(www)과 일치시킴(env 확인 후). 본문·첫 화면은 변경 없음. 별도 URL 추가 없음.
- 성공 지표: GA 표준 보고서 "Organic Search" 신규 사용자(이벤트 추가 불필요), 대표 작업으로 Search Console·네이버 서치어드바이저 노출/클릭. 자체 이벤트로는 측정 불가함을 명시. 반영 효과는 색인 갱신 때문에 2~6주 지연.
- 왜 지금: 반영~색인에 시간이 걸려 결산 창(11/27~12/10)과 #48 판독(12/25경) 전에 심어두는 편이 효과 시차를 줄인다. 첫 화면을 안 건드려 #48 측정을 오염시키지 않고, G2(SSR 본문·sitemap 확장)의 선행 조각으로 재사용된다.
- 규모·위험: S, 위험 low. 정직한 한계: 월 17명 규모에서 검색 비중이 작으면 체감 증가는 작다. 후보 0(획득 보고서)에서 Organic 비중이 낮으면 보류.
- 근거: `layout.tsx:30-72`, `config/app.ts:15,18-29`, `sitemap.ts:5-14`, `robots.ts:24`, `manifest.ts:8`.
- 충돌: 결산·홈 팁 무접촉. #48 OG 이미지 설정(`layout.tsx:51`)과 같은 파일이나 이미 머지됨, 첫 화면 퍼널과 무관. G2와는 head(이 후보)와 본문 SSR(G2)로 나뉘어 중복 아님 — 단, G2 재개 때 합칠 것.

## 후보 3 서비스 소개 링크 보내기 (자산 데이터 없음) + 유입 출처 표시
- 누구의 어떤 문제: 엑셀로 정리하던 사용자가 "이거 좋더라"를 주변에 전할 가장 쉬운 방법이 없다. 지금 공유 기능은 자산 데이터 링크·카드뿐(`tool-menu.tsx:166-181`, `share-menu.tsx:188-249`)이라 서비스 자체를 알리는 용도가 아니다.
- 개선안: 설정 또는 더보기에 "시크릿에셋 소개 링크 보내기" 행 1개. OS 공유창(`navigator.share`, 기존 패턴 `cloud-sync-menu-entry.tsx:114`)으로 사이트 루트에 `?utm_source=invite&utm_medium=share`를 붙인 주소와 한 줄 소개만 전달. 자산 값·사용자 식별자 없음. 폴백은 클립보드 복사. 새 URL 진입점이 아니라 같은 루트의 쿼리다.
- 성공 지표: `share`(method=link, content_type=link)는 기존 자산 공유 링크가 같은 값을 쓰므로(`tool-menu.tsx:175`) 구분 불가 → source에 `invite` 추가(PARAM_VALUES). 유입 측면은 GA 획득 보고서의 소스 `invite`.
- 왜 지금 / 정직한 한계: LEARNINGS의 반려는 "자산·성과 카드 공유"이며 이 후보는 서비스 소개 링크라 같은 이유는 아니다. 다만 3040 투자자가 지인에게 자산 앱을 추천할 동기가 약하고 첫 요청 트리거도 마땅치 않아 근거는 가장 약하다. 홈 팁·결산에 붙이지 않는다(무접촉 약속). 후보 1·2 결과를 본 뒤 3순위.
- 규모·위험: S, 위험 low.
- 충돌: 결산·홈 팁 무접촉(설정/더보기 행만). #48 첫 화면 무관.

## 후보 4 (코드 변경 없음, 상시 동승) 채널 링크 UTM 규약
- 문제: 월 신규 17명이 어디서 오는지 모르면 어떤 채널을 늘릴지 판단할 수 없다.
- 내용: Threads·카페·블로그 게시물의 링크에 `?utm_source=threads|cafe|blog&utm_medium=social|community|post` 형식을 쓰도록 마케팅 초안 규칙에 추가(초안 단계만, 게시는 대표). GA가 자동 수집하므로 서비스 코드 변경 없음.
- 지표: GA 획득 보고서 소스별 신규 사용자. 확인 필요: 가상 화면 page_view가 page_location을 덮어 utm 귀속이 끊기지 않는지는 코드 미확인(`trackScreen`, 개발 시 점검).
- 위험: 없음. 카페는 도배 금지 원칙 유지.

## 참고 (후보 아님)
- `manifest.ts:29-38`에 `share_target`(GET, title·text·url → "/")이 선언돼 있으나 받아서 쓰는 코드가 없다(searchParams로 text·url 소비 없음). 설치한 Android 사용자의 공유창에 앱이 뜨는데 열어도 아무 일이 없다. 성장 기여는 약해 정리(type:simplify) 후보로만 기록.
- `/invalid-access`는 만료·손상 링크 수신자에게 "내 자산 홈으로 돌아가기"만 보인다(`invalid-access/page.tsx`). 신규가 이 화면을 볼 일은 드물어 지표 근거 없음.
