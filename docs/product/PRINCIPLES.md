# 시크릿에셋 제품 원칙과 결정 기록

모든 에이전트의 최상위 판단 기준. 이 문서와 충돌하는 제안은 채택하지 않는다.
원칙을 바꾸는 제안은 에이전트가 확정할 수 없고 `status:needs-human`으로 올린다. 최종 결정은 대표가 한다.

## 1. 제품 정체성
- 한 줄 정의: 자산관리 앱이 아니라, **내 자산을 내가 정확히 아는 상태를 유지시켜주는 도구**
- 핵심 강점
  1. 유려한 UI 기반의 자산 관리, 특히 주식 자산 관리
  2. 로그인 없는 로컬 저장 + E2EE 기기 동기화 → 보안과 편리함 동시 제공
  3. 내 자산 정보 기반 AI 프롬프트, 자산 성적표·수익·배당 같은 성과 기능
- 진짜 경쟁자: 토스·뱅크샐러드가 아니라 **엑셀·구글시트·노션으로 자산을 직접 정리하는 습관**

## 2. 아키텍처 원칙
- 사용자 자산 데이터는 기기 로컬에만 저장한다.
- 서버 역할은 두 가지뿐: 시세(주가·환율·코인) 제공, E2EE 동기화·공유 중계.
- 서버로 보낼 수 있는 값: 종목코드, 시세 조건(등락률·목표가) 등 사용자 보유 정보를 역산할 수 없는 값.
- 서비스 형태는 PWA. iOS Web Push는 홈 화면 설치 상태에서만 동작하므로, 알림이 없어도 핵심 기능은 완결되어야 한다.
- 로그인·계정 시스템 없음 (의도된 제약).

## 3. 하지 않는 것
- 마이데이터·오픈뱅킹 연동 (정체성 포기)
- 투자 조언, 종목 추천
- 광고, 사용자 데이터 활용
- 소셜 피어 비교 등 서버가 사용자 자산을 알아야 하는 기능
- 기능 수 늘리기 경쟁. 새 기능 제안은 "돌아올 이유" 또는 "첫 발견"에 기여하는지로 판단
- 결제 도입 (월 활성 사용자 100명 달성 전)

## 4. 현재 단계와 목표 (2026-10 기준)
- 월 활성 사용자 약 50명, 감소 추세
- 목표: **월 활성 사용자 100명 이상**
- 진단: 스크린샷 갱신 구조라 시간이 지나면 숫자가 낡고, 다시 열 이유가 사라져 이탈한다
- 우선순위
  1. 리텐션: 한 달에 한 번 확실히 돌아오는 "월말 결산" 의식
  2. 유입: 첫 페이지를 "투자 유형 테스트"로 → 테스트가 곧 온보딩
  3. 채널: 도배 없이, 금액은 가리고 비중·%만 보여주는 월 1회 연재형 콘텐츠

## 5. UI 원칙
- 첫 화면은 최소한으로, 플로팅 CTA는 하나
- 상세 화면과 공유 이미지는 시각적으로 동일 (`data-screenshot-hide` 패턴)
- 디자인 토큰 일관성 유지
- 성과 메뉴는 "자산 변화 / 배당 / 자산 성적표" 3개로 정리 (#1 이슈)
- preview 환경은 데모 데이터만 사용하고 실제 동기화 쓰기를 하지 않는다

## 6. 마케팅 문구 규칙
- 구체적 금액 금지
- 브랜드는 항상 "안전한 자산 관리, 시크릿에셋"으로 자연스럽게 마무리
- 톤: 친구에게 말하듯 편안한 반말 축약형, 감성적·과장된 표현 금지
- 사실과 다른 기능 설명 금지 (예: 연도별 순자산은 수동 입력이다)

## 7. 결정 기록
결정은 이 문서가 아니라 팀 메모리 `memory` 브랜치의 `DECISIONS.md` 에 쌓는다. 반려 사유는 `LEARNINGS.md`.
이 문서는 원칙만 담고, 원칙 변경은 대표만 할 수 있다.
